书写模式 Writing Modes

writing-mode · 竖排文字 · vertical-rl · 纵横对齐

writing-mode 重定义整盒子的流方向:vertical-rl 一句让中文回到传统竖排(行从右往左),text-orientation 管竖排里每个字形的朝向,text-combine-upright 把年份数字叠成一小格——书脊、诗笺与竖排表单的底座。

Web 标准 ★★
实例演示 官方默认
参数
动效▾
modevertical-rl

信纸的书写模式(CSS 型 --wm-mode)。默认 vertical-rl——调研 12§2 记为「传统中日竖排」且 12§2 片段给出 aside h2 { writing-mode: vertical-rl } 书脊标签配方;horizontal-tb 为规范默认值;sideways-lr 为 experimental,引擎不支持时值无效回落 horizontal-tb,demo 用 @supports 思路的运行时检测(CSS.supports)如实报告。

orientationmixed

竖排里的字形朝向 text-orientation(CSS 型 --wm-orientation;调研 12§2 配套属性)。mixed 为规范默认:汉字保持直立、西文旋转 90°;upright 让拉丁字母也一个个直立堆叠;sideways 全部侧放——demo 标题里的「Li Bai」是观察三档差异的探针,仅竖排档生效。

combinenone

年份「2026」的 text-combine-upright(CSS 型 --wm-combine;调研 12§2 记为「纵横对齐」)。all 档把竖排行内连续数字压缩进一个字格横排显示——日文「縦中横」惯例,中文竖排年份同样适用;仅对行内短数字串有意义。

代码拆解

结构与 DOM

书写模式是「容器级声明」:挂在祖先盒上,整棵子树的块流与内联流一起转向,DOM 顺序不变:

<article class="paper">   <!-- writing-mode 挂容器 -->
  <h3>静夜思 · Li Bai</h3>
  <p>床前明月光</p>
  <p>疑是地上霜</p>
  <p>…</p>
  <p><span class="year">2026</span> 年书</p>
</article>
<aside><h2 class="spine">书脊标签</h2></aside>
.paper {
  writing-mode: vertical-rl;      /* 传统中日竖排:行自上而下、从右往左(调研 12§2) */
  text-orientation: mixed;        /* 汉字直立、西文旋转(规范默认) */
  height: 320px;                  /* 竖排要限高,行(列)沿块轴排列 */
}
.paper .year {
  text-combine-upright: all;      /* 纵横对齐:「2026」压进一个字格 */
}
.spine { writing-mode: vertical-rl; }  /* 侧边书脊标签(调研 12§2 片段原样) */

关键点:

  • 取值:horizontal-tb(默认)/ vertical-rl / vertical-lr / sideways-rl / sideways-lr(字形整体侧放,experimental);lr/tb 旧值已废弃(调研 12§2);
  • 竖排下「行」变成列:vertical-rl 行从右往左排,vertical-lr 从左往右——诗句顺序的视觉翻转由这一个值决定;
  • 配套三件:direction(行内方向)、text-orientation(竖排字形朝向)、text-combine-upright(纵横对齐)(调研 12§2);
  • writing-mode 也改变逻辑属性的轴:padding-block 在竖排里就是左右方向——与 logical-properties 条目天然联动。

样式与参数

三个参数,全部 CSS 型变量注入:

.paper {
  writing-mode: var(--wm-mode, vertical-rl);        /* 默认竖排:12§2 记「传统中日竖排」 */
  text-orientation: var(--wm-orientation, mixed);   /* mixed 为规范默认 */
}
.paper .year { text-combine-upright: var(--wm-combine, none); }

数值出处:

  • vertical-rl 书脊配方 aside h2 { writing-mode: vertical-rl } 与西文侧放 sideways-lr + @supports not (…) { transform: rotate(-90deg) } 回退逐字出自调研 12§2 可复用片段;
  • horizontal-tb 为规范默认值;mixed 为 text-orientation 规范默认值;
  • sideways-rl / sideways-lr 为 experimental,调研 12§2 明确「需 @supports 检测」,各家正式版本未核验(未证实)——demo 以 CSS.supports('writing-mode','sideways-lr') 运行时检测如实报告;
  • writing-mode Baseline 自 2017-03(调研 12§2)。

动效与交互

书写模式切换是整棵子树的流翻转,读数负责把「不可见」变「可见」:

  • 切 mode:信纸瞬时重排——vertical-rl 与 vertical-lr 的诗句左右互换、horizontal-tb 回横排;竖排要限高才成「列」,demo 固定信纸高度让换列可见;
  • orientation 三档探针:标题里的「Li Bai」——mixed 旋转 90°、upright 逐字母直立堆叠、sideways 全侧放;汉字在三档下都保持直立(mixed/upright),该属性仅竖排生效;
  • combine 的纵横对齐:落款「2026 年书」在 all 档把四位数压进一个字格,行气不断;
  • sideways 检测读数:页面载入即跑 CSS.supports,原生支持走 writing-mode: sideways-lr,不支持时按钮可切换 rotate(-90deg) 回退并如实标注「需回退」;
  • 卡片入场 0.45s 淡入上移只动 opacity/translate,prefers-reduced-motion 下取消;书写模式切换本身无过渡——流方向翻转做补间只会头晕。

真实产品案例

  • 侧边书脊标签(调研 12§2 片段原始用例):aside h2 { writing-mode: vertical-rl } 把侧栏标题竖起来,中文文档站与日文站常用于装饰性分区标签(编辑性应用——具体站点清单未逐一核实;配方逐字出自调研);
  • 中文竖排诗笺/书法页面:诗词主题站点用 vertical-rl 恢复「自上而下、行从右起」的传统文序,配合 text-combine-upright 处理纪年(编辑性总结——具体站点实现未逐一核实;机制与取值均为调研 12§2 记载);
  • MDN writing-mode 参考页与 css-writing-modes 规范(调研 12§2 来源):取值表、text-orientation/text-combine-upright 配套语义与「旧值已废弃」标注的权威出处。

参数敏感度

参数调大(切档)会…调小(回默认)会…
mode → vertical-lr行序从左往右——与中文传统文序相反,诗句左右互换一眼可辨vertical-rl 是中文竖排正字法;horizontal-tb 回横排通用
orientation → upright拉丁字母逐个直立堆叠,适合单词竖排标记;长句可读性骤降mixed 是规范默认:汉字直立 + 西文旋转,混排最稳
combine → all「2026」压进一个字格,竖排行气连贯;四位数以上开始拥挤none 逐字竖排,数字逐个占格,年份行被拉长
信纸高度限高越低,竖排列数越多、换列越频繁不限高时所有行挤进一列,竖排的「多列文序」消失

经验要点:竖排容器必须限高,否则块轴不换行;experimental 值永远配特性检测;竖排只做呈现增强,关闭后内容仍按 DOM 顺序横排可读。

适用场景 4
  • 中文竖排诗笺/书法页面:vertical-rl 恢复「自上而下、行从右起」的传统文序
  • 侧边书脊标签:aside h2 { writing-mode: vertical-rl }——调研 12§2 片段的原始用例
  • 竖排里的年份与编号:text-combine-upright: all 让「2026」占一个字格,不打断行气
  • 日式纵排表单/名片类版式:vertical-rl + text-orientation 控制混排字形朝向
何时不要用 4
  • 整站正文竖排——竖行阅读效率低于横排,竖排适合短文本与装饰性版块
  • 生产环境裸写 sideways-lr 不加检测——experimental 值在未支持引擎整条无效(调研 12§2)
  • 用 lr/tb 旧值——已废弃(调研 12§2)
  • 竖排里塞长英文单词——词内断行不可控,拉丁长词应放横排容器或 sideways 独立块
无障碍

writing-mode 只改视觉流,不改 DOM 顺序——读屏按 DOM 朗读,竖排诗的行序在无障碍树里保持书写者语义(WCAG 1.3.2);竖排容器中的方向性图标与下划线需核对镜像;sideways-lr 的 transform 回退不改变文本语义,读屏读到的仍是原文;对比度在竖排长笔画字形下仍按 WCAG 1.4.3 核对;装饰性书脊标签 aria-hidden。

浏览器支持

writing-mode Baseline 自 2017-03(调研 12§2);horizontal-tb / vertical-rl / vertical-lr 与配套 text-orientation、text-combine-upright 各主流引擎长期可用。sideways-rl / sideways-lr 仍为 experimental——调研 12§2 明确要求 @supports 检测,各家正式支持版本未核验(未证实),demo 以 CSS.supports 运行时检测如实报告当前路径。

兼容回退

渐进增强两级:①sideways-lr 不支持时值无效回落 horizontal-tb,故实验值永远配 @supports 检测——调研 12§2 片段的回退写法是 transform: rotate(-90deg) 侧放西文,demo 用同一思路的运行时检测并切换回退类;②竖排整体不支持的环境(极老引擎)保持横排可读,内容顺序仍按 DOM——竖排是呈现增强,不是内容依赖。

来源 2

起源出自 CSS Writing Modes(css-writing-modes 规范,调研 12§2):取值 horizontal-tb(默认)/ vertical-rl(传统中日竖排)/ vertical-lr / sideways-rl / sideways-lr(字形整体侧放,仍为 experimental,需 @supports 检测);lr/tb 等旧值已废弃。配套属性:direction(行内方向)、text-orientation(竖排字形朝向)、text-combine-upright(纵横对齐)。writing-mode Baseline 自 2017-03;sideways-* 需特性检测(调研 12§2)。
