分栏视图 Split View

分栏面板 · 可拖分栏 · Resizable Panels · Split Pane

一条可拖的分隔条把界面分成可调双栏:拖拽与方向键共用同一数值,栏内组件用容器查询随栏宽自适应——IDE、邮件客户端与文档站的骨架。

代码拆解

结构与 DOM

分栏视图没有 CSS 原生标准(调研 05§8),DOM 上就是「左栏 + 分隔条 + 右栏」三兄弟,分隔条是一个真正的可交互元素而不是装饰线:

<div class="split">
  <div class="pane pane-left">文件树…</div>
  <button
    type="button"
    role="separator"
    aria-orientation="vertical"
    aria-valuemin="20" aria-valuemax="80" aria-valuenow="40"
    aria-label="调整左右栏宽度"></button>
  <div class="pane pane-right">预览卡…</div>
</div>

关键点:

  • 分隔条用 role="separator" + tabindex="0" + 方向键——这是 WAI-ARIA separator 模式的最低配,react-resizable-panels 的 README 也采用同一语义(调研 05§8);
  • 左栏宽度是唯一状态,右栏 flex: 1 吃剩余空间;aria-valuenow 与视觉宽度共享同一数值;
  • 右栏声明 container-type: inline-size,栏内组件用 @container 按栏宽自适应——「分栏」与「容器查询」联动后,拖窄栏宽会看到卡片自动翻排;
  • MDN Cookbook 的「Split navigation」是导航分组的视觉分隔,与桌面式可拖分栏并非同一概念(调研 05§8)。

样式与参数

两个参数:初始栏宽与夹紧下限,分别经 --sv-start 注入、以 JS 状态参与夹紧:

.split { display: flex; }
.pane-left {
  width: var(--sv-start, 40%);   /* 初始 40%:演示基准值,未证实 */
  min-width: var(--sv-min, 20%); /* 夹紧下限 20%:演示基准值,未证实 */
  flex: none;
  transition: width 0.15s ease;  /* 只平滑参数滑杆;拖拽中由 JS 直写,无感知延迟 */
}
.pane-right { flex: 1; min-width: 0; container-type: inline-size; }

/* 栏内联动:查询条件必须是字面量(容器查询条件不接受自定义属性) */
@container (max-width: 280px) {
  .pane-right .card { flex-direction: column; }
}

数值出处:

  • 参数默认值 40% / 20% 为本条目演示基准值,未证实——react-resizable-panels 的 defaultSize/minSize 由各产品自定,无统一官方值;
  • 分隔条命中区 ≥10px 宽并配 touch-action: none 防移动端滚动劫持;焦点环 2px 在分隔条本体上;
  • 容器查询断点 280px 亦为演示基准值,生产上应按卡片内容的折叠宽度决定。

动效与交互

拖拽是主交互,键盘是等价交互,二者共用同一夹紧函数:

  • 拖拽:Pointer Events + setPointerCapture,拖拽中直接写宽度(无过渡),松手结束;touch-action: none 让触屏可拖;
  • 方向键:←/→ 步进 ±2%(Shift ×3),Home/End 直达夹紧极限——步长为演示基准值;aria-valuenow 随每一步更新;
  • 双击复位:回到 startSize 默认值,reset() 复用 store 的恢复逻辑;
  • 宽度过渡:参数滑杆改变时 0.15s ease 平滑;prefers-reduced-motion 下取消过渡;
  • 容器查询联动是布局反馈而非动画:卡片翻排瞬间完成,不做补间——栏宽由用户拖拽控制,动画反而碍事。

真实产品案例

  • react-resizable-panels(调研 05§8):生态事实标准的出处本身——<PanelGroup>/<Panel> 分组、拖拽手柄、WAI-ARIA separator 键盘可访问性与 gridline 增强,README 一手核对;VS Code 式可调面板在 Web 端的多数实现基于它或同款语义(具体采用清单未逐一核实);
  • IDE 与邮件客户端的双栏骨架:编辑器资源树+编辑区、邮件列表+阅读窗是最典型的分栏产品形态,分隔条均可拖拽且带双击复位(编辑性总结——各家具体实现参数未逐一核实);
  • MDN Layout Cookbook:与分栏相关的官方配方是「Split navigation」(导航分组分隔)——调研 05§8 明确指出它与桌面式可拖分栏不是同一概念,查资料时不要混淆。

参数敏感度

参数调大会…调小会…
startSize左栏更宽,文件树全名可见;右栏更早触发 280px 容器断点、卡片翻纵排右栏主导,预览卡横排舒展;左栏文件名截断(有 overflow: hidden 兜底)
minSize两栏都被保底,拖拽行程变短;过高的下限让分栏失去意义拖拽自由度更大;低于 ~15% 后窄栏内容容易挤压不可读,demo 的容器查询翻排就是兜底

经验要点:下限取「窄栏内容刚好还可读」的宽度而不是对称百分比;分隔条命中区宁可偏宽(≥10px);双栏 DOM 顺序不随拖拽改变,读屏顺序保持稳定。

适用场景 4
  • IDE/编辑器的资源树与编辑区、邮件客户端的列表与阅读 pane
  • 文档站/后台的侧栏导航,用户可按自己的屏幕宽度收窄
  • 对比场景:图集编辑器原图与调色结果并排、日志查看器
  • 栏内组件密度自适应——配合容器查询让卡片随栏宽自行重排(本条目 demo 的联动)
何时不要用 4
  • 手机竖屏主界面——拇指拖拽分隔条误触率高,直接堆叠
  • 内容必须完整可见的场景(报表、表单)——分栏挤压会截断关键信息
  • 把 MDN Cookbook「Split navigation」(导航分组视觉分隔)当成可拖分栏——两者不是同一概念(调研 05§8)
  • 分隔条只做鼠标目标——无键盘等价操作违反 WCAG 2.1.1(调研 05§8 的 separator 模式正是为此)
无障碍

分隔条是 WAI-ARIA separator:role="separator"、tabindex=0、aria-orientation="vertical"、aria-valuenow/min/max 实时反映栏宽、方向键调整(调研 05§8 react-resizable-panels README 同款语义);拖拽中 aria-valuenow 同步更新;夹紧下限防止任一栏被压到内容不可达;面板重排只改视觉不改 DOM 顺序(WCAG 1.3.2);焦点环在分隔条上清晰可见;prefers-reduced-motion 下取消面板宽度过渡。

浏览器支持

本条目 demo 依赖的 Pointer Events、role="separator" 与容器查询均为广泛可用能力;容器查询 Baseline Widely available 自 2023-02(调研 05§6)。分栏本身无 CSS 原生标准——生态方案 react-resizable-panels 的兼容性随 React 走(调研 05§8)。

兼容回退

不支持拖拽/指针事件的环境(键盘、读屏)必须保留方向键等价操作——role="separator" + tabindex + 方向键是 WAI-ARIA separator 模式的最低配(调研 05§8);极窄视口放弃分栏,改上下堆叠(媒体查询先于分栏生效);容器查询不生效时栏内组件保持默认纵排,不报错。

来源 2

起源CSS 无原生可拖拽分栏标准(调研 05§8);生态事实标准是 React 生态的 react-resizable-panels:PanelGroup/Panel 组件分组、拖拽手柄、支持 WAI-ARIA separator 角色的键盘可访问性(方向键调整,README 一手核对)。MDN Cookbook 的「Split navigation」是视觉分隔的导航配方,与桌面式可拖分栏并非同一概念,注意区分(调研 05§8)。本条目 demo 以原生 Pointer Events + role="separator" 复刻同一模式,零第三方库。
