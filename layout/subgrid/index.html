子网格 Subgrid Subgrid

grid-template-rows: subgrid · grid-template-columns: subgrid · 轨道继承

嵌套组件继承父网格的轨道:grid-template-rows/columns: subgrid 让卡片内部的行/列直接使用父网格轨道,跨卡片的标题与页脚水平对齐不再依赖魔法数字。

Web 标准 ★★
实例演示 官方默认
参数
动效▾
axisrows

JS 型参数(demo 切换 data-axis 与对应 DOM)。rows:三张卡片各跨越父网格 3 条行轨道并声明 grid-template-rows: subgrid,标题/正文/页脚三个内部行成为共享轨道——正文长短不齐页脚也水平对齐;columns:每行卡片跨越父网格 3 条列轨道声明 grid-template-columns: subgrid,标签/值/操作三列全表对齐。

代码拆解

结构与 DOM

父子两层网格:父网格定义轨道,子元素声明 subgrid 把这些轨道「借」下来用。子元素必须先跨越父网格的多条轨道(grid-row: span 3 等),才有可继承的轨道。

<div class="cards">          <!-- 父网格:定义列轨道 -->
  <article class="card">     <!-- 子网格:跨 3 条行轨道 -->
    <h6>标题</h6>            <!-- 内部行 1 = 父网格共享行 -->
    <p>正文</p>              <!-- 内部行 2 -->
    <footer>页脚</footer>    <!-- 内部行 3 -->
  </article>
  <article class="card">…</article>
</div>

关键点:

  • grid-template-rows: subgrid / grid-template-columns: subgrid 继承父网格轨道定义(调研 05§4);
  • 跨越的父轨道数必须与内部条目数一致,否则布局溢出或折叠;
  • subgrid 只共享轨道几何(尺寸与 gap 一并继承),不改变 DOM 语义与读屏顺序;
  • Baseline Widely available 自 2023-09(MDN,调研 05§4)——三引擎全线可用,可以放开用。

样式与参数

两个参数:axis 为 JS 型(data-axis 切换 rows/columns 两套声明),gap 为 CSS 型(—sg-gap):

.cards {
  display: grid;
  grid-template-columns: repeat(3, 1fr);   /* 父网格裁定 3 条列轨道 */
  gap: var(--sg-gap);                       /* 16px,WebKit 官方示例(调研 05§5) */
}

/* 行轴:卡片跨 3 条父行轨道,内部行 = 共享轨道 */
.card { grid-row: auto / span 3; display: grid; }
.card[data-mode="sub"] { grid-template-rows: subgrid; }
.card[data-mode="ind"] { grid-template-rows: auto auto auto; }  /* 回退:独立轨道 */

/* 列轴:卡片跨父网格全部列轨道,内部列 = 全表对齐 */
.card { grid-column: 1 / -1; }
.card[data-mode="sub"] { grid-template-columns: subgrid; }
.card[data-mode="ind"] { grid-template-columns: auto auto auto; }

@supports (grid-template-rows: subgrid) {
  /* 增强样式;不支持的环境停留在 ind 回退形态 */
}

数值出处:Baseline 2023-09(MDN,调研 05§4);gap 16px 取自 WebKit 官方示例(调研 05§5);demo 无其他硬编码布局数值——对齐完全由轨道继承产生。

动效与交互

对齐变化是轨道几何重排,瞬时完成:

  • 「换长度」按钮循环正文长短档位:真实 DOM 文本驱动行高,subgrid 面板的页脚恒定齐平,independent 面板页脚随内容漂移——这就是两个面板的全部差异;
  • axis 切换 data-axis,行轴/列轴两套 DOM 与声明同时切换,无过渡动画;
  • 状态徽标颜色切换带 0.25s 过渡,prefers-reduced-motion 下关闭;
  • 不写任何固定高度伪造对齐——对齐必须由轨道继承产生,这是验收红线。

真实产品案例

  • MDN Subgrid 指南 —— 收录嵌套组件对齐父网格的标准示范(卡片、表单场景),是 subgrid 的权威用法参照(调研 05§4 来源)。
  • 设计系统组件接入页面级网格 —— 组件内部轨道即页面轨道,表单 label 列、卡片页脚行由页面统一裁定(社区公认主战场,编辑性内容,与 MDN 指南场景同源)。
  • 杂志式跨栏排版 —— 标题/导语/正文分层共享行轨道实现基线对齐(编辑性内容,基于 subgrid 的轨道共享能力)。

参数敏感度

参数切到 rows 轴…切到 columns 轴…
axis卡片纵向并排,跨 3 条父行轨道;标题/正文/页脚三行全墙共享,页脚恒齐平卡片横向堆叠,跨全部父列轨道;标签/值/操作三列全表对齐,类似表格
gap父网格行/列间距增大:卡片间距与内部行间距同步变化(轨道定义一并继承)列间距变化同步作用于所有行的三列,全表节奏一致

经验要点:subgrid 的价值全部来自「共享父网格轨道」,先定父网格的列数与行语义,再让子组件 span 对应轨道数;不支持环境保留 independent 回退面板,降级代价一目了然。

适用场景 4
  • 卡片墙的跨卡对齐:标题占第 1 行、正文若干行、页脚恒定对齐在最后一行
  • 表单/数据表的列对齐:label / value / action 三列贯穿所有行,由父网格统一裁定
  • 设计系统组件接入页面级网格:组件内部轨道即页面轨道,不再各自为政
  • 杂志式排版的跨栏基线对齐(标题/导语/正文分层共享行轨道)
何时不要用 4
  • 子网格轨道数与父网格对不上(跨越的轨道数 < 内部条目数)——布局会溢出或折叠,先对齐 span 数
  • 仅需一维排布的场景——Flexbox 更简单,subgrid 只在需要共享父网格轨道时才有意义
  • 深层级嵌套的网格套网格——每层 subgrid 都共享祖先轨道,改动一层会波及全树,层级控制在两层
  • 不支持环境的唯一布局方案——必须保留独立网格回退(见 fallback)
无障碍

subgrid 只共享轨道几何,不改变 DOM 语义——读屏顺序仍按文档流;跨卡对齐依赖视觉位置,信息本身不得只靠对齐传达(标签与值要在同一 DOM 子树内配对);键盘焦点顺序随 DOM,与共享轨道无关;对照演示中两侧面板分别可达,tab 顺序明确。

浏览器支持

Baseline Widely available 自 2023-09(MDN,调研 05§4);Chrome 117(2023-09)补齐后全线可用——具体版本号以 MDN Baseline 日期为准,调研正文只记 Baseline 日期。 · Baseline Widely available (2023-09)

兼容回退

@supports (grid-template-rows: subgrid) 检测后增强;不支持的环境回退为独立嵌套网格(每张卡片自算三行)——内容完整可读,只是页脚不再跨卡对齐。demo 的右侧对照面板(independent)就是这个回退形态,可直接向利益相关者演示降级代价。
