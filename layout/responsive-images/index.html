响应式图片 Responsive Images

srcset · sizes · picture 元素 · fetchpriority

srcset/sizes 让浏览器按『槽宽 × DPR』自选分辨率候选,<picture> 管艺术指导与格式切换,fetchpriority 提示首屏大图的加载优先级——三件套分工,一张图省一半流量。

代码拆解

结构与 DOM

三件套各司其职,DOM 结构由用途决定:

<!-- 仅多分辨率:官方建议直接 img,不包 picture(省流模式可自动降密度,调研 12§1) -->
<img src="hero.jpg"
     srcset="hero.avif 1200w, hero@2x.avif 2400w"
     sizes="(min-width: 900px) 60vw, 100vw"
     width="1200" height="675" fetchpriority="high" alt="…" />

<!-- 艺术指导/格式切换:picture 显式控制,img 兜底 -->
<picture>
  <source type="image/avif" srcset="hero.avif 1200w, hero@2x.avif 2400w"
          sizes="(min-width: 900px) 60vw, 100vw" />
  <source type="image/webp" srcset="hero.webp 1200w" />
  <img src="hero.jpg" width="1200" height="675" alt="…" />
</picture>

关键点:

  • srcset 每项 = URL + 描述符:1200w 宽度描述符或 2x 密度描述符,两者不可混用、不允许重复值;sizes 是「媒体条件–槽宽对」,只在 srcset 用 w 描述符时生效(调研 12§1);
  • 选择规则:有 sizes 时「槽宽 × DPR = 理想宽度」,浏览器下载前从候选里选最接近者;全部不匹配回退 <img src>(调研 12§1);
  • <source> 的 media 条件为假、或 type MIME 不认识,就跳过该 source 选下一个——兜底 img 永远在最后;
  • fetchpriority 是提示性信号非指令(high/low/auto,默认 auto);object-fit/object-position 必须写在子 <img> 上,不是 <picture> 上(调研 12§1)。

样式与参数

本条目的「参数」更多是属性级配置,demo 三个参数全部 JS 型驱动(浏览器选择算法不吃自定义属性):

<img srcset="…640w, …1200w, …2400w"
     sizes="{槽宽}px"
     fetchpriority="high" width="1200" height="675" />

数值出处:

  • 60vw 与 min-width: 900px 断点、1200w/2400w 候选、width="1200" height="675" 配对逐字出自调研 12§1 片段;demo 补的 640w 档为演示补充档,未证实(为让小槽位也有可见切换);
  • 视口档位 390/768/1280px 为社区常见设备基准值,未证实为规范值(手机 CSS 宽 390、iPad 竖屏 768、入门桌面 1280 的社区划分惯例);
  • <picture>:Baseline Widely available 自 2016-03(MDN,调研 12§1);fetchpriority:Chrome/Edge 102+、Firefox 132+、Safari 17.2+(web.dev,调研 12§1)。

动效与交互

这张图「动」的其实是选择算法,不是动画:

  • 切视口/槽宽占比:demo 重写 sizes 属性——srcset/sizes 是「相关变更」,浏览器重跑选择算法并即时换图;demo 每帧读 currentSrc 展示真实命中,不做预测;
  • DPR 参与运算:读数展示 槽宽 × DPR = 理想宽度,DPR 取真实 devicePixelRatio(高分屏 2x 档下槽位更宽、命中更大候选);
  • 艺术指导面板的 media 条件按真实浏览器视口求值(模拟视口改不了它)——拖动真实窗口宽度才能看到宽幅/方幅切换,demo 如实标注这一差别;
  • fetchpriority 只在真实网络加载时起效:demo 写入属性并回显;调研 12§1 实测 Google Flights 给 LCP 图加 high 后 LCP 2.6s→1.9s,Oodle 轮播非首图设 low 省 2s;loading="lazy" 的近视口图若仍被 high 加载,应改用 fetchpriority="low";
  • 候选切换无过渡动画——换图是瞬时资源替换,淡入反而不真实。

真实产品案例

  • Google Flights(web.dev 实测,调研 12§1):给 LCP 首图加 fetchpriority="high",LCP 从 2.6s 降到 1.9s——该案例连同「lazy 图仍被 high 加载时改 low」的细则一起收录在 web.dev fetch-priority 文档;
  • Oodle 轮播(web.dev 实测,调研 12§1):非首图设 fetchpriority="low",页面加载减少 2s——「首图 high、其余 low」的轮播配方出处;
  • MDN <picture> 文档场景三分法(调研 12§1):art direction / 格式切换 / 按设备能力选图的官方分类, AVIF→WebP→jpg 的 source 排列即文档推荐形态(编辑性组合——具体站点采用清单未逐一核实)。

参数敏感度

参数调大会…调小会…
viewport槽宽变大 → 理想宽度上移,命中更大候选(流量换清晰)槽宽收缩 → 命中小候选(清晰换流量);命中标签实时反映
vwShare槽位占视口更满,64%→100% 每档都可能跨过候选边界槽位变窄;20% 的窄图槽在 2x 屏也只配得上一半候选
fetchpriorityhigh 把资源提到加载队列前排——只该给 LCP 图,全员 high 等于没提示low 主动让路——轮播非首图与折叠下方图适用;auto 交还浏览器默认

经验要点:候选按 2x 递增(1200w→2400w)比均匀铺更省流量;sizes 断点跟着布局槽位走,而不是跟着设备型号走;width/height 属性 + 槽位 CSS 比例锁,加载前后零偏移。

适用场景 4
  • 首屏 LCP 大图:srcset 多密度 + fetchpriority="high" + 显式 width/height 防布局偏移(调研 12§1 片段与 Google Flights 实测)
  • 艺术指导:桌面宽幅构图、手机方幅构图——<source media> 按视口换图而不是缩放同一张
  • 格式切换:AVIF/WebP source 在前、jpg 兜底,新格式省流量老浏览器不破
  • 轮播/长列表的非首图:fetchpriority="low"(+ loading="lazy"),调研 12§1 记 Oodle 实测省 2s
何时不要用 4
  • 只有多分辨率却硬包 <picture>——官方建议直接 img srcset,省流模式还能自动降密度(调研 12§1)
  • srcset 里混用 w 与 x 描述符或重复同一值——两者不可混用、不允许重复值(调研 12§1)
  • 把 object-fit 写在 <picture> 上——它必须写在子 img 上(调研 12§1)
  • 给所有图加 fetchpriority="high"——提示性信号全部拉满等于没提示,首屏只保 LCP 图(调研 12§1 语义)
无障碍

候选切换不改变语义:无论浏览器选了哪个候选,alt 只写一次且描述图像内容(不是文件名或尺寸);<picture> 内的 img 是唯一的 alt 载体,source 不参与无障碍树;装饰性图 alt="";demo 的设备框是模拟界面,真实读数(槽宽/DPR/命中候选)以文本呈现,不依赖颜色区分候选。

浏览器支持

<picture> 为 Baseline Widely available,自 2016-03 起主流浏览器可用(MDN,调研 12§1);srcset/sizes 同期落地。fetchpriority:Chrome/Edge 102+、Firefox 132+、Safari 17.2+(web.dev,调研 12§1)。不支持的浏览器忽略该属性并按默认优先级加载,不报错。

兼容回退

<picture> 的兼容回退内建于结构:不带 type/media 的 <img> 是最后兜底,浏览器跳过不支持的 source(media 条件为假或 MIME 不认识)选下一个;不支持 srcset/sizes 的极老浏览器直接加载 img src(写足尺寸的 jpg 兜底);fetchpriority 不被识别时静默忽略——所以「兜底图务必选够用的最大体积」是结构级纪律。

来源 2

起源出自 HTML 规范的响应式图片机制(调研 12§1,MDN/web.dev 一手核对):仅提供多分辨率版本时官方建议直接用 <img srcset> 而不必包 <picture>(省流模式下浏览器可自动选低密度版本);<picture> 用于三种显式控制场景——① art direction 按视口换构图、② 格式切换(AVIF/WebP 兼容回退)、③ 按设备能力选图;fetchpriority 是资源相对优先级的提示性信号(high/low/auto,默认 auto),对应 Fetch API 的 priority 选项。
