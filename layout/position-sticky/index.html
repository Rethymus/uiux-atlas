粘性布局 Sticky position: sticky

position-sticky · 粘滞定位 · 吸顶 · 粘滞区域

元素随容器滚动,触达最近滚动祖先的偏移阈值后停留——position: sticky; top: 20px; 不脱离文档流,一行声明实现吸顶表头与粘滞侧栏。

Web 标准 ★★
实例演示 官方默认

px

吸顶偏移阈值(CSS 型,注入 --sticky-top)。默认 20px 取自调研 05§7 记载的示例 position: sticky; top: 20px; —— 元素滚到距滚动容器顶部 20px 处停住;0px 是全局导航的常见取值方向,留出阈值可以叠出层叠卡片效果。

动效▾
trapoff

JS 型参数(demo 切换 data-trap,给滚动内容包一层 overflow: hidden 祖先)。sticky 只对『最近滚动祖先』生效——中间任何祖先 overflow 非 visible 都会成为它认错的滚动容器,吸顶随之失效。这是 sticky 最常见的生产事故,不是兼容性 bug。

结构与 DOM

两层结构:滚动容器(overflow 可滚的祖先)+ 粘滞元素(声明 sticky 的标题/导航/侧栏)。粘滞元素不脱离文档流,后续内容不被上移。

<div class="scroll-box">          <!-- 最近滚动祖先:粘滞范围的参照系 -->
  <section>
    <h4 class="sticky-head">§1 分组标题</h4>  <!-- position: sticky -->
    <p>…</p><p>…</p>
  </section>
  <section>…</section>
</div>

关键点:

  • position: sticky; top: 20px; —— 元素随容器滚动,触达最近滚动祖先的偏移阈值后停留;不脱离文档流(调研 05§7);
  • 粘滞范围以父容器为界:父容器滚完,sticky 元素跟着走;
  • sticky 只认「最近滚动祖先」——祖先链上任何 overflow: hidden/auto/scroll 都会劫持它(见 demo 陷阱档);
  • Baseline Widely available 自 2015-07(MDN position,调研 05§7)。

样式与参数

两个参数:top 为 CSS 型(—sticky-top),trap 为 JS 型(data-trap 切换陷阱包装层):

.scroll-box {
  height: 300px;
  overflow-y: auto;          /* 最近滚动祖先 */
}
.sticky-head {
  position: sticky;
  top: var(--sticky-top);    /* 20px,调研 05§7 示例值 */
  background: <实底>;         /* 必须实底,否则内容从下方穿透 */
  transition: box-shadow 0.2s ease;
}
.sticky-head[data-stuck="true"] { box-shadow: 0 4px 14px rgba(0,0,0,.18); }

/* 陷阱档:滚动内容与吸顶标题之间插入 overflow 祖先 → sticky 失效 */
.trap { overflow: hidden; }

数值出处:top: 20px 为调研 05§7 记载的示例值;Baseline 2015-07(MDN position,调研 05§7);吸顶阴影与实底为演示层样式。

动效与交互

粘滞是状态变化,不是动画:

  • 元素「随流滚动 → 触阈值停留」瞬时切换;demo 用真实滚动监听驱动状态徽标(标题矩形与容器顶部距离 ≤ 阈值即 stuck),不用定时器伪造;
  • 吸顶瞬间阴影加深(0.2s box-shadow 过渡)提示状态;prefers-reduced-motion 下关闭过渡;
  • 「回到顶部」按钮用瞬时滚动(scrollTo 默认 behavior),不制造无谓平滑动画;
  • 拖动 top 滑杆实时改变阈值:0px 贴顶(全局导航方向),值越大标题停得越低。

真实产品案例

  • MDN Layout Cookbook —— 收录 Sticky footers(内容不足时页脚贴底,Grid/Flexbox 实现)与 Split navigation 配方(调研 05§7)。
  • 长列表分组标题吸顶 —— iOS 分组列表范式的 Web 同源实现:滚到哪组,哪组标题停在阈值处(编辑性内容)。
  • 数据表格表头吸顶 —— 长表滚动时列名始终可见,是后台产品的普遍用法(编辑性内容)。

参数敏感度

参数调大会…调小会…
top标题停在更低处:阈值以上留出更大观察窗,可叠出层叠卡片效果;96px 时吸顶窗占容器近三分之一趋向贴顶:0px 即全局导航形态;多层吸顶时阈值递增(0/48/96px…)才能各层都可见
trapon:overflow 祖先劫持 sticky,标题随内容滚走、徽标恒显「未吸顶」——生产事故可视化off:正常 sticky,标题在阈值处停留,阴影提示状态

经验要点:粘滞范围 = 父容器;吸顶元素必须带实底背景;祖先链保持 overflow: visible 直到滚动容器为止;多层吸顶的阈值与 z-index 先画层级图再写码。

适用场景 4
  • 长列表/长表单的分组标题吸顶——滚到哪组,哪组的标题停在阈值处
  • 数据表格的表头吸顶,长表滚动时列名始终可见
  • 文档站的左侧目录与全局导航吸顶(MDN Cookbook 的 Split navigation 同族用法,调研 05§7)
  • 内容不足时页脚贴底的 Sticky footer 配方(Grid/Flexbox 实现,MDN Cookbook,调研 05§7)
何时不要用 4
  • 祖先链上有 overflow: hidden/auto/scroll 的布局——sticky 被劫持失效,先修结构再用(demo 陷阱档即此形态)
  • 粘滞元素低于其父容器末尾——父容器滚完 sticky 就跟走了,粘滞范围以父容器为界
  • 大面积吸顶层遮挡内容又不提供收起方式——遮挡是布局决策,不是默认正确
  • 同一视口堆叠多个 sticky 层却算不清 z-index 与阈值——阈值设计先画图再写码
无障碍

sticky 只改视觉位置,不脱离文档流——DOM 顺序与读屏顺序不变;吸顶元素不得遮挡获得焦点的控件:键盘 Tab 到被吸顶遮挡的元素时,浏览器会把焦点元素滚入视口,但吸顶层与内容重叠区仍需人工核对;吸顶工具条上的控件保持可达;粘滞状态本身不承载信息,不得只靠『停在顶部』传达分组语义(分组标题文本才是信息载体)。

浏览器支持

Baseline Widely available 自 2015-07(MDN position,调研 05§7)——三引擎全线可用;失效风险来自布局结构(祖先 overflow / 父容器高度),而非兼容性。 · Baseline Widely available (2015-07)

兼容回退

无需兼容性回退;不支持的环境(极老浏览器)元素按普通流滚动,内容仍可达。真正要防的是结构性失效:① 祖先链上任何 overflow: hidden/auto/scroll 都会劫持 sticky(见 demo 陷阱档);② sticky 元素的父容器高度不足时,元素随父容器一起滚走——粘滞范围以父容器为界。

来源 2
