Grid Lanes 瀑布流 CSS Grid Lanes

grid-lanes · css-grid-3 · 瀑布流(曾名 masonry) · grid lanes layout

CSS Grid Level 3 的泳道布局:display: grid-lanes 让条目逐个放入列轨道、另一轴依次堆叠,自动进入剩余空间最多的列——Pinterest 式瀑布流的原生实现。

代码拆解

结构与 DOM

一层结构:泳道容器 + 平级条目——与普通 Grid 相同的 DOM,只换 display 值:

<div class="wall">
  <article class="card">…</article>
  <article class="card">…</article>
  <!-- 条目高度不一,自动放置 -->
</div>

关键点:

  • 新 display 值:grid-lanes(块级)/ inline-grid-lanes(行内),条目放入一个轴的预定义轨道(grid axis),在另一轴自由堆叠(stacking axis)(调研 11§4B);
  • 自动放置规则:未显式放置的条目按已放置条目尺寸,放入剩余空间最大的列(调研 05§5/11§4B);
  • 新属性 fit-tolerance: normal | <length-percentage> | infinite(调研 11§4B);
  • item-flow / item-* 统一提案已被放弃,收敛为 grid lanes(基于 2026-01-21 Working Draft 的 Recent Changes,调研 05§5);
  • 实验性:语法未冻结(Safari 27.2 仍在改名属性,调研 11§4B),生产勿唯一依赖。

样式与参数

三个参数:minTrack / gap 为 CSS 型(—gl-min / —gl-gap),engine 为 JS 型:

.wall {
  display: grid;         /* 回退:所有浏览器(规范推荐双写,调研 11§4B) */
  display: grid-lanes;   /* Safari 26.4+ / Firefox Nightly */
  grid-template-columns: repeat(auto-fill, minmax(var(--gl-min), 1fr)); /* 220px(11§4B 片段;WebKit 示例为 250px 变体) */
  gap: var(--gl-gap);    /* 16px,WebKit 官方示例(调研 05§5) */
}

/* columns 多列兜底(全平台可用,顺序按列) */
.wall[data-engine="columns"] {
  display: block;
  columns: auto var(--gl-min);
  column-gap: var(--gl-gap);
}
.wall[data-engine="columns"] .card { break-inside: avoid; margin-bottom: var(--gl-gap); }

数值出处:minmax(220px, 1fr) 与 gap: 16px 取自 11§4B 可复用片段与 WebKit 官方示例(05§5 用 250px 变体);双写降级写法出自 css-grid-3 规范原文(调研 11§4B);支持数据:BCD display.json → grid-lanes 标记 experimental——Safari/iOS 26.4、Firefox Nightly preview、Chrome 未支持(调研 11§4B,2026-11-22 抓取)。

动效与交互

泳道放置发生在布局阶段,无动画:

  • 条目进入「剩余空间最多的列」是布局算法,瞬时完成;条目增删后各列重新平衡;
  • demo 用 CSS.supports('display', 'grid-lanes') 实时检测并如实报告当前路径:支持 → 泳道;不支持 → 普通网格回退(行带错位肉眼可见,正是泳道要解决的问题);
  • engine 切换 data-engine,双写声明与 columns 兜底两套形态互切;
  • 状态徽标颜色切换带 0.25s 过渡,prefers-reduced-motion 下关闭。

真实产品案例

  • Pinterest —— css-grid-3 草案把「条目放入剩余空间最多的列」的典型示例直接点名 Pinterest 搜索结果页(调研 05§5 原文核对)。
  • WebKit 官方教程站 gridlanes.webkit.org —— 官方交互式教程,配合《Field Guide to Grid Lanes》发布(调研 11§4B)。
  • Chrome for Developers《CSS masonry》 —— Rachel Andrew 代表 Chrome 团队提出的独立布局模式讨论;该文现已加注「代码示例基于早期草案,现为 Grid lanes layout,以 css-grid-3 为准」(调研 05§5)。

参数敏感度

参数调大会…调小会…
minTrack列数减少:每条泳道更宽,单列承载更多条目;400px 时窄容器只剩一列泳道变多变窄:接近 120px 后文字挤压;列数越多,「最多剩余空间」的分配越细碎
gap泳道与轨道间距变大:呼吸感强,堆叠高度差被间隙放大布局更密:高度差视觉更连续,接近无缝瀑布流
enginegrid-lanes 档:支持环境泳道排布、无行带;不支持环境普通网格(行带错位)columns 档:全平台一致的瀑布流,但顺序按列、DOM 顺序与视觉顺序脱节

经验要点:现在就可以写双声明(规范推荐降级),但生产落地仍需 columns/JS 兜底(调研 05§5);顺序敏感内容(步骤流、排行榜)别用泳道;关注 Safari 27.2 后续命名定稿再全面切换。

适用场景 4
  • Pinterest 式图片/商品瀑布流——条目高度不一、逐个放入剩余空间最多的列(Safari 26.4+ / Nightly)
  • 前瞻性渐进增强:现在写双声明,Safari 26.4+/Nightly 已呈现泳道,其余环境普通网格
  • 原型验证泳道排布与 fit-tolerance 行为(规范新属性:normal | <length-percentage> | infinite)
  • 搜索结果流——css-grid-3 草案把 Pinterest 搜索结果页列为典型示例(调研 05§5)
何时不要用 4
  • 生产环境唯一依赖——Chrome 未支持、Firefox 仅 Nightly、Safari 属性仍在改名(调研 11§4B),必须留兜底
  • 按行序阅读的列表——泳道按列填充顺序,视觉顺序与 DOM 顺序脱节(同 columns 的取舍)
  • 需要精确控制条目位置的编辑场景——自动放置「进剩余空间最多的列」不可指定
  • 把双写声明当万能钥匙——普通网格回退对不等高条目有行带错位,严重场景仍需 columns/JS 兜底
无障碍

泳道按列放置会改变视觉阅读顺序,DOM 顺序仍为准(WCAG 1.3.2 语义顺序)——键盘焦点与读屏顺序随 DOM,可能与视觉列序不一致,顺序敏感内容慎用;回退形态(普通网格)与增强形态(泳道)内容相同、可达性等价;fit-tolerance 等新属性不改变可达性语义;实验语法在生产中必须验证回退路径的键盘可达。

浏览器支持

实验性(BCD display.json → grid-lanes 标记 experimental,调研 11§4B,2026-11-22 抓取):Safari / iOS 26.4 起支持;Firefox 为 Nightly preview;Chrome 未支持。WebKit 官方:可在 Safari Technology Preview 234 试用(调研 05§5);Firefox 正式支持时间表调研未查到可靠资料(调研 05§5 如实声明)。item-flow/item-* 统一提案已弃(调研 05§5);Safari 27.2 仍在改名属性(调研 11§4B)——语法未冻结,生产勿依赖。

兼容回退

规范原文给出的优雅降级即双写声明:`display: grid; display: grid-lanes;` —— 不支持的 UA 忽略第二行、回退普通网格(调研 11§4B)。普通网格对不等高条目会产生行带错位(一行的顶端对齐拖累整行),正式落地仍需 columns 多列或 JS 兜底(调研 05§5)。demo 即按双写实现,并用 CSS.supports('display', 'grid-lanes') 实时报告当前路径。

来源 3

起源出自 CSSWG CSS Grid Layout Module Level 3 草案:Grid lanes layout 定义为常见 Web 设计模式——条目逐个放入列轨道,另一轴内依次堆叠;未显式放置的条目进入「剩余空间最多的列」;新增属性 fit-tolerance(normal | <length-percentage> | infinite);新 display 值 grid-lanes / inline-grid-lanes。WebKit 官方示例语法:display: grid-lanes; grid-template-columns: repeat(auto-fill, minmax(250px, 1fr)); gap: 16px; 可在 Safari Technology Preview 234 试用(WebKit 2025-12-19 官宣,调研 05§5);item-flow/item-* 统一提案已被放弃(基于 2026-01-21 Working Draft 的 Recent Changes,调研 05§5);Safari 27.2 仍在微调属性命名(调研 11§4B)。
