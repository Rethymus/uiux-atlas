字体加载策略 Font Loading Strategy

font-display · FOUT · FOIT · 字体加载 · block/swap/fallback/optional

@font-face 的 font-display 决定字体加载期间文本怎么显示:五档取值对应「封锁期/交换期」两段时间参数——web.dev 数值表:fallback 100ms/3s、optional 100ms/无交换。

代码拆解

结构与 DOM

font-display 写在 @font-face 规则里,不是普通 CSS 属性——它约束的是「字体文件加载期间文本怎么渲染」:

<link rel="preload" href="/fonts/brand.woff2" as="font" type="font/woff2" crossorigin />
@font-face {
  font-family: "Brand";
  src: url("/fonts/brand.woff2") format("woff2");
  font-display: swap; /* 五档之一:auto | block | swap | fallback | optional */
}

body { font-family: "Brand", Georgia, serif; } /* 后备字体度量尽量兼容 */

关键点:

  • 三个时间周期(MDN):封锁期(字体未到、文本不可见)→ 交换期(字体未到、后备字可见)→ 失败期(按加载失败处理);
  • font-family 栈里的后备字体不是摆设——交换期显示的就是它,度量差异决定布局偏移;
  • 自托管优先(web.dev 工程惯例);preload 能提前发现字体文件,但会挤占其他关键资源。

样式与参数

两档参数决定 demo 状态机:display(枚举)+ 模拟网络延迟。五档的周期数值表(web.dev,原文核对):

取值封锁期(block)交换期(swap)
auto浏览器自定义浏览器自定义
block2–3 秒无限
swap0ms无限
fallback100ms3 秒
optional100ms无

数值出处:MDN font-display(五档语义)+ web.dev font-best-practices(数值表),均原文一手核对(调研 05§21);auto 的具体周期浏览器未公开统一数值——以 MDN「浏览器自定义」口径为准。demo 的封锁期时长取上界:block 用 3s,auto 演示按 100ms 处理并标注「浏览器自定义」。

动效与交互

demo 用一个与数值表等价的状态机模拟完整加载过程:

  • 「重新加载」按当前参数跑一轮时间轴(0–3.5s):封锁段(文本隐形/占位块)→ 交换段(后备字 Georgia)→ 字体到达点(切到演示 webfont 形态)或失败;
  • 拖动「模拟网络延迟」滑杆改变字体到达时刻:swap 永远等到字体;fallback 在 3s 后放弃;optional 在 100ms 后放弃(本页不再换);
  • prefers-reduced-motion: reduce 时不播放时间轴扫动,直接呈现该组参数的最终结局(状态机一次推进到位);
  • 状态机的相位判定完全按数值表实现,不是装饰动画——demo 里看到的每一次隐形/换字都是表上的一行。

真实产品案例

  • Google Fonts CSS API:其下发的 CSS 默认带 font-display: swap(该服务多年稳定行为)——接入即获得「后备字立即可见、字体到了就换」的默认策略,是 FOUT 策略全球规模最大的分发。
  • Next.js next/font:构建期自托管字体并自动生成带 font-display 的 @font-face,同时用度量调整(size-adjust 一类)对齐后备字体,官方目标就是消灭交换期布局偏移。
  • Vercel 官网(Geist 字体):调研 05§25 核对其 Geist 字体以 npm 包 npm i geist 分发、按需加载——自托管 + 框架级 @font-face 注入是这类工程字体包的标准加载路径。

参数敏感度

参数调大会…调小会…
display → block封锁期最长 2–3s:网络慢时用户盯着空白,FOIT 代价最大—(它是封锁期最长的档)
display → swap0ms 立即显示后备字;字体无论多慢最终都会换上,换字瞬间可能有布局跳动—
display → fallback / optional交换期越短,慢网下越早「锁死」后备字体;optional 连交换期都没有100ms 封锁几乎无感;快网下字体仍能正常换上
loadDelay超过交换期上限后:fallback/optional 永远用后备,swap/block 等到字体低于 100ms 时四档行为趋同——快网络掩盖策略差异

经验结论:策略选择的本质是「最坏网络下你愿意让用户看什么」——正文选 swap(内容第一),品牌字体选 fallback/optional(布局稳定第一)。

适用场景 4
  • 正文字体:swap 或 auto——FOUT 可接受,保证字体最终换上
  • 非关键展示字体(装饰标题、图标字体):optional——网络慢就永远用后备,零布局偏移
  • 品牌关键但可短暂缺席的标题字体:fallback——100ms 内到达才换,否则整页用后备
  • 配合 prefers-reduced-data 预留省流降级(标准已定,实现待落地,调研 11§3)
何时不要用 4
  • 正文用 block——2–3 秒不可见文本(FOIT)直接伤害阅读与 SEO 体验
  • 把 optional 用在「必须出现」的品牌字体上——慢网络下它永远不换上
  • 只声明 font-display 不管后备字体度量——交换时布局跳动的 CLS 代价
  • 对同一字体家族混用多个 display 策略而不区分场景
无障碍

封锁期(block 2–3s、auto 不确定)意味着文本对所有人不可见——屏幕阅读器通常仍可访问 DOM,但低视力用户的放大镜/高对比场景看到的是空白;交换期后备字体与 webfont 的字宽差异会造成文本重排,配度量兼容后备(size-adjust/ascent-override 等)可消除;optional 的「永不交换」策略对可读性最安全,但品牌字形不可依赖。

浏览器支持

font-display:Baseline Widely available(自 2020-01 起,MDN,调研 05§21);Chrome/Edge、Firefox、Safari 均支持五档取值。FontFace API 的 display 描述符提供等价的运行时能力(demo 用状态机模拟,不依赖该 API 的版本差异)。

兼容回退

font-display 不支持的极老浏览器按默认行为(接近 auto/block)处理,文本始终可见,无需修复;真正的兜底发生在字体之外:字体栈里放度量兼容的系统后备字体,把 FOUT/交换期的布局偏移压到最小;再配合 <link rel="preload">(注意会挤占其他资源)。

来源 2

起源font-display 是 @font-face 描述符(MDN 一手核对,调研 05§21):三个时间周期——封锁期(不显示后备字)、交换期(显示后备字)、失败期(按失败处理);五个取值 auto/block/swap/fallback/optional。数值表(web.dev font-best-practices 一手核对):Block=封锁 2–3 秒+交换无限;Swap=0ms+无限;Fallback=100ms+3 秒;Optional=100ms+无。Baseline Widely available 自 2020-01。工程惯例(同文):优先自托管;preload 提前发现字体但挤占其他资源;后备字体度量不兼容会致布局偏移(CLS)。
