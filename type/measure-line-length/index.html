行长与可读性 Measure & Line Length

measure · line length · 行长 · 栏宽 · 65ch

用 ch 单位给正文栏定宽上限:平均行长保持 45–90 字符(含空格),过长难以垂直追踪回行,过短频繁换行切碎节奏。

几何▾

ch

正文列宽上限(以 ch 计)。已核实适读区间为平均 45–90 字符(Butterick);默认 65ch 落在区间中段,是社区常见惯例(未证实),恰便于双向演示。注意 ch 随字体变化:同一 ch 数在不同字体下物理宽度不同。

fontSize16px
px

正文字号。ch 是相对单位——字号变大,同样 ch 数的列物理宽度也变大;故行长(字符数)只由 measure 决定,栏的物理宽度由两者共同决定。默认 16px 为浏览器正文基字号。

动效▾
alignleft

text-align 取值。左对齐保留自然词间空隙;两端对齐把行长差异摊到空格里,窄栏 + 两端对齐易出「词间河流」。行长极长或极短时,对齐方式的缺陷都会被放大。

代码拆解

结构与 DOM

行长约束不需要新结构——它只是给正文列容器加一个 max-width 上限,单位用 ch(「0」字形的宽度),让「字符数」成为可直接声明的量:

<article class="prose">
  <h1>标题不受行长约束</h1>
  <p>正文列才是约束对象……</p>
</article>
.prose p {
  max-width: min(100%, calc(var(--measure-width) * 1ch)); /* 65ch 默认 */
  font-size: var(--measure-font);                          /* ch 随字号缩放 */
}

关键点:

  • 约束对象是正文段落,不是页面容器——标题、导航、页脚各有自己的宽度策略;
  • min(100%, …) 包一层:窄屏时列宽让位于容器,不产生横向滚动;
  • ch 是相对单位,字号变大后同样的 ch 数物理宽度也变大——字符行长只由 measure 决定,物理栏宽由字号与字体共同决定。

样式与参数

三个参数全部经 --measure-* 变量注入:

.prose p {
  max-width: min(100%, calc(var(--measure-width) * 1ch)); /* dimension,单位 ch */
  font-size: var(--measure-font);                          /* dimension,单位 px */
  text-align: var(--measure-align);                        /* left | justify */
}

数值出处:

  • 45–90 字符(含空格):Butterick《Practical Typography》的已核实建议,约合 2–3 个字母表长度;过长导致垂直追踪困难(调研 05§19);
  • 65ch 默认:社区常见惯例(未证实),恰在区间中段,便于向两侧演示;
  • 传统「45–75 字符」说法与 Butterick 45–90 不一致,本条目以已核对来源的 45–90 为准(调研 05§19 注)。

动效与交互

行长是纯静态约束,没有动效;演示里唯一「动」的部分是实时测量:

  • demo 把样例文本拆成逐字符 span,用 offsetTop 分组数出每一行的字符数,得出最长行 / 平均行读数,并在 45–90 区间带上落针;
  • 调整 measure / fontSize / align 时测量即时重算(ResizeObserver 兜住窗口缩放);
  • 判定文案只对拉丁文本生效——中文以「字」计的行长指导值未在本调研核实,中文样例只展示换行行为,不给通过/失败判定。

真实产品案例

  • Wikipedia(Vector 2022 皮肤):宽屏上给正文内容区加了最大宽度限制,长行不再拉满整个视口——行长控制在全球头部站点的一次大规模落地。
  • Medium / Substack 一类长文平台:文章页采用单列窄栏排版,正文区明显窄于页面可用宽度,配合大行距维持阅读节奏,是「窄栏长文」商业产品的通行形态。
  • Kindle 等电子书阅读器:按设备宽度重排文本,始终把行长维持在适读范围——「内容随栏宽重排、行长恒定可控」是电子书排版的立身之本。

参数敏感度

参数调大会…调小会…
measure超过 90 字符后垂直追踪困难,串行/丢行概率上升低于 45 字符后换行过频,节奏被打碎,两端对齐时更易出「河流」
fontSize物理栏宽同步变大(字符行长不变);移动端可能触发折行策略变化物理栏宽收窄;过小字号叠加长行会同时伤害两个可读性维度
alignjustify 把行长不均摊进词间空隙,窄栏时出现明暗「河流」left 保留自然空隙,行尾参差变明显——参差是可接受的默认

经验区间:正文列 45–90 字符,演示默认 65ch(社区惯例,未证实);先定 measure 再定字号,顺序反过来会让「65ch 究竟多宽」随字体漂移。

适用场景 4
  • 长文正文列(文章页、文档站、博客)——首要可读性约束就是行长
  • 配合流式字阶:clamp() 字号 + ch 上限一起写,窄屏自动收窄
  • 多栏布局与卡片内文本块的宽度约束
  • 设计令牌化:--measure: 65ch 一处声明,全文引用
何时不要用 4
  • 把整个页面容器当正文列用——导航/页脚不是正文,不需要 65ch 约束
  • 超宽屏上不做任何上限,让正文行拉到 120+ 字符
  • 表格、代码块等天然宽内容强行套 65ch——它们有自己的滚动/折叠策略
  • 只写像素宽度不写 ch——换字体/换字号后行长悄悄漂移
无障碍

行长过长时,低视力用户与阅读障碍用户垂直追踪回行容易串行/丢行;WCAG SC 1.4.10 Reflow 要求 400% 缩放无双向滚动,给正文列设 ch 上限是满足它的通行手段之一(社区做法,本调研未逐字核对 SC 原文);WCAG 1.4.8 视觉呈现(AAA)对行宽另有约束,常被引用为不超过 80 字符(未逐字核对,建议查 SC 原文后引用)。

浏览器支持

ch 单位属 CSS Values 基础单位,所有现代浏览器广泛可用(MDN);本条目无兼容性风险。文本换行测量用逐字符 span + offsetTop 实现,零依赖。

兼容回退

ch 单位不可用时,退回 max-width 的 em/px 上限或百分比宽度即可——行长约束的本质是「列宽上限」,单位只是度量口径;现代浏览器 ch 均可用,无需兜底。
