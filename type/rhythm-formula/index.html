行高韵律公式 Line-height Rhythm

baseline rhythm · line-height snapping · vertical rhythm · CLREQ line spacing

行高 × 字号 = 基线倍数:先按密度算 lh = fs×m,再吸附到基线半格 lh = round(fs×m/unit)×unit——乘法管张力、加法管秩序,中西文各有硬约束。

Web 标准 ★★
实例演示 官方默认

几何▾

字号 fs(px)。默认 16 = Web 正文锚点(与 8pt 网格、48px 触控目标互质兼容的最小公倍半格来源);demo 里 17 是 Apple iOS Body 官方字号。

结构与 DOM

demo 是一段带韵律标尺的正文块:文字按 fs/lh 真实渲染,半透明横线按吸附后的行高逐行画线——「行盒逐行叠加」直接可见,读数条并列原始值与吸附值:

<div class="rh-block" style="font-size:16px; line-height:24px">
  <span class="rh-line" style="top:24px"></span><!-- 每 24px 一条韵律线 -->
  <p>字号乘倍率出密度,吸附到基线半格出秩序。</p>
</div>
<code>raw: 16 × 1.5 = 24px → snap(4) = 24px(Δ0,天然落格)</code>

关键点:

  • 行高是 px 精确值(由 fs×m 吸附而来),韵律线按同一 px 间隔铺——线与行盒必须重合,错位即公式错;
  • 读数三件套:原始 fs×m、吸附 round(fs×m/unit)×unit、差值 Δ 与吸附后的实际倍率;
  • CLREQ 下限检查单列一行:正文 ≥1.5×、注音 ≥1.5×(规范原文口径)。

样式与参数

三个参数(fontSize/multiplier/unit),全部 JS 型,demo 订阅后实跑两段公式(调研 14§7,实跑核验:16×1.5=24 ✓;15×1.5=22.5 → snap(4)=24 ✓):

① 密度 → 节奏,两步走:

lineHeight(px) = fontSize × multiplier        multiplier 控制相对密度
lh = round(fs × m / unit) × unit              先算密度,再吸附节奏(基线对齐:lh ≡ 0 (mod unit))

② 零依赖 JS:

const snap = (v, u = 4) => Math.round(v / u) * u;
const baselineLH = (fs, m, u = 4) => snap(fs * m, u);
const cjkLH = (fs) => Math.max(1.5 * fs, fs + 8);   // CLREQ 印刷约束推及 Web 下限
baselineLH(16, 1.5);  // 24 —— 实跑 ✓
baselineLH(15, 1.5);  // 24(22.5 吸附,宁上行距)—— 实跑 ✓

③ CSS 落地形态:

.prose { font-size: 16px; line-height: 1.5; }        /* 无单位倍数:16→24、20→30 */
.prose  p + p { margin-top: 24px; }                  /* 段距 = 1 个节奏单元 */
.prose  h2 { font-size: 25px; line-height: 32px; }   /* 大字倍率更小(1.28),px 吸 4px 格 */

数值出处:16px 锚点与 4px 半格 = Material「8dp 主体 + 4dp 半格、文字对齐 4dp 基线网格」官方口径的 Web 化;中西文下限 = CLREQ §5.6.1「单面装行距不应小于当前字号的一半」(即总行高 ≥1.5×)与 §5.5.3.2 注音 ≥1.5 倍基字;Apple iOS Body 17/22、Footnote 13/18 为官方实测表(调研 13§1.3);Web 混排 1.5–1.75 倍带为社区惯例(未证实为规范值)。

动效与交互

  • 调倍率:m 从 1.5 拨到 1.25,16px 的原始行高 20px——恰好落 4px 格,Δ0;拨到 1.4 得 22.4 → 吸附 24,Δ+1.6「宁上行距」;吸附的取舍方向在 Δ 读数里透明呈现;
  • 换字号:17(Apple Body)配 1.3 → 22.1 → 吸附 24(Δ+1.9);官方实际用 22/17≈1.294 且不吸附——「平台实测表 vs 工程网格」的真实分歧,demo 如实呈现(demo 倍率步进 0.05,拨不出 1.294 本身);
  • 换吸附单位:unit 从 4 换到 8,小字号(11–13px)的行高会被推到更粗的台阶——半格存在的意义一目了然;
  • 韵律线随参数即时重画;无自主动画,入场淡入尊重 prefers-reduced-motion。

真实产品案例

  • Apple iOS 文字样式表:Body 17pt/22pt(倍率≈1.294)、Footnote 13/18(≈1.385)、Caption 1 12/16(≈1.333)——官方实测表展示「大字倍率小、小字倍率大」的收敛阶梯(调研 13§1.3,Typography.md Specifications);
  • Ant Design 行高公式:源码 genFontSizes.ts 里 lineHeight = (fontSize + 8) / fontSize——主字体 14 → 行高 22,即「绝对加 8px」而非「乘固定倍率」,与模数尺派生的字阶配对使用(调研 13§3.4,源码逐行核验);
  • CLREQ 中文排版硬约束:W3C《中文排版需求》规定单面装行距 ≥ 字号 1/2(总行高 ≥1.5×)、注音场景 ≥1.5 倍基字、横排行长 ≤48 字——中文产品行高 token 的法定级依据(调研 14§7.3,规范原文逐字提取)。

公式的量纲与边界

变量量纲取值边界退化情形
fs(字号)px实务 11–34(Web 正文 14–18);可继承缩放fs→0 无意义;fs 用 px 时行高吸附值随字号重算,用 rem 则随根字号缩放
m(倍率)无单位正文 1.5–1.75(惯例带,未证实为规范)、标题 1.2–1.4;硬下限 1.5(CJK 正文)m=1 行盒紧贴字形(挤);m≤1.2 读写障碍可读性显著下降;m→2 段落松散
unit(吸附单位)px4 或 8;unit < lh 才有意义unit=0 不吸附;unit ≥ lh 时吸附台阶大于行盒本身,小字号被推爆
lh(行高)px(或无单位倍数)吸附后 ≡0 (mod unit)22.5 → 24 是「宁上行距」;若吸附到 20 则丢呼吸感——方向必须写死
Δ(吸附差)pxΔ
CJK 下限倍率/px行距(半行距×2)≥ fs/2,即 lh ≥ 1.5×fs;注音 ≥1.5× 基字CLREQ 是印刷场景硬约束,Web 混排照搬为下限是工程惯例(如实标注,非规范条文)
段距/标题距px(节奏单元整数倍)与 lh 同格才对齐段距不落格 → 相邻段行线错位,韵律断裂

经验口径:正文 16×1.5=24px 是最大公约数;标题倍率小、正文倍率大,px 全落 4px 格;中西文混排先过 1.5× 再调密度;倍率用无单位写法保证跨字号继承。姊妹条目:vertical-rhythm(韵律的完整落地体系)、baseline-grid(4px 半格的网格本体)、modular-scale-math(字号从哪来)、cjk-typography(CLREQ 其余条款的展开)。

适用场景 4
  • 设计系统行高 token:字号阶 × 倍率带,全部吸附到 4px 半格
  • 中西文混排正文:守 CLREQ 下限(≥1.5×)再谈密度
  • 卡片/列表行高定档:行高为节奏单元,内边距取其整数倍
  • 长文排版:行高、段距、标题上下距同用一个节奏单元(vertical-rhythm 条目的数学内核)
何时不要用 4
  • 行高用无单位数以外的写法跨字号复用(px 行高不能继承缩放)
  • 标题用正文倍率(1.5+)——大字行高比率应更小(1.2–1.4),否则标题块虚胖
  • 吸附单位 ≥ 行高本身——8px 单位配 11px 字号会把小字推到爆
  • 行高低于 1.5 还开注音/拼音——CLREQ 注音场景要求 ≥1.5 倍基字,低于下限标音互相碰撞
无障碍

WCAG 1.4.12 文本间距要求行高可被用户放大到字号 1.5 倍而不破版——用无单位 line-height 并给段落留吸附余量是达标前提;行高 ≥1.5 同时是低视力用户的可读下限;CJK 大字号等效条款见 contrast 条目。行高不是装饰:过密(≤1.2)显著降低读写障碍用户的阅读速度。

浏览器支持

line-height 与间距吸附是纯 CSS 数学,全环境支持;行盒半Leading(leading-trim)尚未普及(提案阶段,社区口径),当前半行距分布由字体度量决定——跨字体对齐要按实测微调。

兼容回退

无兼容性回退可言;真正的风险是把行高吸附得太狠——15×1.5=22.5 吸附到 24 是『宁上行距』(惯例方向),但吸附到 20 就丢了呼吸感。把方向写死:round 永远向可读性侧取整。

来源 3

起源「字号乘比率出层级、行高吸 4px 回节奏」是 Web 排版的工程惯例(调研 14§7,标注为从业者共识);中西文硬约束来自 W3C《中文排版需求》CLREQ:单面装行距不小于字号 1/2、注音场景 ≥1.5 倍基字(规范原文逐字提取);Web 混排 1.5–1.75 倍带为社区惯例,无单一权威规范(未证实,如实标注);Apple iOS 文字样式表(17/22 等)为官方实测值(调研 13§1.3)。

    反向自「模数倍率公式」的精选:搭配关系,原句「字阶的几何级数与行高的基线倍数是同一门「倍数学」:层级向上乘比率,行盒按基线半格吸附。」
