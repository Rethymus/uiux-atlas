小型大写与开放特性 Small Caps & OpenType Features

小型大写 · smcp · font-feature-settings · OpenType features

font-variant-* 高层属性直连 OpenType 特性(smcp/c2sc/liga/zero…),font-feature-settings 是低层兜底:官方明确「能用高层就用高层,不要用它启用小型大写」。

实例演示 官方默认
参数
动效▾
capsall-small-caps

font-variant-caps(高层属性)。small-caps 只转换小写字母(OpenType smcp);all-small-caps 连大写一起转(c2sc+smcp),是眉标/标签的常用档。MDN 映射(本批次补核):若字体无 smcp/c2sc 字形,浏览器从普通大写字形合成近似小型大写;无大小写之分的字符(标点)绝不合成。

ligaturescommon-ligatures

font-variant-ligatures(高层属性)。common-ligatures 启用 fi/fl/ffi 等标准连字(OpenType liga,默认开);no-common-ligatures 关闭(低层等价:font-feature-settings "liga" 0)。代码片段/URL 场景常关连字以逐字符对齐源码。

zeronormal

font-variant-numeric 的 zero 关键字(高层属性,OpenType zero)。给 0 加斜杠与字母 O 区分;Inter 官方提供 slashed zero 特性(调研 05§24)。

代码拆解

结构与 DOM

无特殊结构——特性声明在文本元素上,建议优先用高层 font-variant-*:

<p class="kicker">Uiux Atlas · Typography Notes</p>
<p class="liga">Difficult waffles — efficient airflow.</p>
<p class="num">O0 · 编号 0070</p>
.kicker { font-variant-caps: all-small-caps; }       /* 高层:c2sc + smcp */
.liga   { font-variant-ligatures: no-common-ligatures; } /* 关连字 ≡ 低层 "liga" 0 */
.num    { font-variant-numeric: slashed-zero; }      /* 高层 ≡ "zero" 1 */

/* 低层兜底:仅高层无法表达时用(如风格集 ss01–ss20、花体 swsh) */
.fancy  { font-feature-settings: "ss07" 1; }

关键点:

  • 标签语法:低层标签恰好 4 个 ASCII 字符(U+20–U+7E),写错整条声明无效;on/off ≡ 1/0,缺省 1;非布尔特性用数值选字形变体(如 "swsh" 2 = 第 2 个花体字形)(调研 12§10,MDN 原文);
  • 官方分层指引:能用高层属性就用高层;MDN 明确「不要用 font-feature-settings 启用小型大写」(12§10 原文核对);
  • 特性生效前提是字体文件包含对应 OpenType 特性表;不含表的声明无效但无害。

样式与参数

三个参数全部是 CSS 变量型,各自落到一条高层属性:

.sc-kicker { font-variant-caps: var(--sc-caps); }              /* normal|small-caps|all-small-caps */
.sc-liga   { font-variant-ligatures: var(--sc-lig); }          /* common|no-common-ligatures */
.sc-zero   { font-variant-numeric: var(--sc-zero); }           /* normal|slashed-zero */

数值出处:

  • font-feature-settings Baseline 2016-03;font-variant-caps Baseline 2020-01(MDN,本批次补核);
  • 小型大写关键字→OpenType 映射(MDN,本批次补核):small-caps = smcp(只转小写字母);all-small-caps = c2sc + smcp(大写也转);pcap/unic/titl 为扩展档,MDN 注明并非所有浏览器实现全部值;
  • 缺字形回退(MDN,本批次补核):字体没有小型大写字形时,浏览器从普通大写字形合成近似小型大写;无大小写之分的字符(标点等)绝不合成;低层 font-feature-settings 则只开关字体内已有的表,没有即无效果;
  • 字距 0.08em:本站大写小标纪律同款(src/styles/global.css:852-856);眉标叠加小型大写时同用。

动效与交互

  • 宽度探针:两栏同文本对照(左原样、右特性生效),实测 getBoundingClientRect().width 差——小型大写 Δ>0 说明字形已替换(真 smcp 字形或 MDN 记载的合成字形,宽度无法区分二者);Δ≈0 时如实标注「当前字体可能缺该特性表」;
  • 连字开关:切到 no-common-ligatures,waffle airflow 的 fi/fl 组合宽度立刻变化——连字(liga)默认开启,这是最容易实测验证的特性;
  • 斜杠零:font-variant-numeric 的 zero 关键字,Inter 官方提供(调研 05§24),效果直接可见;
  • 无动画,全部为即时重排,prefers-reduced-motion 无需处理。

真实产品案例

  • MDN 的官方分层指引本身就是行业标准叙事:「能用高层属性就用高层属性,不要用它启用小型大写」写在 font-feature-settings 参考页正文(12§10 原文核对)——低层属性被官方定位为「风格集、花体等高层表达不了的场景」的兜底。
  • Inter 字体:官方仓库列出 slashed zero、表格数字等 OpenType 特性(调研 05§24),被 Figma、GitLab、NASA 采用——特性表质量决定 CSS 声明的实际效果,选字体就是选特性供给。
  • 本站 uiux-atlas:元数据小标采用「全大写 + 0.08em 字距」而非小型大写(源码 src/styles/global.css:852-856)——系统字体栈无法保证 smcp 字形供给,全大写是零依赖的可控替代;这是「特性依赖字体前提」在真实工程里的取舍。

参数敏感度

参数调大会…调小会…
capsall-small-caps 整行转小型大写(眉标常用);缺字形时按 MDN 规则合成normal 恢复原大小写;短标签之外慎用,大段正文难读(MDN 无障碍提示)
ligaturescommon-ligatures 回到默认连字,fi/fl 融为一体、排版更顺no-common-ligatures 拆开连字,代码/URL 场景逐字符更清晰
zeroslashed-zero 防止 O/0 混淆(订单号/验证码防错)normal 保留字体默认 0 形

经验法则:小型大写只给短标签;先确认字体特性表(CSS 声明只是开关);高层属性优先,低层留给风格集;合成行为因浏览器而异,关键界面实测。

适用场景 4
  • 眉标/章节小标:all-small-caps + 0.08em 字距(本站大写小标纪律同款字距,src/styles/global.css:852-856)
  • 法律/学术文本中的缩略语:small-caps 保留原大小写语义
  • 代码块与 URL:关连字(no-common-ligatures)保 fi/fl 逐字符清晰
  • 风数百变的高级用法:风格集 ss01–ss20/花体 swsh 只能用低层 font-feature-settings 表达(12§10)
何时不要用 3
  • 用 font-feature-settings 启用小型大写——MDN 官方明确禁止此用法,高层 font-variant-caps 才有合成回退与语义(12§10)
  • 大段正文 all-small-caps——MDN 记载对阅读障碍(如 dyslexia)用户可能难读(本批次补核)
  • 中文正文套小型大写——smcp 只作用于拉丁字母;中文字形不受影响,混排时视觉重量需单独核对
无障碍

MDN 无障碍提示(本批次补核):大面积 all-small-caps/all-petite-caps 文本对认知障碍(如阅读障碍)用户可能难读——小型大写只用于短标签、眉标与缩略语;小型大写不改变文本语义,读屏仍按原大小写朗读;合成字形与真 smcp 字形的可读性可能不同,关键界面以实测为准。

浏览器支持

font-feature-settings Baseline Widely available(自 2016-03,调研 12§10);font-variant-caps Baseline Widely available(自 2020-01,本批次补核 MDN);petite-caps/unicase 等扩展关键字属 CSS Fonts L4 语法,MDN 注明并非所有浏览器实现全部值——用前以 @supports/CSS.supports 实测。

兼容回退

字体缺特性表时:高层 font-variant-caps 按 MDN 记载回退为「从大写字形合成」;低层 font-feature-settings 只开关字体内已有的特性表,没有该表即无效果(声明无害)。两者都以不破坏文本为底线——特性失效不产生布局错误,只是观感差异。
