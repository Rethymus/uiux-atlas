## Structure & DOM

A fluid type scale needs no extra DOM — it is a **layer of CSS custom-property tokens**: define `--step-0..5` on `:root`, and components pick them up semantically.

```html
<body>
  <h1 class="step-5">Headlines that scale with the viewport</h1>
  <p class="step-0">Body copy keeps its base size.</p>
</body>
```

```css
:root {
  --step-0: clamp(1rem, 0.875rem + 0.4167vw, 1.25rem);
  --step-1: clamp(1.25rem, 1.0938rem + 0.5208vw, 1.5625rem);
  /* … --step-2..5 generated the same way */
}
```

Key points:

- The viewport range `minViewport/maxViewport` and the size range `minSize/maxSize` are two parallel rulers: slope = (max−min)÷(maxVw−minVw), with viewports converted to rem at a 16px root;
- Each step multiplies both its min and max by the `ratio` (Utopia allows separate ratios per side; this entry simplifies to one);
- Generated clamp values are rounded to 4 decimals, matching Utopia's output precision.

## Styling & Parameters

All five parameters are JS-type (no cssVar): the demo subscribes to the parameter panel, recomputes the ladder live with the formula above, writes `--step-0..5` onto the preview area, and shows the generated code.

```css
/* Generated by the demo defaults: 480px→1440px, 1rem→1.25rem, ratio 1.25 */
:root {
  --step-0: clamp(1rem, 0.875rem + 0.4167vw, 1.25rem);
  --step-5: clamp(3.0518rem, 2.6703rem + 1.2716vw, 3.8147rem);
}
h1  { font-size: var(--step-5); line-height: 1.05; }  /* tighten leading on display sizes */
h2  { font-size: var(--step-3); line-height: 1.15; }
p   { font-size: var(--step-0); line-height: 1.6; }   /* body ≥1.5 (WCAG 1.4.12) */
```

Where the numbers come from:

- Formula and output shape = Utopia's fluid type scale calculator (research 05 §13, first-hand measured output: `--step-0: clamp(1.125rem, 1.0739rem + 0.2273vw, 1.25rem)` — the demo formula reproduces that line byte-for-byte from the same inputs);
- Ratio 1.25 = a Utopia selectable ratio, modularscale's 4:5 major third (research 05 §13/§17);
- The `maxSize` default of 1.25rem matches the max in the Utopia sample above; the `minViewport/maxViewport` defaults of 480/1440px are this entry's task-spec values, while Utopia's sample back-solves to ≈360/1240px (not directly documented — both stated side by side).

## Motion & Interaction

The scale is a static token layer — "motion" only happens as the viewport changes:

- While the viewport resizes continuously, clamp output changes continuously: no jumps and no transition needed;
- Dragging the demo's simulated-viewport slider is equivalent to resizing the browser; the px badges use the same formula, so you can probe both ends from a fixed window;
- No `prefers-reduced-motion` handling is required (this entry produces no animation).

## Parameter Sensitivity

| Parameter | Turning it up… | Turning it down… |
| --- | --- | --- |
| `minViewport` | shifts the whole curve right: small screens (e.g. 375px) sit pinned at the min values and the mobile scale goes static | starts interpolation earlier — sizes already grow on phones, shortening the flat region |
| `maxViewport` | flattens the slope: desktop scaling becomes subtler and the ceiling arrives later | steepens the slope: desktop size jumps get exaggerated and the ceiling arrives early |
| `minSize` | raises the floor of body and every step, closing the gap to `--step-5` and weakening contrast | pushes the body floor toward 0.8rem, hurting long-form readability |
| `maxSize` | enlarges body on big screens and steepens the slope — the whole ladder gets louder | approaches `minSize`, the slope approaches zero and the scale degenerates to static; below `minSize` the clamp semantics invert (min wins) |
| `ratio` | inflates higher steps exponentially — `--step-5` rushes toward its ceiling for a poster-like look | near 1.1 the steps crowd together and hierarchy shifts to weight rather than size |

Working ranges: viewport 360–1440px, body from 1–1.125rem, ratio 1.2–1.333 (Utopia's sample and modularscale's common stops); keep body within 1–2 steps of range and tighten leading per step.
