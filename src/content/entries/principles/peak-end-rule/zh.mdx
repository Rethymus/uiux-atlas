## 结构与 DOM

演示是一段**8 时刻的体验旅程曲线**(内联 SVG)+ 两根对比条:

```html
<svg viewBox="0 0 380 190">
  <path class="pe-area" d="…" />
  <path class="pe-curve" d="M26,150 L81,133 …" />
  <circle class="pe-dot-peak" cx="81" cy="87" r="6" />  <!-- 第 3 时刻 = 峰 -->
  <circle class="pe-dot-end"  cx="354" cy="150" r="6" /> <!-- 第 8 时刻 = 终 -->
</svg>
```

关键点:

- 曲线 8 个点由固定基线生成,只有**第 3 点(峰)**与**第 8 点(终)**被参数覆写——「其余时刻不动」本身就是定律的表达:中间过程的改动对记忆影响最小;
- 结论不走读图:全程平均与峰终预测两组数值**同时**以条形+文本呈现;
- 预设按钮直接 `store.set("peak"/"ending", …)`——参数面板的滑块随之联动,演示与面板共享同一 store。

## 样式与参数

```tsx
// peak / ending 是 JS 型参数;preset 点击时反向写入 store
const journey = BASE.map((v, i) => (i === 2 ? peak : i === 7 ? ending : v));
const avg = journey.reduce((a, b) => a + b, 0) / journey.length;
const peakEnd = (peak + ending) / 2;
```

- `peak` 默认 **8**、`ending` 默认 **2**(=「烂尾」预设):一段高开低走的旅程,记忆预测只有 5.0,而全程平均 4.4——两者的差距就是定律的可见度;
- `(峰值+结尾)/2` 是**教科书化简**,不是 Kahneman 1993 原始实验公式——面板与 schema 都按此口径如实标注;
- 三种预设:烂尾(8/2)、平顺(5/4)、惊喜收尾(6/9)——6/9 的记忆预测 7.5 高于其全程平均 5.0,正是「结尾投资回报率最高」的量化演示。

## 动效与交互

- 拖动参数时曲线用 `transition: d 0.3s ease` 平滑重排(`d` 作为 CSS 属性可过渡,不支持时退化为直接跳变,无兼容风险);两根对比条宽度同步 0.3s 过渡;
- `prefers-reduced-motion: reduce` 下两处过渡全部取消,数值即时更新;
- 预设按钮无动画,点击即写 store——「惊喜收尾」按钮本身不投惊喜,惊喜留给真实产品的峰值时刻。

## 真实产品案例

- **Mailchimp 发送成功动画**:点击发送后的 High-five 小拳拳动画——把「终」做成整段旅程的记忆锚点,是 lawsofux/NN/g 反复引用的峰值收尾案例(调研 07§25);
- **Uber 的时间感知设计**:调研 07§25 记载 Uber 用时间感知(精确到分钟的 ETA、行程进度可视化)降低取消率——把「等待」这个负面峰值专门拆掉;
- **NN/g 的收尾清单**:Lexie Kane 的 The Peak–End Rule 文章建议专门设计旅程的收尾时刻——提交成功页、任务完成态、退出确认都值得独立打磨,而不是「顺手带过」(调研 07§25 相关阅读)。

## 参数敏感度

| 参数 | 调大会… | 调小会… |
| --- | --- | --- |
| `peak` | 峰终预测线性上升;但峰从 8→10 的记忆增益,远小于终从 2→9 的增益(两条参数同权重) | 峰平庸后,旅程只剩「平稳」,记忆预测贴近全程平均 |
| `ending` | 6/9 预设下预测 7.5——同样强度的投入,投在结尾的记忆回报最高 | 烂尾:峰值再高也被结尾拖住,这正是默认值 8/2 想让人看见的 |
| `preset` | 一键写入 peak/ending,滑块联动——方便复现三种典型旅程 | custom:保持手动值,预设不再覆盖 |

经验结论:资源有限时**优先投结尾,其次投峰值**,中间过程「不烂即可」;负面峰值(等待、报错)的消除优先级高于正面峰值的堆砌——负面的记得更牢(调研 07§25)。
