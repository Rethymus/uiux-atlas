## 结构与 DOM

演示是一张**回忆实验卡**:随机数字串按块长分组展示 3 秒 → 隐藏 → 输入回忆 → 按位计分:

```html
<div class="ml-digits">
  <span class="ml-digit">4</span>
  <span class="ml-digit-group-gap"></span> <!-- chunk 边界 -->
  <span class="ml-digit">9</span>
</div>
<input class="ml-input" id="ml-recall" inputmode="numeric" />
```

关键点:

- 数字串生成、隐藏、计分全部 demo 内闭环,零外部依赖;
- 分块边界用一块占位宽度表达(组间 gap 0.75em),数字卡本身不动——**分组靠间距,不靠容器**,这是与「共同区域」原则的分工;
- 回忆输入框带可视隐 label 与 `inputmode="numeric"`,Enter 直接触发记分。

## 样式与参数

```tsx
// digits / chunk 是 JS 型参数:demo 订阅 store 驱动
const [digits, setDigits] = useState(() => store.get("digits") as number);
useEffect(() => store.subscribe(() => {
  setDigits(store.get("digits") as number);
  setChunk(store.get("chunk") as number);
}), [store]);
```

- `digits` 默认 **10**:刻意略超 7±2 上界,不分组时大多数人漏 1–3 位,体感最明显;lawsofux 原文:平均人只能保持 7±2 项(调研 07§24);
- `chunk` 默认 **3**:与「电话号码 3–4 位一组」同构;10 位数字按 3 分块 = 4 个组块,工作记忆只需持 4 项;
- 展示固定 3 秒,是 demo 节奏选择;「重看」由按钮触发,不做自动重播(避免闪现内容,呼应 WCAG 2.2.1 可调时限的精神)。

## 动效与交互

- 「开始一轮」→ 生成数字串 → 展示 3s → 隐藏并自动聚焦输入框(聚焦发生在用户主动发起的流程内,不是页面加载即抢焦点——APG 键盘实践条目里「页面加载不要主动设初始焦点」的边界案例);
- 「记分」(或 Enter)→ 按位对照:绿色=命中,红色=错漏,并记录本轮最佳;
- 「再来一轮」生成新串,可分别用 chunk=0 / chunk=3 各打几轮,对比正确率;
- 无动画;阶段切换用文本提示而非动效——记忆实验里动画本身就是干扰变量;
- 记分后数字卡着色:命中绿、错漏红——**颜色不是唯一通道**,每格仍有数字文本(呼应 SC 1.4.1);
- Enter 记分、Tab 顺序:开始 → (展示期不可交互) → 输入框 → 记分按钮 → 再来一轮;
- 输入框自动聚焦不抢页面初始焦点:仅发生在用户点「开始一轮」之后。

## 真实产品案例

- **电话号码输入框**:国际通行的 3–4 位分组(如 `138 8888 8888`)是 chunking 最家喻户晓的落地——把 10 个独立数字变成 3–4 个组块,输入与复核都更不易错;
- **信用卡卡号四位分组 + 逐位自动前进**:支付表单把 16 位卡号按 4 位分块并自动跳格,把「持住 16 项」压成「持住 4 项」,是电商表单的事实标准做法;
- **iOS 设置列表的分组(编辑性泛例)**:把几十个设置项切成 3–7 项一组的分组列表,配合 section 标题,是移动系统设置页的通行范式;组内持组、组间扫读,显著降低回忆负担(此处为泛化惯例,lawsofux 未见点名具体产品)。

## 参数敏感度

| 参数 | 调大会… | 调小会… |
| --- | --- | --- |
| `digits` | 超过 ~9 位后不分组命中率急剧下降——7±2 的体感墙;14 位几乎必败 | 4–6 位不分组也轻松,实验失去张力 |
| `chunk` | 块长 4–5 时组块更少但每块更难「记成一个整体」 | 0 = 不分组,作为对照基准;1 位一组过碎,反而添乱 |

经验区间:`digits` 8–12、`chunk` 3–4 时对照最鲜明;最终教学结论是 lawsofux 的原文告诫——**不要拿「神奇数字七」为不必要的设计限制辩护**,个体容量因先前知识与情境而异(调研 07§24)。
