## 结构与 DOM

演示是一组**同一功能、两种完成度**的 A/B 自测:两张 ATM 风格卡片,按钮布局与数量完全一致,只有装饰层不同。

```html
<div class="au-cards">
  <section class="au-card">                <!-- 素坯对照 ATM-A -->
    <h3>素坯终端 ATM-A</h3>
    <div class="au-menu">…4 个功能按钮…</div>
    <p class="au-status" aria-live="polite">用时 — ms · 误点 0</p>
    <label class="au-rate">感知易用性 <input type="range" min="1" max="7" /></label>
  </section>
  <section class="au-card" data-beauty="refined">  <!-- 精修 ATM-B -->
    …结构与左侧逐字节一致…
  </section>
</div>
<div class="au-compare">感知分差 +1 · 实测用时差 0 ms · 误点差 0</div>
```

关键点:

- 两侧的**功能层逐字节一致**(4 个按钮、同一任务「查询余额」),`data-beauty` 只切换右侧卡的装饰层——这是受控变量:任何评分差只能来自完成度;
- `handicap` 缺陷对**两侧等量**注入(同一缺陷、同一位置),干净地隔离出「美观容忍」这一变量;
- 结论不走读图:用时、误点、感知分差、实测差异全部以文本呈现(`aria-live` 同步)。

## 样式与参数

```css
/* 完成度只写在装饰层:圆角、描边色、阴影、头部下划线 */
.au-card[data-beauty="refined"],
.au-card[data-beauty="premium"] {
  border-color: color-mix(in srgb, var(--au-accent) 45%, transparent);
  border-radius: 14px;
  box-shadow: 0 6px 20px rgba(0, 0, 0, 0.1);
}
.au-card[data-beauty="premium"] { border-radius: 18px; /* + 渐变头部、更大留白 */ }
```

- `beauty` 三档:**plain**(与素坯完全一致,退化为 A/A 自对照)→ **refined**(14px 圆角 + 柔和阴影 + accent 主色)→ **premium**(再叠渐变头部、18px 圆角与更大留白);全部为 demo 教学档位;
- `handicap` 两个演示缺陷值:**small-target = 按钮 18px 高**、**slow-response = 成功反馈延迟 900ms**——均非定律数值,schema 如实标注;
- `accent` 经 `--au-accent` 注入,只上装饰(下划线、hover、成功态),文字保持固定深色;
- 实验出处数值:**26 种 ATM 界面变体 × 252 名参与者**(Kurosu & Kashimura 1995,日立设计中心;12 补研 §14)——这是定律的官方实证,不是可调参数;
- 评分量表 1–7 为 demo 教学选择(原实验用语义差异量表),用途是自测相对差而非复现原实验绝对值。

## 动效与交互

- 点击任意按钮即开始计时,点中「查询余额」结束:用时 = 首次交互 → 成功的真实毫秒数;`slow-response` 档在成功前插入 900ms「处理中…」态,两侧同样迟缓;
- 感知评分用**原生 `input[type=range]`**,数值文本同步,无自定义组件;
- 底部对照条在两侧都完成后才给出结论,未完成时如实显示占位文案;
- `prefers-reduced-motion: reduce` 下按钮过渡取消,成功态只变色不动效——评分与计时不受动效开关影响。

## 真实产品案例

- **日立 ATM(Kurosu & Kashimura 1995 的实验载体)**:26 种界面变体在真实 ATM 布局上检验,252 名被试的美观评分与感知易用性相关更强——定律第一次被量化就是在产品上,不是在实验室抽象任务里(12 补研 §14);
- **Apple 全局导航与 macOS Big Sur 半透明侧栏**:站内调研 03§1 记载的审美打磨生产参照——高完成度材质让系统级界面读作「精致、可信」,是审美投资转化为感知品质的直接例证(编辑性引申自调研 03§1);
- **警戒案例:Apple Liquid Glass 的全屏化批评**:NN/g 批评其全屏使用伤害可读性(调研 03§2)——当审美升级压过可读性,审美可用性效应就反转为伤害,「美观」不再能掩盖问题。

## 参数敏感度

| 参数 | 调高/换档会… | 调低/换档会… |
| --- | --- | --- |
| `beauty` | premium:渐变头部 + 大圆角 + 留白,感知分差通常拉到最大 | plain:两侧完全一致(A/A 自对照),感知分差应趋近 0——这是检验自己评分是否公允的基线 |
| `handicap` | 两档缺陷都让「实测差异」出现:18px 热区拉高误点,900ms 延迟拉高用时——但精修侧的感知分往往跌得更少,容忍效应可见 | none:回到纯完成度对照,实测两侧打平,只剩感知分差 |
| `accent` | 只改装饰层颜色,功能与数据不变——可验证「仅配色变化」是否足以移动你的感知分 | 对素坯卡无效(不消费该变量),对照侧始终中性 |

经验结论:**美观是合法的可用性投资,但要在测试规程里设防**——首轮可用性测试用未抛光线框稿,或在抛光版上强制测量任务用时与错误率;好评不能替代指标(12 补研 §14)。
