## 结构与 DOM

错误抖动演示是「一个错误源 + 两条实现轨」:密码框(错误源)+ 水平抖动的字段轨(CSS keyframes 版)与字段轨(弹簧速度注入版)。两轨结构相同,只是动引擎不同:

```html
<label class="sd-lane-label">CSS keyframes(衰减版)</label>
<div class="sd-field" data-error="true" data-shake="true">水平抖动</div>

<label class="sd-lane-label">弹簧速度注入(Motion velocity)</label>
<div class="sd-field" data-error="true">
  <motion.div style="x"><!-- motion value 驱动 --></motion.div>
</div>
```

关键点:

- 错误必须同时有**非动效承载**:描边变红 + 文案(`role="status"` 播报)——抖动只是强化,不是唯一信号;
- CSS 轨的 `@keyframes` 由 JS 按 A/λ **采样生成**(事件级重生成样式表,不是逐帧写 CSS 变量——变量逐帧改会整棵子树样式失效,调研 10§7.4);
- 弹簧轨把速度交给欠阻尼弹簧,Motion 的 `velocity` 参数默认取「当前值速度」,显式传入即注入初速度(调研 10§4.2)。

## 样式与参数

两个参数(JS 型,驱动两条轨):

```ts
// 上轨:衰减 keyframes 采样(自推导,调研 10§4.3 示例同构)
// x(t) = A·e^(−λt)·sin(ω_d t);ω_d 取每拍半周期 0.1s → 包络每拍 ×e^(−λ·0.1)
const beats = Math.ceil(Math.log(20) / (lambda * 0.1)); // 包络→5% 的拍数
// λ=6, A=10 → 5 拍 / 500ms;振幅序列 10→7.4→4.1→2.2→1.2→0.7(每拍 ×0.74)

// 下轨:弹簧速度注入(调研 10§4.2 档位)
animate(x, 0, { type: "spring", stiffness: 500, damping: 24, velocity: -amp * ω_d });
// ζ = 24/(2√500) ≈ 0.536 → 过冲≈13.5%;ω_d = √500·√(1−ζ²) ≈ 18.9 rad/s
// 初速度 v₀ = A·ω_d(x(t)=A·e^(−λt)sin(ω_d t) 在 t=0 的导数)→ 首拍振幅≈A
// 该轨的 λ = ζω₀ ≈ 12(固定档位决定)
```

数值出处:

- **animate.css shakeX 是等幅特例**:`±10px` 每拍等幅、默认时长 1s——「适合通知,不太像物理失败」(调研 10§4.1);
- **衰减公式与 ζ 定义**:运动方程 `m·x''+c·x'+k·x=0`、`ζ=c/(2√(mk))`、`λ=ζω₀`、`ω_d=ω₀√(1−ζ²)`、包络半衰期 `ln2/λ`——维基 Damping ratio 原文,且与 Motion 源码 `spring.ts` 的 `exponentialDecay/calcAngularFreq` 逐字对应(调研 10§4.3);
- **弹簧档位 500/24**:ζ≈0.536、过冲≈13.5%、λ≈12、包络→5%≈250ms(调研 10§4.2);
- **macOS 登录框抖动**:公认系统行为,但 **Apple 未公开参数,未证实**;社区复刻收敛在水平 4–6 拍、单拍 ~10px、总时长 ~0.5s——社区经验仅供等感参考(调研 10§4.4);demo 的每拍 0.1s 即按此量级取。

## 动效与交互

- **触发**:密码少于 4 位点「登录」(或回车)→ 两轨同时抖动 + 描边变红 + `role="status"` 文案;密码合规则不抖、显示通过;
- **两轨对照**:上轨按公式采样成静态 keyframes(每次触发重播同一条曲线);下轨把初速度注入欠阻尼弹簧让物理自己衰减——**连按/中断天然连续**(Motion 物理弹簧从当前值速度续接,调研 10§7.3);
- **为什么推荐速度注入**(调研 10 签名巧思 4):keyframes 版每次触发都从振幅 A 满血开始,连按会「重置跳变」;速度注入版从当前状态接力,物理连续;
- **reduced-motion**:两条轨都不动,只保留描边变红与文案——错误信息绝不依赖抖动传达;
- 性能:两轨都只动 `transform: translateX`(合成器属性)。

## 真实产品案例

- **macOS 登录界面**:密码错误时输入框水平抖动,是苹果生态最著名的错误抖动案例;参数未公开,社区复刻按 ~0.5s/±10px 等感(调研 10§4.4);
- **animate.css shakeX**:等幅抖动的事实标准(±10px/1s),被大量表单库直接引用作错误提示——「等幅特例」的出处(调研 10§4.1);
- **Motion 生态表单校验**:velocity 注入式抖动(Motion 文档 `velocity` 参数:「默认取当前值速度」),React Hook Form 等生态的常见自定义实现思路(调研 10§4.2)。

## 参数敏感度

| 参数 | 调大会… | 调小会… |
| --- | --- | --- |
| `amp`(A) | 首拍位移更大、错误感更强;>16px 在窄输入框上会撞到相邻 UI | 温和提示;≤4px 几乎不可察觉,抖动失去意义 |
| `lambda`(λ) | 包络衰减更快,拍数变少、总时长缩短(λ=20 → 2 拍/200ms,「顿一下」) | 衰减更慢、拍数更多(λ=3 → 10 拍/1s,接近等幅 animate.css 的观感) |
| 弹簧档(固定) | 下轨 500/24 定死 ζ≈0.537:过冲≈13.5%、包络 250ms——比上轨默认 λ=6 衰减更快 | 想要更慢衰减需同时降 damping(ζ↓)与 stiffness(ω₀↓),参考 damping-craft 条目 |
| 首拍方向 | 先向左(与调研 10§4.2 velocity:−2000 一致);方向本身无语义,关键是全程同向起步 | — |

经验区间:A 8~12px、λ 5~8(3~5 拍、0.3~0.5s);错误抖动总时长超过 0.6s 就从「提示」滑向「惩罚」,低于 0.2s 又读不出「失败」。
