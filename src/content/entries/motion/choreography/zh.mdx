## 结构与 DOM

编排的载体是**一个语义容器 + N 个子项**:容器不参与动画,子项各自声明同一条入场动画,差异只在 `animation-delay`(按序号递增)与统一的 `--ch-from` 初态位移:

```html
<ul class="list"><!-- 语义容器:动画不改变可达性结构 -->
  <li style="--i: 0">…</li>
  <li style="--i: 1">…</li>
  <li style="--i: 2">…</li>
</ul>
```

关键点:

- 交错的是**起点**不是时长:每个子项都跑满自己的 250ms,第 i 项在 i × stagger 后启动;
- `--i` 由模板/JS 写入,纯 CSS 侧也可用 `:nth-child` 手写,两种写法等价;
- 整组共享**一个进入方向**(`--ch-from`),方向是组级语义,不是逐项花样;
- 列表保持 ul/li 语义:动画只作用于 opacity/transform,可达性树从第一帧完整,读屏立即读到全部子项。

## 样式与参数

`stagger` 与 `direction` 都是 JS 型参数(demo 订阅 store 后内联下发 delay 与 `--ch-from`);时长/曲线固定取 M3 官方配对:

```css
.item {
  animation: enter 250ms cubic-bezier(0, 0, 0, 1) both;  /* std-decel 250ms:进入屏幕(官方配对) */
  animation-delay: calc(var(--i) * var(--stagger, 40ms));
}
@keyframes enter {
  from { opacity: 0; transform: var(--ch-from, translateY(14px)); }
  to   { opacity: 1; transform: none; }
}
/* 退场:反向序交错,200ms std-accel cubic-bezier(0.3, 0, 1, 1)(官方配对) */
.item.exit { animation-name: exit; animation-duration: 200ms; animation-timing-function: cubic-bezier(0.3, 0, 1, 1); }
@media (prefers-reduced-motion: reduce) {
  .item { --ch-from: none; }  /* 去位移、保留交错节奏(纯 opacity 淡入) */
}
```

数值出处:进入 std-decel 250ms / 退出 std-accel 200ms 出自 M3 官方配对表(调研 04§1.4);「进入比退出更长」同为官方准则。stagger 间隔官方未给推荐值——demo 默认 40ms 为社区常见值,未证实;方向语义出自 M3《Transition patterns》Enter/exit 模式(通知自顶部、抽屉自侧缘、sheet/键盘自底部,调研 04§3.3)。

## 动效与交互

- **两组按钮、两种编排**:入场按自然序交错,退场按反向序交错(最后一项先走)——反向退场把视线从末项收回到起点,与「退得更快」配合;
- **总铺开时间 = stagger × (n−1)**:demo 实时标注;先定「最后一项何时落地」,再回推 stagger;
- **方向即空间模型**:整组一个方向,且方向必须与内容的真实来源一致(列表自下、通知自上、抽屉自侧,M3 官方语义);
- **与 JS 编排的关系**:Motion 的 delay/stagger 是同一编排的库化表达(支持负 delay = 中途开始,调研 04§1.3),见 stagger-orchestration 条目;纯 CSS 版零依赖、无水合成本;
- **性能**:只动画 opacity 与 transform(合成器属性,web.dev 底线,调研 04§1.5);长列表(>20 项)不要整段交错,首屏之外改用滚动触发(见 scroll-driven-animations 条目);
- **reduced-motion**:去位移、保留交错节奏(纯 opacity 淡入)——大平移是前庭触发源(调研 04§6.1)。

## 真实产品案例

- **snackbar/toast 定向展开**:M3 官方描述 snackbar 依位置定向展开——底部出现则向上、顶部出现则向下(Android 系统行为,调研 04§3.3),这是「方向=空间模型」最典型的产品落法;
- **系统通知与抽屉**:通知自顶部、抽屉自侧缘、sheet/键盘自底部——M3《Transition patterns》对 Android 系统进入方向的官方归纳(调研 04§3.3);
- **Google 搜索的转场即编排**:Luke W 记载 Google 搜索用「页面滑入即转场」把加载指示并入转场来营造即时感(调研 04§2.2)——方向性入场 + 内容快速呈现的组合拳。

## 参数敏感度

| 参数 | 调大会… | 调小会… |
| --- | --- | --- |
| `stagger` | 点名感更强,组像逐项确认;>80ms × 5 项时末项要等 400ms+,关键内容不宜排在尾部 | 趋近齐发;0 = 同步入场,编排感消失(只剩方向性) |
| `direction` | 换方向即换空间暗示:up=内容到来、down=通知抵达、侧向=面板进出;选错方向暗示与来源打架 | fade 关掉位移只留节奏——即 reduced-motion 降级形态,也是最保守的编排 |

选型口诀:方向由内容的真实来源决定(不许倒置);stagger 由「末项允许的落地时刻」回推;入场 250ms / 退场 200ms 直接取官方配对,不要再自行加长。
