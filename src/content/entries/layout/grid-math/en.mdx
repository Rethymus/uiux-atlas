## Structure & DOM

The demo is a **true-scale model drawn to proportion**: the SVG viewBox equals the container width C, drawing n column tracks with (n−1) gutters, each column labeled with its real px width; the minmax (auto-fit) counting derivation sits below:

```html
<div class="gm-model">
  <svg viewBox="0 0 1440 120"><!-- n column tracks, gutters per --grid-gap --></svg>
  <code>colW = (1440 − 11×16) / 12 = 105.33px</code>
  <code>auto-fit: ⌊(1440+16)/(250+16)⌋ = 5 columns → realized 252.8px</code>
</div>
```

Key points:

- The model scales with its viewBox, but the **readings are real px, not proportional sketches** — changing the container changes the canvas;
- The column formula is one line: `colW = (C − (n−1)×g)/n`, equivalent to CSS `(100% − (n−1)×gap)/n` (% and px mixed, digested by calc);
- The minmax derivation and subgrid notes live in this MDX; the demo pairs the auto-fit count with its realized width.

## Styling & Parameters

Four parameters (container/columns/gap/minCol), with gap doubling as cssVar `--grid-gap`. The formulas, step by step (production figures from research 13 §2.1/§3.2, TDesign/Ant official docs):

**① Equal-split column width (Grid/Flex alike):**

```css
.grid {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr)); /* 1fr IS the equal split */
  column-gap: var(--grid-gap, 16px);                 /* TDesign's official fixed gutter: 16px */
}
/* Column formula: colW = (100% − (n−1)×gap) / n
   1440px / 12 columns / gap 16 → (1440 − 176)/12 = 105.33px */
```

**② auto-fit/minmax column counting (same source as the auto-fit-minmax entry):**

```
How many fit?  n* = ⌊(C + g) / (minCol + g)⌋     (+g spares the last column its gutter)
Realized width w  = (C − (n*−1)×g) / n*
1440/16/250: n* = ⌊1456/266⌋ = 5 columns, w = (1440 − 64)/5 = 252.8px
```

**③ subgrid size conduction:**

```css
.card {
  grid-column: span 3;                 /* occupy 3 parent columns */
  display: grid;
  grid-template-rows: subgrid;         /* row tracks = the parent's row tracks */
  grid-row: span 3;                    /* 3 rows: title/body/footer, one each */
}
/* The card's title row does not set its own height — it IS the parent's row height.
   N cards' title baselines align across cards, no magic numbers. */
```

Production doctrine: Ant divides by 24, recommends gutter `(16+8n)` px, responsive `{xs:8, sm:16, md:24, lg:32}`, and wraps whenever Col sums exceed 24; TDesign runs a 12-column content area, a fixed 16px gutter, 24px margins, and breakpoints deliberately set low to dodge Safari scrollbar jitter; the shared consensus: **columns scale with the container, gutters never change**.

## Motion & Interaction

- **Adjust columns**: from 12 to 24, readings fall from 105.33px to 38px per column — "24 divisions exist to be spanned" holds at a glance;
- **Adjust gutters**: pull gap from 16 to 48 and (n−1)×gap crowds the container, column widths collapsing toward zero with a "gutter too wide" warning — exactly why production bans percentage gutters and limits column×gutter combos;
- **auto-fit comparison**: change minCol or the container and watch the count hop between 4↔5↔6 while realized widths recompute — the estimate matches intuition;
- No autonomous animation; the entrance fade respects `prefers-reduced-motion`.

## Real-world examples

- **Ant Design's 24-column grid**: the official docs state it divides by 24 on top of the 12-column system, recommends gutter `(16+8n)` px and responsive `{xs:8, sm:16, md:24, lg:32}` (grid-cn verbatim); the admin Layout (Header/Sider/Content/Footer) all lands on this grid;
- **TDesign's 12-column grid**: 12-column content area on the design side, default fixed 16px gutter, 24px margins; sidebar 232px expanded/64px collapsed, auto-collapsing below 992px — the column formula and margin formulas share one spec page (canvas 1440);
- **This site (the auto-fit-minmax entry)**: `repeat(auto-fit, minmax(250px, 1fr))` column prediction is formula ② running in production; the subgrid entry demonstrates card internals inheriting parent row tracks for cross-card alignment — the three entries close the engineering loop together.

## Units, bounds & degenerate cases

| Variable | Unit | Working bounds | Degenerate cases |
| --- | --- | --- | --- |
| `C` (container width) | px | >0; canvas doctrine 1440/1920 | C→0 collapses everything; for % containers write the formula in its calc form with % |
| `n` (columns) | unitless integer | practically 1–24; n=0 meaningless | n=1 → colW=C (single column); more columns mean narrower ones — 1440/24 is 38px |
| `gap` (gutter) | px | fixed; mainstream ladders 8/16/24 | gap=0 → colW=C/n pure equal split; percentage gutters collapse on narrow screens — Ant: 'gutter width never changes' |
| `colW` | px (or %) | (C−(n−1)g)/n > 0 or there is no layout | (n−1)g=C → colW=0, total collapse; (n−1)g>C gives negative widths — Grid overflows or silently clips; clamp first |
| `minCol` | px | minmax floor; 250 is the classic recipe | minCol>C pins auto-fit at 1 column; minCol=0 degrades to auto-fill tiling |
| `n*` (auto-fit count) | unitless integer | ⌊(C+g)/(minCol+g)⌋ ≥1 | the +g numerator term is the last-column gutter allowance; omit it and the count underestimates |
| subgrid rows | none (inherited) | child track count ≤ what the parent offers | spanning beyond the parent's tracks errors or creates implicit rows; a child can never be 'finer' than its parent |
| % mixed with px | calc algebra | calc allows % ± px | in CSS, 100% is the container share; inside calc the gap operand must carry a unit |

Working doctrine: 12 columns (content) or 24 (for spanning); gutters fixed at 16, stepping 8/16/24/32 at breakpoints; card grids at minmax(250px, 1fr); subgrid conducts exactly one level. Sibling entries: **auto-fit-minmax** (formula ② in full behavior), **subgrid** (formula ③ in full behavior), **container-queries** (the variant where C is a container width), **fluid-spacing** (gutters can breathe too — sparingly).
