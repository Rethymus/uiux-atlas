## Structure & DOM

A dimming layer is a standalone veil stacked between the content below and the foreground; the two forms live at two DOM positions: the dialog scrim's native carrier is the top-layer element's `::backdrop` pseudo-element (no DOM node), while the caption gradient is a real element between image and caption.

```html
<!-- Solid form: dialog scrim -->
<dialog class="modal">
  <h3>Title</h3>
  <p>Body</p>
</dialog>
<!-- dialog::backdrop is the dimming layer: viewport-sized, rendered directly beneath the top-layer element, LIFO, inheriting nothing -->

<!-- Gradient form: caption over photo -->
<figure class="figure">
  <img src="photo.jpg" alt="" />
  <div class="caption-scrim"></div>   <!-- gradient dimming: bottom-up -->
  <figcaption>Caption text</figcaption>
</figure>
```

Key points:

- `::backdrop` **inherits nothing** — color and opacity must be declared fully on the pseudo-element; "the scrim vanished" on older engines almost always traces back to this (research 12 §8);
- The gradient only reaches peak α at its bottom vertex: text must sit inside the protected zone or it is effectively bare;
- The scrim is a layer between content and backdrop, not the backdrop itself — it dims "the content below" in service of "foreground legibility".

## Styling & Parameters

Two CSS-variable parameters (strength → `--dim-alpha`, color → `--dim-color`) plus one JS form switch (mode):

```css
/* Solid form: dialog scrim (native) */
dialog::backdrop {
  background: color-mix(in srgb, var(--dim-color) calc(var(--dim-alpha) * 100%), transparent);
}

/* Gradient form: caption over photo */
.caption-scrim {
  position: absolute;
  inset: auto 0 0 0;
  height: 55%;
  background: linear-gradient(to top,
    color-mix(in srgb, var(--dim-color) calc(var(--dim-alpha) * 100%), transparent),
    transparent);
}
```

α presets (all values recorded in research; nothing invented):

- **25%** = the MDN `::backdrop` typical example `rgb(0 0 0 / 25%)` (research 12 §8);
- **30%** = the SwiftUI `Glass.clear` doc example `.black.opacity(0.3)` (research 09 §1.3);
- **35%** = the HIG recommendation — "when underlying content is bright, consider adding a 35%-opacity dark dimming layer" (research 09 §1.3, the default);
- **55%** = the `color-mix(in oklab, black 55%, transparent)` heavy-scrim recipe in research 12 §8.

Additional reference: apple.com's glass base color steps by state — light `rgba(250,250,252,.8→.92)`, dark `rgba(22,22,23,.8→.88)` (floating up when stuck; production CSS, research 09 §1.4b); Material Design's scrim spec value (M2 ~32% black) is unverified and gets no step.

## Motion & Interaction

- **Scrim fade-in**: on open, α fades in over ~0.25s (opacity only); a hard cut steals the user's context of the layer below in an instant — the fade reads as "entering modality"; disabled under `prefers-reduced-motion`;
- **Modal semantics**: iOS 26 sheets are officially described as "the glass recedes slightly, paired with a dimming layer to express modality" (WWDC25 356 [438–494s], research 09 §8.9) — the scrim is part of modality's visual grammar;
- **Localized dimming**: small-footprint elements use localized dimming rather than a full-screen scrim (WWDC25 219, research 09 §1.3);
- **Scroll isolation**: while a modal is open, the layer below must not scroll (`overscroll-behavior: contain` — MDN's own recommended scenario, research 09 §7.1).

## Real-world examples

- **Apple HIG Liquid Glass (clear variant)**: the official advice — "when underlying content is bright, consider adding a 35%-opacity dark dimming layer"; the SwiftUI `Glass.clear` doc example ships `.black.opacity(0.3)` (research 09 §1.3) — dimming is the ticket that lets ultra-transparent glass hold readability (research 09 §11.6);
- **MDN's `<dialog>` examples**: `::backdrop { background: rgb(0 0 0 / 25%) }` is the typical dialog-scrim step (research 12 §8); the same doc family pairs `::backdrop` with `backdrop-filter: blur(0.5rem)` (research 09 §7.1) — the canonical dim-plus-blur pairing;
- **apple.com global nav**: a three-state glass base color — resting 0.8, stuck floating up to 0.92 (light) / 0.88 (dark), solid when the menu expands (production CSS, research 09 §1.4b) — a production implementation of state-stepped dimming bases.

## Parameter Sensitivity

| Parameter | Turning it up… | Turning it down… |
| --- | --- | --- |
| `strength` → 55% | heavy scrim: the layer below is barely legible and attention goes fully to the foreground — true modality only | the 25% light scrim keeps the layer below perceptible; on bright content text often fails 4.5:1 — dim first, then typeset |
| `strength` → 35% (default) | the official advice: the fallback step when the content beneath is bright | 30% (SwiftUI's example) vs 35% is a small visual delta; below 30% needs per-backdrop testing |
| `mode` → gradient | dims the bottom only: the media subject stays clear and the caption gets the full α; text elsewhere is unprotected | the solid form dims uniformly everywhere — the most stable for readability and the dialog default |
| `color` | a brand-tinted scrim (the 12 §16.10 trick) carries the theme hue; every contrast relationship must be re-tested after tinting | pure black is the safest base; a whitening scrim is a different form whose semantics flip from dimming to brightening |

Working ranges: start modals at 25–35%, push toward 35–55% over bright media; the gradient occupies about half the image height (55%) with text inside the peak zone. The single criterion for α: foreground text must hold 4.5:1 against "the brightest content below" (WCAG 2.1 SC 1.4.3).
