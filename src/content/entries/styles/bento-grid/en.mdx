## Structure & DOM

A bento's DOM is one grid container plus its cells, with **DOM order = reading order** (the most important fact first); hierarchy is delegated entirely to spans:

```html
<section class="bento">
  <div class="bento-hero">The most important fact</div>
  <div class="bento-wide">Secondary fact (horizontal)</div>
  <div class="bento-cell">Spec number</div>
  <div class="bento-tall">Secondary fact (vertical)</div>
  <div class="bento-cell">Spec number</div>
</section>
```

Key points:

- Each cell **holds exactly one fact**; cell size encodes information priority — the largest cell carries the most important fact;
- Bento is a **layout, not a color scheme**: cell interiors can be any style (light `#f5f5f7` / dark `#161617` both come from Apple's grays);
- Asymmetric but balanced overall: a hero in one corner, small cells backfilling around it, `grid-auto-flow: dense` filling the holes;
- Dense can pull visual order away from DOM order — use with care on content grids (see Motion & Interaction).

## Styling & Parameters

Four parameters map to columns, row height, gap and radius, injected via `--bento-*` variables; every default comes from the documented recipe:

```css
.bento {
  display: grid;
  grid-template-columns: repeat(var(--bento-cols), minmax(0, 1fr)); /* default 4 */
  grid-auto-rows: var(--bento-row);   /* default 180px */
  gap: var(--bento-gap);              /* default 16px */
  grid-auto-flow: dense;
}
.bento > * { border-radius: var(--bento-radius); }  /* default 24px, signature value */

.bento-hero { grid-column: span 2; grid-row: span 2; }  /* 2×2 hero */
.bento-wide { grid-column: span 2; }
.bento-tall { grid-row: span 2; }

/* Responsive breakpoints (documented: 768px→2 columns, 480px→1 column with spans reset; the demo uses container queries) */
@container bg-stage (max-width: 768px) {
  .bento { grid-template-columns: repeat(2, minmax(0, 1fr)); }
  .bento-hero { grid-column: span 2; grid-row: span 1; }
  .bento-wide, .bento-tall { grid-column: span 2; grid-row: span 1; }
}
@container bg-stage (max-width: 480px) {
  .bento { grid-template-columns: repeat(1, minmax(0, 1fr)); }
  .bento > * { grid-column: auto; grid-row: auto; }
}
```

Where the numbers come from (the superdesign.dev bento-grid page):

- The recipe, verbatim: `display:grid; grid-template-columns: repeat(4, minmax(0,1fr)); grid-auto-rows: 180px; gap:16px; grid-auto-flow: dense`;
- Radius 20–28px with **24px the signature value**; below 16px cells degrade into ordinary cards; light `#f5f5f7` / dark `#161617` (Apple grays);
- Breakpoints 768px→2 columns, 480px→1 column with spans reset; the `span 2×2` hero;
- Reference cases: Apple MacBook Air's "Get the highlights" section, Raycast, Amie, GitHub Copilot; gallery bentogrids.com.

## Motion & Interaction

Bento is a static layout; motion does "entrance choreography" and clickability hints only:

- **Entrance**: cells fade in with an 8px rise, staggered 40ms apart, animating only `opacity/transform`; under `prefers-reduced-motion`, a single block fade or the final state directly;
- **Hover**: clickable cells lift 2px with a deepened shadow; non-clickable cells stay still — hover is a promise of clickability, and adding it to decorative cells misleads;
- **Focus-order trap**: `grid-auto-flow: dense` makes visual order ≠ DOM order, so Tab jumps around (WCAG 2.4.3/1.3.2); content bentos either skip dense or keep DOM order as reading order;
- Once breakpoints reset the spans, hierarchy flattens — keep h2/h3 semantics so structure, not cell size, carries the information.

## Parameter Sensitivity

| Parameter | Turning it up… | Turning it down… |
| --- | --- | --- |
| `cols` | 6 columns get spec-sheet dense with fiddly small cells; 4 is the sweet spot; 2–3 suit narrow containers and mobile-first | cells grow fewer and larger, nearing a "big card list"; span-2 cells may fill entire rows |
| `rowHeight` | taller, airier cells; past 220px few fit in one viewport | flatter cells nearing banners; below 140px the hero (2 rows) lacks height and hierarchy weakens |
| `gap` | visible seams, stronger modularity; past 24px it loosens and the "compact grid" signature erodes | near 0 cells fuse into a mosaic; readability survives only via the radius |
| `radius` | a capsule feel close to Apple keynotes; past 32px small cells lose usable text width | below 16px cells degrade into ordinary cards — the documented style-failure line |

Working ranges: 4 columns, row height 160–200px, gap 12–20px, radius 20–28px. After changing columns, first check the hero still dominates, then check small-cell text for overflow.
