## 结构与 DOM

60-30-10 是**角色分工**法则:三个色不是随便三色,而是各占一个视觉职责,占比即「视觉面积预算」:

- **60% 主导色**——大面积基调,UI 中就是背景画布,通常用中性色(白/浅灰/深灰);
- **30% 辅助色**——次级表面:侧边栏、卡片、面板、搜索栏(LogRocket 原文例举);
- **10% 强调色**——CTA、链接、图标等少数焦点元素,是界面最鲜艳的部分(hype4:强调色是「焦点/行动号召」)。

demo 把三个占比做成一根构图条与一个线框示意,结构如下:

```html
<div class="r-frame">
  <section class="r-band r-dominant">…画布骨架…</section>
  <section class="r-band r-secondary">…卡片骨架…</section>
  <section class="r-band r-accent">…CTA…</section>
</div>
```

- 三段的 `flex-grow` 由归一化占比驱动——**flex-grow 按比例分配剩余空间,天然完成归一化**,与 JS 算出的百分比互为印证;
- 三色是 demo 固定的示意配色(白画布/浅灰组件/亮蓝按钮,对应 LogRocket 记述的 Material 例证),**参数只调占比、不调色**。

## 样式与参数

三个 number 参数(0–100,JS 型,demo 内归一化):

```ts
// demo 内归一化:总和不必等于 100
const total = dominant + secondary + accent;
const pct = (v: number) => (total === 0 ? 0 : (v / total) * 100);
// 60/30/10 → 60% / 30% / 10%;70/40/20 → 53.8% / 30.8% / 15.4%
```

- 默认 **60 / 30 / 10** 取法则定义值,LogRocket 与 hype4 两篇交叉一致(调研 06§9);
- 经典例证(LogRocket):Material **白底 60 / 浅灰组件 30 / 亮蓝按钮 10**;Spotify **黑 60 / 深灰 30 / 活力绿 10**——同一法则在亮暗两种主题下都成立;
- 法则源自室内设计,两篇来源均明示**是指导原则而非硬性规定**——占比是「预算线」,不是逐像素指标。

落到主题层,三个角色就是三条语义变量——组件只引用角色,占比与色值都在主题层集中管理:

```css
:root {
  --role-dominant: var(--neutral-0);   /* 60%:画布,常为中性色 */
  --role-secondary: var(--neutral-50); /* 30%:卡片/侧栏/面板 */
  --role-accent: var(--brand-500);     /* 10%:CTA/链接/图标 */
}
.dark {
  /* 暗色翻转映射表;强调色在此提亮降饱和(M3 惯例,见上) */
  --role-dominant: var(--neutral-950);
  --role-secondary: var(--neutral-900);
  --role-accent: var(--brand-300);
}
```

**暗色模式告诫(hype4 原文,调研 06§13)**:暗色下避免过度饱和——对比过高会造成视觉疲劳。官方注脚是 M3 的做法:暗色 accent 提亮降饱和(亮色 `#6750A4` → 暗色 `#D0BCFF`,调研 06§7/§14)。调研同时明确:诸如「暗色整体降饱和 15–30%」的量化惯例**未找到可靠量化标准**——降饱和方向可信,具体幅度没有官方数字,按视觉复核为准。

## 动效与交互

- 改任一占比参数,三段宽度即时重排,读数条同步显示**归一化后的百分比**(保留一位小数);
- 宽度变化用 0.3s `transition` 过渡,只动 `flex-grow`(布局属性,动效克制、时长短);`prefers-reduced-motion` 时取消过渡直接跳变;
- 归一化读数同时给出原始总和:当三者之和 ≠100 时,demo 明示「总和 X → 已归一化」,避免误读成占比失效;
- 法则本身无动效语义;若给强调色元素加微动效(hover 提亮等),只动 `transform/opacity`,并且暗色下避免高饱和闪烁。

## 参数敏感度

| 参数 | 调大会… | 调小会… |
| --- | --- | --- |
| `dominant` | 画布更空更稳,页面呼吸感强;超过 ~70% 后辅助表面显得单薄 | 画布被挤压,页面开始「吵」;主导色失去大面积定调作用 |
| `secondary` | 次级表面扩张,信息密度感知上升;接近主导色占比时层次开始混淆 | 卡片/面板萎缩,内容缺少落脚面;趋近 0 时只剩画布与 CTA 的两极 |
| `accent` | 焦点元素更多更显眼;但强调色一旦不再稀少,「焦点」语义被稀释,页面变花(hype4:不要让所有颜色都鲜艳) | CTA 存在感不足,行动号召难以被注意到;趋近 0 时界面只剩中性的两个层级 |

经验:把三参数拖到 70/20/10、40/40/20 等组合观察读数条,可以直观感受「预算转移」——主导色每让出一份,辅助与强调就获得一分存在感;真正稳定的界面几乎总是把强调压在最小的一份里。
