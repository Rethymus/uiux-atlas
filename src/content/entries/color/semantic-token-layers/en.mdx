## Structure & DOM

The three layers discipline **the direction of reference**, not folder layout: layer 1 primitives hold raw values (with indexed levels), layer 2 semantics name roles and **reference only primitives**, layer 3 component CSS **consumes only semantic variables**.

```html
<article class="card">…</article>
```

```css
/* Layer 3: zero hex in the component file */
.card {
  background-color: var(--st-bg, #ffffff);   /* semantic variable + fallback */
  color: var(--st-fg, #1c1b1f);
}
```

```css
/* Layer 2: a semantic mapping sheet (one row of the light theme, Primer's measured layering) */
[data-theme="light"] {
  --st-bg: var(--st-primitive-neutral-0);
}
```

Key points:

- One-way chain: component → semantic → primitive; reaching past the semantic layer into primitives from a component is the anti-pattern the Android docs call out ('assign color roles semantically, not concrete values');
- Theme switching swaps exactly one mapping sheet: the data-theme attribute remounts semantic variables while all 9 themes share the same component CSS;
- Semantic names must be **role words** (`bgColor-default`, `fgColor-muted`), never appearance words (`--light-blue-500`) — appearance words die on the first theme swap.

## Styling & Parameters

The demo remaps 6 semantic variables across 9 themes via `data-theme`; all three params are JS-type (`theme` / `role` / `layer`), and the mapping panel renders the three layer definitions in DTCG shape:

```css
.st-scene[data-theme="dark"] {
  --st-bg: oklch(0.19 0.01 297);      /* illustrative mapping */
  --st-accent: #D0BCFF;                /* official M3 dark primary baseline (research 06 §7) */
  --st-on-accent: #381E72;             /* official M3 dark on-primary baseline */
}
```

Where the names and numbers come from (all from the Primer Primitives README, research 06 §10):

- The official theme list is **9 sets**, reproduced verbatim in the demo: `light / dark / dark-dimmed / light-high-contrast / dark-high-contrast / light-colorblind / dark-colorblind / light-tritanopia / dark-tritanopia`;
- Official semantic token examples: `bgColor-default`, `fgColor-muted`, `borderColor-accent.muted`; the official primitive example key: `base.color.blue.3` (the index = lightness level);
- Token files follow the **W3C Design Tokens Community Group** format (`$value`/`$type`/`$extensions`), with alpha transforms (official shape `{ $value: '{base.color.blue.3}', alpha: 0.4 }`) and the `@`-hack for default+child values (`bgColor.accent.@` → `bgColor-accent`);
- Compiler: style-dictionary (as Primer actually uses).

## Motion & Interaction

Theme-switch motion stays restrained and optional — the architecture is a static discipline:

- **theme param**: data-theme remounts variables with a 0.25s ease cross-fade on card background/text; disabled under `prefers-reduced-motion`;
- **role param**: the selected semantic role's host element is located on the card with a 2px dashed outline (bgColor-default → card, fgColor-muted → muted text, borderColor-accent.muted → badge) while the panel magnifies that row;
- **layer param**: the panel switches between the primitive definition (raw values + the alpha-transform shape), the semantic definition (DTCG $value references), and the component definition (the consuming side);
- The colorblind/tritanopia themes show one unchanged component CSS "turning blue" as a set — the accent mapping moves toward blue at 220° (Evil Martians' hue map), which is exactly the proof that accessibility modes are generated by swapping the sheet.

## Real-world examples

- **GitHub.com**: Primer's production home — all 9 themes shipped, including 4 accessibility sets (high-contrast×2, colorblind×2, tritanopia×2, research 06 §10/§19); users switch them at github.com/settings/appearance;
- **Android Dynamic Color**: the official docs state design tokens 'assign color roles semantically rather than concrete values', with light/dark themes and wallpaper-derived dynamic color sharing one token set (research 06 §10 corroboration) — the mobile twin of the same layering;
- **style-dictionary ecosystem**: Primer's primitives compile through it into multi-platform artifacts (W3C DTCG as the interchange format, research 06 §10) — one primitive sheet feeding Web/iOS/Android.

## Parameter Sensitivity

| Parameter | Switch to… | And… |
| --- | --- | --- |
| `theme` → dark | surfaces darken while the accent brightens and desaturates (#6750A4→#D0BCFF, the M3-baseline convention) | dark-dimmed is the middle grade; dark is crisper |
| `theme` → high-contrast | text pushes to pure black/white, accent deepens, translucent borders consolidate to high opacity | it is an independent mapping sheet, not 'the same colors darker' — contrast is audited per sheet |
| `theme` → colorblind | the accent moves toward blue (illustrative mapping); red/green information re-rides lightness | tritanopia resolves the same way — once the semantic layer exists, accessibility themes are 'fill in a sheet', not 'edit components' |
| `role` | highlights a different host element, showing how one sheet divides labor across roles | — |
| `layer` | the primitive layer is the only place a hex may appear; the component layer holds zero color values | — |
