## Structure & DOM

The five tiers are a **role system**, not five CSS classes: each tier is one semantic role; components claim a role by their hierarchical standing, and light/dark themes each ship a tone mapping sheet.

```html
<main class="page">                      <!-- surface-container-lowest -->
  <section class="section">…</section>   <!-- surface-container-low -->
  <article class="card">…</article>      <!-- surface-container -->
  <footer class="dock">…</footer>        <!-- surface-container-high -->
  <dialog class="sheet">…</dialog>       <!-- surface-container-highest -->
</main>
```

```css
[data-theme="light"] .card { background-color: var(--ts-surface-container); }
[data-theme="dark"]  .card { background-color: var(--ts-surface-container); } /* same role, new sheet */
```

Key points:

- The M3 blog (2023-02) retires 'surface + elevation 1–5 opacity overlays' for surface container **lowest / low / (container) / high / highest** — five tonal roles with hierarchy decoupled from elevation (research 02 §B7);
- Roles are paired: each surface tier pairs with its on-surface text/icons, officially guaranteed to a minimum 3:1 contrast (research 02 §B6);
- Dark themes don't 'swap the shadow' — they **flip the direction**: hierarchy is expressed by brightening, and a brighter tier reads as closer to the viewer (structurally the same convention as Apple's base/elevated, research 06 §14).

## Styling & Parameters

The machinery underneath is the HCT tonal palette: Tone 0–100 is CIE L*, with hue and chroma fixed and only tone varying (13 steps per key color on Android, research 06 §5); the surface family draws from a neutral low-chroma column. The demo approximates tone with oklch L (a different scale); `--ts-hue` / `--ts-chroma` are CSS-variable params:

```css
.ts-card { background-color: oklch(var(--ts-l) var(--ts-chroma) var(--ts-hue)); }
/* demo ladder (illustrative): light 0.985→0.87 descending L; dark 0.06→0.22 ascending (brighter = forward) */
```

Where the numbers come from:

- Tier naming and the elevation decoupling: the official M3 blog tone-based-surface-color-m3 (research 02 §B7);
- Tone 0–100 = CIE L*, 13-step palettes, the five core palettes (Primary/Secondary/Tertiary/Neutral/Error): material-color-utilities and the Android docs (research 06 §5);
- M3 baseline reference values (the demo's light on-surface converts from these): surface `#FFFBFE`, on-surface `#1C1B1F`, light primary `#6750A4`, dark primary `#D0BCFF` (≈tone 80) (research 06 §7);
- **The official per-tier tone values were not verified in this research** — community-transcribed tables like 'light lowest≈tone 100 / low 96 / container 90 / high 92 / highest 94, dark 4/10/12/17/22' are common community values, unverified; the demo uses a monotonic illustrative ladder and does not claim that table.

## Motion & Interaction

The tiers are a static role system; motion happens only in 'selection and switching':

- **tier param**: the selected tier card shifts right 6px with a border fade-in, 0.25s ease; the shift and transitions are disabled under `prefers-reduced-motion`;
- **mode param**: the whole L ladder flips between themes (light descending / dark ascending) with a 0.25s background transition — same component DOM, a new mapping sheet per theme;
- The tier gap itself is the 'motion substitute': M3 replaces elevation-shadow animation with tonal gaps, so scrolling and hover never re-render shadows per frame;
- No self-driven animation; on a 'colored surface' (chroma raised), text contrast must be audited per tier against WCAG AA (body 4.5:1, research 06 §17).

## Real-world examples

- **Android 12+ system UI (Material You)**: after dynamic color extraction, all five surface roles remap with the wallpaper, and the hierarchy of system settings, the notification panel and bottom sheets rides entirely on tonal tiers — the flagship use of the tone-based surfaces update (research 02 §B7/06 §6);
- **Material Theme Builder** (Figma plugin / web, goo.gle/material-theme-builder-web): the official tool expands a seed color into the full role set (including the five-tier surface family) and exports both theme token sets (research 06 §7);
- **Radix Colors steps 1–3**: the 12-step scale writes 'app background (step 1) → subtle background (step 2) → component surface (step 3)' directly into step semantics — the web-side counterpart of tiered surfaces (research 06 §8; the analogy is editorial).

## Parameter Sensitivity

| Parameter | Turning it up… | Turning it down… |
| --- | --- | --- |
| `mode` → dark | the ladder flips: higher tier = brighter (brightening = forward); shadows vanish, hierarchy rides on tonal gaps alone | light: tiers converge toward white, hierarchy expressed by slightly descending L |
| `chroma` | surfaces turn 'colorful' and more branded while eating on-surface contrast headroom — body 4.5:1 flags first | returns to neutral gray — the M3 surface family's default shape (illustrative 0.02) |
| `hue` | tints the whole family toward one hue; watch separation from accent roles when sweeping | 0°/neutral reads as pure gray, the quietest hierarchy |
| `tier` | high/highest read as 'floating' — dialogs, bottom bars, FABs belong here | lowest reads as 'recessed' — page base and embedded backdrops belong here |

Working ranges (illustrative): neutral surfaces chroma ≤0.03; adjacent tiers need ≥0.03 L gap to be discriminable; the dark ladder can span slightly wider than light (dark environments have lower lightness sensitivity; Apple HIG dark-mode floors are 4.5:1 with 7:1 aimed for small text, research 06 §13).
