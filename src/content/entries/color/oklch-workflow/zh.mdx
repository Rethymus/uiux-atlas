## 结构与 DOM

演示分两栏:左侧大色块(背景由 L/C/H 实时换算的 sRGB 上色,上面放黑字/白字两组示例文本),右侧是读数面板——`oklch()` 字符串、换算出的 `rgb()`、对黑/白两色底的对比度比值与 AA/AAA 徽章。

```ts
// oklch → sRGB:Ottosson 矩阵(与 CSS Color 4 一致),无第三方包
const l_ = L + 0.3963377774 * a + 0.2158037573 * b;  // a = C·cos(H), b = C·sin(H)
const m_ = L - 0.1055613458 * a - 0.0638541728 * b;
const s_ = L - 0.0894841775 * a - 1.2914855480 * b;
const [r, g, b2] = lmsToLinearSrgb(l_ ** 3, m_ ** 3, s_ ** 3);
// 线性 sRGB → 相对亮度 → 对比度
const Y = 0.2126 * r + 0.7152 * g + 0.0722 * b2;
const vsBlack = (Y + 0.05) / 0.05;   // 黑字在色块上
const vsWhite = 1.05 / (Y + 0.05);   // 白字在色块上
```

- 色块上色用换算后的 `rgb()`,同时展示 `oklch()` 原串——换算链路全程可核对;
- 越出 sRGB 色域的通道按浏览器现状直接裁剪,并以警示条如实标注(Chrome/Safari 尚未实现规范的降 chroma 映射,直接裁剪会肉眼可见地偏色相)。

## 样式与参数

`oklch(L C H / A)` 是 Oklab(2020,Björn Ottosson)的柱坐标形式,2023-05 起全主流浏览器(Baseline)。工作流法则来自 Evil Martians《OKLCH in CSS》:

- **固定 L、只调 C/H**:同一 L 的颜色感知亮度一致,文字对比度因此可预测。文中示例:头像衍生主色 `oklch(from var(--dominant) 0.8 0.17 h)`——L=0.8 时任何色相配黑字都清晰;**L≥87% 的背景配黑字对比度全部达标**;
- **C 的实测上限约 0.37**(sRGB 色域边界,P3 屏略高);MDN:理论上限约 0.5,且 100% = 0.4 而非 1;
- **H 的经验映射**:红≈20°、黄≈90°、绿≈140°、蓝≈220°(本条目默认值)、紫≈320°——注意与 hsl 的色相角不重合(oklch 里 CIELab 的红约 41°);
- 顺带的收益:老 CIELab 在蓝区(270–330°)有「蓝变紫」的色相漂移缺陷,Oklab 正是为此而生;
- 主题工程:组件只引用 `var(--error)` 等语义变量,亮暗主题只换映射表;hover 用相对颜色 `calc(l + 0.1)` 实现。

把工作流落到 CSS 的完整姿势——sRGB 兜底在前、oklch 覆写在后,P3 上再放开色度:

```css
.swatch { background: rgb(82 207 243); }              /* 基础 sRGB 兜底 */
@supports (color: oklch(0.8 0.12 220)) {
  .swatch { background: oklch(80% 0.12 220); }
}
@media (color-gamut: p3) {
  .swatch { background: oklch(80% 0.2 220); }         /* P3 上放开色度,更鲜艳 */
}
/* hover 提亮一档感知亮度:相对颜色语法(CSS Color 5;calc 只能加减数字,不能加 10%) */
.swatch:hover { background: oklch(from oklch(80% 0.12 220) calc(l + 0.1) c h); }
```

## 动效与交互

- 改任一参数,色块、`rgb()`、对比度比值即时重算——感知均匀性意味着拖 H 时颜色转动而对比度几乎纹丝不动,拖 L 时对比度沿刻度线性走;
- 色块背景用 0.18s `transition` 平滑过渡,只动 `background-color`;`prefers-reduced-motion` 时取消过渡直接跳变;
- 对比度判定**不得四舍五入达标**(WCAG 2.1 原文要求):4.499:1 就是不达标;
- 阈值速查(WCAG 2.1 Understanding):正文 AA 4.5:1 / AAA 7:1;大字(≥18pt 或 ≥14pt 粗体)3:1 / 4.5:1;UI 组件边界 3:1(SC 1.4.11);
- 与宽色域配合:P3 的色域体积约是 sRGB 的 1.5 倍,标准姿势是「基础 sRGB 值 + `@supports (color: color(display-p3 1 0 0))` + `@media (color-gamut: p3)` 手写更鲜艳的覆写」,而不是指望浏览器映射;
- 渐变同理:插值空间显式声明 `linear-gradient(in oklab, …)` 可避开默认 sRGB 插值的长距脏灰带(Tailwind v4 已把整个调色板换成 oklch、渐变默认 OKLAB 插值)。

## 参数敏感度

| 参数 | 调大会… | 调小会… |
| --- | --- | --- |
| `L` | 更亮:对黑字对比度下降、对白字上升;0.8 是「配黑字」工作区的甜点,≥87% 恒达标 | 更暗:对黑字对比度上升、对白字下降;低于 ~50% 后白字才开始可行 |
| `C` | 更鲜艳;接近 0.37 时容易越出 sRGB 色域,被裁剪后色相跑偏(演示会亮警示条) | 趋向灰;C=0 时颜色完全由 L 决定(纯中性灰,黑白两端的对比度也最极端) |
| `H` | 沿色环转动(220=蓝);同一 L/C 下对比度几乎不变——这是 OKLCH 感知均匀的核心收益 | 反向转环;个别高 C 区域转动时会触发色域裁剪,亮度感受依旧稳定 |

口诀:先用 L 定「这层信息多重」,再用 C 定「多鲜艳」,最后用 H 定「什么色」;每一步的对比度都可预测,但仍要在最差背景组合上复核——Evil Martians 原文警示「仅靠 OKLCH 不能保证可访问性,还需 APCA 校验」。
