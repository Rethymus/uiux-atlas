柔光设计 Soft-Glow Design

柔光设计 · 柔光美学 · Soft-Glow Aesthetics · Glow-First Design

以「光」而非「色块」组织层级的暗场设计语言:低填充玻璃面板做导航层、内容层保持高可读实底;每个发光元素都有单一方向光源;光色与内容主色同族。

代码拆解

结构与 DOM

定义 [R]:以「光」而非「色块」组织层级的暗场设计语言——低填充玻璃面板做导航层、内容层保持高可读实底;每个发光元素都有单一方向光源;光色与内容主色同族。它是 Liquid Glass(官方,2025)与早期 glassmorphism(社区,2018–2020)在「发光维度」上的合流(调研 17 §9)。

历史脉络:2018–2020 的 glassmorphism 建立了「模糊+低填充+亮边」的玻璃语法(见 glassmorphism 条目);2025-06 WWDC25 发布 Liquid Glass,两周内社区复刻仓库爆发(GitHub API 检索核验:“liquid glass css” 420 仓库、“liquid-glass in:name” 2924 仓库),把「玻璃会反光、会与环境互动」提升为官方设计语言;2026 年两条谱系在「发光维度」上合流为本流派。

层级架构(demo 即此结构):

<body class="dark-stage">          <!-- 暗底 ≈ #0B0F14 -->
  <nav class="glass">…</nav>       <!-- 玻璃层 1:导航(玻璃是导航层特权) -->
  <section class="glass">…</section><!-- 玻璃层 2:英雄/强调卡 -->
  <main class="solid">…</main>     <!-- 内容层:实底高对比,永不玻璃化 -->
</body>

关键点:玻璃面板全站 ≤ 3 层(Apple “sparingly” 原则的落地数字,调研 17 §11.10);内容层一律退回标准磨砂五档或实底。

样式与参数

三个流派级参数(组成技法的完整配方见 soft-glow-glass/halo-glow-border/breathing-glow 条目):

.dark-stage {
  background: radial-gradient(120% 90% at 50% -20%,
    hsl(var(--sgd-hue) 45% 22% / .55), transparent 60%), #0b0f14;  /* 暗底 + 单一顶光方向 */
}
.glass {
  background: rgb(255 255 255 / .06);
  backdrop-filter: blur(12px) saturate(1.5) brightness(1.06);
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / .4),                                             /* 受光亮边 */
    inset 0 0 16px 2px color-mix(in srgb, hsl(var(--sgd-hue) 90% 78%) 26%, transparent), /* 渗光 */
    0 0 0 1px rgb(255 255 255 / .16),
    0 0 var(--sgd-bloom) 4px color-mix(in srgb, hsl(var(--sgd-hue) 90% 78%) 35%, transparent), /* 泛光 */
    0 12px 32px rgb(0 0 0 / .35);                                                    /* 落影 */
}

数值出处:暗底 #0B0F14 级别、单一主光色、玻璃 ≤3 层:调研 17 §9 实现基调;hsl(hue 90% 78%)、渗光 26%(域 22–32%)、泛光 40px/alpha .35、受光 .4:取自 §1.3 柔光玻璃配方域。

与 glassmorphism 的对照:glassmorphism 的辨识度在「模糊+亮边」,光不是必要条件;柔光设计在玻璃语法之上注入光学事件(渗光/泛光/呼吸),光成为层级语言本身。与 neumorphism 的对照:neumorphism 靠「同色明暗差」做挤压浮雕,元素与背景同色、对比天生孱弱(a11y 弱点);柔光设计靠「暗场上的光」分层,内容层强制实底高对比——两者都做「柔和立体」,但柔光设计的可读性下限由实底内容层兜底。

动效与交互

流派的动效基调是「光响应,不自主运动」:

  • 玻璃层入场淡入 + 8px 上移,prefers-reduced-motion 时取消;第三块玻璃显隐用 0.25s opacity/translate 过渡;
  • 常驻的光动画只有 breathing-glow 一种合法形态(2.4–4s、alpha/blur only、reduce 取中间帧);其余「发光」全部是静态构图或输入驱动(指针跟随辉光,参照 liquid-glass 条目的触碰辉光近似);
  • 背景「活体内容」(缓慢漂移的色斑)只动 transform,为玻璃的每帧重采样提供变化(同 backdrop-filter 性能准则);
  • 状态变化(选中、聚焦)优先用光圈出现/消失表达,过渡 0.25s,且必有文字/图形冗余。

真实产品案例

  • iOS 26 / iPadOS 26 / macOS Tahoe 26 全系统 Liquid Glass:流派的官方母题——玻璃只在导航/控件层、环境光反射、节制使用(HIG Materials + WWDC25 219 核验,调研 17 §0/§9);
  • itsEricWu/ericwu.me:liquid-glass bento grid 个人站(GitHub API 核验 373★)——流派在真实站点级产品的社区落地;
  • hyalite demo:SDF 透镜 + per-channel 色散 + rim 光的完整流派实现(仓库元数据核验,demo 地址 https://vii-cae.github.io/hyalite—liquid-glass/demo/index.html)。

参数敏感度

参数调大会…调小会…
hue光色偏离内容主色后,「环境在照亮面板」变「滤镜贴脸」;双光色场景层级混乱收敛回单一主光色;32° 暖琥珀在暗底上最接近「灯」而非「霓虹」
bloom泛光淹没深底层级,「人人发光」;alpha 同步走高时洗白面板(alpha 超 .45 即违反配方域)泛光收窄,光退为点缀;16px 时流派辨识度主要由渗光与亮边承担
layers3 层是 sparingly 上限;超过后透出层互相发浑,层级感先死(§11.10)1 层最安静:只剩导航玻璃,光叙事让位给内容;适合工具型页面

经验区间:全场单一 hue;bloom 32–48px / alpha .35;玻璃 1–2 层为主、3 层封顶;内容层零玻璃。与 glassmorphism 条目互参:玻璃语法基座;与 neumorphism 条目互参:「柔和立体」的另一条路线及其 a11y 分野;与 soft-glow-glass/halo-glow-border/breathing-glow 条目互参:三个发光维度的材质级配方;与 liquid-glass 条目互参:官方设计语言的语义与约束。

适用场景 3
  • 暗场产品:开发者工具、音乐/媒体、游戏与品牌站——「光」是天然的主题语言(调研 17 §9)
  • 导航层玻璃 + 内容层实底的二分结构(Apple HIG 原则的流派化落地,调研 17 §0/§9)
  • 需要「面板参与场景光照」的品牌叙事:产品图、仪表盘、英雄区
何时不要用 3
  • 浅色主题:柔光的「暗场 + 泛光」前提在亮底上不成立(改用玻璃参数收敛的 glassmorphism)
  • 内容层玻璃化:官方明确玻璃不进内容层、全站 ≤3 层(调研 17 §11.10)
  • 多光源色相混用:两个主光色打架时,「单一方向光源」的流派前提崩塌
无障碍

流派级铁律:内容层一律实底高对比(4.5:1,WCAG 2.1 SC 1.4.3),玻璃只许在导航层;发光是装饰叙事,状态与信息必须有文字/图形冗余;呼吸类光动画遵循 prefers-reduced-motion(breathing-glow 条目同规则);暗底上的玻璃面板按透出最亮/最暗背景双极核对。

浏览器支持

组成技法全基线或近基线:backdrop-filter Baseline 2024-09(MDN)、@property Baseline 2024-07、box-shadow 多层/渐变全基线(调研 17 §1.4);不支持 backdrop-filter 的环境回退为实底面板,流派观感靠光色与层级仍可保全大半。

兼容回退

backdrop-filter 缺失时玻璃面板退回实底(填充提到 .7+,调研 17 §1.4);流派的层级组织(导航玻璃层/内容实底、单一光源、光色同族)不依赖 backdrop-filter,回退后仍然成立。
