玻璃色散边 Chromatic Edge

玻璃色散边 · 色散边 · 色差边 · Chromatic Aberration Edge

边缘的 RGB 分离/色差:真实玻璃对不同波长折射率不同,边亮缘处红蓝光错位。Web 两条实现路线:SVG 滤镜位移(真位移,仅 Chromium)与双层复制 + 色彩偏移(假位移,全浏览器)。

代码拆解

结构与 DOM

色散边是边缘的 RGB 分离/色差:真实玻璃对不同波长折射率不同,边亮缘处红蓝光错位(调研 17 §6.1)。Web 两条实现路线:

<!-- 路线 A:SVG 滤镜真位移(仅 Chromium 完整支持) -->
<svg width="0" height="0" aria-hidden="true">
  <filter id="chromatic" x="-20%" y="-20%" width="140%" height="140%"
          color-interpolation-filters="sRGB">
    <feTurbulence type="fractalNoise" baseFrequency="0.008" numOctaves="1" seed="7" result="map"/>
    <feDisplacementMap in="SourceGraphic" in2="map" scale="4"
                       xChannelSelector="R" yChannelSelector="G" result="d0"/>
    <!-- 同一位移场做三次,每次先做通道萃取,再偏移量逐通道递增 -->
    <feOffset in="d0" dx="2" dy="0" result="oR"/>
    <feOffset in="d0" dx="-2" dy="0" result="oB"/>
    <feBlend in="oR" in2="oB" mode="screen"/>
  </filter>
</svg>
<div class="chromatic">…</div>   <!-- backdrop-filter: url(#chromatic) blur(2px) saturate(1.5) -->

<!-- 路线 B:双层复制 + 边缘蒙版(全浏览器兜底),本体 + 两个伪层,无新增 DOM -->
<div class="chromatic-lite">…</div>

关键点:

  • 路线 A 是「真位移」:feDisplacementMap 按 hyalite 的官方级做法「每个 RGB 通道各跑一次位移再求和」(README 全文核验【S】);但 backdrop-filter: url(#svg) 只有 Chromium 完整支持——且 CSS.supports 会到处返回 true,特性检测会撒谎(调研 17 §6.4);
  • 路线 B 是「假位移」:本体 + ::before/::after 两个 background: inherit 的同底复制,双 mask 挖空只留 1.5px 边缘,色相错开 + screen 混合近似色差;
  • 色散层是纯装饰:pointer-events: none,不承载信息。

样式与参数

三个参数对应路线 B 配方(调研 17 §6.3,[R]):

.chromatic-lite { position: relative; }
.chromatic-lite::before, .chromatic-lite::after {
  content: ""; position: absolute; inset: 0; border-radius: inherit;
  background: inherit;                       /* 与本体同底 */
  mix-blend-mode: screen; opacity: calc(var(--ce-op) / 100%);
  padding: 1.5px;
  -webkit-mask: linear-gradient(#000, #000) padding-box, linear-gradient(#000, #000);
  -webkit-mask-composite: xor; mask-composite: exclude;   /* 只留边缘 */
}
.chromatic-lite::before { transform: translateX(var(--ce-shift)); filter: hue-rotate(calc(var(--ce-hue) * -1)) saturate(3); }
.chromatic-lite::after  { transform: translateX(calc(var(--ce-shift) * -1)); filter: hue-rotate(var(--ce-hue)) saturate(3); }

数值出处:

  • 分离量默认 2px:社区量化参考 rdev/liquid-glass-react 的 aberrationIntensity: 2(README 核验【S】);路线 B 配方用 1.5px;hue-rotate ±28°、opacity .35、saturate(3):路线 B 配方记载值(调研 17 §6.3);
  • hyalite 官方建议【S】:色散 expressed in pixels of channel separation,独立于折射强度——「可单独归零省一次渲染」,所以 dispersion 是独立参数;
  • 路线 A 的 scale(位移幅度):MDN 示例用 50 为强扭曲,玻璃边建议 2–6(MDN feDisplacementMap 页核验);
  • 本体必须带色相:白/灰的色相错开几乎不可见——demo 卡用饱和渐变底(青→紫)让色差读得出来(工程推演,已在本站 demo 验证)。

动效与交互

色散是静态材质,几乎不需要动效:

  • 入场淡入 + 8px 上移;prefers-reduced-motion 时取消(本材质无自主动画,仅此一处);
  • 不要把 dispersion 绑到指针:指针驱动的实时色散意味着每帧两次全边缘重绘,且容易滑向「故障风」——那是另一个风格,不是玻璃;
  • 状态切换(卡片出现/消失)时色散层随本体一起过渡即可,不单独动画;
  • 生产建议:dispersion 归零开关做成站点级开关——省一次渲染成本(hyalite 官方做法【S】)。

真实产品案例

  • hyalite demo:SDF 透镜 + per-channel 色散的完整实现,demo 地址 https://vii-cae.github.io/hyalite—liquid-glass/demo/index.html(仓库元数据核验);
  • rdev/liquid-glass-react:以 aberrationIntensity(默认 2)参数化色散的社区组件(GitHub API + README 核验,6798★);
  • 同方向仓库:electrikmilk/liquid-css(「Refractive chromatic aberration effects in CSS」)、dpawlikowski/liquid-glass(「pure CSS and SVG… chromatic aberration, no WebGL」,GitHub API 核验);系统级产品中未观察到独立使用(调研 17 §6.6 如实标注)。

参数敏感度

参数调大会…调小会…
dispersion>4px 边缘出现明显「重影」,材质感转「故障感」;成本同步上升(两次边缘重绘)色差收窄;0 = 单关色散(省一次渲染,hyalite 官方做法),玻璃退回普通锐边
hueAngle±28° 以上红/青偏更浓;>45° 色散变成「彩虹包边」两层色相靠拢,错位只剩亮度差;0 = screen 混合同色,色散不可见
intensity>60% 边缘 ghosting 压过本体内容色散变隐约;10% 时只在深底亮缘处隐约可见

经验区间:dispersion 1.5–3px、hueAngle ±20–32°、intensity 25–45%。与 liquid-glass 条目互参:折射位移与 lensing 的官方定性在那里;与 backdrop-filter 条目互参:url() 引用的浏览器矩阵;与 halo-glow-border 条目互参:同为「边缘光学事件」,halo 加光、chromatic 偏色。

适用场景 3
  • 高折射玻璃拟真:强透镜感面板的边缘点睛(hyalite demo 的 SDF 透镜 + per-channel 色散,核验)
  • 科技感品牌强调:边缘 1–2px 的色差暗示「光学镜头」而非「贴图」
  • Chromium-only 的产品内嵌页(如 Electron 壳)可上路线 A;开放 web 一律路线 B
何时不要用 3
  • 正文与数据边缘:色差降低边缘锐度感知,密集文本上等于自带模糊
  • 低饱和底材:白/灰色相错开几乎不可见(saturate(3) 也救不了无色相的底)
  • 依赖 CSS.supports 特性检测启用路线 A:检测会撒谎(调研 17 §6.4)——必须用 UA 判断或直接接受降级
无障碍

色散是纯装饰:不得承载任何信息,decorative 伪层一律 pointer-events: none + aria 不可见;边缘文字的辨识度按未加色散的版本核对 4.5:1(WCAG 2.1 SC 1.4.3);prefers-reduced-motion 下本材质无自主动画,仅有输入驱动的入场。

浏览器支持

路线 A(SVG feDisplacementMap 进 backdrop-filter: url()):feDisplacementMap 本身 2015-07 起全浏览器,但 backdrop-filter 引用 SVG 滤镜只有 Chromium 完整支持——rdev README:「Safari and Firefox only partially support the effect」;hyalite README:「Actual refraction works only in Chromium… feature detection lies (CSS.supports returns true everywhere)」——不能用 CSS.supports 检测(调研 17 §6.4【S】)。路线 B(双层复制):全浏览器基线。

兼容回退

路线 B 即回退:双层复制 + 边缘蒙版在所有浏览器可用(调研 17 §6.4);或如 hyalite 一样直接回退为纯 blur。别用 CSS.supports 判断路线 A——它会到处返回 true。

来源 5

起源官方级做法由社区仓库 hyalite 背书:「Dispersion is done by running one displacement pass per RGB channel and summing them — expressed in pixels of channel separation, independent of lens strength」(README 全文核验【S】);feDisplacementMap 位移公式与 in/in2/scale 属性(MDN 全文核验);社区量化参考:rdev/liquid-glass-react 的 aberrationIntensity 默认 2(README 核验【S】);同方向仓库:electrikmilk/liquid-css、dpawlikowski/liquid-glass(GitHub API 核验)。双层复制 + 边缘蒙版的兜底路线为本站工程综合 [R](调研 17 §6.3)。
