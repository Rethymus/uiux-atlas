压暗层 Dimming Layer

压暗层 · Scrim · Dimming Layer · 遮罩压暗

压在下层内容上的半透明遮罩,为前景换回可读性:弹窗遮罩(::backdrop 纯色式)与文字压图(底部梯度式)两式,α 用官方/可核验档位分档。

结构与 DOM

压暗层是叠在下层内容与前景之间的独立遮罩,两种形态对应两个 DOM 位置:弹窗遮罩的真身是顶层元素的 ::backdrop 伪元素(无 DOM 节点);文字压图的梯度层是图片与图注之间的真实元素。

<!-- 纯色式:弹窗遮罩 -->
<dialog class="modal">
  <h3>标题</h3>
  <p>正文</p>
</dialog>
<!-- dialog::backdrop 即压暗层:与 viewport 同尺寸、渲染于顶层元素正下方、LIFO、不继承任何属性 -->

<!-- 梯度式:文字压图 -->
<figure class="figure">
  <img src="photo.jpg" alt="" />
  <div class="caption-scrim"></div>   <!-- 梯度压暗:底部向上 -->
  <figcaption>图注文字</figcaption>
</figure>

关键点:

  • ::backdrop 不继承任何属性——颜色、透明度必须在伪元素上完整声明,旧环境「遮罩消失」多半源于此(调研 12 §8);
  • 梯度式只在底部顶点达到 α 峰值:文字必须落在受保护的区域内,否则等于裸放;
  • 压暗层是内容与背景之间的一层,不是背景本身——它压暗的是「下层内容」,为「前景可读性」服务。

样式与参数

两个 CSS 变量型参数(strength → --dim-alpha、color → --dim-color)+ 一个 JS 型形态开关(mode):

/* 纯色式:弹窗遮罩(真身) */
dialog::backdrop {
  background: color-mix(in srgb, var(--dim-color) calc(var(--dim-alpha) * 100%), transparent);
}

/* 梯度式:文字压图 */
.caption-scrim {
  position: absolute;
  inset: auto 0 0 0;
  height: 55%;
  background: linear-gradient(to top,
    color-mix(in srgb, var(--dim-color) calc(var(--dim-alpha) * 100%), transparent),
    transparent);
}

α 档位(全部为调研记载值,无发明值):

  • 25% = MDN ::backdrop 典型示例 rgb(0 0 0 / 25%)(调研 12 §8);
  • 30% = SwiftUI Glass.clear 官方文档示例 .black.opacity(0.3)(调研 09 §1.3);
  • 35% = HIG 官方建议——「下层内容偏亮时,考虑添加 35% 不透明度的深色压暗层」(调研 09 §1.3,默认档);
  • 55% = 调研 12 §8 的 color-mix(in oklab, black 55%, transparent) 重遮罩配方。

补充参照:apple.com 玻璃底色按状态分档——浅 rgba(250,250,252,.8→.92)、深 rgba(22,22,23,.8→.88)(吸顶上浮,生产 CSS 实抓,调研 09 §1.4b);Material Design 的 scrim 规范值(M2 约 32% 黑)未证实,不设档。

动效与交互

  • 遮罩淡入:弹窗开启时 α 淡入约 0.25s(只动 opacity);突变压暗会让用户瞬间丢失下层上下文,淡入给出「进入模态」的过渡感;prefers-reduced-motion 时取消;
  • 模态语义:iOS 26 sheet 的官方定性是「玻璃轻微后退,配压暗层表达模态」(WWDC25 356 [438–494s],调研 09 §8.9)——压暗层是模态的视觉语法之一;
  • 局部压暗:小 footprint 元素用局部压暗(localized dimming)而非全屏遮罩(WWDC25 219,调研 09 §1.3);
  • 下层隔离:模态开启时下层禁滚(overscroll-behavior: contain,MDN 官方建议场景,调研 09 §7.1)。

真实产品案例

  • Apple HIG Liquid Glass(clear 变体):官方明文建议「下层内容偏亮时,考虑添加 35% 不透明度的深色压暗层」;SwiftUI Glass.clear 文档示例给出 .black.opacity(0.3)(调研 09 §1.3)——压暗是高透玻璃守住可读性的「门票」(调研 09 §11.6);
  • MDN <dialog> 官方示例:::backdrop { background: rgb(0 0 0 / 25%) } 是弹窗遮罩的典型档(调研 12 §8);同一文档体系在示例里还给 ::backdrop 配 backdrop-filter: blur(0.5rem)(调研 09 §7.1)——压暗与虚化的标准搭配;
  • apple.com 全局导航:玻璃底色三态——静置 0.8、吸顶上浮至 0.92(浅)/0.88(深)、展开转实色(生产 CSS 实抓,调研 09 §1.4b)——压暗底色随状态分档的生产实现。

参数敏感度

参数调大会…调小会…
strength → 55%重遮罩:下层几乎不可辨,注意力完全交给前景——只配真模态25% 轻遮罩:下层保持可感知;亮背景上的文字常常守不住 4.5:1,先加压再排版
strength → 35%(默认)官方建议档:下层内容偏亮时的兜底值30%(SwiftUI 示例)与 35% 之间肉眼差异小;低于 30% 需逐背景实测
mode → gradient只压底部:媒体主体保留、图注获得满档 α;顶部文字不受保护纯色式:全区域均匀、可读性最稳——弹窗的默认形态
color掺品牌色(12 §16.10 技巧)让遮罩带主题色相;掺色后对比关系全部重测纯黑最稳;偏白遮罩(亮化)是另一种形态,语义从「压暗」变为「提亮」

经验区间:常规模态 25–35% 起步,亮色媒体上向 35–55% 加码;梯度式高度约占图高一半(55%),文字必须落在峰值区。α 的裁决标准只有一条:前景文字对「下层最亮内容」守住 4.5:1(WCAG 2.1 SC 1.4.3)。

适用场景 4
  • 模态弹窗/对话框背后的纯色遮罩(::backdrop 形态)——把注意力让给前景并把下层压到可容忍的噪声级
  • 照片/视频上的图注与字幕条(梯度式)——只压文字落点,媒体主体保留
  • iOS 26 sheet 的模态语义:「玻璃轻微后退,配压暗层表达模态」(WWDC25 356,调研 09 §8.9)
  • clear 玻璃控件压在亮色媒体上:官方「下层内容偏亮时加 35% 深色压暗层」的推荐场景
何时不要用 4
  • α 不足还要硬放文字——下层内容偏亮时 α 低于 30% 常常守不住 4.5:1,先加压暗再谈排版
  • 全屏重遮罩(≥55%)叠在需要保留上下文的界面上——下层几乎不可辨,模态之外的场合不要用
  • 梯度式遮罩保护不到的文字位置——渐变只在底部顶点达到 α 峰值,顶部文字等于裸放
  • 掺品牌色的遮罩不复核对比度——色相偏离黑/白后,与前景的对比关系全部改变
无障碍

压暗层存在的唯一理由是对比度:遮罩上的前景文字必须按「下层最亮内容」核对 4.5:1(WCAG 2.1 SC 1.4.3);模态形态应配合焦点管理(打开时焦点入弹窗、关闭时归还,WCAG 2.1 SC 2.4.3)与下层滚动隔离(overscroll-behavior: contain);α 档位切换不得作为传达状态的唯一手段;深浅两层背景要分别实测。

浏览器支持

::backdrop Baseline 自 2022-03(调研 12 §8);color-mix() Baseline 自 2023-05(Chrome 111+ / Safari 16.2+ / Firefox 113+,调研 12 §11)。::backdrop 不继承任何属性——颜色必须在伪元素上完整声明,这也是旧浏览器上「遮罩消失」的常见原因。

兼容回退

不支持 color-mix() 时用 rgba() 直接写同值透明度;不支持 ::backdrop 的环境(旧浏览器)改为在弹窗元素前插一个真实遮罩 div(全屏 fixed、z-index 次于弹窗)——这也是 ::backdrop Baseline 之前的通行做法。压暗层不承载内容,降级不影响功能。

来源 3

起源web 原生载体是顶层元素的 ::backdrop 伪元素——与 viewport 同尺寸、渲染于顶层元素正下方、LIFO、不继承任何属性(MDN,调研 12 §8);Apple HIG 给出唯一一条官方数值建议:「下层内容偏亮时,考虑添加 35% 不透明度的深色压暗层」,SwiftUI Glass.clear 文档示例为 .black.opacity(0.3)(调研 09 §1.3)。Material Design 的 scrim 规范值(M2 约 32% 黑)未能核验,不采用(调研 12 §8 如实标注)。
