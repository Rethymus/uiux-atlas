混合模式 Blend Modes

混合模式 · mix-blend-mode · background-blend-mode

CSS 混合模式:Compositing and Blending Level 1 定义的 16 种命名模式,经 mix-blend-mode(元素与其背景)或 background-blend-mode(同一元素的多层背景)叠加。

Web 标准 ★★
实例演示 官方默认
参数
动效▾
modenormal

混合模式枚举,取 Compositing 1 §10.1 全部 16 个命名值。默认 normal 为规范 initial value(不混合,直接遮住下层)。前 12 种按分量混合明暗,后 4 种(hue/saturation/color/luminosity)按 non-separable 亮度/色相分量混合。

几何▾
opacity100%
%

混合层的整体不透明度,默认 100% 对应 CSS opacity 的 initial value(1)。降不透明度 = 混合结果与原样按 alpha 插值,常用于把强混合(multiply/difference)调到可用强度。

结构与 DOM

混合模式有两个入口:mix-blend-mode 把整个元素与其背后内容混合;background-blend-mode 只混合同一元素自己的多层 background。demo 用前者:底层彩色渐变 + 上层近白渐变,混合范围用 isolation: isolate 限定在舞台内:

<div class="stage">              <!-- isolation: isolate -->
  <div class="layer-a"></div>    <!-- 底层:彩色渐变 -->
  <div class="layer-b"></div>    <!-- 上层:mix-blend-mode + opacity -->
</div>

关键点:

  • 混合发生在同一个 stacking context 内——没有 isolate 时,上层会一路混到页面背景,这是最常见的翻车点;
  • mix-blend-mode 会让元素形成一个独立合成层,其效果等价于规范定义的「源 = 元素渲染结果,目标 = 其背后所有内容」;
  • 16 种模式全部是规范命名值,不可自造(如 linear-burn 不存在)。

样式与参数

两个参数各对应一条声明:

.stage { isolation: isolate; }
.layer-a {
  background:
    radial-gradient(60% 80% at 22% 24%, oklch(0.66 0.2 330 / 0.9), transparent 70%),
    radial-gradient(55% 70% at 80% 22%, oklch(0.72 0.16 85 / 0.85), transparent 68%),
    linear-gradient(140deg, oklch(0.4 0.12 250), oklch(0.34 0.1 190));
}
.layer-b {
  background: linear-gradient(120deg,
    oklch(0.96 0.03 260), oklch(0.93 0.05 320) 60%, oklch(0.9 0.04 200));
  mix-blend-mode: var(--blend-mode);  /* normal(默认)…luminosity,16 种 */
  opacity: var(--blend-opacity);      /* 100%(默认)= 不做 alpha 衰减 */
}

数值出处:

  • 16 种枚举逐一取自 Compositing 1 §10.1 的命名清单:normal、multiply、screen、overlay、darken、lighten、color-dodge、color-burn、hard-light、soft-light、difference、exclusion、hue、saturation、color、luminosity(调研 02§D3,规范页已一手核验);
  • normal 与 opacity: 1 为规范 initial value(故作默认);
  • demo 的渐变色为演示用 oklch 光斑(结构照 MDN《Using CSS gradients》的多层叠加式),非规范内容。

动效与交互

模式切换本身无需动画——混合结果即时生效,这也是它适合做交互式调色的原因:

  • 切换 --blend-mode 是一次样式重算,肉眼即时可见;避免对 mix-blend-mode 值本身做过渡(规范未定义混合函数间的插值,过渡行为不可预期);
  • opacity 可以正常过渡(alpha 插值有明确定义),用来做混合层的淡入;
  • difference 类模式配合指针移动(把上层跟手)是经典「反色探照灯」玩法,但要注意重绘成本;prefers-reduced-motion 时取消跟手动画,demo 已处理。

参数敏感度

参数调大会…调小会…
mode(按族)明暗族(multiply/color-burn/darken)整体压暗压深;提亮族(screen/color-dodge/lighten)洗白发光;difference/exclusion 出高对比反色;hue/saturation/color 只换色相不保亮度,luminosity 只留亮度回到 normal 即纯遮盖;soft-light/hard-light 居中,变化温和——先从这两档探路最安全
opacity100% 时混合全强度,multiply/difference 可能压得文字无法读向 0% 退化为「逐渐消失的 normal」,混合感按 alpha 线性衰减;50–70% 常是强模式的可用区

经验法则:上层越「白」,multiply/overlay 的效果越像给底图打光;上层越「黑」,screen 越像镂空。文字要落在混合层上时,先试 soft-light + opacity ≤70%,再用取色器对最终合成结果核对比度。

与 background-blend-mode 的分工:两层背景同属一个元素时优先用它,天然没有 stacking context 陷阱;demo 用 mix-blend-mode 是因为两层是独立元素,需要 isolation 划界。

适用场景 4
  • 文字与彩色底的可控反色:difference/排除 让文字在任意底上自动可读的『反色标题』
  • 双层渐变/光斑的色彩融合:multiply/overlay 压出深度,screen 提亮氛围(极光、玻璃底衬的常用搭档)
  • 同一元素多层背景的混合:background-blend-mode 让照片与品牌色一次成型
  • 色相/明度分离式调色:hue/color/luminosity 做『保持明度只换色相』的风格化
何时不要用 4
  • 跨 stacking context 的意外混合:上层元素意外混到页面背景——用 isolation: isolate 限定混合范围
  • 正文文字上叠 difference/强混合——对比度随下层内容实时变化,无法静态验收
  • 高频重绘区域(拖拽、滚动跟随)上用混合——每次合成都要重算混合,代价高于普通合成
  • 需要精确品牌色的输出——混合结果取决于两层的具体色值,不可移植
无障碍

混合模式改变实际呈现的对比度:文字经混合后的前景/背景对比必须按最终合成结果核算 WCAG 2.1 SC 1.4.3(4.5:1)/SC 1.4.11(3:1),不能按原色声明;混合是纯视觉手段,信息必须有非混合的呈现路径(如 hover 后的实色版)。

浏览器支持

BCD(调研 02§D3/§D4 表):mix-blend-mode Chrome 41 / Firefox 32 / Safari 8;background-blend-mode Chrome 35 / Firefox 30 / Safari 8。isolation 同族支持。全部为多年基线能力。

兼容回退

不支持混合模式的环境退回 normal 叠放(上层遮住下层)——信息不丢,只损失色彩融合;需要保底观感时,把关键配色预先混进下层渐变本身,而不是依赖运行时混合。
