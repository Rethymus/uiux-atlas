湍流液缘 Turbulence Edge

boiling edge · feTurbulence liquid edge · 沸腾边缘 · 湍流边缘

feTurbulence + feDisplacementMap 把纯色遮罩的硬边扭成有机液缘,逐帧步进 seed 得到持续「沸腾」的边缘;每像素位移 = scale×(噪声−0.5);滤镜只能挂普通元素层,不能上过渡伪元素(spike S5 反证)。

Web 标准 ★★
实例演示 官方默认
参数
几何▾
baseFrequency0.012

噪声基础频率(每 px 的周期数)。默认 0.012 为 spike 在纯色遮罩上的实证档(0.012/0.02);MDN 官方示例为 0.05。调大边缘越碎、高频毛刺越密集,0.05 量级已是「碎浪」;调小趋近 0.005 时边缘呈大起伏长波,毛边感减弱。demo 把单一值同置 x/y 两轴;站点液缘配方可用双值「0.012 0.05」把横向拉长呈丝状(调研 20§6.2)。

scale60px
px

feDisplacementMap 的最大位移(px)。每像素实际位移 = scale × (噪声通道值 − 0.5),落在 [−scale/2, +scale/2]。默认 60 为 spike 在纯色遮罩上的实证值(有机液缘清晰);调研 §6.2 的液缘描边场景建议 10–20(细毛边)。调大扭曲越强,超过 100 后边缘可能撕裂出孤岛像素;调小趋近 0 退回光滑硬边(滤镜等于没开)。

boil11

seed 步进频率(步/秒),0 = 冻结种子(静态液缘)。spike 以 90ms 间隔步进 seed 实证沸腾成立(≈11 步/秒,帧间 diff ≈2 万像素);调研 §6.2 建议「每 3–4 帧步进」(60fps 下 ≈15–20 步/秒)。调大沸腾更急促、滤镜重渲染更频繁(开销随频率线性上升);调小趋近 0 液缘静默。seed 只换噪声场、不改变计算量,所以「步进 seed」比「步进 baseFrequency」便宜。

代码拆解

结构与 DOM

架构是双层渲染(spike 20a 推荐架构 2):纯色遮罩 + SVG 滤镜挂在普通元素层上,绝不写进 ::view-transition-* 伪元素——spike S5 实测滤镜在过渡伪元素上被忽略、且冻结裁剪态下改 seed 帧间 diff=0。遮罩层与换肤逻辑解耦,液缘只是表演层:

<svg width="0" height="0" aria-hidden="true">
  <filter id="liquid-edge">
    <feTurbulence type="turbulence" baseFrequency="0.012 0.05" numOctaves="2" seed="7" result="n"/>
    <feDisplacementMap in="SourceGraphic" in2="n" scale="14" xChannelSelector="R" yChannelSelector="G"/>
  </filter>
</svg>
<div class="liquid-mask" style="filter:url('#liquid-edge')"><!-- 纯色遮罩,硬边被扭成液缘 --></div>

(配方出自调研 20§6.2)

关键点:

  • 位移作用于整个 SourceGraphic:纯色遮罩内部各像素位移后仍是同一纯色(不可见),唯独边缘处像素被推入/推出——硬边被扭成有机液缘,这正是「作用于纯色遮罩」的原因;
  • seed 属性唯一决定噪声场形状:逐帧步进 seed = 边缘持续「沸腾」(spike 以 90ms 步进实测成立,帧间 diff ≈2 万像素);
  • 滤镜区要留出血(x/y=-20%、width/height=140%),防止被推出去的边缘像素被裁掉;
  • 与 gooey(blur+contrast)家族的区别:goo 融合多个形状(CSS-Tricks《The Gooey Effect》),湍流只扭曲单个遮罩的边;与 motion/theme-wave-flood 的关系:那条目的平滑波缘由 JS 逐帧算 path,本条目的毛边由滤镜静态扭出——两者可叠成「波身 + 毛缘」;
  • motion/view-transitions / color/theme-transition 的揭示层如果需要毛边,应把本滤镜层叠在其外(双层渲染),或把噪声项直接烘进逐帧 path(§6.2 的另一条路线)。

样式与参数

MDN 官方示例是所有参数语义的起点(§2.5,逐字):

<feTurbulence type="turbulence" baseFrequency="0.05" numOctaves="2" result="turbulence"/>
<feDisplacementMap in2="turbulence" in="SourceGraphic" scale="50" xChannelSelector="R" yChannelSelector="G"/>

位移公式(MDN 逐字):P'(x,y) ← P(x + scale·(XC(x,y) − 0.5), y + scale·(YC(x,y) − 0.5))——即每像素位移 = scale × (噪声通道值 − 0.5),取值落在 [−scale/2, +scale/2];XC/YC 取 in2 噪声图的 R/G 通道(0–1 归一),scale 即最大位移像素数。

三个 JS 型参数(demo 订阅 store 后注入滤镜):

  • baseFrequency:默认 0.012(spike 实证档 0.012/0.02);MDN 示例 0.05;
  • scale:默认 60(spike 实证值);液缘描边场景建议 10–20(§6.2);
  • boil:seed 步进频率,默认 11 步/秒(spike 90ms 间隔实测);§6.2 建议「每 3–4 帧步进」≈15–20 步/秒;
  • numOctaves 固定 2(MDN 官方示例与 spike 一致);demo 用 fractalNoise 型——spike S5 在纯色遮罩上实证的就是该型(§6.2 配方的 turbulence 型是站点液缘描边变体)。

动效与交互

  • 沸腾:rAF 累计器按 boil(步/秒)步进 seed → feTurbulence 重渲染 → 边缘形状持续变化;boil=0 冻结种子;seed 步进只换噪声场、计算量不变,比调 baseFrequency 便宜;
  • 主题切换:点击切换钮,新主题色遮罩自底部涌入(500ms = M3 整屏档,§5),前缘即湍流液缘;覆盖完成瞬间翻转 data-fx-theme(液面恰已盖满,换肤无可见缝)、液层随即归位——与 motion/theme-wave-flood 的差异:波身是直边被滤镜扭弯,不需要逐帧 path 数学;
  • 过渡中再次点击:旧过渡立即收尾(主题落定、液层隐藏),新过渡完整播放,不停在半途;
  • reduced-motion:seed 步进停止、切换瞬时完成(时长视作 0)——沸腾是持续环境动画,必须可停;
  • 性能:滤镜重渲染开销随面积线性涨(Bebber「大面积耗性能」告诫同族,§2.4);demo 把沸腾限制在舞台内、步进频率 11 步/秒,且步进 seed 而非 baseFrequency。

真实产品案例

  • MDN 官方配方示例:feTurbulence + feDisplacementMap(baseFrequency 0.05 / numOctaves 2 / scale 50 / RG 通道)套在 <circle> 上——本效果全部参数语义与位移公式的权威出处(调研 20§2.5);
  • luukdv/gooey-react(React,676★,README 与文档站 gooey-react.netlify.app 核实):把 SVG 滤镜组件化到 DOM 元素并补齐 Safari 支持的先例,证明「DOM 元素 + filter:url(#id)」通路可生产化(§4);
  • Chrome for Developers 主题切换官方配方(同族对照,§1.1):湍流液缘常叠在它的揭示层之外作边缘装饰——双层渲染组合(spike 推荐架构 2)。
  • 注:2026 年 Safari 对 DOM 元素套 SVG 滤镜的支持现状未复测(§9 未证实清单),上线前需真机验证;网页端大厂产品把该滤镜用于主题切换的公开实现未找到,不虚构。

参数敏感度

参数调大会…调小会…
baseFrequency边缘越碎、高频毛刺越密;0.05 量级(MDN 示例档)已是「碎浪」大起伏长波,毛边感减弱;0.005 附近近乎直边微颤
scale扭曲越强;超过 100 边缘可能撕裂出孤岛像素,且需更大出血区趋近 0 退回光滑硬边(滤镜等于没开);10–20 是细毛边档(§6.2)
boil沸腾更急促,滤镜重渲染更频繁、开销线性上升;上限附近对低端机压力大液缘趋静;0 = 冻结种子,静态液缘(装饰仍在、动效归零)

经验区间:baseFrequency 0.008–0.02(spike 实证 0.012/0.02)、scale 10–60、boil 8–15 步/秒;numOctaves 2 起步,3 以上细节更碎但开销上升;滤镜区出血至少 scale/2,防止边缘像素被裁。

适用场景 4
  • 主题切换揭示层的边缘处理:双层渲染——滤镜层是独立普通元素,叠在揭示层之外(spike S5 反证滤镜不能上过渡伪元素)
  • 液体/水体 UI 的常驻环境动效:水位面板、注水卡、液态分隔带的「沸腾」边缘
  • 插画感章节过渡与装饰条带:纯色块 + 有机硬边,不需要逐帧 path 数学
  • 与 motion/theme-wave-flood 组合:平滑波缘烘进 path,湍流毛边走本条目的独立滤镜层(spike 推荐架构 2)
何时不要用 4
  • 把滤镜写进 ::view-transition-* 伪元素求液缘——spike S5 反证:滤镜被忽略、冻结裁剪态下 seed 变化帧间 diff=0
  • 大面积长时间沸腾不做节流——滤镜逐帧重渲染开销随面积线性涨(Bebber「大面积耗性能」告诫同族,§2.4)
  • prefers-reduced-motion 用户仍看持续沸腾——持续环境动画必须可停(HIG Motion / WCAG 2.3.3 精神)
  • 用湍流滤镜扭曲小号正文文字——位移作用于整个 SourceGraphic,文字随边缘一起被揉皱,可读性直接受损
无障碍

沸腾是持续环境动画:prefers-reduced-motion 下必须停止 seed 步进、切换瞬时完成;HIG(visionOS)告诫避开约 0.2Hz 的持续振荡(人对该频率极敏感)——seed 步进属空间噪声变化而非周期性振荡,但常驻动效仍应可关且默认克制(boil 11 步/秒、面积收敛)。主题信息由颜色与 data-theme 属性承载,液缘只是边缘装饰,不得作为传达状态变化的唯一手段(WCAG 2.3.3 精神);滤镜层 aria-hidden 且 pointer-events:none。

浏览器支持

feTurbulence / feDisplacementMap 属 SVG 1.1 滤镜基元,Baseline Widely available 自 2015-07(MDN,调研 20§1.4);CSS filter:url(#id) 引用文档内 SVG 滤镜是标准语法(CSS-Tricks goo 全文示例,§2.4)。历史告诫:2015 年 Safari 对 DOM 元素套 SVG 滤镜支持差(Bebber 原文),2026 年现状未复测——未证实(§9 未证实清单 2),上线前需真机验证。

兼容回退

SVG 滤镜不可用或引用失效 → 撤掉 filter,纯色遮罩回退为光滑硬边——平滑边缘本身就是可独立成立的底型(调研 §6.2 降级路径);prefers-reduced-motion: reduce → 停止 seed 步进(沸腾是持续环境动画)且切换瞬时完成(时长视作 0);滤镜渲染失败不阻塞主题切换本身——换肤只翻 data-theme,液缘只是表演层。

来源 4

起源基元与公式核验自 MDN(调研 20§2.5):feTurbulence 用 Perlin 湍流函数生成噪声(type/baseFrequency/numOctaves/seed),feDisplacementMap 位移公式 P′(x,y) ← P(x + scale·(XC−0.5), y + scale·(YC−0.5)) 为 MDN 逐字,scale 即最大位移像素数;MDN 官方示例 type=turbulence / baseFrequency 0.05 / numOctaves 2 / scale 50 / RG 通道套在 circle 上。液缘场景参数(水平频率 0.01 量级、scale 10–20、seed 每 3–4 帧步进)出自调研 20§6.2。技术 spike 20a S5 实测:fractalNoise + baseFrequency 0.012/0.02 + numOctaves 2 + scale 60 作用于纯色遮罩得到有机液缘,90ms 步进 seed 得到沸腾(帧间 diff ≈1.9–2.2 万像素);同一滤镜挂 ::view-transition-new(root) 被忽略且不随 seed 重渲染——故架构定为双层渲染的普通元素层。
