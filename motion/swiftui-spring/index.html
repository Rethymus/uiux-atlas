SwiftUI 弹簧 SwiftUI Spring

Apple 弹簧 · response/dampingFraction · .spring()

SwiftUI .spring(response:dampingFraction:blendDuration:) 两参数弹簧:response 是刚度的时间尺度(秒),dampingFraction 是相对临界阻尼的比例——iOS 原生手感的来源。

Apple HIG ★★★
实例演示 官方默认

弹簧刚度的时间尺度,以近似时长(秒)表达(Apple 原文:『response 是以近似时长表达的刚度』,0 表示无限刚、适合交互驱动)。官方默认 0.5s(Apple DocC)。调大更慢更黏;调小更急促,趋近 interactiveSpring 的交互区间。

结构与 DOM

演示是两条并排弹簧轨,同起点、同目标、同时发射:上轨跑预设(Apple 官方 duration+bounce 定义),下轨跑自定义 response/dampingFraction(换算成 Motion 物理弹簧)。每条轨道只有三件套 DOM:

<div class="ss-lane">
  <div class="ss-end ss-end-l"></div>
  <div class="ss-end ss-end-r"></div>
  <motion.div class="ss-ball" style={{ x }} />  <!-- x 即 useMotionValue -->
</div>

关键点:

  • 球的位置由 useMotionValue 驱动 transform: translateX,对同一个 MotionValue 调用 animate() 即可发射/打断;
  • 两轨共用一个「发射」入口(按钮或点击轨道),保证手感差异在同一时间轴上可直接对照;
  • 读数条实时显示换算出的 stiffness/damping(下轨)与预设 bounce(上轨),数值与手感一一对应。

样式与参数

三个参数都是 JS 型(无 CSS 变量),由 demo 订阅 store 组装 Motion transition:

// SwiftUI response/dampingFraction → Motion stiffness/damping 换算:
// 二阶阻尼谐振子(mass = 1)的标准等价——
//   stiffness = (2π / response)²
//     (Apple 定义:response 是「以近似时长(秒)表达的刚度」≈ 固有周期,ω₀ = 2π/response)
//   damping = 4π × dampingFraction / response
//     (Apple 定义:dampingFraction 是「相对临界阻尼所需阻尼量的比例」,ζ = c / (2√(km)))
// 注意:这是物理推导的换算,Apple 与 Motion 均未发布官方互转公式。
const stiffness = (2 * Math.PI / response) ** 2;          // 默认 0.5s → ≈ 157.9
const damping = (4 * Math.PI * dampingFraction) / response; // 默认 0.825 → ≈ 20.7
animate(xCustom, target, { type: "spring", stiffness, damping, mass: 1 });

// 上轨:预设严格按 Apple 官方定义(duration 0.5s + 基础 bounce)
animate(xPreset, target, { type: "spring", duration: 0.5, bounce: bounceOf(preset) });

数值出处(Apple DocC,官方 JSON 数据接口核实;调研 02§A11/A13、04§1.3B 双源一致):

  • response 官方默认 0.5s、dampingFraction 官方默认 0.825(blendDuration 默认 0,不在本条目参数内);
  • 预设族官方定义:bouncy = duration 0.5s + bounce 0.3、snappy = 0.5s + 0.15、smooth = 0.5s + 0;
  • 参数语义为 Apple 原文:response=「以近似时长表达的刚度」,dampingFraction=「相对临界阻尼所需阻尼量的比例」。

Motion 消费换算结果:motion.dev 文档定义 type:"spring" 接受 stiffness/damping/mass(默认 1/10/1,见 motion-spring 条目),与 SwiftUI 体系同族但参数轴不同——不能直接互传,必须走上面的换算。

动效与交互

  • 同跑对照:点「发射」(或任一轨道/回车)两轨同时奔向同一目标——snappy 与自定义 0.5/0.825 的差异、bouncy 的回弹次数,一眼可辨;
  • 参数即改即看:拖动 response/dampingFraction 滑杆会打断下轨当前弹簧并从当前位置续接(Motion 物理弹簧继承当前值速度,文档默认行为);选预设则切换上轨的 bounce;
  • 对照组的存在理由:预设是 duration+bounce 体系(总时长可预估),response/dampingFraction 是刚度+阻尼体系(手感可迁移)——同一颗球两条轨道,把两套体系的差异变成可见事实;
  • reduced-motion:检测到 prefers-reduced-motion: reduce 时跳过动画,球直接落在目标位;读数条仍显示当前参数换算值;
  • 性能:只动画 transform(球位移),符合 web.dev 底线(调研 04§1.5)。

参数敏感度

参数调大会…调小会…
response弹簧更慢更黏:换算 stiffness 按 1/response² 陡降,行程耗时明显拉长更急促利落;趋近 0.1 时接近「弹射」,Apple 明示 0=无限刚适合交互驱动
dampingFraction趋近 1 回弹消失(临界阻尼);>1 过阻尼,缓慢爬向目标回弹增多,<0.5 明显振荡;0.825 官方默认是「带一丝回弹」的平衡点
presetbouncy(基础 bounce 0.3)回弹幅度最大、次数最多smooth(基础 bounce 0)临界阻尼无回弹;snappy(0.15)居中,Apple 定位为通用交互
换算值(只读)stiffness 越大越突然、damping 越大越快吸收振荡——两者都由 response/dampingFraction 唯一决定同理反向;读数条让你在拖滑杆时看到数值随动,建立「参数轴↔手感」直觉

选型口诀:对齐 iOS 手感 → response/dampingFraction(可从系统控件实测值出发);对齐时间轴 → 预设 duration+bounce;两套体系换算走二阶阻尼谐振子等价,不要直接互传。

适用场景 4
  • iOS 原生手感的跨端复刻:用 response/dampingFraction 对齐系统控件
  • 默认 0.5s/0.825 适合大多数浮层、卡片与切换;想要更利落先调小 response
  • 预设族选型:回弹选 bouncy、通用交互选 snappy、无回弹选 smooth(官方定义见参数说明)
  • 交互驱动的跟手动画:response 调小(趋近 0=无限刚),Apple 明示 0 适合交互驱动
何时不要用 4
  • 进度条等连续量——不该有回弹(参考 motion 弹簧条目同款告诫)
  • Web 端把 response/dampingFraction 当官方互换参数直接传给 Motion——两者参数体系不同,必须换算
  • 高频小控件(checkbox 等)加弹簧——HIG:高频交互避免加动效(调研 04§2.1)
  • 把预设(bouncy/snappy/smooth)与 response/dampingFraction 混为一谈——预设的官方定义是 duration+bounce 体系
无障碍

弹簧属位移类动效,是前庭障碍的常见触发源:必须响应 prefers-reduced-motion(demo 直出终态);不要让『等弹簧播完』成为操作前置条件(HIG:动效可取消);回弹幅度(dampingFraction 调小)会放大位移不适,弱跌用户与 0.2Hz 振荡敏感人群尤甚(调研 04§1.6/§6)。

浏览器支持

原生 API 属 SwiftUI(iOS 13+);Web 端等价物由 Motion(前 Framer Motion)的物理弹簧承载——两套参数体系为当前主流(调研 04§1.3)。demo 为 Web 演示:依赖 JS 执行,禁用 JS 时元素停在初始位置。

兼容回退

prefers-reduced-motion 时直出终态(demo 以 useReducedMotion 检测并跳过动画);动效不作传达关键信息的唯一手段(HIG 动效原则);连续 spring 动画接力会保留速度——打断不是重置(调研 04§1.3B)。

来源 4

起源Apple DocC 官方默认值:response = 0.5s、dampingFraction = 0.825、blendDuration = 0(经官方文档 JSON 数据接口核实,调研 02§A11 与 04§1.3B 双源一致);预设族 bouncy/snappy/smooth 官方定义为 duration 0.5s + 基础 bounce 0.3/0.15/0(调研 02§A13)。
