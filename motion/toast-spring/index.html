Toast 弹簧入场 Toast Spring Entrance

toast 入场 · snackbar spring · 过冲 bezier · toast bounce-in

Toast 从屏幕边缘弹入:入场带过冲(真弹簧或 y₂>1 的过冲 bezier),退场纯缓出收尾,生命周期到点自动消失——『进攻退守,一进一出永不打架』。

组件库 ★★★
实例演示 官方默认
参数
几何▾
stiffness300

入场弹簧刚度(mass=1)。默认 300 取调研 10§2.3『中·微弹』档(与卡槽弹簧同档):ω₀≈17.3rad/s。Motion 源码默认 100(调研 10§6.3)。调大弹入更猛;调小飘入感更强、占屏时间变长。

damping25

入场弹簧阻尼。默认 25 与刚度 300 配对 ζ≈0.722、过冲≈3.8%——与 react-hot-toast 过冲 bezier 的轻微过冲量级相当(调研 10§2.3/§5.1)。调大回弹消失(ζ→1);调小过冲变大,ζ<0.5 时 toast 会明显弹跳。

lifetime4000ms
ms

自动消失计时。默认 4000 = sonner `TOAST_LIFETIME = 4000` 源码值(调研 10§5.1);AntD message 默认 3s(调研 06§4.10)。低于 2s 时读不完即消失、违反 WCAG 2.2.3 风险陡增;上限 8s 再长用户会误以为需要手动关。

动效▾
edgebottom

JS 型参数(demo 订阅后切换弹入边缘)。底部弹出贴近拇指/视线收尾区,顶部弹出更醒目(MUI Snackbar 默认底、AntD message 默认顶居中,见 components/toast 条目);方向语义:toast 从哪条边来、退场回哪条边去。

代码拆解

结构与 DOM

Toast 系统四件:触发按钮、堆叠容器(role=status,aria-live=polite)、单条 toast(圆点 + 文案 + ✕)、计时器表。容器绝对定位在边缘(底部/顶部),toast 从同一边缘弹入、退场回同一边缘:

<div class="ts-stack" role="status" aria-live="polite">
  <div class="ts-toast">
    <span class="ts-dot"></span> 已保存到云端 <button class="ts-close">✕</button>
  </div>
</div>

关键点:

  • 堆叠容器固定在边缘、pointer-events: none,单条 toast 恢复 auto——不挡下层交互;
  • AnimatePresence 编排退场:移除数据后由 Motion 播完 0.4s 缓出再卸 DOM,避免闪跳(调研 10§3.3 同语义);
  • 堆叠上限 3 条,超限移除最旧;每条 toast 一个 setTimeout 计时器,手动关闭/卸载时清理;
  • ✕ 手动关闭 + role=status 播报,满足「可关闭的非关键信息」(与 components/toast 条目同口径)。

样式与参数

四个参数全部 JS 型,demo 组装 Motion transition:

// 入场:真弹簧(stiffness/damping 可调)+ react-hot-toast 同构初态
<motion.div
  initial={{ y: `${dir * 160}%`, scale: 0.6, opacity: 0.5 }}   // 屏外滑入 + 缩小 + 半透明
  animate={{ y: "0%", scale: 1, opacity: 1,
    transition: { type: "spring", stiffness: 300, damping: 25, mass: 1 } }}
  exit={{ y: `${dir * 160}%`, scale: 0.6, opacity: 0,
    transition: { duration: 0.4, ease: [0.06, 0.71, 0.55, 1] } }} // 退场纯缓出回边缘
/>
// lifetime 到点 setTimeout 后触发 exit(sonner TOAST_LIFETIME = 4000 同款)

数值出处(调研 10§5.1/§5.2 源码逐字):

  • react-hot-toast 入场:从屏幕外 200% 滑入 + scale(.6) + opacity .5,0.35s cubic-bezier(.21,1.02,.73,1)(y₂>1 → 轻微过冲);退场 0.4s cubic-bezier(.06,.71,.55,1) 纯缓出;reduced-motion 退化为纯 fade;容器 will-change: transform;
  • sonner:过渡 400ms、TOAST_LIFETIME = 4000(4s 自动消失)、后排下沉堆叠 translateY(40%);
  • 真弹簧档位:Motion 版 bounce 0.25 + visualDuration 0.35(调研 10§5.2);bounce 0.25 → ζ=0.75(bounceToDampingRatio 源码换算,调研 10§6.3);demo 默认 stiffness 300 / damping 25(ζ≈0.722、过冲≈3.8%)取同一『弹而不闹』区间(调研 10§2.3);
  • 生命周期下限的规范依据:WCAG 2.2.3(自动消失需可暂停/持久)与 WAI-APG Alert 告诫——详见 components/toast 条目。

动效与交互

  • 进攻退守(调研 10 签名巧思 6):入场带过冲(弹簧或 y₂>1 bezier),退场纯缓出收尾——「进攻」的动感与「退守」的安静分工明确;.35/.40 一进一出永不打架;
  • 边缘语义:从哪条边来回哪条边去(bottom/top 可切);toast 永远不从屏幕中央出现(M3 enter-exit 同则,调研 04§3.3);
  • 参数即改即看:拖 stiffness/damping 立即影响下一条 toast 的弹入手感;ζ≈0.72 过冲约 4%,与过冲 bezier 观感同级;
  • 手动关闭/批量:✕ 立即移除;连点触发时堆叠到 3 条,最旧的先退场;
  • reduced-motion:入/出都退化为 0.2s 纯 fade(react-hot-toast 官方降级路径);
  • 性能:入场/退场只动 transform/opacity;容器 will-change: transform 与 react-hot-toast 同款(常驻单容器场景,调研 10§5.1/§7.2)。

真实产品案例

  • react-hot-toast:200% 滑入 + scale 0.6 + 过冲 bezier 0.35s / 缓出 0.4s——本条目入场编排的直接源码出处(调研 10§5.1);
  • sonner(Shadcn 生态默认 toast):400ms 过渡 + 4s 生命周期 + 后排下沉堆叠与滑出手势(vaul 同作者的 EASE [0.32,0.72,0,1]、CLOSE_THRESHOLD 0.25)(调研 10§5.1);
  • Gmail「邮件已发送」:底部弹出 toast 附「撤销」动作,自动消失后动作失效——toast 携带动作 + 生命周期的经典产品案例(与 components/toast 条目互链)。

参数敏感度

参数调大会…调小会…
stiffness弹入更猛更利落,屏外行程耗时缩短飘入感强,toast 「悬浮时间」变长;≤100 时像纸片漂上来
dampingζ↑ 回弹消失,入场收敛为一次到位(ζ→1)过冲变大;ζ<0.5 明显弹跳,连续保存时像果冻
edgebottom 贴拇指区、不打断阅读(MUI 默认)top 更醒目但压内容(AntD message 默认顶居中);同站固定一边
lifetime停留更久、可读性更好;>8s 用户误以为需要手动关读不完即消失;<2s 违反 WCAG 2.2.3 的风险陡增;4s 是 sonner 源码档

经验区间:stiffness 200400 / damping 2030(过冲 2%8% 的「弹而不闹」带)、lifetime 35s、堆叠 ≤3;入场短于退场是铁律——进攻可以带弹,退守必须安静。

适用场景 4
  • 保存成功/已复制/已发送类即时确认——从边缘弹入、4s 后自动退场(sonner 生命周期档)
  • 轻量反馈但想要『有生命感』:真弹簧(300/25)或过冲 bezier(.21,1.02,.73,1) 替代平淡 fade
  • 移动端底部边缘:与手势区重合,弹入后可用下滑手势提前退场(sonner/vaul 的滑出语义)
  • 批量操作的多条反馈:堆叠上限 2~3 条,超限移除最旧(与 components/toast 的 maxCount 同则)
何时不要用 4
  • 关键信息(错误需要动作、账户安全)用 toast 自动消失——违反 WCAG 2.2.3 与 WAI-APG Alert 告诫(components/toast 条目已详述)
  • 入出时长打架:入场 0.35s/退场 0.4s 是基准对——退场短于入场残余动画会互相截断(调研 10 巧思 6)
  • ζ<0.5 的夸张弹跳放在高频操作上——每次保存都弹跳会迅速从『活泼』变成『噪音』(HIG:高频交互避免加动效)
  • 把 toast 从屏幕中央弹出——边缘来、边缘去是方向语义;中央弹入无空间锚点(调研 04§3.3 M3 enter-exit 同则)
无障碍

容器 `role="status"`(aria-live=polite)播报非关键消息;自动消失时长 ≥ 与文本长度匹配的下限(WCAG 2.2.3:自动消失的非干扰内容需可暂停/持久);提供手动 ✕ 关闭;prefers-reduced-motion 时纯 fade;颜色不作成功/错误的唯一区分(配图标/文案)。堆叠时旧消息不被新消息顶掉到读不到(上限内逐条播报)。

浏览器支持

demo 用 Motion(AnimatePresence + spring)驱动,依赖 JS;百分比 y 位移与 scale/opacity 过渡均为 Baseline 能力。退场计时与 animationend/退出完成回调为标准事件。reduced-motion 降级为纯 fade(react-hot-toast 官方降级路径,调研 10§5.1)。

兼容回退

prefers-reduced-motion 时入/出都退化为纯 fade(react-hot-toast 官方做法);toast 只承载非关键信息,关键信息走持久组件(components/toast 条目口径);消息可手动关闭(✕)+ 悬停可暂停计时是推荐增强;计时器在组件卸载时清理。
