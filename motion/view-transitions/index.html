视图过渡 View Transitions

视图过渡 · startViewTransition · 共享元素过渡

document.startViewTransition(cb) 对旧/新状态分别截图,再以 CSS 动画驱动快照过渡:整页交叉淡化是平台默认,view-transition-name 命名元素可做共享元素 morph。

Web 标准 ★★★
实例演示 官方默认
参数
几何▾
duration300ms
ms

过渡时长,经 ::view-transition-group/old/new 的 animation-duration 覆写生效。默认 300ms 取 Chrome 官方 Material shared-axis 示例主段时长(调研 04§3.2);平台内置交叉淡化的默认时长调研未记载,不作官方标注。调大过场更从容,调大过 500ms 开始拖沓;调小至 150ms 以下接近直切。

动效▾
easingcubic-bezier(0.4, 0, 0.2, 1)

过渡缓动,经同组伪元素的 animation-timing-function 覆写。默认 (0.4, 0, 0.2, 1) 取官方 Material shared-axis 示例主段曲线(调研 04§3.2)——与 MUI 沿用的 M2 standard easeInOut 同值。morph 模式下该曲线同时作用于位置/尺寸的补间。

modemorph

JS 型参数:morph=被点卡片与详情主图携带同一 view-transition-name(可为不同 DOM 节点——过渡期间动态赋名即可),::view-transition-group 自动过渡位置/宽高(官方共享元素过渡,调研 04§3.2);fade=不命名,退化为整根 root 的交叉淡化(平台默认过渡)。名字必须同时唯一,否则整个过渡被跳过(官方警告)。

代码拆解

结构与 DOM

演示是「卡片列表 ⇄ 详情页」两个状态的同文档过渡。列表态 4 张卡片各是一个 <button>;详情态一张大图 hero + 返回按钮。核心流程只有一段:

const open = (id: string) => {
  // 旧快照拍下前:给被点卡片赋名(morph 模式)
  cardRefs.current[id]?.classList.add("vt-name");
  const apply = () => flushSync(() => setDetailId(id)); // DOM 更新必须在回调内同步完成
  const doc = document as VTDocument;
  if (!doc.startViewTransition || reduced) {
    apply(); // 无 API 或 reduced-motion:直切
    cardRefs.current[id]?.classList.remove("vt-name");
    return;
  }
  doc.startViewTransition(apply);
};

关键点:

  • 浏览器把回调前后的页面各拍一张快照,期间渲染冻结;所有过渡动画都是 CSS 动画,伪元素树 ::view-transition → group → image-pair → old/new 承载快照(调研 04§3.1);
  • morph 的魔法:旧新两侧不必是同一 DOM 节点——过渡前给列表卡片赋名、过渡后详情 hero 带同名,::view-transition-group(name) 自动补间位置/宽高(官方 shared element transition,调研 04§3.2);
  • 名字必须同时唯一:同一时刻两个元素同名,整个过渡被跳过——demo 在发射前清理旧名、过渡结束后摘名,保证任何时刻至多一个持有者。

样式与参数

duration/easing 是 CSS 型参数(经 --vt-duration/--vt-easing 注入);mode 是 JS 型,demo 订阅后决定赋名策略。覆写伪元素动画:

/* 快照动画全部可覆写——这是「所有动画都是 CSS 动画」的直接收益 */
::view-transition-group(*),
::view-transition-old(*),
::view-transition-new(*) {
  animation-duration: var(--vt-duration, 300ms);
  animation-timing-function: var(--vt-easing, cubic-bezier(0.4, 0, 0.2, 1));
}
/* morph 模式:被点卡片 / 详情 hero 共享的名字 */
.vt-name { view-transition-name: vt-card; }

数值出处:默认 300ms + cubic-bezier(0.4, 0, 0.2, 1) 取 Chrome 官方 same-document 页的 Material shared-axis 示例主段(退出 90ms + 主段 300ms,进入 210ms 延迟 90ms;demo 取主段参数,调研 04§3.2)。平台内置交叉淡化的默认时长调研未记载,不作官方标注。

实现细节:伪元素树挂在 <html> 下,不继承 .demo-stage 上的变量——demo 把两个 CSS 变量同步镜像到 document.documentElement,卸载时移除;React 的 DOM 更新经 flushSync 在过渡回调内同步完成,回调不做异步等待(官方建议 100ms 内)。

动效与交互

  • morph:点任一卡片 → 卡片与 hero 互换身份,位置/尺寸由 group 自动补间;返回时反向再来一次(hero→卡片)。view-transition-name 唯一性由「发射前清名、结束后摘名」保证;
  • fade:不赋名,只剩 root 一层的交叉淡化——平台默认过渡,时长/缓动同样受参数控制;
  • 不支持 / reduced-motion 直切:无 API 或系统要求减少动效时,apply() 直接执行,界面瞬间换态、功能不损失;
  • 同一时刻仅一个过渡:快速连点时新过渡把旧过渡跳到结尾(官方行为),不会叠加;
  • 性能与冻结:过渡期间页面渲染冻结,apply 是同步小更新,无长任务。

参数敏感度

参数调大会…调小会…
duration过场更从容,morph 的位移轨迹更可辨;>500ms 开始拖沓,冻结感变重(渲染冻结期变长)接近直切;<150ms 时 morph 的空间关系读不出来,只剩闪变
easingy2<1 的减速收尾让 morph 停得稳;y 越界会在整页位移上放大过冲,慎用两控制点趋近对角线读作 linear——匀速的整页滑动比 ease 更显机械
modemorph:空间连续性最强(容器变换体验),列表↔详情的因果关系明确fade:最朴素保守,元素无空间关联或大量内容重排时反而更干净

经验区间:同文档小范围状态切换 200–300ms;morph 建议配 (0.4, 0, 0.2, 1) 这类无过冲曲线(整页位移过冲极易晕);fade 模式时长可更短。唯一性纪律优先于一切:先摘名,再发起下一次过渡。

适用场景 4
  • SPA 状态/路由切换的兜底动画:列表→详情、标签页切换(同文档 API,调研 04§3.1)
  • 共享元素 morph:缩略图展开为大图、导航持久元素跟随(名字唯一 + group 自动补间,调研 04§3.2)
  • 时长/缓动全部可覆写——所有动画都是 CSS 动画(官方强调),可按品牌统一曲线
  • 进入/退出差异化:::view-transition-old/new(name):only-child 分别定义(官方示例,调研 04§3.2)
何时不要用 4
  • 给多个元素同名 view-transition-name——过渡整体被跳过(官方唯一性警告,调研 04§3.2)
  • 把过渡当关键信息载体——不支持/关闭动效的环境必须能无过渡完成同一操作
  • 在过渡回调里做超长异步等待——官方建议 100ms 内(官方文档,调研 04§3.2)
  • 跨文档场景误用同文档 API——MPA 走 @view-transition 声明且无 JS API(Chrome 126+/Safari 18.2+,Firefox 未支持,调研 04§3.1)
无障碍

视图过渡是整页级位移,前庭影响最大:prefers-reduced-motion 时必须直切(demo 内建);操作结果不得依赖过渡呈现(不支持环境直切且功能完整);morph 的位置补间遵循用户系统设置;过渡期间渲染被冻结,回调要短(官方 100ms 建议)以免输入停顿。

浏览器支持

同文档过渡(document.startViewTransition):Chrome/Edge 111+、Safari 18+、Firefox 144+(Chrome 文档表格,调研 04§3.1);跨文档 @view-transition:Chrome 126+、Safari 18.2+(Firefox preview,BCD,调研 02§D6)。demo 仅演示同文档;无 API 时直切不过渡。 · Newly available (Chrome 111+ / Safari 18+ / Firefox 144+ for same-document)

兼容回退

无 document.startViewTransition 或 prefers-reduced-motion 时直接切换状态(不做任何过渡)——过渡只是包装,内容照常可达;同一时刻只允许一个视图过渡,新过渡开始时旧过渡直接跳到结尾(官方行为,demo 不排队);回调可返回 promise(官方建议 Promise.race 限 100ms),demo 的 DOM 更新是同步 flushSync,无需等待。

来源 3
