骨架屏 Skeleton Loading

骨架屏 · 加载骨架 · Skeleton screen

用几何色块复刻即将出现的内容布局,叠加一道扫光脉动表示「加载中」;内容就绪后快速淡入覆盖,布局零跳动。

结构与 DOM

骨架屏是「同一张卡片的两个状态」:占位态用几何色块复刻内容布局,内容就绪后快速淡入覆盖。占位块与内容块尺寸对齐,切换时不发生布局跳动:

<div class="card" aria-busy="true">
  <!-- 占位态(纯装饰,读屏跳过) -->
  <div class="sk-avatar sk-block" aria-hidden="true"></div>
  <div class="sk-line sk-block" style="width: 62%" aria-hidden="true"></div>
  <!-- 内容态(淡入覆盖) -->
  <img class="avatar" src="…" alt="" />
  <h3 class="name">Ada Lovelace</h3>
</div>
  • M3 把 skeleton loaders 列为六大转场模式之一:「UI 抽象,暗示内容加载后出现的位置」,用微妙脉动表示不确定进度(视觉走向:从屏幕左上到右下),内容加载完成后快速淡入覆盖骨架(调研 04§2.2);
  • Luke Wroblewski《Avoid The Spinner》:进度指示让人「盯着钟看」,骨架屏让注意力落在「内容正在到来」而非「等待」,Polar 用它消灭了 spinner(调研 04§2.2);
  • 色块是纯装饰,加载语义走 aria-busy 与文字状态,不依赖动画。

样式与参数

脉动用 transform 扫光实现(合成器友好,web.dev 性能底线,调研 04§1.5):

.sk-block { position: relative; overflow: hidden; background: <基色>; }
.sk-block::after {
  content: ""; position: absolute; top: 0; bottom: 0; left: 0; width: 45%;
  background: linear-gradient(90deg, transparent, hsla(0 0% 100% / 0.4), transparent);
  animation: sk-sweep var(--skeleton-duration, 1200ms) ease-in-out infinite;
}
@keyframes sk-sweep {
  from { transform: translateX(-100%); }
  to   { transform: translateX(400%); }
}
/* diagonal:120° 渐变 + 对角位移,对应 M3「左上→右下」的视觉走向 */

两个参数:

  • pulse(CSS 型,--skeleton-duration):脉动周期。M3 只要求「微妙脉动」,未记载数值——1200ms 为社区常见值,未证实;
  • direction(JS 型,demo 切 data-dir):horizontal=经典左→右扫光;diagonal=120° 渐变对角扫过(M3 的左上→右下走向,调研 04§2.2)。

加载选型阈值(NN/g,调研 04§2.2)——先选型,再决定要不要骨架:

预期加载时长官方建议
<1s即时状态变化(按钮按压态等),不做指示器
≥1s必须给进度指示
2–10s循环动画(spinner / 循环进度条 / 骨架脉动)
≥10s百分比进度条 + 文字说明(如 “Loading comments…”);>10s 再附完成时间估计

有进度指示时用户满意度更高、平均可等待约 3 倍时长(NN/g 转述内布拉斯加大学实验)。

动效与交互

  • 状态切换:demo 点「重新加载」重进占位态,1.8s 后内容淡入(演示用时长,落在 NN/g「≥1s 必须指示」区间);
  • 内容淡入:200ms + M3 Standard easing cubic-bezier(0.2, 0, 0, 1)(M3 short4 档 200ms + Standard easing,调研 04§1.4/§2.6);
  • 切换零跳动:占位块与内容块同尺寸同圆角,布局位移为 0——骨架屏「稳定布局」的价值所在;
  • reduced-motion:扫光停用(色块保持静态基色)、淡入直出;「正在加载」由 aria-busy + role="status" 文字兜底;
  • spinner 与骨架的取舍:同为不确定进度,骨架保留布局线索(lukew),循环动画适合 2–10s(NN/g)。

参数敏感度

参数调大会…调小会…
pulse呼吸更舒缓、更「微妙」;>2.4s 后扫光变得难以察觉,用户可能以为页面静止脉动急促抢眼,违反 M3「微妙」要求;600ms 时接近闪烁
directiondiagonal 沿 M3 的左上→右下走向,大面积卡片上方向感更强horizontal 是社区最常见形态,扫描线更「直给」;两者都只改视觉走向,不改语义

选型口诀:先问「大概等多久」——<1s 什么都不做,1–10s 用骨架/循环指示,≥10s 上百分比进度;骨架只在布局可预知时有意义。

适用场景 3
  • 内容型列表/卡片的首屏加载(Feed、详情页、仪表盘卡片)
  • 预期加载 1s 以上且布局已知的页面——先按 NN/g 阈值选型再做骨架
  • 局部刷新的区块(换页、筛选),保持布局稳定降低跳动
何时不要用 3
  • 预期 <1s 的请求——NN/g:用即时状态变化(按压态)即可,骨架反而制造等待感
  • 预期 ≥10s 的长任务——改用百分比进度条 + 文字说明
  • 布局未知的动态内容——占位块与实际内容对不上时,切换瞬间跳动反而更明显
无障碍

骨架色块是纯装饰,对读屏隐藏;加载状态用 aria-busy 与文字状态(如「正在加载…」)同步传达,不依赖脉动动画;reduced-motion 下停用扫光;内容淡入期间保持布局稳定,避免焦点元素移动。

浏览器支持

纯 CSS 渐变 + transform 动画 + data 属性切换,全浏览器可用,无新特性依赖;不支持时骨架退化为静态色块,语义不受影响。

兼容回退

prefers-reduced-motion 时停用脉动(色块保持静态基色)、内容切换不做淡入直接呈现;「正在加载」的语义不得只靠动画传达——同时用 aria-busy / 状态文字兜底。

来源 3

起源Luke Wroblewski《Avoid The Spinner》确立了骨架屏对 spinner 的替代(注意力落在「内容正在到来」);M3 把 skeleton loaders 列为六大转场模式之一:微妙脉动(视觉走向左上→右下)+ 完成后快速淡入(调研 04§2.2);选型阈值来自 NN/g 进度指示研究(调研 04§2.2)。
