滚动溢出行为 Scroll Overflow Behavior

overscroll-behavior · 滚动链 · scroll chaining · 滚动穿透

overscroll-behavior 决定滚到边界后发生什么:contain 拦滚动链、留回弹;none 两者都拦;overflow:hidden 的容器恒在边界,天生可当弹层打开时的背景锁。

Web 标准 ★★
实例演示 官方默认
参数
动效▾
innerModecontain

弹层内滚动容器的 overscroll-behavior。默认 contain = 弹层防穿透的标准姿势(MDN:『拦滚动链不拦回弹』);auto 是浏览器默认、也是滚动穿透的来源;none 连 iOS 橡皮筋回弹一并禁掉,弹层内少用。demo 用穿透计数器实时显示 auto 档的滚动链后果。

lockPageoff

JS 型参数(demo 订阅后切换 data-locked)。on = 外层页面容器 overflow:hidden——MDN 原文推论:『无滚动溢出的滚动容器(如 overflow:hidden)恒处于边界 → 设 contain/none 即可阻止背景滚动』,是弹层打开时锁背景的标准做法;配合内层 contain 形成完整防穿透。

代码拆解

结构与 DOM

演示是两层滚动嵌套:外层假页面(stage 充当滚动容器,14 行内容)+ 居中弹层(标题栏 + 内层 30 条列表)。弹层打开时,在内层滚到底,浏览器要不要把滚动「链」给外层,就是本条目的全部:

<div class="so-outer" data-locked="false"><!-- 外层滚动容器 -->
  <div class="so-page">…背景内容…</div>
</div>
<div class="so-modal" role="dialog" aria-modal="true">
  <div class="so-modal-head">弹层 <button class="so-close">关闭 ✕</button></div>
  <div class="so-inner" tabindex="0" role="region" aria-label="内层列表"><!-- 内层滚动容器 -->
    <div class="so-item">条目 1</div>…
  </div>
</div>

关键点:

  • 内层滚动区 tabindex=0 + role="region"——可聚焦、方向键/翻页键可滚(WCAG 2.1 SC 2.1.1 邻接要求);
  • 穿透计数器:弹层打开且指针悬于内层时,外层发生滚动即滚动链发生——把「滚动穿透」变成可观测事件;
  • 弹层为 role="dialog" + aria-modal,Esc 关闭、焦点打开入弹层/关闭归还(WAI-APG Dialog 语义)。

样式与参数

两个参数,一条 CSS 变量、一个 JS 开关:

/* 内层:防滚动链标准姿势(参数经 --ob-inner 注入) */
.so-inner {
  overflow-y: auto;
  overscroll-behavior: var(--ob-inner, contain);  /* contain 拦链留弹 / none 拦链拦弹 */
  scrollbar-width: thin;
}
/* 外层:弹层打开时锁背景(MDN 原文推论) */
.so-outer[data-locked="true"] { overflow: hidden; }

数值与语义出处(MDN overscroll-behavior 全文抓取,调研 10§8.1/09§7.1 双源):

  • 滚动链定义:「对话框滚到底后,底层页面开始滚动」;
  • 四值语义:auto 默认链出;contain 阻止滚动链、保留回弹;none 两者都拦;2025 新增 chain(允许链但禁回弹);形式语法支持 overscroll-behavior: x y 双轴;
  • 锁背景推论(MDN 原文):「无滚动溢出的滚动容器(如 overflow:hidden)恒处于滚动边界 → 设 contain/none 即可阻止背景滚动」——弹层打开时锁背景的标准做法;
  • 边界:iframe 不是滚动容器,控制 iframe 内滚动链需在其文档的 html/body 上设置;
  • 配套警告(MDN 原文):scroll-snap mandatory 在内容超高时用户可能永远看不到某段内容——一般交互用 proximity;scrollbar-width: none 影响键盘滚动(WCAG 2.1.1)。

动效与交互

  • 实验流程:弹层默认打开 → 把 innerMode 切到 auto → 在内层列表滚到底继续滚——外层页面跟着滚,穿透计数 +1 → 切回 contain 同样操作——外层纹丝不动(iOS 回弹保留);
  • 锁背景实验:lockPage 切 on,外层 overflow:hidden,背景完全冻结——这是「弹层打开时锁背景」的官方姿势;注意 contain 只拦「链」,不拦用户直接滚动背景,所以两者要配合;
  • none 与 contain 的取舍:弹层内选 contain——保留回弹的手感;none 连橡皮筋一并禁掉,iOS 上像卡死,整页 body 千万别用;
  • reduced-motion:关掉 scroll-behavior: smooth 与工具条 backdrop-filter(演示性效果);本条目无动画依赖;
  • 弹层内滚动区键盘可达(tabindex=0),滚动条 scrollbar-width: thin(省空间而非审美,MDN)。

真实产品案例

  • MDN 官方弹层示例:dialog 滚动区挂 overscroll-behavior: contain,配 ::backdrop { backdrop-filter: blur(0.5rem) }——本条目 demo 的直接母本(调研 10§8.1);
  • iOS 模态 sheet:系统 sheet 内容滚到底继续滚是拖动 sheet 本身而非穿透背景页——原生交互的标准答案;Web 对位就是内层 contain + 背景 overflow:hidden;
  • Twitter/X 与 Reddit 的时间线抽层:打开详情层后背景时间线不可滚、关闭后回到原位——「锁背景 + 位置保持」的产品范式(具体实现未逐帧核验,交互行为公知)。

参数敏感度

参数调大会…调小会…
innerModeauto→contain:滚动链消失、iOS 回弹保留(推荐);contain→none:回弹也消失,触感变「硬」反向:auto 档穿透发生——弹层滚动到底继续滚背景,操作上下文瞬间丢失
lockPageon:背景完全冻结,弹层滚动体验最干净;记得关闭后恢复滚动位置off:背景可被直接滚动(注意 contain 拦链不拦直滚);适合非模态浮层
内层内容量列表越长,滚到边界的概率越高,contain 的价值越大内容不足一屏时内层恒在边界——此时即便 auto 也几乎不穿透,但显式 contain 仍是正确姿势
穿透计数(只读)计数只在「弹层开 + 指针在内层」时累计——干净的实验对照—

工艺结论:弹层滚动区必挂 overscroll-behavior: contain(调研 10 巧思 8);锁背景用 overflow:hidden 的「恒在边界」推论;轮播横滑配 overscroll-behavior-x: contain + scroll-snap-type: x proximity;none 只给确需禁回弹的局部组件。

适用场景 4
  • 弹层(dialog/drawer/popover)内的滚动区:必挂 `overscroll-behavior: contain`(调研 10 巧思 8)
  • 打开弹层时锁背景:外层页面容器 overflow:hidden(+ contain),MDN 官方做法
  • 横向轮播/卡片流:`overscroll-behavior-x: contain` 防横滑链出页面,配 scroll-snap-type: x proximity(调研 10§8.4)
  • 嵌入第三方页面的滚动组件(聊天窗、日历):contain 防止组件滚穿宿主页面;iframe 场景在其文档根上设置
何时不要用 4
  • 给整页 body 设 `none`——连橡皮筋回弹都消失,iOS 上像页面卡死;页面级留 auto 或 contain
  • 依赖 overscroll-behavior 替代焦点管理——它只管滚动链,弹层的键盘焦点圈定仍是 WAI-APG Dialog 的必答题
  • 滚动容器里 `mandatory` 吸附配超高内容——MDN:用户可能永远看不到某段内容,一般交互用 proximity
  • 以为 contain 能阻止背景滚动却不锁背景——contain 只拦『链』,背景自身仍可被直接滚动;锁背景要用 overflow:hidden/滚动锁
无障碍

滚动链是触控/滚轮用户的操作正确性问题,也是 WCAG 2.1 SC 2.1.1(键盘全功能)的邻接面:弹层内滚动区需可聚焦且支持方向键/翻页键滚动;锁背景(overflow:hidden)时保证页面滚动位置不丢、关闭后可恢复;滚动条用 scrollbar-width 控制时注意 none 影响键盘滚动(MDN 警告);prefers-reduced-motion 下本条目无动画依赖,平滑滚动(如 scroll-behavior:smooth)应同时关闭。

浏览器支持

overscroll-behavior:Chrome/Edge 63+(2017)、Firefox 59+(2018)、Safari 16+(2022)起支持——**具体版本号为 MDN 兼容表内容,本次调研未逐项核验,以 MDN 页为准**;2025 标准新增 `chain` 关键字(浏览器落地进度同样以 MDN 为准)。iframe 不是滚动容器,控制 iframe 内滚动链需在其文档的 html/body 上设置(MDN 原文)。

兼容回退

Safari 15 及更早不支持 overscroll-behavior:内层滚到底会继续链出——退路是 JS 在内层 touchmove 到边界时 preventDefault,或接受穿透并保证背景无危险交互;scroll snap 配套警告:mandatory 在内容超高时可能永远看不到某段内容,一般交互用 proximity(MDN 原文);demo 无 JS 时弹层常开,内层为普通滚动容器。

来源 4

起源MDN overscroll-behavior 官方语义(本次全文抓取):`auto` 默认(滚界后继续滚动链);**`contain` 阻止滚动链(scroll chaining)但保留 overscroll 回弹**;`none` 同时阻止滚动链与回弹;形式语法 `[contain|none|auto|chain]{1,2}` 支持双轴;2025 标准新增 `chain`(允许链但禁回弹);滚动链定义即『对话框滚到底后,底层页面开始滚动』(调研 10§8.1、09§7.1 双源一致)。
