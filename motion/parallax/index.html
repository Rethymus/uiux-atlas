视差滚动 Parallax

视差 · parallax scrolling · 多层滚动速率差

多层滚动速率差制造深度:背景层跟随滚动慢于前景(跟随比例 p,0=钉在视口、1=与内容同步),用 scroll-driven animations 的 scroll() 时间轴按层下发位移,可运行在主线程之外;reduced-motion 直出静态分层。

Web 标准 ★★★
实例演示 官方默认
参数
几何▾
rate0.3

最远层的滚动跟随比例 p:层随滚动移动的距离 = p × 滚动距离。0 = 层钉在视口上(完全无视差);1 = 与前景同步(视差消失)。中层/近层按 p×2、p×3 推导并封顶 1(演示分层)。官方未给推荐值——0.3 为演示值(社区常见分层多在 0.2–0.6,未证实)。

动效▾
modecss

实现对照:css 模式用声明式 animation-timeline: scroll()——官方文章指出声明式滚动驱动动画可在主线程之外运行;js 模式用主线程 scroll 事件 + rAF 直写 transform,官方同页指出传统 scroll 事件在主线程且与合成器滚动异步,快速滚动易卡顿。浏览器不支持 scroll() 时 css 模式自动落到 js 路径并标注。

代码拆解

结构与 DOM

视差是「一个滚动容器 + 一个分层世界」:滚动容器承载全部内容,.world 里叠三层装饰层(远/中/近)+ 一层 1:1 随滚动的真实内容:

<div class="scroller">          <!-- overflow-y: auto,唯一滚动源 -->
  <div class="world">           <!-- 相对定位,高度撑出可滚动距离 -->
    <div class="layer far"  aria-hidden="true"></div><!-- 装饰层不承载内容 -->
    <div class="layer mid"  aria-hidden="true"></div>
    <div class="layer near" aria-hidden="true"></div>
    <div class="copy">…</div>   <!-- 内容层 1:1 随滚动,永远可读 -->
  </div>
</div>

关键点:

  • 装饰层是纯背景(aria-hidden、pointer-events: none),任何正文都不落在视差层上;
  • 每层一个乘数 m(远 1 / 中 2 / 近 3),跟随比例 p = min(rate × m, 1);内容层恒为 p=1;
  • 位移方向与滚动相反地「补慢」:层随滚动移动 p×距离,视口内净移动只剩 p 倍速——p 越小越接近钉死。

样式与参数

声明式实现(CSS 变量型参数 rate → --par-rate;JS 量测可滚动距离写入 --par-s):

@supports (animation-timeline: scroll()) {
  .layer {
    animation: drift linear both;
    animation-timeline: scroll(nearest block); /* 必须写在 animation 简写之后 */
    animation-duration: auto;                  /* 时长交给滚动进度 */
  }
}
@keyframes drift {
  from { transform: translateY(0); }
  to   { transform: translateY(calc((1 - min(var(--par-rate) * var(--px-m, 1), 1)) * var(--par-s))); }
}

JS 对照实现(官方文章的传统路径):scroll 事件 + rAF 直写 el.style.transform——它在主线程运行且与合成器滚动异步,快速滚动易掉帧;声明式 scroll() 可在主线程之外运行(调研 04§4)。demo 的 mode 参数即这两条路径的现场对照;浏览器不支持 scroll() 时自动落到 JS 路径并标注。

数值出处:实现机制全部出自 Chrome 官方滚动驱动文章(调研 04§4);官方未给跟随比例的推荐值——demo 默认 0.3 为演示值(社区常见分层 0.2–0.6,未证实);Firefox/Safari 支持现状调研明确未逐项核实,以 MDN 兼容表为准。

动效与交互

  • 速率差即深度:滚动时远层以 30%(默认)速跟进、中层 60%、近层 90%,内容层 100%——三层视觉速度梯度一屏可辨;
  • p=0 / p=1 两个边界:0 = 远层钉在视口(星空不动),1 = 全部层与内容同步(视差消失);demo 两个边界都有标注;
  • JS/CSS 现场对照:切到 js 模式滚动对比流畅度——官方结论(主线程 vs 合成器)直接可体感;
  • 性能:只动画 transform;--par-s 只在挂载/resize 时量测一次,滚动路径零布局读取;
  • reduced-motion:reduce 时视差整体关闭,静态构图直出(JS 路径同样停),内容不受影响。

与滚动时间轴的基础用法(进度条、reveal、animation-range)见 scroll-driven-animations 条目;「转场内的视差」(iOS 前进/后退)见 page-transitions 条目。

真实产品案例

  • iOS 前进/后退转场:M3《Transition patterns》记载 iOS 的层级转场使用视差——背景慢于前景(调研 04§3.3),这是「速率差=深度」在系统级产品里的官方例证;
  • Chrome 官方滚动驱动文档:把「视差背景图」列为 scroll() 时间轴的典型用例(前景/背景随不同 timeline/range 速度移动,调研 04§4)——官方推荐的实现路径即本条的声明式写法;
  • 营销页多层 hero(社区常见,未证实):星空/山峦/前景三层以不同速率陪跑是 Web 营销页的常见做法,但无官方规范文章——调研明确「视差未找到更专门的一手规范」(调研 04§8.5),实现时应以滚动驱动文档为唯一一手依据。

参数敏感度

参数调大会…调小会…
rate各层更贴近内容速度,视差感减弱;1 = 无视差(全同步)远层更接近钉死,深度感更强;0 附近时星空完全静止,长时间注视易察觉层间脱节
modejs:可对照体感主线程路径的掉帧代价,也是不支持 scroll() 浏览器的兜底css:声明式、可离主线程,是官方推荐路径;两模式在慢速滚动下观感几乎一致

选型口诀:内容层永远 1:1,视差只给装饰层;rate 从 0.3 起步按「远层要退多慢」微调;能用声明式 scroll() 就不写 scroll 事件。

适用场景 3
  • 营销页/叙事页的多层背景(星空、山峦、城市天际线)——背景慢于前景制造纵深
  • 卡片/英雄区的深度分层:装饰层以 p×2/p×3 推导速率陪跑,内容层保持 1:1 可读
  • 系统转场里的深度暗示——iOS 前进/后退转场即内置视差(背景慢于前景,M3 转场文档记载)
何时不要用 4
  • 正文/数据落在视差层上——文字随层变速移动直接伤害可读性;视差层只放装饰
  • 全屏视差铺满整个页面(visionOS 借鉴建议明确避免全屏视差,调研 11§5)
  • 多层全用 JS scroll 事件驱动——主线程逐帧直写,快速滚动掉帧(官方同页结论);优先声明式 scroll()
  • 不做 reduced-motion 降级就上视差——前庭安全红线(MDN,调研 04§6.1)
无障碍

视差必须响应 prefers-reduced-motion(reduce 时直出静态分层,不允许 JS 路径继续动);视差层不得承载任何关键信息(纯装饰,aria-hidden);大面积持续位移是前庭障碍的常见触发源(MDN),HIG 同时要求动效可取消、不得是关键信息唯一渠道;visionOS 借鉴建议:关键内容置于视口中部安全区,避免全屏视差(调研 11§5)。

浏览器支持

scroll()/view() 时间轴:官方文章快照为 Chrome/Edge 115+(调研 04§4);Firefox/Safari 的精确支持状态调研明确未逐项核实,以 MDN 兼容性表为准——demo 因此内置能力检测:不支持时自动落到 JS 兜底并标注。prefers-reduced-motion: Baseline 2020-01(调研 04§6.1)。

兼容回退

两级降级:① 浏览器不支持 animation-timeline: scroll() 时,demo 自动切 JS 路径(rAF + scroll 事件直写 transform),视差保留;② prefers-reduced-motion: reduce 时视差整体关闭,所有层按静态构图直出——视差是典型前庭触发源,内容不依赖视差层传达。

来源 2

起源Chrome for Developers《Scroll-driven animations》(Bramus,实抓,调研 04§4)把「视差背景图」列为滚动驱动动画的典型用例:前景/背景随不同 timeline/range 以不同速度移动;实现机制(scroll()/view() 时间轴、duration auto、animation-timeline 须写在 animation 简写之后、声明式实现可在主线程外运行)同页。官方明确:视差未找到更专门的一手规范文章(调研 04§8.5);「iOS 转场的前景/背景视差」另见 M3 转场文档(调研 04§3.3)。跟随比例 p 无官方推荐值。
