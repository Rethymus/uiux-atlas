元素级翻转换肤 Theme Flip Stagger

卡片翻转换肤 · flip stagger · 元素级翻转 · 逐卡翻转换肤

每张卡片绕纵轴(rotateY)翻到 90° 侧棱时换肤、再翻回平面,逐张错峰;总时长 = duration + (n − 1) × stagger。不做整屏快照表演,与 color/theme-transition(root 快照)和 motion/view-transitions(元素级 view-transition-name)互补。

代码拆解

结构与 DOM

元素级翻转换肤不做整屏快照表演:每张卡片各自绕纵轴(rotateY)翻到 90° 侧棱——在恰好看不见的一瞬换掉自己的配色——再翻回平面,逐张错峰,像一排卡片依次「换装」。与 color/theme-transition(root 快照整屏)和 motion/view-transitions(元素级 view-transition-name + 快照)不同,它不依赖 View Transitions API:纯 CSS 3D 关键帧 + JS 编排。

<div class="stage" data-fx-theme="dark" data-fx-duration="800">
  <div class="grid" style="perspective: 900px">
    <div class="card" data-face="light" data-phase="idle" style="--tf-sign: 1">…</div>
    <!-- ×n:每张卡只此一个元素,配色由 data-face 两套变量表驱动 -->
  </div>
  <button data-fx-toggle>切换主题</button>
</div>

关键点:

  • 卡片是单面元素(没有正反两张脸):配色由 data-face 驱动,翻转中段(90° 侧棱)元素宽度为 0,换面不可见——不需要 backface 双面结构;
  • 翻转拆两段 CSS 动画:转出 rotateY 0→±90°(accelerate)→ animationend 时换 data-face 并接转回 ±90°→0(decelerate)——换面发生在 animationend 帧(恰好 90°),不靠猜时长的 setTimeout;
  • 舞台 data-fx-theme 点击即翻转(契约),而卡片各自的面在自己翻到 90° 时才跟上——「逐张换装」的错峰感正来自这个差值;
  • perspective 放在栅格容器上,n 张卡共享一个灭点;每张卡自带 --tf-sign 决定翻向。

样式与参数

两套配色变量表 + 两段翻转关键帧:

.card[data-face="light"] { --card: #fff; --fg: #1f2430; /* …亮面变量表 */ }
.card[data-face="dark"]  { --card: #21252d; --fg: #eceff5; /* …暗面变量表 */ }

.card[data-phase="out"] { animation: flip-out var(--half-out) cubic-bezier(0.4, 0, 1, 1) forwards; }
.card[data-phase="in"]  { animation: flip-in  var(--half-in)  cubic-bezier(0, 0, 0.2, 1) forwards; }
@keyframes flip-out { to { transform: rotateY(calc(var(--tf-sign) * 90deg)); } }
@keyframes flip-in  { from { transform: rotateY(calc(var(--tf-sign) * 90deg)); } to { transform: rotateY(0deg); } }

时间结构(demo 逐次实算,data-fx-duration 始终写实际值):

单卡时长 duration = 转出 half-out(40%)+ 转回 half-in(60%)
总时长 = duration + (n − 1) × stagger          ← n = 卡片数
默认:duration 500(转出 200 + 转回 300)、stagger 60、n = 6 → 总时长 800ms

数值出处(调研 20):

  • 转出 accelerate cubic-bezier(0.4, 0, 1, 1) / 转回 decelerate cubic-bezier(0, 0, 0.2, 1)、200ms + 300ms 不对称:调研 §6.5 元素级翻转配方的两段曲线与时长(退出快进入慢 = M3 §5 原则;时间骨架同 Chrome 文档 shared-axis 示例,§1.1 同页);demo 把 200/300 按 40%/60% 随 duration 等比缩放;
  • stagger 默认 60ms:demo 编排取值,无官方规定;级联思路与揭示转场族(15–30ms 级联带,§6.3)及 motion/stagger-orchestration(第 i 项在 i × delay 启动、铺开 = delay × (n−1))同构——翻转行程更大,取值相应放大;
  • rotateY/perspective 全引擎支持,无 API 依赖(见 browserSupport)。

动效与交互

  • 一次点击:舞台 data-fx-theme 即时翻转 → 第 i 张卡在 i × stagger 后起翻 → 转出段 animationend(恰好 90° 侧棱)同一批次内换 data-face + 接转回段 → 全部落平即完成;
  • 中断(动画进行中再次点击):清全部计时器,所有卡瞬时落平并归位到中断前的全局主题(= 旧编排的终态),再从该状态错峰翻向新目标——语义对应「新过渡开始时旧过渡跳到结尾」(Chrome 文档,调研 §1.1;二次点击/skipTransition 行为已在无头 Edge 实证,调研 20a§S8),不停在半途;
  • reduced-motion:时长视作 0——所有卡瞬时换面、无旋转(WCAG 2.3.3/C39,调研 §5);matchMedia 变化动态生效;
  • 元素级 VT 是同一手感的 API 版:调研 §6.5 给的 view-transition-name 版(旧快照 flip-out 200ms / 新快照 flip-in 300ms)与本条目共用曲线与不对称时序;API 版有快照捕获成本(实测 57–94ms,调研 20a§S9),纯 CSS 版无捕获成本、但换面帧要自己保证落在 90°(animationend 挂钩即为此);
  • 动效只是增强:主题结论同时由颜色承载,动效被禁用时换肤结论不变(HIG「Make motion optional」,调研 §5)。

真实产品案例

  • Chrome 官方开发者文档(View Transitions same-document 页):「退出快、进入慢」两段结构的官方参照——页内 Material shared-axis 示例(退出 90ms + 主段 300ms)确立了出/进不对称骨架,元素级 view-transition-name 翻转配方(旧快照 flip-out 200ms / 新快照 flip-in 300ms,调研 §6.5)即同一页机制的直接应用;
  • Apple HIG Motion(iOS 26 Liquid Glass 动效原则):系统级约束参照——「反馈动效短促精准」「高频交互避免加动效」「让用户可取消」(HIG motion 页 .md 直抓,调研 §4/§5);卡片翻转换肤属偶发的仪式性反馈,落在该约束的适用面内。具体哪款产品采用「逐卡翻转换肤」,调研未核实到公开案例,不作罗列。

参数敏感度

参数调大会…调小会…
duration单卡翻转更从容;>600ms 单卡开始拖沓(超出 M3 大区域档)<300ms 翻转发脆、接近「闪换」;转出段被压到 <100ms 时换面帧可能被察觉
stagger铺开 = stagger×(n−1) 变长,逐卡「点名」感强;n 大时最后一张等待明显趋近整排同翻;0 = 六张同时翻,错峰叙事消失
directionalternate 奇偶反翻,节奏最花样;单向翻(right/left)页流感最强、最克制—(枚举两向:单向 = 克制,交替 = 花哨;按页面气质选)
转出/转回比(派生)固定 40/60(200/300 出处);调平到 50/50 会失去「退出快进入慢」的 M3 节奏比例更悬殊则转出像抽走、转回像砸下——保持 40/60 附近

经验区间:duration 400–600ms、stagger 30–90ms(演示取值,无官方规定)、n ≤ 12;总时长随 n 线性增长,盯住 duration + (n−1) × stagger 的上限。

适用场景 3
  • 仪表盘/组件展示页的低频换肤:卡片逐张「换装」让每个模块的变化可感知,总铺开 = stagger × (n − 1) 与 stagger-orchestration 同构
  • 卡片数量适中(6–12)且每张内容简单(色块 + 短标签)——90° 侧棱一闪而过,复杂内容看不清
  • 需要明确「逐模块换装」节奏的演示页、组件库文档、设计系统宣传页
何时不要用 4
  • 高频主题切换(Apple HIG:高频交互避免加动效,调研 §5)——每次点击都是 n 段串联动画
  • 卡片内容复杂/含图片:翻转中途 90° 侧棱只余一条线,复杂内容可读性差
  • n 大而 stagger 不收敛:总时长 = duration + (n − 1) × stagger 随 n 线性膨胀,最后一张等待明显
  • 几十张卡同时翻转:每张 3D 卡各自占合成层,层叠开销随 n 上升(demo n=6)
无障碍

翻转是交互触发的运动动画,受 WCAG 2.3.3 Animation from Interactions 约束、必须可禁用:demo 在 prefers-reduced-motion 下时长视作 0、点击瞬时换面(C39/SCR40 充分技术,调研 §5);主题状态同时由颜色承载(动效不是「已换肤」的唯一信息通道);卡片文字对比在两套配色下分别核对 4.5:1(WCAG 1.4.3);动画进行中再次点击不卡死不停半途(中断 = 旧编排跳到终态,语义同 Chrome 文档「新过渡开始时旧过渡跳到结尾」,调研 §1.1/20a§S8)。

浏览器支持

rotateY 3D 变换 + perspective 全引擎支持;不需要 View Transitions API 与 clip-path——纯 CSS 关键帧 + JS 编排,禁用 JS 时卡片保持当前面(切换按钮失效,属 demo 控件依赖);换面时机挂在 animationend 上,不受 setTimeout 节流影响。

兼容回退

prefers-reduced-motion: reduce → 时长视作 0,点击后所有卡瞬时换面、无旋转(WCAG 2.3.3/C39,调研 §5);不支持 CSS 动画的遗留环境 → 卡片直接换色;动画进行中再次点击 → 全部卡瞬时落平并归位到中断前主题(= 旧编排终态),再错峰翻向新目标,不停在半途;主题结论同时由颜色承载,动效被禁用时换肤结论不变。

来源 4

起源曲线与时序结构出自调研 20§6.5 元素级翻转配方:旧快照 flip-out 200ms + 新快照 flip-in 300ms、加速出(cubic-bezier(0.4, 0, 1, 1))/减速进(cubic-bezier(0, 0, 0.2, 1))——退出快进入慢 = M3 §5 原则,时间骨架同 Chrome 文档 shared-axis 示例(§1.1 同页);本条目把同一组曲线/不对称时序搬到单面元素的 0→90°→0 翻转(无 View Transitions API 版)。二次点击「旧过渡跳到结尾」的中断语义出自 Chrome 文档并由无头 Edge 实证(调研 20a§S8)。stagger 默认值为 demo 编排取值,无官方规定。
