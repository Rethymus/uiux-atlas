动效编排 Choreography Motion Choreography

编排 · choreography · 方向性编排 · stagger delay

纯 CSS 的动效编排:animation-delay 按 --i 递增做交错起点,方向(上/下/左/右/无)给整组元素统一的空间语义;时长/曲线取 M3 官方配对(进入 std-decel 250ms、退出 std-accel 200ms),进入恒长于退出。

Material 3 ★★★
实例演示 官方默认
参数
几何▾

相邻子项的启动间隔,demo 按 delay = i × stagger 下发给 5 个子项。M3/Motion 文档均未给出交错间隔的推荐值——40ms 为社区常见值,未证实;总铺开时间 = stagger × (n−1),demo 实时标注。

动效▾
directionup

整组统一的空间语义(M3 Enter/exit 方向性):进入方向暗示来源——列表内容自下方上浮读作「更多内容到来」,通知类自上方下落,侧栏类自侧缘;fade 去掉位移只留节奏,也是 reduced-motion 的降级形态。

代码拆解

结构与 DOM

编排的载体是一个语义容器 + N 个子项:容器不参与动画,子项各自声明同一条入场动画,差异只在 animation-delay(按序号递增)与统一的 --ch-from 初态位移:

<ul class="list"><!-- 语义容器:动画不改变可达性结构 -->
  <li style="--i: 0">…</li>
  <li style="--i: 1">…</li>
  <li style="--i: 2">…</li>
</ul>

关键点:

  • 交错的是起点不是时长:每个子项都跑满自己的 250ms,第 i 项在 i × stagger 后启动;
  • --i 由模板/JS 写入,纯 CSS 侧也可用 :nth-child 手写,两种写法等价;
  • 整组共享一个进入方向(--ch-from),方向是组级语义,不是逐项花样;
  • 列表保持 ul/li 语义:动画只作用于 opacity/transform,可达性树从第一帧完整,读屏立即读到全部子项。

样式与参数

stagger 与 direction 都是 JS 型参数(demo 订阅 store 后内联下发 delay 与 --ch-from);时长/曲线固定取 M3 官方配对:

.item {
  animation: enter 250ms cubic-bezier(0, 0, 0, 1) both;  /* std-decel 250ms:进入屏幕(官方配对) */
  animation-delay: calc(var(--i) * var(--stagger, 40ms));
}
@keyframes enter {
  from { opacity: 0; transform: var(--ch-from, translateY(14px)); }
  to   { opacity: 1; transform: none; }
}
/* 退场:反向序交错,200ms std-accel cubic-bezier(0.3, 0, 1, 1)(官方配对) */
.item.exit { animation-name: exit; animation-duration: 200ms; animation-timing-function: cubic-bezier(0.3, 0, 1, 1); }
@media (prefers-reduced-motion: reduce) {
  .item { --ch-from: none; }  /* 去位移、保留交错节奏(纯 opacity 淡入) */
}

数值出处:进入 std-decel 250ms / 退出 std-accel 200ms 出自 M3 官方配对表(调研 04§1.4);「进入比退出更长」同为官方准则。stagger 间隔官方未给推荐值——demo 默认 40ms 为社区常见值,未证实;方向语义出自 M3《Transition patterns》Enter/exit 模式(通知自顶部、抽屉自侧缘、sheet/键盘自底部,调研 04§3.3)。

动效与交互

  • 两组按钮、两种编排:入场按自然序交错,退场按反向序交错(最后一项先走)——反向退场把视线从末项收回到起点,与「退得更快」配合;
  • 总铺开时间 = stagger × (n−1):demo 实时标注;先定「最后一项何时落地」,再回推 stagger;
  • 方向即空间模型:整组一个方向,且方向必须与内容的真实来源一致(列表自下、通知自上、抽屉自侧,M3 官方语义);
  • 与 JS 编排的关系:Motion 的 delay/stagger 是同一编排的库化表达(支持负 delay = 中途开始,调研 04§1.3),见 stagger-orchestration 条目;纯 CSS 版零依赖、无水合成本;
  • 性能:只动画 opacity 与 transform(合成器属性,web.dev 底线,调研 04§1.5);长列表(>20 项)不要整段交错,首屏之外改用滚动触发(见 scroll-driven-animations 条目);
  • reduced-motion:去位移、保留交错节奏(纯 opacity 淡入)——大平移是前庭触发源(调研 04§6.1)。

真实产品案例

  • snackbar/toast 定向展开:M3 官方描述 snackbar 依位置定向展开——底部出现则向上、顶部出现则向下(Android 系统行为,调研 04§3.3),这是「方向=空间模型」最典型的产品落法;
  • 系统通知与抽屉:通知自顶部、抽屉自侧缘、sheet/键盘自底部——M3《Transition patterns》对 Android 系统进入方向的官方归纳(调研 04§3.3);
  • Google 搜索的转场即编排:Luke W 记载 Google 搜索用「页面滑入即转场」把加载指示并入转场来营造即时感(调研 04§2.2)——方向性入场 + 内容快速呈现的组合拳。

参数敏感度

参数调大会…调小会…
stagger点名感更强,组像逐项确认;>80ms × 5 项时末项要等 400ms+,关键内容不宜排在尾部趋近齐发;0 = 同步入场,编排感消失(只剩方向性)
direction换方向即换空间暗示:up=内容到来、down=通知抵达、侧向=面板进出;选错方向暗示与来源打架fade 关掉位移只留节奏——即 reduced-motion 降级形态,也是最保守的编排

选型口诀:方向由内容的真实来源决定(不许倒置);stagger 由「末项允许的落地时刻」回推;入场 250ms / 退场 200ms 直接取官方配对,不要再自行加长。

适用场景 3
  • 首屏内容组的方向性入场:列表自下方上浮、通知自上方下落、侧栏自侧缘滑入(M3 空间模型)
  • snackbar/toast 依位置定向展开——底部向上、顶部向下(M3 官方描述)
  • 需要退出比进入更快的组:入场 std-decel 250ms + 退场 std-accel 200ms 反向交错
何时不要用 4
  • 长列表(>20 项)整段交错——末项等待线性拉长;首屏之外改用滚动触发的 reveal(见 scroll-driven-animations 条目)
  • 同一视图多组同时交错入场——编排是强调手段,并发即互相抵消(HIG:反馈动效简短精确)
  • 方向与空间模型矛盾:内容出现在顶部却配「自下方」方向,来源暗示与实际来源打架
  • 用户高频重复操作每次都整段点名入场(HIG:高频交互避免加动效、动效可取消)
无障碍

位移类入场是前庭触发源,必须响应 prefers-reduced-motion(降级为纯 opacity 交错淡入);列表保持语义 DOM(ul/li 或有序容器),动画只作用于 opacity/transform,可达性树从第一帧完整、读屏立即读到全部子项;末项落定前不承载关键信息,或提供跳过路径(HIG:动效可取消)。

浏览器支持

只用 animation-delay + CSS 变量(全现代浏览器可用,属 CSS Animations 既有特性);本次调研未逐浏览器核验版本矩阵。不依赖任何 JS 动效库;禁用 JS 时列表以最终状态渲染(demo 的重播按钮失效但不影响阅读)。

兼容回退

prefers-reduced-motion 时去掉位移、改用纯 opacity 交错淡入(保留节奏、去掉位移)——大平移是前庭障碍的常见触发源(MDN prefers-reduced-motion,调研 04§6.1);stagger=0 时退化为同步入场,也是合法降级。

来源 3

起源两处官方依据的组合:① 交错起点——CSS animation/transition delay 的编排用法,JS 库等价物为 Motion 的 delay/stagger(调研 04§1.3,负值=中途开始);② 方向性——M3《Transition patterns》Enter and exit 模式:进入方向建立空间模型,通知自顶部、抽屉自侧缘、sheet/键盘自底部,snackbar 依位置定向展开(调研 04§3.3);时长取官方配对表 std-decel 250ms(进入)/ std-accel 200ms(退出)(调研 04§1.4)。交错间隔具体数值官方未给出。
