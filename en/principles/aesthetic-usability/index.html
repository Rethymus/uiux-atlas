Aesthetic-Usability Effect

美学可用性效应 · Aesthetic-Usability

Users judge beautiful designs as more usable: aesthetics correlates with *perceived* ease of use more strongly than with *actual* ease of use. Beauty buys tolerance — and can mask real problems.

Parameters
Motion▾
beautyrefined

JS-type param (demo subscribes and toggles the right card's data-beauty): the right card's finish level. plain = identical to the left plain card (degenerates into an A/A self-control); refined = 14px radius + soft shadow + accent color; premium = refined plus a gradient header, 18px radius and more whitespace. Only the decoration layer changes — button layout and count stay identical on both sides.

handicapnone

JS-type param: injects the same real usability defect into BOTH sides equally (controlled variable). small-target = menu buttons squashed to 18px tall; slow-response = success feedback delayed 900ms with a 'processing' state. Intent: under an identical defect the refined side's perceived rating drops less — beauty buying tolerance. Both values are demo defect values, not law constants (stated as such).

Code breakdown

Structure & DOM

The demo is an A/B self-experiment of the same functionality at two finish levels: two ATM-style cards whose button layout and count are byte-identical — only the decoration layer differs.

<div class="au-cards">
  <section class="au-card">                <!-- plain control, ATM-A -->
    <h3>Plain terminal ATM-A</h3>
    <div class="au-menu">…4 menu buttons…</div>
    <p class="au-status" aria-live="polite">time — ms · misses 0</p>
    <label class="au-rate">Perceived ease <input type="range" min="1" max="7" /></label>
  </section>
  <section class="au-card" data-beauty="refined">  <!-- refined, ATM-B -->
    …structure identical to the left…
  </section>
</div>
<div class="au-compare">Perceived gap +1 · measured time gap 0 ms · miss gap 0</div>

Key points:

  • The functional layer is identical on both sides (4 buttons, the same “balance check” task); data-beauty only switches the right card’s decoration — a controlled variable, so any rating gap can only come from finish level;
  • The handicap defect is injected equally into both sides (same defect, same place), cleanly isolating “beauty tolerance” as the variable;
  • The conclusion never relies on reading a chart: time, misses, perceived gap and measured gap all appear as text (aria-live keeps it synced).

Styling & Parameters

/* Finish level lives only in the decoration layer: radius, border color, shadow, header underline */
.au-card[data-beauty="refined"],
.au-card[data-beauty="premium"] {
  border-color: color-mix(in srgb, var(--au-accent) 45%, transparent);
  border-radius: 14px;
  box-shadow: 0 6px 20px rgba(0, 0, 0, 0.1);
}
.au-card[data-beauty="premium"] { border-radius: 18px; /* + gradient header, more whitespace */ }
  • Three beauty tiers: plain (identical to the control — degenerates into an A/A self-test) → refined (14px radius + soft shadow + accent color) → premium (plus gradient header, 18px radius, more whitespace); all are demo teaching tiers;
  • The two handicap demo defect values: small-target = 18px-tall buttons, slow-response = 900ms delayed success feedback — neither is a law constant, stated as such in the schema;
  • accent arrives via --au-accent and colors only decoration (underline, hover, success state); text keeps a fixed dark color;
  • The experiment’s official numbers: 26 ATM interface variants × 252 participants (Kurosu & Kashimura 1995, Hitachi Design Center; supplement research 12 §14) — the law’s evidence, not adjustable knobs;
  • The 1–7 rating scale is a demo teaching choice (the original study used semantic-differential scales); it measures your own relative gap, it does not reproduce the study’s absolute values.

Motion & Interaction

  • Any button click starts the timer; hitting “balance check” stops it: elapsed = real milliseconds from first interaction to success; the slow-response tier inserts a 900ms “processing…” state before success — equally slow on both sides;
  • Perceived ratings use the native input[type=range] with synced numeric text, no custom component;
  • The compare strip at the bottom only concludes once both sides are done; before that it shows an honest placeholder;
  • Under prefers-reduced-motion: reduce button transitions drop and the success state changes color only — ratings and timing are unaffected by the motion setting.

Real-world examples

  • Hitachi ATMs (the vehicle of Kurosu & Kashimura 1995): 26 interface variants tested on real ATM layouts with 252 participants, whose aesthetic ratings correlated more strongly with perceived usability — the law was first quantified on a product, not on an abstract lab task (supplement research 12 §14);
  • Apple’s global nav and the macOS Big Sur translucent sidebar: production reference points recorded in research 03 §1 — high-finish materials make system-level interfaces read as “polished, trustworthy”, a direct case of aesthetic investment converting into perceived quality (editorial extrapolation from research 03 §1);
  • Cautionary case: the full-screen criticism of Apple Liquid Glass: NN/g criticized its full-screen use for hurting readability (research 03 §2) — when aesthetic upgrades outrun readability, the aesthetic-usability effect flips into harm, and “beautiful” no longer masks the problem.

Parameter Sensitivity

ParameterUp / higher tier…Down / lower tier…
beautypremium: gradient header + big radius + whitespace usually stretches the perceived gap to its maxplain: both sides identical (A/A self-test), the perceived gap should collapse to ~0 — the baseline for checking whether your own ratings are fair
handicapboth defect tiers make the measured gap appear: 18px targets raise misses, the 900ms delay raises time — yet the refined side’s perceived rating usually drops less: tolerance made visiblenone: back to a pure finish-level contrast; measured performance ties and only the perceived gap remains
accentchanges decoration color only, function and data untouched — tests whether a color-only change is enough to move your perceived scorehas no effect on the plain card (it never consumes the variable); the control side stays neutral

The lesson: aesthetics is a legitimate usability investment — but guard it in the test protocol — run the first usability round on unpolished wireframes, or force-measure task time and error rate on the polished build; praise is not a metric (supplement research 12 §14).

When to use 3
  • Trust-sensitive surfaces (landing, sign-up, payment): finish level drives first impressions and perceived quality
  • When features are at parity with competitors, finish level builds a perceived edge
  • Legacy or internal-tool redesigns: aesthetics first — it cheaply buys tolerance of the old warts
When not to use 3
  • Using beauty to bury unresolved usability defects (performance, error rates, accessibility)
  • Testing only the polished build — praise substitutes for real metrics
  • Sacrificing readability for looks: NN/g criticized Liquid Glass' full-screen use for hurting readability (research 03 §2)
Accessibility

An aesthetic upgrade must not break contrast or accessibility (WCAG 2.1 SC 1.4.3, 4.5:1): in this demo the accent is decorative only (underline, hover, success) and text keeps a fixed dark color; the A/B sides are distinguished by headings and structure, never by color alone; ratings use native input[type=range] + label, task state is presented as text and announced via aria-live — never conveyed by animation or color alone.

Browser support

The demo uses only native DOM/CSS/JS (buttons, range sliders, transitions) — no cutting-edge features; any modern browser runs it.

Fallback

The engineering exit: aesthetics is not a degradable CSS feature but a production process — treat 'finish level' as its own acceptance item; and bake 'beauty masks usability' into the test protocol: run the first usability round on unpolished wireframes, or force-measure task time and error rate on the polished build, never letting praise stand in for metrics. If oklch is unsupported the accent falls back to the nearest parseable color.
