Hick's Law

希克定律 · Hick-Hyman Law · 希克-海曼定律

Decision time grows with the number and complexity of choices: more alternatives, slower decisions. Cut options where response time matters, split complex tasks, and surface a recommended option.

Code breakdown

Structure & DOM

The demo is a choice-reaction-time experiment: N candidate target buttons on a ring, one randomly highlighted each round, measuring “highlight appears → hit”:

<div class="hk-ring">
  <button class="hk-target" data-active="false">1</button>
  <button class="hk-target" data-active="true">2</button>
  <!-- N of them -->
</div>

Key points:

  • N is controlled by the choices param (2–8); the highlighted target gets a 3px green outline + a “Hit” label — dual-channel marking, never color alone (SC 1.4.1);
  • Wrong clicks don’t end the round — error count and the timer coexist; “slow decision” and “wrong decision” are two separate measurements;
  • The stats table groups median RT by N with sample counts; cross-N comparison happens entirely in the side panel.

Styling & Parameters

// choices / pause are JS-type params: the demo subscribes to the store
const [choices, setChoices] = useState(() => store.get("choices") as number);
useEffect(() => store.subscribe(() => {
  setChoices(store.get("choices") as number);
  setPause(store.get("pause") as number);
}), [store]);
  • choices defaults to 4: a teaching starting point, not a claim of the law; the classic Hick-Hyman form is RT = a + b·log₂(N) (Hick & Hyman 1952), and the demo lets you measure your own a and b;
  • pause defaults to 800ms: the inter-round gap, a demo pacing param (too short bleeds one round’s hesitation into the next round’s timer);
  • Highlight marking: 3px outline + text label — the “Hit” cue also serves screen readers (the button text stays a number).

Motion & Interaction

  • Each round: the highlight flips on (opacity 0.45→1 plus outline switch, 0.12s) and the timer starts; a hit extinguishes it, and the next round fires after pause ms;
  • Wrong clicks: errors +1, highlight stays, timer keeps running — no punishment, no interruption, the data speaks;
  • Changing choices re-lays out the ring immediately (changing N ends the current round; tap any target to restart);
  • No looping animation, no reduced-motion need; every target is a real button, Tab-focusable one by one (key conventions in the keyboard-navigation entry).

Real-world examples

  • Google’s homepage: Laws of UX’s first example — decision cost for entering a keyword is minimized by removing anything distracting or requiring extra decisions, the extreme form of “cut options where response time matters”;
  • Apple TV remote: the second Laws of UX example — the remote itself carries very few keys, transferring complexity to the TV interface where information is organized and progressively disclosed in menus;
  • Slack’s progressive onboarding: research 07 §23’s original case — newcomers see only the message input, learn messaging via Slackbot first, and the rest unlocks gradually instead of flooding the user with every feature at once.

Parameter Sensitivity

Working range: teach the contrast with N=2 vs N=8; read medians only once a single N has ≥5 samples; and mind the law’s own caveat — don’t simplify to the point of abstraction: you cut decision cost, not function.

When to use 4
  • Narrow options where response time is critical (checkout, flash sale, emergency actions)
  • Split complex tasks into wizard steps that reveal progressively
  • Highlight a recommended option instead of a flat sea of equal choices
  • Progressive onboarding for new users (the Slack case, research 07 §23)
When not to use 2
  • Simplifying to the point of abstraction — the Laws of UX caveat verbatim
  • Flat undifferentiated long lists that dump the whole decision on the user
Accessibility

Reducing visible options must not reduce reachable function: features hidden behind progressive disclosure stay reachable via keyboard and screen readers (structure in the keyboard-navigation entry). The highlighted target is never color-only (cf. WCAG SC 1.4.1); the demo marks it with an outline plus text.

Browser support

The demo times with performance.now() and schedules via rAF/timeout — all modern browsers; performance timing is quantized by browser protections (~1ms), plenty for 100ms-scale behavior.

Fallback

The law cannot degrade, but its UI conclusions have three engineering exits: narrow options on critical paths, split complex flows into wizards, and surface a recommended option so users don't drift across a flat list. All capability must remain — you reduce decision cost, not function.

Sources 1

OriginIn 1952 British psychologist William Edmund Hick and American psychologist Ray Hyman experimentally related the number of stimuli to reaction time, yielding the Hick-Hyman law: more choices, slower decisions (Jon Yablonski, Laws of UX; research 07 §23). Its classic form is RT = a + b·log₂(N).
