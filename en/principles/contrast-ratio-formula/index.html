Contrast Ratio Formula

WCAG relative luminance · relative luminance · 4.5:1 · contrast ratio

The full WCAG 2.1 derivation: 8-bit→[0,1]→γ decode→0.2126R+0.7152G+0.0722B relative luminance→(L1+0.05)/(L2+0.05) — feed two colors, get the ratio live, judged against the AA/AAA gates.

Web Standard ★★★
Live demo official default
Parameters
Color▾
fg#767676

Foreground (text) color. Default #767676 is the classic AA-critical gray — 4.5422:1 against white when run live, just clearing the 4.5:1 gate; one step lighter (#8a8a8a ≈ 3.5:1) passes only as large text.

bg#ffffff

Background color. The demo computes L for both colors and puts the lighter one in the numerator of (L1+0.05)/(L2+0.05) — the formula is polarity-symmetric.

Code breakdown

Structure & DOM

The demo is a live contrast calculator: the panel’s two swatches (fg/bg) are the inputs, the stage renders an “Aa” specimen in the real colors, and the derivation unfolds line by line beside it:

<div class="cr-card" style="--cr-fg:#767676; --cr-bg:#ffffff">
  <span class="cr-preview">Aa specimen</span>
  <ol class="cr-steps">
    <li>sRGB → [0,1]: 118/255 = 0.4627</li>
    <li>γ decode: ((0.4627+0.055)/1.055)^2.4 = 0.1804</li>
    <li>L = 0.2126·R + 0.7152·G + 0.0722·B = 0.1804</li>
    <li>Contrast = (1.05)/(0.2304) = 4.5422:1 → AA body ✓</li>
  </ol>
</div>

Key points:

  • The specimen’s color/background bind straight to --cr-fg/--cr-bg — what the eye sees and what the formula sees are the same color pair;
  • The four rows are the formula’s four steps: normalize → γ decode → weighted sum → ratio;
  • Verdicts cover all four gates (AA body / AA large / AAA body / AAA large); misses flag red.

Styling & Parameters

Two color parameters (fg/bg, injected via cssVar), with the math implemented in-demo, zero dependencies. The complete derivation (research 14 §2.3; formulas quoted verbatim from the WCAG 2.1 spec):

① Relative luminance (three steps):

RsRGB = R8bit/255 (likewise G, B)
R = RsRGB ≤ 0.04045 ? RsRGB/12.92 : ((RsRGB + 0.055)/1.055)^2.4
L = 0.2126·R + 0.7152·G + 0.0722·B     ← sRGB-primary luminance coefficients (BT.709 lineage)

② The contrast ratio:

Contrast = (L1 + 0.05) / (L2 + 0.05)     L1 is the lighter; 0.05 is the flare allowance

③ Zero-dependency JS (shares its γ decode with oklch-conversion):

const srgb2lin = c => (c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4);
const wcagLuminance = (r8, g8, b8) =>
  0.2126 * srgb2lin(r8 / 255) + 0.7152 * srgb2lin(g8 / 255) + 0.0722 * srgb2lin(b8 / 255);
const wcagContrast = (L1, L2) => (Math.max(L1, L2) + 0.05) / (Math.min(L1, L2) + 0.05);
wcagContrast(wcagLuminance(118,118,118), wcagLuminance(255,255,255)); // 4.5422:1

Gates (same spec): 1.4.3 AA — body ≥4.5:1, large ≥3:1; 1.4.6 AAA — body ≥7:1, large ≥4.5:1; 1.4.11 non-text component boundaries 3:1. Large = ≥18pt (24px) regular or ≥14pt (≈18.66px) bold, with the spec noting ‘CJK takes equivalent sizes’. Verification: #767676 vs white = 4.5422:1 (the classic AA-critical gray) ✓.

Motion & Interaction

  • New colors, new verdict: change fg/bg in the panel (the demo carries quick chips for critical-gray / passing-gray / failing-gray) and the four derivation rows and verdict stamps recompute live;
  • Swap experiment: swapping fg/bg leaves the ratio unchanged (the formula is polarity-symmetric), demonstrating “L1 is always the lighter one”;
  • Dark-mode experiment: set bg dark and fg a light gray (e.g. #b0b0b8 on #0b1220) — the ratio climbs high, exactly where APCA flags the proportional metric for overestimating light-on-dark readability; both the MDX and the demo readouts note that boundary;
  • No autonomous animation; the entrance fade respects prefers-reduced-motion.

Real-world examples

  • #767676, the critical gray: 4.5422:1 against white — the a11y community’s hard marker for “how light can body gray go”; palette generators draw their AA line right around it (verified by running the formula here);
  • Apple Dark Mode: the official doctrine sets 4.5:1 as the floor and pushes custom foreground/background pairs toward 7:1 (AAA) — the canonical split between the legal minimum and the in-house bar (research 13 §1.5, Typography/Materials official Markdown);
  • Ant Design’s text colors: body/background contrast targeted at ≥7:1 (AAA), with primary text at #000000E0 (88% black) rather than pure black — holding AAA while shaving pure black’s harshness (research 13 §3.4); its sibling entry wcag-contrast ships the same formula as a live checking panel.

Working doctrine: the WCAG ratio is the compliance instrument (law and audits), while product bars push toward 7:1; audit dark themes as pairs; translucent layers get checked at both extremes. Sibling entries: wcag-contrast (the same formula as a shipped checking entry), oklch-conversion (shares the γ decode), prefers-contrast (the user-side contrast preference), oklch-workflow (fixing L to make contrast predictable).

When to use 4
  • Design-token sign-off: compute each text/background pair under both themes before tokens ship
  • Generating gray ramps: find the last step that clears 4.5:1 — the AA-critical gray
  • Accessibility audits and compliance: WCAG 2.x / EN 301 549 legally hinge on this exact formula
  • Component-library docs: attach measured ratios to color tokens so reviews stop arguing about appearances
When not to use 4
  • Reporting the ratio alone for light-on-dark — the proportional metric systematically overestimates readability there
  • Treating AA as the finish line — AAA 7:1 for body text is Apple's and Ant's internal bar; 4.5:1 is the legal floor, not the goal
  • Computing one ratio for translucent overlays — the composite shifts as backdrop scrolls; check the brightest and darkest extremes separately
  • Rounding up to pass: 4.49:1 written as 4.5:1 — the raw value must clear the gate
Accessibility

This formula IS the accessibility tool: body text AA 4.5:1, large text 3:1; AAA body 7:1, large 4.5:1; non-text component boundaries 3:1 (SC 1.4.11). Large = ≥18pt (24px) regular or ≥14pt (≈18.66px) bold, with the spec noting 'CJK takes equivalent sizes'. Known bias: the proportional metric overestimates light-on-dark readability — re-check with APCA (Lc scale), where Lc 75 is the perceptual body-text floor.

Browser support

A pure mathematical definition, browser-independent; the CSS contrast-color() function (auto black/white foreground) is still a proposal per community sources — precompute with this formula in production instead. WCAG 2.2 is out but the contrast definition is unchanged, so the 2.1 doctrine stands.

Fallback

The formula has no runtime dependency and no fallback path; the real 'fallback' is on the design side: if the ratio misses, darken/lighten one side and recompute — each ~10% step in gray moves the ratio roughly 0.4–0.6:1 (a linear-domain approximation) — compute before shipping, never eyeball 'dark enough'.

Sources 3

OriginThe formulas are quoted verbatim from the WCAG 2.1 spec (the relative-luminance and contrast-ratio definitions, full text fetched and checked); the 0.2126/0.7152/0.0722 coefficients share their origin with ITU-R BT.709 primaries; 0.05 is the flare allowance; the γ threshold was 0.03928 before 2021-05 (older spec), updated to 0.04045 per official note 2 with no practical difference (research 14 §2.3).
