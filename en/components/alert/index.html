Alert

警告条 · 通知条 · 横幅提示 · Inline Alert

A four-tone warning block in the document flow: never steals focus, does not auto-dismiss, announced via role=alert — splitting feedback duty with toast (floating, auto-dismiss) and Dialog (blocking).

Live demo official default
Parameters
Motion▾
typeinfo

Four semantic states (JS-type param). AntD Alert type defaults to **info**; banner mode flips the default to **warning**. Colors follow antd seed functional tokens: success #52c41a / info(primary) #1677ff / warning #faad14 / error #ff4d4f; pale fills and borders derive via the 'Bg=step1, Border=step3' palette rule.

closableoff

Whether a manual close button is offered (JS-type param). AntD Alert closable defaults to **false**. Alerts persist by default — exactly the boundary with toast (APG warns alerts must not auto-dismiss, WCAG 2.2.3); with the close button the user decides when to remove it.

showIconoff

Whether the semantic icon shows (JS-type param). AntD Alert showIcon defaults to **false**; banner mode flips the default to **true**. Icons add a second channel beside color (NN/g error guideline 5: icon + color for color-blind users) — shape first, then text, when scanning.

banneroff

Whether to render as a full-width top banner (JS-type param). AntD Alert banner defaults to **false**; when on, radius and side borders drop, it spreads full-width, and type/showIcon defaults flip to warning/true — banners suit site-level notices (maintenance, storage warnings).

Code breakdown

Structure & DOM

An alert is a persistent in-flow warning block (splitting feedback duty with floating toasts and blocking dialogs): a semantic color block, optionally with an icon, description text, and a close button.

<div class="alert" role="alert" data-type="warning">
  <svg class="icon" aria-hidden="true">…</svg>
  <div>
    <strong>Title</strong>
    <span>Description</span>
  </div>
  <button aria-label="Close">×</button>
</div>

Key points:

  • The container carries role="alert": dynamically inserted, it is auto-announced by most screen readers and never steals keyboard focus — when you must interrupt, escalate to an alertdialog (APG Alert);
  • The icon is an auxiliary channel: aria-hidden, colored via currentColor in the same semantic hue; color-only encoding violates WCAG 1.4.1, so color + icon is the dual-channel fallback;
  • The close control is a real <button> (focusable, aria-label); alerts do not auto-dismiss by default — APG explicitly warns that disappearing too fast violates WCAG 2.2.3.

Styling & Parameters

All four parameters are JS-type (the demo subscribes to the store): type switches the data-type semantic color, closable/showIcon add or remove elements, banner switches the full-width layout.

.alert {
  display: flex; align-items: flex-start; gap: 10px;
  padding: 10px 14px; border-radius: 8px; border: 1px solid;
  background: color-mix(in srgb, var(--c) 10%, #fff);   /* pale fill ≈ palette step 1 */
  border-color: color-mix(in srgb, var(--c) 40%, #fff); /* border ≈ palette step 3 */
  color: rgba(0, 0, 0, 0.88);                            /* antd colorText */
}
.alert[data-type="success"] { --c: #52c41a; }
.alert[data-type="info"]    { --c: #1677ff; }
.alert[data-type="warning"] { --c: #faad14; }
.alert[data-type="error"]   { --c: #ff4d4f; }
.alert.is-banner { border-radius: 0; border-top: 0; border-left: 0; border-right: 0; }

Where the numbers come from (antd 6.7.1): type defaults to info, showIcon/closable/banner all default false; the four hues are the seed functional tokens colorSuccess #52c41a, colorWarning #faad14, colorError #ff4d4f, colorPrimary #1677ff (design-study 06 §2.2); the ‘Bg=palette step1 / Border=step3 / main=step6’ derivation comes from genColorMapToken (06 §2.3⑤), approximated with color-mix for steps 1/3. In banner mode the defaults flip: type → warning, showIcon → true (06 §4.13).

Motion & Interaction

  • No entrance animation is the norm: the goal is to remain until read; toast-style slide choreography is noise here; the demo keeps only a 0.15s light fade, dropped under reduced-motion;
  • Close interaction: with closable=on, a real button removes the block (the removed node holds no focus); the demo offers a re-show entry so play is recoverable;
  • Banner mode: full-width, pinned to the top, pushing content down — the layering between site-level notices and page content; watch antd’s flipped defaults (warning/true) when toggling;
  • Never carousel multiple alerts: APG warns frequent interruptions harm users with visual/cognitive disabilities (WCAG 2.2.4); merge messages or restructure the page.

Real-world examples

  • GitHub: full-width top banners on repository pages — the “This repository has been archived” strip and security alerts for sensitive dependencies — all full-width, dismissible, persistent banners;
  • Gmail: when the free quota is nearly full, a top banner appears (storage running out, with a “Manage storage” entry) — it never blocks reading or sending but stays put until space is freed;
  • VS Code: notification-center cards in the bottom-right carry an icon, description, and close button, persisting until handled — the editor’s “persistent, workflow-interrupting-light” reminders share the same semantics as in-flow alerts.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
typeno size per se — it swaps semantics and mood: success closure, info neutral, warning caution, error urgency; wrong semantics hurt more than wrong huessame; on multi-alert pages keep error the rarest (Von Restorff: emphasis needs restraint)
closableon: users gain the right to clear — right for notice-type content that is useless once readoff: persists to the end — right for standing constraints (like an archived state); both must never auto-dismiss
showIconon: shape is recognized before text, faster scanning, color-blind safe, slightly taller blockoff: quieter, semantics ride on the pale fill alone — leaving low-vision users only the text title
banneron: site-level forced exposure, a full row of height, content pushed down; only one should exist at a timeoff: an ordinary flow block, several may coexist but keep ≤1 per screen; mixing banner and non-banner muddies hierarchy

Working ranges: one per screen, errors rarest, banner only for site-level exposure; keep text within a one-line title plus one-line description.

When to use 3
  • Page-level or form-top summary errors and status notes (Carbon: overall errors as inline notifications)
  • Site-level banners: storage warnings, maintenance notices
  • Success/outcome feedback that must remain until read
When not to use 4
  • Auto-dismissal — that is toast's job; fast-disappearing alerts violate WCAG 2.2.3 (APG)
  • Must-act-before-continue info — use an alertdialog (APG: escalate to a dialog when you must interrupt)
  • Field-level form validation — errors belong next to the field (NN/g guideline 3)
  • Stacking many alerts per screen — noise; merge into one or restructure the page
Accessibility

Container role=alert, auto-announced by most screen readers on dynamic insertion (WAI-APG); never takes focus — escalate to alertdialog when you must interrupt; no auto-dismiss (WCAG 2.2.3), no frequent interruptions (2.2.4); icons are auxiliary — color + icon dual-channel avoids color-only encoding (WCAG 1.4.1); close button is a real focusable control with aria-label.

Browser support

Implemented as ordinary flow-level blocks with color-mix-derived pale fills, all Baseline; color-mix is available across browsers since 2023, degrading to a white fill where unsupported (message unaffected).

Fallback

Without color-mix, older environments stay readable with the functional-color border on white; icons are SVG currentColor so no image loading is involved; the close button must be a real button, never hidden by CSS alone.

Sources 2

OriginSemantics from the W3C APG Alert pattern: role=alert shows a short important message, auto-announced by most screen readers on dynamic insertion, never stealing keyboard focus; APG specifically warns against auto-dismissing (WCAG 2.2.3) and frequent interruptions (2.2.4). Implementation follows Ant Design Alert: type default info, showIcon/closable/banner default false (antd 6.7.1, research 07 §9, design-study 06 §4.13).
