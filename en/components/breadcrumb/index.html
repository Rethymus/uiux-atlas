Breadcrumb

面包屑导航 · Breadcrumb Trail · 路径导航

A list of parent-page links ordered by hierarchy showing where the current page sits in the site structure: horizontal, before the main content, with every ancestor clickable for step-by-step backtracking.

Component Lib ★★
Live demo official default
Parameters
Motion▾
separator/

JS-type param (the demo subscribes and switches the between-level separator). Ant Design Breadcrumb's separator officially defaults to "/" (06-antdesign.md §4.21); the separator is purely decorative and should be aria-hidden for screen readers (natural when rendered via CSS pseudo-elements — MUI's accessibility notes treat it exactly this way, verified live 2026-11-21).

Geometry▾
maxItems3

JS-type param: when the trail exceeds N levels, the middle levels collapse into one clickable "…" expander (first and last levels always stay). Ant Design Breadcrumb has no such prop; MUI Breadcrumbs does have maxItems (official example maxItems={2} collapses the middle into "…", with no default documented, verified live 2026-11-21); this entry's default of 3 is a task-spec demo value — on the 5-level sample path the collapse is visible out of the box.

Code breakdown

Structure & DOM

A breadcrumb = navigation landmark + ordered list + hierarchical links. A list of parent-page links ordered by hierarchy that helps users locate themselves; placed horizontally before the main content (APG, research 07§12).

<nav aria-label="Breadcrumb">
  <ol>
    <li><a href="/">Home</a></li>
    <li aria-hidden="true">/</li>
    <li><a href="/resources">Resources</a></li>
    <li aria-hidden="true">/</li>
    <li aria-current="page">Breadcrumb</li>
  </ol>
</nav>

Key points:

  • The current page is not a link and carries aria-current="page"; if a product makes it clickable, the attribute stays (APG: optional when the current page is not a link, research 07§12);
  • Separators are pure decoration: aria-hidden (as explicit list items) or rendered via CSS pseudo-elements, never read aloud (MUI accessibility notes, verified live 2026-11-21);
  • Long trails collapse: middle levels fold into a focusable ”…” button that expands the full trail on click (MUI “Collapsed breadcrumbs”: past maxItems the middle collapses into an ellipsis, verified live 2026-11-21);
  • Every ancestor is a clickable link — clicking it means “go back up to that level”.

Styling & Parameters

Two parameters: separator switches the between-level glyph and maxItems sets the collapse threshold; both are JS-type (the demo subscribes to the store).

.crumbs ol { display: flex; align-items: center; gap: 8px; margin: 0; padding: 0; list-style: none; }
.crumbs a { font-size: 14px; color: rgba(0, 0, 0, 0.65); text-decoration: none; border-radius: 6px; padding: 2px 6px; }
.crumbs a:hover { color: #1677ff; background: rgba(0, 0, 0, 0.04); } /* primary + 4% neutral fill (§2.3-⑤) */
.crumbs a:focus-visible { outline: 2px solid #1677ff; outline-offset: 1px; }
.crumbs [aria-current="page"] { font-size: 14px; color: rgba(0, 0, 0, 0.88); font-weight: 500; } /* neutral text 88% */
.crumbs .sep { color: rgba(0, 0, 0, 0.45); }
.crumbs .expander {
  border: 1px solid #d9d9d9; background: #fff; border-radius: 6px;
  padding: 2px 10px; cursor: pointer; font-size: 14px;
}

Where the numbers come from (cross-checked against antd 6.7.1 in out/design-study/06-antdesign.md): separator officially defaults to ”/” (§4.21); non-current text 65% (colorTextSecondary), current-page text 88% (colorText), hover fill 4% (FillTertiary tier), primary #1677ff, stroke #d9d9d9 (colorBorder); collapsing aligns with MUI Breadcrumbs maxItems (first/last kept, middle folded; official example maxItems={2}, no default documented — this entry’s default of 3 is a task-spec demo value).

Motion & Interaction

  • Backtracking: clicking any ancestor truncates the trail there — the interaction is fundamentally “move a pointer on the hierarchy tree”, not browser history back;
  • Collapse/expand: clicking ”…” reveals the folded middle levels (with a way back); no animation by default — if you add one, keep it under 0.2s of fade and respect prefers-reduced-motion;
  • Hover: non-current items hover to primary color + 4% fill as the “clickable” cue; the current item is never clickable;
  • Relationship to top navigation: the nav answers “switch areas”, the breadcrumb answers “go up a floor” — they complement, not replace.

Real-world examples

  • MDN doc pages: every article opens with a hierarchy line (e.g. Home → CSS → CSS layout), the current page bold and non-clickable; deep information hierarchy makes the trail a standard fixture of doc sites.
  • Windows Explorer address bar: the path renders as a breadcrumb where each directory segment is clickable and a per-segment dropdown reveals sibling directories — a hybrid “breadcrumb + dropdown” form.
  • E-commerce product pages: product detail pages show “Home → Category → Subcategory → Product”, and clicking any upper category returns to its listing — an important traffic-return entry.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
separator (glyph choice)> points harder with a sense of “entering”; · is the quietest, fitting visually calm surfaces; / is antd’s default and the docs-site convention with the lowest recognition costHeavier glyphs (icon arrows) grab attention and compete with content; with many levels, heavy glyphs amplify the noise
maxItemsLess collapsing, the full trail stays visible, but long trails grow linearly in width and overflow narrow screensCollapsing kicks in earlier and the trail stays compact; below 3 the middle is almost entirely hidden and backtracking first costs an extra expansion click

Working ranges: trails of 3–5 levels; no folding on mobile or for trails under 6; the ”…” expander about 32px wide with a hit area ≥24px.

When to use 3
  • Hierarchical sites of 3+ levels: docs, e-commerce categories, admin consoles — locate the user and backtrack level by level (APG: helps users locate themselves, research 07§12)
  • Complementing top navigation: the nav handles cross-area jumps while the breadcrumb handles in-area depth
  • Backtracking on deep detail pages: after drilling in level by level, every step stays clickable on the way back
When not to use 4
  • Flat sites of 1–2 levels — the trail is redundant and costs more visual space than it informs
  • Replacing primary navigation or history back — a breadcrumb expresses hierarchy, not browsing history
  • Long trails on narrow screens without folding — beyond 5 levels on mobile, collapse or elide the middle
  • Making the current page a link to itself — pointless and misleading
Accessibility

APG Breadcrumb semantics (research 07§12): the whole trail lives in a navigation landmark named via aria-label; levels use an ol; the current page sets aria-current="page" (optional when the current page is not a link); separators are aria-hidden (MUI accessibility notes, verified live 2026-11-21); the collapsed "…" must be a focusable button with aria-expanded and a label like "expand collapsed levels", with a way to collapse again.

Browser support

No CSS compatibility gate: the structure is a nav landmark + ol + links, all baseline web features; pseudo-element separators are not focusable and stay out of the accessibility tree (MUI accessibility notes, verified live 2026-11-21).

Fallback

Without JS it degrades to a plain link trail: all levels stay as links inside the ol and the collapsing logic disappears, but no path information is lost; only the final level becomes plain text and loses its backtrack entry.

Sources 3

OriginThe metaphor comes from Hansel and Gretel's trail of crumbs: the WAI-ARIA APG "Breadcrumb" pattern defines the navigation landmark + ordered-list semantics (research 07§12, first-hand); production references are Ant Design Breadcrumb (separator officially defaults to "/", see out/design-study/06-antdesign.md §4.21) and MUI Breadcrumbs (maxItems collapsing, verified live 2026-11-21).
