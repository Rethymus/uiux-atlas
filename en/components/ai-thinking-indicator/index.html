Code breakdown

Structure & DOM

A thinking indicator is a “wait-acknowledgment mechanism”: a status line (thinking/done) → the thinking body (a shimmer label or dot pulse) → an optional step card (the reasoning process). Three layers that upgrade with elapsed time — not a beauty contest among three decorations.

<div class="msg" aria-busy="true">          <!-- thinking region: busy semantics on the container -->
  <button class="step-toggle" aria-expanded="true">
    Thinking… <span class="shimmer">step-card title</span>
  </button>
  <div class="steps">                       <!-- step card: complete/active/pending -->
    <p data-state="done">Read the question</p>
    <p data-state="active">Comparing options…</p>
  </div>
  <button class="stop">Stop</button>         <!-- must stay visible past 10s -->
</div>

Key points:

  • The form follows NN/g’s three limits, not aesthetics: no special feedback for 0.1–1s; past 1s the machine must show it is working (shimmer/dots); past 10s a percent-done progress plus a clearly marked way to interrupt (NN/g first-hand text, research 15 §3.1);
  • The shimmer is not a glow filter — vercel/chatbot implements it as a gradient sweep with text-transparent + background-clip: text, parameterized by duration (2s linear default) and spread (the highlight-band factor, officially 2, adapting to text length: dynamicSpread = children.length × spread);
  • The step card is a small state machine: AI Elements ChainOfThought uses complete | active | pending, and Task uses pending | in_progress | completed with a built-in done/total counter;
  • Division of labor with skeleton screens: skeletons say “this block hasn’t arrived”, thinking indicators say “the whole answer is still in flight”; the relation to the Doherty threshold: 1s is exactly the response ceiling, and this entry serves the 1–10s band.

Styling & Parameters

Six parameters map to three kinds of declarations: form selection (enum), sweep pacing (a CSS variable), and step-card behavior (JS-type, subscribed by the demo):

/* Shimmer thinking label: gradient sweep + background-clip:text (vercel/chatbot isomorphic) */
.sti-shimmer {
  background: linear-gradient(90deg, var(--text-faint) 40%, var(--text-1) 50%, var(--text-faint) 60%);
  background-size: calc(200% * var(--sti-spread, 2)) 100%;
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
  animation: sti-sweep var(--sti-shimmer-ms, 2000ms) linear infinite;
}
@keyframes sti-sweep { from { background-position: 100% 0; } to { background-position: -100% 0; } }

/* Dot pulse: the submitted gap (AI SDK's official form family) */
.sti-dots i { animation: sti-pulse 1.2s ease-in-out infinite; }
.sti-dots i:nth-child(2) { animation-delay: 0.15s; }
.sti-dots i:nth-child(3) { animation-delay: 0.3s; }
@keyframes sti-pulse { 0%, 70%, 100% { opacity: 0.25; } 35% { opacity: 1; } }

Where the numbers come from (first-hand source/docs, research 15 §3.2):

  • Sweep duration: 2s default, linear loop; AI Elements’ official tiers are Fast 1s / Default 2s / Slow 4s / Very Slow 6s — the parameter slider is exactly those four tiers;
  • Highlight band: spread defaults to 2, with dynamicSpread = children.length × spread adapting to text length;
  • Auto-collapse: AUTO_CLOSE_DELAY = 1000ms (a reasoning.tsx source constant, firing once only);
  • The submitted gap: status === ‘submitted’ && spinner/loading dots (the official AI SDK example);
  • The exact dot-grid forms of the three consumer products have no published UI spec (unverified); open source consistently clones “thinking-text shimmer → dot pulse”.

Motion & Interaction

  • Duration tiers: the demo advances through time — gap (dots) → thinking span (shimmer + step card lighting up level by level) → done (collapse + readout); each form switch visualizes one of NN/g’s limits;
  • Auto-collapse: after the stream ends wait stepAutoCollapseMs (official 1000ms), then collapse once automatically; the title row then carries the “Thought for N seconds” readout (officially degrading to a few seconds when the duration is unavailable) and the user can reopen manually;
  • Expansion policy: autoOpenOnStream: on is reasoning.tsx’s defaultOpen ?? isStreaming — the card opens when the stream starts so users follow the reasoning; the off tier keeps it collapsed with only the shimmering title hinting;
  • Stop button: stopVisible: off demonstrates the NN/g third-limit violation — thinking past 10s with no marked way to interrupt; AI SDK’s official companion is useChat’s stop();
  • No fake progress bars in 2–10s: NN/g’s display inertia — the screen would change faster than users can track; that band gets rotating text/pulse, i.e., imprecise feedback;
  • prefers-reduced-motion: stop the sweep and pulse, keep a static “Thinking…” label (demo behavior).

Real-world examples

  • vercel/chatbot shimmer.tsx: duration 2s linear loop, spread 2, dynamicSpread adapting to text length, module-level motion-component caching wrapped in memo — the first-hand production sample of the shimmer label (verified against the repository, research 15 §3.2);
  • vercel/chatbot reasoning.tsx: the stream triggers “Thinking…” with Shimmer; on finish AUTO_CLOSE_DELAY = 1000ms auto-collapses (once); duration = Math.ceil((Date.now() - startTime) / 1000) feeds the “Thought for N seconds” readout; the card auto-expands when the stream starts (defaultOpen ?? isStreaming); the content area auto-scrolls to bottom while streaming (research 15 §3.2);
  • AI SDK Chatbot docs: the status === ‘submitted’ stage officially pairs Spinner/loading dots — the “sent, waiting for the stream” gap has an official owner;
  • AI Elements ChainOfThought / Task: step state machines complete|active|pending and pending|in_progress|completed, the latter with a built-in done/total counter and configurable progressive reveal — the official parts for >10s thinking (research 15 §3.2).

Working ranges: sweep 2s (spread 2 + length adaptation), collapse delay 1000ms, dot-pulse cycle 1.2s; let NN/g’s three limits pick the form — don’t put it to a beauty vote.

When to use 3
  • The status === 'submitted' gap — request sent, token stream not yet started (AI SDK officially pairs Spinner/dots here)
  • Reasoning models' 1–10s thinking span — shimmer label plus an expandable step card (the vercel/chatbot reasoning.tsx pattern)
  • Long tasks beyond 10s — step/counter progress plus a visible Stop button (NN/g's hard third-limit requirement)
When not to use 4
  • Fake progress bars on 2–10s operations — NN/g's display inertia: the screen would change faster than users can track; imprecise feedback (rotating text/pulse) is the right call
  • Collapsing the step card instantly after the stream with no duration readout — reasoning.tsx waits AUTO_CLOSE_DELAY 1000ms and leaves "Thought for N seconds"
  • Encoding "thinking" in animation alone — screen readers get nothing from shimmer/pulse; pair it with aria-busy and a text status line
  • Attaching indicators to sub-second responses — NN/g's 0.1–1s band needs no special feedback; adding one only creates jitter
Accessibility

Mark the thinking region aria-busy="true" and announce thinking/done/duration via an aria-live="polite" status line — the duration readout is the only wait quantifier screen readers can get; drive the step card with a real button + aria-expanded, keeping its content in the DOM or reachable when collapsed; Stop is a real button (focusable, with a pressed state) and must not be hidden in >10s scenarios; shimmer/dots/spinner are pure decoration (aria-hidden) — semantics never ride on animation; under prefers-reduced-motion stop the shimmer and pulse, keeping the static text label.

Browser support

Demo infrastructure: background-clip: text shimmer needs the -webkit- prefix (supported across Chromium/Firefox/Safari; CSS masking is Baseline); dot pulse and spinner are plain CSS animation; step-card expand/collapse is ordinary DOM visibility. No new dependencies.

Fallback

Without background-clip: text the shimmer degrades to a static "Thinking…" label (the information survives); without CSS animation the dots freeze as static dots; step-card collapse is progressive enhancement — failing to collapse only costs space, never semantics.

Sources 7
