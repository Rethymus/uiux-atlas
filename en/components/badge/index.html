Badge

角标 · 徽标 · 通知数 · Notification Badge

A status count attached to the corner of another control: capped at 99+, hidden at zero, degradable to a red dot — every default is converging information density on the user's behalf.

Component Lib ★★★
Live demo official default
Parameters
Geometry▾
count8

JS-type param. The default of 8 is a demo value (antd count has no documented default); antd semantics: count hides at 0 (showZero defaults to false) and shows `${overflowCount}+` past the cap (index.zh-CN.md:47). The demo pins count to two hosts: a button and an avatar.

max99

JS-type param. The default of 99 matches antd overflowCount's documented default of 99 (index.zh-CN.md:51; Badge.tsx:70); past the cap the badge renders `99+`. max is this entry's param name; antd's original is overflowCount (no maxCount exists in 5.x/6.x — the research records that name as unverified).

offset0px
px

CSS-variable param (--bd-offset consumed via translate). antd offset is a two-value [number, number] with no default (index.zh-CN.md:50); the demo simplifies it to a single value applied as extra translation on both x/y axes — the direction semantics follow antd's docs, and this only demonstrates that the offset is tunable.

Motion▾
dotoff

JS-type param (demo subscribes and toggles data-dot). antd dot defaults to false (index.zh-CN.md:49): no number, just a small red dot, for 'new content exists but the amount doesn't matter'; dot mode also hides when count is 0.

Code breakdown

Structure & DOM

A badge has no standalone form — it must parasitize a host (button, icon, avatar, tab): the host is a position: relative anchor and the badge is an absolutely positioned child at the top-right corner, with the count decision made before render.

<button class="host" aria-label="Inbox, 8 unread">
  Inbox
  <span class="badge" aria-hidden="true">8</span>
</button>

Key points:

  • The count decision chain (antd semantics): count === 0 → hide entirely (showZero defaults to false); count > max → render ${max}+; otherwise the raw number;
  • To screen readers the badge is not a standalone control: the count goes into the host’s aria-label and the badge itself is aria-hidden (so it isn’t announced twice);
  • The red dot (dot) is another fill state of the same element: number removed, shrunk to a circle;
  • Never casually set overflow: hidden on the host — it clips the badge protruding past the corner.

Styling & Parameters

offset is CSS-variable driven (--bd-offset feeds translate); count / max / dot are JS-typed (store subscription, with the demo computing the rendered value):

.badge {
  position: absolute; top: 0; right: 0;
  transform: translate(50%, -50%) translate(var(--bd-offset, 0px), var(--bd-offset, 0px));
  min-width: 20px; height: 20px; padding: 0 5px;
  border-radius: 10px; background: #ff4d4f; color: #fff;  /* red = antd colorError seed */
  font-size: 12px; line-height: 20px;
  font-variant-numeric: tabular-nums;
  box-shadow: 0 0 0 2px #fff;   /* white ring: separates the badge from the host fill */
}
[data-dot="on"] .badge { min-width: 0; width: 8px; height: 8px; border-radius: 50%; font-size: 0; }

Where the numbers come from (antd 6.7.1, verified via out/design-study/06-antdesign.md §4.17 plus the local .scratch/antd06 source):

  • overflowCount defaults to 99 and appends + past the cap (index.zh-CN.md:51; Badge.tsx:70 default 99, :112 appending +) — this entry’s param name max maps to it;
  • count hides at 0: showZero defaults to false (index.zh-CN.md:52, :47);
  • dot defaults to false (index.zh-CN.md:49);
  • offset is a two-value [number, number] with no default (index.zh-CN.md:50); the demo simplifies it to one value applied on both x/y axes;
  • The badge red is antd’s colorError seed default #ff4d4f (06-antdesign.md §2.2); the 20px badge height and 8px dot diameter are demo values (the pixel specs of antd’s medium|small badge size tiers aren’t recorded in the research — unverified).

Motion & Interaction

  • A badge may pop on appearance (scale 0.6 → 1, 0.25s = antd motionDurationMid, easeInOut curve) — but only when the count changes, never looping; disabled under prefers-reduced-motion: reduce;
  • The host’s interaction never changes because of the badge: the button still opens the list; the badge is not a click target;
  • Clearing to zero is a content change, not an effect: at count = 0 the badge simply disappears — no “zeroing animation”;
  • The +1 / clear toolbar rewrites count through store.set, and the panel slider follows — a two-way channel over the same store, with every change visible instantly.

Real-world examples

  • WeChat’s bottom-tab unread badges: the “Chats” tab shows the exact unread count while tabs like “Discover” use a red dot for “new content exists but the amount doesn’t matter” — count and dot splitting the work by information value within one nav bar;
  • The Pull requests / Issues counters on GitHub repo pages: a gray counter beside the tab name, keeping “open items” permanently visible at the entry — unlike red unread badges it’s a low-emphasis neutral count, proving badges don’t have to be red warnings;
  • The blue dot on iOS App Store’s “Today” tab: Apple uses a numberless dot for “new content” — when the number carries no action value, the system-level choice is exactly the dot form.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
countbigger, more urgent numbers; past max everything folds into N+, never widening further1 is the smallest valid value; at 0 the badge hides entirely and the host returns to its unbadged state
maxlater capping keeps exact numbers longer (audit/reconciliation scenarios need precision)earlier folding: at max=9, ten renders as 9+ — browsing-first entries prefer small caps for faster scanning
doton = number hidden, only a red dot — “there is”, not “how many”, reducing noiseoff = the full count, when the number itself drives action (like a cart)
offsetthe badge drifts away from the host corner and can collide with neighbors; watch container overflow0 returns the standard straddling corner position; negative values would burrow into the host (this demo clamps ≥ 0)

Working ranges: unread counts cap at 99 (antd default); browsing-first entries may cap at 9; nudge offset 1–4px only to resolve occlusion at the host corner; keep two or three badges per screen, or their attention value dilutes each other.

When to use 3
  • Unread counts on message/notification entries (buttons, tabs, icons), capped at 99+ to converge big numbers
  • Status dots on avatars (online, has updates), degraded to dot when the amount doesn't matter
  • Use count when the number itself informs (cart items, todo count); use dot when only presence matters
When not to use 3
  • Pinning a never-changing number on a corner — a badge signals 'needs attention'; permanent display is noise
  • Saturating many hosts with badges at once — attention value dilutes with count; keep two or three per screen
  • Red dots carrying critical, unrecoverable information — dots have no content or detail; critical info belongs in lists/banners
Accessibility

To screen readers a badge is not a standalone control but part of the host's accessible name: add aria-label on the host ('Inbox, 8 unread') or wrap with antd Badge semantics; when count is 0 the badge hides visually and readers shouldn't announce '0' either; red dots must pair with host text state (never color-only, SC 1.4.1); the #ff4d4f fill against white digits is roughly 3.9:1 — fine for large bold digits at WCAG's 3:1 large-text bar, but darken the fill for small digits.

Browser support

This entry uses only div + CSS (absolute positioning, translate, border-radius, min-width pill) — baseline in every browser, nothing to feature-detect. The real guard is clipping at the host corner (a host with overflow: hidden will cut the badge off).

Fallback

If the host clips the badge, give the host padding or switch the badge to inset positioning; a purely visual badge must travel with visible text or an aria-label carrying the count, or the number lives only in the visual layer; a red dot must never be the sole carrier of key information (color is not the only indicator, WCAG 2.1 SC 1.4.1).
