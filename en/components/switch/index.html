Switch

切换开关 · Toggle · Toggle Switch

An instant two-state toggle: the thumb slides across the track to express on/off — the change takes effect immediately, no submit button needed.

Component Lib ★★★
Live demo official default
Parameters

sizemd

JS-type param (demo subscribes and toggles data-size). Aligns with antd Switch size: medium|small defaulting to **medium** (v5 was default|small defaulting to default, design study 06 §4.7/§5.1); the demo's track/thumb pixel values are drawn for illustration and are not official track dimensions (not documented in the research).

loadingoff

JS-type param (demo subscribes and toggles data-loading). Aligns with antd Switch loading, default false (06 §4.7); while loading the thumb shows a spinner and interaction is suppressed — the semantics of 'change accepted, taking effect'.

disabledoff

JS-type param (demo subscribes and toggles data-disabled). Aligns with antd Switch disabled, default false (06 §4.7); disabled means no permission or an unmet parent condition — visually dimmed and unresponsive to keyboard.

checkedoff

JS-type param (demo subscribes to drive aria-checked; clicking the switch writes back to this param — two-way). Aligns with antd Switch checked/defaultChecked, default **false** (06 §4.7); this IS the switch state — the panel and the demo switch share one value.

Code breakdown

Structure & DOM

A switch is a “constant label + thumb” structure; the thumb itself is a native button carrying role="switch":

<label class="switch-row" id="mail-label">Receive product update emails</label>
<button type="button" role="switch" aria-checked="true" aria-labelledby="mail-label">
  <span class="thumb">
    <span class="glyph" aria-hidden="true">ON</span>
  </span>
</button>

Key points:

  • The accessible name is constant: the external label supplies the name via aria-labelledby, and the ON/OFF glyphs inside the thumb are aria-hidden — if the name changed with the state, what a screen reader announces at focus would desync (APG iron rule, research 07 §6);
  • aria-checked is the sole state carrier (“true”/“false”) — no mixing with pressed/checked;
  • The thumb slide is written as transform only, transitioning on the compositor with no reflow;
  • loading/disabled add aria-disabled="true" so screen readers know why Space does nothing.

Styling & Parameters

All four parameters are JS-typed (store-subscribed data-* and aria-checked switches); the CSS branches on data-size / data-loading / data-disabled:

.switch-btn {
  position: relative;
  display: inline-flex;
  align-items: center;
  border: 0;
  border-radius: 999px;
  background: rgba(0, 0, 0, 0.25);
  cursor: pointer;
  transition: background 0.2s cubic-bezier(0.645, 0.045, 0.355, 1);
}
.switch-btn[aria-checked="true"] { background: #1677ff; }   /* colorPrimary */
.switch-btn .thumb {
  position: absolute;
  left: 2px;
  border-radius: 50%;
  background: #fff;
  translate: 0 0;
  transition: translate 0.2s cubic-bezier(0.645, 0.045, 0.355, 1);
}
.switch-btn[aria-checked="true"] .thumb { translate: var(--thumb-travel) 0; }
.switch-btn[data-loading="on"] .thumb::after {              /* spinner */
  content: "";
  position: absolute;
  inset: 3px;
  border: 2px solid rgba(0, 0, 0, 0.25);
  border-top-color: transparent;
  border-radius: 50%;
  animation: sw-spin 0.6s linear infinite;
}
.switch-btn[data-disabled="on"] { opacity: 0.45; cursor: not-allowed; }
@keyframes sw-spin { to { rotate: 360deg; } }
@media (prefers-reduced-motion: reduce) {
  .switch-btn, .switch-btn .thumb { transition: none; }
  .switch-btn[data-loading="on"] .thumb::after { animation: none; }
}

Where the numbers come from:

  • size aligns with antd v6 medium|small defaulting to medium (v5 was default|small, design study 06 §4.7/§5.1); the demo’s track pixel values are drawn for illustration — the research holds no official track dimensions, so no official claim is made;
  • checked/loading/disabled defaults align item-by-item with the antd 6.7.1 doc audit (06 §4.7): false/false/false;
  • On-track color #1677ff = antd colorPrimary (06 §2.2); the 0.2s transition = motionDurationMid (06 §3.1); easing = motionEaseInOut;
  • Off-track gray rgba(0,0,0,0.25) is a demo illustration (semantically aligned with the neutral 25% alpha tier, 06 §2.3⑤ — not an official track token).

Motion & Interaction

  • Thumb slide: 0.2s cubic-bezier(0.645, 0.045, 0.355, 1) (antd motionDurationMid + motionEaseInOut); only translate (transform) animates;
  • Keyboard: Space toggles (native button behavior, Enter optional) — no custom keyboard code; leave predictability to the platform (APG, research 07 §6);
  • loading: a 0.6s linear spinner inside the thumb with interaction suppressed but the state not rolled back — it expresses “accepted, taking effect”; under prefers-reduced-motion the spinner freezes into a ring;
  • disabled: the whole key dims, cursor becomes not-allowed, Space does nothing; it stays reachable in Tab order semantics via aria-disabled (a disabled button is unfocusable, so the aria state carries the meaning).

Real-world examples

  • iOS Settings (UISwitch): nearly every row in system settings is “copy + thumb on the right”, green when on and gray when off, with the whole row acting as the hit area — the most ubiquitous switch form on mobile;
  • WeChat chat settings: “Mute notifications” and “Pin to top” in chat details are instant-effect thumbs with no confirmation dialog — the canonical carrier of the instant-effect mental model;
  • Android M3 Switch: the selected thumb carries a check icon, the track widens with state, and the thumb scales on press — Material’s more emphatic take on the same semantics.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
sizemd gives a larger hit area — better for touch and primary settings rowssm fits compact lists/toolbars, but the smaller thumb raises mis-tap rate
loadingon locks interaction and absorbs rapid re-clicks — right for genuinely async saves; if the backend is unreliable users get stuck in “forever taking effect”off returns to instant toggling; loading should only exist for real async waits, never as decoration
disabledon clearly says “not touchable”, cutting dead clicks; a fully disabled group needs a reason (parent condition / no permission)off restores interactivity; a permanently disabled setting should be removed from the UI rather than gray forever
checkedon turns the track primary and slides the thumb — a strong instant-feedback signal; many switches on at once flood the screen with primary coloroff returns to the gray track; defaulting everything to on dilutes the scarcity and discoverability of “enabled”

Working ranges: no more than 6–8 switches per screen; default conservatively — most settings start off, leaving “enable” as an explicit user decision; every loading state needs a timeout fallback, never spin forever.

When to use 3
  • Instant-effect settings: notifications, do-not-disturb, dark mode — change lands immediately, no save step
  • Feature-flag panels: a group of switches named via fieldset/legend or role=group (research 07 §6)
  • Strictly binary config: only on/off, no 'partially selected' semantics needed
When not to use 4
  • Form fields that only take effect after submit — use a checkbox with a save button; switches promise instant effect
  • Labels that flip with the state (the label itself toggling on/off) — APG iron rule: the announced name at focus must stay constant (research 07 §6)
  • Needing a third state (all/partial) — switch is strictly binary; partial belongs to checkbox's indeterminate (research 07 §6)
  • Screens packed with switches — sliders cost more to scan than a checklist; prefer a checkbox group for bulk settings
Accessibility

button (role="switch") + aria-checked expresses state; **the accessible name must stay constant** — the demo uses the external label copy as the name and hides the on/off glyphs inside the thumb with aria-hidden (otherwise name and announcement desync on state change, research 07 §6); Space toggles (Enter optional); loading/disabled set aria-disabled; groups use fieldset/legend or role=group + aria-labelledby (research 07 §6).

Browser support

button + role="switch" + aria-checked works in all mainstream browsers; the thumb slides via transform (compositor-friendly). Screen-reader announcement of the switch role ('on/off' state) is mature across ATs; the loading indicator is pure CSS rotation with no JS animation API dependency.

Fallback

Without JS, or when AT lacks role="switch" support, fall back to a native <input type="checkbox"> (checkbox mode); APG advises choosing by semantics — 'lights switch on' reads better as a switch, while checklist flows read better as checkboxes (research 07 §6).

Sources 2

OriginAPG defines switch as an on/off-only control: Space toggles, aria-checked expresses state, and the label must never change with the state (research 07 §6); checkbox and toggle button are the ones allowed a third/half state. The production reference is Ant Design Switch (checked against antd 6.7.1: checked defaults false, size defaults medium (renamed from v5's default), loading false, disabled false — design study 06 §4.7).
