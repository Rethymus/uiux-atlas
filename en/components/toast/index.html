Toast

轻提示 · Snackbar · Message · 全局轻提示

Lightweight non-blocking feedback: fixed positioning over the page, auto-dismiss on a timer, announced via role=alert — for non-critical messages only.

ms

How long one toast stays before the whole block is removed (antd's no-queue-exit principle). Default 3000ms matches AntD message.duration default 3 (seconds; 0 = never auto-close); MUI warns autoHideDuration must leave enough reading time — disappearing too fast violates WCAG 2.2.3 (WAI-APG Alert). JS-type param; the demo subscribes and drives the timer.

maxCount3

Max simultaneous toasts; the oldest is removed once exceeded. AntD message.config.maxCount defaults to unlimited (-); this demo narrows the range to 1–5, and the default 3 is a demo value, not any library's official default (3-as-default is unverified in research).

stiffness100

Stiffness k of the entrance spring (semi-implicit Euler integration, m=1): larger ω₀=√(k/m) starts harder and arrives sooner, with the overshoot ratio unchanged (at fixed ζ). Default 100 = the Motion engine's spring.ts source default stiffness=100 (research 10 §6.3, source verified verbatim; the motion.dev docs page says 1 — the source wins). Reference presets (research 10 §2.3, locally computed): 700/40 ≈ quick-steady (2.7% overshoot), 300/25 ≈ micro-bounce (3.8%), 200/15 ≈ slow-bouncy (14.0%).

damping10

Damping coefficient c of the entrance spring: ζ=c/(2√(km)) sets the overshoot — the default 10 with stiffness 100 gives ζ=0.5 and a first overshoot of ≈16.3% (research 10 §6.3 Motion source default + §4.3 computation); ζ≈1 is the fastest overshoot-free critical damping (e.g. 100/20), ζ>1 turns sticky (the community-circulated 500/50 is actually an overdamped ζ≈1.12 counter-example, research 10 §2.3). c=0 never settles (Motion docs warning), so the floor is 1.

Code breakdown

Structure & DOM

A toast is a floating stack above page content: a fixed (or stage-relative) container positioned at the anchor spot, with each toast as a small card inside it — appearing and leaving without touching the document flow.

<div class="toast-stack" data-placement="top-center">
  <div class="toast" role="alert">
    <span class="toast-icon" aria-hidden="true"></span>
    Saved to drafts
  </div>
</div>

Key points:

  • Each toast carries role="alert", so most screen readers auto-announce it on DOM insertion (WAI-APG Alert); a toast must never steal keyboard focus — if you need to interrupt, use an alertdialog instead;
  • The container gets pointer-events: none while cards restore auto, so the floating layer never blocks the page underneath;
  • MUI separates Snackbar (= toast) from Alert (in-flow) and Dialog (blocking): toasts carry non-critical messages only.

Styling & Parameters

All five parameters are JS-type (the demo subscribes to the store): duration drives the timer, placement switches the container’s 6-way alignment, maxCount trims the oldest entries, and stiffness/damping drive the entrance spring (see “Motion & Interaction”). Visually they map to:

.toast-stack {
  position: fixed;            /* or absolute within a stage */
  inset: 0;
  padding: 14px;              /* AntD message.config.top defaults to 8 (viewport) */
  display: flex;
  flex-direction: column;
  gap: 10px;
  pointer-events: none;
  z-index: 1010;              /* AntD message sits above Modal (1000) */
}
.toast-stack[data-placement="top-center"] { align-items: center; justify-content: flex-start; }
.toast {
  background: #fff;
  border: 1px solid #f0f0f0;  /* antd colorBorderSecondary */
  border-radius: 8px;         /* antd borderRadiusLG */
  box-shadow: 0 1px 2px 0 rgba(0,0,0,.05), 0 1px 6px -1px rgba(0,0,0,.03), 0 2px 4px 0 rgba(0,0,0,.03);
}

Where the numbers come from (all checked against antd 6.7.1): functional colors success #52c41a / warning #faad14 / error #ff4d4f / info #1677ff (seed tokens); 3s auto-dismiss default, unlimited maxCount, pauseOnHover true (AntD message docs). The 6-way model comes from MUI Snackbar’s anchorOrigin (vertical top/bottom × horizontal left/center/right). The spring defaults stiffness 100 / damping 10 are the Motion engine’s spring.ts source defaults (research 10 §6.3, source verified verbatim; the docs page’s stiffness default of 1 disagrees with the source — the source wins); the entrance overlay curve cubic-bezier(.21,1.02,.73,1) and the “slide in from 200% of its own height” start come from react-hot-toast’s source (research 10 §5.1).

Motion & Interaction

  • Entrance (spring, panel-tunable): a new toast slides in from −200%/+200% of its own height on a physics spring — semi-implicit Euler integration (m=1, per-step dt capped at 1/30, restDelta 0.002 matching Motion’s granular threshold), writing el.style.transform per frame; stiffness/damping are panel-tunable with defaults 100/10 (ζ=0.5, first overshoot ≈16.3%); retuning mid-flight continues from the current position and velocity (velocity handoff — interruptible, never restarts from zero). The card layer additionally carries react-hot-toast’s scale/fade: 0.35s cubic-bezier(.21,1.02,.73,1), scale 0.6→1, opacity 0.5→1;
  • No exit queue: when the timer fires the whole block disappears at once — no per-item exit animation, per AntD’s “exits are faster than entrances” principle; hitting maxCount likewise drops the oldest immediately. Library contrast: react-hot-toast exits with a 0.4s cubic-bezier(.06,.71,.55,1) pure ease-out, and sonner uses a 400ms transition + 4s lifetime (research 10 §5.1) — this demo keeps AntD’s whole-block dismissal;
  • Esc to close: MUI’s accessibility requirement for Snackbar; the demo listens for keydown while toasts exist and clears on Esc;
  • Pause on hover (pauseOnHover, AntD default true) and a manual close button are optional enhancements;
  • Under prefers-reduced-motion: reduce, both the spring and the scale/fade are disabled and the toast simply appears (MDN: large translation animations discomfort vestibular users);
  • Spring deep-dive: the full stiffness/damping/mass ↔ ζ feel breakdown (ζ↔overshoot conversion, preset table, interruptible velocity handoff) lives in the motion entry Toast spring.

Real-world examples

  • Gmail: after sending, a dark toast appears bottom-left saying the mail was sent, with an Undo action button — the canonical “toast with action” pattern; once the undo window lapses the mail truly goes out;
  • Google Docs: while editing, a bottom-left status line continuously reads “All changes saved in Drive”, surfacing async save results without interrupting writing;
  • GitHub: saving a repository settings page raises an auto-dismissing confirmation toast at the bottom; GitHub’s (Primer) Toast component is fixed to the viewport bottom and disappears after a few seconds.

Working ranges: duration 2–5s (default 3s matching AntD), maxCount 1–3, one placement per product (antd-family top-center, MUI-family bottom); spring presets — micro-bounce 300/25 (3.8% overshoot), Motion default 100/10 (16.3%), quick-steady 700/40 (2.7%), and always compute ζ=c/(2√(km)) before copying numbers (research 10 §2.3 computed table + craft 3). Critical information never rides a toast — use a persistent banner or an alertdialog.

When to use 3
  • Non-critical process feedback like 'saved' or 'copied' (non-blocking)
  • Light feedback with an undo action (Gmail-style 'Sent + Undo')
  • Batch result summaries ('12 items archived')
When not to use 4
  • Critical, must-act messages — use Dialog (alertdialog) or a persistent banner (APG: too-fast auto-dismiss violates WCAG 2.2.3)
  • Form validation errors — keep errors persistent next to the field (NN/g: no floating-layer-only errors)
  • Long progress (>10s) — use a progress bar with an interrupt path (NN/g response-time limits)
  • Stacking floods — MUI explicitly discourages stacking multiple Snackbars
Accessibility

Give each toast a role=alert container — dynamic insertion is auto-announced by most screen readers (WAI-APG Alert); never steal keyboard focus, use alertdialog when you must interrupt; Esc must dismiss (MUI Snackbar a11y requirement); auto-dismiss only for non-critical info — too fast violates WCAG 2.2.3, frequent interruptions violate 2.2.4 (APG Alert).

Browser support

Implementation only needs CSS fixed positioning + transform/opacity transitions and JS timers/events, all Baseline; prefers-reduced-motion is supported across browsers since 2020-01 (research 07 §37).

Fallback

Without transform transitions the toast simply appears/disappears with no motion — the message itself is unaffected; with JS disabled toasts cannot fire, so critical information must also live in persistent in-page UI, never in a toast alone.

Sources 6

OriginFused from two first-hand paradigms: Ant Design message (top-center, 3s auto-dismiss default, non-blocking) and MUI Snackbar (non-critical only, role=alert content container); the 'never auto-dismiss critical info' rule comes from the WAI-APG Alert pattern citing WCAG 2.2.3 (research 07 §8/§9).
