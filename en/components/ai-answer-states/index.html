AI Answer States

回答安全态 · Answer States · 拒答卡片 · 引用来源 · Refusal & Citations

Three non-normal answer states: the refusal card (display, don't parse), generic error text + retry, and structured citations (source cards/badges/footnotes) — nothing leaks on failure, every citation traces to a passage.

Code breakdown

Structure & DOM

Answer safety states are “three cards for non-normal answers”: a refusal card (a card in the normal message position, not an exception branch) → an error card (generic text + retry) → the citation layer (source card / badges / footnotes). All three share one discipline: nothing leaks, an exit always exists.

<article class="msg" role="status">          <!-- refusal card: a normal-200 message position -->
  <span class="badge">refusal · cyber</span> <!-- stop_details category badge -->
  <p>Sorry, I can't help with that request.</p> <!-- explanation verbatim, never parsed -->
  <div class="partial" data-incomplete>Streamed partial output (dimmed, marked incomplete)</div>
  <button class="retry">Retry</button>
</article>

<details class="sources">                    <!-- citation layer: the collapsed sources card -->
  <summary>Used 2 sources</summary>
  <ul><li><a href="…">Doc title — example.com</a></li></ul>
</details>

Key points:

  • A refusal is a normal 200 response, not an error — Anthropic returns stop_reason: “refusal” plus stop_details with five categories (cyber / bio / frontier_llm / reasoning_extraction / general_harms); OpenAI carries refusal in the assistant message’s refusal: string|null field — both point to “render the card in the normal message position”;
  • The explanation is displayed, not parsed — the docs’ own words: display it rather than parse it; the text is unstable and any parsing branch will break;
  • A mid-stream refusal discards partial output — the docs are explicit that existing partial output is incomplete and should be discarded; the demo dims the streamed text and marks it;
  • Citations ride on structured data — Anthropic’s citations array (cited_text quoting the exact supporting passage, not counted as output tokens) and OpenAI’s url_citation annotations (url/title/start_index/end_index) are the official recommendation; markdown-inline citations are the officially warned-against unsupported route;
  • The hookup with AI Streaming Response: when a safety state interrupts the stream, the streaming state machine drops from streaming straight to the refusal/error terminal state; the relation to the status color system: refusal/error cards take their semantic color from the status layer, never inventing a new red.

Styling & Parameters

Six parameters map to three kinds of declarations: citation form (mode + carousel), the refusal exit (retry + mid-stream policy), and the safety gates (link modal + disclaimer position):

/* Refusal card: normal message position + category badge (semantic color from the status system) */
.refusal-card {
  border: 1px solid var(--border);
  border-left: 3px solid var(--status-warn, var(--accent));
  border-radius: 12px;
  background: var(--bg-elev);
  padding: 12px 16px;
}
.refusal-badge {
  font-family: var(--font-mono, ui-monospace, monospace);
  font-size: 11px;
  padding: 2px 8px;
  border-radius: 999px;
  background: color-mix(in srgb, var(--accent) 12%, transparent);
  color: var(--text-1);
}
/* Mid-stream partial output: dimmed + marked incomplete (officially incomplete, to be discarded) */
.partial[data-incomplete="true"] {
  opacity: 0.45;
  text-decoration: line-through solid color-mix(in srgb, var(--text-1) 35%, transparent) 1px;
}
/* Sources card: the trigger count = the number of source-url parts (AI Elements Sources isomorphic) */
.sources summary { cursor: pointer; font-size: 12.5px; color: var(--text-dim, var(--text-1)); }
.sources summary:hover { color: var(--accent); }
.sources a { color: var(--accent); text-underline-offset: 2px; }

Where the numbers come from (all official first-hand, research 15 §6):

  • Refusal categories: five — cyber / bio / frontier_llm / reasoning_extraction / general_harms (Anthropic’s stop_details);
  • Partial output: “treated as incomplete and discarded” (Anthropic’s own wording);
  • Generic error text: Something-went-wrong class (AI SDK’s official suggestion) + the regenerate() retry;
  • Citation chunking: automatic sentence-level chunking, cited_text not counted as output tokens; incompatible with structured outputs (JSON mode 400s) — citations must interleave with text;
  • The four link-safety gates: allowedImagePrefixes / allowedLinkPrefixes / allowedProtocols / allowDataImages (rehype-harden); out-of-bounds links rewrite to [blocked];
  • Disclaimer placement: officially unspecified (unverified); common practice is a message footer or below the sources card.

Motion & Interaction

  • Three-state switching: the demo’s scenario picker (normal / refusal / error) swaps the cards; the refusal tier first streams out half an answer, and when the refusal signal lands the midStreamRefusalPolicy decides — discard-partial dims and marks the partial incomplete, keep-partial keeps it verbatim (the anti-pattern);
  • The retry exit: three refusalRetry tiers — regenerate restarts generation (generic), fallback goes to a backup model (Anthropic’s official mechanism), none is the dead end (the anti-pattern);
  • Citation forms: three citationMode tiers — the collapsed sources card (count = number of sources), the inline-hover badge with hover card (supporting carouselEnabled multi-source carousels, prev/next + a “1/5” index), and the footnote list;
  • The link-safety gate: AI-generated outbound links show the full URL before navigation under linkSafetyModal: on (rehype-harden semantics); the off tier navigates directly (the risk demo);
  • Disclaimer position: disclaimerPosition — message footer / below the sources card / none (unverified; a practice suggestion).

Real-world examples

  • Anthropic Refusals docs: stop_reason: “refusal” + stop_details.category/explanation/recommended_model; “display it rather than parse it”; mid-stream refusals discard partial output; server/client fallback retries are configurable — the complete official blueprint for the refusal card (research 15 §6.1);
  • OpenAI API reference: the assistant message’s refusal: string|null field — refusal transported as a message field, not an exception; annotations[].type === “url_citation” with url/title/start_index/end_index (research 15 §6.1/§6.2);
  • Anthropic Citations API: cited_text quoting exact passages, not counted as output tokens, automatic sentence-level chunking, three locators (char/page/content_block); “significantly more likely to cite the most relevant passages” and “guaranteed to cite from provided documents” (research 15 §6.2);
  • AI SDK Error State: generic error text + a regenerate() retry is the official suggestion — the first-hand wording for the error card (research 15 §6.1);
  • AI Elements Sources / InlineCitation: the collapsed “Used 3 sources” trigger and the hover source card (carousel prev/next + “1/5”), plus the official warning that inline citations are unsupported and structured rendering is the recommended route (research 15 §6.2);
  • Streamdown’s security layer: rehype-sanitize (the GitHub sanitization schema) + rehype-harden’s four gates; the site confirms the pre-navigation modal showing the full URL; a production configuration example against prompt injection (tight prefixes for AI content, looser for user content) (research 15 §6.2).

Working ranges: the refusal card = badge + verbatim text + an exit; the error state = generic text + regenerate; citations = structured-data driven with the sources card as the floor; links = four gates + the full URL before navigation.

When to use 3
  • Classifier refusals (the safety boundary) — carding a normal-200 response with a refusal stop_reason (Anthropic's official form)
  • Answers with cited sources — structured rendering of citations arrays / url_citation annotations (the official two-vendor spec)
  • Generation failures/timeouts — generic error text + retry (the official anti-leak best practice)
When not to use 4
  • Parsing the refusal explanation for branching logic — the docs are explicit: display it, don't parse it; the text is unstable
  • Keeping streamed partial output after a mid-stream refusal — the docs say discard it; the partial may be exactly what was refused
  • Surfacing raw server exception text to users — generic text + retry is the official line; leaking stack traces hands attackers a map
  • Doing citations with inline markdown syntax — officially warned against: no good syntax, models don't emit it; structured citations-array rendering is the official recommendation
Accessibility

Announce refusal/error cards via role="status" or aria-live="polite" (never interrupting screen readers); retry buttons are real buttons (focusable, pressed states) and focus never lands on the disabled partial output; the sources card folds with native details/summary semantics (keyboard reachable), and hover badges also expand on focus with the full URL in the safety hint; dimmed partial output stays in the DOM, marked incomplete; citation badges never ride on color alone (they carry numbers); prefers-reduced-motion is not implicated (no decorative animation).

Browser support

Demo infrastructure: native details/summary for the sources card; CSS color-mix for the dimmed partial output (Baseline 2023); the safety modal is a static in-demo reveal (no dialog element dependency). No new dependencies.

Fallback

Without details/summary the sources card degrades to an always-open list; without hover cards badges fall back to title hints; without modals the full URL is shown inline beneath the link (nothing is lost); without color-mix the partial output dims via opacity.

Sources 8

OriginRefusal's official two-vendor spec: an Anthropic classifier refusal returns a normal 200 response — stop_reason: "refusal" plus stop_details with five categories (cyber / bio / frontier_llm / reasoning_extraction / general_harms); the docs are explicit that the explanation text is unstable and should be "displayed rather than parsed", and a mid-stream refusal marks existing partial output as incomplete and should be discarded; OpenAI transports refusal as an assistant-message field (refusal: string|null), not an exception. Citations' official two-vendor spec: Anthropic's Citations API carries a citations array with cited_text quoting the exact supporting passage (not counted as output tokens, auto sentence-level chunking, incompatible with structured outputs); OpenAI's annotations[].type === "url_citation" carries url/title/start_index/end_index character ranges. The error state's official best practice: AI SDK suggests generic text (like Something went wrong) to prevent leakage plus a regenerate() retry. Streamdown's official warning: inline citations have no official support (no good markdown syntax, models don't emit citation syntax unprompted, no AI SDK built-in) — structured, citations-array-driven rendering is the officially recommended path (research 15 §6).
