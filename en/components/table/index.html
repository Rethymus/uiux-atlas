Table

数据表格 · Data Table · DataGrid

A row-column matrix for structured data: headers carry column semantics, rows carry records. Sorting, striping and row hover are scanning aids, not decoration.

Code breakdown

Structure & DOM

A table is a strict semantic tree in a fixed order: table wraps thead + tbody, each column gets one th (with scope="col") inside thead, and each tbody row is a tr of td cells.

<table>
  <thead>
    <tr><th scope="col">Name</th><th scope="col" aria-sort="ascending">Price</th></tr>
  </thead>
  <tbody>
    <tr><td>Spruce lamp</td><td>129</td></tr>
  </tbody>
</table>

Key points:

  • Real table semantics, not div soup: screen readers announce a table as a table, and the WAI-APG Table pattern is the first reference for custom implementations (research 07 §34);
  • Sortable headers are buttons; the sort direction is expressed with aria-sort="ascending / descending", and the attribute is absent when unsorted;
  • Row count is a function of the data — at zero rows the empty state replaces the whole table (no leftover header or frame) so screen readers don’t announce a full table before “no content” (Carbon, research 07 §17); same rule as the empty entry.

Styling & Parameters

All four parameters are JS-typed (the demo subscribes to the store and toggles data-* attributes); density tiers follow antd Table’s cell-padding tokens:

/* Three density tiers: antd cellPadding large 16 / medium 12·8 / small 8
   (table/style/index.ts:457-462; padding 16, paddingSM 12, paddingXS 8) */
.tb-table[data-size="lg"] th, .tb-table[data-size="lg"] td { padding: 16px; }
.tb-table[data-size="md"] th, .tb-table[data-size="md"] td { padding: 12px 8px; }
.tb-table[data-size="sm"] th, .tb-table[data-size="sm"] td { padding: 8px; }

/* bordered (antd default false): outer frame colorBorder #d9d9d9, column lines colorBorderSecondary #f0f0f0 */
.tb-table[data-bordered="on"] { border: 1px solid #d9d9d9; }
.tb-table[data-bordered="on"] td:not(:last-child) { border-right: 1px solid #f0f0f0; }

/* Striping (antd has no such prop; the off default follows TDesign stripe @default false);
   stripe 2% / hover 4% take antd's neutral fill alpha tiers (FillQuaternary/Tertiary) */
.tb-table[data-striped="on"] tbody tr:nth-child(even) { background: rgba(0,0,0,0.02); }
.tb-table tbody tr:hover { background: rgba(0,0,0,0.04); }

/* Numeric columns: right-aligned + tabular figures (antd recommends tabular-nums, 06-antdesign.md §1.3) */
.tb-num { text-align: right; font-variant-numeric: tabular-nums; }

Where the numbers come from:

  • size defaults to large and bordered to false, both verified against the antd 6.7.1 doc sources (out/design-study/06-antdesign.md §4.15; re-checked locally in .scratch/antd06, index.zh-CN.md:129 and :148);
  • Striping: antd 6.7.1 has no striped prop; the off default follows TDesign Table stripe’s documented @default false;
  • Always-on row hover is an explicit Carbon requirement (“row hover state should always be enabled to aid scanning”, research 07 §13); hover does not depend on the stripe parameter.

Motion & Interaction

  • Row hover: a 0.2s background transition (antd motionDurationMid) on the cubic-bezier(0.645,0.045,0.355,1) curve (motionEaseInOut); hover changes the fill only — no shifts, no per-row outlines;
  • Sort click: asc → desc → clear, a three-state cycle, with the header’s aria-sort kept in sync; antd sortDirections defaults to ['ascend','descend'] (6.7.1);
  • Entrance: the table fades in with an 8px rise, animating only opacity/translate; both the entrance and the hover transition are disabled under prefers-reduced-motion: reduce;
  • Empty-state switch: setting rowCount to 0 replaces the table with an empty-state block carrying role="status" for screen-reader announcement; its “create record” is the single primary action (avoiding multiple primary buttons when several empty states coexist — Carbon, research 07 §17).

Real-world examples

  • GitHub repository file list: a three-column table (name / latest commit message / time) with highlighted row hover to aid scanning and icon prefixes distinguishing folders from files — the canonical form of a table for scanning structured records;
  • The API doc tables on ant.design component pages: a four-column “parameter / description / type / default” layout — exactly the kind of table this repo’s research (out/design-study/06-antdesign.md) reads row by row; long types wrap without overflowing the column;
  • Stripe Dashboard payments list: one payment per row with colored status badges and right-aligned amounts — right-aligned tabular figures are the standard for financial tables so vertical comparison doesn’t jitter.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
size (sm→lg)looser density and taller rows — better readability but fewer rows per screentighter density and more rows per screen; at sm (8px) the breathing room is gone — only for short-field tables
borderedouter frame + column lines make column boundaries crisp, good for wide multi-column data; too many borders start to read like a formrow separators only — lighter and more content-like; with many columns the column boundaries drift and are hard to align
stripedtinted even rows keep horizontal scanning from slipping lines, good for dense tables with small row heightsback to plain white with hover-only row targeting; on airy rows stripes start to look dirty
rowCountmore rows lengthen the page; past one screen, add pagination or virtual scrollingfewer rows; at 0 the empty state replaces the whole table (no header left), same rule as the empty entry

Working ranges: admin data tables use md density with always-on hover; narrow containers get horizontal scrolling instead of squeezed columns; never use tables as spreadsheet replacements and never nest tables (Carbon, research 07 §13).

When to use 4
  • Scanning and comparing structured records (orders, inventory, logs) with right-aligned numeric columns in tabular figures
  • Sortable data lists — antd sortDirections defaults to ['ascend','descend'] (6.7.1)
  • Primary data area of admin consoles: always-on row hover to aid scanning (Carbon, research 07 §13)
  • Empty-data scenes guided by an empty state (same rule as the empty entry, research 07 §17)
When not to use 3
  • Using tables as spreadsheet replacements or nesting tables (explicitly rejected by Carbon, research 07 §13)
  • Pure layout alignment (form label grids) — a semantic table is announced as a table by screen readers; use CSS grid for layout
  • Too many columns with no grouping or collapse — offer column settings or summaries instead of endless horizontal scrolling
Accessibility

Semantics: table > thead/tbody > tr > th (scope='col')/td; sortable headers express ascending/descending via aria-sort, changing only after a click; row hover is always on but hover is never the only channel (all data stays readable in the DOM); empty states use role='status' to be announced; borders and hover fills keep 3:1 non-text contrast (WCAG 2.1 SC 1.4.11); numeric columns use font-variant-numeric: tabular-nums (antd's recommendation, 06-antdesign.md §1.3) so vertical comparison doesn't jitter.

Browser support

table/th/td, scope, aria-sort, :nth-child and CSS variables are all baseline web capabilities with nothing to feature-detect; the real compatibility work is overflow strategy in narrow containers (table-layout and horizontal scrolling), not rendering support.

Fallback

The table itself has no visual feature to degrade; degrade content instead: give narrow containers a horizontal scroller rather than squeezing columns, fall back to static headers when sorting can't be implemented (don't render clickable headers that do nothing), and replace the whole table with an empty state for empty data.

Sources 4

OriginSpec aligned with Ant Design Table (antd 6.7.1: size defaults to large, bordered to false); data-table principles (sorting, always-on row hover, no nested tables) from IBM Carbon Data Table usage (research 07 §13); interaction and ARIA semantics from the WAI-APG Table pattern (research 07 §34).
