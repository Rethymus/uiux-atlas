M3 Duration Tokens

时长分档 · duration tokens · md.sys.motion.duration

Material 3's four duration tiers with 16 tokens: short 50–200ms (small utilities), medium 250–400ms, long 450–600ms, extra-long 700–1000ms; pick by transition coverage, and anything past 600ms is for ambient transitions without user input only.

Code breakdown

Structure & DOM

Duration tokens are not a DOM structure but a tier-selection table: first classify the transition (how much area it covers, entering or exiting, user-initiated or not), then pick a token from the four official tiers. The DOM itself only needs an element to host the transition:

<!-- Selection-control transition: short4 = 200ms -->
<button class="chip" style="--md-duration: 200ms">…</button>

<!-- Container transitions: FAB→Sheet = medium4 400ms; Card→fullscreen = long2 500ms -->
<div class="sheet" style="--md-duration: 400ms">…</div>

Key points:

  • Official token names are md.sys.motion.duration.{tier}{n}, four tiers with four steps each: short1–4, medium1–4, long1–4, extra-long1–4;
  • Tiers are semantic, not a continuous scale: selection controls belong to short (official example 200ms + Standard), FAB→Sheet to medium (400ms), Card→fullscreen to long (500ms + Emphasized);
  • The demo replays a sample card at the selected token so switching tiers in the panel compares feel directly.

Styling & Parameters

Both enum params (tier / step) are JS-type; the demo subscribes, converts to ms, and injects the animation duration. The easing stays Standard cubic-bezier(0.2, 0, 0, 1):

.sample {
  animation: enter var(--md-duration, 200ms) cubic-bezier(0.2, 0, 0, 1) both;
}
@keyframes enter {
  from { opacity: 0.25; transform: translateY(14px) scale(0.97); }
  to   { opacity: 1; transform: none; }
}

Motion & Interaction

  • Retier replays: any tier/step change remounts the sample card so the animation replays at the new duration — same easing, only duration moves, making “unhurried vs sluggish” directly comparable;
  • >600ms warning: selecting the extra-long tier surfaces the official note that it serves ambient, input-free transitions only;
  • Enter/exit asymmetry: exits should take the same tier or lower (official example: 200ms), handing attention to the next task;
  • Performance: animate only opacity/transform (web.dev baseline, research 04 §1.5);
  • reduced-motion: under reduce the final state renders directly instead of playing displacement transitions; tiers still serve opacity-only micro-motions.

For pairing tiers with curves see the easing-pairs entry (the official table binds them into six pairs); for a small-control selection example see press-feedback.

Real-world examples

  • Selection controls (official M3 example): switches, checkboxes and radios uniformly take short4 200ms + Standard easing — the official note on the tokens page and the de-facto baseline for small state changes;
  • FAB→Sheet (official M3 example): the FAB-to-Sheet container transition takes medium4 400ms, and Card→fullscreen takes long2 500ms + Emphasized — the official demonstrations of “tier by coverage”;
  • Enter/exit asymmetry (official guidance): the enter 500ms / exit 200ms example ratio comes from M3 guidance, and Android/iOS system transitions consistently exit faster than they enter (see page-transitions).

Parameter Sensitivity

ParameterTurning it up…Turning it down…
tierlarger-area transitions spread out more leisurely; extra-long (700–1000ms) may only serve ambient transitions — on user input it reads as sluggishsnappier transitions; short (50–200ms) fits small controls, but large-area transitions will feel abrupt
stepslower within the tier, blurring toward the next tier (short4 200ms already feels close to medium’s 250ms floor)faster within the tier, approaching the previous tier’s ceiling; 50ms-level differences are barely perceptible on small controls

Selection rule of thumb: first ask “how much area, and who triggers it” — area picks the tier, input caps the ceiling (>600ms is off-limits for user input), the step fine-tunes; enters always outlast exits.

When to use 4
  • Selection-control state transitions — the official example short4 200ms + Standard
  • Container transitions: FAB→Sheet at medium4 400ms, Card→fullscreen at long2 500ms + Emphasized (official examples)
  • Scaling duration by transition coverage: small areas 200ms, large areas 500ms (official M3 guidance)
  • Ambient transitions without user input (loading atmosphere, environmental feedback) may use extra-long 700–1000ms
When not to use 3
  • Durations past 600ms on user-initiated transitions — officially those belong to ambient only; users will read them as sluggish
  • Raising every tier to look refined — exits should be faster than enters (official example: enter 500ms / exit 200ms)
  • Using extra-long as "important = slower" emphasis — duration tracks area and attention, not weight
Accessibility

Duration tiers never waive prefers-reduced-motion: under reduce, displacement transitions render their final state directly (vestibular safety, MDN); motion must not be the sole channel for key information (HIG: pair with haptics/audio); the official enter-longer-than-exit rule hands attention back to the next task, which is cognitively friendly.

Browser support

Duration tokens are design-spec values, not a Web API; the demo hosts them in CSS animation (per-browser CSS animation support was not audited in this research pass). The Emphasized curve from the same page's pairing table has no CSS bezier equivalent (officially marked N/A, Standard as fallback, research 04 §1.4).

Fallback

Under prefers-reduced-motion, do not play displacement transitions at token durations — render the final state directly (equivalent to a 0ms hard cut); this matches the official "motion is cancellable" principle (HIG, research 04 §1.6). Tier values can still serve opacity-only micro-motions.
