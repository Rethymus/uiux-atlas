Cubic Bézier Easing

贝塞尔缓动 · cubic-bezier() · 自定义缓动曲线

cubic-bezier(x1,y1,x2,y2) maps time to progress via two control points: x stays within [0,1] while y may overshoot for bounce — the universal building block of CSS easing.

Web Standard ★★★
Live demo official default
Parameters
Motion▾
curvecubic-bezier(0.25, 0.1, 0.25, 1)

The easing curve itself, consumed by animation-timing-function / transition-timing-function. Default (0.25, 0.1, 0.25, 1) is the official value of the ease keyword (MDN); x∈[0,1], y may overshoot (panel-limited to -0.5–1.5) for bounce (MDN example cubic-bezier(0, 1.1, 0.8, 4)). Official keyword preset values: ease (0.25,0.1,0.25,1), ease-in (0.42,0,1,1), ease-out (0,0,0.58,1), ease-in-out (0.42,0,0.58,1).

Code breakdown

Structure & DOM

The demo pairs two panels side by side: a motion area (a track with a ball) and a curve preview (an SVG coordinate system). The DOM needs only three pieces:

<div class="cb-track">
  <div class="cb-ball"></div>  <!-- animation-timing-function: var(--cb-curve) -->
</div>
<svg viewBox="0 -40 100 180">  <!-- headroom reserved for y>1 / y<0 -->
  <path class="cb-curve" d="M 0 100 C …" />
  <g class="cb-dot-x"><circle class="cb-dot-y" cx="0" cy="100" r="4.5" /></g>
</svg>

Key points:

  • The ball’s shuttle and the tracer dot’s horizontal/vertical components all consume the same cubic-bezier() value — preview and motion stay in sync by construction;
  • The tracer is split into two nested layers: the outer g moves linearly horizontally, the inner circle moves vertically on the Bézier. Two CSS animations writing the same property would override each other, so nesting is the only clean way to compose two timing functions;
  • The preview maps the SVG y-axis to progress via y = (1 - progress) × 100; the bands above the top edge (y>1) and below the bottom (y<0) mark the overshoot zones.

Styling & Parameters

One parameter, curve (cubicBezier type, injected through --cb-curve) — the curve itself:

.cb-ball {
  animation: cb-run 1.6s var(--cb-curve) infinite alternate;
}
@keyframes cb-run {
  from { transform: translateX(0); }
  to   { transform: translateX(var(--cb-dist)); } /* track width - ball size, measured by JS */
}
.cb-dot-x  { animation: cb-dot-x 1.6s linear infinite alternate; }            /* horizontal: linear = the time axis */
.cb-dot-y  { animation: cb-dot-y 1.6s var(--cb-curve) infinite alternate; }   /* vertical: Bézier = progress */

Where the numbers come from (MDN <easing-function> wording, research 04 §1.1):

  • Default ease = cubic-bezier(0.25, 0.1, 0.25, 1);
  • Official keyword preset values: ease-in = cubic-bezier(0.42, 0, 1, 1), ease-out = cubic-bezier(0, 0, 0.58, 1), ease-in-out = cubic-bezier(0.42, 0, 0.58, 1) (plus linear = cubic-bezier(0, 0, 1, 1));
  • x1 and x2 must stay within [0,1] (otherwise the whole declaration is invalid); y may overshoot — MDN’s own example cubic-bezier(0, 1.1, 0.8, 4) overshoots via y>1.

Only transform is animated (ball travel, tracer dot), honoring the web.dev “transform/opacity only” performance floor (research 04 §1.5); the travel distance is measured by a JS ResizeObserver into --cb-dist so left is never animated.

Motion & Interaction

  • Live coupling: dragging the two control points in the parameter panel (or tapping the ease/ease-in/ease-out/ease-in-out presets) updates --cb-curve immediately — the running CSS animation re-interpolates on the new curve, and the ball and tracer reshape together with no restart;
  • Replay: tapping “Replay” remounts the animated elements via a React key, replaying the current curve from t=0 (useful for studying the start/end segments);
  • Overshoot made visible: whenever the curve crosses the top line (y=1) the tracer briefly exits past the 100% progress position and settles back;
  • Reduced motion: under prefers-reduced-motion: reduce all looping animations stop — the ball rests at the end, the tracer pins to the curve’s end, and the preview still shows the full curve shape — no information lost.

Parameter Sensitivity

One parameter, curve, but the four control points have distinct jobs — covered one by one:

Control pointTurning it up…Turning it down…
curve overallboth halves steepen, sharpening the “launch late, brake hard” contrastapproaches a straight line and reads as linear
x1 (P1 time)delays the start, making the first half feel sluggishstarts earlier and harder; at 0 the max slope hits immediately
y1 (P1 progress)>1 overshoots outright (overshoots then returns); a punchy opening<0 pulls back before advancing; a draggier opening
x2 (P2 time)the closing acceleration starts later, lengthening the mid plateauenters the closing earlier; at 1 the closing is squeezed to almost nothing
y2 (P2 progress)>1 bounces at the end; <1 decelerates to rest (ease-out feel)the lower it goes, the longer the end “hovers”; at 0 it pauses before arriving

Working ranges: the four ease-family presets cover ~90% of transitions; light bounce lives at y∈(1, 1.5); y>2 heavy overshoot only suits very short travels. Remember a single Bézier segment cannot express a true spring — interruptibility and velocity inheritance need a JS physics spring or linear() sampling (research 04 §1.2/1.3).

When to use 4
  • The default feel for general UI transitions (ease); pair with 150–200ms on small controls (research 04 §2.1)
  • ease-out family to decelerate entrances, ease-in family to accelerate permanent exits (same shape logic as M3's easing selection, research 04 §1.4)
  • Emphatic arrival and light bounce: y1 or y2 > 1 (e.g. (0.34, 1.56, 0.64, 1)), best on short travels
  • Aligning with official system curves, e.g. M3 Standard = cubic-bezier(0.2, 0, 0, 1) (research 04 §1.4)
When not to use 4
  • Continuous quantities like progress bars and scroll sync — use linear; no acceleration belongs there (research 04 list #1)
  • True interruptible springs with velocity inheritance — a single Bézier segment cannot express them; approximate via linear() sampling (research 04 §1.2/1.3)
  • Large-travel y-overshoot bounce — displacement motion is a vestibular trigger and must ship a reduced-motion fallback (research 04 §6)
  • Frame-by-frame or stepped state changes — use steps(), not a Bézier (research 04 §1.1)
Accessibility

The curve itself carries no information, but overshoot and large displacement are common vestibular triggers: decorative animation must degrade under prefers-reduced-motion (built into the demo); avoid y-overshoot bounce in endless loops; never gate information on animation completion (HIG: motion is cancellable and never the sole carrier of key info, research 04 §1.6/§6).

Browser support

cubic-bezier() is a CSS Transitions/Easing baseline capability available in all mainstream browsers since the CSS3 era — no version risk, and y-overshoot works everywhere. To export spring-like curves as pure CSS, use linear() segment sampling instead (Baseline since 2023-12, research 04 §1.2). · Widely available (long-standing CSS Transitions/Easing feature; no modern support risk)

Fallback

No degradation needed: cubic-bezier() is unsupported only where CSS itself is disabled — elements then sit at their start/end states and no information is lost, since easing changes the journey, not the endpoints. Decorative animations must still honor prefers-reduced-motion (built into the demo).
