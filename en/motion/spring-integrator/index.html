Spring Integrator

semi-implicit Euler · symplectic Euler · damped harmonic oscillator · spring simulation

The physics core of UI springs: m·ẍ+c·ẋ+k·(x−target)=0 discretized with semi-implicit Euler — update velocity first, then push position with the NEW velocity; ζ=c/2√(km) pins the feel in one line, dt decides energy conservation vs explosion.

Parameters
Geometry▾
stiffness100

Spring stiffness k (N/m). Default 100 = Motion's factory spring; sets the natural frequency ω₀=√(k/m) — larger k quickens the rhythm while overshoot ratio (governed only by ζ) stays put.

damping10

Damping coefficient c (N·s/m). Default 10 with k=100, m=1 is Motion's factory feel: ζ=0.5, overshoot 16.3%; raise to 20 for critical damping (ζ=1, fastest with no overshoot).

mass1

Mass m (kg). Default 1; growing m lowers both ω₀ and ζ (while critical damping c_crit=2√(km) rises) — the math behind 'heavy elements feel slower and wobblier'.

dt4ms
ms

Integration step (milliseconds). Default 4ms ≈ 1/240s (the research's verified precision); at dt≤1/120 the symplectic integrator keeps energy drift-free; large dt first stiffens then diverges the semi-implicit curve, while explicit Euler explodes at even smaller dt — the demo overlays both curves.

Structure & DOM

The demo is a two-curve comparison: against the same 0→1 target step, the semi-implicit and explicit Euler trajectories share one coordinate system, with readout chips listing the analytic and measured ζ/overshoot/settling; a ball replays the semi-implicit curve in real time beneath the plot:

Key points:

  • Both curves share one k/c/m/dt — the only difference is the integration order (position-first vs velocity-first), and at large dt their fates diverge completely;
  • Readouts come in two flavors: analytic formulas computed directly (OS, t_s, c_crit) and measurements taken off the discrete trace (peak, last out-of-band moment), each cross-checking the other;
  • The replaying ball is only a visualization of the readings, aria-hidden; the real information lives in the text readouts.

Styling & Parameters

Four JS-type parameters (k/c/m/dt), subscribed from the store, integrated in-page with zero dependencies. The formulas, step by step (research 14 §3; the iteration quoted verbatim from Wikipedia, the industrial defaults read from motion-dom@14.14.0 source):

① The ODE and its semi-implicit (symplectic) Euler discretization — velocity first, position second:

m·ẍ + c·ẋ + k·(x − target) = 0

v_{n+1} = v_n + ( −k·(x_n − target) − c·v_n ) / m × dt
x_{n+1} = x_n + v_{n+1} × dt          ← uses v_{n+1} (explicit Euler would use v_n)

② Feel analytics (standard control-theory results; the research ran them against the simulation: analytic OS=0.163 vs simulated peak 115.89 at dt=1/240, a 0.3% gap):

const springAnalytics = (k, c, m) => {
  const w0 = Math.sqrt(k / m), z = c / (2 * Math.sqrt(k * m)); // ω0, ζ
  return { w0, z, ccrit: 2 * Math.sqrt(k * m),
    OS: z < 1 ? Math.exp(-Math.PI * z / Math.sqrt(1 - z * z)) : 0, // overshoot ratio
    ts2: z > 0 ? -Math.log(0.02) / (z * w0) : Infinity };          // 2% settling
};

③ The integrator itself (returns the whole trace for plotting/sampling):

function springSim(k, c, m, x0, target, dt = 1 / 240, T = 2) {
  let x = x0, v = 0, peak = 0, ts2 = 0;
  const band = 0.02 * Math.abs(target - x0);
  for (let i = 1; i <= Math.round(T / dt); i++) {
    const a = (-k * (x - target) - c * v) / m;
    v += a * dt;                            // velocity first
    x += v * dt;                            // then position (with the NEW v)
    if (x - target > peak) peak = x - target;
    if (Math.abs(x - target) > band) ts2 = (i + 1) * dt;
  }
  return { peak, ts2, final: x };
}

Verified output (run here, k=100, c=10, m=1 — Motion’s defaults): ω0=10, ζ=0.5, c_crit=20; analytic overshoot OS=0.163 → expected peak 116.30, simulated 115.89 @t≈0.358s; analytic 2% settling 0.7824s vs simulated 0.7917s ✓. Working bands: UI feel ζ∈[0.6, 1] (0.7≈4.6% overshoot, 0.5≈16.3%), k∈[50,300], dt≤1/120 keeps the symplectic integrator drift-free.

Motion & Interaction

  • Parameters recompute live: drag k/c/m and the curve reintegrates with readouts in sync — moving c from 10 to 20 (ζ 0.5→1) makes overshoot vanish while settling slightly lengthens; “critical damping is fastest without overshoot” reads straight off the plot;
  • The dt experiment: pull dt from 4ms to 30–40ms and the semi-implicit curve first stiffens (slow energy drift) then diverges, while the explicit curve snowballs at even smaller dt — that fork is the symplectic integrator’s entire value;
  • Ball replay: press “replay” to run the semi-implicit trace in real time over 2s; under prefers-reduced-motion the replay is skipped while the curve and readouts stay;
  • Divergence guard: a trace leaving the plot window (±3) is truncated and flagged “diverged”, never drawn to infinity.

Real-world examples

  • Motion’s (ex-Framer Motion) default spring: source stiffness:100, damping:10, mass:1 → ζ=0.5, overshoot≈16.3%, settling≈0.78s — the “factory feel” of UI springs is exactly this ODE solved at k/c/m (100,10,1) (read from motion-dom@14.14.0 source);
  • Apple’s UISpringTimingParameters(dampingRatio:): iOS promotes ζ to a first-class API parameter (‘more damped, less bouncy → 1.0; bouncier → near 0.15’), solving the same second-order equation internally — platform-level evidence (research 10 §4.3, cross-confirmed by the damping-craft entry);
  • The iOS segmented-control indicator (the slot-spring entry): the bubble sliding between slots is an interruptible spring — the integrator holds current x/v and the next frame resumes iterating from (x_n, v_n), which is precisely what “interruptible physical animation” means in engineering.

Working doctrine: compute ζ first to set the shape (0.5 bouncy, 0.8 restrained, 1 critical), then set the tempo with k or ω₀; dt only governs fidelity and stays ≤1/120. Sibling entries: damping-craft (ζ feel tiers), slot-spring (interruptible-resume engineering), motion-spring / swiftui-spring / m3-spring-tokens (how platforms expose ζ as API), linear-easing (compiling the integrated trace into linear() keyframes).

When to use 4
  • In-house spring engines: hand-write the integrator instead of pulling a library; compute ζ before picking parameters
  • The sampling side of spring→linear() compilation: integrate at the physics step, emit keyframes (upstream of the linear-easing entry)
  • Calibrating motion tokens for a design system: solve ζ and k back from target overshoot/settling time
  • Reviewing spring feel: convert 'vibes' into numbers with OS=e^(−πζ/√(1−ζ²)) and t_s≈4/(ζω₀)
When not to use 4
  • Explicit Euler in production — it diverges earlier and pumps energy where semi-implicit conserves
  • Using raw frame gaps as dt without a cap — one 200ms hiccup flings the spring off screen
  • Tuning k while ignoring ζ — k changes only the tempo; how far it overshoots is ζ's verdict alone
  • Ceremonial giant-m + tiny-c combos — ω₀ drops to single digits and settling takes seconds, interactions sink into mud
Accessibility

Spring parameters ultimately drive CSS transform animation and must honor prefers-reduced-motion globally (skip or jump to the end state); overshoot is not decoration — large overshoot causes genuine vestibular discomfort, making ζ≥0.8 the safe accessibility tier; the plotted curve carries no sole information, readings are duplicated as text.

Browser support

Pure JS numerics, no platform variance; browser animations typically take dt from the rAF frame cadence (60Hz ≈ 16.7ms) — here dt means the physics step: integrate with the real Δt per frame, and cap a single dt to guard against long-frame blowups.

Fallback

On numerical divergence (explicit Euler, oversized dt), clamp the per-step dt (e.g. ≤1/120s) and treat it as energy leakage; on environments without high-resolution timers, integrate per frame length — the integrator is precision-tolerant: ζ sets the shape, dt only the fidelity.

OriginThe damped harmonic oscillator is a standard second-order control-theory model; the semi-implicit (Euler–Cromer/symplectic) iteration is quoted verbatim from Wikipedia's 'Semi-implicit Euler method' — 'v_{n+1}=v_n+g(t_n,x_n)Δt; x_{n+1}=x_n+f(t_n,v_{n+1})Δt'; the industrial counterpart is Motion's (ex-Framer Motion) physical spring: defaults k=100, c=10, m=1, and the bounce→ζ mapping documented as '0 = critically damped' (read from motion-dom@14.14.0's spring.mjs, research 14 §3).
