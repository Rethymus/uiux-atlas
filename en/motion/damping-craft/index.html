Damping Ratio Craft

阻尼比 · damping ratio · ζ 手感 · critical damping

The damping ratio ζ is the first variable of feel: 0.3–0.7 is the 'bouncy' band, 0.5–0.8 the target for most UI, ζ=1 critical is the fastest no-overshoot settle, and >1 is overdamped crawl — four hand-feels at one target, set by a single ratio.

Live demo official default
Parameters
Geometry▾
zeta0.5

Damping ratio ζ=c/(2√(mk)) (the demo's adjustable lane). Default 0.5 = the damping ratio of Motion's source-default spring (100/10, mass 1), overshoot≈16.3% (research 10 §6.3). 0.3–0.7 is the bouncy band; 0.7–0.85 suits high-frequency interactions; ζ=1 critical settles fastest with no overshoot; >1 is overdamped crawl (research 10 §6.2).

stiffness200

Stiffness k (mass = 1, ω₀ = √k), applied to all five lanes. Perceptual rule (derived + computed, research 10 §4.3): raising ω₀ at the same ζ packs waves tighter with the overshoot ratio unchanged — 'ζ decides how many wobbles, ω₀ decides how fast'. Higher = everything snappier; lower = everything slower.

Code breakdown

Structure & DOM

The demo is five spring lanes at one target: an adjustable lane on top (ζ continuously adjustable) + four fixed reference lanes (0.3 bouncy / 0.5 Motion default / 0.8 restrained / 1.1 overdamped). Each lane is just a “target marker + one ball”:

<div class="dc-row">
  <div class="dc-meta"><b>bouncy ζ=0.30</b><span>overshoot 37.2%</span><span>envelope→5% 300ms</span></div>
  <div class="dc-lane" aria-hidden="true">
    <div class="dc-goal"></div>
    <motion.div class="dc-ball" style="x"></motion.div>
  </div>
</div>

Key points:

  • All five lanes share one stiffness and one target — ζ is the only variable; every difference comes from the damping ratio;
  • Per-lane readouts (overshoot %, envelope→5% time) are computed from formulas and displayed alongside the animation, so “feel” can always be cited numerically;
  • Lanes are aria-hidden — pure visual contrast carrying no sole information.

Styling & Parameters

Two JS-type parameters, converted by the demo into per-lane Motion springs:

// Per-lane damping solved from the ratio (mass = 1): c = 2·ζ·√(k·m) — the critical-damping definition c_c=2√(mk)
const damping = 2 * zeta * Math.sqrt(stiffness);
animate(x, target, { type: "spring", stiffness, damping, mass: 1 });

// Readouts (computed locally, research 10 §2.3):
const w0 = Math.sqrt(stiffness);                    // ω₀ = √(k/m)
const overshoot = Math.exp(-Math.PI * zeta / Math.sqrt(1 - zeta * zeta)) * 100; // ζ<1
const envelope5 = Math.log(20) / (zeta * w0) * 1000; // ms until the envelope decays to 5%

Where the numbers come from (research 10 §6.1/§6.2/§6.3/§4.3):

  • Physics (Wikipedia Damping ratio): ζ=c/c_c, ω₀=√(k/m), m·x''+c·x'+k·x=0; 0<ζ<1 underdamped (overshoot oscillating with exponential decay), ζ=1 critical (fastest no-overshoot settle), ζ>1 overdamped;
  • ζ→overshoot table (computed locally in Python): 0.10→72.9%, 0.15→62.1%, 0.25→44.4%, 0.50→16.3% (Motion’s source-default spring 100/10), 0.70→4.6%, 0.80→1.5% (BuildUI bounce 0.2), 1.00→0;
  • Perceptual bands: 0.3–0.7 = the “bouncy” band; 0.5–0.8 = the target band for most UI; 0.7–0.85 for high-frequency interactions; ζ=1 = Apple’s official “more damping, less oscillation” tier; ζ>1 overdamped crawl (Motion’s negative bounce expresses the same);
  • bounce↔ζ conversion (Motion’s bounceToDampingRatio source): bounce 0.2→ζ0.8, 0.3→ζ0.7, 0.7→ζ0.3; SwiftUI’s dampingFraction is ζ, official default 0.825 (overshoot≈1.3%, dual-source confirmed in the swiftui-spring entry).

Motion & Interaction

  • Same-target race: one click launches all five balls from the same start to the same target — 0.3 overshoots hugely, 0.5 sways once, 0.8 trembles faintly, 1.1 crawls: four hand-feels on one screen;
  • Live parameters: dragging ζ reshapes only the adjustable lane’s damping; dragging stiffness retunes every lane’s tempo (wave density) — verifying “ζ decides how many wobbles, ω₀ how fast”;
  • Interrupt handoff: rapid re-launches continue from current position + velocity (physics springs);
  • Reduced motion: animation skipped, all five balls land directly, readouts stay;
  • Performance: only transform animates (ball travel) — compositor-friendly.

Real-world examples

  • Motion’s (framer-motion successor) default spring: source stiffness:100, damping:10, mass:1 → ζ=0.5, overshoot≈16.3% — the “factory feel” of UI springs sits mid-bouncy (research 10 §6.3);
  • Apple’s UISpringTimingParameters.init(dampingRatio:): ζ is a first-class iOS spring parameter, officially “more damping/less oscillation → 1.0; more oscillation → close to 0.15” — platform-level evidence (research 10 §4.3);
  • BuildUI’s slot bubble: bounce 0.2 / duration 0.6 → ζ≈0.8, overshoot≈1.5% — a production instance of the “restrained” tier (research 10 §2.1).

Working ranges: most UI at ζ 0.5–0.8 (overshoot 16%→1.5%); high-frequency at 0.7–0.85; gesture-end emphasis at 0.3–0.5; compute ζ before shipping any combo (craft #3) — 0.7 ± 0.1 is the universal sweet spot.

When to use 4
  • Picking a feel tier for a control: fix the ζ band first (bouncy 0.3–0.7 / steady 0.7–1 / sticky >1), then tempo with ω₀
  • Calibrating spring presets: verify Motion bounce ↔ ζ conversions (0.2→ζ0.8, 0.3→ζ0.7) against this entry's readouts
  • A baseline experiment before tuning mass: lock ζ at mass=1 first, then evaluate mass' 'heavier sinks slower' separately (same logic as Motion's mass:'auto', research 10 §6.3)
  • Reviews/teaching: four ζ tiers racing to one target, with overshoot and envelope readouts turning 'feel' into discussable numbers
When not to use 4
  • ζ<0.3 ball-bounce feel in forms/lists or other high-frequency interactions — >37% overshoot reads toyish, not lively (research 10 §6.2)
  • Treating stiffness/damping as independent feel knobs without ever computing ζ — combos like `500/50` are overdamped fake springs (ζ≈1.118) (research 10 §2.3, craft #3)
  • Underdamped springs on progress bars/continuous values — continuous quantities take no overshoot (see the motion-spring entry caveat)
  • Heavy overdamping past ζ>1.2 on feedback that needs arrival certainty — the sticky crawl reads as lag or breakage
Accessibility

The demo is pure visual contrast and carries no sole information (text labels + readouts per lane); under prefers-reduced-motion everything lands directly; heavy oscillation is a vestibular trigger (MDN), hence the demo caps overshoot bands and honors reduced-motion; production springs owe users the same cancellable/interruptible treatment (HIG Motion).

Browser support

The demo rides Motion physics springs and needs JS; without it the balls rest at their start. ζ/overshoot/envelope readouts are computed locally from formulas (browser-independent). The continue-from-velocity semantics come from Motion.

Fallback

Under prefers-reduced-motion the animation is skipped and all five balls land on target directly, with readouts still showing each lane's ζ/overshoot; damping feel never carries state alone — arrival is also signaled by color/position.
