Liquid Theme Reveal

liquid theme switch · liquid reveal · theme pour · 液体切换 · 倾倒主题 · 液态主题过渡 · theme liquid transition

The new theme pours out from under the button: a true view-transition reveal + dynamic SVG clipPath, where the joint outline of column, droplets, splash and waves is rebuilt per frame as one path d by a single rAF loop (the liquid edge lives in the d — no filters); the old snapshot underlays with pixel-perfect alignment, plus a four-stage Web Audio score (off by default).

px

Lateral sway of the liquid column (phase-lagged sine along the column, maximal at the tip). Higher sways like a heavy pour; toward 2px the column straightens and loses the pouring gesture. Amplitudes scale with stage height (0.45–1.25×) so one parameter reads the same on phone and desktop.

waveAmp8px
px

Amplitude of the two-sine wave surface (1:1.618 angular-speed beat ratio prevents mechanical looping). Higher reads stormier and more 'liquid' during the rise; toward 2px it nears still water. The settle stage forces amplitude to zero so the final state covers smoothly without a flickering edge.

droplets4个
个

Cap on simultaneously-alive separating droplets during the feed (one detaches every ~110ms from the mid-lower column and merges on touching the surface). Higher reads more intermittent; 0 = column and splash only. The impact splash is a separate fixed burst of 7 parabolic droplets.

Code breakdown

Structure & DOM

On toggle, the new theme pours out from under the button. The reveal body is a true view transition: document.startViewTransition(applyTheme) with default animations disabled by injected style, and ::view-transition-new(root) carrying clip-path: url(#id) that references an in-document dynamic SVG clipPath; after vt.ready a single rAF loop changes exactly one <path d> attribute per frame — the d is the joint outline of the column, separating droplets, splash droplets and the wave surface (the key route proven by the 20a spike, S3):

<!-- Runtime temp layers (injected by the module; removed on end/interrupt/unmount; unique uid) -->
<style>
  ::view-transition-old(root), ::view-transition-new(root) { animation: none; mix-blend-mode: normal; }
  ::view-transition-new(root) { clip-path: url(#liquid-fx-clip-N); }
  ::view-transition-group(*), ::view-transition-image-pair(*) { pointer-events: none; }
</style>
<svg width="0" height="0" aria-hidden="true" focusable="false"><!-- 0×0 carrier; never in focus/a11y order -->
  <defs><clipPath id="liquid-fx-clip-N" clipPathUnits="userSpaceOnUse">
    <path d="…joint outline of column/droplets/splash/surface, rebuilt per frame…"/>
  </clipPath></defs>
</svg>

Key points:

  • The two layers correspond exactly in content and layout — guaranteed by the browser: the old-theme snapshot naturally underlays and the new-theme snapshot is the reveal layer; size, position, scroll position and sticky/fixed elements align pixel-perfectly (S9 measured: identity callback, two frames, diff = 0). This is not a DOM clone — zero duplicated business listeners; form contents and filter state live on the real DOM untouched;
  • The liquid edge lives in the per-frame d, not in filters: S5 disproved SVG filters on transition pseudo-elements (they are ignored); column sway (phase-lagged sine along the column), thickness variation and the two-sine wave surface are all computed directly into the path;
  • The joint outline = same-winding clockwise subpaths union (nonzero fill), fixed-point coordinates via toFixed(2) (S7 discipline); subpath count may change freely frame to frame (no WAAPI interpolation, no ring-count constraint);
  • The transition lifetime is stretched by an opacity 1→1 no-visual WAAPI “keeper” animation on ::view-transition-group(root); canceling the keeper after the reveal completes tears the transition down (the S9 recipe);
  • The reveal layer is a pure compositor overlay (pointer-events: none); interaction lands on the real DOM — scrolling keeps working mid-animation (S8: the liquid edge stays viewport-fixed while content scrolls beneath).

Styling & Parameters

All four parameters are JS-type; theme tokens are stage-scoped variables (switched by data-fx-theme, values taken from the site’s design-spec §2.1 dark/light sets — the site theme is untouched):

// Per-frame geometry (20a spike recommended architecture; shares: pour 16% / splash 16.5% / rise→settle 78%)
const tipY = origin.y + (bottomY - origin.y) * (p / 0.16) ** 2;      // column falls with gravity
const sway = u * amp * Math.sin(u * 2.1 + tau * 5.0 + 0.6);          // column sway
const surf = amp * (sin(k1x - ω1τ) + 0.45 * sin(k2x - ω2τ + 1.1));   // surface: ω2/ω1 = 1.618 beat
// Impact ripple = Gaussian packet (widening + decaying); droplets = gravity projectiles merging on contact;
// all coordinates scale adaptively with the stage height

Where the numbers come from:

  • Two-sine surface, angular-speed ratio 1:1.618 = research 20 §2.6 recorded values (Wikipedia, Dispersion (water waves) beat effect, anti-mechanical-looping);
  • Liquid easing cubic-bezier(0.3, 0, 0.2, 1) = research 20 §6.3 recorded value (JS bisection solver);
  • Stage shares (16%/16.5%/78%), sway=10px, waveAmp=8px, droplet interval 110ms, splash burst of 7 = demo tuning values (research verified the mechanisms — per-frame d works, snapshots align, filters don’t attach — not these absolute figures);
  • Amplitude/gravity scale with the fill region’s height (0.45–1.25×) — one parameter set reads the same from phone to desktop; no fixed stage size is assumed.

Motion & Interaction

  • Four stages: ① a slender column extends from the button (pour) with sway, thickness variation and separating droplets; ② it lands and fires splash droplets plus a local ripple (splash); ③ liquid accumulates into a continuously undulating wave surface that rises (rise); ④ the surface covers the viewport, wave amplitude eases to zero and the switch settles (finish). Light→dark and dark→light both play the full animation (direction only tints the sound); wherever the liquid passes, background/cards/text/borders/charts switch — uncovered areas keep the old theme — never a circular wipe, a gradient fade, a solid mask, or a whole-page swap;
  • Sound (Web Audio local synthesis, zero remote assets): pour = short drip, landing = light splash, rise = low-volume continuous flow, finish = short soft outro; to-dark sits lower (×0.78), to-light brighter (×1.26). Off by default; the switch and volume persist to localStorage (atlas-sound); the AudioContext is a module singleton created/resumed inside the click gesture; stages fire from the animation’s actual progress (at most once per stage per run), never stacked fixed delays; interrupting stops the flow and never plays the finish cue; mute/zero-volume/background/unmount stop and disconnect promptly; reduced-motion skips the long flow and keeps only a short switch feedback; if audio is unavailable the switch still completes;
  • Re-clicks: ignored inside the debounce window (200ms); outside it the current run finishes instantly (explicit skip, theme already committed) — never stuck, never left half-way (S8 discipline);
  • Window changes: a resize mid-run → the browser auto-skips the transition (S8) and the module skip()s proactively for a consistent state; scrolling is never blocked;
  • Degradation: without startViewTransition (older Firefox) → direct switch (the site already has the @view-transition progressive-enhancement precedent in global.css); prefers-reduced-motion: reduce → direct switch (duration treated as 0, data-fx-duration synced to 0); backgrounding the page → instant finish + sound stopped;
  • Cleanup: the animation frame, temp nodes (style + svg) and the resize/visibilitychange/RM listeners are removed on all three exits — end, interrupt, unmount.

Real-world examples

  • View Transitions API same-document transitions (MDN / Chrome 111+ docs): the official mechanism behind startViewTransition + pseudo-element clipping — this entry swaps the default cross-fade for a per-frame liquid outline (S3/S4 measured routes);
  • In-site precedents: global.css’s @view-transition MPA rule (the same structural-degradation thinking for browsers without support); motion/theme-reveal-wipes and theme-wave-flood are same-family fixed-shape / whole-screen-wave variants;
  • No citable public product-grade implementation of “a theme pouring out from the button” was found (research 20 §4) — the demo parameters (sway/wave amplitude/stage shares) are design values, while the mechanism layer (S3/S5/S8/S9/S10) all carries spike-measured evidence.

Parameter Sensitivity

ParameterTurning it up…Turning it down…

Working ranges: duration 1200–2000ms, sway 6–14px, waveAmp 5–12px, droplets 2–6; keep the stage shares (16/16.5/78) — a shorter pour hides the column, a longer one delays the splash.

When to use 4
  • The branded moment of a theme/appearance switch: two complete themes pour from the trigger button, complementing the site's existing data-theme switch semantics (research 20 §8 candidates)
  • Theme migrations where the process should be legible: regions switch as the liquid passes so users see how the new theme floods in, instead of an instant whole-page swap
  • Local-to-fullscreen reveals launched from an explicit interaction point: origin from the real button position, fill range from the real stage/viewport size — one adaptive geometry from phone to desktop
  • Family pairing with theme-reveal-wipes (fixed shapes) / theme-water-fill (level tiers): pick this entry when the liquid must pour from the button as a joint outline
When not to use 4
  • High-frequency theme inputs (a slider scrubbing themes): a 1.6s animation plus snapshot cost must not ride continuous input; use a direct switch on the fast path (same caveat as motion/theme-transition)
  • Auto-playing on first paint: the reveal must originate from a user gesture (AudioContext gesture constraint + a 57–94ms main-thread snapshot cost that shouldn't be spent unprompted)
  • Stacking a full-page mask during the run or reusing stale overlay layers: the reveal already rides the transition pseudo-elements; an extra mask doubles the color change — temp layers must be removed on end/interrupt/unmount
  • Claiming the static snapshot 're-renders the other theme by itself': a transition snapshot is pixels captured at one instant — Canvas/WebGL/video are static inside the reveal layer; live re-painting needs a two-layer rendering scheme (stated honestly in docs/liquid-theme.md)
Accessibility

The reveal layer (transition pseudo-element tree) never enters keyboard focus or the accessibility tree; the 0×0 aria-hidden SVG host is just a clipPath carrier with no duplicate IDs. Theme state rides the data-fx-theme attribute (stage-scoped; the site theme is untouched). prefers-reduced-motion: reduce → direct switch (duration 0). Temp nodes (style + svg), the animation frame and the resize/visibilitychange/RM listeners are cleaned on all three exits — end, interrupt, unmount; form contents and business state live on the real DOM and the reveal never steals input focus. Sound defaults off, with a switch, a volume control and persistence (localStorage atlas-sound); mute/zero-volume/backgrounding/unmount stop and disconnect promptly; if audio is unavailable or unlock fails the theme switch still completes.

Browser support

The main path needs View Transitions L1 (document.startViewTransition + ::view-transition-* pseudo-elements): Chromium 111+ / Safari 18+; unimplementing Firefox degrades to a direct switch (same progressive-enhancement precedent as the site's @view-transition MPA rule in global.css). rAF + per-frame SVG path d and clipPath userSpaceOnUse clipping work everywhere. No SVG filters for the edge (S5 measured filters ignored on transition pseudo-elements). Web Audio works everywhere; if unavailable the sound silently drops and the switch completes.

Fallback

Three-tier direct-switch degradation (S8/S9 discipline): 1) without document.startViewTransition (older Firefox) → apply the theme directly (the site already has the @view-transition progressive-enhancement precedent); 2) prefers-reduced-motion: reduce → direct switch (duration treated as 0, data-fx-duration synced to 0); with sound on, only a short switch feedback plays, no long flow; 3) a window resize mid-run → the browser auto-skips the transition (S8) and the module skip()s proactively for a consistent state. Re-clicks: ignored inside the debounce window (200ms); outside it the current run finishes instantly (explicit skip, theme already committed) — never stuck half-way. Backgrounding the page finishes instantly and stops sound.
