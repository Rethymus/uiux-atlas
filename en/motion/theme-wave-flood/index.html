Theme Wave Flood

wave surge · liquid theme flood · 波浪液面切换 · 液面上涨

The new theme floods in as one undulating liquid surface built from two superposed sine waves: rAF rewrites the surface path per frame, wavenumber k=2π/λ sets crest density, the theme attribute flips the instant coverage completes, and the 500ms full-screen tier bounds the whole run.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
amplitude8px
px

Primary wave amplitude A1. Default 8px is the value recorded in research 20 §6.1 (A1=8/A2=3); the demo layers the secondary wave at the fixed ratio A2=A1×3/8, so the crest is the in-phase sum of both. Higher crests read wavier — past 24px the surface looks exaggerated on small stages and the per-frame path spans grow; toward 0 the surface degenerates into a straight edge sweeping across (loses the liquid feel but remains a legitimate degradation form).

wavelength240px
px

Primary wavelength λ; wavenumber k=2π/λ (rad/px), and a viewport of width W shows W/λ full crests. Default 240px is about 1/3.5 of the measured demo stage (≈840px wide), slightly denser than the width/3 tier; on a 1440px site viewport take 720 (width/2) or 480 (width/3) per research §6.1. The demo layers the secondary wave at the fixed ratio λ2=λ1×2/3 (the /2 and /3 tiers of §6.1). Higher = sparse crests, the edge reads as one tilting surge — near viewport width only one crest remains; below 120px chop sets in and the required sample count grows.

duration500ms
ms

Time from first rise to full coverage — the demo stage's actual data-fx-duration. Default 500ms is the full-screen/large-area tier of M3's duration-by-area table (research 20 §5); longer totals belong to multi-phase orchestration (M3 allows longer entry to focus the new content — §6.6's four phases total 700ms). Higher reads calmer but adds wait; past 800ms it clashes with HIG's 'avoid motion on frequent interactions'; below 300ms the wave shape barely reads and it approaches a hard cut.

Motion▾
directionup

JS-type param (the demo subscribes and switches the sampling axis). up/down flood vertically — the edge is a horizontal wave, matching the 'filling with water' mental model (the default); left/right flood horizontally — the edge is a vertical wave, suited to sidebar/drawer re-skins. All four directions share the same η(x,t) sampling formula with only the sampling axis and the mean-edge travel direction swapped, all on the same 500ms tier.

Code breakdown

Structure & DOM

Skin logic and the performance layer are fully decoupled: the theme state lives only in data-theme, while the wave is an aria-hidden persistent overlay (fixed, pointer-events:none) stacked above the content layer (research 20 §6 shared skeleton):

<div class="liquid-overlay" aria-hidden="true">
  <svg class="liquid"><path class="liquid-body" fill="var(--liquid-fill)"/></svg>
</div>

Key points:

  • --liquid-fill takes the target theme’s surface color; below the surface is the new theme (the liquid fill), above it the old theme not yet covered (data-fx-theme flips only the instant coverage completes);
  • Site-level path (spike 20a S3, the key route): document.startViewTransition(flip theme) + ::view-transition-new(root){ clip-path: url(#liquid) } referencing an in-document SVG <clipPath>, then after vt.ready an rAF loop calls clipP.setAttribute('d', waveD(y)) every frame — during the transition, changing one SVG attribute per frame is enough to keep the clip following;
  • Demo path (spike S4 proved the ordinary-element equivalent): the persistent overlay draws the surface path directly and rewrites d per frame — no startViewTransition needed, runs in any browser;
  • A url() clip-path reference cannot be CSS-interpolated (MDN clip-path Formal definition, research 20 §1.2), so the surface must be rewritten per frame in JS — never CSS-transitioned;
  • Relations to existing entries: color/theme-transition documents Chrome’s official circular reveal recipe (verbatim-checked in research 20 §1.1); this entry is its liquid-family reinforcement — same VT skeleton, with the reveal shape swapped from a circle to a per-frame wave path; motion/view-transitions set the name-before/unnam-after rules, and S3 is the proven version of “a transition pseudo-element referencing an in-document SVG resource”; motion/page-transitions page-level liquid reveals share this recipe’s structure (the wave path becomes the page mask).

Styling & Parameters

All four parameters (amplitude / wavelength / duration / direction) are JS-type; the demo subscribes to the store and drives the rAF loop:

const surf = (x, t) =>
  A1 * Math.sin(k1 * x - w1 * t) +            // primary wave
  A2 * Math.sin(k2 * x - w2 * t + phi);       // secondary wave (1:1.618 frequency ratio, beat effect)
// Per frame: M bottom corner → sample η(x,t) along x as a polyline → close at the top corners; t += dt lifts the level (0→100%)

(recipe verbatim from research 20 §6.1)

Wavenumber and edge position over time:

  • Wavenumber k = 2π/λ (rad/px): at λ=240px, k≈0.0262 rad/px; a viewport of width W shows N = W/λ full crests — the intuitive reading of the wavelength parameter;
  • Edge position = mean level + waveform: the mean level meanY(t) follows the eased progress p, traveling from H + A (hide one amplitude before the rise so no sliver shows) to −A (sink one amplitude at the end so no gap shows); the instantaneous edge is y(x,t) = meanY(t) + A1·sin(k1·x − ω1·t) + A2·sin(k2·x − ω2·t + φ);
  • The waveform itself travels along x at phase speed c = ω/k (the demo uses a 1s primary period, i.e. crests advance one λ per second; the absolute angular speed is a demo-tuned value — only the 1:1.618 ratio is research-verified);
  • Primary/secondary ratios all come from research 20 §6.1: A1=8px, A2=3px, λ≈viewport/2 and /3 (a 2:3 ratio), angular-speed ratio 1.618 — two superposed sines create beats / wave groups, so the surface never repeats itself (Wikipedia Dispersion (water waves), §2.6);
  • 500ms = the full-screen/large-area tier of M3’s duration-by-area table (§5); the easing is the liquid-cell curve recorded in §6.3, cubic-bezier(0.3, 0, 0.2, 1).

Motion & Interaction

  • Click → flood: rAF rewrites the path d every frame — the mean level advances with the easing while the waveform advances with phase; data-fx-duration matches the real duration; data-theme flips the instant coverage completes — the surface just filled the stage, so the re-skin has no visible seam (the site-level four-phase recipe flips past the midpoint, §6.6; the demo simplifies to a single commit at completion, keeping the flip aligned with data-fx-duration);
  • Re-click mid-transition: the old transition finishes immediately (theme committed, liquid hidden) and the new one plays in full — never frozen or left half-way (proven in spike S8: a second click skips the running transition instantly; site implementations add a ~200ms debounce or an “if active, skip first” guard);
  • Three degradation tiers (§6 skeleton + S8): no startViewTransition → direct switch; prefers-reduced-motion: reduce → instant completion (duration treated as 0); ready rejection / resize mid-transition → caught, falls back to the direct switch (S8: resize skips the transition, i.e. a hard cut);
  • Scrolling is never blocked: the reveal edge stays viewport-fixed, content scrolls normally beneath the liquid, and snapshot content re-anchors with the scroll (verified frame-by-frame in spike S8);
  • Variant: the drain-out exit (surface sinking from 100%) is simply the reverse playback (§6.1).

Real-world examples

  • Cuberto/liquid-swipe (iOS, Swift 4.2, MIT, 2984★): liquid swiping with a wave-shaped path as the page mask — “the old page is swept away by water”; the most-cited open-source precedent for liquid page reveals (GitHub API/README verified, research 20 §4);
  • iamSahdeep/liquid_swipe_flutter (Flutter, 1266★): same family — wave-masked sliding with the crest following the gesture (§4);
  • Chrome for Developers’ official theme-switch recipe (circular reveal, 500ms ease-in): the only documented “theme switch + snapshot reveal” official recipe on the web, already captured verbatim by color/theme-transition; the wave flood shares its VT skeleton with the reveal shape replaced by a per-frame wave (§1.1).
  • No open, confirmable large-vendor web implementation of “liquid theme switching” was found (§4) — none is invented; which also means this entry is currently the documented recipe source for the effect on the web.

Working ranges: amplitude 4–12px, wavelength at 1/2–1/3 of the viewport width, duration held to the 500ms full-screen tier; reserve one amplitude of travel at each end so the edge hides below the bottom before rising and sinks past the top when finishing.

When to use 4
  • Full-screen liquid reveal on dark/light switches (theme button, theme cards in settings) — the default up direction matches the 'filling' mental model
  • Branded, infrequent theme moments: onboarding, seasonal themes, ceremonial switching between theme tiers
  • Re-skinning scrollable long pages: the reveal edge stays viewport-fixed while content scrolls normally beneath (ideal behavior proven in spike S8)
  • Combined with motion/theme-turbulence-edge: bake the smooth wave into the path, put the turbulent fringe on a separate filter layer
When not to use 4
  • Playing a full-screen wave on every press of a high-frequency toggle — HIG's 'avoid motion on frequent interactions'; a 500ms run per press slows rapid toggling (research 20 §5)
  • Showing the wave to prefers-reduced-motion users — WCAG 2.3.3 requires interaction-triggered motion to be disableable (C39); the reduce tier must hard-cut or cross-fade
  • Hanging an SVG filter on ::view-transition-* pseudo-elements for a fringe — spike S5 disproved it (filters are ignored); bake the fringe into the path or use a separate layer
  • Letting the wave be the sole carrier of key information — HIG: motion must never be the only channel; the theme state needs color/text of its own
Accessibility

WCAG 2.3.3 'Animation from Interactions': interaction-triggered motion must be disableable — via C39 (CSS prefers-reduced-motion blocking motion) or SCR40 (JS check); the reduce tier switches instantly with no half-played surface. HIG Motion: 'let people cancel motion' — a re-click mid-transition must complete the old transition immediately and play the new one in full, never freezing halfway; keep feedback brief, and hold the full-screen wave to the 500ms tier. The theme itself rides color and the data-theme attribute; the wave is enhancement only; the demo scopes data-fx-theme to the stage and never touches the site theme.

Browser support

The site-level path needs document.startViewTransition (same-document): Chrome/Edge 111 (2023-03), Safari 18 (2024-09-16), Firefox 144 (2025-10-14; MDN BCD JSON fetched live, data 8.1.11, research 20 §1.4). The demo path (rAF + SVG path + persistent overlay) does not depend on that API and works everywhere. clip-path itself is Baseline Widely available since 2020-01 (§1.4), but a url() clip-path reference cannot be CSS-interpolated (§1.2) — the surface must be rewritten per frame in JS, never CSS-transitioned.

Fallback

Three-tier degradation (research 20 §6 shared skeleton + 20a recommended architecture): (1) no document.startViewTransition (e.g. older Firefox) → switch the theme directly — the performance layer is a persistent overlay that never needed the API; (2) prefers-reduced-motion: reduce → cancel the wave, switch instantly or cross-fade only (a full-screen liquid surface is a vestibular 'scaling/panning large objects' trigger and must degrade, C39); (3) transition.ready rejection or a resize mid-transition → catch and fall back to the direct switch, leaving the UI in the correct post-switch state (spike S8: resize skips the transition, i.e. a hard cut). The demo path adds one more net: environments without rAF/SVG commit directly.

Sources 5

OriginThe recipe comes from research 20 §6.1 'wave surge': a two-sine liquid surface (primary A1=8px, secondary A2=3px, angular-speed ratio 1:1.618 for the beat effect), k=2π/λ (λ≈viewport/2 and /3), and the 500ms full-screen tier of M3's duration-by-area table (§5); the wave math (wavenumber, wave groups, beats) is verified against Wikipedia Dispersion (water waves) (§2.6). The mechanism was proven in tech-spike 20a: a transition pseudo-element referencing an in-document SVG clipPath whose d is rewritten per frame via rAF (S3 — the site-side key path), and the equivalent CSS-variable path() drive works on ordinary elements (S4); the same spike disproved SVG filters on VT pseudo-elements (S5), so turbulent fringes must be baked into the path or live on a separate layer (see motion/theme-turbulence-edge).
