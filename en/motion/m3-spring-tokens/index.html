M3 Spring Tokens

Material 3 弹簧 token · MotionScheme · spring composite tokens

M3 Expressive's motion physics system: scheme (expressive/standard) × speed (fast/default/slow) × type (spatial/effects) — 12 spring composite tokens, with official Web cubic-bezier conversions and durations.

Material 3 ★★★
Live demo official default
Parameters
Motion▾
schemeexpressive

The two official MotionScheme presets: expressive = spatial springs with overshoot and bounce, the more expressive M3 Expressive look; standard = low-bounce and functional (research 02 §B1). Switching scheme swaps the curves and durations of all 12 tokens.

speeddefault

Speed tier, which sets both the converted curve's duration and the Compose spring stiffness: fast 150–350ms / default 200–500ms / slow 300–750ms depending on type (research 02 §B2); on the Compose side fast = high stiffness, slow = low stiffness (research 02 §B3).

typespatial

spatial = spatial springs for positional/size properties (curves may overshoot, y>1); effects = effect springs for state feedback like color/opacity (damping 1.0 = critically damped with no overshoot, shorter durations, research 02 §B2/B3).

Code breakdown

Structure & DOM

The demo is a compact “animation + readout” workbench: a chip travels along a track (consuming the current token’s Web conversion curve and duration), an SVG beside it draws the same curve with a synchronized tracer dot, and readouts below pair the Web curve/duration with the Compose-side damping/stiffness. Core DOM:

<div class="m3-track"><div class="m3-chip"></div></div>
<svg viewBox="0 -40 100 180">
  <path class="m3-curve" d="M 0 100 C …" />          <!-- current token curve -->
  <g class="m3-dot-x"><circle class="m3-dot-y" /></g> <!-- outer linear-X + inner Bézier-Y -->
</svg>
<dl class="m3-readout">cubic-bezier / duration / damping / stiffness</dl>

Key points:

  • The three parameters are JS enums; the demo subscribes to the store, looks the token up in the 12-row table, and feeds “curve + duration” straight into the animation — switching swaps the animation instantly, with no blended transition state;
  • The Compose damping/stiffness figures are a side-by-side reference, not the driver: one token is a physics spring on Android and the official converted curve on the Web, and the two number sets come from two official sources.

Styling & Parameters

On the Web, consuming a token means writing its official conversion into plain CSS:

.m3-chip {
  animation: m3-run var(--m3-dur) cubic-bezier(var(--m3-curve)) both;
}
@keyframes m3-run {
  from { transform: translateX(0); }
  to   { transform: translateX(var(--m3-dist)); }
}

The 12 official tokens (curves are the Web cubic-bezier conversions, durations in ms; the demo embeds the same table, from m3.material.io/styles/motion/overview/specs, research 02 §B2):

Expressive fast spatial(0.42, 1.67, 0.21, 0.90)350ms
Expressive default spatial(0.38, 1.21, 0.22, 1.00)500ms
Expressive slow spatial(0.39, 1.29, 0.35, 0.98)650ms
Expressive fast/default/slow effects(0.31, 0.94, 0.34, 1) / (0.34, 0.80, 0.34, 1) / (0.34, 0.88, 0.34, 1)150/200/300ms
Standard fast/default spatial(0.27, 1.06, 0.18, 1.00)350/500/750ms
Standard fast/default/slow effectssame three curves as Expressive effects150/200/300ms

The Compose MotionScheme damping/stiffness values (official androidx sources ExpressiveMotionTokens.kt / StandardMotionTokens.kt, research 02 §B3): Expressive spatial default 0.8/380, fast 0.6/800, slow 0.8/200; Expressive effects 1.0/1600 (default), 1.0/3800 (fast), 1.0/800 (slow); Standard spatial 0.9/700, 0.9/1400, 0.9/300; Standard effects 1.0/1600, 1.0/3800, 1.0/800.

Stated honestly: in the official table the Standard spatial row covers one curve (fast/default listed, with the slow 750ms duration on the same row); the research did not capture a separate slow-spatial curve. The demo reuses (0.27, 1.06, 0.18, 1.00) at 750ms for standard+slow+spatial and says so in the readout. The legacy Emphasized easing has no CSS Bézier equivalent (officially N/A, Standard as fallback, research 04 §1.4) — this entry uses the post-replacement spring conversion table and is not affected by that limit.

Motion & Interaction

  • Switch = new animation: any enum change cancels the running animation (controls.cancel()) and re-runs element.animate() with the new curve/duration immediately;
  • Curve visualization: the tracer shares the chip’s curve shape, making y>1 overshoot obvious (expressive spatial’s (0.42, 1.67, …) leaps out of the gate);
  • Aligned readouts: the readout shows the full token name (e.g. Expressive fast spatial), the cubic-bezier, the duration, and the Compose damping/stiffness — parameter axes mapped to number axes;
  • Replay: clicking the track or “Replay” re-runs the current token;
  • Reduced motion: the animation is skipped and the final state shown directly; readouts persist;
  • Performance: the chip animates transform only.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
schemeexpressive: curves overshoot (y1 up to 1.67), the look is exuberant, and spatial springs run low stiffness (380) for extra bouncestandard: overshoot reined in (y1 = 1.06), more restrained, spatial springs run high stiffness (700/1400/300) for crispness
speedslow: durations rise to 300–750ms while Compose stiffness drops to 200–800 — for large, infrequent transitionsfast: compressed to 150–350ms with stiffness up to 800–3800 — instant feedback for small controls; default sits between
typespatial: overshoot allowed and durations longer, serving position/sizeeffects: damping 1.0 = critically damped, no overshoot, shorter durations, serving color/opacity state feedback
Combined feelall expressive + slow = the most expressive large-area transition at 500–750msall standard + fast = the most restrained quick feedback at 150–350ms

Selection rule: position/size goes spatial (overshoot allowed), state feedback goes effects (no overshoot); raise the speed tier for large/infrequent surfaces, keep fast for small controls; hand off to Web by copying the official conversion table, never by fitting curves by hand.

When to use 4
  • M3 Expressive-style positional transitions: FAB expansion, container transforms and other spatial animations
  • State-feedback animation (selection, color fades) on the effects tier: critically damped, 150–300ms, quick without bounce
  • Cross-platform consistency: Web consumes the official cubic-bezier conversions while Android uses the same-named Compose MotionScheme tokens
  • Handing off Material designs to Web component libraries using this table's curves + durations
When not to use 4
  • spatial curves (y>1 overshoot) on continuous quantities (progress bars, scroll sync) — overshoot is decorative displacement
  • Treating expressive/standard as old vs new — they are parallel MotionSchemes; the thing being replaced is the old easing+duration system (research 02 §B1/B4)
  • slow tier on frequent same-screen operations — 300–750ms is for large, infrequent transitions (M3 duration rules, research 04 §1.4)
  • Fabricating Béziers in place of official tokens — values must be taken token-by-token from the official table (research 02 §B2), not from community-circulated M2 curves
Accessibility

The spatial tier's overshoot is displacement motion and must honor prefers-reduced-motion with the final state (built into the demo); the effects tier is short and critically damped — lower risk, but degrade it too; motion is never the sole carrier of key information (shared HIG/M3 principle).

Browser support

On the Web these tokens are consumed via the official cubic-bezier conversions — plain CSS animation/transition, available in every browser with no new-feature dependency; the native physics springs live on the Compose (Android) side. The demo replays them with CSS curves + WAAPI; very old environments (no Web Animations API) output the final state directly.

Fallback

Output the final state directly under prefers-reduced-motion (the demo skips element.animate); environments without the Web Animations API do the same — the token data (curve/duration values) is always shown as text and never depends on the animation.

Sources 3

OriginM3's official motion physics system replaces the old easing+duration system with springs (stiffness/damping/mass) and ships two MotionScheme presets, expressive/standard (research 02 §B1); the 12 composite tokens' Web cubic-bezier conversions come from m3.material.io/styles/motion/overview/specs (research 02 §B2); the Compose MotionScheme damping/stiffness values come from the official androidx source (research 02 §B3).
