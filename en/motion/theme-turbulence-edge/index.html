Turbulence Edge

boiling edge · feTurbulence liquid edge · 沸腾边缘 · 湍流边缘

feTurbulence + feDisplacementMap warp the hard edge of a solid mask into an organic liquid fringe; stepping the seed per frame keeps the edge 'boiling'. Per-pixel displacement = scale×(noise−0.5); the filter may only ride ordinary element layers — never transition pseudo-elements (disproved by spike S5).

Web Standard ★★
Live demo official default
Parameters
Geometry▾
baseFrequency0.012

Noise base frequency (cycles per px). Default 0.012 is the spike-verified tier on a solid mask (0.012/0.02); the MDN official example uses 0.05. Higher = choppier edges with denser high-frequency fringing — 0.05 already reads as broken surf; toward 0.005 the edge becomes long, broad undulations and the fringe fades. The demo sets one value on both axes; the site recipe may use the two-value '0.012 0.05' to stretch the fringe horizontally into strands (research 20 §6.2).

scale60px
px

Maximum displacement of feDisplacementMap (px). The actual per-pixel displacement is scale × (noise channel − 0.5), within [−scale/2, +scale/2]. Default 60 is the spike-verified value on a solid mask (a clear organic fringe); the edge-stroke scene of research §6.2 suggests 10–20 (fine fuzz). Higher warps harder — past 100 the edge can tear into orphaned islands; toward 0 it returns to the smooth hard edge (as if the filter were off).

boil11

Seed stepping rate (steps/second); 0 freezes the seed (static fringe). Spike verified boiling at a 90ms interval (≈11 steps/s, frame diffs ≈20k px); research §6.2 suggests stepping every 3–4 frames (≈15–20 steps/s at 60fps). Higher = more frantic boiling and more frequent filter re-renders (cost grows linearly with the rate); toward 0 the fringe goes still. Changing the seed swaps the noise field without changing the computation, so stepping the seed is cheaper than stepping baseFrequency.

Code breakdown

Structure & DOM

The architecture is dual-layer rendering (spike 20a recommended architecture #2): the solid mask + SVG filter ride an ordinary element layer, never ::view-transition-* pseudo-elements — spike S5 measured that filters on transition pseudo-elements are ignored, and with a frozen clip a seed change yields a 0px frame diff. The mask layer is decoupled from skin logic; the fringe is only the performance layer:

<svg width="0" height="0" aria-hidden="true">
  <filter id="liquid-edge">
    <feTurbulence type="turbulence" baseFrequency="0.012 0.05" numOctaves="2" seed="7" result="n"/>
    <feDisplacementMap in="SourceGraphic" in2="n" scale="14" xChannelSelector="R" yChannelSelector="G"/>
  </filter>
</svg>
<div class="liquid-mask" style="filter:url('#liquid-edge')"><!-- solid mask; its hard edge warps into a liquid fringe --></div>

(recipe from research 20 §6.2)

Key points:

  • Displacement applies to the whole SourceGraphic: inside a solid mask every displaced pixel stays the same solid color (invisible) — only edge pixels get pushed in/out, warping the hard edge into an organic liquid fringe; that is exactly why the technique targets solid masks;
  • The seed attribute alone determines the noise field’s shape: stepping the seed per frame keeps the edge “boiling” (spike verified a 90ms interval, frame diffs ≈20k px);
  • Leave bleed in the filter region (x/y=-20%, width/height=140%) so edge pixels pushed outward are not clipped;
  • Difference from the gooey (blur+contrast) family: goo merges multiple shapes (CSS-Tricks “The Gooey Effect”), turbulence warps the edge of one mask; relation to motion/theme-wave-flood: that entry computes the smooth wave body per frame in JS, this one bends a straight edge with a static filter — the two stack into “wave body + fuzzy crest”;
  • If the reveal layers of motion/view-transitions / color/theme-transition need a fringe, stack this filter layer outside them (dual-layer), or bake the noise term directly into the per-frame path (the other route of §6.2).

Styling & Parameters

The MDN official example is the starting point for every parameter’s semantics (§2.5, verbatim):

<feTurbulence type="turbulence" baseFrequency="0.05" numOctaves="2" result="turbulence"/>
<feDisplacementMap in2="turbulence" in="SourceGraphic" scale="50" xChannelSelector="R" yChannelSelector="G"/>

Displacement formula (verbatim MDN): P'(x,y) ← P(x + scale·(XC(x,y) − 0.5), y + scale·(YC(x,y) − 0.5)) — i.e. the per-pixel displacement = scale × (noise channel value − 0.5), within [−scale/2, +scale/2]; XC/YC read the R/G channels of the in2 noise image (normalized 0–1), and scale is the maximum displacement in pixels.

Three JS-type parameters (the demo subscribes to the store and injects them into the filter):

  • baseFrequency: default 0.012 (the spike-verified tier 0.012/0.02); the MDN example uses 0.05;
  • scale: default 60 (spike-verified); the fringe-stroke scene suggests 10–20 (§6.2);
  • boil: seed stepping rate, default 11 steps/s (spike’s measured 90ms interval); §6.2 suggests “every 3–4 frames” ≈15–20 steps/s;
  • numOctaves stays fixed at 2 (the MDN official example and the spike agree); the demo uses the fractalNoise type — exactly what spike S5 verified on a solid mask (§6.2’s turbulence type is the site fringe-stroke variant).

Motion & Interaction

  • Boiling: an rAF accumulator steps the seed at boil (steps/s) → feTurbulence re-renders → the edge keeps changing shape; boil=0 freezes the seed; stepping the seed only swaps the noise field without changing the computation, so it is cheaper than animating baseFrequency;
  • Theme switch: clicking the toggle floods the new theme color mask in from the bottom (500ms = M3’s full-screen tier, §5), its leading edge being the turbulent fringe; data-fx-theme flips the instant coverage completes (the surface just filled the stage — no visible seam) and the liquid resets right after — the difference from motion/theme-wave-flood: the body is a straight edge bent by the filter, no per-frame path math;
  • Re-click mid-transition: the old transition finishes immediately (theme committed, liquid hidden) and the new one plays in full — never left half-way;
  • Reduced motion: seed stepping stops and switches complete instantly (duration treated as 0) — boiling is sustained ambient motion and must be stoppable;
  • Performance: filter re-render cost grows linearly with area (same family as Bebber’s “expensive on large areas” warning, §2.4); the demo confines boiling to the stage, keeps 11 steps/s, and steps the seed rather than baseFrequency.

Real-world examples

  • The MDN official recipe example: feTurbulence + feDisplacementMap (baseFrequency 0.05 / numOctaves 2 / scale 50 / RG channels) applied to a <circle> — the authoritative source for every parameter’s semantics and the displacement formula (research 20 §2.5);
  • luukdv/gooey-react (React, 676★, README and the docs site gooey-react.netlify.app verified): the precedent that componentized SVG filters onto DOM elements and patched Safari support, proving the “DOM element + filter:url(#id)” route is production-viable (§4);
  • Chrome for Developers’ official theme-switch recipe (adjacent precedent, §1.1): a turbulent fringe is usually stacked outside its reveal layer as edge decoration — the dual-layer combination (spike recommended architecture #2).
  • Note: the 2026 status of SVG filters on DOM elements in Safari has not been re-tested (§9 unverified list); validate on real devices before shipping. No public large-vendor web product using this filter for theme switching was found — none is invented.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
baseFrequencychoppier edges, denser high-frequency fringing; 0.05 (the MDN example tier) already reads as broken surflong broad undulations, the fringe fades; near 0.005 it is a barely trembling straight edge
scaleharder warping; past 100 the edge can tear into orphaned islands and needs a larger bleed regiontoward 0 it returns to the smooth hard edge (as if the filter were off); 10–20 is the fine-fuzz tier (§6.2)
boilfrantically boiling, more frequent filter re-renders with linearly growing cost; near the ceiling it pressures low-end devicesthe fringe goes still; 0 = frozen seed — decoration stays, motion drops to zero

Working ranges: baseFrequency 0.008–0.02 (spike verified 0.012/0.02), scale 10–60, boil 8–15 steps/s; start numOctaves at 2 — 3+ adds crisper detail at rising cost; give the filter region at least scale/2 of bleed so edge pixels are not clipped.

When to use 4
  • Fringing the edges of a theme-switch reveal: dual-layer rendering — the filter layer is an independent ordinary element stacked outside the reveal (spike S5 disproved filters on transition pseudo-elements)
  • Sustained ambient motion for liquid/water UI: boiling edges on water-level panels, fill cards, liquid dividers
  • Illustrated section transitions and decorative bands: solid blocks with organic hard edges, no per-frame path math needed
  • Combined with motion/theme-wave-flood: bake the smooth wave into the path, put the turbulent fringe on this entry's separate filter layer (spike recommended architecture #2)
When not to use 4
  • Putting the filter on ::view-transition-* pseudo-elements for a fringe — disproved by spike S5: the filter is ignored and frozen-clip seed changes yield a 0px frame diff
  • Large-area long-running boiling without throttling — filter re-render cost grows linearly with area (same family as Bebber's 'expensive on large areas' warning, §2.4)
  • Leaving the boil running for prefers-reduced-motion users — sustained ambient motion must be stoppable (HIG Motion / the spirit of WCAG 2.3.3)
  • Distorting small body text with the turbulence filter — displacement applies to the whole SourceGraphic, so text crumples along with the edge and readability collapses
Accessibility

Boiling is sustained ambient motion: under prefers-reduced-motion, seed stepping must stop and switches complete instantly; HIG (visionOS) warns against sustained oscillation around 0.2Hz (people are extremely sensitive to it) — seed stepping is spatial noise change rather than periodic oscillation, but ambient motion should still be switchable and restrained by default (11 steps/s, contained area). The theme state rides color and the data-theme attribute; the fringe is edge decoration only and must never be the sole carrier of a state change (the spirit of WCAG 2.3.3); the filter layer is aria-hidden with pointer-events:none.

Browser support

feTurbulence / feDisplacementMap are SVG 1.1 filter primitives, Baseline Widely available since 2015-07 (MDN, research 20 §1.4); CSS filter:url(#id) referencing an in-document SVG filter is standard syntax (full example in the CSS-Tricks goo article, §2.4). Historical caveat: in 2015 Safari handled SVG filters on DOM elements poorly (Bebber's own warning); the 2026 status has not been re-tested — unverified (§9 unverified list item 2); validate on real devices before shipping.

Fallback

If the SVG filter is unavailable or its reference breaks → drop the filter and the solid mask reverts to a smooth hard edge — the smooth edge is independently a valid base form (research §6.2 degradation path); prefers-reduced-motion: reduce → stop seed stepping (boiling is sustained ambient motion) and complete switches instantly (duration treated as 0); filter rendering failures never block the theme switch itself — re-skinning only flips data-theme, the fringe is just the performance layer.

Sources 4

OriginPrimitives and the formula are verified against MDN (research 20 §2.5): feTurbulence generates Perlin noise (type/baseFrequency/numOctaves/seed), and the feDisplacementMap formula P′(x,y) ← P(x + scale·(XC−0.5), y + scale·(YC−0.5)) is verbatim MDN, with scale as the maximum displacement in px; the MDN official example runs type=turbulence / baseFrequency 0.05 / numOctaves 2 / scale 50 / RG channels on a circle. The liquid-edge scene parameters (horizontal frequency ~0.01, scale 10–20, seed stepping every 3–4 frames) come from research 20 §6.2. Tech-spike 20a S5 measured: fractalNoise + baseFrequency 0.012/0.02 + numOctaves 2 + scale 60 on a solid mask yields an organic liquid fringe, and stepping the seed every 90ms boils it (frame diffs ≈19–22k px); the same filter on ::view-transition-new(root) is ignored and does not re-render with the seed — hence the dual-layer, ordinary-element architecture.
