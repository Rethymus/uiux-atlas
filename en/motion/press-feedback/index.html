Press Feedback Pair

按压态 · pressed state · highlighted · active 反馈

Press and release form a state pair: the press lands instantly (0ms) and only the release gets a short transition — mature libraries default to color-stepping, not scale; scale(0.95–0.98) is a community convention.

Parameters
Geometry▾
pressScale0.97

Press scale factor. Default 0.97: a community-common value, unverified — no default button in AntD/Arco/shadcn/Magic UI ships any press scale (research 10 §1.1/§9); the folk range is scale(0.95–0.98). Higher (closer to 1) = weaker feedback; lower = heavier press and more visible text distortion.

pressAlpha0.8

Press opacity. Default 0.8: community-common, unverified (research 10 §1.1 records the folk range alpha≈0.7–0.8 with no first-hand library default). iOS' native highlighted alpha change is likewise unpublished (research 09 §4). Higher = more subtle; lower = big contrast loss and legibility risk on light buttons.

releaseDuration120ms
ms

Release rebound duration. Default 120ms from the reusable snippet in research 10 §1.3 (Arco-shaped: instant press, eased release); Arco's official tier is 0.1s linear (@transition-duration-1). Higher = stickier; past 200ms hand-following degrades clearly. Near 0 it equals the instant press — feedback reduces to a bare state flip.

pressResponseinstant

JS param (demo subscribes and toggles data-response). instant = `:active { transition: none }` — the press lands in 0ms, Arco's official craft; eased = the same transition also on press-in, delaying the press feel — kept as a teaching counter-example. JS param (demo toggles data-mode). scale = the community-convention scale+alpha press pair (values flagged unverified); color = the library-default semantics: only background/text colors change — AntD's official implementation transitions just color/background-color/border-color/box-shadow/opacity over 0.2s easeInOut, and apple.com's `:active` also swaps fill and text color without touching outline (research 10 §1.1, 09 §4).

Code breakdown

Structure & DOM

Press feedback is a state pair: normal (released) ↔ highlighted (pressed). Apple’s canonical semantics is UIControl.isHighlighted — “the control automatically sets and clears this state with the appropriate touch events”, i.e. pressed in, released/moved-out out, a natural pair (research 09 §4). The web counterpart is :active, but a data attribute is more reliable across keyboard and touch:

<button class="pf-btn" data-pressed="false">Primary</button>
<span class="pf-badge" data-hot="false">normal (released)</span>

Key points:

  • Pressed in, released/moved-out/cancelled out — pointerdown sets data-pressed, pointerup/pointercancel clears it; with setPointerCapture, dragging out of the button keeps it highlighted (matching the iOS semantics);
  • Holding Space/Enter enters the pressed state with keyboard parity; blur resets as a safety net;
  • The readout badge shows live whether the control is normal or highlighted, turning “pairing” into a visible fact.

Styling & Parameters

Five parameters map to a group of CSS variables plus two data switches:

.pf-btn {
  /* Release rebound: 120ms + Arco decelerate curve (reusable snippet, research 10 §1.3) */
  transition: all var(--press-release-ms) cubic-bezier(0.4, 0.8, 0.74, 1);
}
/* Instant press: the equivalent of Arco Button's official :active { transition: none } */
[data-response="instant"] .pf-btn[data-pressed="true"] { transition: none; }
/* The scale+alpha press pair */
.pf-btn[data-pressed="true"] {
  transform: scale(var(--press-scale));   /* 0.97 */
  opacity: var(--press-alpha);            /* 0.8 */
}
/* Color-step variant: library-default semantics, fill/luma only */
.pf-btn[data-pressed="true"] { filter: brightness(0.88); }

Where the numbers come from (all source-verified this session, research 10 §1.1):

  • Arco Button: transition: all 0.1s linear + :active { transition: none }; primary hover = color step −5 (brighter), active = step −7 (deeper); the global easing tokens include decelerate cubic-bezier(0.4, 0.8, 0.74, 1);
  • AntD Button: transitions only the five color-ish props color / background-color / border-color / box-shadow / opacity, over motionDurationMid = 0.2s (motionUnit 0.1 × 2) with motionEaseInOut = cubic-bezier(0.645, 0.045, 0.355, 1) — no scaling by default;
  • scale(0.95–0.98) and alpha≈0.7–0.8: community-common, unverified — no press scale exists in the default buttons of the four libraries; iOS’ native highlighted alpha/scale change is likewise unpublished (research 09 §4);
  • apple.com’s :active only swaps background and text color variables without touching outline — the first-hand official implementation of press-as-color (research 09 §4).

Motion & Interaction

  • Instant press, eased release (research 10 signature craft #1): the state flip itself costs 0ms; only recovery gets a 100–120ms transition — the first rule of hand-following; WWDC18 803 states the same: every interactive object must “respond immediately” (research 09 §4);
  • Two semantic lanes: scale+alpha demonstrates the touch-first physical feel (values flagged unverified); the color-step lane demonstrates the library-default craft (no transform, zero layout impact);
  • Reduced motion: under prefers-reduced-motion: reduce, transitions and the scale deformation are dropped while the instant alpha/color flip stays — the state itself is information and must survive;
  • Performance: scale/opacity/filter never trigger layout; high-frequency buttons follow HIG “avoid motion on frequent interactions” — an instant color flip suffices (research 04 §1.6).

Real-world examples

  • Arco Design buttons: the primary button brightens one step on hover (step −5) and darkens one step on press (step −7), landing instantly and recovering over 0.1s — a source-code-level implementation of “color stepping + instant press” (research 10 §1.1);
  • Ant Design buttons: no scaling by default — press only eases the five color props over 0.2s easeInOut, plus a toggleable click ripple (_util/wave) — direct evidence that “library default = color feedback” (research 10 §1.1);
  • apple.com buttons: the pressed :active state only swaps the background/text color variables (--sk-button-background-active) and adds no outline — grabbed from the site’s production CSS (research 09 §4).

Working ranges: releaseDuration 100–120ms, pressScale 0.95–0.98 (community convention, unverified), pressAlpha 0.7–0.8 (same). The mature desktop library answer is color stepping; scale is the popular touch/community supplement.

When to use 4
  • Baseline feedback for every tappable button/card: default to color stepping (Arco hover −5 / active −7 semantics)
  • Touch-first products: a scale+alpha press pair sells the physical 'pushed down' illusion, released over 100–120ms ease-out
  • Keyboard reachability: design `:active` together with `:focus-visible` so Space/Enter activation shows the pressed state too
  • High-frequency buttons: follow HIG 'avoid motion on frequent interactions' — an instant color flip is enough
When not to use 4
  • Transitioning the press-in too — it delays the press feel against 'respond immediately' (WWDC18 803); Arco officially ships `:active { transition: none }`
  • Claiming press-scale is a library default — no default AntD/Arco/shadcn/Magic UI button scales; the claim has no first-hand evidence (research 10 §9)
  • Pressing alpha too low (≤0.6) — text contrast collapses, unreadable on light fills
  • Release rebounds past 200ms — with rapid clicking the previous feedback is still playing and state semantics start to collide
Accessibility

The pressed state is visual enhancement, never the sole signal of clickability (WCAG 2.1 SC 1.4.11: component boundaries ≥3:1); keyboard users must see an equivalent focus cue via `:focus-visible` (apple.com's ring: 2px accent outline + 1px offset, research 09 §3); under prefers-reduced-motion keep the state flip and drop the rebound; the alpha change must not push text below 4.5:1 (WCAG 2.1 SC 1.4.3).

Browser support

Implementation only uses `:active`/`:focus-visible` plus transition/transform/opacity — all Baseline; on touch, `:active` follows the touch press. The demo additionally drives the highlighted-semantics readout via pointer events, themselves Baseline.

Fallback

Under prefers-reduced-motion, drop the scale rebound and release transition but keep the instant color/alpha state flip (the state itself is information and must survive); press feedback is never the sole affordance for 'clickable' — keep cursor and shape cues.
