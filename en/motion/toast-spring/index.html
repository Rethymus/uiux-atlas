Toast Spring Entrance

toast 入场 · snackbar spring · 过冲 bezier · toast bounce-in

A toast springs in from the screen edge: the entrance carries overshoot (a true spring or a y₂>1 overshoot bezier), the exit is a pure eased settle, and the lifecycle auto-dismisses on time — attack in, retreat out, the pair never collides.

Component Lib ★★★
Live demo official default
Parameters
Geometry▾
stiffness300

Entrance spring stiffness (mass = 1). Default 300 from the 'medium-microbounce' tier in research 10 §2.3 (the same tier as the slot spring): ω₀≈17.3rad/s. Motion's source default is 100 (research 10 §6.3). Higher = fiercer spring-in; lower = a floatier entrance that occupies the screen longer.

damping25

Entrance spring damping. Default 25 pairs with stiffness 300 at ζ≈0.722, overshoot≈3.8% — comparable to react-hot-toast's slight overshoot bezier (research 10 §2.3/§5.1). Higher removes the bounce (ζ→1); lower grows the overshoot, and ζ<0.5 makes the toast visibly bounce.

lifetime4000ms
ms

Auto-dismiss timer. Default 4000 = sonner's `TOAST_LIFETIME = 4000` source value (research 10 §5.1); AntD message defaults to 3s (research 06 §4.10). Under 2s it vanishes unread and the WCAG 2.2.3 risk spikes; past 8s users assume it needs manual dismissal.

Motion▾
edgebottom

JS param (demo switches the entry edge). Bottom suits thumb/reading-finish zones; top is more insistent (MUI Snackbar defaults bottom, AntD message top-center — see the components/toast entry). Directional semantics: the toast returns to the same edge it came from.

Code breakdown

Structure & DOM

The toast system has four parts: a trigger button, a stack container (role=status, aria-live=polite), individual toasts (dot + text + ✕), and a timer table. The container is fixed at the edge (bottom/top); toasts spring in from — and exit back to — that same edge:

<div class="ts-stack" role="status" aria-live="polite">
  <div class="ts-toast">
    <span class="ts-dot"></span> Saved to cloud <button class="ts-close">✕</button>
  </div>
</div>

Key points:

  • The stack container is fixed at the edge with pointer-events: none; each toast restores auto — the layer never blocks what’s beneath;
  • AnimatePresence orchestrates the exit: removal happens after Motion finishes the 0.4s ease-out, avoiding flash-jumps (same semantics as research 10 §3.3);
  • Stack cap 3, oldest dropped first; each toast owns one setTimeout timer, cleared on manual close/unmount;
  • ✕ manual close + role=status announcement satisfy “dismissible non-critical info” (same stance as the components/toast entry).

Styling & Parameters

All four parameters are JS-type, assembled into a Motion transition:

// Entrance: true spring (stiffness/damping adjustable) + react-hot-toast-shaped initial state
<motion.div
  initial={{ y: `${dir * 160}%`, scale: 0.6, opacity: 0.5 }}   // off-screen + shrunk + half-faded
  animate={{ y: "0%", scale: 1, opacity: 1,
    transition: { type: "spring", stiffness: 300, damping: 25, mass: 1 } }}
  exit={{ y: `${dir * 160}%`, scale: 0.6, opacity: 0,
    transition: { duration: 0.4, ease: [0.06, 0.71, 0.55, 1] } }} // pure ease-out back to the edge
/>
// lifetime reached → setTimeout fires the exit (sonner's TOAST_LIFETIME = 4000 pattern)

Where the numbers come from (research 10 §5.1/§5.2, verbatim source):

  • react-hot-toast entrance: slides in from 200% off-screen + scale(.6) + opacity .5 over 0.35s cubic-bezier(.21,1.02,.73,1) (y₂>1 → slight overshoot); the exit is 0.4s cubic-bezier(.06,.71,.55,1) pure ease-out; reduced-motion degrades to a bare fade; container carries will-change: transform;
  • sonner: 400ms transitions, TOAST_LIFETIME = 4000 (4s auto-dismiss), back rows sink-stacked at translateY(40%);
  • True-spring tier: Motion’s take uses bounce 0.25 + visualDuration 0.35 (research 10 §5.2); bounce 0.25 → ζ=0.75 via the bounceToDampingRatio source conversion (research 10 §6.3); the demo defaults to stiffness 300 / damping 25 (ζ≈0.722, overshoot≈3.8%) — the same “bouncy but quiet” band (research 10 §2.3);
  • The lifecycle floor’s normative basis: WCAG 2.2.3 (auto-dismissing content must be pausable/persistent) and the WAI-APG Alert caveat — detailed in the components/toast entry.

Motion & Interaction

  • Attack in, retreat out (research 10 craft #6): the entrance carries overshoot (spring or y₂>1 bezier), the exit is a pure eased settle — the “attack” energy and the “retreat” calm have separate jobs; .35/.40 never collide;
  • Edge semantics: return to the edge you came from (bottom/top switchable); a toast never appears from mid-screen (same rule as M3 enter-exit, research 04 §3.3);
  • Live parameters: dragging stiffness/damping immediately shapes the next toast’s spring; ζ≈0.72 overshoots ~4%, perceptually level with the overshoot bezier;
  • Manual close / batching: ✕ removes immediately; rapid triggers stack to 3 with the oldest exiting first;
  • Reduced motion: both directions degrade to a 0.2s bare fade (react-hot-toast’s official degradation);
  • Performance: entrance/exit animate only transform/opacity; the container’s will-change: transform matches react-hot-toast (a single persistent container is the legitimate resident use, research 10 §5.1/§7.2).

Real-world examples

  • react-hot-toast: 200% slide-in + scale 0.6 + overshoot bezier 0.35s / 0.4s ease-out — the direct source provenance of this entry’s entrance orchestration (research 10 §5.1);
  • sonner (the shadcn ecosystem’s default toast): 400ms transitions + 4s lifecycle + sink-stacked back rows and a swipe-out gesture (vaul by the same author, EASE [0.32,0.72,0,1], CLOSE_THRESHOLD 0.25) (research 10 §5.1);
  • Gmail’s “Message sent”: a bottom toast with an Undo action that dies with the toast — the canonical toast-with-action + lifecycle product case (cross-linked with components/toast).

Parameter Sensitivity

Working ranges: stiffness 200–400 / damping 20–30 (the 2–8% overshoot “bouncy but quiet” band), lifetime 3–5s, stack ≤3; entrance shorter than exit is the iron rule — attacks may bounce, retreats must be quiet.

When to use 4
  • Instant confirmations (saved/copied/sent) — spring in from the edge, auto-dismiss at 4s (sonner's lifecycle tier)
  • Lightweight feedback that should feel alive: a true spring (300/25) or the overshoot bezier(.21,1.02,.73,1) instead of a flat fade
  • Mobile bottom edge: overlapping the gesture zone, dismissable early with a swipe (sonner/vaul swipe-out semantics)
  • Batch-operation feedback: cap the stack at 2–3 and drop the oldest (same rule as components/toast's maxCount)
When not to use 4
  • Critical info (actionable errors, account security) auto-dismissing in a toast — violates WCAG 2.2.3 and the WAI-APG Alert caveat (detailed in components/toast)
  • Entrance/exit colliding: 0.35s in / 0.4s out is the benchmark pair — an exit shorter than the entrance's tail truncates it (research 10 craft #6)
  • ζ<0.5 showy bouncing on high-frequency actions — a bounce on every save quickly turns from lively to noise (HIG: avoid motion on frequent interactions)
  • Springing toasts from mid-screen — edge in, edge out is the directional semantics; center entrances have no spatial anchor (same rule as M3 enter-exit, research 04 §3.3)
Accessibility

The container carries `role="status"` (aria-live=polite) for non-critical messages; the auto-dismiss timing respects a floor matched to text length (WCAG 2.2.3: auto-dismissing non-interrupting content must be pausable/persistent); a manual ✕ close is provided; bare fade under prefers-reduced-motion; color never alone distinguishes success/error (icon + text). Stacked messages must not push older ones out unread — announce within the cap.

Browser support

The demo rides Motion (AnimatePresence + spring) and needs JS; percentage-y travel and scale/opacity transitions are all Baseline. Exit timing uses standard timers/completion callbacks. Reduced-motion degrades to a bare fade — react-hot-toast's official degradation path (research 10 §5.1).

Fallback

Under prefers-reduced-motion both directions degrade to a bare fade (react-hot-toast's official take); toasts carry non-critical info only — critical messages go to persistent components (the components/toast stance); manual close (✕) and hover-pause are recommended enhancements; timers are cleaned up on unmount.
