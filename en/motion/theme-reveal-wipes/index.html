Theme Reveal Wipes

百叶窗转场 · 棋盘格转场 · 对角擦除 · 多边形揭示 · reveal wipes · 几何揭示

Four clip-path keyframe geometric reveals — blinds, checkerboard, diagonal wipe, polygon fan: one persistent overlay split into N same-structure basic shapes that cascade the old theme away, complementing color/theme-transition's circular spread — that entry covers the official circle recipe, this one covers every other geometry.

patternblinds

JS param (demo rebuilds cells on change). blinds = horizontal slats collapsing alternately up/down (research §6.3: 8–12 slats); checkerboard = cells collapsing to their own center, cascading as a (row+col) diagonal wave (research §6.3 precedent 6×4; demo cols=stripes, rows=⌈stripes/2⌉); diagonal = 45° bands translating off along the diagonal; polygon = large triangles fanning from center, interlocking, collapsing back to the apex (research §6.3: 2–4 large triangles; 'clip-path polygon() instead of background blocks' is exactly same-structure basic-shape interpolation). Each pattern keeps from/to same-structure; no cross-type mixing.

Target total duration. Default 500 = M3 full-screen/large-area tier (research §5 'duration by transition area: small 200ms, large 500ms'; §6.3 aligns the family to 500). Derived: cell duration = duration − cascade × max delay index, cascade default 20ms (midpoint of research §6.3's 15–30ms band); when cells are squeezed below the 150ms demo floor the cascade compresses first, and if that is not enough the total moves up — data-fx-duration always carries the actual total. Code breakdown

Structure & DOM

The reveal family is a “one overlay + N cells” structure: the re-skin (data-fx-theme flip) happens underneath, while the performance layer is a persistent overlay whose N absolutely-positioned cells tile the stage — at animation start the cells fully cover the stage painted in the old theme (no flash at t=0), then wipe away cell by cell via clip-path keyframes, revealing the interface that has already switched to the new theme.

<div class="stage" data-fx-theme="dark" data-fx-duration="500">
  <div class="content">…normal content; colors flip instantly with data-fx-theme…</div>
  <button data-fx-toggle>Toggle theme</button>
  <div class="overlay" data-from="light" aria-hidden="true">
    <span class="cell" style="--rw-in: inset(0 0 0 0); --rw-out: inset(0 0 100% 0)"></span>
    <!-- ×N: blinds 8–12 slats / checkerboard 6×4 / diagonal bands / polygon 2–4 big triangles (research §6.3) -->
  </div>
</div>

Key points:

  • The re-skin and the performance are fully decoupled: clicking flips the theme variables immediately, and the overlay already covers the flip at t=0 — the audience only sees “the old theme being wiped away”;
  • Every pattern’s cell shapes are same-structure basic shapes (matching inset() components / polygon() vertex counts) — the MDN clip-path Formal definition states only <basic-shape> animates by interpolation; url() references do not (research 20 §1.2); same-structure interpolation is verified by a local headless-Edge spike: two same-structure path() values on a transition pseudo-element interpolate per-coordinate, three computed frames matching theory point for point (research 20a §S1), and CSS-variable-driven clip-path also verified on plain elements (20a §S4);
  • Complementary to color/theme-transition’s circular spread: that entry covers the official circle recipe (circle() expanding on ::view-transition-new(root)); this entry covers every other geometry; both share the “decoupled re-skin + no overshoot + reduced-motion instant switch” skeleton;
  • The overlay is pointer-events: none and aria-hidden — the wipe blocks no clicks and carries no information; the toggle stays clickable throughout.

Styling & Parameters

All cells share one CSS animation; they differ only in three variables: the in-state --rw-in, the out-state --rw-out, and the per-cell incremented --rw-delay:

.cell {
  position: absolute;
  clip-path: var(--rw-in);
  animation: wipe var(--rw-cell-dur) cubic-bezier(0.3, 0, 0.2, 1) var(--rw-delay) forwards;
}
@keyframes wipe { to { clip-path: var(--rw-out); } }

/* blinds: adjacent slats collapse alternately up/down (same-structure inset)
   checkerboard: cells collapse to their own center · diagonal: whole-band polygon translates off
   polygon: fan triangles collapse back to the apex (same-structure polygon) */
.overlay[data-from="light"] .cell { background: #f2efe8; } /* old-theme surface */
.overlay[data-from="dark"]  .cell { background: #14161b; }

Timing structure (computed live by the demo; data-fx-duration always carries the actual value):

cell duration = duration − cascade × max delay index
actual total = cell duration + cascade × max delay index
defaults: duration 500, cascade 20ms, blinds 8 slats → cell = 500 − 20×7 = 360ms (inside the 300–400ms cell band ✓)

Where the numbers come from (research 20):

  • 500ms total: M3’s “duration by transition area: small 200ms, large 500ms” full-screen tier (§5); §6.3 aligns the family to 500;
  • cubic-bezier(0.3, 0, 0.2, 1): verbatim from research §6.3 — an overshoot-free decelerate curve; overshoot is forbidden on reveals (the snap-back shows), same conclusion as color/theme-transition;
  • Cell magnitudes: blinds 8–12 slats, checkerboard 6×4, polygon 2–4 big triangles; adaptive count min(12, viewport/120) (§6.3);
  • clip-path Baseline Widely available (since 2020-01, MDN, §1.4).

Motion & Interaction

  • One click, three beats: ① flip the stage’s data-fx-theme (the UI enters the new theme variables immediately); ② mount the overlay — N old-theme cells cover everything; ③ cells wipe away on their cascade delays, revealing the new theme;
  • Interruption (re-click mid-animation): clear the timer and rebuild the overlay under a new key, replaying from the start — cells re-cover with the current theme’s color and wipe away again; never stuck halfway. This matches the View Transitions rule “only one transition may run at a time; a new transition skips the old one to its end” (Chrome docs, research §1.1; re-click/skip behavior verified on headless Edge, research 20a §S8);
  • Reduced motion: duration treated as 0 — a click switches instantly with no overlay (C39, research §5); matchMedia changes apply live;
  • No View Transitions API dependency: the overlay plays independently of document.startViewTransition (research §6.6, “the pure-overlay approach has no API dependency”) — the API mechanism itself lives in the site’s motion/view-transitions entry; two verified routes exist to move it into VT — WAAPI double same-structure path() interpolation on ::view-transition-new(root) (20a §S1) or CSS-variable-driven clip-path (20a §S4); do not hang SVG filters on transition pseudo-elements for liquid edges — measured to be ignored (20a §S5 counter-proof);
  • The cascade mirrors the site’s motion/stagger-orchestration entry: cell i starts at i × cascade, spread = cascade × max delay index.

Real-world examples

  • Chrome for Developers (View Transitions same-document page): the official source of the same family’s “root snapshot + clip-path reveal” — the circular spread is that page’s “Animating with JavaScript” example (circle() expanding from the click point, 500ms ease-in); this entry is every other geometry on the same skeleton (research §1.1, quoted verbatim and re-checked);
  • Cuberto/liquid-swipe (iOS, MIT, 2984★) and its open-source family: liquid_swipe_flutter (1266★), Chrisvin/LiquidSwipe (Android, 848★) — the “wavy path as a page mask, the old page swept away” liquid-reveal family, each repo verified via the GitHub API (research §4); these are page-level liquid reveals rather than theme switching — close cousins of the reveal family. For web products shipping geometric reveal theme switches, the research found no openable, confirmable precedent (§4), so none are listed.

Working ranges: total 400–500ms, cascade 15–30ms, cell 300–400ms, cells 8–12 (all from research §5/§6.3); reduce cells on narrow screens.

When to use 3
  • Ceremonial low-frequency re-skins: settings pages, profile pages, campaign skins — the 500ms geometric reveal makes the theme change perceptible (the inverse of research §5's 'no motion on frequent interactions': use only when infrequent)
  • Mixing with the circular spread: keep the circle (color/theme-transition) as the global default and switch to the geometric family for campaign skins
  • Checkerboard for dashboards with clear zones (per-zone re-skin stays legible); blinds/diagonal for reading pages (strongest directionality)
When not to use 4
  • High-frequency theme toggling — every click is a full-screen motion animation (Apple HIG: avoid motion on frequent interactions, research §5)
  • Overshoot curves (the ease-out-back family) — reveals show the snap-back and break the illusion; forbidden (research §6.3; same conclusion as color/theme-transition)
  • Too many cells squeezed too short — the rhythm shatters; adapt with min(12, viewport/120) (research §6.3)
  • Giving reduced-motion users 'no animation' without 're-skin done' — after the instant switch the UI must sit in the correct new-theme state
Accessibility

The color swap itself is an instantaneous change, not a motion animation (WCAG 2.3.3 boundary, research §5); but the geometric wipe is interaction-triggered motion and must be disableable — the demo treats duration as 0 under prefers-reduced-motion, switching instantly (sufficient techniques C39/SCR40, research §5). The wipe layer is aria-hidden and pointer-events:none — it carries no information and blocks no interaction; the conclusion 'theme changed' is carried by the new colors and text contrast — check both theme palettes at 4.5:1 (WCAG 1.4.3); motion is never the sole channel for the change.

Browser support

clip-path is Baseline Widely available (since 2020-01, MDN, research §1.4); same-structure basic-shape keyframe interpolation is CSS clip-path animation, supported by all major engines. The demo does not need document.startViewTransition — the overlay plays independently of VT (research §6.6: 'the pure-overlay approach has no API dependency'), so engines without VT behave identically; do not hang SVG filters on transition pseudo-elements for liquid edges — measured to be ignored (counter-proof in research 20a §S5); bake edges into the path itself or use a separate plain-element layer.

Fallback

prefers-reduced-motion: reduce → duration treated as 0, click switches instantly with no wipe layer (WCAG 2.3.3/C39, research §5); engines without the View Transitions API → nothing to do, the overlay approach has no API dependency; legacy environments without clip-path → fall back to a whole-layer opacity exit; re-click mid-animation → clear timers and rebuild the overlay from the start under a new key, never stuck halfway.
