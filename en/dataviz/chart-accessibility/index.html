Chart Accessibility

Complex Images · Chart alt text · Data sonification · aria.decal

Two-tier alternative text for complex images: a short alt/svg aria-label naming type + summary, an in-page long description carrying trends/scale/color order; the carrier of choice is figure role=group + figcaption (visible to everyone), while aria-describedby takes plain text only — plus two non-color channels: direct labels and decal patterns.

Live demo official default
Parameters
Motion▾
decaloff

JS-type param (the demo subscribes and overlays a pattern). A diagonal decal on bars = a second visual channel beyond hue. ECharts' aria.decal.show officially defaults to false (aria.ts verified verbatim) — decals are the colorblind safety net of last resort, and the library ships them off: you must turn them on; ECharts decals are defined in util/decal.ts (dashArrayX/dashArrayY/rotation etc., the demo uses an equivalent SVG pattern).

directLabelon

JS-type param. Every bar carries its value on top. jfly verbatim: "label elements of the graph on the graph itself rather than making a separate color-coded key, since matching same colors in distant places is extremely difficult" (08 §1.1 page verified) — direct labels serve low-vision, colorblind and screen-reader paths at once; switching off degrades to axis ticks only, hurting read precision.

longDesctable

JS-type param (switched via an ARIA tablist; the panel and demo stay in sync). The long-description carrier contrast: the WAI tutorial prefers figure role=group + figcaption — the description stays visible to everyone, benefiting low-vision and learning-disabled users; aria-describedby suits plain text only, and structured tables hung on it get read as run-on paragraphs (WAI verbatim). Both tiers must carry the WAI checklist: trend conclusions/scale/color order/relative heights.

Code breakdown

Structure & DOM

Complex images need “two-tier alternative text” (the W3C WAI complex-images tutorial): tier one is a short alt / svg aria-label naming the chart type + content summary; tier two is an in-page long description carrying trend conclusions, scale, color order and relative heights — visible to everyone, preferably riding figure role="group" + figcaption.

<figure role="group">
  <svg role="img" aria-label="Bar chart: site visits March–August, rising overall, see long description">
    <title>…</title><desc>…</desc>
    …bars and axes…
  </svg>
  <figcaption><!-- long description: table or prose, visible to all users -->
    <table><caption>Site visits March–August</caption>…</table>
  </figcaption>
</figure>

Key points:

  • aria-describedby takes plain text only: hang a structured table on it and screen readers read it as one run-on paragraph (WAI verbatim) — tables belong in figcaption;
  • Summarize the chart in one sentence in the body text before the figure — the tutorial’s own ordering;
  • There must be a second channel beyond hue: direct value labels (jfly: “label elements of the graph on the graph itself rather than making a separate color-coded key”) and decal patterns;
  • The svg carries title + desc as a backstop; interactive tooltips additionally owe the WCAG 2.1 SC 1.4.13 trio (Esc-dismissible/hoverable/persistent, W3C understanding page verified — see the Tooltip & Legend entry).

    <line x1="0" y1="0" x2="0" y2="8" stroke="rgba(255,255,255,.8)" stroke-width="2.5"/>
  </pattern>
</defs>

Motion & Interaction

  • The long description switches via an ARIA tablist: two role="tab" buttons (aria-selected + roving tabindex) + role="tabpanel", arrow keys to switch; in the demo a tab click writes back to the parameter store, keeping panel and view in sync;
  • Sonification notes: mapping values onto sound parameters (this demo’s original sketch: value → pitch, 220–880Hz sine blips) gives blind users a second, audible perception channel; product-level sonification implementations (specific libraries and their defaults) were not verified this round — no specifics cited; WebAudio requires creating the AudioContext after a user gesture (autoplay policy), and playback status announces via aria-live="polite";
  • Decal/label toggles redraw instantly with no transition dependencies; the chart body’s motion discipline (data-layer animation, static axes, final state under reduce) lives in the Chart Animation entry;
  • The screen-reader path never depends on motion: values are always reachable via axis ticks, <title> and the figcaption table — three independent channels.

Real-world examples

  • ECharts v5.5.1 (aria.ts verified verbatim, research 08 §3.4): aria.label.enabled defaults true (auto graphic summary for screen readers), aria.decal.show defaults false — “summary on by default, patterns off by default” is the library’s official a11y stance; decal params (dashArrayX/Y, rotation) sit in util/decal.ts.
  • W3C WAI complex-images tutorial (w3.org verified, supplement 12 §13): alt names “chart type + content summary”, the long description carries trend/scale/color order/relative heights, figure role="group" + figcaption is preferred, aria-describedby takes plain text only — this demo’s whole structure is built to that spec.
  • jfly / Okabe-Ito CUD guide (research 08 §1.1, page verified): “For graphs and line drawings, label elements of the graph on the graph itself rather than making a separate color-coded key” — the original source of the direct-labeling principle; value labels on bar tops apply it directly to bar charts.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
decalon gives colorblind users a texture channel when hue fails; patterns too dense (wide strokes) flower the bar face and hurt label legibilityoff is the official default — solid bars lean on hue alone, so colorblind scenes must fall back to labels/the table
directLabelon reads values without axis or color; on narrow panels the top labels may collide with neighborsoff degrades to axis ticks only: read precision drops and screen readers still have the table, but the low-vision scan channel narrows
longDesctext tier gives the narrative conclusion fastest; weaker for structured proofing than the tabletable tier keeps values copyable and checkable; hung on aria-describedby instead of figcaption, screen readers read it as a run-on paragraph

Working combination: decal=off (official default) + directLabel=on + longDesc=table is the safest factory state; switch decals on for colorblind or grayscale-print scenes; reserve aria-describedby for plain-text summaries — structured data always goes in figcaption.

When to use 4
  • Any chart carrying a conclusion — the two-tier alt + in-page long description so screen-reader and low-vision users get the takeaway
  • Multi-series categorical charts — enable decals (ECharts aria.decal, default false, must be turned on) + direct labels so hue is never the only encoding
  • Compliance/audit contexts — a figcaption data table keeps values copyable and checkable, visible to everyone
  • An enhanced channel for blind data exploration — sonification (values mapped to pitch) as an auditory supplement, sketched in the demo
When not to use 4
  • alt that only says "chart" or "bar chart" — WAI requires type + content summary; an empty alt is a forfeit
  • Hanging a structured table on aria-describedby — screen readers read it as a run-on paragraph (WAI verbatim); put tables in figcaption instead
  • Distinguishing series by color alone with no second channel — colorblind users (NEI: about 1 in 12 men) lose the series entirely
  • Hiding the long description in a tooltip/collapsed panel — WAI prefers it visible to everyone; hiding it leaves screen readers as the only narrow path
Accessibility

This entry is accessibility itself: svg role="img" + aria-label (type + summary) with title/desc as backstop; the long description rides figure role=group + figcaption with trend/scale/color-order/relative-heights filled in; the tablist follows roving tabindex (arrow keys); sonification status announces via aria-live; interactive tooltips must also meet the WCAG 2.1 SC 1.4.13 trio (Esc-dismissible/hoverable/persistent, W3C understanding page verified — see the Tooltip & Legend entry).

Browser support

SVG title/desc, ARIA role/aria-selected/aria-live and figure/figcaption are mature features available in all modern browsers; WebAudio (the demo's sonification sketch) is widely available, but AudioContext must be created after a user gesture (autoplay policies; per-browser policy details not audited this round).

Fallback

If a screen reader lacks SVG title/desc support, the figcaption long description remains visible (no ARIA dependency); the data table is the chart's natural fallback — through broken charts, collapsed CSS and screen-reader contexts, the table still conveys every value on its own; decals rely on SVG pattern and fall back to solid bars on very old environments (keep directLabel on there, as labels become the only non-color channel).
