Data Color Ordering

Series Color Sequence · dataColors Order · Accent Color Strategy · 系列色序 · 灰底彩突出

Series colors are an ordered queue, not a free palette: the official order maximizes adjacent contrast; to emphasize, mute the context series to gray and let only the focal series keep saturation.

Community ★★
Live demo official default
Parameters
Motion▾
orderofficial

JS-type param (the demo subscribes and reassigns series colors). official = series i takes palette slot i (Okabe-Ito's first 5 colors, R grDevices fixed values, light colors first per CUD advice); shuffled = the same set reassigned by a fixed scramble. Carbon's official guidance is strict in-order use to maximize adjacent contrast — shuffling pushes weakly-separated pairs into slots 1–2; Power BI's dataColors works the same way: array order is series order, and a scrambled theme file scrambles every visual.

emphasisgray-context

JS-type param (the demo subscribes and redraws). full-color = every series renders saturated in palette order, for equal-weight multi-series comparison; gray-context = the focal series stays saturated and heavier while the rest mute to the context gray, focusing attention on a single narrative line. The strategy is community practice (Claus Wilke's color chapter and similar); no official numbers exist; the context gray injects via --co-gray. Note: with all series full-color, line-end labels collide — the demo falls back to a legend there, since direct labeling suits single-focal plots.

Geometry▾
accentSeries2

Index of the focal series (1–5). Under the gray-context strategy only this series keeps its palette color and a heavier stroke while the rest drop to the context gray; the full-color strategy treats it like any other. The default of 2 is a demo-chosen example focal point with no official basis — the emphasis slot belongs to the story's protagonist, not necessarily series one.

Color▾
contextGray#B0B0B0

The context gray (CSS-variable param injected onto .demo-stage, consumed by SVG strokes via var(--co-gray, #B0B0B0)). It must be neutral enough — and hold ≥3:1 non-text contrast against both the background and the focal color (WCAG SC 1.4.11) — to read as 'background information' rather than a second datum. The default #B0B0B0 is a common community value, unverified (no official number exists).

Code breakdown

Structure & DOM

“Data color ordering” answers a different question than the categorical palette (see dataviz-categorical-palette): the palette covers which colors exist, the ordering covers which color series i gets, and who is the protagonist. The demo is a 5-series line chart where series i takes palette slot i; the emphasis strategy only changes stroke color and weight:

<div class="stage">
  <svg viewBox="0 0 640 340" role="img" aria-label="Data color ordering demo">
    <!-- Line of series i: stroke = palette[i] (official order)
         Gray context: context strokes = var(--co-gray), focal keeps its palette color + heavier weight -->
    <path class="line" stroke="#E69F00" />
  </svg>
  <div class="readout" role="status"><!-- order / focal / strategy / context-gray chips --></div>
</div>

Key points:

  • Order is contrast: Carbon’s official guidance is to use the 14-color categorical palette “strictly in order to maximize adjacent contrast”; Power BI’s official docs confirm the theme dataColors array order is the series color order — a scrambled theme file scrambles every visual (research 08 §1.3/§4.2);
  • Okabe-Ito practice (official CUD page): light colors first (orange → sky blue → bluish green), the red/green confusable pair (vermillion / reddish purple) reserved for rare classes, capped at 8 classes with class 9 merged into ‘Other’;
  • Gray-context emphasis is hierarchy, not a new color: context series mute to gray and the focal series gains weight — never manufacture an Nth color via alpha or lightness variants.

Styling & Parameters

Three JS-type params plus one CSS-variable param:

/* context gray injected as --co-gray on .demo-stage, consumed by SVG strokes */
.line-context { stroke: var(--co-gray, #B0B0B0); stroke-width: 1.5; }
.line-accent  { /* color stays a palette value; only weight changes */ stroke-width: 3; }

Motion & Interaction

  • Parameter changes redraw immediately with no transition — a color reassignment is a data-mapping change, not a cross-fade performance;
  • Chip state-color changes (background/border 0.2s) are disabled under prefers-reduced-motion: reduce;
  • In gray-context mode the focal series gets a line-end direct label (name + bold); in full-color mode five adjacent end values would collide, so the demo falls back to a legend — direct labels suit a single focal point; equal-weight multi-series still needs a legend (jfly objects to distant legends only where direct labels would fit);
  • Hover readouts use native <title> (series · color name · final month value); full tooltip rules live in dataviz-tooltip-legend.

Real-world examples

  • Power BI report themes: official docs confirm the dataColors array order is the series color order, and the theme JSON also carries good/neutral/bad semantic slots — ordering and semantic emphasis live on separate layers (official docs verified, research 08 §4.2).
  • IBM Carbon: the 14-color categorical palette must be used strictly in order to maximize adjacent contrast; the alert colors danger #da1e28 / serious warning #ff832b / warning #f1c21b / success #198038 are the official anchors for semantic emphasis; red line — no gradients in charts (Apache-2.0, official site verified, research 08 §1.3).
  • ggplot2’s gray canvas: the official docs describe “The signature ggplot2 theme with a grey background and white gridlines” — the panel gray is parameterized as col_mix(ink, paper, 0.92) (theme-defaults.R L271, source-verified, research 08 §5.3), the textbook “gray backdrop makes data colors pop”: a low-saturation canvas lets data colors stand out naturally.

Rules of thumb: take colors in official order, cap at 8 classes; emphasis is zero-sum — one protagonist per chart; hold the context gray at ≥3:1, and run dataviz-colorblind-safe’s three-model simulation when unsure.

When to use 4
  • Dashboard hero cards / KPI storytelling: one protagonist per chart, everything else muted to gray backdrop
  • Multi-series line charts where only one line's trend matters (performance reviews, A/B metric comparisons)
  • Persist the palette as a Power BI theme following dataColors order so every visual takes colors identically (order = assignment order, officially verified)
  • Up to 8 classes in official palette order: Okabe-Ito's 8 colors are the ceiling, class 9 merges into 'Other'
When not to use 4
  • Emphasizing everywhere: keeping context series saturated kills the focal one — emphasis is a zero-sum resource
  • A context gray too close to the background, or under 3:1 separation from the focal color — no hierarchy reads (WCAG SC 1.4.11)
  • Shuffling an official palette — Carbon's red line: strict in-order use to maximize adjacent contrast
  • Manufacturing 'half-emphasis' via alpha or lightness variants — hierarchy comes from gray value and stroke weight, not an invented Nth color
Accessibility

Gray-context is not an accessibility substitute: muted series must stay legible — ≥3:1 non-text contrast against background and neighbors (WCAG 2.1 SC 1.4.11, research 06 §17); the focal point never rides on color alone — line-end name labels, legend swatches and stroke weight are the redundant encodings (CUD principle 2); verify with three-model CVD simulation (see dataviz-colorblind-safe: Viénot for protan/deutan, Brettel mandatory for tritan); for full-color multi-series legends, jfly prefers direct labels.

Browser support

The demo is hand-drawn SVG + React with no reliance on new CSS/JS features; the context gray flows through the var(--co-gray) custom property, supported in all modern browsers, and is injected as hex without depending on oklch().

Fallback

No browser-compat fallback (stroke falls back to the built-in #B0B0B0 if var() fails). The real degradation is strategic: when readers must trace every series' values, gray-context makes context series hard to follow — fall back to the full-color sequence, switch to small multiples, or keep direct labels only for the focal series; past 8 classes, merge into 'Other' before discussing emphasis.
