Dashboard Density

Grid Density · Dashboard Spacing · 信息密度

The density base of BI grids: Grafana's 24 columns × 30px row height × 8px panel gap (source constants) driving Power BI's official example font ladder 45/12/12/10 — a comfortable/compact switch that retunes the whole board's breathing room.

Code breakdown

Structure & DOM

Dashboard density is a two-tier DOM: the “grid container + panels”. The container owns the three constants (columns / row height / gap); panels only declare spans and never care about the grid.

<div class="dash">  <!-- grid: 24 cols × N rows -->
  <div class="panel kpi" style="grid-column: span 6; grid-row: span 3">
    <span class="label">Revenue</span>
    <span class="callout">¥1.28M</span>   <!-- 45px -->
  </div>
  <div class="panel chart" style="grid-column: span 12; grid-row: span 3">…</div>
  <div class="panel table" style="grid-column: span 24; grid-row: span 3">…</div>
</div>
.dash {
  display: grid;
  grid-template-columns: repeat(24, minmax(0, 1fr)); /* Grafana GRID_COLUMN_COUNT=24 */
  grid-auto-rows: var(--dvz-row);                    /* 30px = GRID_CELL_HEIGHT */
  gap: var(--dvz-gap);                               /* 8px = GRID_CELL_VMARGIN */
}
/* Minimum panel = 3 rows = 90px (Grafana MIN_PANEL_HEIGHT=90) */

Key points:

  • The three constants belong to the grid, not the panels: panels declare spans, the container manages spacing — only then do drag layouts hold together;
  • Trade-off vs ECharts/D3: a chart library draws “one panel’s content”; grid density belongs to the dashboard framework (Grafana/Power BI). The hand-drawn mock exists to demonstrate that split: the library ignores gaps, the framework tokens ignore in-chart font sizes — each aligns to its own research values.

comfortable = the research values as-is; compact is a demo-proposed preset: gaps ÷2, rows ×0.8, callout 45→32, label 10→9, title 12→11 — no official compact conventions exist (Grafana docs name Standard/Narrow/Wide presets but publish no pixels; Power BI has no density presets; Tableau’s conventions were not found), so compact values are demo-proposed and unverified.

Motion & Interaction

Density switching is the kind of layout motion to keep on a short leash:

  • Switching density: the whole board’s gaps and font sizes jump instantly (no transition in the demo) — a density preset is a view mode, not animation material; if your product insists, ease gap/padding/font-size over ≤150ms and respect prefers-reduced-motion (instant swap under reduce);
  • Dragging the gap / rowHeight sliders: CSS variables apply instantly with zero JS reflow — exactly the point of CSS-var params (the panel never re-renders);
  • The demo’s dashboard container is overflow: auto: oversized row heights scroll instead of breaking the stage;
  • Panel hover highlights are optional; skip them on high-frequency ops screens.

Real-world examples

  • Grafana: 24 columns × 30px rows × 8px gaps × 3-row minimum panels are all source constants (public/app/core/constants.ts, verified verbatim); the official docs name only Standard/Narrow/Wide and Short/Tall presets with custom px, never publishing pixel values (verified this session).
  • Power BI: the official theme docs’ textClasses give the example ladder callout 45 / title 12 / header 12 / label 10, and dataColors order plus good/neutral/bad semantic colors complete the theme JSON (official docs verified).
  • Tableau: official numeric conventions for default canvas, card gaps and font ladders are unpublished (help pages 404’d, blog 403’d) — no invented values; benchmarking Tableau means measuring its exported files.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
densitycompact fits roughly 40–60% more panels per screen but pushes type to the readability floor — for ops walls, not boardroom projectorscomfortable is the default; 45px callouts and 10px labels breathe for demos and print
gappast 12px the grid texture outshouts the content; on 24 columns the gaps eat usable widthunder 6px panel edges start to fuse — drag handles and hover boundaries get hard to tell apart
rowHeightpast 36px the 3-row minimum panel grows (90px → 108px) and rows per screen dropunder 24px mini-charts flatten vertically and line slopes start lying

Working range: start from gap 8px / row 30px as-is (a decade-hardened value); adopt the Power BI example ladder then tune to viewing distance — projector decks can take callout to 60px.

When to use 4
  • BI/monitoring dashboards with draggable grids — 24 columns × 30px rows × 8px gaps is the drag base Grafana has hardened for a decade
  • KPI cards and big numbers — the official callout 45px example tier: readable at a glance without stealing the chart's job
  • Dense ops/monitoring screens (compact) — more panels per screen by halving gaps
  • Design-token adoption — persist gap/row/font ladder as --dvz-* variables; themes and density presets swap variables only
When not to use 4
  • Porting the 24-column grid to mobile — drag grids are a desktop BI convention; mobile wants card flows
  • Pushing compact further by shrinking type — below label 9px readability collapses and density gains vanish
  • Treating 45/12/12/10 as a mandatory spec — Power BI's docs present them as example values; tune to your product
  • Reusing grid gap as panel padding — panel padding is intra-panel density, a different tier from GRID_CELL_VMARGIN
Accessibility

Density's readability floor: within the 45/12/12/10 ladder, label 10px is far under the WCAG large-text line (≥18.66px bold earns 3:1), so check colors at the 4.5:1 body-text ratio; compact's label 9px sits even closer to the floor — keep dense screens to numbers and short labels. Grafana's calculateSpace() adapts tick spacing in CSS pixels precisely to prevent tick crowding — density may compress, axis ticks may never overlap; drag handles under compact still need a ≥24px hit area.

Browser support

The demo uses CSS Grid repeat(24, minmax(0,1fr)) plus calc() for the compact preset — available in all modern browsers; no JS layout dependency (params only touch CSS variables and a data attribute).

Fallback

No compat issue; the real fallback is narrow viewports: a 24-column grid degrades to a single-column stack on narrow containers (CSS Grid auto-fit or container queries), ordered by information priority; the compact preset's floor is readability — at label 9px you are near the AA readability floor, and below that trade density for whitespace.
