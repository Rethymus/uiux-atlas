Chart Axes & Grid

Axis Lines · Gridlines · splitLine

The chart's 'table lines' discipline: grids stay faint (Grafana inverts the theme text color at 9% alpha), axis lines are optional (ECharts vs ggplot2 take opposite defaults), tick counts stay restrained (ECharts splitNumber defaults to 5) — three params decide a line chart's professionalism.

Component Lib ★★
Live demo official default
Parameters
Geometry▾
gridOpacity0.09

CSS-var param (injected by DemoStage). Gridline opacity; the 0.09 default matches Grafana's getGridColor() formula verbatim — 9% alpha of the theme-inverted text color (dark rgba(240,250,255,.09) / light rgba(0,10,23,.09)); ECharts' equivalent is the solid #E0E6F1 (≈0.12 visual equivalent on white). 0 = no grid, 1 = gridlines as heavy as text.

tickCount5

JS-type param (the demo recomputes nice ticks on change). Tick count; the default of 5 matches ECharts splitNumber: 5 verbatim (6 for time axes); the demo rounds step size via the classic nice-ticks algorithm (1/2/2.5/5 × 10ⁿ), so the realized tick count may land 1–2 short — same as real chart libraries.

Motion▾
axisLineon

JS-type param (the demo subscribes and redraws). on = axis lines #6E7079 at width 1 (ECharts axisDefault defaults, verified verbatim); off = the ggplot2/Grafana route — ggplot2 removes axis lines via element_blank() by default, expressing the coordinate system as grey panel + white grid; Grafana hides axis borders by default. Both official routes are legitimate; the constant is 'keep the grid, keep it faint'.

Code breakdown

Structure & DOM

Axis lines and grids are the “reference layer”, separate from the data layer: in one SVG, grid and axes render at the bottom, data lines on top — references never occlude data.

<svg viewBox="0 0 600 340">
  <!-- Reference layer: value-axis horizontal grid (opacity: var(--dvz-grid-op)); no grid on the category axis -->
  <g class="grid"><line x1="46" x2="554" y1="…" y2="…" stroke="currentColor" /></g>
  <!-- Axis layer: #6E7079 width 1; tick length 5; the whole layer may hide (ggplot2 route) -->
  <g class="axes" stroke="#6E7079"><line … /><line … /></g>
  <!-- Label layer: fontSize 12 / margin 8 -->
  <text x="38" y="…" text-anchor="end">25</text>
  <!-- Data layer -->
  <polyline points="…" stroke="#0072B2" stroke-width="2.5" />
</svg>

Key points:

  • Horizontal grids belong to the value axis only: ECharts source forces the category axis’ splitLine off — grid semantics are “what is the value”, and categories have none;
  • Grid color uses currentColor (inherited text color) + opacity: a demo-friendly rendering of Grafana’s formula — each theme inverts toward its text color at 9%, no second grey to maintain;
  • Trade-off vs ECharts/D3: ECharts/D3 axes are config objects (axisLine.show / splitNumber / axisLabel.margin) with all defaults built in; hand-drawn SVG makes every default visible and individually overridable — prototype with the library, then audit its defaults one by one against this entry’s research values.

License backdrop: ECharts and Grafana are Apache-2.0 (source headers/LICENSE verified), ggplot2 MIT-family; the FT poster is copyrighted and must not be reproduced — cite the principle only.

Motion & Interaction

The reference layer’s motion principle: grids and axes never animate.

  • Switching axisLine / dragging tickCount: data and ticks recompute and redraw instantly, no transition — if tick positions animated, readers would misread “moving ticks” as “moving data”;
  • gridOpacity rides a CSS variable: the slider applies with zero JS reflow;
  • Data-line entrance animation (if any) animates only stroke-dashoffset or opacity, disabled under reduce; hovering a point shows a native <title> (series · month · value);
  • The demo has no sustained animation and respects prefers-reduced-motion.

Real-world examples

  • ECharts v5.5.1: the default is “axis lines optional, grid kept and faint” — in a cartesian pair, the value axis’ axisLine/axisTick flip to auto (not drawn) while splitLine defaults on at #E0E6F1 (axisDefault.ts verified verbatim; master has tokenized default colors — watch tokens.color.axisLine on major upgrades).
  • Grafana (on uPlot): getGridColor() hard-codes the grid as “9% of the theme-inverted color”, flipped between dark and light; axis borders are hidden by default, axis text uses the theme’s primary text color with labelPad = 8 (UPlotAxisBuilder.ts verified verbatim).
  • ggplot2: the signature “grey panel, white grid” theme — axis lines removed by default, panel background at col_mix(ink, paper, 0.92), minor gridlines at half width (theme-defaults.R L194/L271/L276 verified) — the academic origin of the “grid expresses the coordinate system, axis lines optional” route.
  • FT Visual Vocabulary: the authoritative baseline wording “Column must always start at 0 on the axis”; line charts may start elsewhere (citing ONS and Quartz); the poster is © FT and needs syndication to republish (README verified) — cite the principle, never reprint the poster.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
gridOpacitypast 0.3 the grid outshouts the data and a line chart reads as a table; at 1 the grid weighs as much as textbelow 0.05 it’s near-invisible — value reading falls to point labels; at 0 you must add tooltips/direct labels
axisLineon gives the chart a definite frame, sturdier in print and pale themes; drawing both axes doubles the frame feeloff is the ggplot2/Grafana minimal route with the least visual noise — valid only while the grid stays and labels align
tickCount8 classes crowd a 300px-tall chart — at 12px labels the class gap drops under 38px; the rounding algorithm will merge classes anyway2–3 classes is maximal restraint for overviews but cuts reading precision; interactive value-picking wants 5+

Working range: gridOpacity 0.05–0.15 (Grafana’s 0.09 sits mid-range), 4–6 tick classes, axis lines “keepable on light, droppable on dark”; in every case: no horizontal grid on the category axis, and a zero baseline for bars.

When to use 4
  • Grid tuning for line/area/bar charts — the grid is the value ruler: faint enough to ignore, present enough to read
  • Dark-theme dashboards — invert the grid color toward the theme's text color at 9% (Grafana's formula); don't copy the light theme's grey
  • Minimal-style charts (no axis lines) — ggplot2's grey-panel-white-grid or Grafana's hidden borders
  • Print/export contexts — raise gridOpacity or thicken axis lines; the screen's 9% vanishes on paper
When not to use 4
  • Grids heavier than the data (gridOpacity > 0.3) — readers see the table before the data
  • More than 8–10 ticks — ECharts' default of 5 is deliberate restraint; cramming ticks forfeits nice step rounding
  • Bar charts not starting at 0 — the FT/ONS zero-baseline principle; truncated bars amplify differences
  • Horizontal gridlines on category axes — ECharts source forces category-axis splitLine off; horizontal grids belong to the value axis
Accessibility

Axis text (fontSize 12, margin 8) needs ≥4.5:1 against the backdrop (ECharts' #6E7079 mid-grey passes on light; on dark themes switch to the theme text color); grids carry no information so 3:1 non-text contrast is not required of them, but axis and tick lines that do carry scale semantics need ≥3:1 against adjacent colors (WCAG 2.1 SC 1.4.11); at gridOpacity 0, data points must carry value labels or tooltips or low-vision and screen-reader users lose the value channel.

Browser support

The demo is hand-drawn SVG + CSS variables with no cutting-edge dependencies; grid opacity rides on CSS opacity over SVG elements, axis lines/ticks/labels are plain SVG.

Fallback

No compat issue; the real fallback is the zero-baseline discipline: grids and axis lines may go, but the baseline rule may not break — bar/area charts must start at 0 (FT Visual Vocabulary: Column "Must always start at 0 on the axis"), line charts may not start at zero but should hint truncation on the axis; if readers can't read values once the grid is gone, add direct labels instead of restoring the grid.
