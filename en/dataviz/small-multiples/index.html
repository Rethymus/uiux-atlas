Small Multiples

Trellis Chart · Lattice Chart · Panel Chart · Grid Chart

A row of similar small charts at one shared scale and axes: each panel tells a single series, and cross-panel comparison works only because every panel shares the same ruler — Tufte's defining requirement; the dual-axis mashup is its exact opposite.

Parameters
Motion▾
layoutmultiples

JS-type param (the demo subscribes and switches). multiples = four regions, one small panel each, all panels sharing one y domain (0–100) — the defining form; dual-axis = the same four lines crammed into one chart, East/South on a left axis of 0–100 and North/West on a right axis of 0–70: each group is stretched by its own axis and crossings no longer mean anything — exactly the anti-pattern the shared-scale discipline exists to prevent.

scaleModeshared

JS-type param (applies in multiples mode only). shared = every panel spans 0–100 so line heights read as magnitudes across panels — the defining requirement; independent = each panel scales to its own max (East 0–100 / South 0–90 / North 0–70 / West 0–50), the Wikipedia-documented "deliberately different scales to stress relative change" variant — shape comparison survives, magnitude comparison dies, and each panel must carry its own scale ceiling.

Code breakdown

Structure & DOM

Small multiples are “similar small charts juxtaposed at one shared scale and axes”: each panel tells a single series, and cross-panel comparison works only because every panel shares the same ruler. Also known as trellis / lattice / grid / panel charts; popularized by Edward Tufte — Envisioning Information (1990, p.67): “the core of quantitative reasoning is one sentence: compared to what?”

<div class="multiples"> <!-- display:grid; gap: var(--sm-gap) -->
  <svg role="img" aria-label="East: Jan-Dec index, scale 0-100">…one line…</svg>
  <svg role="img" aria-label="South: Jan-Dec index, scale 0-100">…</svg>
  <svg role="img" aria-label="North: Jan-Dec index, scale 0-100">…</svg>
  <svg role="img" aria-label="West: Jan-Dec index, scale 0-100">…</svg>
</div>

Key points:

  • The shared scale is the defining requirement: all four panels span the same y domain (0–100 in this demo) so line/bar heights read as magnitudes across panels;
  • A mini keeps only the baseline + ceiling tick + direct label — no full grid or legend furniture (reference-layer discipline lives in the Chart Axes entry); the panel title carries the series name and the latest value — jfly’s own words: “label elements of the graph on the graph itself rather than making a separate color-coded key, since matching same colors in distant places is extremely difficult”;
  • The map-domain research conclusion (Wikipedia article): animation wins at presenting trend and motion; small multiples win at comparison between time points — the two forms divide labor rather than replace each other;
  • The anti-pattern is the dual-axis mashup: many series in one chart, two axes split among them — every series is stretched by its own axis and crossings no longer constitute any comparison.

  grid-template-columns: repeat(2, 1fr);
  gap: var(--sm-gap, 8px);          /* panel gap: Grafana GRID_CELL_VMARGIN */
}
.multiples svg { color: var(--text); }  /* reference lines: currentColor + opacity .09 */

Motion & Interaction

Small multiples are a static array — they barely need motion:

  • Switching layout / scaleMode redraws instantly with no transition — if scale changes animated, readers would misread “the ruler moving” as “the data moving” (same discipline as the Chart Axes entry);
  • panelGap rides a CSS variable: the slider applies with zero JS reflow;
  • Hovering a point shows a native <title> (series · month · value); panel switches keep only a 0.2s opacity micro-transition, removed under prefers-reduced-motion;
  • If you do play panels over time (time-slice animation), the map research warns: animation expresses motion/trend, while precise between-timepoint comparison still belongs to side-by-side panels.

Real-world examples

  • Wikipedia’s “Small multiple” article: the definition, the trellis/lattice/grid/panel aliases, the independent-scale “deliberately different scales to stress relative change” variant, and the map-domain conclusion “animation for trend/motion, small multiples for between-timepoint comparison” (supplement 12 §13, page verified) — the variant is legitimate only when each panel labels its own scale ceiling.
  • Grafana dashboard grid: public/app/core/constants.ts hard-codes GRID_COLUMN_COUNT = 24, GRID_CELL_HEIGHT = 30, GRID_CELL_VMARGIN = 8, MIN_PANEL_HEIGHT = 90 (research 08 §4.1, source-verified) — panel arrays ship with source-level spacing/minimum defaults; the official docs give tier names but no pixels (verified), so copy the source constants.
  • jfly / Okabe-Ito CUD guide: the original “on-graph labels beat remote color keys” wording (research 08 §1.1, page verified) — minis have no room for legends, so series name + latest value in the panel title is that principle applied directly.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
layoutdual-axis mode interleaves North (0–70 axis) with East (0–100 axis); “North looks higher” is pure right-axis stretching — crossings mean nothingmultiples keeps one ruler across four panels; more series means more rows/columns and smaller minis
scaleModeindependent tops out every series in its own panel: shape differences get amplified (the Wikipedia variant’s purpose) while cross-panel magnitude comparison dies, and every panel needs a ceiling labelshared restores “height = magnitude”; the cost is low-range series (West 22–47) reading as flat
panelGappast 24px the array falls apart and whitespace eats the data area; the grid feel disappearsbelow 4px adjacent panels start gluing together and may read as one chart; 0px removes all grouping

Working range: panel gap 8–16px (Grafana’s 8px sits at the low end), one line + one direct label per panel, shared scale as the default and labeled ceilings whenever independent; the dual-axis mashup should never substitute for a multiples array when units match.

When to use 4
  • Same-unit metrics across regions/products/sites — one series per panel, magnitudes readable at a glance
  • Time series sliced into per-period panels — map research: between-timepoint comparison favors small multiples over animation
  • Dashboard panel arrays — Grafana's 24 columns × 30px row × 8px gap grid is the engineering precedent
  • The independent-scale variant stressing shape/trend — a deliberate Wikipedia-documented use, but label every panel's scale
When not to use 4
  • Cramming series into one chart and "solving" scale clashes with dual axes — crossings imply nothing, the demo's contrast case
  • Independent scales on same-unit data without labels — readers misjudge a stretched 0–50 panel as higher
  • Different-unit series on one ruler (% vs. counts) — convert or split panels; never share the axis
  • Restoring full axis furniture inside each panel — minis keep only baseline, ceiling tick and direct labels; see the Chart Axes entry for reference-layer discipline
Accessibility

Give each panel svg role="img" and an aria-label naming series + period + metric; put the cross-panel takeaway (who's highest, biggest gap) in a text summary outside the chart so screen-reader users get conclusions without scanning four minis; use the Okabe-Ito palette (hex as fixed in R grDevices, research 08 §1.1) and direct-label the latest value in the panel title (jfly: on-graph labels beat remote color keys); below a 4px gap adjacent panels may read as one blob, and any touch targets stay ≥24px.

Browser support

The demo is CSS Grid + hand-drawn SVG with no cutting-edge dependencies; panel switching is an instant redraw with no transition dependencies.

Fallback

No compat fallback; the real fallback is principle-level: when the array truly won't fit, go faceted with explicit per-panel scales instead of returning to dual axes; independent mode must label each panel's scale ceiling (a 0–50 mini next to a 0–100 mini without labels is a lie); if panels overflow, cut series before cutting the shared scale.
