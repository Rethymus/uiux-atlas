Chart Selection

Chart Chooser · Visual Vocabulary · 图表类型选择 · 选型决策树

Identify the data relationship first, then pick the chart: compare → bars, trend → lines, distribution → histogram, composition → stacked bars; columns/areas must start at zero, line charts may not.

Community ★★
Live demo official default
Parameters
Motion▾
relationcompare

JS-type param (the demo subscribes and redraws the SVG). Each relationship maps to one baseline chart: compare → bar chart (length encoding compares best at equal widths), trend → line chart (evolution over time), distribution → histogram (binned counts), composition → stacked bars (part-to-whole). A mismatched relationship (pie chart for a time trend, line for discrete classes) is far more damaging than a styling flaw — selection is the first readability decision.

baselinezero

JS-type param (the demo subscribes and recomputes the y domain). zero = axis starts at 0; truncated = the y floor rises near the data to magnify differences. FT's rule: columns "Must always start at 0 on the axis", summarized as 'columns/areas must start at zero'; line charts may skip zero (FT cites two ONS pieces, 'Does the axis have to start at zero?'), lollipop charts are exempt. When bar-family charts truncate, the demo raises a Carbon-danger (#da1e28, officially verified) warning chip — demo data 49 vs 78 differ 1.6× from zero, 4.2× when truncated at 40.

labelsdirect

JS-type param (the demo subscribes and switches annotation mode). direct = values/series names written on the marks themselves (bar tops, line ends, segment centers); legend = a color-key at the right. jfly CUD verbatim: "For graphs and line drawings, label elements of the graph on the graph itself rather than making a separate color-coded key, since matching same colors in distant places is extremely difficult." Direct labels come first; when they do not fit (stacked segments under 14px tall) they are omitted and a legend takes over.

Code breakdown

Structure & DOM

Selection happens before the SVG: identify the data relationship first, then decide the form. The demo hosts all four baseline charts in one <svg>, switching only the mix of <rect> / <path> / <text>:

<div class="stage">
  <svg viewBox="0 0 640 340" role="img" aria-label="Chart selection demo: baseline charts switched by data relationship">
    <!-- Compare: a row of <rect>; trend: one <path> + points;
         distribution: axis-hugging histogram <rect>; composition: four stacked <rect> per quarter -->
  </svg>
  <div class="map">   <!-- the four-relationship → four-chart mapping strip -->
  <div class="readout" role="status"><!-- baseline rule / annotation chips --></div>
</div>

Key points:

  • The compare / trend / distribution / composition taxonomy is the community-standard classification of chart choosers (the FT Visual Vocabulary poster organizes chart families by data relationship; this research did not transcribe its full family tree, so the taxonomy is not attributed to FT);
  • The default relationship → chart mapping: compare → bars (equal-width length encoding compares best), trend → lines (evolution over time), distribution → histogram (binned counts), composition → stacked bars (part-to-whole);
  • The zero-baseline rule (FT chart-doctor README verbatim, research 08 §5.4): Column “Must always start at 0 on the axis”, summarized as “columns/areas must start at zero”; line charts may skip zero (FT cites ONS’ “Does the axis have to start at zero?”), lollipop charts are exempt.

Styling & Parameters

All three parameters are JS-type; the demo subscribes to the store and redraws, no CSS variables:

/* the demo uses only fill/stroke + 1px axis lines, no chart library */
.cs-bar { stroke: var(--border-strong); stroke-width: 1; }
/* the truncation warning chip uses Carbon danger #da1e28 (official site verified, research 08 §1.3) */
.cs-chip[data-warn="true"] { color: #da1e28; border-color: #da1e28; }
ParameterDefaultWhere the numbers come from
relationcompareThe four-relationship mapping is the community-standard taxonomy; each option pairs with one baseline chart (bar/line/histogram/stacked)
baselinezeroFT rule: bar family at zero, lines exempt (README verified); truncated raises the #da1e28 warning on the bar family
labelsdirectjfly CUD verbatim: direct labels beat distant color keys (research 08 §1.1); segments under 14px tall drop their labels and fall back to a legend

All demo data is deterministic: compare has 4 classes (64/49/78/57), trend 12 months, distribution 8 bins (40 samples), composition 4 quarters × 4 segments. The truncation distortion is computable: 49 vs 78 differ 1.6× from zero — 4.2× when truncated at 40. That is the geometric reason “columns must start at zero”.

Motion & Interaction

  • Parameter changes redraw immediately with no transition — data-mapping changes should not disguise themselves as color cross-fades (same rule as dataviz-categorical-palette);
  • The baseline warning chip is the only state-color change (0.2s border/color transition), disabled under prefers-reduced-motion: reduce;
  • Switching direct labels / legend only adds or removes <text> and the legend group; the marks themselves do not move;
  • Hover readouts use native <title> (hoverable, gone when the pointer leaves); the full WCAG 1.4.13 triad lives in dataviz-tooltip-legend.

The README closes with an FT copyright notice — reprinting requires syndication clearance — cite the principles, do not reprint the poster (README verified, research 08 §5.4).
  • The ONS zero-baseline debate: FT’s repo cites two UK Office for National Statistics pieces, “Does the axis have to start at zero?”, on when line charts may leave zero — the authoritative origin of the “columns zero, lines exempt” pairing (cited via research 08 §5.4; the ONS originals were not directly verified).
  • Cleveland & McGill, Graphical Perception: the methodology citation printed on FT’s poster — the experimental source of the encoding-precision ranking, i.e. the literature behind “why bars beat pies”; the detailed ranking lives in the paper and was not transcribed into this research.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
relationswitching to composition: segments are hue-only, middle baselines drift with the stack — the easiest place to misreadcompare is the steadiest form: equal-width bars on zero, the highest-precision encoding
baselinetruncated on the bar family is a red-line error: the demo gap grows from 1.6× to 4.2×; on the line chart it is legitimatezero is the only safe bar-family setting; in distribution mode truncation would also clip the first bin (count 2) away entirely
labelslegend frees plot area but forces long-distance color matching (jfly: extremely difficult); right for dense charts where labels cannot fitdirect puts numbers on the marks with zero look-back; dense small segments degrade back to a legend automatically

Rules of thumb: settle the relationship before styling; bar family always starts at zero; direct labels first, legend as fallback; annotate a truncated line-chart axis range.

When to use 4
  • Run the four-relationship question on any new dataset before picking a chart — compare/trend/distribution/composition settles it in one step
  • Use the zero-baseline rule to spot misleading charts in review: any truncated bar family is a flag
  • Line charts may legitimately truncate the axis to show movement — annotate the range so readers do not over-read magnitude
  • Dense dashboards prefer direct labels to reclaim legend space; hover readouts go to tooltips (see dataviz-tooltip-legend)
When not to use 4
  • Pie charts for time trends, lines connecting discrete classes — relationship mismatch is the primary source of misleading charts
  • Truncated axes on bar/histogram/stacked/area charts (FT red line); switch to a line or dot plot if truncation is truly needed
  • Comparing middle stacked segments across stacks — their baselines drift with the pile; only the first segment sits on zero and reads precisely. Use grouped bars for cross-series comparison
  • A distant color legend where direct labels would fit — jfly verbatim: matching colors from afar is extremely difficult
Accessibility

Chart elements hold ≥3:1 non-text contrast against adjacent colors (WCAG 2.1 SC 1.4.11, research 06 §17); direct labels spare readers long-distance color matching (jfly CUD); the SVG needs role="img" plus an aria-label stating the chart's purpose, per-point values via native <title>, and the full hover triad (dismissible/hoverable/persistent) lives in dataviz-tooltip-legend; color stays a redundant channel — text and position carry the key distinctions (CUD principle 2).

Browser support

The demo is hand-drawn SVG + React with no reliance on new CSS/JS features; available in all modern browsers. The y domain and bar geometry are computed in JS with no layout-engine dependency.

Fallback

No browser-compat fallback; the real 'fallback' is selection correction: when the relationship was misjudged (a time trend drawn as composition, a distribution drawn as a line), go back to the relationship question and change the chart type instead of polishing styles. Where direct labels do not fit, fall back to a legend with swatches mapped one-to-one to series. SVG text uses <text>, not bitmaps, so it scales, selects and reads out.
