Categorical Palette

Qualitative Palette · Categorical Color Scheme · 定性色标

A qualitative scheme whose colors are distinctly different yet mutually equivalent: take colors in the official order, cap at 8 classes, and let lightness differences secure adjacent contrast.

Community ★★★

Parameters
Motion▾
paletteokabe-ito

JS-type param (demo subscribes and redraws the SVG). okabe-ito: 8 colors fixed by R grDevices (source-verified); the demo puts light colors first per CUD advice (orange → sky blue → bluish green), with official black #000000 last and outlined for dark themes. carbon: IBM's official 14-color categorical palette, to be taken strictly in the official order with no skips (verified on the official site, Apache-2.0). tableau10: hex corroborated by R source comments (Maureen Stone & Cristy Miller); the official blog post returned 403 and the official license is unverified.

layoutgrouped

JS-type param (demo subscribes and redraws). grouped = bars side by side within each group, best for comparing a single series across groups; stacked = segments piled within each group, best for part-to-whole totals — but stacked segments are distinguished by hue alone, the weak spot under color-vision deficiency (check with the dataviz-colorblind-safe entry).

Geometry▾
series4

Number of series (= classes). Okabe-Ito's 8 colors are the practical ceiling of a qualitative palette — merge class 9 into 'Other'; Carbon's 14 colors support up to 14 classes but must still be taken in the official order to maximize adjacent contrast. The default of 4 is a readable baseline for a multi-series bar chart.

Code breakdown

Structure & DOM

A categorical palette only answers “which series gets which color”: it is a hex table ordered by the official sequence, and a chart assigns series i the i-th value — the order must never be shuffled.

<svg viewBox="0 0 640 340">
  <!-- Bar of series i: fill = palette[i], i increments in official order from 0 -->
  <rect class="bar" fill="#E69F00" />  <!-- series 1: orange -->
  <rect class="bar" fill="#56B4E9" />  <!-- series 2: sky blue -->
  <rect class="bar" fill="#009E73" />  <!-- series 3: bluish green -->
  <!-- Legend swatches map one-to-one to series; 1px outline covers black / dark themes -->
</svg>

Key points:

  • Order is contrast: Carbon’s official guidance is to use the 14-color categorical palette “strictly in order to maximize adjacent contrast” — skipping colors weakens the separation between classes 1 and 2;
  • The demo puts light colors first (orange → sky blue → bluish green) with the official black #000000 last — on dark themes the black bar stays legible via a 1px outline, same for swatches;
  • Trade-off vs ECharts/D3: ECharts/D3 ship built-in schemes (category10, tableau10, …) and assign series colors automatically, but keeping “official order only” is on you; hand-drawn SVG buys byte-exact color control and direct reconciliation with design tokens — prototype with a chart library, then promote the palette into tokens and decide whether to migrate back.

Motion & Interaction

A palette is a static asset; chart motion stays auxiliary:

  • Switching palette / series / layout from the panel redraws the chart with no transition (data-mapping changes should not disguise themselves as color cross-fades);
  • Hovering a bar shows a native <title> tooltip (series · quarter · value), honoring the WCAG 1.4.13 baseline of hoverable and dismissible; full tooltip rules live in dataviz-tooltip-legend;
  • The demo has no entrance animation and respects prefers-reduced-motion; if you add growing-bar animation, animate only height/transform and drop it under reduce.

Real-world examples

  • IBM Carbon Charts: the official dataviz color-palettes page publishes the 14-color categorical palette and requires strict in-order usage; the same page draws a red line — no gradients in charts: “Multiple gradients are often inaccessible and are discouraged” (official text verified).
  • R grDevices: Okabe-Ito is not R’s default palette (R ≥ 4.0 defaults to the HCL-based “R4”) — it is the named built-in of palette.colors(palette = "Okabe-Ito"), with hex constants fixed in grDevices/R/colorstuff.R (source-verified).
  • Power BI report themes: official docs confirm the dataColors array order in a theme JSON is the series color order — persist the palette as a theme file and every visual inherits it (official docs verified).

Working range: 2–6 series is comfortable; 7–8 warrants a simulation pass — run dataviz-colorblind-safe’s three modes when unsure.

When to use 4
  • Series colors for multi-series bar/line charts — fix orange → sky blue → bluish green as the first three, reserving the red/green confusable pair for rare classes
  • Commercial products needing a clean license — IBM Carbon's 14-color palette (Apache-2.0) is the only one of the three references with an explicit open-source license
  • palette.colors(palette = "Okabe-Ito") in R graphics and academic figures
  • Power BI theme dataColors arrays — official docs confirm the array order is the series color order
When not to use 4
  • Ordered data (intensity, grades) — a qualitative palette implies no order; switch to an ordinal scale (see dataviz-ordinal-scale)
  • Cramming more than 8–14 classes — merge class 9+ into 'Other'; readers cannot match the swatches back
  • Gradients on categorical fills — Carbon's official red line: no gradients in charts, "Multiple gradients are often inaccessible and are discouraged"
  • Manufacturing a 'ninth color' via alpha or lightness variants of existing swatches — breaks both equivalence and CVD separability
Accessibility

A qualitative palette is not automatically colorblind-safe: Okabe-Ito was 'repeatedly experimentally screened across color-vision types', yet stacked segments and adjacent fills still need simulation checks (see dataviz-colorblind-safe); jfly's CUD principle 2 requires redundant encoding via shape/line-style/texture beyond color; Carbon requires ≥3:1 non-text contrast between chart elements and adjacent colors (WCAG 2.1 SC 1.4.11); when series exceed what readers can match back in a legend, jfly recommends direct labeling on the graph.

Browser support

The demo is hand-drawn SVG + React with no reliance on new CSS features; available in all modern browsers. Carbon's dataviz guidance additionally requires chart elements to hold 3:1 non-text contrast against adjacent colors (WCAG 2.1 SC 1.4.11).

Fallback

No browser-compat issue; the real fallback is over-capacity: beyond the palette ceiling (8 for Okabe-Ito), extra series should merge into an 'Other' class or gain shape/texture redundancy instead of inventing a ninth color. Tableau 10's redistribution license is unverified — assess it yourself before shipping it in commercial products.
