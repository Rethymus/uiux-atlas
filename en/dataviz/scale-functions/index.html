Scale Functions

d3-scale · linear scale · log scale · normalize interpolate · domain range

The mother formula of all mapping: a linear scale is normalize ∘ interpolate, y = r0 + (x−d0)/(d1−d0) × (r1−r0); the log scale runs the same pipeline in log space — domain→[0,1]→range, with adjustable domain/range computed live.

Lower domain end d0 (data units). Must be >0 in log mode: the demo falls back to 1 with a warning when d0≤0 (log is undefined at 0 and negatives).

Upper domain end d1. Defaults pair with range 0→640 as the verified sample: scaleLinear(0,100,0,640)(50) = 320; in log mode with domainMin=1, domainMax=1000 you get the verified scaleLog(...)(10)=213.33.

rangeMin0px

Lower range end r0 (output units — px, channel, opacity…). The scale is agnostic to output units: bar heights, color-ramp positions and opacities all ride the same formula.

rangeMax640px

Upper range end r1 (px). Default 640 is the verified sample value; d3 semantics: out-of-domain input extrapolates unless you call clamp(true).

Code breakdown

Structure & DOM

The demo is a draggable mapping pipeline: one input-value slider (in data units) drives two readings — the normalized t and the mapped output y — while the full domain→range curve plots beside them with the current input marked as a point:

<div class="sf-panel">
  <input type="range" min="0" max="100" value="50" /><!-- input x (data units) -->
  <code>t = (50 − 0)/(100 − 0) = 0.5</code>          <!-- normalize -->
  <code>y = 0 + 0.5 × (640 − 0) = 320px</code>       <!-- interpolate -->
  <svg><!-- curve + current point --></svg>
</div>

Key points:

  • The readings split strictly in two — normalize (x→t) and interpolate (t→y) — which is exactly d3’s continuous.js composition;
  • The curve flips with the transform: linear is a straight line, log bends downward (every decade equidistant);
  • Switching to log with a domain containing ≤0 clamps to 1 with a warning — the log domain boundary, made visible instead of silent.

Styling & Parameters

Five parameters (transform/domainMin/domainMax/rangeMin/rangeMax), subscribed by the demo, mapped with zero dependencies. The formulas (research 14 §8 — the source IS the formula: d3-scale/src/continuous.js and log.js read directly):

① linear scale = normalize ∘ interpolate (two-segment affine):

const scaleLinear = (d0, d1, r0, r1) => x => r0 + ((x - d0) / (d1 - d0)) * (r1 - r0);
scaleLinear(0, 100, 0, 640)(50);  // 320 — verified ✓ (golden sample)

② log scale = the same pipeline run in log space:

const scaleLog = (d0, d1, r0, r1, b = 10) => {
  const lb = Math.log(b);
  return x => r0 + ((Math.log(x)/lb - Math.log(d0)/lb) / (Math.log(d1)/lb - Math.log(d0)/lb)) * (r1 - r0);
};
scaleLog(1, 1000, 0, 640)(10);    // 213.33 (one decade = 1/3 of the range) — verified ✓

d3 implementation detail: transformLog(x) = Math.log(x) wraps the same transformer; negatives/mirrors take the −log(−x) branch.

③ Isomorphic sightings (the same formula in three settings):

// Scroll progress normalization (the JS twin of scroll-driven animations, research 14 §6.2)
const viewProgress = (scrollY, elTop, elH, vh) =>
  Math.min(1, Math.max(0, (scrollY - (elTop - vh)) / (elH + vh)));
// Utopia clamp: S(vw) = clamp(min, intercept + slope × vw, max) — the same linear regression (modular-scale-math)

Verified output (run here): linear midpoint 50→320 ✓; log’s 10→213.33 (one decade exactly 1/3 of the range) ✓.

Motion & Interaction

  • Drag the input slider: t and y update per frame as the point slides along the curve — every step of “normalize first, map second” visible;
  • Switch to log: the line bends into a log curve; switching log with domain 0→100 clamps to 1 and raises a warning — the domain boundary is never silent;
  • Adjust domain/range: compressing the domain (0→20) steepens the slope — “the data range sets the mapping gain”, readable directly off the curve;
  • Every interaction is user-driven, no autonomous animation; the entrance fade respects prefers-reduced-motion.

Real-world examples

  • d3-scale: the normalize(x) = (x−a)/(b−a) / interpolate composition in continuous.js is this entry’s formula; Observable Plot and most charting libraries carry the same scale thinking — the shared foundation of dataviz (source read and verified);
  • CSS scroll-driven animations: the JS twin of animation-range: cover 0% cover 100% semantics is precisely the viewProgress normalization (research 14 §6.2, Chrome’s official write-up on range semantics); this site’s scroll-driven-animations entry is its CSS form;
  • OKLCH color ramps (upstream of dataviz-ordinal-scale): the research-verified red→blue OKLCH five-station ramp (255,0,0 → 229,0,122 → 183,0,185 → 122,23,225 → 26,51,229) — feeding t∈[0,1] into OKLCH interpolation (short-arc H); the magenta midpass is the signature of a perceptually uniform ramp, where sRGB-space interpolation would gray out midway (research 14 §8.3).

Working doctrine: first ask “how many orders of magnitude” — zero says linear, ≥2 says consider log; always clamp before mapping scroll/progress; when outputting color, let the scale emit t and let the ramp layer interpolate. Sibling entries: dataviz-ordinal-scale (the t→ramp segment), scroll-driven-animations (CSS-native normalization), modular-scale-math (the isomorphic clamp regression), dataviz-chart-axes (scales made visible).

When to use 4
  • Chart axes: the first line of any d3-style chart is a scale
  • Scroll progress normalization: p=(scrollY−start)/(end−start) → offsets/opacity (the JS twin of scroll-driven animations)
  • Palette generation: scales map data to [0,1] before color-ramp interpolation (upstream of dataviz-ordinal-scale)
  • Sensor/financial data spanning orders of magnitude: log scales put 1 and 1000 equidistant on the plot
When not to use 4
  • Feeding 0 or negatives to a log scale — undefined at zero, meaningless extrapolated negative; shift or mirror first
  • d0=d1 (divide by zero) or r0=r1 (constant mapping) — the demo blocks the former; the latter deserves a constant, not a scale
  • Linear scales for exponential data — one towering bar, everything else flat; past a 2-orders-of-magnitude spread, switch to log
  • Forgetting clamp semantics: d3 extrapolates by default, out-of-domain in → out-of-range out — the readout flags whether extrapolation is active
Accessibility

Scales decide the fairness of 'value → visual': the wrong linear/log choice makes one dataset tell opposite stories — axis ticks and scale type must be declared on the chart; log axes need 10ⁿ tick labeling; color-ramp mapping must keep lightness monotone (perceivable order) or colorblind users cannot rank values (the dataviz-colorblind-safe entry); this entry's formula handles mapping only, never a substitute for axis labeling and readability checks.

Browser support

Pure JS math with no platform variance; SVG/Canvas/CSS outputs bring their own evergreen support. CSS has no native scale function — either precompute in JS or let clamp()/calc() carry the linear segment (CSS has no log equivalent).

Fallback

For ≤0 data in log mode: shift the domain by an offset or use d3's symmetric mirror −log(−x) per domain convention — the demo takes the most conservative route (clamping to the smallest legal domain) with a warning; linear scales have no illegal inputs (only the d0=d1 divide-by-zero, which the demo intercepts).
