Ordinal Scale

Sequential Scale · Color Ramp · 顺序色阶

A scale mapping ordered values to ordered colors: monochrome linear (light → dark) or multi-hue progression, taken as official ColorBrewer classes with the midpoint anchored to the data zero — the default for heatmaps and choropleths.

Community ★★★
Live demo official default
Parameters
Geometry▾
steps5

Number of classes (discrete bins). The default of 5 matches ColorBrewer's most-used Blues 5 (#EFF3FF→#08519C); in production take the official 3–9 class values wholesale (the official JSON ships them all) — never invent classes by interpolating in the shipped artifact. More classes make legend lookup harder and adjacent classes converge on print or low-grade screens.

Motion▾
modemonochrome

JS-type param (demo subscribes and redraws the heat cells). monochrome = Blues, light→dark with monotonically decreasing lightness — the most faithful read of 'bigger value, heavier color'; multihue = YlGnBu, pale yellow → blue, exploiting lightness and hue at once, more sensitive to small differences but easier to misread as categories. Diverging data (RdBu) should be saturated at both ends with white at the exact middle, anchored to the data zero/mean.

Code breakdown

Structure & DOM

An ordinal scale divides the value range [0,1] into N equal classes, one official color per class; heat cells and the legend share the same scale array, so the class count moves them in lockstep.

<svg viewBox="0 0 512 460">
  <!-- Heat cell: fill = scale[bin(value)], bin = floor(v * steps) -->
  <rect fill="#6BAED6" />  <!-- class 3 of Blues 5 -->
  <!-- Legend strip: same array, light → dark = low → high -->
</svg>

Key points:

  • Binning is discrete: value → class index → official color; no continuous gradient in the shipped artifact (continuous interpolation is the chart library’s internal business);
  • Legend and cells must be same-source — the demo reads one scale array for both, class count included;
  • Trade-off vs ECharts/D3: ECharts’ visualMap and d3-scale’s scaleQuantize both bin a range into colors, and d3-scale-chromatic carries every ColorBrewer scheme (continuous versions via uniform B-spline interpolation); hand-drawn SVG’s value is byte-exact equality with the official JSON and a forced same-source legend — production charts use the library, spec pages use hand-drawing to guarantee “what you see is the official value”.

Styling & Parameters

Two parameters; every number comes from the official ColorBrewer export JSON (downloaded and parsed in-session via curl https://colorbrewer2.org/export/colorbrewer.json, 35 schemes):

Parameters: steps (3–9, default 5), mode (monochrome linear / multi-hue) — both JS-type. The demo interpolates linearly in sRGB between the 5 official anchors purely to demonstrate arbitrary 3–9 class counts; production must take ColorBrewer’s official per-class values (3–9 classes all exist) or d3-scale-chromatic’s uniform B-spline — their middle classes differ from linear interpolation. Licensing: ColorBrewer states no license text on official channels (attribution © Brewer/Harrower/Penn State; the circulating Apache-2.0 claim is unverified); Crameri Scientific Colour Maps v9.0.0 is presented as free to use, with the specific license unverified.

Motion & Interaction

A scale is a static mapping; motion stays a reading aid:

  • Adjusting steps / mode recomputes and redraws cells and legend together, with no transition (data-mapping changes get no color cross-fade);
  • Hovering a cell shows a native <title> (value + class index) — static, zero delay;
  • The demo has no animation and respects prefers-reduced-motion; if you add a value-sweep demo, animate only a highlight box’s transform, static under reduce.

Real-world examples

  • d3-scale-chromatic: the README states most schemes are “derived from Cynthia A. Brewer’s ColorBrewer”, with discrete schemes turned continuous by uniform B-spline interpolation; the Viridis family provides perceptually uniform continuous ramps (repo verified).
  • Fabio Crameri Scientific Colour Maps: v9.0.0, permanently archived on Zenodo (DOI 10.5281/zenodo.1243862), in use by the IPCC Interactive Atlas; the companion paper Crameri, Shephard & Heron (2020), Nature Communications 11:5444, criticizes rainbow ramps for distorting data (official page verified).
  • ColorBrewer 2.0 (colorbrewer2.org): the official color-picking tool for map classification, with three selection methods — Sequential for increasing values / Diverging around a midpoint / Qualitative for classes; HEX/RGB/CMYK export (official site and export JSON verified).

Working range: 3–5 classes for overviews, 5–7 for analysis, 9 only for high-fidelity output; diverging data always moves to RdBu with a locked midpoint — don’t force-signed values through a single-hue ramp.

When to use 4
  • Fills for heatmaps, calendar heatmaps and density maps — value order = color order, monochrome linear first
  • Choropleth class breaks — ColorBrewer was built for map classification in the first place
  • Diverging data (deviation, P&L, temperature) — the RdBu diverging scheme with its midpoint locked to the data zero
  • Scientific publication figures — Crameri Scientific Colour Maps v9.0.0 (used by the IPCC Interactive Atlas; perceptually uniform, readable in grayscale and under CVD)
When not to use 4
  • Unordered categorical data — an ordinal scale implies magnitude; use a categorical palette instead (dataviz-categorical-palette)
  • Rainbow ramps (jet-like) as a default — Crameri's paper (Nature Communications 11:5444) specifically criticizes their perceptual non-uniformity as data distortion
  • Interpolating your own in-between classes in the shipped artifact — take official classes or d3's B-spline; interpolation belongs to the library
  • Letting a diverging midpoint drift off the data zero — the 'white middle' must anchor at 0/mean, never at a visually convenient spot
Accessibility

An ordinal scale's information channel is a lightness gradient: monochrome light→dark inherently carries the value order and survives both CVD and grayscale printing; multi-hue ramps (YlGnBu) add hue but still rely mainly on lightness under CVD; Crameri maps are explicitly designed to be 'Fair to the data / Readable by everyone' (official page verified). Keep heat cells at 3:1 non-text contrast against the backdrop (WCAG 2.1 SC 1.4.11); the legend must track the class count, and past 7 classes consider annotating key break values instead.

Browser support

The demo is hand-drawn SVG with inline hex colors — no reliance on new CSS/JS features; available everywhere. The scale values themselves are design assets, independent of the browser.

Fallback

No browser-compat issue; the real fallback is the source of intermediate classes: the demo interpolates linearly in sRGB between the 5 official anchor colors purely to demonstrate arbitrary 3–9 class counts — production must take ColorBrewer's official per-class JSON or d3-scale-chromatic (uniform B-spline), which differ from linear interpolation in the middle classes. Monochrome linear ramps survive grayscale printing naturally; multi-hue ramps need a grayscale check first.
