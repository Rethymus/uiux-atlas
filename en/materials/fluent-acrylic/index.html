Fluent Acrylic

亚克力 · Acrylic · Fluent 亚克力

Microsoft Fluent's translucent material brush: backdrop blur + luminosity blend + tint layer + noise, in background (desk-through) and in-app variants; the web recreation approximates it via tintOpacity / tintLuminosityOpacity.

Fluent ★★★
Live demo official default
Parameters
Geometry▾
tintOpacity0.6

Opacity of the tint layer (official parameter name AcrylicBrush.TintOpacity, research 02 §3 C1). No official default is published — the default 0.6 is a community-common value (unverified): raising it firms the tint and hides the backdrop; lowering it turns the surface more transparent and text contrast harder to hold over dark backdrops.

tintLuminosityOpacity0.35

Opacity of the luminosity tint (official parameter name TintLuminosityOpacity, blended against the backdrop's luminosity, research 02 §3 C1). No official default is published — the default 0.35 is a community-common value (unverified): raising it brightens and 'fogs' the surface, steadier over bright backdrops; 0 disables luminosity compensation and muddies acrylic over dark content.

Motion▾
fallbackoff

Maps to the official AlwaysUseFallback switch (research 02 §3 C1): when on, the blur/luminosity/noise layers are skipped in favor of a solid surface. Real environments also trigger the fallback automatically without backdrop-filter support or in power-saving mode; the demo toggle makes both states comparable.

Code breakdown

Structure & DOM

Official Acrylic is a XAML material brush: in WinUI it attaches to a window via AcrylicBrush or Window.SystemBackdrop / DesktopAcrylicBackdrop (research 02 §3 C1). It comes in two types: background acrylic sees through the desktop wallpaper and other windows (for transient UI), while in-app acrylic layers within the app. The web recreation stacks “blurred backdrop → luminosity layer → tint layer → noise layer → content”:

<div class="scene">
  <img class="wallpaper" src="photo.jpg" alt="" />
  <section class="acrylic">   <!-- in-app acrylic panel -->
    <div class="lum"></div>   <!-- luminosity layer: TintLuminosityOpacity -->
    <div class="noise"></div> <!-- noise layer: feTurbulence -->
    <div class="content">…</div>
  </section>
</div>

Key points: the two types differ in their sampling source (desktop vs in-app); the web cannot see through the desktop, so a photo stands in for the wallpaper scene; AlwaysUseFallback is the official forced-fallback switch (C1).

Styling & Parameters

Three parameters inject through --fa-* variables; fixed layer colors like TintColor are community approximations (WinUI light-theme base ≈ #F3F3F3):

.acrylic {
  position: relative;
  /* blur radius unpublished; blur 24px + saturate 125% is a common web approximation */
  -webkit-backdrop-filter: blur(24px) saturate(1.25);
  backdrop-filter: blur(24px) saturate(1.25);
  background: rgb(243 243 243 / var(--fa-tint-opacity)); /* TintColor × TintOpacity */
}
.acrylic .lum { position: absolute; inset: 0; background: #fff; opacity: var(--fa-lum-opacity); }
.acrylic .noise {
  position: absolute; inset: 0; opacity: 0.04;
  background-image: url("data:image/svg+xml,…feTurbulence baseFrequency='0.9' numOctaves='2'…");
}
/* Fallback: the official AlwaysUseFallback switch + auto-triggered without backdrop-filter */
.acrylic[data-fallback="on"] { background: #f3f3f3; }
@supports not (backdrop-filter: blur(1px)) {
  .acrylic { background: #f3f3f3; }
}

Where the numbers come from:

  • tintOpacity / tintLuminosityOpacity / AlwaysUseFallback / TintTransitionDuration: official parameter names (research 02 §3 C1); no official defaults are published — the demo’s 0.6 / 0.35 are community-common values (unverified);
  • The two types (background / in-app): the official docs (C1);
  • The noise recipe feTurbulence baseFrequency=0.9 numOctaves=2: the lightweight noise layer from research 06 §IV §15 (banding killer);
  • Support: backdrop-filter in Chrome 76 / Firefox 103 / Safari 9 (BCD, research 02 §4 D2).

Motion & Interaction

  • Live tuning: the two opacity variables rewrite the tint/luminosity layers instantly — dragging a slider visibly firms or thins the material;
  • Fallback switch: material layers fade out over 0.25s while the solid fades in — echoing the official TintTransitionDuration (tint switch duration, C1) whose value is unpublished; the demo uses 0.25s;
  • Transitions are removed under prefers-reduced-motion and the switch becomes instant;
  • The demo backdrop is static: acrylic layering is easiest to judge in a static comparison, and per-frame animated backdrops blow up backdrop-filter sampling cost.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
tintOpacitya firmer tint layer: less visible backdrop, steadier text contrast; 1.0 degrades into a solid cardmore transparent, more material; light text over dark backdrops punches through 4.5:1, 0 leaves only blur + noise
tintLuminosityOpacitybrighter and “foggier”: harmonizes over bright backdrops (daytime wallpaper) but turns gray in dark themesluminosity compensation vanishes: acrylic muddies over dark content and the transition between the pale tint and the dark backdrop hardens; 0 disables it entirely
fallbackon: a solid surface with maximum readability and performance, at the cost of the material feeloff: the full acrylic stack; the system still forces a fallback without backdrop-filter support or in power-saving mode

Working ranges: tintOpacity 0.5–0.8 for supporting surfaces, 0.3–0.5 for emphasis-transparent flyouts; tintLuminosityOpacity 0.2–0.5. Aside from the parameter names, none of these values are officially verified — production recreations should defer to real WinUI rendering.

When to use 3
  • in-app acrylic: sidebars, command bars, flyouts and other supporting surfaces (official use)
  • background acrylic: transient UI — menus and popovers briefly seeing through the desktop (official use)
  • Cards and containers that need a material feel without competing with content
When not to use 3
  • Body-reading areas and dense data — tint + noise layers dilute contrast
  • Large areas over fast-moving content — per-frame re-sampling gets expensive
  • Treating the web tintOpacity numbers as official defaults — the research records parameter names only, values unverified
Accessibility

Check text on acrylic against the brightest/darkest transmitted backdrop for 4.5:1 (WCAG 2.1 SC 1.4.3, research 06 §V §17); the noise layer is extremely low-contrast and texture-only, never an information carrier (research 06 §IV §15 positions noise as a banding-killing texture); the solid fallback state must be equally readable.

Browser support

The native material is Windows-only (AcrylicBrush and DesktopAcrylicBackdrop in XAML/WinUI, research 02 §3 C1). Web recreation: backdrop-filter works in Chrome 76 / Firefox 103 / Safari 9 (-webkit- prefix, research 02 §4 D2); the noise layer uses SVG feTurbulence (recipe in research 06 §IV §15), available in all browsers.

Fallback

AlwaysUseFallback (or missing backdrop-filter support / power-saving mode) switches to a solid surface — the demo shows it via fallback=on and auto-drops to solid via @supports in browsers without backdrop-filter; TintTransitionDuration (an official parameter) is approximated with a 0.25s transition.

Sources 2
