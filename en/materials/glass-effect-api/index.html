Glass Effect API (Liquid Glass)

液态玻璃 API · glassEffect · GlassEffectContainer

Apple Liquid Glass' declarative API surface: glassEffect(_:in:) / Glass (variant, tint, interactive) / GlassEffectContainer(spacing) / glassEffectID morphing — presented here as a CSS approximation of the parameter semantics.

Apple HIG ★★★
Live demo official default
Parameters
Motion▾
variantregular

The two official Liquid Glass variants. regular = blurs the backdrop and tunes luminance for legibility, used by most system components and the documented default of glassEffect (A2); clear = highly transparent, reserved for floating controls over rich media, and HIG says to dim it when underlying content is bright (research 02 §A1, 06 §16: a 35%-opacity dark layer). JS-type param toggled via data-variant in the demo.

interactiveoff

The interactive-feedback switch, mapping to Glass.interactive(_:) and UIGlassEffect.isInteractive (research 02 §A3/A6): when on, glass gives glow/press feedback to pointer and touch. off corresponds to glass without interactive(_:) applied; treat the API pages as authoritative for defaults. The demo toggles data-interactive.

Geometry▾
tintIntensity0%
%

Tint-strength mapping. The official APIs Glass.tint(_:) / UIGlassEffect.tintColor accept an arbitrary Color (research 02 §A3/A6) with no numeric-strength parameter — this entry maps tint to the overlay opacity of one fixed accent color, 0 = untinted (demo default); a Web approximation, not the official API surface.

spacing8

The blend distance of GlassEffectContainer(spacing:content:): glass shapes begin blending when closer than spacing (A4 verbatim: larger spacing makes shapes blend earlier). Apple records no numeric default — 8 is this entry's demo value; the demo fixes a 24px gap between two capsules and fades in a liquid bridge as spacing approaches it.

Code breakdown

Structure & DOM

The SwiftUI API is three-tier: glassEffect(_:in:) puts glass on a single view; GlassEffectContainer(spacing:content:) merges a group of glass shapes into one rendering field with morph support; glassEffectID(_:in:) registers each shape’s identity for morph matching. The Web approximation mirrors the hierarchy:

<div class="scene">
  <img class="backdrop" src="photo.jpg" alt="" />
  <div class="container">                 <!-- ≈ GlassEffectContainer -->
    <button class="glass">A</button>      <!-- ≈ glassEffect(.regular, in: Capsule) -->
    <div class="bridge"></div>            <!-- spacing-driven blend bridge (merged-render cross-section) -->
    <button class="glass">B</button>
  </div>
</div>

Key points:

  • The official default shape is a Capsule (glassEffect’s default in: argument, research 02 §A2) — both demo controls are capsules;
  • “Merged rendering” approximates on the Web as a fading blend bridge: as spacing approaches the shapes’ actual gap, the bridge fuses them into one; a true shared blur field and morphing need the native API;
  • Variant and interactive are written by JS to data-variant / data-interactive; all material styling stays in CSS.

Styling & Parameters

The four parameters map to the API surface: variant (Glass regular/clear), tintIntensity (a strength mapping of tint), interactive (interactive(_:)), spacing (the container’s blend distance):

.glass {
  border-radius: 999px;                      /* documented default shape Capsule */
  /* regular approximation: blur + luminance lift + hairline (Web values, not official) */
  background: oklch(1 0 0 / 0.22);
  backdrop-filter: blur(14px) saturate(1.6);
  -webkit-backdrop-filter: blur(14px) saturate(1.6);
  border: 1px solid oklch(1 0 0 / 0.45);
}
.scene[data-variant="clear"] .glass {
  background: oklch(1 0 0 / 0.06);
  backdrop-filter: blur(3px) saturate(1.2);
}
.scene[data-variant="clear"] .glass::after {  /* HIG: 35% dark layer over bright content */
  content: ""; position: absolute; inset: 0; border-radius: inherit;
  background: rgb(0 0 0 / 0.35);
}
.glass::before {                              /* tint(_:): one fixed accent × intensity */
  content: ""; position: absolute; inset: 0; border-radius: inherit;
  background: oklch(0.62 0.17 250); opacity: var(--liquid-tint);
}
.scene[data-interactive="on"] .glass:hover { filter: brightness(1.12); }
.scene[data-interactive="on"] .glass:active { transform: scale(0.96); }
.bridge {                                     /* spacing: 24px fixed gap between capsules */
  width: 24px; height: 44px; margin: 0 -12px;
  opacity: clamp(0, calc((var(--liquid-spacing) - 8) / 16), 1); /* fades in near the gap */
}

Where the numbers come from:

  • Variant semantics, default .regular, default Capsule, interactive(:)/tint(:), and the container’s blending rule: all from Apple’s API docs and HIG Materials (research 02 §A1–A6, fetched firsthand);
  • The 35%-opacity dark layer on clear over bright content: verbatim HIG Materials (research 06 §16/§18);
  • blur(14px)/saturate(1.6)/22% white fill are Web approximation demo values — Apple publishes no material blur numbers and they must never be cited as official;
  • The spacing default of 8 and the (s−8)/16 bridge ramp are demo fits (no official numeric default), flagged in the param effect.

Motion & Interaction

The motion core of Liquid Glass is morphing: when two shapes come closer than the container spacing they blend, and with glassEffectID identity matching they can deform continuously between forms. The Web approximation can only present the static cross-section of “blend bridge fades in”:

  • The spacing slider drives the bridge’s opacity (clamp ramp), demonstrating “larger spacing blends earlier” (A4 verbatim);
  • interactive=on gives hover brightening and a 0.96 press scale over 0.15s; under prefers-reduced-motion drop the transform transition and keep only the luminance change;
  • Variant switching cross-fades over 0.2s; Liquid Glass’ real refraction and scroll edge effect cannot be replicated on the Web, and the demo does not pretend otherwise.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
variant (→clear)clear is nearly blur-free, transmitting all backdrop detail — fit only for floating controls over mediaback to regular: blur + luminance lift for legibility, the default for most contexts (HIG)
tintIntensitystains the glass with the accent; past 40% it reads as a solid button and the glass feel dies0% is pure untinted glass (the demo default); brand color stays subtle
interactive (→on)pointer feedback appears — hover lift + press scale, communicating “tappable”feedback off, visually silent — but the keyboard focus indicator must always remain
spacingat ≥24px (reaching or exceeding the fixed gap) the bridge fully shows and both shapes read as one, echoing “larger spacing blends earlier”under 8px the bridge vanishes and the shapes are fully independent; true morph matching additionally needs glassEffectID, which the Web approximation omits
(fixed semantics)—without the dim layer, white text on clear over bright backdrops (snow, sky) always fails contrast — the 35% dim layer is a legibility precondition, not optional

Rule of thumb: start functional layers on regular; switch to clear only over photos/video with minimal content; morphing happens only inside one GlassEffectContainer — shapes never blend across containers.

When to use 4
  • Nav bars, tab bars and toolbars of system components on iOS 26+-class platforms (functional layers above content)
  • Floating controls over photos/video with the clear variant (add the 35% dim layer over bright content)
  • Clusters of adjacent controls blending/morphing: GlassEffectContainer plus glassEffectID identity matching
  • Web recreations of the same look: paired capsule glass and high-transparency media overlays approximated by these params
When not to use 4
  • Applying Liquid Glass to content layers (list bodies, forms) — HIG explicitly forbids content-layer use and overuse
  • The clear variant over flat/pale backdrops — high-transparency glass collapses without a rich backdrop (same as glassmorphism)
  • Treating the Web approximation as official rendering — dynamic refraction, scroll edge effect and luminance adaptation cannot be replicated in static CSS
  • Long text directly on clear — legibility is regular's job; on clear, text contrast must be checked against the brightest backdrop
Accessibility

Glass is a functional-layer material: text on it must hold 4.5:1 against the brightest/darkest transmitted content (WCAG 2.1 SC 1.4.3); the clear variant needs the dim layer or a switch to regular to stay legible; interactive feedback never replaces focus indicators (SC 2.4.7); per HIG, glass is never the content layer — text always lives on the content layer itself.

Browser support

glassEffect/GlassEffectContainer are SwiftUI/UIKit APIs on iOS 26+/macOS 26+ class platforms, not in browsers (research 02 §A2–A6); the Web demo approximates with backdrop-filter plus gradients (backdrop-filter: Chrome 76 / Firefox 103 / Safari 9 with the -webkit- prefix per BCD, research 02 §D2). API availability follows Apple's platform versions.

Fallback

A Web-approximated glass lacks Liquid Glass' dynamic refraction/real-time luminance tuning — when shipping cross-platform, deliver the variant semantics (regular for legibility, clear over media only) and the spacing semantics as the spec, not rendered values; browsers without backdrop-filter follow the glassmorphism fallback of raising fill opacity.
