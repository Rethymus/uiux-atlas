Liquid Glass

液态玻璃 · 苹果玻璃材质 · Glass Effect

Apple's unified dynamic material from iOS 26: forms a separate 'functional layer' for controls and nav floating above content; two official variants — regular and clear, the latter stacking a 35% dark dimming layer over bright backdrops.

Apple HIG ★★★
Live demo official default
Parameters
Motion▾
variantregular

The two official variants (research 02 §1 A1 / 06 item 18): regular blurs the backdrop and adjusts luminosity for readability — used by most system components and the glassEffect default (A2); clear is highly transparent, reserved for floating controls over rich media. The demo subscribes and toggles data-variant — regular gets a white luminosity veil approximation, clear stacks the dark dimming layer.

morphpod

Morph target of the web-approximation demo. Official semantics: 'when state changes, Liquid Glass dynamically morphs between controls across contexts, maintaining a single floating plane' and 'the bubble pops open in place to reveal content' (WWDC25 219 [283–320s], research 09 §8.3); natively driven by GlassEffectContainer + glassEffectID(_:in:). pod = capsule control cluster (the official default Capsule shape); panel = an in-place expanded media menu, whose larger footprint deepens the shadow and boosts refraction per the official qualitative statement (219 [422–445s]). The demo subscribes and toggles data-morph, transitioning with the apple.com production CSS token (320ms cubic-bezier(0.4, 0, 0.6, 1), research 09 §1.4a).

Geometry▾
dimming35%
%

Opacity of the clear variant's dark dimming layer; the official recommendation is 35% (HIG Materials: when content under clear is bright, add a 35%-opacity dark dimming layer — research 06 §IV §16 and summary item 18). The luminosity adjustment of regular has no published official number, so the demo approximates it with a white veil of the same value (approximation, not an official figure).

blur20px
px

Backdrop blur radius. Apple does not publish Liquid Glass blur numbers; the default 20px borrows the classic glass recipe recorded in research 06 §IV §16 (glassmorphism.com) as the web approximation starting point (not verified as an Apple official value).

tint0%
%

Tinting strength of the glass. The official API Glass.tint(_:) is an optional instance method (research 02 §1 A3) and glass ships untinted by default — hence 0 = off; the demo renders strength as the alpha of a blue veil (demo color, not an official value).

refraction34

Refraction displacement strength, written to the SVG feDisplacementMap scale (Chromium only; everything else falls back to pure blur). The default 34 is this demo's existing value — Apple never publishes refraction numbers (WWDC25 219 only describes lensing qualitatively, research 09 §8.1), and the SVG displacement approach is a community practice whose source could not be verified (research 09 §8 ⚠️unverified). Officially, 'refraction strength is a function of size' (219 [422–445s]): the demo scales the displacement by the current-width / capsule-base-width ratio in the morphed state. 0 = refraction layer off. JS-type param; the demo subscribes and writes the filter attribute.

Code breakdown

Structure & DOM

The native form is SwiftUI’s declarative API: glassEffect(_:in:) turns a view into Liquid Glass, defaulting to the .regular variant in a Capsule shape (research 02 §1 A2). A web recreation stacks “content layer → glass pod → state layers”:

// Official API (iOS 26+, research 02 §1 A2/A3)
HStack { Image(systemName: "play.fill"); Image(systemName: "pause.fill") }
  .padding()
  .glassEffect(.regular, in: .capsule)   // defaults: .regular, Capsule
  .tint(.blue)                            // optional tinting: Glass.tint(_:)
<div class="scene">
  <img class="content-layer" src="photo.jpg" alt="" /> <!-- content: scrolls through -->
  <div class="glass-pod"> <!-- glass pod: the functional layer -->
    <button>…</button>
  </div>
</div>

Key points: the pod belongs only to the functional layer of controls and nav, with content scrolling through beneath it; Apple explicitly says not to use Liquid Glass for content layers and not to overuse it (research 02 §1 A1).

Styling & Parameters

The web approximation is driven by --lg-* variables: blur samples what’s behind, the variant decides the state layers, and refraction comes from an SVG feDisplacementMap; three JS-type params are consumed by the demo’s subscription — variant toggles the state layers, refraction writes the filter’s displacement scale, and morph switches pod ↔ panel:

.glass-pod {
  border-radius: 999px;                     /* official default shape: Capsule (A2) */
  box-shadow: inset 0 1px 0 rgb(255 255 255 / 0.55); /* 1px inner highlight */
  -webkit-backdrop-filter: blur(var(--lg-blur));
  backdrop-filter: blur(var(--lg-blur));    /* 20px: classic glass recipe approximation (06§16) */
}
.glass-scene[data-refraction="on"] .glass-pod {
  backdrop-filter: url(#lg-refraction) blur(var(--lg-blur)); /* Chromium only */
}
.glass-veil { opacity: var(--lg-dimming); }  /* default 35% */
.glass-scene[data-variant="regular"] .glass-veil { background: rgb(255 255 255 / 0.92); } /* luminosity approx */
.glass-scene[data-variant="clear"]   .glass-veil { background: rgb(8 10 18 / 0.92); }     /* official dark dimming */

Where the numbers come from:

  • dimming default 35%: the official HIG recommendation for the clear variant (research 06 §IV §16 and summary item 18) — when content under clear is bright, stack a 35%-opacity dark dimming layer;
  • variant two options, default regular: the official definition (research 02 §1 A1) plus the glassEffect default (A2);
  • tint default 0: Glass.tint(_:) is optional and glass ships untinted (A3);
  • blur 20px: Apple publishes no number — borrowed from the classic glass recipe as an approximation (unverified);
  • refraction (JS-type) default 34: this demo’s existing value — Apple never publishes refraction numbers (WWDC25 219 describes lensing only qualitatively), and the SVG displacement approach is a community practice whose source could not be verified (research 09 §8: ⚠️unverified);
  • morph (JS-type) default pod: the capsule is the official default Capsule shape (A2); the transition timing/curve, 320ms cubic-bezier(0.4, 0, 0.6, 1), is the apple.com production CSS token (research 09 §1.4a/§9.3);
  • Refraction: an SVG feTurbulence → feOffset → feDisplacementMap filter, Chromium only — Firefox/Safari reject url() references inside backdrop-filter, so they fall back to pure blur.

Motion & Interaction

Liquid Glass’s dynamic behaviors (WWDC25 219 official descriptions, research 09 §8), approximated in the demo:

  • Pointer-following refraction (lensing approximation): Apple defines glass through lensing — “bends, shapes and gathers light in real time”, unlike older materials’ scattering (219 [118–159s]). The demo shifts the feDisplacementMap field with the pointer — feOffset translates the noise field, and the pointer’s offset relative to the pod (normalized, rAF-batched) writes dx/dy. Apple publishes no refraction numbers; the displacement magnitude is a demo value;
  • Refraction strength is a function of size: “when the glass flexes/morphs into a bigger element, the material simulates thicker glass: deeper shadows, more pronounced lensing and refraction, softer light scattering” (219 [422–445s]). The demo binds the displacement scale to refraction × (current width / capsule base width), so the panel state automatically deepens distortion and shadow — a proportional implementation with no magic constants;
  • Morph: “when state changes, Liquid Glass dynamically morphs between controls across contexts, maintaining a single floating plane”; menus “pop open in place, a lightweight transition that keeps the tapped control connected to its content” (219 [283–320s]); natively driven by GlassEffectContainer + glassEffectID(_:in:), with UIKit triggering a materialize animation by swapping UIGlassEffect inside an animation block. The demo approximates it with a pod ↔ panel transition on width/height/border-radius — width/height trigger layout, so production morphs should use FLIP/view-transitions animating only transform (research 09 §8 web recipe);
  • Touch glow: “lights up from under the fingertip and spreads across the whole element, even to nearby glass” (219 [725–737s]). The demo stacks a pointer-following radial-gradient highlight inside the pod, writing element style directly per frame instead of CSS variables (per-frame variable writes invalidate the whole subtree); the glow recipe is a demo approximation with no published numbers;
  • Shared sampling domain: “glass cannot sample glass” — adjacent glass elements must share one container’s sampling domain or they render inconsistently (323 [1200–1229s]); the demo’s single pod is naturally compliant — wrap multiple glass elements in one container;
  • Existing behaviors unchanged: the variant veil cross-fades over 0.25s; the “live content” behind (drifting blobs) animates only transform, feeding the pod’s blur/refraction a changing scene each frame; the pod itself never translates — hover feedback belongs to system behaviors like Glass.interactive(_:) (A3);
  • Under prefers-reduced-motion, the morph transition and entrance animation are removed (pointer-following refraction/glow is input-driven rather than autonomous motion, so it stays).

Real-world examples

  • iOS 26 system tab bars / toolbars: Liquid Glass’s home turf — a glass control cluster floats above content and morphs between contexts on navigation changes, keeping a single floating plane (WWDC25 219 demo scenarios);
  • apple.com global nav: the web production counterpart of the Liquid Glass vocabulary — after scrolling past the hero, blur(0→20px) saturate(180%), the fill lifts from rgba(250,250,252,.8) to .92 (stuck state) and turns solid when the menu opens, transitioning over 320ms cubic-bezier(0.4, 0, 0.6, 1) (apple.com production CSS, research 09 §1.4);
  • visionOS windows: a system-level, non-modifiable glass material that adapts to ambient brightness with no separate dark-mode switch — the official exemplar of choosing materials by semantics, not looks (HIG Materials, research 09 §1.2).

Parameter Sensitivity

ParameterTurning it up…Turning it down…
variant → clearhighly transparent, media reads straight through — more “liquid”; bright backdrops then depend on the dimming layerregular is the safe default: blur plus luminosity adjustment keeps text readable
dimminga firmer dark layer on clear, steadier text contrast on bright backdrops; past 50% the glass turns murkytext punches through 4.5:1 on bright backdrops; 0% is bare clear — the official 35% exists to rescue bright backdrops
blura “thicker” pod, less legible content; past 30px it smears into mushbelow 8px the glass degrades into a pale block and the refraction texture loses its substrate
tintstronger tint reads more branded, like colored acrylic; past 60% it masks the glass quality0% is the official default — untinted glass holds its shape through highlights and refraction
refractionmore pronounced distortion and lensing; too high (>80, demo observation) tears the edges into noise and makes the backdrop illegibledistortion falls back to pure blur; 0 = refraction layer off, leaving blur + inner highlight only
morph → panelthe enlarged state deepens the shadow and boosts refraction proportionally to width — the official “bigger elements feel thicker” statement (219 [422–445s])back to the capsule: minimal footprint, baseline refraction, the quietest visual

Working ranges: start dimming at the official 35% and raise it only over bright backdrops; blur 12–24px; tint ≤30% for light branding. Native first: with SwiftUI/UIKit available use glassEffect — web approximation is always the downgrade path.

When to use 3
  • Floating control layers: tab bars, toolbars, media transport — officially positioned as the 'functional layer' for controls and nav (research 02 §1 A1)
  • Floating buttons over photos/videos and other rich backdrops (the official clear-variant use case)
  • Persistent entry points over scrolling content, which passes through beneath them
When not to use 4
  • Content layers: Apple explicitly says not to use Liquid Glass for content (research 02 §1 A1)
  • Overuse: Apple warns against it; glass stacked on glass turns muddy
  • Body-reading areas and dense data — translucent materials dilute contrast
  • Flat solid backdrops — with nothing to refract or blur the glass feel collapses
Accessibility

Text on the glass keeps high contrast: 4.5:1 (WCAG 2.1 SC 1.4.3, research 06 §V §17); on bright backdrops the clear variant must stack the official 35% dark dimming layer before placing text; the material must never be the sole carrier of key information.

Browser support

The official capability is Apple-only: SwiftUI glassEffect / UIKit UIGlassEffect on iOS/iPadOS/macOS/tvOS/watchOS 26+ (research 02 §1 A1–A6). Web approximation: backdrop-filter works in Chrome 76 / Firefox 103 / Safari 9 (-webkit- prefix, research 02 §4 D2); the SVG feDisplacementMap refraction renders in Chromium only (Firefox/Safari do not support url() filter references inside backdrop-filter) — everything else falls back to pure blur.

Fallback

Without SVG backdrop refraction, fall back to pure blur plus a 1px inner highlight to approximate the glass feel (this demo's default downgrade); without backdrop-filter, use a firmer translucent surface; off Apple 26+ platforms there is no native version at all — approximation is the only path.
