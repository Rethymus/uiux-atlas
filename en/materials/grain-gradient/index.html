Grain Gradient

噪点渐变 · Grainy gradients · feTurbulence noise

Grainy gradients: SVG feTurbulence generates gray noise laid over the gradient, then contrast/brightness pushes it into grain — whose main job is killing gradient banding on cheap panels.

Community ★★★
Live demo official default
Parameters
Geometry▾
baseFrequency0.65

feTurbulence noise frequency, setting grain coarseness. Default 0.65 is the CSS-Tricks recipe verbatim (fractalNoise + baseFrequency='0.65'); CodeFronts' lightweight variant uses 0.9. JS-type param: the demo rebuilds the data-URI with the rewritten SVG attribute.

numOctaves3

Turbulence octave count — more octaves means finer detail and higher render cost. Default 3 is the CSS-Tricks recipe verbatim (numOctaves='3'). JS-type param: the demo rebuilds the data-URI with the rewritten SVG attribute.

contrast170%
%

The contrast filter value pushing gray noise into grain. Default 170% is the CSS-Tricks recipe verbatim (filter: contrast(170%) brightness(1000%)); the recipe's brightness(1000%) is fixed inside the demo rather than listed as its own param.

grainOpacity0.16

Overall opacity of the noise layer. Default 0.16 comes from CodeFronts' lightweight variant (inline data-URI feTurbulence baseFrequency='0.9' numOctaves='2', noise layer opacity: .16) — enough to kill banding without looking dirty (research 06 §15).

Code breakdown

Structure & DOM

Grainy gradients are a “gradient base + noise overlay” two-layer structure: the noise is generated by an inline SVG feTurbulence filter (tiled as a data-URI, zero requests), and the gradient ends transparent so the noise shows through:

<div class="scene">          <!-- isolation: isolate, keeps blend modes contained -->
  <div class="gradient"></div>
  <div class="grain" aria-hidden="true"></div> <!-- noise layer: data-URI + filter + opacity -->
</div>
<!-- The noise SVG itself (baseFrequency/numOctaves driven by params) -->
<svg><filter id="n"><feTurbulence type="fractalNoise" baseFrequency="0.65"
  numOctaves="3" stitchTiles="stitch"/></filter>
  <rect width="100%" height="100%" filter="url(#n)"/></svg>

Key points:

  • type='fractalNoise' + stitchTiles='stitch' makes the noise tile seamlessly (CSS-Tricks recipe);
  • Stacking order: background: linear-gradient(..., transparent), url(noise.svg) — the transparent gradient end is the precondition for visible noise;
  • The noise layer is always aria-hidden and can be removed wholesale without losing information.

Styling & Parameters

Of the four parameters, two are written into the SVG filter (JS-type: changes rebuild the data-URI), two run through CSS variables:

.grain {
  position: absolute;
  inset: 0;
  opacity: var(--grain-opacity);               /* 0.16, CodeFronts lightweight variant */
  filter: contrast(var(--grain-contrast)) brightness(1000%); /* 170% / 1000%, CSS-Tricks */
  mix-blend-mode: multiply;                    /* refinement: blend against the gradient only */
}
.scene { isolation: isolate; }                 /* keeps multiply off the page background */
.grain {
  background-image: url("data:image/svg+xml,..."); /* feTurbulence baseFrequency=0.65 numOctaves=3 */
  background-size: 180px 180px;                /* data-URIs don't tile naturally; size it explicitly */
}

Where the numbers come from:

  • fractalNoise / baseFrequency 0.65 / numOctaves 3 / stitchTiles stitch and contrast(170%) brightness(1000%): the CSS-Tricks “Grainy Gradients” recipe verbatim (research 06 §15);
  • Noise layer opacity 0.16 and “the main job is killing gradient banding”: CodeFronts’ lightweight variant (that variant uses baseFrequency 0.9 / numOctaves 2 / rect opacity 0.55, research 06 §15) — this entry defaults to CSS-Tricks’ filter parameters plus CodeFronts’ layer opacity, and the combination is documented in the param effects;
  • mix-blend-mode: multiply + isolation: isolate on the parent is CSS-Tricks’ refined route; its comments also warn that extreme contrast/brightness sacrifices color and a mask approach may be more efficient — documented as-is.

Motion & Interaction

This entry is fully static by default — grain is spatial texture, not temporal motion:

  • No CSS animation; if you want “film grain flicker”, it must be frame-limited (e.g. steps() shuffling background-position) and disabled under prefers-reduced-motion;
  • Changing baseFrequency/numOctaves rebuilds the data-URI: one background repaint, acceptable as an editing-time action;
  • The contrast parameter rides a CSS variable — no SVG rebuild, changes apply instantly.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
baseFrequencyfiner, denser grain (0.9 = CodeFronts’ lightweight variant); past 0.9 it approaches TV staticcoarser, clumpier grain; under 0.2 only a few large blobs remain and the even texture is gone
numOctavesmore layered detail, more “filmic”; render cost climbs in stepflatter, more uniform noise; at 1 it has almost no depth but still breaks banding
contrastpushes gray noise into hard black-and-white grain — strongest stylization; past 220% color gets eaten (per the CSS-Tricks comments)noise retreats into an even gray haze; under 100% the grain nearly vanishes, leaving a faint dither
grainOpacitynoise overpowers the gradient and turns “dirty”; past 0.4 it starts interfering under textapproaches the pure gradient; under 0.08 the anti-banding effect fails on some panels — 0.16 is CodeFronts’ banding sweet spot

Working ranges: anti-banding use opacity 0.12–0.2 + contrast 100–170%; stylized grain use contrast 170–250% + opacity 0.25–0.5 — and re-check text contrast in every case.

When to use 4
  • Anti-banding layer over large flat gradients: 0.16-class low opacity shows most on cheap panels
  • Poster/print-flavored ambience — high contrast turns the noise into a visible grain style
  • Matte treatment for dark UIs: fine grain softens banding and the glossy feel of deep OLED surfaces
  • Texturing gradient heroes, buttons and cards at near-zero cost (inline data-URI)
When not to use 4
  • High-contrast grain right under text — extreme contrast/brightness eats color and disturbs small type (noted in the CSS-Tricks comments)
  • Applying it to box-shadow — the technique does not reach shadows and needs separate handling (per the CSS-Tricks article)
  • numOctaves maxed out over large canvases — cost climbs with octaves and large areas stutter
  • Expecting grain to improve accessibility — it is pure decoration; contrast sign-off still uses the ungrained base
Accessibility

Grain is pure decoration: the layer is aria-hidden and carries no information; banding relief is visual comfort, not an accessibility metric; text contrast is computed against the ungrained base (WCAG 2.1 SC 1.4.3); no vestibular burden since the entry is static by default.

Browser support

Both the feTurbulence SVG filter and CSS filter are baseline capabilities (long supported across mainstream browsers); data-URI SVG as background-image is universal. This research pass did not audit a per-browser matrix for feTurbulence; treated as baseline per MDN convention.

Fallback

Without SVG filter support fall back to the plain gradient (loses texture, not information); without the contrast filter the noise stays flat gray — still enough to break banding; the noise layer is always an aria-hidden decoration and can be removed wholesale.
