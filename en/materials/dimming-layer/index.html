Dimming Layer

压暗层 · Scrim · Dimming Layer · 遮罩压暗

A translucent veil pressed over underlying content to buy back legibility for the foreground: the dialog-scrim (::backdrop, solid) and caption-over-photo (bottom gradient) forms, with α stepped through official/verifiable presets.

Web Standard ★★
Live demo official default
Parameters
Motion▾
modesolid

JS-type param; the demo subscribes and toggles data-mode. solid = uniform dimming over the whole area (the dialog ::backdrop form); gradient = a bottom-up dimming ramp (caption-over-photo: the image center stays clear while the caption point reaches the α preset). Gradients only protect where the text sits — text elsewhere is unprotected.

strength0.35

Dimming opacity α; all four steps are values recorded in research: 25% = the MDN ::backdrop typical example (rgb(0 0 0 / 25%), research 12 §8); 30% = the SwiftUI Glass.clear doc example (.black.opacity(0.3), research 09 §1.3); 35% = the HIG recommendation (a dark dimming layer when content under clear glass is bright — the default); 55% = the color-mix heavy-scrim recipe in research 12 §8. Material Design's scrim spec value is unverified and gets no step.

Color▾
color#000000

The scrim base color. Pure black is the base in every official example (HIG's 'dark dimming layer', SwiftUI .black, MDN rgb(0 0 0 / 25%)); research 12 §8/§16.10 also demonstrates blending in a brand hue (color-mix(in oklab, scrim 80%, brand)) — after tinting, re-check text contrast.

Code breakdown

Structure & DOM

A dimming layer is a standalone veil stacked between the content below and the foreground; the two forms live at two DOM positions: the dialog scrim’s native carrier is the top-layer element’s ::backdrop pseudo-element (no DOM node), while the caption gradient is a real element between image and caption.

<!-- Solid form: dialog scrim -->
<dialog class="modal">
  <h3>Title</h3>
  <p>Body</p>
</dialog>
<!-- dialog::backdrop is the dimming layer: viewport-sized, rendered directly beneath the top-layer element, LIFO, inheriting nothing -->

<!-- Gradient form: caption over photo -->
<figure class="figure">
  <img src="photo.jpg" alt="" />
  <div class="caption-scrim"></div>   <!-- gradient dimming: bottom-up -->
  <figcaption>Caption text</figcaption>
</figure>

Key points:

  • ::backdrop inherits nothing — color and opacity must be declared fully on the pseudo-element; “the scrim vanished” on older engines almost always traces back to this (research 12 §8);
  • The gradient only reaches peak α at its bottom vertex: text must sit inside the protected zone or it is effectively bare;
  • The scrim is a layer between content and backdrop, not the backdrop itself — it dims “the content below” in service of “foreground legibility”.

Styling & Parameters

Two CSS-variable parameters (strength → --dim-alpha, color → --dim-color) plus one JS form switch (mode):

/* Solid form: dialog scrim (native) */
dialog::backdrop {
  background: color-mix(in srgb, var(--dim-color) calc(var(--dim-alpha) * 100%), transparent);
}

/* Gradient form: caption over photo */
.caption-scrim {
  position: absolute;
  inset: auto 0 0 0;
  height: 55%;
  background: linear-gradient(to top,
    color-mix(in srgb, var(--dim-color) calc(var(--dim-alpha) * 100%), transparent),
    transparent);
}

α presets (all values recorded in research; nothing invented):

  • 25% = the MDN ::backdrop typical example rgb(0 0 0 / 25%) (research 12 §8);
  • 30% = the SwiftUI Glass.clear doc example .black.opacity(0.3) (research 09 §1.3);
  • 35% = the HIG recommendation — “when underlying content is bright, consider adding a 35%-opacity dark dimming layer” (research 09 §1.3, the default);
  • 55% = the color-mix(in oklab, black 55%, transparent) heavy-scrim recipe in research 12 §8.

Additional reference: apple.com’s glass base color steps by state — light rgba(250,250,252,.8→.92), dark rgba(22,22,23,.8→.88) (floating up when stuck; production CSS, research 09 §1.4b); Material Design’s scrim spec value (M2 ~32% black) is unverified and gets no step.

Motion & Interaction

  • Scrim fade-in: on open, α fades in over ~0.25s (opacity only); a hard cut steals the user’s context of the layer below in an instant — the fade reads as “entering modality”; disabled under prefers-reduced-motion;
  • Modal semantics: iOS 26 sheets are officially described as “the glass recedes slightly, paired with a dimming layer to express modality” (WWDC25 356 [438–494s], research 09 §8.9) — the scrim is part of modality’s visual grammar;
  • Localized dimming: small-footprint elements use localized dimming rather than a full-screen scrim (WWDC25 219, research 09 §1.3);
  • Scroll isolation: while a modal is open, the layer below must not scroll (overscroll-behavior: contain — MDN’s own recommended scenario, research 09 §7.1).

Real-world examples

  • Apple HIG Liquid Glass (clear variant): the official advice — “when underlying content is bright, consider adding a 35%-opacity dark dimming layer”; the SwiftUI Glass.clear doc example ships .black.opacity(0.3) (research 09 §1.3) — dimming is the ticket that lets ultra-transparent glass hold readability (research 09 §11.6);
  • MDN’s <dialog> examples: ::backdrop { background: rgb(0 0 0 / 25%) } is the typical dialog-scrim step (research 12 §8); the same doc family pairs ::backdrop with backdrop-filter: blur(0.5rem) (research 09 §7.1) — the canonical dim-plus-blur pairing;
  • apple.com global nav: a three-state glass base color — resting 0.8, stuck floating up to 0.92 (light) / 0.88 (dark), solid when the menu expands (production CSS, research 09 §1.4b) — a production implementation of state-stepped dimming bases.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
strength → 55%heavy scrim: the layer below is barely legible and attention goes fully to the foreground — true modality onlythe 25% light scrim keeps the layer below perceptible; on bright content text often fails 4.5:1 — dim first, then typeset

Working ranges: start modals at 25–35%, push toward 35–55% over bright media; the gradient occupies about half the image height (55%) with text inside the peak zone. The single criterion for α: foreground text must hold 4.5:1 against “the brightest content below” (WCAG 2.1 SC 1.4.3).

When to use 4
  • Solid scrims behind modal dialogs (::backdrop form) — handing attention to the foreground and pushing the layer below to tolerable noise
  • Captions and subtitle bars over photos/videos (gradient form) — dim only where text sits, keep the media subject clear
  • iOS 26 sheet modality: 'the glass recedes slightly, paired with a dimming layer to express modality' (WWDC25 356, research 09 §8.9)
  • clear glass controls over bright media: the official 'add a 35% dark dimming layer when content beneath is bright' scenario
When not to use 4
  • Placing text over an under-dimmed backdrop — below 30% α often fails 4.5:1 on bright content; dim first, then typeset
  • Heavy full-screen scrims (≥55%) over interfaces that need context — the layer below becomes illegible; reserve for true modality
  • Text outside a gradient scrim's protected zone — the ramp only reaches peak α at the bottom vertex; text elsewhere sits bare
  • Brand-tinted scrims without a contrast re-check — once the hue leaves black/white, every foreground relationship changes
Accessibility

The scrim's only reason to exist is contrast: foreground text over the scrim must hold 4.5:1 against the brightest underlying content (WCAG 2.1 SC 1.4.3); the modal form pairs with focus management (move focus in on open, restore on close, WCAG 2.1 SC 2.4.3) and scroll isolation below (overscroll-behavior: contain); never let an α step be the sole carrier of state; measure against both bright and dark backdrops.

Browser support

::backdrop is Baseline since 2022-03 (research 12 §8); color-mix() is Baseline since 2023-05 (Chrome 111+ / Safari 16.2+ / Firefox 113+, research 12 §11). ::backdrop inherits nothing — the color must be declared fully on the pseudo-element, which is also why scrims silently vanish on older engines.

Fallback

Without color-mix(), write the same opacity directly with rgba(); where ::backdrop is unsupported (legacy engines), insert a real scrim div before the dialog (full-screen fixed, z-index below it) — the common practice before ::backdrop reached Baseline. The scrim carries no content, so degradation never affects function.
