Glass Text

折射文字 · 玻璃文字 · 文字透镜 · 文字色散 · Glass Text Effect

Lens distortion and edge dispersion at the glyph level: the SVG feDisplacementMap filter applies naturally to text, shrinking the container-level chromatic edge down onto letterforms — slight warping and red/blue misalignment at glyph edges, as if reading through a small lens.

Code breakdown

Structure & DOM

Glass text is lens distortion / edge dispersion at the glyph level (research 17 §12.5): the container-level chromatic edge’s SVG displacement filter applies naturally to text. Two routes, mirroring the container-level chromatic-edge A/B split:

<!-- Route A: true displacement via an SVG filter, hung on the heading with element-level filter: url() -->
<svg width="0" height="0" aria-hidden="true">
  <filter id="gt-lens" x="-20%" y="-20%" width="140%" height="140%"
          color-interpolation-filters="sRGB">
    <feTurbulence type="fractalNoise" baseFrequency="0.008" numOctaves="1" seed="7" result="map"/>
    <feDisplacementMap in="SourceGraphic" in2="map" scale="4"
                       xChannelSelector="R" yChannelSelector="G"/>
  </filter>
</svg>
<h1 class="gt-lens">Glass Text</h1>   <!-- filter: url(#gt-lens) -->

<!-- Route B: twin text copies (all browsers); body + data-text attribute, no extra DOM -->
<h1 class="gt-faux" data-text="Glass Text">Glass Text</h1>

Key points:

  • The text body must be real DOM text (selectable, readable by AT); route A’s filter and route B’s ::before/::after copies (content: attr(data-text)) are pure decoration outside the accessibility tree;
  • Route A shrinks the container-level filter onto text using research 17 §6.3’s recipe: baseFrequency 0.008 / numOctaves 1 / seed 7 / scale 4 are all documented values of that recipe; the per-browser matrix of element-level filter: url() was NOT verified in the research (only backdrop-filter: url()’s Chromium-only matrix was, §6.4) — on failure it silently degrades to clean text;
  • Route B is “faux displacement”: two transparent-background glyph copies, hue-split and screen-blended to approximate the red/blue refraction mismatch — text has no edge mask to knock out, so the copies overprint the whole glyph rather than leaving only an edge;
  • No verified text-level precedent: hyalite/rdev are container-level (§12.5 states so honestly) — every recipe value here is treated as engineering extrapolation [R].

Styling & Parameters

Three parameters: two CSS-variable driven, one SVG-attribute driven:

.gt-faux { position: relative; }
.gt-faux::before, .gt-faux::after {
  content: attr(data-text);
  position: absolute; inset: 0;
  mix-blend-mode: screen; opacity: 0.5;
  pointer-events: none;
}
.gt-faux::before { transform: translateX(var(--gt-shift)); filter: hue-rotate(calc(var(--gt-hue) * -1)) saturate(3); }
.gt-faux::after  { transform: translateX(calc(var(--gt-shift) * -1)); filter: hue-rotate(var(--gt-hue)) saturate(3); }

/* Route A: element-level filter */
.gt-lens { filter: url(#gt-lens); }
// lensScale is a filter-primitive attribute and does not accept CSS variables —
// the demo subscribes and rewrites the attribute (engineering constraint)
lens.setAttribute("scale", String(store.get("lensScale")));

Where the numbers come from:

  • dispersion default 2px: the community reference rdev/liquid-glass-react’s aberrationIntensity: 2 (README verified [S]);
  • lensScale default 4: §6.3 route-A recipe scale="4"; MDN’s example uses 50 for strong distortion, glass/text ranges suggest 2–6 (MDN feDisplacementMap page verified [S]);
  • hueAngle ±28°, saturate(3): route-B recipe values (§6.3);
  • Copy opacity 0.5 with screen blending is a value validated in this site’s demo (copies must sit on the body without washing it out — engineering inference).

Motion & Interaction

Dispersed text is a static material — it needs almost no motion:

  • Entrance fade + 6px rise; removed under prefers-reduced-motion (the material has no autonomous animation, this is the only case);
  • Never bind displacement to the pointer: per-frame text re-rendering triggers full-line repaints, and constantly jittering glyphs slide toward “glitch” rather than glass;
  • Route switching (true ↔ faux displacement) is a discrete toggle with no transition — the two routes image differently, so an in-between state is meaningless;
  • In hero scenes the dispersion can “freeze in” once at load and stay static afterwards.

Real-world examples

  • hyalite demo: a complete container-level SDF lens + per-channel dispersion implementation, at https://vii-cae.github.io/hyalite—liquid-glass/demo/index.html (repo metadata verified);
  • rdev/liquid-glass-react: the community component parameterizing dispersion via aberrationIntensity (default 2) (GitHub API + README verified, 6798★);
  • No verified text-level precedent: research 17 §12.5 states honestly that “hyalite/rdev are container-level; the text-level implementation is engineering extrapolation with no verified precedent” — this entry is that extrapolation landed on this site; no unverified sites are cited.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
dispersionpast 3px it starts eating thin strokes and glyph edges grow “cracked shadows”; italics and light weights break firstthe aberration narrows; 0 = dispersion switched off alone and glyphs return clean (the same “zero it independently” convention as chromatic-edge)
lensScalepast 8 the glyphs visibly undulate, like reading through a thick lens; MDN’s 50 is poster-grade distortionapproaches plain text; 0 = no displacement, leaving only route B’s hue split
hueAnglepast ±28° the red/cyan cast thickens; past 45° it becomes a “3D anaglyph glasses” effectthe two hues converge; 0 = screen-blending the same color, dispersion invisible, leaving only a washed-out overprint

Working ranges: dispersion 1.5–3px, lensScale 2–6 (MDN’s glass range), hueAngle ±20–32°; enable only on glyphs ≥32px. Related entries: chromatic-edge holds the container-level dispersion edge-mask knock-out method; liquid-glass holds the official lensing description and the “keep text out of the content layer” restraint principle; backdrop-filter documents the url() reference browser matrix.

When to use 3
  • Brand taglines / large hero headlines: big glyph area makes dispersion legible without hurting small-text recognition
  • Glass-themed sites: the typographic companion to liquid-glass panels (the text-level counterpart of container lensing)
  • Tech / optics themed posters, covers, and full-sentence taglines on 404 pages
When not to use 3
  • Body copy and small text: displacement eats strokes outright — the thinner the stroke, the less it tolerates offset
  • Gating route A on CSS.supports: the check lies (research 17 §6.4 [S]) — accept the silent downgrade instead
  • Long strokes-dense CJK passages: per-glyph displacement stacks up and blurs the whole line
Accessibility

The text body must be real DOM text (selectable, readable by AT, zoomable); the filter and copy layers are pure decoration: copies live in ::before/::after content or aria-hidden nodes, never enter the accessibility tree, and get pointer-events: none; check body contrast at 4.5:1 against the un-filtered version (WCAG 2.1 SC 1.4.3); the material has no autonomous animation — prefers-reduced-motion only cancels the entrance.

Browser support

feDisplacementMap itself is universal since 2015-07 (MDN verified [S]). Route A hangs the filter on text via element-level filter: url(#svg) — that route's per-browser matrix was NOT verified in the research, stated honestly (research 17 §6.4 only verified the backdrop-filter: url() Chromium-only matrix and that "CSS.supports lies" [S]; element-level filter cannot cite that conclusion, nor be gated on CSS.supports). Route B (twin copies + hue-rotate + screen blend) is baseline CSS, all browsers.

Fallback

Route B is the fallback: twin attr() text copies + hue-rotate + screen blend, no SVG filter involved; when route A fails it degrades to clean undisplaced text (the filter is silently dropped) with zero information loss — the text body is always real DOM text, and the filter/copy layers are pure decoration whose absence never changes content.

Sources 3
