Chromatic Edge

玻璃色散边 · 色散边 · 色差边 · Chromatic Aberration Edge

RGB separation / chromatic aberration at the edge: real glass refracts wavelengths differently, so red and blue misalign at bright rims. Two web routes: SVG filter displacement (true displacement, Chromium only) and twin-layer copy + color shift (faux displacement, all browsers).

Code breakdown

Structure & DOM

The chromatic edge is RGB separation / chromatic aberration at the rim: real glass refracts wavelengths differently, so red and blue misalign at bright edges (research 17 §6.1). Two web routes:

<!-- Route A: true displacement via SVG filters (fully supported in Chromium only) -->
<svg width="0" height="0" aria-hidden="true">
  <filter id="chromatic" x="-20%" y="-20%" width="140%" height="140%"
          color-interpolation-filters="sRGB">
    <feTurbulence type="fractalNoise" baseFrequency="0.008" numOctaves="1" seed="7" result="map"/>
    <feDisplacementMap in="SourceGraphic" in2="map" scale="4"
                       xChannelSelector="R" yChannelSelector="G" result="d0"/>
    <!-- same displacement field run per channel, offsets increasing per channel -->
    <feOffset in="d0" dx="2" dy="0" result="oR"/>
    <feOffset in="d0" dx="-2" dy="0" result="oB"/>
    <feBlend in="oR" in2="oB" mode="screen"/>
  </filter>
</svg>
<div class="chromatic">…</div>   <!-- backdrop-filter: url(#chromatic) blur(2px) saturate(1.5) -->

<!-- Route B: twin-layer copies + edge mask (all-browser fallback); body + two pseudos, no new DOM -->
<div class="chromatic-lite">…</div>

Key points:

  • Route A is “true displacement”: feDisplacementMap run per hyalite’s official-grade approach of “one displacement pass per RGB channel, summed” (README verified in full [S]); but backdrop-filter: url(#svg) is fully supported in Chromium only — and CSS.supports returns true everywhere, so feature detection lies (research 17 §6.4);
  • Route B is “faux displacement”: the body plus ::before/::after copies with background: inherit, a double-mask leaving only a 1.5px edge, hue-split and screen-blended to approximate the aberration;
  • Dispersion layers are purely decorative: pointer-events: none, carrying no information.

Styling & Parameters

Three parameters drive the route-B recipe (research 17 §6.3, [R]):

.chromatic-lite { position: relative; }
.chromatic-lite::before, .chromatic-lite::after {
  content: ""; position: absolute; inset: 0; border-radius: inherit;
  background: inherit;                       /* same base as the body */
  mix-blend-mode: screen; opacity: calc(var(--ce-op) / 100%);
  padding: 1.5px;
  -webkit-mask: linear-gradient(#000, #000) padding-box, linear-gradient(#000, #000);
  -webkit-mask-composite: xor; mask-composite: exclude;   /* edge only */
}
.chromatic-lite::before { transform: translateX(var(--ce-shift)); filter: hue-rotate(calc(var(--ce-hue) * -1)) saturate(3); }
.chromatic-lite::after  { transform: translateX(calc(var(--ce-shift) * -1)); filter: hue-rotate(var(--ce-hue)) saturate(3); }

Where the numbers come from:

  • Default separation 2px: the community reference rdev/liquid-glass-react’s aberrationIntensity: 2 (README verified [S]); route B’s recipe uses 1.5px; hue-rotate ±28°, opacity .35, saturate(3): route-B recipe values (research 17 §6.3);
  • hyalite’s official advice [S]: dispersion is expressed in pixels of channel separation, independent of lens strength — “it can be zeroed alone to save a render pass”, which is why dispersion is an independent parameter;
  • Route A’s scale (displacement magnitude): MDN’s example uses 50 for strong distortion; glass edges suggest 2–6 (MDN feDisplacementMap page verified);
  • The body must carry hue: white/gray hues barely separate — the demo card uses a saturated gradient base (cyan → violet) so the aberration reads (engineering inference, validated in this site’s demo).

Motion & Interaction

Dispersion is a static material — it needs almost no motion:

  • Entrance fade + 8px rise; removed under prefers-reduced-motion (the material has no autonomous animation, this is the only case);
  • Never bind dispersion to the pointer: real-time pointer-driven dispersion means redrawing the full edge twice per frame and slides toward “glitch” — a different style, not glass;
  • On state changes (card enter/leave) the dispersion layers transition with the body; no separate animation;
  • Production advice: make the dispersion zero-switch a site-level toggle — it saves a render pass (hyalite’s official practice [S]).

Real-world examples

  • hyalite demo: a complete SDF lens + per-channel dispersion implementation, at https://vii-cae.github.io/hyalite—liquid-glass/demo/index.html (repo metadata verified);
  • rdev/liquid-glass-react: the community component parameterizing dispersion via aberrationIntensity (default 2) (GitHub API + README verified, 6798★);
  • Same-direction repos: electrikmilk/liquid-css (“Refractive chromatic aberration effects in CSS”), dpawlikowski/liquid-glass (“pure CSS and SVG… chromatic aberration, no WebGL”) (GitHub API verified); no standalone use observed in system-level products (research 17 §6.6 states so honestly).

Parameter Sensitivity

ParameterTurning it up…Turning it down…
dispersionpast 4px the edge shows obvious “ghosting” and the material reads as a glitch; cost climbs too (two edge redraws)the aberration narrows; 0 = dispersion switched off alone (saves a render pass, hyalite’s practice), the glass returns to a plain sharp edge
hueAnglepast ±28° the red/cyan cast thickens; past 45° dispersion becomes a “rainbow trim”the two hues converge and the offset reads only as luminance; 0 = screen-blending the same color, dispersion invisible
intensitypast 60% edge ghosting overpowers the contentdispersion turns subtle; at 10% it is barely visible except on bright edges over dark backdrops

Working ranges: dispersion 1.5–3px, hueAngle ±20–32°, intensity 25–45%. Related entries: liquid-glass holds the official lensing/refraction descriptions; backdrop-filter documents the url() reference browser matrix; halo-glow-border — both are “edge optical events”: halo adds light, chromatic shifts color.

When to use 3
  • High-refraction glass realism: the finishing touch on strongly lensed panels (hyalite demo's SDF lens + per-channel dispersion, verified)
  • Tech-brand accents: a 1–2px edge aberration hints at optics, not textures
  • Chromium-only embedded surfaces (e.g. Electron shells) may take route A; the open web always gets route B
When not to use 3
  • Body copy and data edges: aberration lowers perceived edge sharpness — self-inflicted blur on dense text
  • Low-chroma substrates: white/gray hues barely separate — saturate(3) cannot rescue a hueless base
  • Gating route A on CSS.supports: the check lies (research 17 §6.4) — use UA hints or accept the graceful downgrade
Accessibility

Dispersion is purely decorative: it must carry no information; decorative pseudo-layers always get pointer-events: none and stay aria-invisible; verify text legibility at 4.5:1 against the non-dispersed version (WCAG 2.1 SC 1.4.3); this material has no autonomous animation — only input-driven entrances — so prefers-reduced-motion needs no special casing beyond entrances.

Browser support

Route A (SVG feDisplacementMap inside backdrop-filter: url()): feDisplacementMap itself is universal since 2015-07, but referencing an SVG filter inside backdrop-filter is fully supported in Chromium only — rdev README: "Safari and Firefox only partially support the effect"; hyalite README: "Actual refraction works only in Chromium… feature detection lies (CSS.supports returns true everywhere)" — do not detect via CSS.supports (research 17 §6.4 [S]). Route B (twin copies): baseline in all browsers.

Fallback

Route B is the fallback: twin copies + edge mask work in every browser (research 17 §6.4); or fall back to pure blur like hyalite does. Never gate route A on CSS.supports — it returns true everywhere.

Sources 5

OriginThe official-grade approach is backed by the community repo hyalite: "Dispersion is done by running one displacement pass per RGB channel and summing them — expressed in pixels of channel separation, independent of lens strength" (README verified in full [S]); feDisplacementMap's displacement formula and in/in2/scale attributes (MDN verified in full); community quantification reference: rdev/liquid-glass-react's aberrationIntensity default of 2 (README verified [S]); same-direction repos: electrikmilk/liquid-css, dpawlikowski/liquid-glass (GitHub API verified). The twin-layer + edge-mask fallback route is this site's engineering synthesis [R] (research 17 §6.3).
