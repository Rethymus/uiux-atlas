Filter Functions

CSS 滤镜 · filter 函数族 · 图像滤镜

The filter function family applied to an element itself: blur, brightness, contrast, hue-rotate and more — chained together they form the color-grading layer for imagery and materials.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
blur0px
px

Gaussian blur radius applied to the element itself (unlike backdrop-filter, which hits what's behind). Default 0px is the identity/interpolation initial value defined by Filter Effects L1 (research 02 §4 D1); glass-style recipes use 10–20px (blur(20px) recorded in research 06 §IV §16).

brightness100%
%

Linear multiplicative brightness: default 100% is the identity point (research 02 §4 D1); 0% is pure black, past 150% highlights clip to white. The grainy-gradient recipe pushes grain with brightness(1000%) against contrast(170%) (research 06 §IV §15).

contrast100%
%

Pulls the light/dark extremes apart or together: default 100% is the identity point (research 02 §4 D1); 0% is uniform mid-gray, past 120% it trends posterized. The grainy-gradients recipe uses contrast(170%) (research 06 §IV §15).

hue-rotate0deg
deg

Rotates the underlying colors around the hue wheel: default 0deg is the identity point (research 02 §4 D1); 180° yields complementary colors and 360° lands back at the start. Weak on low-saturation photos, clearest on colorful fills and gradients.

Code breakdown

Structure & DOM

filter operates on the element’s own rendered output — that is the dividing line from backdrop-filter. A same-image comparison is simply a set of tiles: every tile shares one source image, each chaining a single function (or a full chain).

<div class="grid">
  <figure><img src="photo.jpg" alt="original" /></figure>
  <figure><img class="f-blur" src="photo.jpg" alt="blurred" /></figure>
  <figure><img class="f-combo" src="photo.jpg" alt="combined" /></figure>
</div>

Key points:

  • The written order of the chain is the pixel-processing order: blur() brightness() contrast() differs from the reverse;
  • Functions hit the whole element render (children, borders and shadows included); to blur only the backdrop use backdrop-filter;
  • Every function has an identity point (blur 0 / brightness 100% / contrast 100% / hue-rotate 0deg); at identity the element equals the original.

Styling & Parameters

Four parameters map to four standalone declarations plus one chained declaration, injected through --ff-* variables:

.f-blur  { filter: blur(var(--ff-blur)); }               /* 0–20px, default 0 */
.f-bri   { filter: brightness(var(--ff-brightness)); }    /* 0–200%, default 100% */
.f-con   { filter: contrast(var(--ff-contrast)); }        /* 0–200%, default 100% */
.f-hue   { filter: hue-rotate(var(--ff-hue)); }           /* 0–360deg, default 0 */
.f-combo {
  filter: blur(var(--ff-blur)) brightness(var(--ff-brightness))
    contrast(var(--ff-contrast)) hue-rotate(var(--ff-hue));
}

Where the numbers come from:

  • All four defaults (0px / 100% / 100% / 0deg) are the identity points defined by Filter Effects L1 (research 02 §4 D1) — the spec’s initial values for “no filter applied”;
  • The function list (blur/brightness/contrast/grayscale/hue-rotate/invert/opacity/saturate/sepia/drop-shadow) also comes from D1;
  • Community recipe references: grainy noise at contrast(170%) brightness(1000%) (research 06 §IV §15), whole-layer aurora gradients at blur(42px) saturate(1.15) (research 06 §IV §14);
  • Support: Chrome 18 / Firefox 49 / Safari 6 / Edge 12 (BCD, research 02 §4 D1), unprefixed.

Motion & Interaction

  • Tile entrance: fade + slight staggered rise, animating only opacity/translate; disabled under prefers-reduced-motion;
  • Filter values are poor candidates for per-frame animation (each frame repaints) — prefer a short transition: filter 0.3s; keep continuous animation on transform/opacity only;
  • Live tuning: dragging any slider moves both its single-function tile and the combined tile while the original tile stays fixed as the reference frame;
  • Hover micro-shifts (e.g. brightness 1.06) are common — give them a transition around 150ms.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
blurdetail smears and edges bloom; past 10px structure visibly collapses, past 16px only color blobs remain0 restores the original; below 2px there is little visible payoff beyond sampling noise
brightnesspast 150% highlights clip to white, 200% approaches overexposure; hue information erodes along the waybelow 50% it darkens noticeably, 0% is pure black — overlaid text instantly loses its contrast baseline
contrastpulls shadows and highlights apart and deepens color; past 120% it trends posterized, blocking up shadows at 200%below 50% it turns flat and hazy, 0% is uniform gray (luminance only) — the photo reads as fogged
hue-rotatespins the wheel: 90°/180°/270° give three complementary palettes, 360° lands back at the startmicro-shifts under 30° are only perceptible on high-saturation sources; low-saturation photos barely change

Working ranges: retouching uses blur 0–6px, brightness 90–110%, contrast 95–115%; step hue-rotate by 30° when deriving themes; the two “heavy-handed” values (contrast 170% / brightness 1000%) belong to noise textures, not photos.

When to use 4
  • Image states: grayscale(1) for disabled, gentle brightness/contrast shifts on hover
  • Aurora/mesh gradient backdrops: a whole-layer filter: blur(42px) saturate(1.15) (recipe in research 06 §IV §14)
  • Grain textures: feTurbulence noise pushed by contrast(170%)+brightness(1000%) (research 06 §IV §15)
  • Theming one asset many ways: hue-rotate derives cool/warm variants instantly
When not to use 4
  • blurring body text — legibility drops to zero
  • per-frame animated filters on large areas — filter triggers repaints; only transform/opacity are compositor-friendly
  • using brightness/contrast as a theming system — they lose hue; themes should swap semantic color tokens
  • stacking >200% extreme combos on photos — detail is annihilated, leaving flat color blobs
Accessibility

Filtered imagery must not be the sole carrier of information — filter states (e.g. grayscale disabled) need a text/icon twin (WCAG 1.4.1 use of color); overlay text on darkened/brightened images still needs 4.5:1 (WCAG 2.1 SC 1.4.3, research 06 §V §17).

Browser support

filter: Chrome 18 / Edge 12 / Firefox 49 / Safari 6 (BCD-measured, research 02 §4 D1); the function family works unprefixed in all modern browsers.

Fallback

The filter family degrades gracefully: without support the element renders as-is and layout is unaffected; readability-sensitive filters (e.g. dimming text with brightness) should still be legible at their 0-filter state by design.
