Breathing Glow

呼吸光晕 · 呼吸灯 · Breathing Glow · Pulsing Halo

An ambient breathing-glow animation: a soft halo oscillates its alpha/blur on a 2–6s cycle, for online status, notification dots and brand mood. Iron rule: animate only box-shadow's alpha/blur — never scale/translate.

Code breakdown

Structure & DOM

Breathing glow is an ambient breathing-halo animation: a soft halo oscillates its alpha/blur on a 2–6s cycle, for online status, notification dots and brand mood (research 17 §8.1). Its entire body is one element + one keyframes rule — there is no structure to speak of; discipline matters more than structure.

<span class="breathing" aria-hidden="true"></span>  <!-- the halo itself is purely decorative -->
<span>Online</span>                                 <!-- the state text must exist redundantly -->

Key points:

  • The halo element is aria-hidden="true": the light is decoration; the state is carried by adjacent text/graphics (WCAG 1.4.1);
  • Iron rule: animate only box-shadow’s alpha/blur, never scale/translate — MDN’s own text names scaling/translating large objects as “vestibular motion triggers”; this material’s legitimacy rests on that rule (research 17 §8.1/§8.2 [S]);
  • The keyframes hold only two states — 0%/100% (rest) and 50% (peak) — with cubic-bezier(.4, 0, .6, 1) easing both ends.

Styling & Parameters

Three parameters drive the recipe (research 17 §8.3, [R]):

@keyframes breathe {
  0%, 100% { box-shadow: 0 0 10px 0 color-mix(in srgb, var(--brg-color) 22%, transparent); }
  50%      { box-shadow: 0 0 26px 4px color-mix(in srgb, var(--brg-color) var(--brg-amp), transparent); }
}
.breathing { animation: breathe var(--brg-period) cubic-bezier(.4, 0, .6, 1) infinite; }
@media (prefers-reduced-motion: reduce) {
  .breathing {
    animation: none;
    /* mid-frame static value: blur 18px / spread 2px / alpha at the midpoint of .22 and the peak */
    box-shadow: 0 0 18px 2px color-mix(in srgb, var(--brg-color) calc((22% + var(--brg-amp)) / 2), transparent);
  }
}

Where the numbers come from:

  • The two keyframe values (rest alpha .22 / blur 10px; peak alpha .55 / blur 26px / spread 4px), the 3.2s period, the cubic-bezier(.4, 0, .6, 1) curve, and the reduce static frame (18px / 2px / alpha .38): all recorded in the research 17 §8.3 recipe;
  • Agreements: duration 2.4–4s (breathing rhythm), peak alpha ≤ .6, and under reduce the mid-frame static value — equivalent to MDN’s official demonstration of “substituting a non-vestibular alternative state” (verified), rather than going dark;
  • Default color #6EE7B7 = the recipe’s rgb(110 231 183); the media query is Baseline since January 2020 (MDN prefers-reduced-motion page verified [S]).

Motion & Interaction

This entry’s “motion section” is motion itself — the rules are everything:

  • Rhythm: 2.4–4s is the breathing range; status lights may go to 2s, mood halos slow to 6s — longer periods lower stimulation;
  • Amplitude: peak alpha ≤ .6; express stronger light through hue/area, never bigger flicker;
  • Reduce settles to static: take the mid-frame (alpha midpoint + blur/spread midpoints) and keep “the light exists” instead of dimming the dot — “substitute, don’t delete” is MDN’s official approach (§8.2 verified);
  • Animation failure is static: environments without animation support rest on the first frame, itself a legal end state (§8.4);
  • A textual/graphic redundant state indicator must sit beside the breathing dot — never light alone (WCAG 1.4.1).

Real-world examples

  • System online-status dots, recording/live indicators: the common breathing/pulse pattern (research 17 §8.6; per-site verification not performed — stated honestly);
  • iOS 26 controls’ elastic touch response is an official close relative on the “light responding to interaction” axis (Glass.interactive(), verified) — but that is input-driven, a different lineage from breathing’s autonomous animation, cited as lineage context only;
  • Per-site exemplars unverified — no specific sites listed.

Working ranges: period 2.4–4s (status lights 2s / mood 4–6s), amplitude 35–55%, color locked to semantic hues. Related entries: inner-glow-panel shares the “alpha/blur only” rule and the same reduce strategy if inner light must move; soft-glow-glass is the static form of light presence; the whole entry follows MDN’s prefers-reduced-motion semantics.

When to use 3
  • Online status dots, recording/live indicators: an oscillating halo = 'alive' (common pattern; research 17 §8.6, per-site verification not performed — stated honestly)
  • Notification dots / unread badges as low-stimulus attention guidance: an order of magnitude calmer than shaking/bouncing
  • Brand mood halos in dark scenes: slow period (4–6s) + low amplitude
When not to use 3
  • Implementing the breath via scale/translate — MDN's named vestibular triggers, a direct violation of this material's iron rule (research 17 §8.2)
  • Strong flicker above .6 amplitude: photosensitivity risk, and it is no longer breathing — it is flickering
  • Resident breathing over body-reading areas: any resident animation steals reading attention
Accessibility

Breathing is a state hint and must not be the sole carrier of key information (WCAG 1.4.1); under prefers-reduced-motion: reduce it settles to the **mid-frame static halo** (alpha at the midpoint of .22 and the peak; blur/spread likewise) — equivalent to MDN's official approach of substituting a non-vestibular state, rather than going dark (research 17 §8.3 [S]); peak alpha ≤ .6; only box-shadow's alpha/blur animates.

Browser support

The prefers-reduced-motion media query is Baseline since January 2020 (MDN verified [S], research 17 §8.4); @keyframes/box-shadow animation is baseline capability; where animation is unsupported the element naturally rests on the first frame (a static halo).

Fallback

Where the media query or animation is unsupported, the element rests on the first-frame static halo — itself a legal end state, no extra fallback needed (research 17 §8.4); the reduce branch uses the mid-frame static value instead of going dark.
