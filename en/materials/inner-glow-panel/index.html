Inner-Glow Panel

内发光面板 · 内泛光 · Inner Glow · Inset Glow

An inset-lit panel: no outward light — the glow is sealed inside, as an overall inner wash + a lit top edge + an ambient dark bottom. The muted version of the glow family; typical on dark dashboard containers, code blocks and selected states.

Code breakdown

Structure & DOM

The inner-glow panel is the muted member of the glow family: no outward light — the glow is sealed inside, as an overall inner wash + a lit top edge + an ambient dark bottom (research 17 §7.1). The grammatical basis is MDN box-shadow’s inset keyword, whose documented semantics read “as if the content is pressed into the box” (box-shadow page verified).

<section class="inner-glow">   <!-- single element: every light layer lives in box-shadow -->
  <h3>Overview</h3>
  …
</section>

Key points:

  • A single-element material: the wash, top-edge light, bottom ambient dark and outer stroke are all box-shadow layers — no pseudo-elements, no DOM;
  • Paint order is light order (MDN: earlier layers paint on top): the main glow goes first, the dark layers last — in the wrong order the top-edge light is eaten by the wash (the same syntax rule as the contact-shadows/theme-shadow entries);
  • Inset shadows paint above the background and below the content (MDN verified): so the inner glow never covers the panel’s own text.

Styling & Parameters

Four parameters drive the recipe (research 17 §7.3, [R]):

.inner-glow {
  background: rgb(255 255 255 / .04);
  border-radius: 16px;
  box-shadow:
    inset 0 0 var(--ig-size) 2px color-mix(in srgb, var(--ig-color) var(--ig-a), transparent), /* inner wash (main light) */
    inset 0 1px 0 rgb(255 255 255 / .35),        /* top-edge light */
    inset 0 -1px 0 rgb(0 0 0 / .30),             /* bottom ambient dark (thickness) */
    0 0 0 1px rgb(255 255 255 / .08);            /* optional outer stroke */
}
/* Single-side light: re-aim the first layer's y offset, tighten with a negative spread */
.inner-glow--top {
  box-shadow:
    inset 0 18px 24px -12px color-mix(in srgb, var(--ig-color) 30%, transparent),
    inset 0 -1px 0 rgb(0 0 0 / .3);
}

Where the numbers come from:

  • The wash inset 0 0 24px 2px rgb(120 180 255 / .18) (recipe intensity 18%; demo default raised to the suggested-range ceiling 22% — SJ-11, muted yet legible / spread 24px / #78B4FF), top edge white/.35, bottom black/.30, outer stroke white/.08, directional inset 0 18px 24px -12px / alpha .30: all recorded in the research 17 §7.3 recipe;
  • Ranges: wash blur 18–32px / alpha .12–.22; directional glows tighten with negative spread −8 ~ −16px (research 17 §7.3);
  • Inset semantics and paint order: MDN box-shadow page verified [S]; iOS dark-mode cards/keyboard keys’ pressed-inset feel is the system-level use of this semantic.

Motion & Interaction

Inner light is static — motion needs are minimal:

  • Entrance: fade + 8px rise; removed under prefers-reduced-motion;
  • Selection changes: transition the glow alpha over 0.2s (opacity/box-shadow); the state must still carry graphic/text redundancy (the demo’s dot + aria-selected) — never light alone (WCAG 1.4.1);
  • No breathing on inner light: breathing belongs to the separate breathing-glow material, and MDN names scale/translate as vestibular triggers — if inner light must move at all, animate only box-shadow alpha/blur under the same reduce rules;
  • Zero reflow: box-shadow changes don’t trigger layout, but large-panel repaints still deserve care — static is inner light’s default form.

Real-world examples

  • iOS dark-mode cards / keyboard keys’ pressed-inset feel: the inset semantics are literally “pressed into the box”, MDN verified (research 17 §7.6) — the pressed-inset light is the system-level expression of “light sealed inside the element”;
  • Dark dashboard containers / code blocks / selected states are common engineering scenarios (research 17 §7.1); per-site exemplars could not be verified (research 17 §7.6 states so honestly) — no specific sites listed.

Working ranges: intensity 12–22%, spread 18–32px, directional negative spread −8 ~ −16px, glow color locked to cool low-saturation families. Related entries: soft-glow-glass for the inner/outer divide; breathing-glow shares the “alpha/blur only” rule if inner light must move; theme-shadow/contact-shadows share the box-shadow order syntax.

When to use 3
  • Dark dashboard containers/sections: panels lit from within, without polluting the layout outward (research 17 §7.1)
  • Code blocks, terminal panes: a cool-blue inner wash is the quietest way to say the surface is alive
  • Selected states / active sections: inner light keeps attention inside the element, quieter than outer glow
When not to use 3
  • Narratives where the element must glow into the scene — that is soft-glow-glass/breathing-glow territory
  • Pale substrates: inner glow is nearly invisible on light panels, leaving a dirty rim
  • Alpha past ~25%: the wash starts smearing the panel's own content — the muted promise breaks
Accessibility

Inner light is decorative: selected/active states need textual/graphic redundancy (never light alone, WCAG 1.4.1); check text contrast for 4.5:1 against the brightest point of the wash (WCAG 2.1 SC 1.4.3); this material has no autonomous animation.

Browser support

inset box-shadow is fully baseline (long-standing MDN capability, verified) — zero fallback cost (research 17 §7.4); color-mix (Baseline 2023) appears only in the demo to turn the hex into translucent layers — production can write rgba() directly.

Fallback

No fallback needed: inset box-shadow is fully baseline (research 17 §7.4). The only caveat is paint order — the glow layer must come first (MDN: earlier layers paint on top); in the wrong order the top-edge light gets eaten by the wash.
