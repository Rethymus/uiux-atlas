Aspect Ratio

宽高比例 · aspect-ratio 属性 · 固定比例盒

One declaration locks a box's width-to-height ratio: change the width and the height follows; pair it with object-fit to decide whether images crop, letterbox or stretch inside — the foundation of video slots, avatars and CLS-proof cards.

Web Standard ★★
Live demo official default
Parameters
Motion▾

The box's preferred width/height ratio (CSS-type --ar-ratio feeding aspect-ratio). The 16 / 9 default is an MDN official example value; 1/1, 4/3, 3/2, 21/9 and 9/16 are common content ratios in the community (square avatars, 3:2 film, 16:9 HD video, ultrawide/vertical shorts), unverified as any spec recommendation — pick by content shape.

fitcover

The child img's object-fit (CSS-type --ar-fit; object-fit must sit on the image element, not the container — research 12 §1). The demo's sample image has an intrinsic 4:3 ratio, deliberately different from the default 16:9 box, so the three grades are unmistakable: cover crops, contain letterboxes, fill squashes.

Code breakdown

Structure & DOM

Ratio locking is a two-layer “container + replaced content” structure: the outer box declares the ratio, the inner image fills it:

<div class="ratio-box">
  <img src="photo.jpg" width="1200" height="900" alt="…" />
</div>
.ratio-box {
  width: 100%;
  aspect-ratio: 16 / 9;   /* omitting the height after the slash treats it as 1, e.g. 21 / 9 */
}
.ratio-box img {
  width: 100%;
  height: 100%;
  object-fit: cover;      /* must sit on the img, not the container (research 12 §1) */
}

Key points:

  • The ratio only applies when at least one of the box’s sizes is auto — hard-code both and the declaration is ignored (explicit MDN condition); in the demo the height stays auto, derived from the ratio;
  • aspect-ratio = auto || <ratio>: the auto <ratio> combination is special for replaced elements like img — the declared ratio reserves space before content loads, then the intrinsic ratio takes over (MDN);
  • The img’s width/height attributes (not CSS) let the browser reserve space at the intrinsic ratio before load — itself a CLS defense (the topic of MDN’s “Image aspect-ratio: preventing jank” guide);
  • object-fit decides how the image sits inside the ratio box: cover crops to fill, contain letterboxes, fill stretches — object-position then controls the crop anchor.

Styling & Parameters

Three parameters, all CSS-variable injected:

.ratio-box {
  width: var(--ar-width, 320px);          /* default 320px: demo baseline, unverified */
  aspect-ratio: var(--ar-ratio, 16 / 9);  /* default 16/9: an MDN official example value */
  overflow: hidden;
  border-radius: 12px;
}
.ratio-box img {
  object-fit: var(--ar-fit, cover);       /* cover / contain / fill */
}

Where the numbers come from:

  • 16 / 9, 1 / 1, 0.5 come from MDN’s official examples; the auto 3/2 placeholder-fallback form is likewise an MDN example;
  • The 4:3, 3:2, 21:9 and 9:16 presets in the panel are common content ratios in the community, unverified as spec recommendations — choose by content shape (square avatars, widescreen video, vertical shorts);
  • The sample image is deliberately 4:3 intrinsic (1200×900), different from the default 16:9 box, so the crop/letterbox/squash of the three object-fit grades is unmistakable.

Motion & Interaction

The ratio is a geometric constraint; interaction feedback rides the “width changes → height follows” derivation:

  • Dragging the width slider or switching the ratio re-flows instantly, no tween — transitions on layout properties would cause continuous re-layout, so restraint wins;
  • The demo readout shows both the measured height (ResizeObserver on the real layout) and the computed height (width × height/width); their constant equality is direct proof the ratio is active;
  • The box fades in over 0.45s with a 10px rise, animating only opacity/translate; disabled under prefers-reduced-motion;
  • Switching object-fit triggers no layout re-flow (fit affects painting only), so the three grades swap instantly.

Real-world examples

  • MDN’s official examples and the “preventing jank” guide: the 16/9 and 1/1 example values and the engineering advice “always give img width/height attributes against CLS” come from the MDN aspect-ratio page and its “See also” guide chain (verified live this session);
  • 16:9 slots on video/embed sites: reserving a 16:9 stage so the player and iframe never shift the page on load is the most widespread use of ratio (editorial summary — per-site implementations not individually verified; 16:9 itself is the MDN example value);
  • Feed image cards in social products: uploads arrive at every ratio, so products normalize the timeline with fixed-ratio slots + object-fit: cover to keep the grid tidy (editorial summary — per-product crop strategies not individually verified; the cover + ratio-box pairing follows MDN’s examples and the picture fragment convention in research 12 §1).

Parameter Sensitivity

Rules of thumb: let the ratio follow the content (video 16:9, avatars 1:1, article images around 3:2) rather than picking extremes for novelty; for any replaced content, width/height attributes + one auto CSS axis is the standard anti-CLS pairing.

When to use 4
  • Video/embed slots: reserve a 16:9 stage so iframes never shift the page
  • Avatars and thumbnails: a 1:1 box + object-fit: cover normalizes any upload
  • Grid/masonry placeholders: pre-load sizing in the target ratio kills CLS
  • Paired with responsive images: img width/height attributes + CSS constraining one axis, the browser derives the other from the intrinsic ratio (the width=1200 height=675 pair in research 12 §1)
When not to use 4
  • Hard-coding both width and height — no auto axis means the ratio is ignored (explicit MDN condition)
  • Ratio boxes around variable-length text — text overflows the frame; ratios suit replaced content, let body copy keep natural height
  • CSS ratio on img without width/height attributes — nothing reserves space pre-load, CLS returns
  • Extreme ratios like 21:9 for body illustrations — too short on mobile to read
Accessibility

A ratio box locks geometry, not content: edges cropped away by object-fit: cover may carry key image information — pair important images with sufficient alt text and prefer contain or a different ratio; img width/height attributes prevent load-time layout jumps (predictable layout per WCAG); decorative samples get alt=""; the demo's readouts are live, real measurements, never color-only signals.

Browser support

aspect-ratio is Baseline Widely available, working across browsers since 2021-09 (Chrome 88 / Firefox 89 / Safari 15 ballpark — the Baseline date verified on the MDN page this session; per-browser version numbers are not listed in the MDN body, defer to caniuse). object-fit is an older, widely available capability (research 12 §1 records its pairing constraint on picture's child img). · Baseline Widely available (2021-09)

Fallback

The legacy equivalent is the padding-top percentage hack (a pseudo-element with padding-top: 56.25% creates 16:9, content absolutely positioned over it) — a common community practice, unverified as an official recommendation; if the modern property is unsupported the box degrades to natural content height without breaking layout. Always add width/height attributes to img so space is reserved before load — itself a CLS defense (the topic of MDN's 'preventing jank' guide).
