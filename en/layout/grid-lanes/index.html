CSS Grid Lanes

grid-lanes · css-grid-3 · 瀑布流(曾名 masonry) · grid lanes layout

CSS Grid Level 3's lanes: display: grid-lanes drops items into column tracks one by one, stacking along the other axis and always entering the column with the most remaining space — a native Pinterest-style masonry.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
minTrack220px
px

The column track minimum. Default 220px from the research 11 §4B snippet repeat(auto-fill, minmax(220px, 1fr)); the official WebKit example uses a 250px variant (research 05 §5). Track definition is plain Grid — lanes only take over the stacking axis.

gap16px
px

Track and lane gap. Default 16px from the official WebKit example (research 05 §5 records gap: 16px); the lane axis and the track axis share one gap.

Motion▾
enginegrid-lanes

JS-type param (the demo switches engines). The grid-lanes mode writes the spec-recommended dual declaration display: grid; display: grid-lanes; — supporting engines render lanes, others fall back to a plain grid (whose row-band misalignment is exactly the problem lanes solve); the columns mode switches to the multi-column masonry fallback (works everywhere). The demo reports the active path live via CSS.supports().

Code breakdown

Structure & DOM

One flat layer: a lanes container plus sibling items — the same DOM as a plain Grid, only the display value changes:

<div class="wall">
  <article class="card">…</article>
  <article class="card">…</article>
  <!-- uneven heights, auto-placed -->
</div>

Key points:

  • New display values: grid-lanes (block-level) / inline-grid-lanes (inline); items are placed into predefined tracks on one axis (the grid axis) and stack freely on the other (the stacking axis) (research 11 §4B);
  • Auto-placement rule: unplaced items enter the column with the most remaining space, sized against already-placed items (research 05 §5 / 11 §4B);
  • New property fit-tolerance: normal | <length-percentage> | infinite (research 11 §4B);
  • The item-flow / item-* unification proposal was dropped, converging on grid lanes (Recent Changes on the 2026-01-21 Working Draft, research 05 §5);
  • Experimental: the syntax is not frozen (Safari 27.2 still renames a property, research 11 §4B); never make it the sole production dependency.

Styling & Parameters

Three parameters: minTrack / gap are CSS-type (—gl-min / —gl-gap), engine is JS-type:

.wall {
  display: grid;         /* fallback: all browsers (spec-recommended dual write, research 11 §4B) */
  display: grid-lanes;   /* Safari 26.4+ / Firefox Nightly */
  grid-template-columns: repeat(auto-fill, minmax(var(--gl-min), 1fr)); /* 220px (11 §4B snippet; WebKit example uses a 250px variant) */
  gap: var(--gl-gap);    /* 16px, official WebKit example (research 05 §5) */
}

/* columns multi-column fallback (works everywhere, order runs down columns) */
.wall[data-engine="columns"] {
  display: block;
  columns: auto var(--gl-min);
  column-gap: var(--gl-gap);
}
.wall[data-engine="columns"] .card { break-inside: avoid; margin-bottom: var(--gl-gap); }

Where the numbers come from: minmax(220px, 1fr) and gap: 16px come from the research 11 §4B snippet and the official WebKit example (05 §5 uses a 250px variant); the dual-write degradation comes straight from the css-grid-3 spec text (research 11 §4B); support data: BCD display.json marks grid-lanes experimental — Safari/iOS 26.4, Firefox Nightly preview, Chrome unsupported (research 11 §4B, fetched 2026-11-22).

Motion & Interaction

Lane placement happens at the layout stage — no animation:

  • Entering “the column with the most remaining space” is a layout algorithm, instantaneous; adding or removing items rebalances the columns;
  • The demo detects and honestly reports the active path via CSS.supports('display', 'grid-lanes'): supported → lanes; unsupported → plain-grid fallback (whose row-band misalignment is exactly the problem lanes solve);
  • engine toggles data-engine between the dual-write declaration and the columns fallback;
  • The status chip cross-fades over 0.25s, disabled under prefers-reduced-motion.

Real-world examples

  • Pinterest — the css-grid-3 draft names Pinterest search results as the typical example of “items placed into the column with the most remaining space” (verified against research 05 §5).
  • WebKit’s official tutorial site gridlanes.webkit.org — the official interactive tutorial, shipped with the “Field Guide to Grid Lanes” (research 11 §4B).
  • Chrome for Developers’ “CSS masonry” — Rachel Andrew’s proposal of an independent layout model on behalf of the Chrome team; the post now carries a note that its examples predate the draft and “Grid lanes layout per css-grid-3” is authoritative (research 05 §5).

Parameter Sensitivity

ParameterTurning it up…Turning it down…
minTrackfewer lanes: each lane widens and carries more items; at 400px a narrow container has one lanemore, narrower lanes: below ~120px text squeezes; more lanes make the “most remaining space” allocation finer-grained
gaplarger lane and track gaps: airier layout, height differences amplified by gapsdenser layout: height differences read more continuously, approaching a seamless masonry
enginegrid-lanes: lanes without row bands on supporting engines; a plain grid (row-band misalignment) elsewherecolumns: an everywhere-consistent masonry, but column-wise order decouples DOM order from visual order

Working notes: write the dual declaration today (the spec’s own degradation path), but real deployments still need columns/JS fallbacks (research 05 §5); keep order-sensitive content (step flows, rankings) off lanes; wait for Safari 27.2’s naming to settle before a full switch.

When to use 4
  • Pinterest-style image/product walls — uneven heights, each item into the column with the most remaining space (Safari 26.4+ / Nightly)
  • Forward-looking progressive enhancement: write the dual declaration now — lanes render on Safari 26.4+/Nightly, a plain grid elsewhere
  • Prototyping lane arrangement and fit-tolerance behavior (the spec's new property: normal | <length-percentage> | infinite)
  • Search result streams — the css-grid-3 draft names Pinterest search results as the typical example (research 05 §5)
When not to use 4
  • Sole production dependency — Chrome unsupported, Firefox Nightly-only, Safari still renaming properties (research 11 §4B); always keep a fallback
  • Lists read in row order — lanes fill column-wise, decoupling visual order from DOM order (same trade-off as columns)
  • Editorial layouts needing exact item positions — auto-placement 'into the column with most space' is not specifiable
  • Treating the dual write as a silver bullet — the plain-grid fallback misaligns row bands for uneven heights; serious cases still need columns/JS fallbacks
Accessibility

Lane placement reorders the visual reading sequence while the DOM order remains authoritative (WCAG 1.3.2 Meaningful Sequence) — keyboard focus and screen-reader order follow the DOM and may diverge from visual column order; be careful with order-sensitive content; the fallback (plain grid) and the enhancement (lanes) carry identical content with equivalent accessibility; new properties like fit-tolerance change no accessibility semantics; in production, verify keyboard navigation on the fallback path too.

Browser support

Experimental (BCD display.json marks grid-lanes experimental; research 11 §4B, fetched 2026-11-22): Safari / iOS 26.4 onward; Firefox Nightly preview; Chrome unsupported. WebKit-official: trialable in Safari Technology Preview 234 (research 05 §5); no reliable source on Firefox's stable timeline (research 05 §5 says so explicitly). The item-flow/item-* proposal was dropped (research 05 §5); Safari 27.2 still renames a property (research 11 §4B) — the syntax is not frozen; do not depend on it in production.

Fallback

The spec text itself prescribes the graceful degradation — the dual declaration: display: grid; display: grid-lanes; unsupported UAs ignore the second line and render a plain grid (research 11 §4B). A plain grid misaligns row bands for unequal-height items (each row tops out at its tallest), so real deployments still need columns multi-column or JS fallbacks (research 05 §5). The demo implements exactly the dual write and reports the active path live via CSS.supports('display', 'grid-lanes').
