position: sticky

position-sticky · 粘滞定位 · 吸顶 · 粘滞区域

The element scrolls with its container, then sticks once it reaches the offset threshold of the nearest scrolling ancestor — position: sticky; top: 20px; never leaves document flow, and one line buys sticky table headers and sidebars.

Web Standard ★★
Live demo official default
Parameters
Geometry▾
top20px
px

The sticking offset threshold (CSS-type, injected as --sticky-top). Default 20px follows the example recorded in research 05 §7 — position: sticky; top: 20px; the element parks 20px from the scroll container's top; 0px heads toward global-nav usage, while reserving a threshold stacks cards on top of each other.

Motion▾
trapoff

JS-type param (the demo toggles data-trap, wrapping the scrolled content in an overflow: hidden ancestor). sticky only answers to the 'nearest scrolling ancestor' — any intermediate ancestor with overflow other than visible becomes a mistaken scroll container and breaks sticking. This is sticky's most common production accident, not a compatibility bug.

Code breakdown

Structure & DOM

A two-layer structure: a scroll container (an overflow-scrolling ancestor) plus sticky elements (headers/navs/sidebars declaring sticky). Sticky elements never leave document flow, so nothing after them shifts up.

<div class="scroll-box">          <!-- nearest scrolling ancestor: the frame of reference -->
  <section>
    <h4 class="sticky-head">§1 Group header</h4>  <!-- position: sticky -->
    <p>…</p><p>…</p>
  </section>
  <section>…</section>
</div>

Key points:

  • position: sticky; top: 20px; — the element scrolls with its container, then parks at the offset threshold of its nearest scrolling ancestor, without leaving document flow (research 05 §7);
  • The sticky range is bounded by the parent container: once the parent scrolls past, the sticky element goes with it;
  • sticky only answers to the “nearest scrolling ancestor” — any overflow: hidden/auto/scroll in the ancestor chain hijacks it (see the demo’s trap mode);
  • Baseline Widely available since 2015-07 (MDN position, research 05 §7).

Styling & Parameters

Two parameters: top is CSS-type (—sticky-top), trap is JS-type (data-trap toggles the trap wrapper):

.scroll-box {
  height: 300px;
  overflow-y: auto;          /* nearest scrolling ancestor */
}
.sticky-head {
  position: sticky;
  top: var(--sticky-top);    /* 20px, the example value from research 05 §7 */
  background: <solid>;        /* must be solid, or content shows through from below */
  transition: box-shadow 0.2s ease;
}
.sticky-head[data-stuck="true"] { box-shadow: 0 4px 14px rgba(0,0,0,.18); }

/* trap mode: an overflow ancestor inserted between content and headers kills sticking */
.trap { overflow: hidden; }

Where the numbers come from: top: 20px is the example recorded in research 05 §7; Baseline 2015-07 (MDN position, research 05 §7); the stuck shadow and solid background are demo-layer styling.

Motion & Interaction

Sticking is a state change, not an animation:

  • The “scrolling → parked at threshold” switch is instantaneous; the demo drives its status chip from a real scroll listener (stuck when the header rectangle is within the threshold of the container top), never faked with timers;
  • The stuck moment deepens a shadow (0.2s box-shadow transition) as a status hint; disabled under prefers-reduced-motion;
  • The “Top” button scrolls instantly (scrollTo default behavior), adding no gratuitous smooth animation;
  • Dragging the top slider retunes the threshold live: 0px hugs the top (global-nav territory), larger values park headers lower.

Real-world examples

  • The MDN Layout Cookbook — collects Sticky footers (footer pinned on short pages, Grid/Flexbox) and the Split navigation recipe (research 05 §7).
  • Group headers on long lists — the Web twin of iOS grouped lists: scroll to a group and its header parks at the threshold (editorial content).
  • Sticky table headers — column names stay visible while long tables scroll; a universal back-office pattern (editorial content).

Working notes: the sticky range = its parent container; sticky elements need a solid background; keep the ancestor chain overflow: visible up to the scroll container; design stacked-sticky thresholds and z-indexes on paper before coding.

When to use 4
  • Group headers on long lists/forms — the current group's header parks at the threshold while you scroll
  • Sticky table headers keeping column names visible in long tables
  • Doc-site sidebars and global navs (kin to MDN Cookbook's Split navigation, research 05 §7)
  • Sticky footers pinning to the bottom on short pages (Grid/Flexbox recipe, MDN Cookbook, research 05 §7)
When not to use 4
  • Layouts with any overflow: hidden/auto/scroll ancestor — sticky gets hijacked; fix the structure first (the demo's trap mode shows exactly this)
  • Sticky elements near their parent's end — once the parent scrolls past, the element goes with it; the parent bounds the sticky range
  • Large sticky layers covering content with no way to dismiss — overlaying is a layout decision, not a default
  • Stacking many sticky layers without a worked-out z-index/threshold plan — design the thresholds on paper before coding
Accessibility

sticky changes visual position only and never leaves document flow — DOM and screen-reader order are unchanged; a sticky layer must not cover focused controls: browsers scroll focused elements into view on Tab, but overlap zones between the sticky layer and content still need manual checking; controls on sticky toolbars stay reachable; the stuck state itself carries no information — never let 'parks at the top' be the only carrier of group semantics (the header text is the carrier).

Browser support

Baseline Widely available since 2015-07 (MDN position, research 05 §7) — all three engines ship it; the real risk is structural (ancestor overflow / parent height), not compatibility. · Baseline Widely available (2015-07)

Fallback

No compatibility fallback needed; on ancient engines the element simply scrolls in normal flow and content stays reachable. What actually needs guarding is structural failure: (1) any ancestor with overflow: hidden/auto/scroll hijacks the sticky element (see the demo's trap mode); (2) a too-short parent container carries the element away — the sticky range is bounded by its parent.
