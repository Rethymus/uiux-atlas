Custom Scrollbar

scrollbar-color · scrollbar-width · ::-webkit-scrollbar · scrollbar-gutter

Two implementations, one interoperability truth: the standard scrollbar-color/width properties are the Firefox route (Chrome 121+, Safari 26.2 caught up), the ::-webkit-scrollbar pseudo-elements are the WebKit legacy — and once scrollbar-width ≠ auto, the whole webkit family is ignored; scrollbar-gutter reserves the slot so layouts stop jumping.

Web Standard ★★★
Live demo official default
Parameters
Motion▾
enginestandard

The dual-implementation switch (JS-type, applied as data-engine). standard writes scrollbar-width/color; webkit deliberately leaves the standard properties alone (computed stays auto) to activate the ::-webkit-scrollbar family — the constructive use of research 10 §8.3's interop fact; Firefox doesn't implement the webkit pseudos, so that grade does nothing there, and the demo's readout says so.

widththin

The scrollbar-width value (JS-type). The thin default echoes the site-wide thin-scrollbar convention recorded in the round-2 report (scrollbar-width: thin + scrollbar-color inherited at root) and the 10 §8.4 fragment; the none grade triggers the demo's MDN warning — harms accessibility/WCAG 2.1.1 keyboard scrolling (research 10 §8.3); under the webkit grade this param doesn't apply (the pseudos use a fixed 12px demo baseline, unverified).

gutterauto

The scrollbar-gutter value (CSS-type --sb-gutter). auto is the spec initial value; stable reserves the gutter under classic scrollbars even when content doesn't overflow, preventing the 'content grows → scrollbar appears → layout jumps' effect, with a both-edges modifier for symmetry (MDN, verified this session); overlay scrollbars (e.g. macOS default) take no slot, so the property has no effect there. Baseline 2024 Newly available (2024-12).

Color▾
thumb#6a5cff

The thumb color (CSS-type --sb-thumb, feeding scrollbar-color's first value and the ::-webkit-scrollbar-thumb background). The #6a5cff default is verbatim from research 11 §9's fragment html { scrollbar-color: var(--brand, #6a5cff) transparent } — piping the brand variable through is part of the 'one-line control re-skin' signature idea (research 11 §10-8).

track#00000000

The track color (CSS-type --sb-track, feeding scrollbar-color's second value and the ::-webkit-scrollbar-track background). The default #00000000 (8-digit hex, fully transparent) equals the transparent in research 11 §9's fragment — a hollow track floats the scrollbar over content, the common pairing for thin scrollbars.

Code breakdown

Structure & DOM

Scrollbar styling goes on the scroll container; both implementations can live in the same stylesheet, splitting automatically by the interop fact:

<div class="list" tabindex="0" role="region" aria-label="Messages">
  <div class="row">…</div>
</div>
.list {
  overflow: auto;
  scrollbar-gutter: stable;              /* reserve the slot; growing content stops jumping the layout (MDN use case) */
}
/* Standard route: css-scrollbars */
.list {
  scrollbar-width: thin;                 /* auto | thin | none */
  scrollbar-color: var(--brand, #6a5cff) transparent;  /* thumb / track (research 11 §9 fragment) */
}
/* WebKit route: non-standard pseudos, Blink/WebKit only, unimplemented in Firefox */
.list::-webkit-scrollbar { width: 12px; height: 12px; }
.list::-webkit-scrollbar-thumb { background: var(--brand, #6a5cff); border-radius: 6px; }
.list::-webkit-scrollbar-track { background: transparent; }

Key points:

  • The interop fact (MDN verbatim, research 10 §8.3): once an element’s computed scrollbar-width ≠ auto, the ::-webkit-scrollbar family is ignored; writing back auto restores it — the demo’s standard grade uses exactly this to retire the webkit styles;
  • The purpose of scrollbar-width is saving space, not aesthetics; a value set on root applies to the viewport (research 10 §8.3);
  • scrollbar-color: <thumb> <track> needs both values; the gutter made by scrollbar-gutter sits between the inner border edge and the outer padding edge, painted as a padding extension when no scrollbar shows (verified on MDN this session);
  • Overlay scrollbars (macOS default) float over content and take no slot — scrollbar-gutter has no effect on them (verified this session).

Styling & Parameters

Five parameters: the dual-engine switch, the width, thumb/track colors and the gutter policy:

[data-engine="standard"] .list {       /* JS-type switch */
  scrollbar-width: var(--sb-width, thin);
  scrollbar-color: var(--sb-thumb, #6a5cff) var(--sb-track, #00000000);
}
[data-engine="webkit"] .list::-webkit-scrollbar { width: 12px; }  /* demo baseline, unverified */
[data-engine="webkit"] .list::-webkit-scrollbar-thumb { background: var(--sb-thumb, #6a5cff); }
[data-engine="webkit"] .list::-webkit-scrollbar-track { background: var(--sb-track, #00000000); }
.list { scrollbar-gutter: var(--sb-gutter, auto); }

Where the numbers come from:

  • #6a5cff and the transparent track are verbatim from research 11 §9’s fragment html { scrollbar-color: var(--brand, #6a5cff) transparent }; the demo expresses the same hollow track as 8-digit hex #00000000;
  • The thin default echoes the site-wide thin-scrollbar convention recorded in the round-2 report (scrollbar-width: thin + scrollbar-color inherited at root) and the research 10 §8.4 fragment;
  • Support matrix (BCD, research 11 §9): scrollbar-color Chrome 121 / Firefox 64 / Safari 26.2 (Android WebView not yet); scrollbar-width Baseline 2024-12 (research 10 §8.3); scrollbar-gutter Baseline 2024 Newly available since 2024-12 (verified this session); WebKit officially advises dropping ::-webkit-scrollbar from Safari 26.2 (research 11 §9);
  • The webkit grade’s 12px width is a demo baseline, unverified — pseudo-element values are author-chosen with no spec default.

Motion & Interaction

Scrollbars produce no motion themselves; the demo’s interaction is about switching grades and guarding the cliff:

  • engine switch: standard writes the standard properties (the webkit pseudos are retired automatically by the interop fact); the webkit grade deliberately leaves them unwritten so computed stays auto and the pseudos wake up — the handoff between the two implementations is visible on switch;
  • width grades: thin is the site-wide convention; auto returns to the system; none hides the bar and the demo raises a warning box — MDN is explicit that it harms accessibility/WCAG 2.1.1 keyboard scrolling (research 10 §8.3);
  • Support readouts: CSS.supports('scrollbar-width'/'scrollbar-color'/'scrollbar-gutter') runs on mount; when the standard grade can’t work on this engine (e.g. Safari < 26.2), the demo says so plainly;
  • gutter comparison: auto↔stable shows whether the right edge keeps its slot even without overflow; the scroll region carries tabindex=0 for arrow-key scrolling;
  • The container’s entrance (0.4s fade + rise) animates only opacity/translate, dropped under prefers-reduced-motion; no transitions on scrollbar styling — pseudo-elements don’t participate in transitions.

Real-world examples

  • Site-wide control re-skinning (research 11 §10-8 signature idea): accent-color + color-scheme + scrollbar-color all fed by brand variables, auto-flipping in dark mode — scrollbars as first-class citizens of the theme system (fragment origin in research 11 §9);
  • Thin scrollbars in code blocks and dense data areas: doc sites and IDE-style web apps commonly give code panels scrollbar-width: thin (the same site-wide convention recorded in the round-2 report) — space saved, attention undisturbed (research 10 §8.3: “the purpose is saving space, not aesthetics”);
  • The MDN scrollbar-gutter use cases (verified this session): the official three — stable against layout jumps as content grows, stable both-edges for symmetric spacing, aligning adjacent scrolling/non-scrolling containers — the demo’s gutter parameter implements exactly these.

Rules of thumb: standard properties first, webkit pseudos as the double-write fallback; none only with an alternative scroll indicator; wire colors through brand variables so theme switches cover them automatically.

When to use 4
  • Site-wide scrollbar branding: scrollbar-color on :root fed by the brand variable, auto-flipping in dark mode (research 11 §9 fragment and §10-8 idea)
  • Thin scrollbars in dense data and code blocks: thin saves space without stealing attention (research 10 §8.3: 'the purpose is saving space')
  • Chat streams and terminal panels: webkit pseudos for capsule thumbs and pixel-level control in Blink/WebKit
  • List containers with scrollbar-gutter: stable reserving the slot so layouts stop jittering as content grows (MDN use case, verified this session)
When not to use 4
  • scrollbar-width: none as decoration — MDN warns it harms keyboard scrolling (WCAG 2.1.1, research 10 §8.3)
  • Heavy customization of the viewport scrollbar — a root value applies to the viewport and breaks users' system mental model (research 10 §8.3 root behavior)
  • Assuming webkit pseudos work everywhere — Firefox doesn't implement them and WebKit has advised dropping them since Safari 26.2 (research 11 §9)
  • High-decoration thumb colors — thumb and track must hold contrast against content and each other; decorative palettes still pass WCAG 1.4.11 non-text contrast
Accessibility

The scrollbar is an affordance: hiding it (none) removes the 'this scrolls' cue, and MDN explicitly warns of the WCAG 2.1.1 keyboard-scrolling impact (research 10 §8.3); custom colors must hold two non-text contrasts at once — thumb-vs-track and thumb-vs-content (WCAG 1.4.11); give scrollable regions tabindex=0 with role/aria-label so keyboard users can Tab in and scroll with arrows; decorative changes never alter scrolling behavior or screen-reader output; prefers-reduced-motion has no interaction with scrollbar styling, nothing special needed.

Browser support

scrollbar-width is Baseline 2024-12 (research 10 §8.3); scrollbar-color Chrome 121 / Firefox 64 / Safari 26.2, Android WebView not yet (BCD, research 11 §9; from Safari 26.2 WebKit officially advises dropping ::-webkit-scrollbar); the non-standard ::-webkit-scrollbar is long-broadly available in the WebKit/Blink family and unimplemented in Firefox; scrollbar-gutter is Baseline 2024 Newly available since 2024-12 (verified on MDN this session). On Safari < 26.2 the standard grade has no effect while the webkit grade works.

Fallback

The dual-write strategy is the structural fallback: standard properties and webkit pseudos coexist in the stylesheet and split naturally by the interop fact — engines supporting the standard prefer it (scrollbar-width ≠ auto disables the webkit pseudos), legacy WebKit takes the pseudos, Firefox takes the standard; engines supporting neither keep the native scrollbar — functionality intact, only decoration lost. Never hide scrollbars with none for aesthetics — MDN is explicit that it harms keyboard-scrolling accessibility (WCAG 2.1.1).
