Container Queries

容器查询 · @container · 组件级响应式

Components respond to their container's width, not the viewport: @container breakpoints re-flow cards, and container units (cqw/cqi) let inner sizes track the host.

Code breakdown

Structure & DOM

Container queries are a two-layer host/component structure: the host declares itself a container, and the component branches on the container’s conditions. The host is never queried — only its descendants are.

<!-- Host: any layout position (sidebar / main column / dialog) -->
<aside class="widget-host">
  <!-- Container: the queried element; must declare container-type first -->
  <div class="card-container">
    <article class="card">…</article>
  </div>
</aside>

Key points:

  • container-type: inline-size turns an element into a size container (the common choice; size also takes over the block axis — avoid it on ordinary components, research 05 §6);
  • @container queries the nearest eligible ancestor container, and container-name targets one container among several;
  • Queryable features: width/height/inline-size/block-size/aspect-ratio/orientation; the container units cqw/cqh/cqi/cqb/cqmin/cqmax ship with the same mechanism (cqi = 1% of the container’s inline size);
  • style() queries can inspect custom-property computed values, but the per-browser matrix was not verified in the research (unverified) — use with care in production.

Styling & Parameters

The two parameters divide cleanly: width is CSS-type (the —cq-width variable); breakpoint is JS-type — query conditions must be literals, custom properties are not allowed, so the demo regenerates the rule on change.

.card-container {
  container-type: inline-size;
  container-name: cq-card;
  width: var(--cq-width);           /* 400px: CSS-type parameter */
}

/* Stacked by default (progressive enhancement: works as-is without container queries) */
.card { display: flex; flex-direction: column; gap: 10px; }
.card .banner { height: 64px; height: 18cqw; }          /* fixed value first, container unit after */
.card .title  { font-size: clamp(15px, 5.5cqi, 30px); } /* cqi + clamp keeps a floor */

/* Breakpoint (JS-type, 320px) — regenerated by the demo; var() is not legal here */
@container cq-card (min-width: 320px) {
  .card { flex-direction: row; align-items: stretch; }
  .card .banner { width: 42cqi; height: auto; min-height: 110px; }
  .card .title  { font-size: clamp(17px, 7cqi, 30px); }
}

Where the numbers come from: Baseline 2023-02 (MDN container-type, research 05 §6: Chrome/Edge 105, Safari 16 (2022), Firefox following); MDN’s example breakpoint syntax reads (min-width: 40rem); the demo’s 400px/320px are task-spec demo values — production breakpoints should follow the component’s own content.

Motion & Interaction

The re-flow is a layout switch, not an animation:

  • Crossing the breakpoint flips stacked/row instantly with no transition — flex-direction is not animatable, and forcing one just flickers;
  • The demo grip uses pointer capture and shares one store value with the panel slider (two-way sync); the grip is a WAI-ARIA separator with arrow keys at ±10px (Shift ±50px) as the keyboard equivalent (same pattern as the accessible split-view libraries in research 05 §8);
  • The state badge’s color change has a 0.25s transition, disabled under prefers-reduced-motion;
  • cqw/cqi sizes change continuously while dragging — that is “component-level fluidity”: no JS, no breakpoints.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
widthwidens the container: in row form the banner (42cqi) and headline (7cqi) scale up proportionally, hitting the clamp ceiling near 800pxnarrows it: below the breakpoint the card returns to stacked; the banner (18cqw) flattens and the headline rests on its 15px floor — beyond that it just stays fixed
breakpointmoves the threshold right: the stacked range grows, wider containers stay stacked, and the row form arrives latermoves it left: the row form appears earlier and can crush text in narrow containers; below 200px almost every width renders as a row

Working ranges: one or two content-driven breakpoints per component (flip to a row when the headline fits two lines); proportional elements like banners and headlines ride cqw/cqi with a clamp floor; keep host and component separate — never make the page the container.

When to use 4
  • A card living in sidebars, main columns and dialogs — one component, three shapes by host width
  • Design-system components: form rows, button groups and media objects collapsing to stacked in narrow hosts
  • Headlines sizing in cqi with a clamp floor — a container-local alternative to viewport fluid type
  • Migrating from page-level to component-level breakpoints (the third stage of research 05 §11's evolution chain)
When not to use 4
  • Making the whole page a container — page-level response belongs to media queries; container queries manage components
  • container-type: size on ordinary components — it detaches the container from content sizing and risks circular dependencies; prefer inline-size
  • Stacking as many container breakpoints as viewport breakpoints — the point is fewer breakpoints; one or two content-driven ones suffice
  • Custom properties inside query conditions — conditions must be literals; the demo regenerates rules via JS for that reason
Accessibility

Breakpoint re-flow changes visuals only, never DOM order — Tab and screen-reader order stay stable; after stacked/row switching, controls must remain reachable and hover-independent; cqi/cqw-driven font sizes need a clamp floor so an over-narrow container cannot push text below readable size; the drag grip needs a keyboard equivalent (arrow keys in the demo, echoing the WAI-ARIA separator pattern, research 05 §8).

Browser support

@container and container-type are Baseline Widely available since 2023-02 (MDN, research 05 §6): Chrome/Edge 105, Safari 16 (2022), Firefox following (its exact version is not recorded in the research). Container units cqw/cqi ship with the same mechanism; the per-browser matrix for style() queries was not verified in the research (unverified) — the demo does not use style(). · Baseline Widely available (2023-02)

Fallback

Progressive enhancement: write the stacked layout first (usable as-is where container queries are unsupported), then layer the horizontal layout inside @container — legacy browsers keep the stacked card without errors; give cqw/cqi sizes a fixed px declaration first so unsupported engines cascade back. Page-level responsiveness stays with media queries — the two divide labor rather than replace each other.
