Design Tokens

6 steps

When you finish you can: define a primitive/semantic/component token inventory; support multi-theme with "one vocabulary, many mappings" (swap mappings, zero component changes); give theme switching a transition gated by reduced-motion; make type and spacing flow with the viewport via clamp as responsive token values; and auto-derive every role from a brand source color — source swap + theme switch + window resize stack with no regression.

Who it's for Frontend/design engineers turning a design language into code assets: three-layer tokens, multi-theme mapping and registry engineering.

Path steps

  1. 01

    Semantic Token Layers ENTRY

    Why now Vocabulary first: the platform-agnostic token methodology underpins everything after — M3 places design-tokens at the end of Foundations before customization, "learn tokens before reskinning".

  2. 02

    Multi-Theme Tokens ENTRY

    Why now Above the vocabulary comes "one vocabulary, many mappings": the official theming mechanisms of M3/Semi/Arco share the order tokens → multi-theme → customization — three themes by swapping the mapping file alone, zero component changes.

  3. 03

    Theme Transition ENTRY

    Why now Switching exists only once themes do: View Transitions carries the crossfade, gated by prefers-reduced-motion downgrading to an instant swap.

  4. 04

    Fluid Type Scale ENTRY

    Why now Upgrade from static mappings to responsive token values: clamp lets type scale flow with the viewport, with M3 type-scale tokens as the tier reference.

  5. 05

    Fluid Spacing ENTRY

    Why now The same tools (clamp/calc) move to the spacing axis — deliberately adjacent to transfer practice, with spacing scaling continuously and no breakpoint jumps.

  6. 06

    Brand Color System ENTRY

    Why now Converge on the full pipeline: source color → palette → roles auto-derivation is M3's official dynamic color chain — swap the source and every role regenerates with zero component changes.

Self-check

Tick each criterion as you verify it; progress is saved in your browser (localStorage), never synced to a server.
