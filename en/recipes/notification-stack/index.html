Notification Stack

3 entries

Toast spring + progress motion + shake decay: the notification stack composition.

Combines

Toast Spring Entrance A toast springs in from the screen edge: the entrance carries overshoot (a true spring or a y₂>1 overshoot bezier), the exit is a pure eased settle, and the lifecycle auto-dismisses on time — attack in, retreat out, the pair never collides. Component Lib ★★★ Progress Motion Progress form follows certainty: skeleton blocks (nothing known) → looping sweep (loading, but not how long) → percent bar (exactly how much is left) → fast fade-in completion; the form switches at NN/g duration thresholds, and momentum builds toward the end (goal-gradient). Community ★★ Shake · Exponential Decay Error shakes are best built as the decaying sinusoid x(t)=A·e^(−λt)·sin(ωt): two implementations side by side — CSS decay keyframes vs injecting initial velocity and letting the spring decay itself — continuous under rapid re-triggers. Community ★★★

Why these combine

Research 16 §7 recipe-f (§8 craft 7: "the toast stack is a state machine, not a message stream"): Ant has the fullest stack numbers — message duration 3s / top 8 / maxCount auto-closing the oldest / key reuse of the same toast / stack mode (6.4.0); notification duration 4.5s / placement topRight / stack{threshold:3} / showProgress bar (5.18+) / pauseOnHover (default true) / width 384 / top·bottom 24px (https://ant.design/components/notification-cn/ ; https://ant.design/components/message-cn/ ); M3 snackbar is the counterweight — no-action auto-dismiss 4–10s, only one at a time full-screen, at most one action, and web auto-dismiss must pair with inline feedback or an operable path (https://m3.material.io/components/snackbar/guidelines ). The demo takes Ant numbers as stack discipline and toast-spring entry defaults as spring params: stiffness 300 / damping 25 (ζ≈0.722, overshoot ≈3.8% and no more) / edge bottom / lifetime 4000ms (sonner TOAST_LIFETIME source value); the official spring basis is M3 Expressive motion-physics (spatial + effects springs, the latter owning color/opacity transitions — the narrowing progress bar is exactly that form, https://m3.material.io/blog/building-with-m3-expressive ); the entrance band = TDesign drawer/notification/message 280ms desktop / 140ms mobile with dialogs classified as Z-axis motion, and the perceptual-constancy rule "desktop = mobile ×2" (https://tdesign.tencent.com/design/motion ); the demo progress bar = Ant notification showProgress semantics (countdown narrowing with remaining lifetime, hover pauses = pauseOnHover default true). Shake decay has no official recipe anywhere → unverified (§9 list); the nearest official neighbors are TDesign listing "input shake" as a micro-motion example and Apple's visionOS line against ~0.2Hz sustained oscillation (https://developer.apple.com/design/human-interface-guidelines/motion ); the demo takes shake-decay entry defaults A=10px (animate.css shakeX's ±10px scale) / λ=6s⁻¹ (research 10 §4.3 sampling example: 5 beats/0.5s, envelope ×0.74 per beat) — a decaying transient, not sustained oscillation. Composition glue: the spring owns entrance/exit only, the progress bar owns remaining lifetime only, the shake owns field-level errors only — the three motions never stack; Esc dismisses the newest toast and restores focus; reduced-motion degrades entrance/exit to pure fade and stops the shake (error semantics carried by text and border).

Source out/design-study/16-composition-recipes.md §7 配方 f「通知栈」+ §8 巧思 7(依据:Ant message/notification Token、M3 snackbar/m3-expressive、TDesign motion、Apple Motion ~0.2Hz 红线;摇晃衰减未证实,按条目 schema 默认落地)
