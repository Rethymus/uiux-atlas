Segmented Form Flow

4 entries

Steps + M3 state layers + a spring submit toast + keyboard navigation: the stepped-form composition.

Combines

Steps Split complex tasks into an ordered sub-step navigation: nodes strung on connectors with wait/process/finish/error derived automatically, and a progress ring on the process step. Component Lib ★★★ State Layers (M3) Material 3 state layers: a low-opacity overlay of the content color on top of a control, with fixed percentages distinguishing hover/focus/press/drag instead of ad-hoc colors. Material 3 ★★★ Toast Spring Entrance A toast springs in from the screen edge: the entrance carries overshoot (a true spring or a y₂>1 overshoot bezier), the exit is a pure eased settle, and the lifecycle auto-dismisses on time — attack in, retreat out, the pair never collides. Component Lib ★★★ Keyboard Navigation Tab/Shift+Tab moves between components, arrow keys move inside composites (roving focus); focus indicators stay visible, focus is never lost, and modal traps must release via Esc and return focus. Web Standard ★★★

Why these combine

Research 16 §7 recipe-c: steps use Ant Steps — "split into a series of steps when the task is complex or ordered", auto-vertical under 532px, status's four states can mark the error step, percent progress ring (https://ant.design/components/steps-cn/ ); ProForm StepsForm keeps full data per step and merges at the end (https://procomponents.ant.design/components/steps-form/ ); the Ant form-page template rule: a stepped form = linear task split + progress made visible by the step bar + **one final confirmation right before submitting** (https://ant.design/docs/spec/research-form-cn/ ) (§8 craft 6: "the step bar is a promise list"). All button/step-header feedback goes to M3 content-color state layers: hover +8%, focus +10%, press +10%, one layer at a time, color taken from the content color (https://m3.material.io/foundations/interaction/states/state-layers ). Submit feedback = a spring toast: the official spring basis is M3 Expressive motion-physics (spatial + effects springs, https://m3.material.io/blog/building-with-m3-expressive ), demo params take the entry-schema defaults stiffness 300 / damping 25 (ζ≈0.722, overshoot ≈3.8%), edge bottom, lifetime 4000ms (sonner TOAST_LIFETIME source value); Ant's split: light feedback = 3s message, heavy = result page countdown (https://ant.design/components/message-cn/ ; https://ant.design/docs/spec/research-result-cn/ ); the counter-rule: TDesign "UI uses Cubic curves only, Elastic is for cartoon illustration" — the spring stops at a slight overshoot (https://tdesign.tencent.com/design/motion ); no vendor publishes a form-step spring parameter table → unverified. Keyboard navigation = Ant Modal keyboard-Esc default true + focusable{trap} (https://ant.design/components/modal-cn/ ) + Apple "bind the primary button to Return" (https://developer.apple.com/design/human-interface-guidelines/buttons ), with the law citation backed by WAI-ARIA APG Dialog focus management (https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/ ); step headers form a toolbar with roving tabindex + arrow keys (APG / keyboard-navigation entry).
