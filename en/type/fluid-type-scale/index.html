Fluid Type Scale

流式字阶 · Utopia 字阶 · clamp() 字阶

Font sizes interpolate linearly with the viewport: clamp(floor, rem+vw, ceiling) builds a --step-0..5 ladder — never below the floor, never above the ceiling, smooth in between.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
minViewport480px
px

The viewport where interpolation starts: below it, sizes sit at each step's clamp floor; the slope = (max−min)/(maxVw−minVw) anchors here. Default 480px is this entry's task-spec value; Utopia's recorded output sample (research 05 §13) back-solves to ≈360px (Utopia does not document the viewport default directly — both stated side by side).

maxViewport1440px
px

The viewport where interpolation ends: above it, sizes sit at each step's clamp ceiling. Default 1440px is the task-spec value; Utopia's sample back-solves to ≈1240px (not directly documented — both stated). A wider range flattens the slope, making desktop scaling subtler.

minSize1rem
rem

The floor of --step-0 and the base of the ladder (body-size floor). Default 1rem (16px root) is the common body baseline; Utopia's measured sample uses 1.125rem. Pricing in rem keeps browser font-size settings and zoom working.

maxSize1.25rem
rem

The ceiling of --step-0 (body size on large viewports). Default 1.25rem matches the max of --step-0 in Utopia's first-hand measured output (research 05 §13).

ratio1.25

The modular ratio: each step multiplies both that step's min and max by it. Default 1.25 is one of Utopia's selectable ratios (modularscale's 4:5 major third, research 05 §13/§17). Utopia allows separate min/max ratios (its sample used 1.2/1.25); this entry simplifies to one ratio for both.

Code breakdown

Structure & DOM

A fluid type scale needs no extra DOM — it is a layer of CSS custom-property tokens: define --step-0..5 on :root, and components pick them up semantically.

<body>
  <h1 class="step-5">Headlines that scale with the viewport</h1>
  <p class="step-0">Body copy keeps its base size.</p>
</body>
:root {
  --step-0: clamp(1rem, 0.875rem + 0.4167vw, 1.25rem);
  --step-1: clamp(1.25rem, 1.0938rem + 0.5208vw, 1.5625rem);
  /* … --step-2..5 generated the same way */
}

Key points:

  • The viewport range minViewport/maxViewport and the size range minSize/maxSize are two parallel rulers: slope = (max−min)÷(maxVw−minVw), with viewports converted to rem at a 16px root;
  • Each step multiplies both its min and max by the ratio (Utopia allows separate ratios per side; this entry simplifies to one);
  • Generated clamp values are rounded to 4 decimals, matching Utopia’s output precision.

Styling & Parameters

All five parameters are JS-type (no cssVar): the demo subscribes to the parameter panel, recomputes the ladder live with the formula above, writes --step-0..5 onto the preview area, and shows the generated code.

/* Generated by the demo defaults: 480px→1440px, 1rem→1.25rem, ratio 1.25 */
:root {
  --step-0: clamp(1rem, 0.875rem + 0.4167vw, 1.25rem);
  --step-5: clamp(3.0518rem, 2.6703rem + 1.2716vw, 3.8147rem);
}
h1  { font-size: var(--step-5); line-height: 1.05; }  /* tighten leading on display sizes */
h2  { font-size: var(--step-3); line-height: 1.15; }
p   { font-size: var(--step-0); line-height: 1.6; }   /* body ≥1.5 (WCAG 1.4.12) */

Where the numbers come from:

  • Formula and output shape = Utopia’s fluid type scale calculator (research 05 §13, first-hand measured output: --step-0: clamp(1.125rem, 1.0739rem + 0.2273vw, 1.25rem) — the demo formula reproduces that line byte-for-byte from the same inputs);
  • Ratio 1.25 = a Utopia selectable ratio, modularscale’s 4:5 major third (research 05 §13/§17);
  • The maxSize default of 1.25rem matches the max in the Utopia sample above; the minViewport/maxViewport defaults of 480/1440px are this entry’s task-spec values, while Utopia’s sample back-solves to ≈360/1240px (not directly documented — both stated side by side).

Motion & Interaction

The scale is a static token layer — “motion” only happens as the viewport changes:

  • While the viewport resizes continuously, clamp output changes continuously: no jumps and no transition needed;
  • Dragging the demo’s simulated-viewport slider is equivalent to resizing the browser; the px badges use the same formula, so you can probe both ends from a fixed window;
  • No prefers-reduced-motion handling is required (this entry produces no animation).

Parameter Sensitivity

ParameterTurning it up…Turning it down…

minSizeraises the floor of body and every step, closing the gap to --step-5 and weakening contrastpushes the body floor toward 0.8rem, hurting long-form readability
maxSizeenlarges body on big screens and steepens the slope — the whole ladder gets louderapproaches minSize, the slope approaches zero and the scale degenerates to static; below minSize the clamp semantics invert (min wins)
ratioinflates higher steps exponentially — --step-5 rushes toward its ceiling for a poster-like looknear 1.1 the steps crowd together and hierarchy shifts to weight rather than size

Working ranges: viewport 360–1440px, body from 1–1.125rem, ratio 1.2–1.333 (Utopia’s sample and modularscale’s common stops); keep body within 1–2 steps of range and tighten leading per step.

When to use 4
  • Site-wide scale: one --step-0..5 ladder drives body through display headlines with no breakpoint jumps
  • Article and marketing headlines that scale with the viewport, replacing stacks of media-query font-size overrides
  • Hero/display type collapsing to a readable floor on mobile without blowing the measure
  • As a token layer: isomorphic with Utopia fluid spacing, forming a whole fluid design system
When not to use 4
  • Pure-vw sizes with no rem floor — zooming the OS font cannot rescue them (WCAG 1.4.4 Resize Text)
  • Strongly fluid body text — keep --step-0 within 1–2 steps of range or it reads huge on phones, tiny on desktops
  • Line-height not tightening per step — display sizes inherit body leading; body under 1.5 violates WCAG 1.4.12
  • An overly wide viewport range (e.g. 320–2560) flattens the slope until desktop scaling is invisible
Accessibility

Sizes must be priced in rem with a rem floor: pure-vw sizes break WCAG 2.1 SC 1.4.4 (Resize Text) and user browser font settings; writing clamp's min in rem keeps OS-level zoom working. WCAG 2.2 SC 1.4.12 Text Spacing requires line-height ≥1.5× the size and paragraph spacing ≥2× (research 05 §18) — tighten leading for display steps rather than inflating it.

Browser support

clamp() is Baseline Widely available (since 2020-07, MDN, research 05 §12) and supported in all three engines today; the research did not record per-browser release numbers, so none are claimed here. · Baseline Widely available (2020-07)

Fallback

On environments without clamp(), fall back through cascade: write a fixed font-size (e.g. 1rem) first, then the clamp() declaration — modern browsers override with the latter; or wrap the whole fluid rule set in @supports (font-size: clamp(1rem, 1vw, 2rem)) so old browsers skip it and keep the fixed scale.
