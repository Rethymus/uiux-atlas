Variable Fonts

可变字体 · OpenType 变体 · font-variation-settings

One font file carrying continuous axes: font-variation-settings turns wght/opsz dials — weight and optical size become continuous sliders instead of discrete cuts.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
wght400

The weight axis (CSS-type, injected as --vf-wght and consumed via font-variation-settings). Inter's scale 100–900 spans nine static cuts from Thin 100 to Black 900 (research 05 §24) — continuous on the variable format; default 400 (Regular) is the registered-axis default and matches @fontsource-variable/inter's metadata.json in this repo. Prefer the high-level font-weight property; drop to font-variation-settings for fractional values or multi-axis control.

opsz14

The optical size axis (CSS-type, injected as --vf-opsz). Inter's scale 14–32 (rsms/inter official spec, research 05 §24): 14 is the text optical size with a tall x-height (1118/2048 UPM) for small sizes; 32 is the display optical size (x-height 1056/2048) with tighter, higher-contrast forms. Default 14 = the axis minimum (same value in this repo's @fontsource-variable/inter metadata.json); set font-optical-sizing: none to drive the axis manually — auto lets the browser pick per font-size.

Code breakdown

Structure & DOM

Variable fonts need no special DOM — just a font file carrying the fvar table and plain text. The key separation is between the @font-face declaration (which axes the file has) and the axis-control declaration (where the axes sit right now).

<p class="display">Headlines use the display optical size</p>
<p class="body">Body copy uses the text optical size.</p>
@font-face {
  /* Injected in this repo via @fontsource-variable/inter/standard.css: one file carries wght + opsz */
  font-family: "Inter Variable";
  font-weight: 100 900; /* a range, not a point — the hallmark of a variable font */
}

Key points:

  • The OpenType spec defines five registered axes: wght/wdth/slnt/ital/opsz; a font may support subranges, and custom axes must be named in uppercase (research 05 §20);
  • Inter Variable’s scales: opsz 14–32 and wght 100–900 (rsms/inter official spec, research 05 §24);
  • Axis names are case-sensitive, and font-variation-settings must restate every axis value together once declared.

Styling & Parameters

Two CSS-type parameters are injected as --vf-wght/--vf-opsz; the demo samples consume the variables directly:

.vf-sample {
  font-family: "Inter Variable", system-ui, sans-serif;
  font-optical-sizing: none; /* turn off auto so manual opsz is not overridden */
  font-variation-settings: "wght" var(--vf-wght), "opsz" var(--vf-opsz);
  /* advanced syntax: font-variation-settings: "wght" 375, "GRAD" 88; */
}

Where the numbers come from:

  • wght default 400 (Regular) is the registered-axis default; opsz default 14 is the axis minimum — both match this repo’s @fontsource-variable/inter metadata.json (wght 100–900 default 400; opsz 14–32 default 14);
  • The endpoints 100–900 and 14–32 come from rsms/inter’s official technical spec (research 05 §24, first-hand);
  • x-height reference: at opsz=14 it is 1118/2048 UPM (text optical size — tall x-height aids small sizes); at opsz=32 it is 1056/2048 (display optical size, stronger contrast).

Motion & Interaction

Axes are continuous, but keep motion restrained:

  • Slider changes re-render glyphs instantly — the whole point of variable fonts is continuous interpolation without swapping font files;
  • Hover nudges of ±50 on wght are feasible, but weight changes glyph widths and can move line breaks — restrict to short labels;
  • Weight/optical-size animations (e.g. a headline thickening on scroll) re-rasterize glyphs every frame: expensive and distracting, avoid in production;
  • This demo has no animation, so no prefers-reduced-motion handling is needed.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
wghtthickens strokes toward Black at 900; strengthens hierarchy but crowds letter-spacingthins strokes: 100 (Thin) suits only large decorative sizes; small-size legibility collapses
opszshifts toward the display optical size: more contrast, tighter forms, lower x-height (1056/2048) — refinement for big headlinesshifts toward the text optical size: taller x-height (1118/2048), more open forms — easier small sizes
(combined)high wght + high opsz = a poster-grade display combo, only for very large sizeslow wght + low opsz = the long-form reading combo, the comfort zone for body copy

Working ranges: body at wght 400–450 with opsz 14; text labels 500–600; display headlines 600–800 with opsz 24–32. Always declare a font-weight fallback before the low-level axis control, and restate every axis value together.

When to use 4
  • Fine weight spectra in design systems — 350/450/650 cuts in one CSS line
  • Display optical sizes for headlines (opsz up) and text optical sizes for small UI (opsz down)
  • One variable file replacing nine static weight files — fewer requests, less FOUT
  • Hover states nudging wght by ±50 (used sparingly to avoid layout jitter)
When not to use 4
  • Body text near wght 100 — hairline weights read poorly at low resolution and low contrast
  • Relying on font-variation-settings alone with no font-weight fallback — old browsers lose the declaration entirely
  • Animating weight across body text — glyphs re-rasterize every frame, costing both performance and readability
  • Mis-casing axis names (e.g. Wght) — names are case-sensitive and fail silently
Accessibility

Weight directly affects legibility: keep body at 400 or above and reserve heavier cuts for display; hairline weights are hard to read at small sizes and low contrast (beyond WCAG 1.4.3 contrast). Inter's text optical size (opsz 14, tall x-height) is designed for small sizes — pick low opsz for small UI and high for display. Weight changes glyph widths, so avoid shifts that move line breaks and make content jump.

Browser support

Variable fonts (fvar) and font-variation-settings work in current versions of all three engines; research 05 did not record per-browser release numbers (unverified), so none are claimed. Write a font-weight fallback first, then layer axis control with font-variation-settings.

Fallback

Browsers without font-variation-settings drop the whole declaration: keep weight via font-weight first (the high-level property maps to the wght axis), then layer font-variation-settings for fine control; opsz has no high-level equivalent, so rely on font-optical-sizing: auto (the default) where supported. At the file level, a failed @font-face falls back down the font-family stack to system fonts.
