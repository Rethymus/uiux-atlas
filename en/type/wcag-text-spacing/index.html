WCAG Text Spacing

text spacing · 文字间距 · SC 1.4.12 · 行高字距

WCAG SC 1.4.12: when users override line height to 1.5×, paragraph spacing 2×, letter spacing 0.12× and word spacing 0.16× of the font size, content must not break — don't hard-lock these four ratios.

Paragraph spacing (margin-block-end). WCAG threshold: ≥2em (twice the font size). The 1em default is the common paragraph-gap convention (unverified) and sits below the threshold — the demo button previews the threshold form.

em

Letter spacing. WCAG threshold: ≥0.12em (0.12× font size). Default 0 (browser default). Tight negative tracking must equally not break content under user overrides.

wordSpacing0em
em

Word spacing. WCAG threshold: ≥0.16em (0.16× font size). Default 0. Per CSS semantics word-spacing acts on word separators (spaces), so it has little effect on space-less CJK body text.

Code breakdown

Structure & DOM

No special structure — put text in normal flow and the key is don’t lock it down:

<div class="prose">
  <p>A paragraph…</p>
  <p>Another…</p>
</div>
.prose p {
  line-height: var(--ts-line-height);   /* unitless, overridable */
  margin-block-end: var(--ts-para-gap); /* paragraph gap */
  letter-spacing: var(--ts-letter-spacing);
  word-spacing: var(--ts-word-spacing);
}

Key points:

  • No !important, no fixed-height clipping — 1.4.12 requires that content stays usable after user-agent overrides, and locked styles fail by construction;
  • Give text containers min-height instead of height so a taller line-height never clips;
  • Single-line truncation (white-space: nowrap + overflow: hidden) conflicts with 1.4.12 by nature — don’t use it on meaningful text.

Styling & Parameters

The four ratios (line height / paragraph gap / letter spacing / word spacing) are injected through --ts-* variables:

.prose p {
  line-height: var(--ts-line-height);        /* number, unitless; threshold 1.5 */
  margin-block-end: var(--ts-para-gap);      /* em; threshold 2em */
  letter-spacing: var(--ts-letter-spacing);  /* em; threshold 0.12em */
  word-spacing: var(--ts-word-spacing);      /* em; threshold 0.16em */
}

Where the numbers come from (verified against the WCAG 2.2 Understanding document, research 05 §18):

  • Line height ≥ 1.5× font size; paragraph spacing ≥ 2×; letter spacing ≥ 0.12×; word spacing ≥ 0.16×;
  • The premise is “content must remain usable with no other property changed” — the four ratios are user-override values, not design defaults; defaults stay a typographic decision (commonly 1.5 line-height, 1em paragraph gap — the latter a common convention, unverified);
  • Per CSS semantics word-spacing acts on word separators (spaces), so space-less CJK body text is barely affected; letter spacing does apply to CJK.

Motion & Interaction

Spacing itself has no motion; the interaction lives in “overriding”:

  • The demo’s four sliders simulate user-agent overrides and show each ratio’s pass/fail state against the WCAG threshold (✓/✗ badges with threshold values);
  • The “Set to WCAG thresholds” button writes the four values (1.5 / 2em / 0.12em / 0.16em) into the parameter panel at once; “Reset” returns to typographic defaults;
  • The verdict is an instant numeric comparison with no animation — if the demo text clips or overlaps under overrides, that maps directly to how a real site fails 1.4.12.

Real-world examples

  • The official WCAG toolchain: the W3C Understanding document ships a bookmarklet that injects the four ratios into any page to watch for breakage — the official acceptance path for 1.4.12 (research 05 §18).
  • The GOV.UK Design System: the UK government design system specifies body line-height and paragraph spacing and has long treated “text reflows under user styles” as its accessibility baseline — a representative public-sector implementation of 1.4.12.
  • Reader modes and OS text sizing: browser reader modes and iOS/Android system-wide text scaling are, in effect, user overrides of page spacing — sites that leave override headroom for the four ratios survive these modes intact.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
lineHeighttaller line boxes; dense lists/tables may overflow — fixed-height containers clipbelow 1.5 misses the threshold; near 1 lines fuse together and reading gets hard
paragraphGapclearer paragraph boundaries; past 3em the page turns sparse and scrolling gets costlybelow 2em misses the threshold; at 0 paragraphs fuse into blocks
letterSpacingpasses the threshold at 0.12em; beyond that words visually fall apart and narrow containers wrap more0 is the browser default; negative tracking hurts readability and must still remain usable under overrides
wordSpacingpasses the threshold at 0.16em; word gaps visibly widen in English0 is the default; little visual change for CJK body text (a CSS semantics limit)

Takeaway: the four thresholds are an acceptance form, not a design default — defaults are free, but every default must survive being overridden up to the thresholds.

When to use 4
  • Body-copy baseline: line-height 1.5 with moderate paragraph gaps leaves override headroom by default
  • Design-system type tokens: all four ratios as variables, overridable by user styles
  • Accessibility acceptance for text-dense UIs (docs, readers, form helper text)
  • CI checks against spacing locks: grepping out !important line-heights and fixed-height text containers
When not to use 4
  • Hard-locking line-height/letter-spacing with !important or inline styles user agents can't override
  • Single-line fixed-height boxes (height: 1.5em + overflow: hidden) — overridden line-height clips the text
  • Text in fixed-height popovers/cards that clip once line-height grows
  • Accepting typography only at defaults, never testing the all-four-overrides form
Accessibility

This entry IS the accessibility rule: SC 1.4.12 is Level AA. Accept by overriding from the user's seat — set line height 1.5, paragraph spacing 2, letter spacing 0.12, word spacing 0.16 (all multiples of font size); pass means no truncation, no overlap, no broken function. The W3C Understanding document ships a bookmarklet that injects the four ratios for quick checks (research 05 §18). Word spacing doesn't apply to space-less CJK — for Chinese sites focus on line height and paragraph spacing.

Browser support

This entry only uses four basic properties — line-height, margin, letter-spacing, word-spacing — all widely available; the success criterion constrains behavior, not properties: any user agent can override these values per 1.4.12.

Fallback

No feature fallback needed; the engineering 'fallback' is simply not locking: avoid !important on line-height/spacing, avoid fixed-height text clipping (single-line overflow: hidden truncation), and avoid fixed-height text containers so content stays fully visible after user-agent overrides.
