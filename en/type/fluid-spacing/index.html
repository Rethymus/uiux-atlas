Fluid Spacing

流式间距 · Utopia 间距 · 间距标尺

Spacing tokens ride clamp too: --space-3xs…3xl stretch linearly with the viewport — fixed at both ends, interpolated between — so whitespace breathes instead of jumping at breakpoints.

Web Standard ★★
Live demo official default
Parameters
Geometry▾
minViewport480px
px

The viewport where interpolation starts: below it, every spacing token sits at its min. Default 480px is this entry's task-spec value; Utopia's recorded output sample (research 05 §14) back-solves to ≈360px (not directly documented — both stated).

maxViewport1440px
px

The viewport where interpolation ends: above it, every token sits at its max. Default 1440px is the task-spec value; Utopia's sample back-solves to ≈1240px (not directly documented — both stated). Spacing spans are far smaller than type spans, so slopes are naturally gentler.

minSpace1.125rem
rem

The viewport floor of the base token (--space-s, multiplier 1). Default 1.125rem is taken directly from Utopia's measured --space-s min (research 05 §14, first-hand); other tokens scale down by multiplier (3xs=0.25×, 2xs=0.5×, xs=0.75×).

maxSpace1.25rem
rem

The viewport ceiling of the base token (--space-s). Default 1.25rem comes from Utopia's measured --space-s max (research 05 §14); larger tokens amplify by multiplier (m=1.5×…3xl=6×), reaching 7.5rem at large viewports for 3xl.

Code breakdown

Structure & DOM

Isomorphic with the fluid type scale: no extra DOM, one layer of :root-level spacing tokens. Every piece of whitespace (padding/gap/margin) must ride the tokens — that is the premise of fluid spacing.

<section class="block">
  <div class="chips">…</div>
</section>
:root {
  --space-3xs: clamp(0.2813rem, 0.2656rem + 0.0521vw, 0.3125rem);
  --space-2xs: clamp(0.5625rem, 0.5313rem + 0.1042vw, 0.625rem);
  --space-s:   clamp(1.125rem, 1.0625rem + 0.2083vw, 1.25rem);
  --space-m:   clamp(1.6875rem, 1.5938rem + 0.3125vw, 1.875rem);
  --space-l:   clamp(2.25rem, 2.125rem + 0.4167vw, 2.5rem);
  /* … xl / 2xl / 3xl generated the same way */
}

Key points:

  • The base token --space-s takes minSpace/maxSpace at the viewport ends; every other token = base × multiplier, on the ladder 0.25/0.5/0.75/1/1.5/2/3/4/6 (from Utopia’s multipliers, research 05 §14);
  • The interpolation formula matches the type scale: slope = (max−min)÷(maxVw−minVw), viewports converted to rem at a 16px root;
  • The naming 3xs/2xs/xs/s/m/l/xl/2xl/3xl follows Utopia’s token names (the —space-3xs/2xs/xs/s in research 05 §14’s output sample).

Styling & Parameters

All four parameters are JS-type: the demo subscribes to the panel, generates the nine clamp tokens live, writes them as CSS variables on the sample card, and shows code and bars side by side.

/* Generated by the demo defaults: 480px→1440px, 1.125rem→1.25rem */
.block  { padding: var(--space-l); }
.chips  { gap: var(--space-m); }
.chip   { padding: var(--space-2xs) var(--space-s); }

Where the numbers come from:

  • minSpace 1.125rem and maxSpace 1.25rem defaults = the two ends of Utopia’s measured --space-s: clamp(1.125rem, 1.0739rem + 0.2273vw, 1.25rem) (research 05 §14, first-hand); the demo formula reproduces that line byte-for-byte from its viewport inputs;
  • The minViewport/maxViewport defaults of 480/1440px are this entry’s task-spec values; Utopia’s sample back-solves to ≈360/1240px (not directly documented — both stated);
  • Honest delta: Utopia rounds some tokens independently (its sample —space-3xs is a static fixed value); this entry implements pure multiplier interpolation, so outputs may differ from Utopia’s in the last decimal.

Motion & Interaction

Spacing tokens are static — “motion” only happens as the viewport changes:

  • clamp output changes continuously while the viewport resizes: no jumps, no transitions needed;
  • The demo bars stretch instantly with the simulated-viewport slider, and the sample card’s padding/gap are driven by the real clamp() variables — resize the browser to watch the whitespace breathe;
  • This entry produces no animation, so no prefers-reduced-motion handling is needed.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
minViewportshifts the curve right: small screens sit pinned at the min values and mobile whitespace goes staticstarts stretching earlier — whitespace already breathes on phones, shortening the flat region
maxViewportflattens the slope: desktop whitespace changes become subtler and the ceiling arrives latersteepens the slope: whitespace inflates quickly on large screens and pins early
minSpaceraises the whole scale: looser whitespace on small screens, lower content densitynear 0.5rem the micro tokens (×0.25 → 0.125rem) get too small to separate anything
maxSpacelarger whitespace on big screens with a steeper slope — a more poster-like lookapproaches minSpace, the slope approaches zero and the scale degenerates to static; below minSpace the clamp semantics invert (min wins)

Working ranges: base spacing 1.125–1.25rem (Utopia’s sample), viewport 360–1440px; keep the spacing slope gentler than the type slope, and keep micro tokens (3xs/2xs) static or with minimal span.

When to use 4
  • Section whitespace: padding breathing across 24–40px with the viewport, no breakpoint pile-ups
  • Card padding and grid gaps: one --space-* ladder driving padding, gap and margin alike
  • Generated from the same source as the fluid type scale, forming a full fluid design-system token set
  • Editorial pages: restrained whitespace around body copy, amplified around display sections (m/l/xl tokens)
When not to use 4
  • Strongly fluid micro-spacing (3xs/2xs) — the 3–10px range has almost no span, so interpolation buys nothing
  • Spacing slope steeper than the type slope — whitespace moving faster than text unbalances composition
  • Hand-written spacing values bypassing the tokens — the whole premise is that every gap rides one scale
  • Growing whitespace past 2560px+ — beyond maxViewport tokens are already fixed; a longer range adds nothing
Accessibility

Spacing affects readability, not contrast: WCAG 2.2 SC 1.4.12 Text Spacing requires content to survive user overrides of line/paragraph/letter spacing (line-height ≥1.5×, paragraph spacing ≥2×, research 05 §18) — fluid spacing tokens must remain overridable, never !important; when token shrinkage closes gaps between touch targets, targets must stay hittable — dense lists use 2xs and above.

Browser support

Relies on clamp(): Baseline Widely available since 2020-07 (MDN, research 05 §12); the spacing tokens are ordinary custom properties with no extra compatibility requirements. No per-browser release numbers are claimed. · Baseline Widely available (2020-07)

Fallback

Same pattern as the fluid type scale: declare fixed spacing (e.g. padding: 1rem) first, then the clamp-token declaration so legacy browsers cascade back; or wrap the whole --space-* set in @supports and provide a static spacing ladder on failure.
