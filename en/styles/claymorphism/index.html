Claymorphism

黏土拟物 · Clay UI · 黏土风

Pastel bases, oversized radii, and a puffy 'inflated clay' look built from dual inner shadows plus an outer shadow — elements float above the page instead of being extruded from it, fixing neumorphism's contrast failure.

Community ★★★
Live demo official default
Parameters
Geometry▾
radius32px
px

Corner radius. Default 32px is the card rule of thumb; research range 20–40px, ≈25% of element height (cards 32px / buttons 24px / inputs 20px). Oversized radii are the first source of the puffy look (superdesign.dev).

shadowY35px
px

Outer shadow y-offset (how far the element floats). Default 35px from the recipe 0 35px 68px rgba(112,100,176,.30); blur 68px and alpha 0.30 are fixed by that recipe. The shadow must be tinted with the element's hue (purple here) — never pure black (superdesign.dev).

innerAlpha1

Multiplier on the dual inner-shadow alphas; 1 = the documented recipe: bottom dark inner rgba(95,70,140,.22) + top light inner rgba(255,255,255,.65) (superdesign.dev). 0 removes inner shadows leaving only the outer shadow; 2 maximizes the puffy look but highlights turn dirty.

Code breakdown

Structure & DOM

The structural difference from neumorphism is visible at a glance: the element floats above the page with its own fill — not the same color as the background — so the real element-to-background contrast survives.

<div class="clay-page">
  <div class="clay-card">
    <h3>Clay card</h3>
    <button class="clay-btn">Press me</button>
  </div>
</div>

Key points:

  • The page background (pale pastel) and the clay element (a more saturated pastel) are two different colors; hierarchy is expressed by “floating”;
  • The inflated illusion is composed from a three-part shadow: the outer shadow lifts the element, the dark bottom inner shadow presses out the underside, the light top inner shadow bulges the lit face;
  • Order is critical: outer shadow first, dark inner second, light inner last — swapped, the highlight gets eaten by the dark face.

Styling & Parameters

Three parameters map to radius, outer-shadow y-offset and the inner-shadow alphas, injected via --clay-* variables:

.clay-card {
  background: #b3a4ee;              /* pastel fill, demo sample color */
  border-radius: var(--clay-radius); /* default 32px, card rule of thumb */
  box-shadow:
    0 var(--clay-shadow-y) 68px rgba(112, 100, 176, 0.30),          /* outer: hue-tinted, never black */
    inset 0 -8px 16px rgb(95 70 140 / calc(0.22 * var(--clay-inner-alpha))),  /* dark bottom inner */
    inset 0 8px 16px rgb(255 255 255 / calc(0.65 * var(--clay-inner-alpha))); /* light top inner */
}

/* Press feedback: displacement instead of animated shadows (superdesign.dev) */
.clay-btn:active {
  transform: translateY(2px) scale(0.98);
}
.clay-btn:focus-visible {
  outline: 3px solid #6a5acd;       /* explicit focus ring */
  outline-offset: 2px;
}

Where the numbers come from (superdesign.dev claymorphism page):

  • Radius range 20–40px, ≈25% of element height: cards 32px / buttons 24px / inputs 20px; the default takes 32px;
  • Outer shadow 0 35px 68px rgba(112,100,176,.30) — tinted with the element hue, never pure black;
  • Dual inner shadows: dark bottom rgba(95,70,140,.22) + light top rgba(255,255,255,.65); the dual-inner-shadow technique was popularized by the clay.css library and a LogRocket tutorial;
  • Press feedback translateY(2px) scale(0.98); explicit 3px :focus-visible outline;
  • Representative cases: Duolingo (thick extruded buttons), Fall Guys (inflatable characters → UI), Joon (kids’ habit app).

Motion & Interaction

The motion language of clay is “squish”, not “move”:

  • Press: the button sinks translateY(2px) scale(0.98) over 0.15s ease; animating the three-part shadows to fake a press is explicitly wrong — expensive and muddy;
  • Release: the transform snap-back can carry a slight overshoot like cubic-bezier(0.34, 1.56, 0.64, 1), echoing the inflated feel;
  • Entrance: card fade-in + rise; under prefers-reduced-motion drop transitions and entrance animation, rendering the final state directly;
  • No hover displacement — the fat shadow already carries volume, and extra motion reads jittery.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
radiusmaximum inflation, approaching a balloon; past 40px small elements lose their content area to cornersback to an ordinary rounded card; below 20px the clay signature disappears
shadowYthe element floats higher with stronger layering; past 50px it reads like a hovering sticker and the page loses gravitythe element hugs the page; near 0 only inner shadows remain — a thick flat block
innerAlphaabove 1 both highlight and dark face strengthen — more inflation, but highlights turn dirtyat 0 the inner shadows vanish, leaving a plain card with a tinted shadow

Working ranges: radius 20–40px (cards 32), shadowY 30–40px, innerAlpha 0.8–1.2. The shadow color must always follow the element’s hue — a gray-black shadow turns the clay into plastic instantly.

When to use 3
  • Kids' products, edtech and illustrated landing pages — the style's main 2026 habitat (research 03 §4)
  • CTAs and reward dialogs — thick extruded buttons (Duolingo-style) convert well
  • Gamified progress, achievements and points — the puffy look amplifies positive feedback
When not to use 3
  • Data-dense backends and long-form reading — big radii and fat shadows crowd out content
  • Mature enterprise product shells — a niche style clashes with the restrained tone of tooling
  • Dark themes as-is — the white .65 top inner highlight turns into a glaring rim on dark bases
Accessibility

Because elements float above the page, real contrast between element and background survives — that is exactly how claymorphism repairs neumorphism's contrast failure. Still verify text at 4.5:1 and control boundaries at 3:1 (WCAG 2.2 SC 1.4.11). Press feedback is a transform shift rather than animated shadows, and focus uses an explicit 3px :focus-visible outline — never shadows alone (superdesign.dev).

Browser support

Multi-layer box-shadow, border-radius and transform work everywhere; the demo computes inner-shadow alphas with rgb(... / calc(...)) (supported in all modern browsers). Older environments can hardcode the three recipe colors.

Fallback

Without multi-layer shadow support: keep the pastel base and oversized radius, degrade to a single regular shadow plus a 1px hue-matched edge; the puffy look weakens but hierarchy and readability survive. Press feedback is a transform shift, so it needs no fallback.
