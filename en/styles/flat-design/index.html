Flat Design

扁平设计 · Flat UI · 扁平化

The minimalist UI language: simple elements, typography and flat color — a discipline of no gradients, no highlights, no skeuomorphic shadows; the shared substrate of a whole generation of system languages (Metro→Material→iOS 7), measured by NN/g to slow interactions 22% on average when affordance cues are stripped.

Code breakdown

Structure & DOM

Flat design is “one panel + color blocks”: a settings panel (white, hairline border) holding flat-color tiles, a geometric switch and a solid primary button — all hierarchy rides on color value, spacing and type size; zero decoration layers.

<div class="panel">
  <h2>Settings</h2>
  <div class="tiles">
    <button class="tile" aria-pressed="true">…icon + label…</button>
  </div>
  <div class="row">
    <span>Wi-Fi</span>
    <button role="switch" aria-checked="true" class="switch"><span class="knob"/></button>
  </div>
  <button class="btn-primary">Done</button>
</div>

Key points:

  • Icons are inline SVG simple glyphs in a single currentColor — the same geometry switches between outline and filled modes, which is exactly the parameterized “simple glyph icon”;
  • The switch’s affordance is purely geometric: a rounded track plus a white knob’s displacement, with role="switch" + aria-checked carrying the state;
  • The selected state is triple-expressed — aria-pressed, accent fill, white label — never hue alone (SC 1.4.1).

Styling & Parameters

Two CSS variables, two JS-type params:

.demo-stage { --fd-accent: #007aff; --fd-radius: 4px; }
/* ornament tiers: discipline vs flat 2.0 */
.fd-scene[data-ornament="gradient"] .fd-tile-accent {
  background-image: linear-gradient(to bottom, oklch(1 0 0 / 0.14), transparent 55%);
}
.fd-scene[data-ornament="shadow"] .fd-panel { box-shadow: 0 4px 14px oklch(0 0 / 0.12); }
/* strict flat (none): none of the above exists */
.fd-tile { background: oklch(0.93 0.02 250); border-radius: var(--fd-radius); }
.fd-tile[aria-pressed="true"] { background: var(--fd-accent); color: oklch(1 0 0); }

Where the numbers come from:

  • “Simple elements, typography and flat color”, “simple glyph icons” and “no skeuomorphic depth” are verbatim traits from research 03 §17;
  • The lineage (Metro 2010 → Windows 8, Holo 2011 → Material 2014, iOS 7 2013, Fluent 2017) and “by the mid-2020s gradually replaced by glassmorphism” are recorded in research 03 §17;
  • NN/g’s 2017 finding that flat interfaces were 22% slower on average is verbatim from research 03 §17;
  • The accent #007AFF (community-circulated iOS blue reference, not verified as an official spec value) and radius 4px are this entry’s baselines.

Motion & Interaction

Flat’s motion discipline: “state changes are instant; movement stays light”:

  • Switch: knob translate 0.15s + track recolor — the only allowed motion, expressing state rather than decorating;
  • Tiles: hover deepens one color step (0.15s); aria-pressed swaps to the accent fill — no lift, no shadow growth;
  • Press feedback: the primary button hovers to brightness(0.94) — color only, no displacement; that’s the flat-vs-skeuomorphic line;
  • Under prefers-reduced-motion: reduce all transitions stop; state changes complete instantly.

Real-world examples

  • Windows Phone 7 Metro → Windows 8 (2010/2012, Microsoft) — the starting point of the lineage recorded in research 03 §17: flat tiles, sharp corners and typographic layout as a system language; the industrial start of the flat wave.
  • iOS 7 (2013, Apple) — recorded in research 03 §17: the system-level pivot away from skeuomorphic gloss to hairline icons and flat color; the decisive event of mobile flattening.
  • Google Holo → Material Design (2011/2014) — recorded in research 03 §17: from Holo’s flat blue to Material handing flatness back its hierarchy via the “paper” metaphor — the canonical “flat + shadow” variant.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
accent— (swap brand color freely, but keep exactly one — a second accent breaks the flat palette)— (#007AFF on white ≈4:1, so button labels need bold; a lighter accent falls below SC 1.4.3)
ornamentgradient/shadow gradually hand flatness back its affordance cues (faster interactions — the reverse of NN/g’s 22% finding) at the cost of straying from the “no skeuomorphic depth” disciplinenone is the discipline itself: zero render cost, unconditionally degradable — and the weakest affordance cues
iconStylefilled glyphs carry more visual weight — tiles and selected statesoutline glyphs stay lighter — inline use and dense lists
radiusdrifts toward the iOS 7/Material rounded-rect voice; past 12px it argues with “simplicity”0 returns to Metro’s sharp-corner discipline — denser, less friendly

Working ranges: radius 0 (Metro) or 8–12 (iOS/Material), with 4px the compromise; keep tile fill one value-step off the panel (≥3:1 non-text contrast); accent appearances ≤2 per screen.

When to use 3
  • System utilities and productivity surfaces (settings, files, mail) — flat color + glyph icons, the shared substrate of macOS/Windows/mobile system languages
  • Low-power devices and degradation channels — zero-filter/zero-blur rendering floor, the natural terminus for weak hardware and print styles
  • Content-first editorial/docs interfaces — with decoration at zero, hierarchy rides entirely on typography (naturally complementary to editorial style)
When not to use 3
  • Contexts relying on decorative affordance cues — NN/g's 2017 study: flat interfaces were 22% slower on average once links/buttons lost their clickable cues (research 03 §17)
  • Strong-hierarchy data panels — with no shadows or borders, flat grouping leans on whitespace alone and dense tables blur
  • Marketing pages needing brand differentiation — every system's flat substrate looks alike; memorability is hard to earn
Accessibility

Flat's core risk is 'affordance stripping': once buttons lose depth cues, non-visual cues must backfill — color-block contrast ≥3:1 (SC 1.4.11), explicit hover/focus states, underlined (or at least bolded) links; NN/g's recorded 22% slowdown is the measured price of missing cues (research 03 §17); #007AFF computes to ≈4:1 on white, so small white text on it fails SC 1.4.3 — use bold type or a darker fill for button labels; selected states can't be color-only (SC 1.4.1) — pair them with icons/checkmarks.

Browser support

Strict flat needs no novel features — solid fills, strokes and radii are all CSS1–3 baseline; icons are inline SVG. That's the engineering reason it blanketed every platform overnight in 2013, and its value today as the universal fallback terminus.

Fallback

Flat has no fallback problem — it *is* the fallback: switch off Grid/Flex, gradients and filters and the interface degrades to color blocks and text with hierarchy held by size and spacing. Set the ornament switch to none and you have the unconditionally safe terminus.
