Neumorphism

新拟物 · Soft UI · 软拟物

Elements share the page background color exactly; a dual shadow (dark on one side, light on the other) extrudes or presses them into the surface — a low-contrast soft-plastic look that peaked in 2020 and receded over accessibility failures.

Community ★★★
Live demo official default
Parameters
Color▾
base#e0e5ec

The base color shared by page and elements. Default #e0e5ec is the community classic (superdesign.dev): shaping relies entirely on the dual shadow, so any mismatch between element and background breaks the style. The demo derives the dark shadow via color-mix (base darkened 15%: #e0e5ec → #bec3c9).

Geometry▾
offset9px
px

Dual-shadow offset. Default 9px comes from the classic raised recipe 9px 9px 18px #bec3c9, -9px -9px 18px #ffffff (superdesign.dev); the classic inset recipe uses 6px. Rule of thumb: blur ≈ 2× offset.

blur18px
px

Shadow blur radius. Default 18px is the classic raised recipe value (= 2× the 9px offset); the classic inset recipe uses 12px (superdesign.dev). Too much blur turns the shadow mushy; too little becomes a hard emboss.

Motion▾
moderaised

JS-type param (demo subscribes and toggles data-mode). raised = extruded: dark shadow bottom-right, light top-left; inset = pressed: shadows flip inside. The classic inset recipe is inset 6px 6px 12px (superdesign.dev); the demo insets with the current offset/blur for direct comparison.

Code breakdown

Structure & DOM

Neumorphism is a single-layer structure with one hard constraint: the page and the element share exactly the same color. The shaping does not live in the DOM — it lives in the shadows.

<div class="neu-page">
  <div class="neu-card">
    <input class="neu-input" type="text" />
    <button class="neu-btn">Press me</button>
  </div>
</div>

Key points:

  • .neu-page and .neu-card use one base color (default #e0e5ec) with no border or outline between them;
  • Raised and inset are two orientations of the same shadow pair, expressed by swapping box-shadow;
  • Content inside the element (text, icons) is normal document flow — shadows only shape the “shell”.

Styling & Parameters

Four parameters map to the base color, offset, blur and raised/inset mode, injected via --neu-* variables:

.neu-page { background-color: var(--neu-bg); }  /* classic #e0e5ec */

/* Raised: classic recipe 9px 9px 18px #bec3c9, -9px -9px 18px #ffffff */
.neu-card {
  border-radius: 20px;            /* research range 16–24px */
  color: #3a4453;                 /* text in high-contrast ink */
  box-shadow:
    var(--neu-offset) var(--neu-offset) var(--neu-blur)
      color-mix(in srgb, var(--neu-bg) 85%, black),  /* base darkened 15% */
    calc(-1 * var(--neu-offset)) calc(-1 * var(--neu-offset)) var(--neu-blur)
      #ffffff;                    /* light shadow = pure white, classic value */
}

/* Inset: shadows flip inside (classic recipe inset 6px 6px 12px) */
[data-mode="inset"] .neu-card {
  box-shadow:
    inset var(--neu-offset) var(--neu-offset) var(--neu-blur)
      color-mix(in srgb, var(--neu-bg) 85%, black),
    inset calc(-1 * var(--neu-offset)) calc(-1 * var(--neu-offset)) var(--neu-blur)
      #ffffff;
}

Where the numbers come from (superdesign.dev neumorphism page):

  • Base #e0e5ec, raised recipe 9px 9px 18px #bec3c9, -9px -9px 18px #ffffff, inset recipe inset 6px 6px 12px;
  • Dark shadow = base darkened 15%: color-mix(in srgb, #e0e5ec 85%, black) equals the classic dark value #bec3c9 exactly;
  • blur ≈ 2× offset: classic raised 18px = 2×9px, inset 12px = 2×6px;
  • Radii cluster at 16–24px; dark mode needs both shadows retuned, never a simple inversion.

⚠️ Accessibility counter-example: typical neumorphic edges measure only about 1.4:1 contrast — below the 3:1 non-text boundary requirement of WCAG 2.2 SC 1.4.11 — and the failure cannot be fixed while keeping the soft look. The research records this as the core reason the style retreated through 2021. Always set text in high-contrast ink, reinforce control boundaries with a solid edge, or fall back to regular cards.

Motion & Interaction

Raised⇄inset is the only “verb” in this language:

  • Press feedback: on :active, swap the raised shadow for the inset pair with a 0.15s transition; acceptable on small elements, avoid on large cards (shadow transitions trigger repaints, costlier than transform);
  • Toggle semantics: the slider track stays inset (the well), the knob stays raised; drag only animates transform;
  • Entrance: a simple card fade-in; under prefers-reduced-motion drop transitions and entrance animation, rendering the final state directly;
  • Decorative hover shifts and shadow deepening should be omitted — a low-contrast material cannot afford more ambiguous cues.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
basedarker or more saturated bases widen the dark-shadow gap, shifting “plastic” toward “rubber”brighter bases read creamier, but the gap to the pure-white light shadow widens and the feel turns brittle
offsetdeeper relief, thicker-feeling controls; past 16px the shadow dominates and layouts loosennear 0 it degenerates into a flat block — raised and inset become indistinguishable
blursofter, more diffuse shadow and atmosphere; far beyond 2× offset the shadow smears and edges get harder to reada hard emboss, almost engraved; below the offset the soft-plastic feel is lost
modea globally inset page reads like a mold — suited to status-panel demosraised is the default posture; switching between the two is the most natural press feedback

Working ranges: offset 4–12px, blur at 2× offset, radius 16–24px. Base, dark and light shadows must derive from one another — mixing in unrelated grays reads “dirty” immediately.

When to use 3
  • Soft-plastic control panels: music players, calculators — the style's original home
  • Low-frequency controls (toggles, sliders, button groups) where raised⇄inset reads as press semantics
  • Atmosphere-first brand pages and concept work: low data density, decoration over information
When not to use 3
  • Body text and critical information — typical edge contrast is only ≈1.4:1, below the 3:1 of WCAG 2.2 SC 1.4.11 (research 03 §3 counter-example)
  • Data-dense dashboards and forms — hierarchy cues are too weak to scan
  • Dark themes via simple color inversion — dark mode needs both shadows retuned, not flipped (superdesign.dev)
Accessibility

Counter-example warning: typical neumorphic edges measure only ≈1.4:1 contrast, failing the 3:1 non-text boundary requirement of WCAG 2.2 SC 1.4.11, and the failure is unfixable while keeping the soft look — the core reason for its 2021 retreat. Mitigations: set text in high-contrast ink checked independently at 4.5:1; add a 1px solid edge or revert to regular cards for control boundaries; never encode focus state in shadows alone.

Browser support

box-shadow works everywhere; the demo derives the dark shadow via color-mix() (Chrome 111+/Edge 111+/Firefox 113+/Safari 16.2+). Older browsers can hardcode the classic color pair #bec3c9/#ffffff.

Fallback

Degradation when dual shadows cannot carry hierarchy: fall back to an ordinary light card — keep the shared base, add a 1px solid border and a regular shadow to mark edges, switch text to a high-contrast ink; express pressed/focus states with non-shadow cues (border, fill, underline).

Sources 3

OriginThe term (neo + skeuomorphism) was coined by Jason Kelly in 2019; Alexander Plyuto's Dribbble banking-app shots ignited the trend, with an earlier precursor on Huawei's 2019 Honor Vision UI; macOS Big Sur (Nov 2020) was read as strongly neumorphic; it receded quickly through 2021 over accessibility failures (research 03 §3).
