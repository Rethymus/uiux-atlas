Stroke & Fill Icons

描边图标 · 填充图标 · Outline Icons · Filled Icons · Stroke Icons

The first fork of an SVG icon: linear stroke via currentColor, or solid fill through it — same path, two deliveries; stroke width 1–3 and the fill switch are live-tunable.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
strokeWidth2

SVG stroke-width (inherited property; set on the <svg> root to reach every child shape). Default 2 = the Lucide/Feather source-defined value (defaultAttributes.ts, 07 §1.1); Heroicons 24/outline measures 1.5 in the real file (README quick-start still says 2 — stale v1 copy; the file wins, 07 §1.3). WCAG 1.4.11 understanding doc warns antialiasing renders overly thin lines far fainter than specified — avoid particularly thin strokes (07 §3.3).

Motion▾
filloff

Fill switch. Default off: Lucide's defaultAttributes sets fill:'none' — stroke-only delivery (07 §1.1); on = closed paths gain a solid fill:currentColor. Two caveats: open paths (segments, rays) have no area to fill and keep only their stroke; sub-shapes with a hardcoded fill="none" (this demo's lens/dot knockouts) stay hollow — a hardcoded fill/stroke on the path blocks inheritance (MDN use-attribute shadowing rule, 07 §5.1). Phosphor is the opposite: everything is delivered as filled paths with stroke baked into outlines (07 §1.4).

capJoinround

Cap and corner style. Default round: Lucide/Feather source-define stroke-linecap/linejoin as 'round' (07 §1.1) — round caps are the community signature of stroked sets; the square option shows stroke-linecap: square + stroke-linejoin: miter for a harder look — spikes appear at corners and usually need a miter-limit tune. Material adds numeric corner rules: 2dp default radius, no rounding on shapes 2dp wide or less (07 §2).

Code breakdown

Structure & DOM

Stroke and fill are two ways of “inking” the same SVG path: geometry is drawn once, while color and weight are handed entirely to inherited attributes — stroke and fill live on the <svg> root and child shapes stay bare.

<svg viewBox="0 0 24 24" fill="none" stroke="currentColor"
     stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <path d="M13.5 2.75 6 13.5h4.9L10.5 21.25 18 10.5h-4.9z" />
  <!-- Knockout sub-shape: inline fill="none" stays hollow even when fill is on -->
  <circle cx="12" cy="10.7" r="2.4" fill="none" />
</svg>

Key points:

  • viewBox="0 0 24 24" is the industry’s common ancestor grid (Lucide/Feather/Heroicons/Material all share it, research 07 §0);
  • Color is written exactly once as currentColor: the component sets color: and icon plus text recolor together (CSS Color 4 §6.4: currentcolor is the element’s own color value, 07 §5.2);
  • A hardcoded fill/stroke on a child path severs inheritance — <use> deep-clones into shadow DOM where only inherited properties apply; “attributes already defined ignore the reference value” (MDN use rule, 07 §5.1);
  • Open paths (segments) have no area to fill — switching fill on leaves only the stroke; filling requires a closed path.

Styling & Parameters

Three parameters map to three attribute groups on the svg root; strokeWidth is injected through the --sf-stroke variable while fill/capJoin are JS-type switches:

.sf-ic {
  fill: none;                              /* Lucide source-defined fill: 'none' */
  stroke: currentColor;                    /* Lucide source-defined */
  stroke-width: var(--sf-stroke, 2);       /* default 2 = defaultAttributes.ts value */
  stroke-linecap: round;                   /* source-defined round */
  stroke-linejoin: round;                  /* source-defined round */
}
.sf-scene[data-fill="on"] .sf-art path { fill: currentColor; }
.sf-scene[data-cap="square"] .sf-ic { stroke-linecap: square; stroke-linejoin: miter; }

Where the numbers come from:

  • stroke-width 2 / round caps and joins / fill none / currentColor quartet: source-defined in Lucide’s packages/lucide/src/defaultAttributes.ts, confirmed by the real icons/house.svg (07 §1.1); Feather’s attrs are isomorphic (07 §1.2);
  • The 1.5 exception: Heroicons’ real src/24/outline/bars-3.svg measures stroke-width="1.5"; the README quick-start still says 2 — stale v1 copy; the file wins (07 §1.3);
  • Thin-line debt: the WCAG 1.4.11 understanding doc warns that antialiasing renders particularly thin lines far fainter than the specified color — avoid them (07 §3.3);
  • The opposite extreme: Phosphor delivers all six weights as filled paths (256×256 viewBox measured) with stroke width baked into the outline (07 §1.4).

Motion & Interaction

Stroke/fill are static properties; motion happens at state switches:

  • Fill-to-light: the stroked and filled versions are two deliveries of one path — toggling fill on hover/selection “lights it up”, the SVG counterpart of Material Symbols’ FILL axis (“animated fill effect, to indicate user selection”, 07 §6.1); keep 150–200ms with standard easing (07 §6.2);
  • Do not animate stroke-width: interpolating it re-rasters the whole glyph and jitters at small sizes; to read “heavier”, prefer switching on fill rather than thickening strokes;
  • Under prefers-reduced-motion, the fill switch jumps straight to the end state (transition: none) — feedback kept, motion dropped (07 §6.3);
  • Stroke-dashoffset draw-in effects are covered in the icon-motion entry.

Real-world examples

  • Heroicons’ dual system: maintained by the official Tailwind team, 24/outline (1.5px stroke) and 24/solid (filled) share semantics under the same names, imported tree-shakably via @heroicons/react/24/outline; the project officially declines new icon PRs (07 §1.3);
  • Lucide all-stroke + experimental fill: the default quartet is source-defined, fill weight is experimental; the lucide-react/vue/svelte family leaves animation to the host instead of embedding SMIL (07 §1.1/§6.3);
  • Phosphor’s filled route: Fill/Duotone weights bake stroke into filled outlines and are the only two of the five sets that layer “translucent base + solid top” (Duotone background layer opacity 0.2, measured) (07 §1.4).

Parameter Sensitivity

ParameterTurning it up…Turning it down…
strokeWidthat 3 strokes read bold, but at ≤16px knockouts clog and detail mergesat 1 it looks airy, yet low-dpi screens and small text render it far fainter than specified (WCAG 1.4.11 note), pressuring contrast
fillon solidifies closed paths — visual weight jumps; check the grayscale balance beside stroked versions with the blur test (07 §3.2)off returns to stroke-only, the lightest look; visibility then rests on stroke width and color contrast
capJoinsquare/miter sprouts spikes and square tips — a harder style that gets ragged when smallround is the default and community norm; round caps transition most smoothly on curve corners

Working anchors: 24px grid with 2px stroke (Lucide/Feather official), 1.5px as Heroicons’ measured exception; never mix stroked and filled sets ad hoc on one page.

When to use 3
  • Toolbar/nav linear icons — one path set, stroke width gives the visual ladder; 2px is the Lucide/Feather anchor
  • Controls that 'light up' on hover/selection: stroke version + filled version from the same path — the SVG counterpart of Material's FILL axis
  • Inline icons beside text that must follow text color (one currentColor tint)
When not to use 3
  • Mixing stroked and filled sets ad hoc on one page — inconsistent visual weight, exposed by the blur test (07 §3.2)
  • Pushing 3px strokes at ≤16px — strokes merge and counters clog; conversely ultra-thin strokes render too faint on low-dpi screens (WCAG 1.4.11 note)
  • Hardcoding fill/stroke on reusable paths — it severs the sprite/component color chain (07 §5.1)
Accessibility

As graphical objects, icons need ≥3:1 non-text contrast against adjacent colors (WCAG 2.2 SC 1.4.11; 2.999:1 fails) in every state; avoid overly thin strokes that antialiasing renders fainter. Decorative icons get aria-hidden="true" and never sit on focusable elements; meaningful icons rely on accessible names (see the icon-aria-accessible entry).

Browser support

stroke/fill are SVG 1.1 standard attributes, available in all mainstream browsers; CSS control of them (SVG2 promotes stroke-width/linecap/linejoin to geometry properties) works in Chrome/Firefox/Safari/Edge. The delivery format itself needs no @supports. · widely available

Fallback

Stroke/fill are inline-SVG fundamentals needing no fallback in modern browsers; only when icons ship as external <img> into environments that won't render SVG, fall back to PNG/sprites or an icon font. If inheritance breaks (icon won't recolor), first check for a hardcoded fill/stroke on the path.
