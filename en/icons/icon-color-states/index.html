Code breakdown

Structure & DOM

The structural goal of icon state color is “one tint, whole chain”: paths stay bare, color inherits entirely from the host’s color, and a state switch touches exactly one place:

<!-- Host: the only color declaration; state carried by a data attribute -->
<div class="toolbar" data-state="default">
  <button aria-label="Favorite">
    <svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true">
      <polygon points="…" />
    </svg>
  </button>
  <span>Favorite</span>
</div>
/* State = one host color; icon + text move together (CSS Color 4 §6.4) */
.toolbar { color: #1192e8; }                 /* default */
.toolbar[data-state="hover"]   { color: #002d9c; }
.toolbar[data-state="danger"]  { color: #da1e28; }
/* Opacity de-emphasis rides the whole icon, never the semantics */
.toolbar svg { opacity: 1; }
.toolbar[aria-disabled="true"] svg { opacity: 0.2; }  /* Phosphor duotone's official de-emphasis magnitude */

Key points:

  • currentColor is “the value of the color property on the same element” (CSS Color 4 §6.4 verbatim); all five sets pre-configure it in their source files (Heroicons outline via stroke, solid via fill; Phosphor everywhere fill=currentColor — 07 §1.3/§1.4/§5.2);
  • State meaning cannot ride color alone — text/shape redundancy serves color-blind channels;
  • Decorative icons get aria-hidden; recoloring changes no semantics.

Styling & Parameters

Two parameters — state (JS-type, drives the host color) and opacity (CSS variable --cs-opacity, whole-icon opacity); the demo ships a live contrast panel:

WCAG 1.4.11 computation (official relative-luminance formula):
  blended  = state color × alpha + white × (1 − alpha)
  ratio    = (L_bright + 0.05) / (L_dark + 0.05)      pass at ≥ 3:1

State colors (IBM Carbon dataviz palette; official page verified, Apache-2.0 LICENSE, 08 §1.3):
  default #1192e8 (Cyan 50)  → 3.33:1 on white — passes by a hair
  hover   #002d9c (Blue 80)  → 11.3:1 (Carbon defines no hover color; a verified deep slot stands in, noted)
  danger  #da1e28 (alert danger) → 5.0:1

Measured anchors (drag the demo):

  • #1192e8 at full opacity is 3.33:1 — an edge-of-threshold color; at 80% opacity the blend already fails 3:1;
  • #da1e28 holds 5.0:1, still ≈3.9:1 at 80%, failing near 60%;
  • #002d9c has the largest margin, failing only near 50%;
  • 20% = Phosphor Duotone’s official background-layer value — that is “decorative de-emphasis”, not “interactive icon” territory (07 §1.4).

Motion & Interaction

Motion discipline for state switches:

  • Recolor transition: color over 150–200ms with standard easing — M3’s sanctioned micro-motion range (07 §6.2);
  • Opacity transitions signal de-emphasis, never state notifications (redundancy principle);
  • prefers-reduced-motion: transition: none snaps to the final state — feedback kept, motion dropped (07 §6.3);
  • Hover recoloring pairs with a non-color channel (shadow/underline); it should never be the entire hover feedback.

Real-world examples

  • The Tailwind class pattern: Heroicons’ README tints with text-gray-500 — exactly the currentColor mechanism, one class coloring icon and text together (07 §5.2);
  • Material’s dual-theme states: light icons on black use GRAD −25 to −50 against glare and +200 for emphasis; the axis compensates when a state color is theme-inappropriate (07 §1.5/§3.1);
  • Carbon’s alert family: danger #da1e28 / serious warning #ff832b / warning #f1c21b / success #198038, verified value-by-value on the official dataviz palette page with an Apache-2.0 LICENSE — the only one of the three mainstream palettes with a confirmed open license (08 §1.3).

Anchors: one host color; edge colors on pure white; de-emphasize at 0.2 (Phosphor official) rather than invented numbers; every state holds 3:1 — 2.999:1 fails.

When to use 3
  • Toolbars where icons follow text: one host color tints icon+text together (the Tailwind text-gray-500 pattern is exactly this mechanism, 07 §5.2)
  • Destructive actions (delete/sign-out) wear the danger state color, paired with accessible names (see icon-aria-accessible)
  • Disabled states de-emphasize via opacity (at Phosphor duotone's official 0.2 magnitude) while keeping non-color redundancy
When not to use 3
  • Designing on the edge: #1192e8 holds 3.33:1 on white but a 20% tinted backdrop beneath it breaks 3:1 — edge-of-threshold colors have no interference margin
  • Expressing state by color alone (hover/danger only via hue) — color-blind users lose the message; pair non-color channels (in the spirit of WCAG 1.4.1, 07 §4.3 context)
  • Reusing light-theme state colors on dark backgrounds — light icons glare on black; Material's answer is GRAD −25 to −50 (07 §3.1)
Accessibility

This entry's core duty: graphical objects (icons) keep ≥3:1 against adjacent colors (WCAG 2.2 SC 1.4.11) in every state; 2.999:1 fails; focus indicators share the 3:1 bound; antialiasing renders thin strokes fainter, making edge-riding riskier (07 §3.3/§4.3). Recoloring changes no semantics: state meanings need textual or shape redundancy, and decorative icons always leave the aria tree.

Browser support

currentColor and opacity are baseline CSS, fine in all mainstream browsers; icons may never lose 3:1 against adjacent colors in any state (WCAG 1.4.11) regardless of browser support — the demo's ratio math is the WCAG official relative-luminance definition, consistent cross-platform. · widely available

Fallback

No fallback needed; three engineering facts to respect: (1) opacity de-emphasis must not be the sole information channel (disabled states need textual or shape redundancy); (2) the same state color needs its 3:1 checked per theme — Material adapts dark backgrounds via the GRAD axis for glare (07 §1.5/§3.1); (3) hover recoloring should not be the entire hover feedback — add non-color channels like shadow or displacement.

Sources 3

OriginThe paint mechanism is CSS Color 4 §6.4 (currentcolor is the element's own color value; out/design-study/07-icons.md §5.2), proven by source files across all five sets (Lucide stroke=currentColor, Phosphor fill=currentColor, etc., 07 §5.2); the threshold is WCAG 2.2 SC 1.4.11 non-text contrast ≥3:1 with "2.999:1 would not meet" (07 §4.3); hover/selection recoloring has no added contrast requirement, but no state may lose 3:1 against adjacent colors (07 §4.3). The demo state colors come from IBM Carbon's dataviz palette (08-dataviz.md §1.3; official page fetched in full, Apache-2.0 license verified via the LICENSE file): Cyan 50 #1192e8, Blue 80 #002d9c, alert danger #da1e28.
