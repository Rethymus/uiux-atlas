Icon Micro-Motion

图标微动效 · 描边绘制 · hover 动效 · Icon Motion · stroke-dashoffset

Three hover-triggered path micro-effects: stroke-dashoffset draw-in, ≤90° rotation, fill-opacity light-up — 150–200ms with standard easing is M3's sanctioned range, and prefers-reduced-motion snaps straight to the end state.

Material 3 ★★★
Live demo official default
Parameters
Motion▾
effectdash

The armed motion technique (JS-type; unselected cards stay static). dash = pathLength=1 normalization + stroke-dashoffset 1→0 redraw (fully drawn at rest; hover only replays); rotate = ≤90° — M3 convention keeps travel out of the glyph, rotation ≤90°/±1px (07 §6.2); fill = fill-opacity 0→1 light-up, the SVG counterpart of Material's FILL axis ("indicate user selection", 07 §6.1/§6.3: the equivalent fallback is swapping a stroked for a solid symbol).

easingcubic-bezier(0.2, 0, 1, 1)

The easing curve, injected as a CSS variable (serialized to cubic-bezier()). Default [0.2, 0, 1, 1] = M3 easing.standard ("simple, small, or utility-focused transitions" — the micro-motion first choice, 07 §6.2); emphasized-decelerate [0.05, 0.7, 0.1, 1] serves entering emphasis and emphasized-accelerate [0.3, 0, 0.8, 0.15] exits — icon hover just needs standard. Every axis transition re-rasterizes the glyph, so keep budgets within 150–250ms (07 §6.1).

Geometry▾
duration200ms
ms

Motion duration (ms), injected as a CSS variable. Default 200 = M3's official duration.short4 ("Selection controls have a short duration of 200ms with Standard easing"); 150 = short3; the hover micro-motion convention is 150–200ms (07 §6.2). Above 250ms enters the medium tier (spatial transitions) and feels sluggish for hover; below 100ms approaches a hard cut and loses the sense of response.

Code breakdown

Structure & DOM

All three icon-motion techniques are property transitions on existing DOM — no new structure, no SMIL (component libraries leave animation to the host, keeping tree-shaking intact, 07 §6.3):

<!-- Draw-in: pathLength=1 normalization; fully drawn at rest, hover only replays -->
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" aria-hidden="true">
  <circle cx="12" cy="12" r="8.25" pathLength="1"/>
  <path d="M12 8.5v7M8.5 12h7" pathLength="1"/>
</svg>

<!-- Rotation: transform transition on the svg root -->
<svg class="im-rot" viewBox="0 0 24 24" aria-hidden="true">…ringed arrow…</svg>

<!-- Fill light-up: stroke always on, fill-opacity 0→1 (the FILL axis's SVG counterpart) -->
<svg class="im-fill" viewBox="0 0 24 24" aria-hidden="true">…heart…</svg>
/* M3 official tokens injected as CSS variables */
.im-scene {
  --im-duration: 200ms;                          /* duration.short4 */
  --im-easing: cubic-bezier(0.2, 0, 1, 1);       /* easing.standard */
}

/* dash: pathLength=1 + dasharray 1 → dashoffset 1→0 reads as a redraw */
.im-dash path { stroke-dasharray: 1; stroke-dashoffset: 0; }
.card:hover .im-dash path,
.card[data-play="dash"] .im-dash path {
  animation: im-draw var(--im-duration) var(--im-easing);
}
@keyframes im-draw { from { stroke-dashoffset: 1; } }

/* rotate ≤90° (motion stays out of the glyph) */
.im-rot { transition: transform var(--im-duration) var(--im-easing); }
.card:hover .im-rot { transform: rotate(90deg); }

/* fill: fill-opacity 0→1 — the SVG equivalent of Material's FILL axis ("indicate user selection") */
.im-fill { fill: currentColor; fill-opacity: 0; transition: fill-opacity var(--im-duration) var(--im-easing); }
.card:hover .im-fill { fill-opacity: 1; }

Key points: the dash rest state must be fully drawn (offset 0) — an icon never hides by default, hover merely replays; rotate sits on the svg root without disturbing paths; fill uses fill-opacity (an inherited property) instead of swapping fill values.

Styling & Parameters

Three parameters — two CSS-variable types (duration/easing) and one JS-type (effect, arming the selected card):

duration default 200ms  = M3 duration.short4 ("Selection controls have a short duration of 200ms with Standard easing")
                        150ms = short3; the hover micro-motion range is 150–200ms (07 §6.2)
easing   default [0.2,0,1,1] = M3 easing.standard ("simple, small, or utility-focused transitions")
                        emphasized-decelerate [0.05,0.7,0.1,1] for entries / emphasized-accelerate [0.3,0,0.8,0.15] for exits
effect   dash | rotate | fill — unselected cards drop to static (opacity 0.45)

One note on axis animation from Material Symbols (07 §6.1): subset before animating — only ~1.7KB-level fonts dare sit on first screen; every axis transition re-rasterizes the glyph, budget 150–250ms. The SVG route (fill-opacity) carries no font-loading burden — the lightweight equivalent.

Motion & Interaction

This entry IS the motion spec, with three guardrails:

  1. Reach channels: hover triggers, :focus-visible mirrors it (keyboard parity), and click triggers for touch (no hover); the demo’s three cards are real buttons;
  2. Reduced-motion degradation (MDN, first-class): under @media (prefers-reduced-motion: reduce) all animation/transition disable and hover snaps to the end state — feedback kept, motion dropped; MDN’s own example degrades a pulse scale into an opacity fade, the same spirit; the demo adds a “simulate reduced-motion” switch so users without the system preference can verify;
  3. The equivalent fallback route: swap a stroked and a solid symbol via <use> (07 §6.1/§6.3) — fill light-up at zero animation cost, no vestibular risk.

Real-world examples

  • Material Symbols’ FILL axis: README verbatim — “It can also be manipulated for an animated fill effect, to indicate user selection” — fill-on-select is officially sanctioned semantics, not decoration (07 §6.1);
  • M3 selection controls: the official example runs 200ms with Standard easing — this entry’s default (07 §6.2);
  • MDN prefers-reduced-motion: the first-hand source for the definition, example and degradation strategy (scale-type motion can trigger vestibular triggers; the official pulse degrades into an opacity fade) (07 §6.3).

Anchors: 150–200ms + standard; rotate ≤90°; dash fully drawn at rest; reduced-motion snaps without deleting feedback; subset before animating (the font route).

When to use 3
  • Selection-state icons (favorite/bookmark) filling up — the FILL axis's officially sanctioned semantics (07 §6.1)
  • Refresh/send confirmations rotating 90° at 200ms standard (07 §6.2)
  • List-item hover redraw hints at 150ms short3
When not to use 3
  • Animating high-frequency toolbar icons — frequent interactions should skip motion; reserve hover micro-motion for low-frequency emphasis
  • Icon motion beyond 250ms — the medium transition tier: sluggish for hover and doubles glyph re-raster cost (07 §6.1/§6.2)
  • Fill/rotate motion without a reduced-motion fallback — scale and travel motion can trigger vestibular triggers (MDN, 07 §6.3)
Accessibility

prefers-reduced-motion must degrade: MDN defines it as detecting the user's system preference to 'remove, reduce, or replace motion-based animations', with the official example degrading a pulse scale into an opacity fade; icon strategy = disable transitions/animations and snap to the end state without deleting feedback (07 §6.3). The demo adds a 'simulate reduced motion' switch so users without the system preference can verify. Keyboard: hover effects also bind :focus-visible; touch has no hover, so click-triggered playback is provided.

Browser support

All three techniques ride stable platform capabilities: stroke-dashoffset/pathLength (SVG 1.1/2, all mainstream browsers), transform transitions (compositor-friendly), fill-opacity transitions; @media (prefers-reduced-motion) is supported by all modern browsers (MDN). No SMIL and no JS animation — keeping tree-shaking intact (component libraries leave animation to the host, 07 §6.3). · widely available

Fallback

The reduced-motion fallback is this entry's first-class citizen: all transitions/animations disabled, hover snaps to the end state (or degrades scale-type motion into an opacity fade per MDN's example) — never deleting the state feedback itself (07 §6.3). The equivalent fallback route: swap a stroked and a solid symbol via <use>, filling the light-up with zero animation cost (07 §6.1/§6.3). Environments without pathLength normalization degrade the dash technique to rotate/fill.

Sources 3

OriginDuration and easing come from M3's official tokens (out/design-study/07-icons.md §6.2): duration.short3/short4 = 150/200ms (official example "Selection controls have a short duration of 200ms with Standard easing"), easing.standard = cubic-bezier(0.2, 0, 1, 1) ("simple, small, or utility-focused transitions"); the sanctioned fill light-up channel is Material Symbols' FILL axis (README: "animated fill effect, to indicate user selection", 07 §6.1), whose SVG-side equivalent is a fill-opacity transition; the a11y guardrail is MDN's prefers-reduced-motion: scale/translate motion can trigger vestibular triggers, and the official example degrades a pulse scale into an opacity fade (07 §6.3).
