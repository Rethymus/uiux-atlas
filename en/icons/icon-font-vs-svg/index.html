Icon Font vs SVG

icon font · 图标字体 · Inline SVG · 字形图标 · CAGEMATCH

The two icon delivery formats head-to-head: icon fonts go codepoint → font glyph → color, with a wide failure surface (load failure / CORS / PUA-vs-emoji collisions); inline SVG is true vector, CSS-controllable, embedded in the document with no weird failure states — winning near-across-the-board since the IE9+ era.

Code breakdown

Structure & DOM

The two formats have completely different DOM shapes: an icon font glyph is a text node (a codepoint pointing into a font), while inline SVG is a real vector graphics element:

<!-- icon font: codepoint/ligature → font glyph, tinted by color -->
<i class="icon icon-home" aria-hidden="true"></i>

<!-- inline SVG: true vector, tinted via stroke=currentColor (24 grid, 2px round) -->
<svg viewBox="0 0 24 24" width="24" height="24" fill="none"
     stroke="currentColor" stroke-width="2" aria-hidden="true">
  <path d="…" />
</svg>

Key points:

  • The font route renders through “codepoint → font file → glyph → color”, and every link can fail: @font-face load failure, cross-origin fonts blocked by CORS, Opera Mini without @font-face, ad blockers or user styles removing the font file (the CSS-Tricks CAGEMATCH failure list, 12 §12);
  • The SVG route is embedded in the document and has no external failure states — as long as the page renders, the icon renders;
  • A font glyph is plain text: its size is font-size, and vertical centering takes line-height/vertical-align nudging; SVG’s size is just width/height — positioning is direct.

Styling & Parameters

Four parameters form one controlled experiment: two CSS variables (--icf-size / --icf-color) drive both rendering chains at once, while two JS switches change the delivery format and the failure simulation:

.icf-glyphs { color: var(--icf-color); }          /* host color: shared by both chains */
.icf-glyph   { font-size: var(--icf-size); }      /* font glyph: size = font-size */
.icf-glyph svg { width: var(--icf-size); height: var(--icf-size); } /* SVG: size = width/height */

Where the numbers come from:

  • The default 24px size is the industry-wide ancestral grid (Lucide/Feather source width: 24, height: 24, Heroicons 24 outline, Material’s 24 design base, research 07 §0/§1);
  • The tint chain: stroke="currentColor" comes from Lucide’s defaultAttributes.ts source values (07 §1.1); “currentcolor takes the same element’s color property” is CSS Color 4 §6.4 verbatim (07 §5.2);
  • The failure list (font missing → tofu + raw ligature; codepoint + U+FE0F → color emoji takeover): the former simulates CSS-Tricks’ failure surface, the latter is real browser behavior (platform-dependent).

Motion & Interaction

This entry’s “motion” is instant feedback for format and failure switching — a restrained 0.2s transition is enough:

  • Delivery switch (delivery): the adopted lane lights up with a blue border and an “adopted” badge, and the code snippet below swaps to the real SVG or font usage;
  • Failure simulation (failure) touches the font lane only: font-missing swaps the three glyphs for tofu boxes plus raw ligature text; emoji-crash appends U+FE0F to ⚙ so it really renders as a color emoji — the SVG lane never flinches, which is the visual proof of “embedded, no weird failure states”;
  • Transitions only touch border-color/box-shadow/opacity; under prefers-reduced-motion: reduce they cut straight to the end state (transition: none) without removing the feedback itself;
  • Font glyphs go through text anti-aliasing (fuzzy at small sizes) while SVG uses shape anti-aliasing — put them side by side across sizes and the sharpness gap shows (12 §12).

Real-world examples

  • CSS-Tricks “Inline SVG vs Icon Fonts [CAGEMATCH]” (Chris Coyier, 2014): its verdict — from IE9+/Android 3+ inline SVG wins nearly across the board, IE8 is where icon fonts keep an edge — is still the citation origin for every format-selection writeup (12 §12);
  • Lucide / Feather: modern open-source icon sets dropped the font route entirely; their delivery format is SVG files plus an official sprite (Feather’s external feather-sprite.svg usage is the only one documented in a README among the five sets), with a family-wide currentColor contract (07 §1.1/§1.2/§5);
  • Material Symbols: the modern variant of the font technology — Google ships icons as a variable font (ligature arrow_forward + opsz/wght/GRAD/FILL axes), yet the official guide still demands &display=block against FOUC and icon_names subsetting down to ~1.7KB before touching the first screen: even inside the font route, failure-surface management remains the main topic (07 §1.5).

Anchors: default to inline SVG + currentColor in modern projects; keep the font route only for IE8 legacy and the variable-font special case (Material Symbols); whenever a font glyph is used, decide first what the page looks like when the font never arrives.

When to use 4
  • New icon systems in modern projects: pick inline SVG (or sprite/component layers on top), tint via currentColor (07 §5.2)
  • Multicolor icons, or icons whose individual parts must respond to CSS (hover changes one part) — impossible with font glyphs, native to SVG (12 §12)
  • Legacy systems that must still serve IE8: icon fonts are the exception scenario CSS-Tricks concedes (12 §12)
  • The modern variant of the font approach: Material Symbols ships icons as a variable font (ligatures + four axes), but requires &display=block against FOUC and subsetting to ~1.7KB before hitting the first screen (07 §1.5)
When not to use 4
  • Using text glyphs as icons and expecting pixel-perfect alignment — line-height/vertical-align positioning is a named pain point in CSS-Tricks (12 §12)
  • Carrying critical functional icons via icon font where ad blockers or user stylesheets may exist (failure list, 12 §12)
  • Relying on font glyphs for semantics/a11y — SVG pairs with <title>/<desc>/aria, font glyphs need extra care (12 §12)
  • Choosing fonts 'to save requests' while ignoring the other half — the comments' critiques of SVG (caching, DOM size) stand too (12 §12)
Accessibility

The two routes start accessibility from different points: SVG can carry <title>/<desc> and take ARIA attributes, and decorates via aria-hidden (07 §4); a font glyph is a plain text node that must get aria-hidden="true" and must never sit inside a focusable container (focusable elements must not be aria-hidden — the MDN red line). Either way, icon-only buttons still need their own accessible names (see icon-button / icon-aria-accessible). The demo's emoji-crash option shows how uncontrollable codepoint semantics are one of the font route's semantic risks.

Browser support

SVG icons are fully green (12 §12); icon fonts are the compat option, but their support surface is their failure surface: they depend on @font-face (unsupported in Opera Mini), cross-origin fonts hit CORS, and one load failure wipes out the whole icon set. The system symbol glyphs (⌂ ⚙ ★) used in the simulation and emoji-variant behavior vary by platform font stack — labeled honestly in the demo. · widely available

Fallback

The SVG route needs no fallback (embedded in the document, no external failure states); if a team is still stuck on IE8, icon fonts are the one scenario CSS-Tricks concedes. For the font route, the defensive pattern: give the glyph container a readable stand-in (tofu box / raw ligature text) until the font loads — the demo's font-missing option is exactly what 'the font never arrived' looks like.

Sources 3

OriginThe head-to-head comes from CSS-Tricks' classic 'Inline SVG vs Icon Fonts [CAGEMATCH]' (Chris Coyier, 2014, out/design-study/12-expansion.md §12): icon fonts suffer text anti-aliasing fuzz, line-height/vertical-align positioning pain, and a wide failure surface (CORS, font-load failure, Opera Mini without @font-face, ad blockers, Unicode PUA vs emoji collisions); SVG is sharper, lets CSS control individual parts of multicolor icons, and pairs with <title>/<desc>/aria. The article's verdict: once you can target IE9+/Android 3+, inline SVG wins nearly across the board; IE8 is where icon fonts still hold an edge (comments add SVG's caching / DOM-size costs).
