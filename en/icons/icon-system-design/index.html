Icon System Design

icon grid audit · 图标一致性 · keyline shapes · 键程 · 图标命名规范 · icon audit

Turning 'feels off' into machine-checkable audits: the 24×24 grid + Material keylines (square 18×18 / circle Ø20) + 1px safe area + one stroke width + kebab-case naming — six mini icons run a consistency audit under grid/keyline/safe-area overlays, with every violation flagged.

Code breakdown

Structure & DOM

A mini icon system = a family of SVG files sharing one geometric contract: each icon is its own 24×24 viewBox document, but grid, stroke, caps and naming all answer to a single spec:

<!-- One file per icon; the root element hard-codes the shared contract
     (isomorphic to Lucide's defaultAttributes) -->
<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24"
     fill="none" stroke="currentColor" stroke-width="2"
     stroke-linecap="round" stroke-linejoin="round">
  <path d="M4 11L12 4L20 11"/>  <!-- all-integer X/Y; content inside the trim area -->
  <path d="M6 10V20H18V10"/>
</svg>

The system’s four contract layers, outside in:

  1. Naming: kebab-case, lowercase, no duplicates — naming is the first line to collapse; once search_icon/arrowRIGHT creep in, lookup-by-name and tree-shaking both fail;
  2. Grid: the 24×24 grid with integer-only X/Y coordinates (the official Material rule, 07 §2); keyline shapes set the baseline — square 18×18, circle Ø20, vertical 16×20 / horizontal 20×16, and “the circle beats the square by 2dp” is the official optical law (07 §2/§3.1);
  3. Safe area: the live area 20×20 (2dp padding all around), the trim area = the full 24dp with content never escaping; Lucide adds: strokes ≥1px from the canvas edge, ≥2px gaps between elements (07 §2/§3.2);
  4. Stroke: one system standard (default 2px = Lucide/Feather’s source value); Heroicons’ 1.5px is a separate family that must not be mixed in; continuous weight goes through Material Symbols’ wght 100–700 axis — never scale the SVG (07 §1).

Styling & Parameters

Four parameters build the audit bench: one CSS variable plus three JS switches:

/* The system's standard stroke: an SVG user unit, written once, inherited by every icon */
.isd-tile svg { stroke-width: var(--isd-stroke, 2px); }
  • overlay — all three overlay geometries are research-driven numbers: the keylines option draws square 18×18 / circle Ø20 / both rectangles; the grid option draws a line every 2 units specifically to check integer coordinates; the safe option draws the green live-area frame 20×20 and the orange 1px safe-area boundary;
  • audit injects three real defect classes: search’s handle endpoint at (19.5, 19.5) (integer-coordinate rule), home’s roof at y=1 (the trim-area red line), arrow-right’s hardcoded 1.5px (width consistency) — offending elements turn red, tiles get a red ring, and the table issues verdicts;
  • naming injects the three naming offenders Home / search_icon / arrowRIGHT, flagged in red;
  • The audit table’s four rows (naming / grid / stroke / safe area) each state the standard and its source, machine-checkable.

Where the numbers come from: 2px stroke (Lucide’s defaultAttributes.ts source + Material’s 2dp), the four keyline values plus 2dp padding / integer coordinates (m2.material.io system-icons), the 1px safe area and 2px element gaps (Lucide’s contribution spec), the wght 100–700 axis (Material Symbols README) — all first-hand from research 07.

Motion & Interaction

  • Overlay switch (JS-typed): all six tiles swap their overlay geometry at once — keyline shapes ↔ pixel grid ↔ safe area; the 0.2s border transition cuts straight under prefers-reduced-motion: reduce;
  • Audit switch: violations become visible instantly — red ring, red paths, and the audit table all flip in sync; one click restores the compliant set;
  • Stroke drag (CSS variable): every icon (including the 24px native row) thickens and thins in sync, showing “stroke is a user unit; display scaling keeps the proportion”; at 1.5, arrow-right’s violation verdict disappears by coincidence (still a code smell — noted in the table);
  • The 24px native row: the same set side by side at native size, verifying legibility after shrinking (a static take on the blur test);
  • No translate/scale animation; every piece of feedback is a state switch, not motion.

Real-world examples

  • Material’s official grid template: the numeric origin of the 24dp trim area / 20dp live area / four keyline shapes, distributed as an official AI source-file template (Apache 2.0) — a homegrown system can be checked directly against it (07 §2);
  • Lucide’s contribution spec: 1px safe area, 2px element gaps, the 2.41px diagonal radius, the blur test and optical off-centering written as a checklist every contributor PR must pass — an open-source icon set governing community contributions with machine-checkable rules (07 §3.2);
  • Heroicons’ three-tier grid: 24/20/16 as three independently redrawn viewBoxes (measured from source files) rather than scaling — the industry precedent for “re-tier instead of hard-scale” in dense layouts (07 §1.3).

When to use 4
  • Design acceptance for a homegrown icon set: run each glyph under keyline/safe overlays and measure the circle-beats-square-by-2dp rule and the 18×18 keyline (07 §2/§3.1)
  • Landing team standards: turn 1px safe area, 2px element gaps, integer coordinates and one stroke width into machine-checkable rules (Lucide's acceptance method, 07 §3.2)
  • Visual-weight arbitration: blur the glyph next to circle/square and compare gray levels — turning 'feels too heavy' into a reviewable procedure (Lucide's blur test, 07 §3.2)
  • Multi-size system choices: 24 regular and 20 dense (Material's desktop dense layout), with 16px-class redraws instead of scaling (the Heroicons micro/mini precedent, 07 §1.3/§2)
When not to use 4
  • Scaling an SVG to change stroke weight — width is a user unit on the 24 grid; continuous weight needs the wght axis or a different weight file (07 §1.5)
  • Mixing line-width conventions from different families (a 1.5px Heroicons glyph inside a 2px system) — the audit's first row explodes (07 §1.3)
  • Letting content cross the trim area or putting key detail into the 2dp padding — padding allows weight extension only, it is not content space (07 §2)
  • Forcing geometric centering on asymmetric shapes — Lucide explicitly allows slight optical off-centering; geometric center is not visual center (07 §3.2)
Accessibility

Consistency is the prerequisite of accessibility: (1) thin lines get diluted by anti-aliasing on low-DPI/small sizes — WCAG 1.4.11's understanding doc explicitly advises avoiding particularly thin lines (07 §3.3); a system stroke ≥2px is the readability floor; (2) icons inside keylines keep their recognition size; dense layouts switch to the 20dp tier instead of hard scaling; (3) naming consistency serves search and maintenance directly and alt-text accuracy indirectly (when names are right, authors can find the 'action' rather than the 'shape' for aria-label); (4) the blur test also filters out detail that turns to mush at small sizes, protecting legibility for low-vision users (Lucide density control, 07 §3.2).

Browser support

Pure SVG + CSS variable rendering — fully green; the keyline/safe-area overlays are demo-drawn geometry with no dependency on new features. stroke-width sits on the svg root as an inherited presentation style and behaves consistently across browsers. · widely available

Fallback

No fallback needed: the grid audit is a geometric convention with no runtime dependency. Without CSS variables, stroke falls back to a hard 2px; the audit rules themselves (integer coordinates / safe area / naming) still hold.

Sources 3

OriginTwo numeric backbones: (1) Material's official 24px grid (m2.material.io system-icons, 07 §2): display 24×24 dp, live area 20×20 (2dp padding all around), trim area = the full 24dp with content never escaping; keylines: square 18×18, circle Ø20, vertical/horizontal rectangles 16×20/20×16; X/Y coordinates must be integers (no decimals); corner radius 2dp by default, interior corners square. (2) Lucide's contribution spec (design-principles.md/specification.md first-hand, 07 §3.2): strokes ≥1px from the canvas edge, ≥2px gaps between elements, the blur test for visual weight, optical off-centering allowed for asymmetric shapes. Stroke-width philosophy: static systems anchor at 2px (Lucide/Feather source), Heroicons is the 1.5px exception, continuous weight goes through Material Symbols' wght 100–700 axis — never scale an SVG to fake a stroke width (07 §1).
