24px Icon Grid

图标栅格 · 键程 · Keyline Shapes · Icon Grid · Live Area

24×24 is the industry's common ancestor grid: 24dp display, 20dp live area (2dp padding around), 18×18 square keyline, Ø20 circle keyline — the grid and safe-area guides visualized live.

Material 3 ★★★
Live demo official default
Parameters
Motion▾
gridSize24

Drawing-grid edge length. 24 = the official base: Material displays at 24dp and Feather/Lucide/Heroicons share the size (07 §0/§2); 20 = Material's official dense layout ("measurements may be scaled down to 20dp", live area down to 16×16) and Heroicons mini's redrawn grid (07 §1.3/§2); 16 = Heroicons micro's redrawn grid (viewBox measured, 07 §1.3); 32 = a common doubled-up grid with no official anchor (community norm, unverified). The official practice is redrawing at a new size tier, not proportional scaling (07 §3.1); the demo derives keylines for non-24 tiers proportionally from 24 — indicative only.

Geometry▾
padding2px
px

Live-area inset (px, integer steps to keep pixel alignment). Official value 2: "Icon content is limited to the 20dp x 20dp live area, with 2dp of padding around the perimeter" (07 §2). At 0 the live area fills the trim area and content touches the canvas edge; per the spec, heavier content may extend into the padding between live and trim area, but never outside the trim area (07 §2).

Code breakdown

Structure & DOM

The 24px icon grid is a design-time underlay: a 24×24 canvas (the trim area), content confined to the live area, and four official keylines governing visual weight. The demo draws grid, live area and keyline guides in one SVG with the sample glyph on top:

<svg viewBox="0 0 24 24" width="192" height="192">
  <!-- Grid lines (design-time guides, stripped from the deliverable) -->
  <g stroke="#94a3b8" stroke-width="0.125">
    <line x1="1" y1="0" x2="1" y2="24" /> <!-- one per unit -->
  </g>
  <!-- Live area: 24 − 2×2 = 20×20 -->
  <rect x="2" y="2" width="20" height="20" fill="none"
        stroke="#2563eb" stroke-dasharray="0.375 0.25"/>
  <!-- Keylines: square 18×18 / circle Ø20 / rects 20×16 and 16×20 -->
  <rect x="3" y="3" width="18" height="18" fill="none" stroke="#ea580c"/>
  <circle cx="12" cy="12" r="10" fill="none" stroke="#16a34a"/>
  <!-- The glyph itself -->
  <path d="…" fill="none" stroke="#0f172a" stroke-width="2"/>
</svg>

Key points:

  • Guides are design-time tools — the shipped SVG contains the glyph only;
  • The demo renders at an 8× integer scale (1 unit = 8px), where a 0.125-unit stroke lands exactly on 1px;
  • The sample “image” glyph is authored on the 24 grid and scaled by scale(gridSize/24) when the tier changes — purely for comparison: the official practice is an independent redraw per tier (see below).

Styling & Parameters

Both parameters are JS-type (geometry recompute); the demo derives:

live     = gridSize − 2×padding        // official 24 tier: 24 − 4 = 20
square   = live − 2                    // square keyline: 20 − 2 = 18 (official)
circle   = live                        // circle keyline: Ø20 (official)
landscape = live × (live − 4)          // landscape rect: 20 × 16 (official)
portrait  = (live − 4) × live          // portrait rect: 16 × 20 (official)

Where the numbers come from (m2.material.io system-icons, quoted line by line in research 07 §2):

  • Display 24×24 dp; dense layouts scale down to 20dp;
  • Live area 20×20 dp with 2dp padding all around; dense live area 16×16;
  • Keylines: square 18×18, circle Ø20, portrait 16×20, landscape 20×16;
  • X/Y must be integers (“on pixel”); corner radius defaults to 2dp; corners of shapes ≤2dp wide stay unrounded;
  • Content may extend into the padding for extra weight but must never leave the trim area.

Official template: Material’s grid template AI file (Apache 2.0, 07 §2).

Motion & Interaction

The grid is a static underlay; demo interaction is parameter-only:

  • gridSize switch: the SVG viewBox recomputes; the 16/20/24/32 tiers all render at 8px per unit, so visual size grows with the tier — showing what “switching tiers” means versus “scaling”;
  • padding drag: the blue dashed live-area rect reflows live and the padding corridor (light canvas base) shows through; at 0 the live area fills the trim area;
  • Guides and legend carry aria-hidden; the readout row announces keyline values via aria-live="polite";
  • No motion dependencies, so prefers-reduced-motion needs no fallback.

Real-world examples

  • Material’s official keyline template: the m2.material.io system-icons page defines every number in the table above and ships an official grid template AI file (Apache 2.0) — “circle 2dp larger than square” is a written spec value, not visual folklore (07 §2/§3.1);
  • Heroicons’ three redrawn tiers: 24 / 20 / 16 each carry their own viewBox (measured from real repo files); the official route is redrawing per tier, not scaling the 24 art (07 §1.3);
  • Material Symbols’ pixel-alignment boundary: the opsz axis defaults to 24, and only the 20px and 24px versions achieve perfect pixel-grid alignment — even Google holds integer coordinates on just two tiers (07 §1.5).

Parameter Sensitivity

ParameterTurning it up…Turning it down…
gridSizeat 32 all keylines enlarge (derived values) with more detail headroom; but with no official anchor, cross-set alignment breaksat 16 stroke spacing collapses — Lucide demands ≥2px gaps between adjacent elements and a 2px circle fitting through every counter, which small grids struggle to satisfy (07 §3.2)
paddingthe corridor narrows (0–2): glyphs touch the canvas edge and breathing room vanishes; the spec allows extending into padding for weight, never past the trim areapadding=2 is the official default; above it (3–4) the live area shrinks fast, the square keyline falls below live−2 and icons read small

Anchors: tier 24 + padding 2 = the official base; tier 20 + padding 2 = the official dense layout (live 16); every other combination is a derived demo — redraw independently for delivery.

When to use 3
  • Acceptance underlay for drawing/reviewing icons: compare against the four keylines — square 18×18, circle Ø20, landscape 20×16, portrait 16×20 (07 §2)
  • Preparing a 20px tier for dense desktop layouts: display 20, live 16, padding still 2 (07 §2)
  • Cross-set weight checks: sets share the 24 ancestor grid, and the iron rule 'circle 2dp larger than square' is an official number, not folklore (07 §3.1)
When not to use 3
  • Shipping a 24-grid icon scaled straight down to 16px — the official practice is an independently redrawn tier (Heroicons 20/16 measured standalone viewBoxes, 07 §1.3/§3.1)
  • Content escaping the trim area, or fractional coordinates — the spec requires integer X/Y ("on pixel", 07 §2)
  • Setting padding to 0 and still expecting breathing room — a full-bleed live area makes icons visually glue together
Accessibility

The grid relates to accessibility indirectly: a sane live area preserves stroke spacing, and Lucide's spec requires ≥2px gaps between adjacent independent elements plus a 2px circle fitting through every counter (07 §3.2) — too-tight spacing turns to mush when rendered small. Guides are decoration: never ship them in the deliverable (or mark them aria-hidden).

Browser support

Grid and keylines are design-time concepts; the deliverable is a plain SVG that scales by viewBox, rendered identically in all mainstream browsers. The demo's guide lines use 0.125-unit strokes at an 8× integer scale to stay 1px thin — no compatibility concerns. · widely available

Fallback

No fallback needed: the grid is an authoring discipline, not a runtime feature; hide the guide SVG and keep the glyph itself to see the real deliverable.
