OKLCH Color Space

oklch 色彩空间 · 感知均匀色彩空间 · Perceptually uniform color space

CSS's official perceptually uniform space oklch(L C H / A): numeric deltas equal perceptual deltas — this entry covers the space itself and its four components.

Web Standard ★★★
Live demo official default
Parameters
Geometry▾
L70%
%

Perceived lightness: 0 = black, 100 = white (also writable as 0–1). The L axis is linear to human perception — equal L steps look equally spaced (the fundamental difference from HSL, whose L does not track perceived lightness). Workflow anchors from Evil Martians: L=0.8 (pairs clearly with black text), L≥87% (backgrounds pass contrast with black text). Default 70 is an entry snapshot; research records no official default.

C0.15

Chroma; 0 = neutral gray. MDN: theoretically unbounded, but practically capped near 0.5 — and note 100% = 0.4, not 1. Evil Martians measured the actual sRGB gamut boundary at ≈0.37 (slightly higher on P3 screens): past it the color leaves the gamut and browsers (Chrome/Safari) clip RGB outright, visibly shifting hue. Default 0.15 is an entry snapshot inside the safe sRGB range.

H145deg
deg

Hue angle 0–360°. oklch's hue scale coincides with neither hsl nor lch: hsl 0° = red, CIELab red ≈ 41°; Evil Martians' rule of thumb: red ≈ 20°, yellow ≈ 90°, green ≈ 140°, blue ≈ 220°, purple ≈ 320°. Default 145 (green) follows that mapping. Rotating H at fixed L/C barely moves perceived lightness.

alpha1

Opacity, written after a slash in the syntax: oklch(L C H / A). 1 = fully opaque, 0 = fully transparent; when translucent, the backdrop participates in the final appearance and contrast. Default 1 (opaque).

Code breakdown

Structure & DOM

oklch() is a function adopted in CSS Color 4 with no DOM requirements of its own — it is just a color value. The minimal structure to use it is one element painted with it plus a readout that exposes the component semantics:

<div class="swatch"><!-- the block painted by oklch() --></div>
<span class="readout">oklch(70% 0.15 145)</span>
  • The value is decoupled from elements: it can appear in color, background-color, border-color, fill, shadow — anywhere a <color> is accepted;
  • Transparency goes after the slash: oklch(70% 0.15 145 / 0.5); whatever shows through underneath becomes part of the final look; alpha also accepts percentages and composes with color-mix(in oklab, …) for translucent derivatives (Tailwind v4’s opacity recipe, research 06 §4);
  • Missing components are legal too: oklch(none 0 none) is the W3C example for desaturation animations (CSS Color 4 §4.4, research 06 §1);
  • The demo implements the same conversion in JS (Ottosson matrices) so every numeric step can be inspected.

Styling & Parameters

Four components with clear semantics: L perceived lightness (0 black → 100 white), C chroma (0 = gray), H hue angle, alpha opacity:

.swatch {
  /* sRGB fallback first, oklch override after */
  background-color: rgb(91 182 97);
  background-color: oklch(70% 0.15 145);
  color: oklch(0.15 0.03 145);
}
@supports (color: oklch(70% 0.15 145)) {
  .swatch { border-color: oklch(70% 0.15 145 / 0.4); } /* alpha after the slash */
}
@media (color-gamut: p3) {
  .swatch { background-color: oklch(70% 0.37 145); }  /* release chroma on P3 */
}

Where the numbers come from (research 06 §1/§2):

  • L takes 0–1 or 0%–100%, 0 = black, 1 = white (MDN); C’s practical cap is ≈ 0.5, and 100% = 0.4, not 1 (MDN);
  • H spans 0–360° but its scale matches neither hsl nor lch: hsl 0° = red, CIELab red ≈ 41°; Evil Martians’ mapping: red ≈ 20°, yellow ≈ 90°, green ≈ 140°, blue ≈ 220°, purple ≈ 320° (this entry’s default 145 is “green”);
  • C’s measured sRGB boundary ≈ 0.37 (slightly higher on P3); Chrome/Safari currently clip RGB instead of the spec’s chroma reduction, visibly shifting hue — hand-write P3 overrides;
  • The percentage notation is a particular trap for C: 100% equals only 0.4, so a single oklch(70% 100% 145) is already past the sRGB boundary — prefer decimal notation day to day;
  • Baseline “widely available” = May 2023.

Motion & Interaction

  • Changing any component recomputes the color and readout instantly. The most direct proof of perceptual uniformity: a ladder with fixed C/H and L stepping +10 looks evenly spaced in lightness — the demo converts each step to sRGB in JS and lays out 10 steps;
  • The interaction payoff of uniformity: hover lightening can be a relative color oklch(from var(--c) calc(l + 0.1) c h) (CSS Color 5; calc may only add/subtract numbers) — the same Δl is an equal perceptual step for every hue (research 06 §2);
  • Gradients likewise: declaring linear-gradient(in oklch, …) pins the interpolation space, so long-range hue transitions no longer produce the muddy gray bands of default sRGB interpolation (CSS Color 4 §13, research 06 §4);
  • Swatch transitions animate only background-color (0.18s); under prefers-reduced-motion the transition is removed and values jump;
  • No transform animation: in a color-space demo any movement is just noise;
  • When any converted channel leaves [0,1] the demo raises an honest overflow warning and clips, matching what real pages hit on non-P3 screens.

Parameter Sensitivity

ParameterTurning it up…Turning it down…
Lbrighter: contrast vs black text drops, vs white rises; backgrounds at ≥87% always pass with black text (Evil Martians)darker: contrast vs black text rises; white text only becomes viable below ~50%; 0/100 are pure black/white and C/H lose meaning
Cmore vivid; past ≈0.37 it leaves sRGB and clipping shifts hue (release it on P3 screens)toward gray; at C=0 the color is fully determined by L, with the most extreme black/white contrast endpoints
Hrotates around the wheel (145 = green, 220 = blue): perceived lightness barely moves at fixed L/Crotates the other way; high-C regions may trigger gamut clipping mid-rotation
alphalets more of the backdrop through; element and background interpenetrate and contrast follows the compositetoward solid; 0 makes it invisible

The order of operations: L decides “how heavy”, C decides “how vivid”, H only decides “which color”. This entry covers the space itself — the fix-L picking workflow and contrast engineering live in the sibling entry oklch-workflow.

When to use 4
  • Anywhere numeric steps must equal perceptual steps: scale derivation, gradient interpolation, hover lightening
  • Themed colors with transparency: one oklch(L C H / A) declaration carries color and alpha together
  • Wide-gamut displays: raise C past 0.37 on P3 screens for more vivid brand colors
  • Composed with light-dark()/color-mix: oklch components let dark themes adjust L/C without touching hue
When not to use 3
  • Copying hsl hue angles into oklch — the scales differ; red sits near 20° in oklch, not 0°
  • Treating C as a 0–100 percentage: 100% equals only 0.4, and sRGB's real boundary is ≈0.37
  • Shipping raw high-C values — Chrome/Safari currently clip RGB instead of gamut-mapping, visibly shifting hue
Accessibility

L is perceived lightness and the first determinant of contrast: WCAG 2.1 body-text AA≥4.5:1, AAA≥7:1 (thresholds never round up). With translucent colors (alpha<1) over an uncontrolled backdrop, verify contrast against the composited brightest/darkest states, not the raw color; Evil Martians explicitly warns 'OKLCH alone doesn't guarantee accessibility — verify with APCA/WCAG.'

Browser support

oklch() is widely available across mainstream browsers since May 2023 (CSS Color Module Level 4, Baseline); the relative-color syntax oklch(from …) belongs to CSS Color 5 with newer support. The demo paints and converts via pure JS math (Ottosson matrices + sRGB gamma), independent of the browser's oklch support. · 2023

Fallback

Browsers without oklch(): declare an rgb()/hex base first, then wrap an oklch() override in @supports (color: oklch(0.7 0.15 145)); at build time, convert values to an sRGB fallback via tools like oklch.com. The demo paints with JS-converted rgb() and is compatible by construction.

Sources 3

OriginOklab was published by Björn Ottosson in 2020 as a perceptually uniform space for image processing; oklch is its cylindrical form, standardized in CSS Color Module Level 4 and supported by all mainstream browsers since May 2023 (research 06 §1).
