通知栈 Notification Stack

3 个条目

吐司弹簧 + 进度动效 + 摇晃衰减:通知栈的组合方案。

组合条目

Toast 弹簧入场 Toast 从屏幕边缘弹入:入场带过冲(真弹簧或 y₂>1 的过冲 bezier),退场纯缓出收尾,生命周期到点自动消失——『进攻退守,一进一出永不打架』。 组件库 ★★★ 进度反馈动效 进度形态随「确定性」变:骨架块(什么都不知道)→ 循环扫光(知道在加载)→ 百分比条(知道还剩多少)→ 完成快速淡入;形态切换按 NN/g 时长阈值演进,越接近终点动力越强(目标梯度)。 社区流派 ★★ 错误抖动·指数衰减 错误反馈抖动优先做成 x(t)=A·e^(−λt)·sin(ωt) 的指数衰减正弦:CSS 衰减 keyframes 与『给初速度、让弹簧自己衰减』两种实现对照,连按与中断物理连续。 社区流派 ★★★

组合依据

16 号调研 §7-配方 f(§8 巧思 7「吐司栈的三件套:栈是状态机,不是消息流」):栈管理数值 Ant 最全——message duration 3s/top 8/maxCount 超限自动关最早/key 复用同条消息/stack 堆叠模式(6.4.0),notification duration 4.5s/placement topRight/stack{threshold:3}/showProgress 进度条(5.18+)/pauseOnHover(默认 true)/width 384/top·bottom 24px(https://ant.design/components/notification-cn/ ;https://ant.design/components/message-cn/ );M3 snackbar 作反面配重——无操作 4~10s 自动消失、全屏同时只允许一条、最多一个动作,Web 端自动消失必须配行内反馈或改为可操作(https://m3.material.io/components/snackbar/guidelines )。demo 栈纪律取 Ant 数值,弹簧参数取 toast-spring 条目官方默认:stiffness 300/damping 25(ζ≈0.722、过冲≈3.8%,轻微过冲即止)/edge bottom/lifetime 4000ms(sonner TOAST_LIFETIME 源码值);官方弹簧依据 = M3 Expressive motion-physics(spatial springs + effects springs,后者专管颜色/透明度过渡——进度条收窄即其形态,https://m3.material.io/blog/building-with-m3-expressive );入场时长档 = TDesign 抽屉/消息通知/全局提示 280ms(桌面)/140ms(移动)、弹窗气泡类归 Z 轴运动,感知恒常性公式「桌面 = 移动 ×2」(https://tdesign.tencent.com/design/motion );demo 进度条 = Ant notification showProgress 语义(lifetime 倒计时收窄,悬停暂停 = pauseOnHover 默认 true)。摇晃衰减四家均无官方配方 → 未证实(§9 清单),唯一官方相邻依据 = TDesign 把「输入框抖动」列为微观动效示例 + Apple visionOS 避免约 0.2Hz 持续振荡(对该频率极敏感,https://developer.apple.com/design/human-interface-guidelines/motion );demo 取 shake-decay 条目官方默认 A=10px(animate.css shakeX ±10px 同量级)/λ=6s⁻¹(调研 10§4.3 采样示例:5 拍/0.5s,包络每拍 ×0.74)——瞬态衰减、非持续振荡。组合衔接:弹簧只管入出场、进度条只管剩余寿命、摇晃只管字段级错误,三动效互不叠加;Esc 关最新一条并归还焦点;reduced-motion 入出场退化纯 fade、摇晃停(错误语义由文案与描边兜底)。

出处 out/design-study/16-composition-recipes.md §7 配方 f「通知栈」+ §8 巧思 7(依据:Ant message/notification Token、M3 snackbar/m3-expressive、TDesign motion、Apple Motion ~0.2Hz 红线;摇晃衰减未证实,按条目 schema 默认落地)
