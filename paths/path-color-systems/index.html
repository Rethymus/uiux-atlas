色彩系统 Color Systems

5 步

学完你能:用恒定 C 的 OKLCH 生成色阶并说清 L/C/H 各轴含义;从源色生成 T0–T100 tonal palette 并映射到 M3 roles;把色板令牌化为 primitive → semantic 两层;最后只改一份 semantic 映射完成亮/暗双主题,两主题对比度全过。

目标人群 从「拍脑袋选色」转向「可计算色彩体系」的开发者与设计师:OKLCH、语义 token、可访问对比度一体化。

路径步骤

  1. 01

    OKLCH 选色工作流 ENTRY

    为什么现在学 从「日常能写」入手:感知均匀的 OKLCH 坐标是现代色板的操作单元,用恒定 C 生成色阶先练手感——M3 Styles 恒以 color 居第一组,Ant 全局样式亦以色彩居首。

  2. 02

    OKLCH 色彩空间 ENTRY

    为什么现在学 语法之上补「为什么」:CSS Color 4 在规范层定义 OKLab/OKLCH,会用之后再说清 L/C/H 各轴含义与取值范围。

  3. 03

    HCT 色调调色板 ENTRY

    为什么现在学 学会个人操作后看平台方案:Google 的 HCT tonal palette 与 OKLCH 互证,roles 表是官方「色板→角色」映射。

  4. 04

    语义色三层架构 ENTRY

    为什么现在学 色板要变成可维护系统必须令牌化:primitive → semantic 分层是 W3C Design Tokens 官方方法学,同一色板改一份映射即换语义。

  5. 05

    暗色设计模式 ENTRY

    为什么现在学 semantic 层就位后,暗色只是第二份映射——放最后是「令牌先行」的官方理由;Apple 甚至明示避免应用内自设外观开关。
