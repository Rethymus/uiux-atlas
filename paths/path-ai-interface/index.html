AI 界面工程 AI Interface Patterns

7 步

学完你能:搭通 SSE 流式管线(分片组装 + 中断续传);在首分片到达前给出思考指示;由 JSON Schema 流式渲染可交互卡与逐行流式表格;用建议 chips 引导下一轮;并以 loading/部分/错误/空/无来源/重试 六态状态机收官——把空态做成引导下一轮的邀请,一条对话流跑完全链演示。

目标人群 正在做 AI 产品的界面工程师:流式响应、思考态、建议 chips 到生成式 UI 的完整模式库。

路径步骤

  1. 01

    AI 流式响应 ENTRY

    为什么现在学 流式管线是 AI UI 的地基设施,先通管道再做壳——NN/g 判定 AI 正引入第三种界面范式(意图式结果说明),管道是范式的第一块基石。

  2. 02

    AI 思考中指示器 ENTRY

    为什么现在学 流式引入的第一个 UI 问题=「未完成态」:首分片到达前要有思考指示,官方载体是 progress indicators。

  3. 03

    生成式 UI ENTRY

    为什么现在学 从「文本流」升维到「组件流」:由 JSON Schema 流式渲染可交互卡,是意图范式的官方实现路径(AI SDK 生成式 UI / Ant Design X)。

  4. 04

    AI 流式表格 ENTRY

    为什么现在学 生成式 UI 之后攻最难形态:结构化数据的逐行流——本站自定义条目,无任何厂商专页(官方依据为 MDN Streams + M3 组件组合锚点,如实标注未证实)。

  5. 05

    AI 建议操作 Chips ENTRY

    为什么现在学 答案完整后学「引导下一轮」:建议 chips 是官方建议组件,充当「回答」与「追问」两幕之间的桥。

  6. 06

    AI 回答安全态 ENTRY

    为什么现在学 收官永远是状态完备性:loading/部分/错误/空/无来源/重试 六态状态机全部可达,是 AI 界面的终验。

  7. 07

    空状态 ENTRY

    为什么现在学 六态里「空」最常被敷衍:empty 条目把空态从「没有数据」升级为引导下一轮的邀请——状态机收官后的最后一块收口练习。
