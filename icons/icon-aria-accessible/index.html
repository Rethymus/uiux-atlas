图标语义与无障碍 Icon Semantics & Accessibility

装饰性图标 · 图标可访问名 · aria-hidden · Accessible Icon · Decorative Icon

装饰图标一律 aria-hidden="true" 摘出无障碍树且永不落在可聚焦元素上;语义图标用可访问名写动作(「搜索」不是「放大镜」);四种 aria-hidden × 可访问名组合逐一对照读屏行为。

Web 标准 ★★
实例演示 官方默认
参数
动效▾
decorativeon

装饰化开关。默认 on:图标被摘出无障碍树(MDN:aria-hidden="true" removes the element and all children from the accessibility tree),按钮只播报可访问名——MDN 官方示例即此分工(图标装饰 + 按钮拿名)。红线:aria-hidden 不得用在可聚焦元素或其祖先上(焦点会落进被隐藏子树);本 demo 的 aria-hidden 始终在 svg 上、按钮可聚焦不受影响(07 §4.1)。

labelwith

可访问名开关。默认 with:纯图标按钮必须有可访问名,且写动作不写形状——WAI 教程原文 "'search' rather than 'magnifying lens'","print this page" 而非 "printer"(07 §4.1);demo 取「收藏」而非「星形」。without 档展示失败形态:按钮无可访问名,读屏只能读到「按钮」,信息全失;针对 <img> 缺 alt 时读屏会朗读文件名/URL(内联 SVG 行为因读屏器实现而异,未统一规定)。

结构与 DOM

图标的语义分工发生在两层:图标图形层(装饰 or 携带语义)与承载交互的按钮层(拿可访问名)。正确结构的分工是——装饰图标摘树、可聚焦元素拿名:

<!-- 图标 + 文字按钮:可见文字就是可访问名,图标纯装饰(MDN 官方示例分工) -->
<button>
  <svg aria-hidden="true" viewBox="0 0 24 24">…星形路径…</svg>
  收藏
</button>

<!-- 纯图标按钮:图标装饰化 + 按钮拿 aria-label,名写动作不写形状 -->
<button aria-label="收藏">
  <svg aria-hidden="true" viewBox="0 0 24 24">…星形路径…</svg>
</button>

四条铁律(W3C/MDN 一手,07 §4.1):

  1. 纯装饰图标摘树:aria-hidden="true" 把元素及其全部子节点从无障碍树移除,可隐藏对象明确列举 “Purely decorative content, such as icons”;
  2. 红线:可聚焦元素不得 aria-hidden,也不得加在可聚焦元素的祖先上(隐藏沿树传染,焦点会落进不可见子树);
  3. 摘除的前提:等价信息已从其他通道暴露(“identical or equivalent meaning and functionality” 暴露给 AT);
  4. 语义图标的名写动作不写形状:WAI 教程原文 “print this page” 而非 “(image of a) printer”、“search” 而非 “magnifying lens”。

样式与参数

两个参数都是 JS 型,决定两个真实按钮的 aria 属性;读屏模拟面板按同一规则函数输出播报:

// 装饰化:aria-hidden 始终落在 svg 上,按钮保持可聚焦(红线不破)
<svg aria-hidden={decorative === "on" || undefined} …>…</svg>

// 可访问名:名 = "收藏"(动作),不是 "星形"(形状)
<button aria-label={named ? "收藏" : undefined}>…</button>

// 可访问名计算(简化版 accname):aria-label 优先,回退到按钮文本内容
const name = btn.getAttribute("aria-label") ?? btn.textContent.trim();

四格对照(W3C/MDN 规则推演,实际读屏器实现有差异,已如实标注):

aria-hidden可访问名读屏播报判定
✓✓「收藏,按钮」推荐(MDN 官方分工)
✓✗「按钮」失败:图标摘除后按钮无名
✗✓「收藏,按钮」(图形是否播报因实现而异)可用但冗余风险
✗✗「按钮」;<img> 缺 alt 场景会读文件名/URL失败:无名且无等价文本

动效与交互

无障碍条目的交互就是「配置 → 行为」的即时反馈:

  • 参数切换实时落到真实按钮:svg 的 aria-hidden 与按钮的 aria-label 同步变化,读屏模拟面板与四格表高亮当前组合;
  • 按钮保留真实键盘行为:Tab 聚焦、Enter/Space 激活、:focus-visible 焦点环——焦点环自身受 WCAG 1.4.11 的 3:1 约束(07 §4.3);
  • demo 内无运动动效,prefers-reduced-motion 无需降级;
  • 读屏模拟面板标明是规则推演,不逐字复刻任一读屏器(内联 SVG 播报因 NVDA/JAWS/VoiceOver 实现而异)。

真实产品案例

  • MDN aria-hidden 官方示例:图标装饰化 + 文字标签拿名,即本条目 icon+text 按钮的结构原型(07 §4.1);
  • W3C WAI Images Tutorial:功能图替代文本写动作意图(“search” 而非 “magnifying lens”),图标紧跟链接文字且不携带新信息时 → alt=""(07 §4.1);
  • WAI-APG 现行实践:旧版 Images 实践页 2026-11 实测 404 后,由 “Providing Accessible Names and Descriptions” 与 “Hiding Semantics with the presentation Role” 两页承接,规则实质不变——装饰性摘除、功能性给名(07 §4.2)。

参数敏感度

参数调大会…调小会…
decorativeon 图标摘树、播报干净,但前提是按钮已有等价名;若同时把名也关掉,信息瞬间归零off 图标保留在树里——多数读屏器对无 title 内联 SVG 不播报(行为有差异),留下不确定性而非额外信息
labelwith 给按钮动作名,四种组合中唯一的满分搭配(配 aria-hidden)without 让可访问名为空——读屏只读「按钮」,针对 <img> 还可能朗读文件名/URL,是最严重的失败形态

锚点:装饰图标一律 aria-hidden 且永不落在可聚焦元素上;图标按钮的名永远写动作;摘除前确认等价信息已在别的通道暴露。

适用场景 3
  • 图标 + 文字按钮:图标纯装饰 aria-hidden,文字就是可访问名(MDN 官方示例分工)
  • 纯图标按钮(工具栏):图标 aria-hidden + 按钮拿 aria-label 写动作「收藏/搜索/打印此页」
  • 信息型共享图标(如「新窗口」):替代文本承载图标语义本身(07 §4.1 例 3)
何时不要用 3
  • aria-hidden 放在可聚焦元素或其祖先上——焦点落进隐藏子树是 ARIA 红线(MDN 原文,07 §4.1)
  • 用形状描述当可访问名(「五角星」「放大镜」)——应写动作(「收藏」「搜索」,WAI 教程,07 §4.1)
  • 隐藏后没有等价信息暴露("identical or equivalent meaning and functionality" 是摘除前提,07 §4.1)
无障碍

本条目即无障碍本体:装饰图标 aria-hidden 摘树;图标按钮可访问名写动作;摘除前提是等价信息已从其他通道暴露。另两条相邻护栏:图形对比 ≥3:1(WCAG 1.4.11,见 icon-color-states)、焦点指示同样受 3:1 约束。读屏行为对照表以 W3C/MDN 规则推演,实际播报因读屏器而异(已如实标注)。

浏览器支持

aria-hidden 与 aria-label 是 ARIA 标准属性,现代浏览器 + 主流读屏器(NVDA/JAWS/VoiceOver/Narrator)均支持;读屏器对无 title 内联 SVG 的具体播报行为存在实现差异(未统一规定),demo 的「读屏模拟」按 W3C/MDN 规则推演,不宣称逐字复刻任一读屏器。 · widely available

兼容回退

ARIA 属性在极旧 AT 上可能被忽略,因此可访问名优先用**平台原生机制**:按钮内有真实文字(可见标签)> aria-label;装饰图标在无 ARIA 环境下退化为「多读一段无意义内容」,不破坏功能——这也是 MDN 示例保留文字标签的原因。

来源 3

起源规则主干来自 W3C/MDN 一手:MDN aria-hidden 明确可隐藏对象包含 "Purely decorative content, such as icons",且不得用于可聚焦元素;W3C WAI 功能图教程要求替代文本传达动作意图——"'print this page' rather than '(image of a) printer'"(out/design-study/07-icons.md §4.1)。WAI-APG 旧版 Images 实践页已于 2026-11 实测 404,现行由 names-and-descriptions 与 hiding-semantics 两页承接(07 §4.2)。
