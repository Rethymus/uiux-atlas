图标按钮 Icon Button

icon-only button · 纯图标按钮 · 图标工具栏按钮 · Accessible Icon Button

纯图标按钮 = 真实 <button>(自带 APG Button 的 Enter/Space 键盘)+ 装饰图标(aria-hidden + focusable="false")+ 写动作的可访问名;名称实现三方案(视觉隐藏文本 / hidden + aria-labelledby / aria-label)逐一对照,命中热区可量化审计(WCAG 2.5.8 ≥24×24,M3 触控 48dp)。

代码拆解

结构与 DOM

纯图标按钮的分工是三层的:真实 <button> 承载交互与键盘,图标纯装饰,名称挂在按钮层——与 APG Button 模式对照,原生 <button> 天生满足其键盘契约(Enter/Space 激活),完全不需要 role="button" + tabindex="0" 的手工仿写:

<!-- 方案②(Sara Soueidan 推荐):hidden 文本 + aria-labelledby,名在 DOM 里 -->
<button aria-labelledby="btn-search" aria-pressed="false">
  <svg aria-hidden="true" focusable="false" viewBox="0 0 24 24">…</svg>
  <span id="btn-search" hidden>搜索</span>
</button>

<!-- 方案③:按钮直接拿 aria-label(可用但有四缺点) -->
<button aria-label="搜索">
  <svg aria-hidden="true" focusable="false" viewBox="0 0 24 24">…</svg>
</button>

四条铁律(12 §12 一手结论):

  1. 名称写在按钮层,不写在 SVG 上——Scott O’Hara 的跨浏览器/读屏组合测试中,「名只放 SVG」的方案存在大量失败组合;
  2. 图标装饰化:aria-hidden="true" 且永不落在可聚焦元素或其祖先上(焦点不得落进隐藏子树,MDN 红线);SVG 加 focusable="false" 防 IE 双 Tab 停靠;
  3. 名称写动作不写形状:「搜索」不是「放大镜」(WAI 教程);有可见文字时 aria-label 必须与之一致(WCAG 2.1 Label in Name);
  4. aria-label 的四缺点先知晓再用:文本不进 DOM、整页翻译工具无法处理、部分语音控制识别困难、不可复制。

样式与参数

四个参数把「名称实现 × 热区策略」做成可审计实验:两个 CSS 变量驱动热区与图标,两个 JS 型开关切换命名方案与热区实现:

.icb-btn {
  width: var(--icb-target);            /* 热区边长,默认 48px(M3 target 48dp) */
  height: var(--icb-target);
}
.icb-btn svg { width: var(--icb-icon); height: var(--icb-icon); } /* 字形,默认 24px */

/* 伪元素扩热区:视觉不变,::before 以负 inset 越过可视边界(社区常见做法) */
.icb-btn[data-expand="pseudo"] { width: calc(var(--icb-icon) + 16px); height: calc(var(--icb-icon) + 16px); }
.icb-btn[data-expand="pseudo"]::before {
  content: "";
  position: absolute;
  inset: calc((100% - var(--icb-target)) / 2);  /* 负值 = 向外扩到热区尺寸 */
  border-radius: inherit;
}

数值出处:

  • hitTarget 默认 48px = M3 触控目标规格 target 48dp(research 04 §2.1);法定底线 ≥24×24 CSS px = WCAG 2.2 SC 2.5.8(principles/wcag-checklist 条目同源);
  • iconSize 默认 24px = Material 图标展示尺寸 24×24 dp(07 §2);
  • 「图标 16px + 热区 48px」的常见生产组合无统一标准值(社区常见值,未证实),demo 不预设该组合。

动效与交互

  • 命名方案切换(naming)直接改写真实按钮的 DOM 结构:labelledby 档挂 hidden 文本,hidden-text 档挂视觉隐藏文本(clip-path: inset(100%) 家族),aria-label 档挂 aria-label——审计面板按同一规则函数输出读屏播报推演与判定(推荐/可用/失败);
  • 热区审计(hitTarget):虚线审计框与按钮同心,呈现实际可点区;低于 24px 变红(法定底线失守),背景刻度尺对照 24/48 两档;expand=pseudo 时可视盒缩小而审计框不变——直观看到「热区越过可视边界」;
  • 键盘行为是真实行为:两个按钮都是原生 <button>,Tab 聚焦、Enter/Space 激活、:focus-visible 蓝色焦点环;交互日志把 Enter/Space 事件显式标出(「APG Button」),证明键盘与鼠标行为完全一致;
  • 无装饰性运动动效,prefers-reduced-motion: reduce 时仅有的过渡直切,状态反馈不删。

真实产品案例

  • Sara Soueidan《Accessible Icon Buttons》:三方案对照与推荐(hidden 文本 + aria-labelledby)的原始出处;文中还引 Scott O’Hara 的浏览器/读屏矩阵证明「名只放 SVG」不可靠(12 §12);
  • WAI-ARIA Authoring Practices Button 模式:按钮键盘行为的权威基线——Enter/Space 激活是模式的核心键盘契约;原生 <button> 开箱即满足,手写仿写必须补齐(本条目 demo 即用原生按钮对照);
  • TDesign 文档站顶栏操作栏(调研 02 实测):32×32 图标按钮 + 8px 间距,hover/active 用分层背景——紧凑桌面工具栏把可视盒压到 32px 级,命中合规靠间距与悬停反馈补足(实测值出自 out/design-study/02-tdesign.md)。

参数敏感度

参数调大会…调小会…
naminglabelledby/hidden-text 两档是推荐区:名在 DOM、可翻译可复制svg-only/none 两档是失败区:播报降级为「按钮」甚至不确定——读屏用户失去全部操作语义
hitTarget48px 级触控舒适、误触率低;占用布局空间变大低于 24px 直接触发 WCAG 2.5.8 违规(审计框变红),相邻按钮开始抢命中区
iconSize字形变大、热区不变——「大图标小热区」是倒置的合规观12–16px 的紧凑字形 + 48px 热区是常见生产形态(具体组合无统一标准,社区常见值,未证实)
expandpseudo 档布局零占位变大,但命中区越过可视边界会与相邻热区重叠padding 档热区随盒走、无重叠陷阱,是兜底首选

锚点:名称永远在按钮层写动作;热区永远 ≥24×24,生产看 48;键盘永远交给原生 <button>;伪元素扩热区是紧凑场景的技巧,不是合规底线本身。

适用场景 4
  • 工具栏/顶栏的纯图标操作(收藏、搜索、关闭):真实 <button> + 装饰图标 + 按钮自身拿动作名
  • 移动端底部导航与悬浮操作钮:热区按 48dp 级(M3 target 48dp)拉开,图标可小(07 §2/research 04 §2.1)
  • 图标 + 文字按钮:图标 aria-hidden,可见文字即名——aria-label 若存在必须与文字一致(Label in Name,12 §12)
  • 紧凑桌面工具栏(空间受限):伪元素扩热区保持视觉紧凑的同时守住 24×24 底线(社区常见做法)
何时不要用 4
  • 把可访问名只放在 SVG(<title> 或 aria-label on svg)上——跨浏览器/读屏组合存在失败案例(Scott O'Hara,12 §12)
  • 热区低于 24×24 CSS px(WCAG 2.5.8 法定底线)或热区互相紧贴抢命中(04 §2.1 间距要求)
  • 用 <span role="button"> 仿按钮而丢掉 Enter/Space——原生 <button> 自带 APG Button 键盘行为,仿写必须补 keydown
  • aria-label 与可见文字不一致(或整页翻译后不一致)——Label in Name 红线(12 §12)
无障碍

本条目即无障碍工程本体:①名称写动作不写形状(「搜索」不是「放大镜」,WAI 教程);②图标装饰化(aria-hidden)且永不落在可聚焦元素上,SVG 加 focusable="false";③名称优先 DOM 文本(labelledby/隐藏文本),aria-label 知晓四缺点再用;④热区 ≥24×24 CSS px(WCAG 2.5.8)、生产参照 48dp(M3);⑤键盘行为交给原生 <button>(APG Button:Enter/Space 激活),焦点环 :focus-visible 可见。与 icon-aria-accessible(装饰化×名的四格行为表)、fitts-law(热区尺寸感受)互为补充,本条目聚焦「工程实现三方案 + 热区策略」。

浏览器支持

原生 <button>、aria-label/aria-labelledby、::before 均为 Baseline 广泛可用;读屏器对三种命名方案的播报一致性好(hidden 文本方案为 Sara Soueidan 推荐)。SVG 的 focusable="false" 仅对 IE10/11 的 SVG Tab 停靠问题有意义,现代浏览器忽略之(保留无副作用,12 §12)。 · widely available

兼容回退

极老 AT 可能忽略 ARIA 引用,因此可访问名的最稳来源是**真实文本**(方案①,哪怕是视觉隐藏的);无 ARIA 环境下图标退化为「多读一段无意义内容」而非功能损坏。热区在无 CSS 环境退化为按钮盒本身——所以宁可 padding 撑盒(热区随盒走)也不要只靠伪元素扩热区承载合规底线。

来源 3

起源实现方案对比出自 Sara Soueidan《Accessible Icon Buttons》(out/design-study/12-expansion.md §12):①视觉隐藏文本;②hidden 文本 + aria-labelledby(ARIA 允许引用隐藏元素);③按钮 aria-label。aria-label 的四个缺点:文本不进 DOM、整页翻译工具无法处理、部分语音控制识别困难、不可复制。推荐:图标 aria-hidden="true" + focusable="false"(防 IE 双 Tab 停靠)当装饰,名称由按钮自身提供;有可见文本时 aria-label 必须与之一致(WCAG 2.1 Label in Name);不要把名称只放 SVG 上(Scott O'Hara 跨浏览器/读屏组合测试均有失败)。热区数值:WCAG 2.2 SC 2.5.8 ≥24×24 CSS px(principles/wcag-checklist 条目);M3 target 48dp(research 04 §2.1,fitts-law 条目同源)。
