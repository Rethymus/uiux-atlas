描边与填充图标 Stroke & Fill Icons

描边图标 · 填充图标 · Outline Icons · Filled Icons · Stroke Icons

SVG 图标的第一分叉:stroke 走 currentColor 的线性描边,或 fill 吃满 currentColor 的实底填充;同一路径两种交付,线宽 1–3 与填充开关实时切换。

Web 标准 ★★★
实例演示 官方默认
参数
几何▾
strokeWidth2

SVG stroke-width(继承属性,设在 <svg> 根即可传导全部子形状)。默认 2 = Lucide/Feather 官方源码定值(defaultAttributes.ts,07 §1.1);Heroicons 24/outline 真实文件实测 1.5(README 快速上手仍写 2,系 v1 旧文案,以文件为准,07 §1.3)。WCAG 1.4.11 理解文档提醒:抗锯齿会让过细线条实际渲染远淡于定义色,避免特别细的线(07 §3.3)。

动效▾
filloff

填充开关。默认 off:Lucide defaultAttributes 定值 fill:'none',纯描边交付(07 §1.1);on 时闭合路径得到 fill:currentColor 的实底。注意两点:① 开放路径(线段、射线)fill 无形可填,只留描边;② 已写死 fill="none" 的镂空子形状(本 demo 的镜头/圆点)会保持中空——fill/stroke 写死在 path 上会封死继承(MDN use 属性遮蔽规则,07 §5.1)。Phosphor 则相反:全系以填充路径交付,描边烘焙进轮廓(07 §1.4)。

capJoinround

线帽与转角风格。默认 round:Lucide/Feather 源码定值 stroke-linecap/linejoin: 'round'(07 §1.1),圆头是描边图标的社区主流气质;square 档演示 stroke-linecap: square + stroke-linejoin: miter 的硬朗对照——转角处易出现尖刺,通常需再调 miter-limit。Material 体系对圆角另有数值规则:默认 2dp,≤2dp 宽的形状转角不倒圆(07 §2)。

代码拆解

结构与 DOM

描边与填充是同一套 SVG 路径的两种「上墨」方式:路径(几何)只画一次,颜色与粗细全部交给继承属性——stroke、fill 设在 <svg> 根上,子形状保持裸路径。

<svg viewBox="0 0 24 24" fill="none" stroke="currentColor"
     stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
  <path d="M13.5 2.75 6 13.5h4.9L10.5 21.25 18 10.5h-4.9z" />
  <!-- 镂空子形状:内联 fill="none",填充开也保持中空 -->
  <circle cx="12" cy="10.7" r="2.4" fill="none" />
</svg>

关键点:

  • viewBox="0 0 24 24" 是全行业共同祖先网格(Lucide/Feather/Heroicons/Material 同规格,调研 07 §0);
  • 颜色只写 currentColor 一处:组件层设 color:,图标与文字同步变色(CSS Color 4 §6.4:currentcolor 即同元素 color 属性值,07 §5.2);
  • 子形状上写死 fill/stroke 会封死继承——<use> 深克隆进 shadow DOM 后只吃继承属性,「已定义的属性被引用值忽略」(MDN use 规则,07 §5.1);
  • 开放路径(线段)没有可填充的面积,fill 开了也只剩描边;要填充必须给闭合路径。

样式与参数

三个参数对应 svg 根上的三组属性,strokeWidth 经 --sf-stroke 变量注入,fill/capJoin 为 JS 型开关:

.sf-ic {
  fill: none;                              /* Lucide 源码定值 fill: 'none' */
  stroke: currentColor;                    /* Lucide 源码定值 */
  stroke-width: var(--sf-stroke, 2);       /* 默认 2 = defaultAttributes.ts 定值 */
  stroke-linecap: round;                   /* 源码定值 round */
  stroke-linejoin: round;                  /* 源码定值 round */
}
.sf-scene[data-fill="on"] .sf-art path { fill: currentColor; }
.sf-scene[data-cap="square"] .sf-ic { stroke-linecap: square; stroke-linejoin: miter; }

数值出处:

  • stroke-width 2 / round 圆头圆角 / fill none / currentColor 四件套:Lucide packages/lucide/src/defaultAttributes.ts 源码定值,icons/house.svg 实测同上(07 §1.1);Feather attrs 同构(07 §1.2);
  • 1.5 的例外:Heroicons src/24/outline/bars-3.svg 真实文件实测 stroke-width="1.5",README 快速上手仍写 2 是 v1 旧文案,以文件为准(07 §1.3);
  • 细线负债:WCAG 1.4.11 理解文档提醒抗锯齿会让特别细的线实际渲染远淡于定义色,建议避免(07 §3.3);
  • 填充路线的另一个极端:Phosphor 六权重全系以填充路径交付(256×256 viewBox 实测),描边宽度烘焙进轮廓(07 §1.4)。

动效与交互

描边/填充本身是静态属性,动效发生在「状态切换」上:

  • 填充点亮:描边版与填充版是同一路径的两种交付,hover/选中时切填充即「点亮」——这正是 Material Symbols FILL 轴(“animated fill effect, to indicate user selection”)的 SVG 等效通道(07 §6.1);过渡时长与缓动遵守 150–200ms + standard 缓动(07 §6.2);
  • 线宽不做动画:stroke-width 插值会引发整图标重排,小尺寸下抖动感明显;需要「变重」的感受优先换填充而非加粗线条;
  • prefers-reduced-motion 时填充切换直切终态(transition: none),状态反馈保留、运动取消(07 §6.3);
  • stroke-dashoffset 描边绘制类动效详见 icon-motion 条目。

真实产品案例

  • Heroicons 双体系:Tailwind 官方团队维护的 24/outline(描边 1.5px)与 24/solid(填充)共享语义同名文件,React/Vue 按路径摇树导入(@heroicons/react/24/outline),官方明确不再接受新图标 PR(07 §1.3);
  • Lucide 全描边 + 实验性填充:默认四件套源码定值,填充权重为实验性分支;lucide-react/vue/svelte 等全家桶把动画留给宿主,不在 SVG 内嵌 SMIL(07 §1.1/§6.3);
  • Phosphor 填充路线:Fill/Duotone 权重把描边烘焙为填充轮廓,是五套中唯二能做「半透明底 + 实心上」分层的(Duotone 背景层 opacity 0.2 实测)(07 §1.4)。

参数敏感度

参数调大会…调小会…
strokeWidth3 时线条粗壮醒目,但 ≤16px 渲染时镂空糊死、细节粘连1 时精致轻盈,但低分屏/小字号下实际渲染远淡于定义色(WCAG 1.4.11 提醒),对比度承压
fillon 让闭合路径实底化,视觉重量陡增——与描边版并排需模糊法核对灰度是否失衡(07 §3.2)off 回到纯描边,视觉最轻;依赖线宽与颜色对比支撑可见性
capJoinsquare/miter 转角出现尖刺与方头,风格硬朗但小尺寸易毛糙round 是默认与社区主流;圆头在曲线转角处过渡最顺

经验锚点:24px 网格配 2px 描边(Lucide/Feather 官方)、1.5px 是 Heroicons 的实测例外;描边与填充不要在同页面无体系混用。

适用场景 3
  • 工具栏/导航线性图标——一套路径改线宽即得视觉梯度,2px 是 Lucide/Feather 的官方锚点
  • hover/选中态要「点亮」的控件:描边版 + 填充版同路径切换,是 Material FILL 轴之外的 SVG 等效通道
  • 跟随文字颜色的正文内联图标(currentColor 一处染色)
何时不要用 3
  • 同一页面混用描边集与填充集而不成体系——视觉重量不一致,模糊法一验就穿帮(07 §3.2)
  • 小尺寸(≤16px)硬撑 3px 粗描边——线条粘连,镂空糊死;细分线条在低分屏又会渲染过淡(WCAG 1.4.11 提醒)
  • 把 fill/stroke 写死在复用 path 上——雪碧图/组件染色链会在此断掉(07 §5.1)
无障碍

图标作为图形对象需与相邻底色保持 ≥3:1 非文本对比(WCAG 2.2 SC 1.4.11;2.999:1 即不达标),且任何状态下不得失去;过细描边因抗锯齿实际更淡,应避免。装饰性图标一律 aria-hidden="true" 且不得落在可聚焦元素上;语义图标靠可访问名补足(详见 icon-aria-accessible 条目)。

浏览器支持

stroke/fill 为 SVG 1.1 标准属性,全主流浏览器可用;经 CSS 控制(SVG2 把 stroke-width/linecap/linejoin 升级为几何属性)在 Chrome/Firefox/Safari/Edge 均受支持。图标交付形态本身与 CSS 特性查询无关,无需 @supports。 · widely available

兼容回退

描边/填充是内联 SVG 基础能力,现代浏览器无需回退;仅在把图标当 <img> 外链且旧环境不渲染 SVG 时,退回 PNG/雪碧图或图标字体。若继承链被破坏(图标不着色),先检查 path 上是否写死了 fill/stroke。

来源 4

起源描边四件套(24 网格、stroke-width 2、round 圆头圆角、currentColor)在 Lucide packages/lucide/src/defaultAttributes.ts 中为源码定值,Feather attrs 同构(out/design-study/07-icons.md §1.1/§1.2);Heroicons 则是描边+填充双体系,24/outline 实测 stroke-width=1.5(07 §1.3)。
