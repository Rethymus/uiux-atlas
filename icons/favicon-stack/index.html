Favicon 体系 Favicon Stack

favicon · 站点图标 · apple-touch-icon · maskable icon · web app manifest icon

现代 favicon 链的极小集:**5 图标 + 1 manifest** 覆盖所有需求,不必生成 20+ 张 PNG——ico 32×32 兜底 RSS/旧版、SVG 内嵌 prefers-color-scheme 自动换色、apple-touch 180×180 加内边距、192+512 maskable 走安全区,manifest 仅 PWA 需要。

参数
动效▾
schemelight

配色方案开关(JS 型)。icon.svg 内嵌 <style> 的 @media (prefers-color-scheme: dark) 会在系统深色模式自动把字形从 #0f0f0f 翻到 #f0f0f0(12 §12 官方片段定值);demo 以开关模拟 OS 偏好,同时把模拟浏览器 chrome 一起翻暗,还原真实观感。

maskableshow

安全区叠加层开关(JS 型):maskable 图标的 409×409 中央安全区(512 画布,比值 ≈0.8)。show 档画出虚线安全圆并给出圆形裁切预览——glyph 必须整体落在安全圆内;hide 档模拟「没标 purpose:"maskable"」的裸图,Android 启动器会按自家遮罩盲裁,四角内容随时被切。

色彩▾
accent#0f0f0f

浅色模式字形色(CSS 型)。默认 #0f0f0f = Evil Martians 片段的基础填充值;深色模式按片段翻为固定 #f0f0f0。改它等于改品牌主色——favicon 是品牌色在浏览器最小触点上的落地。

几何▾
padding20px
px

apple-touch-icon 内边距(CSS 型,180 画布上的数值)。默认 20px = Evil Martians 对 iOS 图标的建议(建议加 20px 内边距与背景色);padding=0 时 glyph 顶边,系统一旦套圆角遮罩就有裁切风险。

代码拆解

结构与 DOM

favicon 体系的全部结构都在 <head> 的四行接线里,文件本体只有 5 图标 + 1 manifest(Evil Martians 清单,12 §12):

<link rel="icon" href="/favicon.ico" sizes="32x32">
<link rel="icon" href="/icon.svg" type="image/svg+xml">
<link rel="apple-touch-icon" href="/apple-touch-icon.png">
<link rel="manifest" href="/manifest.webmanifest">

五件套分工:

  • favicon.ico 32×32,根目录:旧浏览器与 RSS 阅读器的兜底——RSS 阅读器只认 /favicon.ico 这个路径;sizes="32x32" 还顺带修 Chrome 忽略 SVG 的 bug;
  • icon.svg:现代浏览器的首选;SVG 是独立文档,可以内嵌 <style> 写 @media (prefers-color-scheme: dark) 自动换色;
  • apple-touch-icon.png 180×180:iOS 主屏;glyph 距边建议 ≥20px 并铺背景色,防系统遮罩裁切;
  • icon-192.png + icon-mask.png 512×512:后者声明 purpose:"maskable",内容落在 409×409 中央安全圆内;
  • manifest.webmanifest:仅 PWA 需要。

关键点:rel="shortcut icon" 从来不是有效写法;ico 必须在根目录;换色机制只属于 SVG 档——位图档没有媒体查询能力。

样式与参数

四个参数覆盖「换色 / 内边距 / 安全区」三条主线:

/* icon.svg 换色(演示以 scheme 开关模拟 OS 偏好;真实文件由系统偏好驱动) */
/* 浅色:glyph fill = var(--fav-accent, #0f0f0f) */
/* 深色:按 Evil Martians 片段翻为固定 #f0f0f0,浏览器 chrome 一起变暗 */

/* apple-touch 内边距:180 画布、显示 96px,同比缩放 */
.fav-touch-pad { inset: calc(var(--fav-padding, 20px) * 96 / 180); }

/* maskable 安全区:512 画布上 409×409 中央圆,比值 ≈0.8 */
.fav-safe { width: calc(96px * 409 / 512); height: calc(96px * 409 / 512); border-radius: 50%; }

数值出处(全部 12 §12 一手):

  • accent 默认 #0f0f0f、深色翻 #f0f0f0 = Evil Martians 片段定值;
  • padding 默认 20px = apple-touch-icon 的官方建议内边距;
  • 安全区 409×409(512 画布)= maskable 规范给定的中央圆;
  • apple-touch 画布 180×180、ico 32×32、maskable 512×512/192×192 均为清单定值。

动效与交互

  • scheme 切换(JS 型参数):模拟系统深色模式——icon.svg 字形在 #0f0f0f ↔ #f0f0f0 之间翻转,模拟浏览器 chrome(标签条/页面区)同步翻暗,还原「系统一切、favicon 跟着变」的真实观感;0.25s 的背景过渡在 prefers-reduced-motion: reduce 下直切;
  • staging 反色标签恒定与生产相反(浅色模式亮 glyph 暗底、深色模式反之)——Evil Martians 的环境防混淆彩蛋;
  • padding 拖动(CSS 变量):apple-touch 面板内的虚线框随之缩放,低于 12px 给出裁切风险警告(建议值 20px);
  • maskable 开关(JS 型):512 画布上叠加/移除 409×409 虚线安全圆,右侧圆形裁切预览的说明在「已标 maskable / 裸图盲裁」之间切换;
  • 标签条与面板均为纯展示结构,无嵌套交互控件。

真实产品案例

  • Evil Martians 官网实践:《How to Favicon in 2024》作者 Andrey Sitnik 给出的 5+1 清单本身就运行在 evilmartians.com 上——文章同时给出 staging 反色 favicon 的环境切换实践(12 §12);
  • Chrome 的 SVG favicon bug:sizes="32x32" 修 Chrome 忽略 type="image/svg+xml" 图标的问题,是清单里「一行属性修一个浏览器缺陷」的真实案例(12 §12);
  • RSS 客户端的路径硬约束:RSS 阅读器类客户端只请求根目录 /favicon.ico,不解析 <head>——这是 ico 必须留在根目录的真实原因(12 §12)。

参数敏感度

参数调大会…调小会…
schemedark 档字形翻 #f0f0f0、chrome 变暗——深色系统用户的真实观感,对比度反而更好light 档是默认态;深色 chrome 下黑 glyph 会融进背景,这正是内嵌媒体查询存在的理由
accent改品牌主色;apple-touch 面板的背景与 maskable 面板的底色同步跟随亮色 accent 在浅色 chrome 里对比度下降,深色档的固定 #f0f0f0 不受影响
padding>20px 图标在 iOS 主屏上显得空;安全但浪费画面<12px 触发裁切警告;0 时 glyph 顶边,系统遮罩一裁就破相
maskableshow 档安全圆可见,设计有明确边界hide 档退回「没标 purpose:“maskable”」的裸图——各启动器遮罩盲裁,四角内容随时被切

锚点:四行接线 + 五件套是极小集,不多生成也不漏兜底;换色只属于 SVG 档;apple-touch 留 20px;padding 之外的 maskable 内容一律住进 409×409 圆。

适用场景 4
  • 任何新站点/新品牌:一次配齐 5 图标 + 1 manifest,从此不再生成 20+ 张 PNG(Evil Martians 主张)
  • 深浅双主题品牌:icon.svg 内嵌 prefers-color-scheme,系统切深色时 favicon 自动反色(12 §12 片段)
  • 多环境部署:staging 环境用反色 favicon,一眼分辨测试站与生产站(Evil Martians 彩蛋)
  • PWA/可安装应用:512×512 maskable(purpose:"maskable")+ 192 常规,glyph 落在 409×409 安全区内
何时不要用 4
  • 给全平台手打 20+ 张尺寸 PNG——现代链路用 5+1 就够,旧尺寸由 ico 兜底
  • 写 rel="shortcut icon"——从来不是有效 rel 值,现代浏览器只认 rel="icon"(12 §12)
  • apple-touch-icon 顶边贴满:不带 20px 内边距与背景色,iOS 遮罩一裁就破相(12 §12 建议)
  • maskable 图标把关键内容画进四角:Android 启动器遮罩各异,只有 409×409 中央圆是承诺安全区(12 §12)
无障碍

favicon 无障碍常被忽略的三点:①icon.svg 的暗色适配同时惠及深色模式用户与低视力用户——#f0f0f0 字形配深色 chrome 的对比度远好于黑 glyph 融进暗背景;②favicon 本身是装饰性图形,信息不应只由 favicon 传递(读屏器默认不播报站点图标);③staging 反色属于「用颜色区分环境」,务必同时配域名/横幅等非颜色通道,色弱用户不靠 hue 也能分辨(WCAG 1.4.1 颜色不是唯一手段的精神)。

浏览器支持

<link rel="icon" type="image/svg+xml"> 现代浏览器均支持(12 §12);favicon.ico 为旧浏览器与 RSS 阅读器的兜底(根目录 32×32);maskable 语义由支持 Web App Manifest 的 Android 启动器消费。SVG 内嵌 <style> 的媒体查询在 <img>/favicon 上下文同样生效(SVG 独立文档),系统深色模式即触发。 · widely available

兼容回退

兜底链就是体系本身:现代浏览器取 icon.svg,旧浏览器/RSS 回落根目录 favicon.ico(32×32),iOS 取 apple-touch-icon.png(180×180),Android PWA 取 192/512 maskable。任何一档缺失都有下一档接管——这正是「5+1」清单的排序逻辑;缺 ico 时 RSS 阅读器等只认 /favicon.ico 路径的客户端会拿不到图标。
