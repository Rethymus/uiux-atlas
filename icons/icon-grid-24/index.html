24px 图标栅格 24px Icon Grid

图标栅格 · 键程 · Keyline Shapes · Icon Grid · Live Area

24×24 是全行业共同祖先网格:展示区 24dp、活动区 20dp(四周 2dp padding)、方形键程 18×18、圆形键程 Ø20;栅格与安全区参考线实时可视化。

gridSize24

绘制网格边长。24 = 官方基准:Material 展示区 24dp、Feather/Lucide/Heroicons 同规格(07 §0/§2);20 = Material 密集布局官方档("measurements may be scaled down to 20dp",活动区缩至 16×16),也是 Heroicons mini 的独立重绘网格(07 §1.3/§2);16 = Heroicons micro 独立重绘网格(实测 viewBox,07 §1.3);32 = 常见的放大倍增网格,官方无锚值(社区常见,未证实)。官方做法是「换尺寸档独立重绘」而非等比缩放(07 §3.1);demo 对非 24 档按 24 基准等比推导键程,仅供参考。

活动区内边距(px,逐格整数步进以保持像素对齐)。官方定值 2:"Icon content is limited to the 20dp x 20dp live area, with 2dp of padding around the perimeter"(07 §2)。调到 0 时活动区吃满修剪区,内容会顶到画布边缘;官方补充:需要更强视觉重量时,内容可伸入 live area 与 trim area 之间的 padding,但绝不可出修剪区(07 §2)。

代码拆解

结构与 DOM

24px 图标栅格是一张创作期底图:画布 24×24(修剪区 trim area),内容限制在活动区(live area),四条官方键程负责视觉重量。demo 用一张 SVG 同时画网格、活动区与键程参考线,示例图形叠加其上:

<svg viewBox="0 0 24 24" width="192" height="192">
  <!-- 网格线(设计期参考,交付时删除) -->
  <g stroke="#94a3b8" stroke-width="0.125">
    <line x1="1" y1="0" x2="1" y2="24" /> <!-- …每 1 单位一条 -->
  </g>
  <!-- 活动区:24-2×2 = 20×20 -->
  <rect x="2" y="2" width="20" height="20" fill="none"
        stroke="#2563eb" stroke-dasharray="0.375 0.25"/>
  <!-- 键程:方形 18×18 / 圆形 Ø20 / 长方 20×16 与 16×20 -->
  <rect x="3" y="3" width="18" height="18" fill="none" stroke="#ea580c"/>
  <circle cx="12" cy="12" r="10" fill="none" stroke="#16a34a"/>
  <!-- 图形本体 -->
  <path d="…" fill="none" stroke="#0f172a" stroke-width="2"/>
</svg>

关键点:

  • 参考线是设计期工具,交付 SVG 只含图形本体;
  • demo 以 8 倍整数缩放渲染(1 单位 = 8px),0.125 单位描边恰好渲染 1px 细线;
  • 示例「图片」图标是 24 网格原稿,切换网格档时按 scale(gridSize/24) 等比缩放示意——官方做法是换档独立重绘,缩放演示仅用于对照(见下文)。

样式与参数

两个参数均为 JS 型(几何重算),demo 内换算关系如下:

live  = gridSize − 2×padding        // 24 档官方:24 − 4 = 20
square = live − 2                    // 方形键程:20 − 2 = 18(官方)
circle = live                        // 圆形键程:Ø20(官方)
landscape = live × (live − 4)        // 横长方:20 × 16(官方)
portrait  = (live − 4) × live        // 竖长方:16 × 20(官方)

数值出处(m2.material.io system-icons,调研 07 §2 逐条原文):

  • 展示区 24×24 dp;密集布局缩至 20dp;
  • 活动区 20×20 dp,四周 2dp padding;密集活动区 16×16;
  • 键程:方形 18×18、圆形 直径 20、竖长方 16×20、横长方 20×16;
  • X/Y 必须整数(“on pixel”);圆角默认 2dp,≤2dp 宽的形状转角不倒圆;
  • 内容可伸入 padding 换视觉重量,绝不可出修剪区。

官方模板源文件:官方栅格模板 AI(Apache 2.0,07 §2)。

动效与交互

栅格是静态底图,demo 的交互只在参数切换上:

  • gridSize 切换:SVG viewBox 重算,画布 16/20/24/32 档全部按 8px/单位渲染——视觉尺寸随档位放大,展示「换尺寸档」与「等比缩放」的区别;
  • padding 拖动:活动区蓝色虚线实时重排,padding 走廊(画布浅灰底)直观呈现;调到 0 时活动区吃满修剪区;
  • 参考线与图例均标 aria-hidden / 供验收;读数行 aria-live="polite" 播报当前键程值;
  • 无动效依赖,prefers-reduced-motion 无需降级。

真实产品案例

  • Material 官方键程模板:m2.material.io system-icons 定义了上表全部数值,并提供官方栅格模板 AI 源文件下载(Apache 2.0)——「圆比方大 2dp」是写进官方规范的硬数值,不是视觉玄学(07 §2/§3.1);
  • Heroicons 三档独立重绘:24 / 20 / 16 三档各有独立 viewBox(仓库真实文件实测),官方路线是「换档重画」而非缩放 24 图(07 §1.3);
  • Material Symbols 的像素对齐边界:opsz 轴默认 24,且仅 20px 与 24px 版本做了完美像素栅格对齐——连 Google 也只在两档上守住整数坐标(07 §1.5)。

参数敏感度

参数调大会…调小会…
gridSize32 档键程全部放大(推导值),细节余量更多;但无官方锚值,跨集对齐失效16 档笔画间距骤减——Lucide 要求相邻元素间隙 ≥2px、镂空塞得进 2px 圆,小网格更难满足(07 §3.2)
padding走廊收窄(0-2),图形顶到画布边,呼吸感消失;官方允许内容伸入 padding 换重量但不可出修剪区padding=2 是官方默认;再往上(3-4)活动区骤缩,方形键程被压到 live−2 以下,图标显小

锚点:24 档 + padding 2 = 官方基准;20 档 + padding 2 = 密集布局官方值(活动区 16);其余组合是推导演示,交付前按官方路线独立重绘。

适用场景 3
  • 自绘/评审图标时的验收底图:方形 18×18、圆形 Ø20、长方 20×16/16×20 四条键程逐一比对(07 §2)
  • 为桌面密集布局准备 20px 档位:展示区 20、活动区 16、padding 仍为 2(07 §2)
  • 跨图标集核对视觉重量:各家共用 24 祖先网格,键程铁律「圆比方大 2dp」是官方数值不是玄学(07 §3.1)
何时不要用 3
  • 把 24 网格图标等比硬缩到 16px 交付——官方做法是换档独立重绘(Heroicons 20/16 实测独立 viewBox,07 §1.3/§3.1)
  • 内容出修剪区,或坐标出现小数——官方要求 X/Y 必须整数(「on pixel」,07 §2)
  • padding 调到 0 还想保住呼吸感——活动区吃满后图标之间会视觉粘连
无障碍

栅格与可访问性间接相关:安全的活动区保证笔画间距,而 Lucide 规范要求相邻独立元素间隙 ≥2px、镂空里塞得进一个 2px 圆(07 §3.2)——间距过小会让小尺寸渲染糊成一片;参考线本身是装饰,交付物中不得出现(或标 aria-hidden)。

浏览器支持

栅格与键程是设计期概念,交付物是普通 SVG(viewBox 缩放),全主流浏览器一致渲染;demo 的参考线用 0.125 单位描边在 8 倍整数缩放下保持 1px 细线,无浏览器兼容问题。 · widely available

兼容回退

无回退需求:栅格是创作规范而非运行时特性;验收时把参考线 SVG 关掉、只留图形本身,即得到真实交付形态。
