峰终定律 Peak-End Rule

峰终法则 · Peak-End

人对一段体验的记忆主要由「峰值时刻」与「结尾感受」决定,而非全程平均。重点设计强度最高与收尾的时刻;负面峰值要专门消除。

社区流派 ★★★
实例演示 官方默认
参数
几何▾
peak8级
级

旅程峰值时刻的体验强度(demo 构造的 8 段旅程第 3 段)。峰终定律的记忆评估按「峰值+结尾」主导;demo 用教科书化简公式 (峰值+结尾)/2 作为记忆预测,与全程平均对比。

ending2级
级

旅程结尾时刻的体验强度(第 8 段)。默认 2 是「烂尾」旅程:峰值 8 的精彩被结尾 2 拖累,记忆预测只有 5——把 ending 拉到 9,看记忆预测怎么翻上去。

动效▾
presetcliff

旅程预设(写入 peak/ending 两个参数)。cliff=烂尾(8/2);smooth=平顺(5/4);finale=惊喜收尾(6/9,Mailchimp 发送成功动画的思路,07§25);custom=保持当前滑块值。

结构与 DOM

演示是一段8 时刻的体验旅程曲线(内联 SVG)+ 两根对比条:

<svg viewBox="0 0 380 190">
  <path class="pe-area" d="…" />
  <path class="pe-curve" d="M26,150 L81,133 …" />
  <circle class="pe-dot-peak" cx="81" cy="87" r="6" />  <!-- 第 3 时刻 = 峰 -->
  <circle class="pe-dot-end"  cx="354" cy="150" r="6" /> <!-- 第 8 时刻 = 终 -->
</svg>

关键点:

  • 曲线 8 个点由固定基线生成,只有**第 3 点(峰)与第 8 点(终)**被参数覆写——「其余时刻不动」本身就是定律的表达:中间过程的改动对记忆影响最小;
  • 结论不走读图:全程平均与峰终预测两组数值同时以条形+文本呈现;
  • 预设按钮直接 store.set("peak"/"ending", …)——参数面板的滑块随之联动,演示与面板共享同一 store。

样式与参数

// peak / ending 是 JS 型参数;preset 点击时反向写入 store
const journey = BASE.map((v, i) => (i === 2 ? peak : i === 7 ? ending : v));
const avg = journey.reduce((a, b) => a + b, 0) / journey.length;
const peakEnd = (peak + ending) / 2;
  • peak 默认 8、ending 默认 2(=「烂尾」预设):一段高开低走的旅程,记忆预测只有 5.0,而全程平均 4.4——两者的差距就是定律的可见度;
  • (峰值+结尾)/2 是教科书化简,不是 Kahneman 1993 原始实验公式——面板与 schema 都按此口径如实标注;
  • 三种预设:烂尾(8/2)、平顺(5/4)、惊喜收尾(6/9)——6/9 的记忆预测 7.5 高于其全程平均 5.0,正是「结尾投资回报率最高」的量化演示。

动效与交互

  • 拖动参数时曲线用 transition: d 0.3s ease 平滑重排(d 作为 CSS 属性可过渡,不支持时退化为直接跳变,无兼容风险);两根对比条宽度同步 0.3s 过渡;
  • prefers-reduced-motion: reduce 下两处过渡全部取消,数值即时更新;
  • 预设按钮无动画,点击即写 store——「惊喜收尾」按钮本身不投惊喜,惊喜留给真实产品的峰值时刻。

真实产品案例

  • Mailchimp 发送成功动画:点击发送后的 High-five 小拳拳动画——把「终」做成整段旅程的记忆锚点,是 lawsofux/NN/g 反复引用的峰值收尾案例(调研 07§25);
  • Uber 的时间感知设计:调研 07§25 记载 Uber 用时间感知(精确到分钟的 ETA、行程进度可视化)降低取消率——把「等待」这个负面峰值专门拆掉;
  • NN/g 的收尾清单:Lexie Kane 的 The Peak–End Rule 文章建议专门设计旅程的收尾时刻——提交成功页、任务完成态、退出确认都值得独立打磨,而不是「顺手带过」(调研 07§25 相关阅读)。

参数敏感度

参数调大会…调小会…
peak峰终预测线性上升;但峰从 8→10 的记忆增益,远小于终从 2→9 的增益(两条参数同权重)峰平庸后,旅程只剩「平稳」,记忆预测贴近全程平均
ending6/9 预设下预测 7.5——同样强度的投入,投在结尾的记忆回报最高烂尾:峰值再高也被结尾拖住,这正是默认值 8/2 想让人看见的
preset一键写入 peak/ending,滑块联动——方便复现三种典型旅程custom:保持手动值,预设不再覆盖

经验结论:资源有限时优先投结尾,其次投峰值,中间过程「不烂即可」;负面峰值(等待、报错)的消除优先级高于正面峰值的堆砌——负面的记得更牢(调研 07§25)。

适用场景 3
  • 表单提交成功页、任务完成态——值得单独打磨的「终」
  • 在最有价值的时刻投放惊喜(Mailchimp 发送成功动画,07§25)
  • 消除负面峰值:等待、报错、排队处专门做时间感知设计(Uber 案例,07§25)
何时不要用 2
  • 把资源平均撒在全程,峰值与收尾反而潦草
  • 在收尾插入打断(强制问卷、广告)制造负面终值
无障碍

曲线信息必须双通道:SVG 曲线之外,峰值/结尾/平均/记忆预测四组数值都以文本呈现(演示面板),不依赖颜色或形状传达结论;动画克制,尊重 prefers-reduced-motion。

浏览器支持

演示用内联 SVG 绘制体验曲线,全现代浏览器可用。

兼容回退

定律的工程出口:在旅程的两个时刻上做确定性设计——「强度最高处」(达成、揭晓、意外之喜)与「收尾处」(提交成功页、任务完成态、退出确认)。没有可降级的 CSS 特性;若旅程数据缺失,降级方案是至少保证「结尾不烂」。

来源 1

起源Kahneman 等人 1993 年冷水实验:被试对整段经历的记忆评估主要取决于峰值与结尾感受,而非时长或平均(Jon Yablonski,Laws of UX;调研 07§25)。相关 NN/g 文章:The Peak–End Rule: How Impressions Become Memories(Lexie Kane)。

  1. 条目 帕累托法则

    搭配:峰终的「优先投结尾」与 80/20 的「预算集中头部」是同一个资源分配问题的两个坐标——先用数据找到头部,再按记忆权重投放。

  2. 条目 Doherty 阈值

    反向自「Doherty 阈值」的精选:搭配关系,原句「>10s 的等待给完进度还要给「完成后的收尾」——峰终定律正是那条收尾法则:提交成功页与任务完成态值得独立打磨,不顺手带过。」

  3. 条目 目标梯度效应

    反向自「目标梯度效应」的精选:搭配关系,原句「达标瞬间的一次性庆祝与「再来一轮」就是终点投资:梯度定律管越近越快,峰终定律管终点记忆——收尾段的投入两个定律都背书。」
