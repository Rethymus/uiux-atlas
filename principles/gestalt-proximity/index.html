格式塔·接近性 Law of Proximity

邻近原则 · 接近原则

相邻的元素被感知为一组:间距本身就是分组语法。组内间距小、组间间距大,关系不用一条线就成立。

社区流派 ★★★
实例演示 官方默认
参数
几何▾
gap36px
px

组与组之间的间距。默认 36px 对三组×4 元素的布局已明显大于组内;调到与组内间距相等时,分组感知崩解——「间距差」才是分组信号,不是绝对值。

inner10px
px

组内元素间距。默认 10px:与 36px 组间形成约 1:3.6 的对比;把 inner 拉大到接近 gap,三组会退化成 12 个散点。

动效▾
layoutgrouped

JS 型参数(demo 订阅后切换布局)。uniform=所有间隙统一(对照组):同样的 12 个元素,没有任何分组感知——接近性的「阴性对照」。

代码拆解

结构与 DOM

演示是 12 个元素排成的 3 组 × 4 阵列,组间与组内用两级间距:

<div class="gp-board"> <!-- gap: var(--gp-gap) -->
  <div class="gp-group"> <!-- gap: var(--gp-inner) -->
    <span class="gp-cell">1</span>
    <span class="gp-cell">2</span>
    <span class="gp-cell">3</span>
    <span class="gp-cell">4</span>
  </div>
  <!-- ×3 组 -->
</div>

关键点:

  • 没有任何容器边框或背景——分组感知完全由两级间距差产生,这正是接近性原则要隔离的单一变量;
  • uniform 对照组:同一批元素、同一种间距——分组的消失证明了「间距差」才是信号;
  • 组与组用 flex + gap 两级嵌套实现,间距变化即改 CSS 变量,DOM 不动。

样式与参数

.demo-stage {
  --gp-gap: 36px;   /* 组间 */
  --gp-inner: 10px; /* 组内 */
}
.gp-board { display: flex; gap: var(--gp-gap); }
.gp-group { display: flex; gap: var(--gp-inner); }
  • gap 默认 36px、inner 默认 10px(比值 3.6:1)——demo 教学几何,非定律数值;格式塔原则本身是定性描述,调研 07§31 未给数值;
  • 判定口径(demo 自定):gap ≥ 2 × inner 记「分组感知成立」,否则记「崩解」——教学近似;
  • layout 是 JS 型参数:uniform 把所有间隙统一成 inner,做阴性对照。

动效与交互

  • 拖动两个滑块时间距以 0.2s gap 过渡平滑变化(gap 属性可过渡);prefers-reduced-motion 下取消过渡;
  • 读数面板实时显示当前比值与「成立/崩解」判定;
  • 窄屏(≤480px)阵列转为纵向排列,两级间距结构保持不变。

真实产品案例

  • 表单的字段分组:地址三行靠在一起、与「支付方式」之间留大空白——主流电商结账页通行的「纯间距分组」,不加任何线框(07§31 指导「表单字段分组」的泛化,调研未点名单一产品);
  • 搜索结果簇:每条结果内部(标题/摘要/链接)紧凑,条目与条目之间疏朗——搜索引擎与列表页靠间距就能让「一簇 = 一条结果」(07§31 指导「搜索结果簇」的泛化);
  • 共同区域的分工:当一组元素需要「强绑定」语义(如一张卡的按钮群),业界通行做法是叠加边框/背景(格式塔·共同区域原则,07§32)——间距负责轻分组,容器负责重分组。

参数敏感度

参数调大会…调小会…
gap组间越拉越开,分组感知更强;超过 ~60px 后三组像三张「看不见的卡片」,再增无益与 inner 接近时分组崩解——12 个散点,间距差信号的消亡实验
inner调到接近 gap 时同样崩解;组内过松还会把「4 个元素」读成「4 个小组」组内越紧,「一块」的感觉越强;过紧(<4px)则互相粘连
layoutuniform 是阴性对照:间距差归零,分组感知归零grouped 恢复两级结构

经验区间:组间:组内 ≥ 2:1 是分组可辨的教学下限,实际产品常见 3–4:1;记住工程红线——强绑定分组不要只靠间距,叠加共同区域与语义分组(fieldset/列表)才是完整答案。

适用场景 3
  • 表单字段分组:相关字段靠近,组间留白
  • 列表与搜索结果簇:条目内紧凑、条目间疏朗
  • 卡片内元素层级:标题-正文-操作靠间距分层
何时不要用 2
  • 全部等距的「均匀网格」承载本该分组的对象
  • 只用间距表达强绑定操作(如批量删除组),不加容器或语义分组
无障碍

视觉分组必须同时是语义分组:字段组用 fieldset/legend,相关列表用列表元素——读屏用户没有「间距」可感知(WCAG SC 1.3.1 信息与关系)。间距只服务视觉通道,语义通道要另行送达。

浏览器支持

纯 CSS flex/grid 间距,全现代浏览器可用。

兼容回退

间距没有兼容性问题,工程红线是:分组信号不能只靠间距单通道——高风险分组(如「同时删除这组」)要叠加共同区域(边框/背景,见格式塔·共同区域原则)与语义分组(fieldset/列表,SC 1.3.1)。窄屏空间不足时优先保住「组间 > 组内」的差,必要时压缩绝对值。

来源 1

起源格式塔心理学分组原则之一:相邻元素被感知为一组(Jon Yablonski,Laws of UX;调研 07§31)。调研 07§31 同时列出格式塔分组五类:Proximity、Similarity、Continuity、Closure、Connectedness;指导:用间距建立元素间关系(表单字段分组、列表条目间距、搜索结果簇),邻近帮助用户更快理解与组织信息。

  1. 条目 格式塔·相似与闭合

    对比:格式塔分组两条线索易混:接近性靠间距差(空间线索),相似性靠颜色/形状标记(特征线索)——两页的红线都是别让语义只活在视觉通道里。

  2. 条目 WCAG 快速清单

    搭配:间距分组要有语义兜底:清单「可感知」组的 1.3.1(信息关系)要求分组进结构而非只靠视觉——间距是轻分组,fieldset 才是完整答案。

  3. 条目 Miller 7±2 法则

    反向自「Miller 7±2 法则」的精选:搭配关系,原句「分块(chunking)的组界就画在间距上:电话号 3–4 位一组与两级间距的分组感知是同一招——数字分块靠间距,强绑定才上容器。」
