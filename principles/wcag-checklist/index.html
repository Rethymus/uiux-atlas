WCAG 快速清单 WCAG Quick Checklist

WCAG 2 清单 · 无障碍检查清单 · POUR

按 POUR 四原则(可感知/可操作/可理解/健壮)组织的 WCAG 2.2 速查清单:交付前按一致性等级(A/AA/AAA)逐条核对。

Web 标准 ★★
实例演示 官方默认
参数
动效▾
levelAA

显示「≤ 所选等级」的全部条目(AA 档 = A+AA;一致性是累进的)。22 条速查覆盖 POUR 四原则,SC 编号与等级为 WCAG 2.2 官方事实。

代码拆解

结构与 DOM

演示是按 POUR 四原则分组的速查清单:22 条常用 SC(fieldset/legend 分组)+ 等级过滤 + 进度 meter:

<fieldset class="wc-group">
  <legend>可感知 Perceivable</legend>
  <label class="wc-item">
    <input type="checkbox" />
    <span><b>1.4.3</b> <i>AA</i> 对比度(最低):文本 ≥ 4.5:1</span>
  </label>
  <!-- … -->
</fieldset>

关键点:

  • 每条保留 SC 编号 + 等级徽章(A/AA/AAA 三色)——可回溯 W3C 官方 Understanding 文档;
  • 过滤语义是「≤ 所选等级」:一致性累进,达标 AA 自动包含全部 A 条目;
  • 勾选框原生 <input type="checkbox">——清单本身就用最高优先级的方式可键盘操作(2.1.1),这是元层面的示范。

样式与参数

const order: Level[] = ["A", "AA", "AAA"];
const visible = ITEMS.filter((it) => order.indexOf(it.level) <= order.indexOf(level));
  • level 默认 AA(绝大多数产品的合规目标);22 条覆盖 POUR:
    • 可感知 8 条(1.1.1、1.3.1、1.4.1、1.4.3 4.5:1、1.4.10 重排 320px、1.4.11 3:1、1.4.12 文本间距 2×/1.5×/0.16×/0.12×、1.4.6 7:1);
    • 可操作 7 条(2.1.1、2.1.2 无键盘陷阱、2.2.1、2.4.1 skip link、2.4.7 焦点可见、2.5.8 目标 ≥24×24 CSS px、2.1.3);
    • 可理解 5 条(3.1.1、3.2.1、3.3.1、3.3.2、3.3.3);
    • 健壮 2 条(4.1.2、4.1.3);
  • SC 编号、等级与阈值(4.5:1 / 3:1 / 7:1 / 24px / 320px / 0.12–2 倍字号间距)为 WCAG 2.2 官方事实;其中对比度与文本间距数值已在调研 05/07 中对照官方原文核验。

动效与交互

  • 勾选即时计入进度 meter(附 n/22 文本,双通道);
  • 切换 level 时清单条目增减——已勾选状态按 SC 编号保留(升等级不清空);
  • 无动画;清单是工作工具,瞬时反馈优于过渡。

真实产品案例

  • WebAIM WCAG 2 Checklist:调研引用的官方参照站——按 POUR 分组、支持按 WCAG 版本(2.0/2.1/2.2)与等级(A/AA/AAA)过滤,本条目的分组与过滤逻辑与其同构;
  • WCAG 2.2 的 2.5.8 目标尺寸(最低):WCAG 2.2(2022-10 定稿)新增 AA 条目,给指针目标设 24×24 CSS px 法定下限——fitts-law 条目的 48px 是更宽松的生产参照,两者一软一硬互为补充;
  • CI 无障碍流水线:业界通行做法是 axe-core 类自动化 + 人工走查结合——自动化可捕获约 30–50% 的常见问题(颜色对比、缺失 alt、重复 id),其余(替代文本是否恰当、焦点顺序是否合理)必须按清单人工核对(编辑性泛例)。

参数敏感度

参数调大会…调小会…
levelAAA:22 条全显,含 7:1 增强对比与无例外键盘——注意 WCAG 官方明确 AAA 不要求全站达标A:12 条最低底线,适合快速体检;AA 是常见合规目标

经验结论:清单的价值在流程位次——设计期问 1.4.3/1.4.11(对比),开发期问 2.1.x/4.1.2(键盘与语义),交付期全量走查;只在上线上跑一次自动化,等于把 22 条缩成 5 条。

适用场景 3
  • 交付前走查:按所选等级逐条核对并记录证据
  • 新组件评审:对照 SC 2.1.1/2.1.2/4.1.2 先问键盘与语义
  • 写验收标准:把「4.5:1 / 焦点可见 / Esc 释放」写进 DoD
何时不要用 2
  • 把「AAA」当成必须全达标的目标——WCAG 官方明确 AAA 不是全站要求
  • 只在上线前跑一次自动化就宣布合规(自动化查不全)
无障碍

清单本身就是 a11y 主题:勾选框真实可操作、分组用 fieldset+legend、进度用 meter;条目文案保留 SC 编号便于回溯官方 Understanding 文档。

浏览器支持

纯 DOM 交互;进度用 meter 语义呈现。

兼容回退

清单是流程工具,无特性降级;工程出口是把「勾选」变成流水线:CI 里跑 axe-core 类自动化(可查出约 30–50% 的常见问题),剩余靠人工按本清单走查(自动化无法判定替代文本是否恰当)。

来源 2

起源W3C WCAG 2.2 官方规范与 WebAIM WCAG 2 Checklist(按 POUR 分组、支持按 WCAG 版本与 A/AA/AAA 等级过滤);调研 07§36 引 WebAIM 键盘页(SC 2.1.2 无键盘陷阱属 Level A),对比度数值 4.5:1 / 3:1 与文本间距数值在调研 05§(WCAG 官方原文一手核对)。

下一步学什么

按依据排序:本条目精选 > 路径下一站 > 反向推导 > 路径与配方归属

  1. 条目 对比度偏好适配

    搭配:清单里的对比度条目(1.4.3 的 4.5:1)管下限,prefers-contrast 管用户主动要的增强——法定阈值与偏好查询在焦点环/分隔线/禁用态三件套上会合。

  2. 条目 键盘导航全景

    路径「无障碍必修」的下一站:第一硬依赖:键盘先行是行为层无障碍的地基——纯键盘完成核心任务,焦点永远可见。

  3. 条目 审美可用性效应

    反向自「审美可用性效应」的精选:搭配关系,原句「审美可用性效应要在测试规程里设防:首轮可用性测试用未抛光稿,好评不能替代 1.4.3 的 4.5:1 对比度法定线——美观不再能掩盖问题。」
