Hick 定律 Hick's Law

希克定律 · Hick-Hyman Law · 希克-海曼定律

决策时间随选项数量与复杂度上升:备选越多,选得越慢。响应时间关键处要减选项、拆步骤、突出推荐项。

每轮实验的候选目标数 N。Hick-Hyman 定律:反应时随 N 对数上升(RT = a + b·log₂(N));把 N 从 2 拉到 8,在统计表里对比同 N 的中位反应时,能直接看出「选项翻倍、决策变慢」。

pause800ms
ms

命中后到下一轮高亮出现的间隔(demo 节奏参数,非定律结论)。太短会让上一轮的决策时间混入下一轮,太长则拖垮实验节奏。

结构与 DOM

演示是一个选择反应时实验:N 个候选目标按钮排成圆环,每轮随机高亮一个,测量「高亮出现 → 点击命中」的时间:

<div class="hk-ring">
  <button class="hk-target" data-active="false">1</button>
  <button class="hk-target" data-active="true">2</button>
  <!-- N 个 -->
</div>

关键点:

  • N 由参数 choices 控制(2–8),改参数即重排;被高亮的目标用 3px 绿描边 + 「点我 Hit」标签双通道标记,不只靠颜色(SC 1.4.1);
  • 误点不结束当前轮——错误计数与计时并存,「决策慢」与「决策错」是两个数据;
  • 统计表按 N 分组记中位反应时与样本数,跨 N 对比就在右侧面板里完成。

样式与参数

// choices / pause 是 JS 型参数:demo 订阅 store 驱动
const [choices, setChoices] = useState(() => store.get("choices") as number);
useEffect(() => store.subscribe(() => {
  setChoices(store.get("choices") as number);
  setPause(store.get("pause") as number);
}), [store]);
  • choices 默认 4:demo 教学起点,而非定律结论;Hick-Hyman 定律的经典形式 RT = a + b·log₂(N)(Hick & Hyman 1952),demo 让你亲手测出自己的 a、b;
  • pause 默认 800ms:两轮间隔,是 demo 节奏参数(调太短会把上一轮的犹豫混进下一轮的计时);
  • 高亮标记:3px 描边 + 文字标签——「点我」提示同时服务读屏(按钮文本语义不变,仍是数字)。

动效与交互

  • 每轮:高亮出现(opacity 0.45→1 + 描边切换,0.12s)即开始计时;命中 → 高亮熄灭,pause 毫秒后下一轮;
  • 误点:错误 +1,高亮保持、计时继续——不惩罚、不打断,让数据自己说话;
  • 改 choices 立即按新 N 重排圆环(改 N 会结束当前轮,点任意目标重新开始);
  • 无循环动画,无 reduced-motion 需求;所有目标均为真实按钮,可 Tab 逐一聚焦(键位惯例见 keyboard-navigation 条目)。

真实产品案例

  • Google 首页:lawsofux 举的第一例——把输入一个关键词所需的决策压到最少,移除一切可能分心或要求额外决策的内容,是「响应时间关键处减选项」的极致版;
  • Apple TV 遥控器:lawsofux 第二例——遥控器本身只承载极少的按键,把复杂度转嫁给电视界面,信息在菜单里被组织并渐进披露;
  • Slack 渐进式 onboarding:调研 07§23 的原例——新手进来只保留消息输入框,先跟着 Slackbot 学会发消息,再逐步解锁其余功能,避免「一进来就被全功能淹没」。

参数敏感度

参数调大会…调小会…
choices决策变慢:中位 RT 随 N 对数上升,「N=8 的中位 − N=2 的中位」就是你的 b·log₂ 差值决策加快;N=2 是纯简单反应时(几乎只剩 a)
pause两轮间隔拉长,实验节奏变慢,统计积累变缓低于 ~400ms 时上一轮决策时间可能混入下一轮,样本变脏

经验区间:教学对比用 N=2 对 N=8;单 N 样本 ≥5 个再读中位数;记住定律的反面告诫——不要简化到失真(be careful not to simplify to the point of abstraction),减的是决策成本,不是功能。

适用场景 4
  • 响应时间关键处(支付、抢购、紧急操作)收窄选项
  • 把复杂任务拆成小步(向导式表单),逐步揭示
  • 突出推荐选项,避免用户在平权列表中淹没
  • 对新用户做渐进式 onboarding(Slack 案例,07§23)
何时不要用 2
  • 为减而减,简化到失真(lawsofux 原文告诫:be careful not to simplify to the point of abstraction)
  • 在平权长列表上不做任何分组/推荐,把决策全推给用户
无障碍

减少视觉选项不等于减少可达功能:被「渐进披露」藏起的功能必须仍可经键盘/读屏到达(结构见 keyboard-navigation 条目)。高亮目标不能只靠颜色区分(对比 WCAG SC 1.4.1);演示中目标同时用描边+文字标记。

浏览器支持

演示用 performance.now() 计时与 rAF/timeout 调度,全现代浏览器可用;performance 计时精度受浏览器凑扰保护(通常 ~1ms 量化),对百毫秒级行为测量足够。

兼容回退

定律不可降级,其 UI 结论有三条工程出口:关键路径收窄选项;复杂表单拆步(向导/分步);把「推荐项」视觉前置以免用户在平权列表里漂移。全都必须保留全部功能——减的是决策成本,不是能力。

来源 1

起源1952 年英国心理学家 William Edmund Hick 与美国心理学家 Ray Hyman 用实验考察「刺激数量与反应时的关系」,得到 Hick-Hyman 定律:选择越多,决策越慢(Jon Yablonski,Laws of UX;调研 07§23)。经典量化形式为 RT = a + b·log₂(N)。

  1. 条目 Miller 7±2 法则

    搭配:减选项(RT = a + b·log₂N)与分组块(7±2)是同一次「减负荷」的两面;两条定律还共享同一条反面告诫——不要简化到失真、别拿七当借口。

  2. 条目 Fitts 定律

    搭配:一次点击耗时 = 决策段(Hick 的 a + b·log₂N)+ 运动段(Fitts 的 ID 指数)——两个反应时实验在同一颗目标按钮上相加。

  3. 条目 帕累托法则

    反向自「帕累托法则」的精选:对比关系,原句「两条「减法」定律易混:80/20 减的是投入面(预算集中头部),Hick 减的是决策面(选项数进 log₂N);本页还点名警告「只顾减少点击次数」的机械套用。」
