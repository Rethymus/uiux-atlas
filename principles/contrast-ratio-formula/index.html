对比度比值公式 Contrast Ratio Formula

WCAG relative luminance · relative luminance · 4.5:1 · contrast ratio

WCAG 2.1 对比度的完整推导:8bit→[0,1]→γ 解码→0.2126R+0.7152G+0.0722B 相对亮度→(L1+0.05)/(L2+0.05)——demo 输入两色实时算比值并按 AA/AAA 阈值判定。

参数
色彩▾
fg#767676

前景色(文字)。默认 #767676 是经典 AA 临界灰——对白底实跑 4.5422:1,恰好过 4.5:1 线;再浅一档 (#8a8a8a ≈ 3.5:1) 就只有大字能过。

bg#ffffff

背景色。demo 用两色各自算 L 后按 (L1+0.05)/(L2+0.05) 取较大在分子——谁亮谁是 L1,公式对明暗两种极性对称。

代码拆解

结构与 DOM

demo 是一台实时对比度计算器:面板的两枚色票(fg/bg)就是输入,舞台中央用真实颜色渲染一个「Aa」字样,旁边逐行展开公式的每一步:

<div class="cr-card" style="--cr-fg:#767676; --cr-bg:#ffffff">
  <span class="cr-preview">Aa 正文样</span>
  <ol class="cr-steps">
    <li>sRGB → [0,1]: 118/255 = 0.4627</li>
    <li>γ 解码: ((0.4627+0.055)/1.055)^2.4 = 0.1804</li>
    <li>L = 0.2126·R + 0.7152·G + 0.0722·B = 0.1804</li>
    <li>Contrast = (1.05)/(0.2304) = 4.5422:1 → AA 正文 ✓</li>
  </ol>
</div>

关键点:

  • 预览字的 color/background 直接绑 --cr-fg/--cr-bg——「眼睛看到的」和「公式算的」是同一对颜色;
  • 四行步骤就是公式的四步:归一化 → γ 解码 → 加权求和 → 求比值;
  • 判定同时输出四档(AA 正文/AA 大字/AAA 正文/AAA 大字),不达标亮红标。

样式与参数

两个 color 型参数(fg/bg,cssVar 注入),数学在 demo 内零依赖实现。完整推导(调研 14§2.3,公式逐字取自 WCAG 2.1 规范):

① 相对亮度(三步):

RsRGB = R8bit/255(同理 G、B)
R = RsRGB ≤ 0.04045 ? RsRGB/12.92 : ((RsRGB + 0.055)/1.055)^2.4
L = 0.2126·R + 0.7152·G + 0.0722·B     ← sRGB 原色亮度系数(BT.709 同源)

② 对比度比值:

Contrast = (L1 + 0.05) / (L2 + 0.05)     L1 为较亮者;0.05 为场景闪烁余量

③ 零依赖 JS(与 oklch-conversion 共享同一条 γ 解码):

const srgb2lin = c => (c <= 0.04045 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4);
const wcagLuminance = (r8, g8, b8) =>
  0.2126 * srgb2lin(r8 / 255) + 0.7152 * srgb2lin(g8 / 255) + 0.0722 * srgb2lin(b8 / 255);
const wcagContrast = (L1, L2) => (Math.max(L1, L2) + 0.05) / (Math.min(L1, L2) + 0.05);
wcagContrast(wcagLuminance(118,118,118), wcagLuminance(255,255,255)); // 4.5422:1

阈值(同规范):1.4.3 AA——正文 ≥4.5:1、大字 ≥3:1;1.4.6 AAA——正文 ≥7:1、大字 ≥4.5:1;1.4.11 非文本组件边界 3:1。大字 = ≥18pt(24px)常规或 ≥14pt(≈18.66px)bold,规范明确「CJK 字体取等效字号」。核验:#767676 vs 白 = 4.5422:1(经典 AA 临界灰)✓。

动效与交互

  • 换色即判定:面板换 fg/bg(demo 内含「临界灰 / 过线灰 / 不及格灰」快捷片),四行推导与判定章实时重算;
  • 交换实验:fg/bg 互换后比值不变(公式对极性对称),演示「L1 恒为较亮者」;
  • 深底实验:把 bg 拨到深色、fg 拨到亮灰(如 #b0b0b8 对 #0b1220)——比值很高,但这就是 APCA 指出「比例制高估亮字可读性」的典型场景,MDX 与 demo 读数都注明该边界;
  • 无自主动画;入场淡入尊重 prefers-reduced-motion。

真实产品案例

  • #767676 临界灰:对白底 4.5422:1——无障碍社区用它标定「浅灰正文能浅到哪」的硬边界;设计系统生成灰阶时就在这附近画 AA 线(调研实跑核验);
  • Apple Dark Mode:官方口径对比度底线 4.5:1,自定义前景/背景力争 7:1(AAA)——把法定下限和产品内标分开的典型实践(调研 13§1.5,Typography/Materials 官方 Markdown);
  • Ant Design 字体颜色:正文/背景对比度目标 ≥7:1(AAA),主文本用 #000000E0(88% 黑)而非纯黑——在守住 AAA 的同时压掉纯黑的刺眼感(调研 13§3.4);其姊妹条目 wcag-contrast 用同一公式做实时校验面板。

公式的量纲与边界

变量量纲取值边界退化情形
RsRGB无单位([0,1])8bit/255,域 [0,1]>1 或 <0 未定义(超域输入先钳制);α 通道不参与(预合成后再算)
γ 解码线性光强(无单位)分段:≤0.04045 直线段,>0.04045 幂段阈值两侧连续;旧值 0.03928 与新值计算结果无差别(官方注 2)
L(相对亮度)无单位([0,1])黑 0 ↔ 白 1;灰色按等值 = 同一 γ 值L=0.5 不是中灰——sRGB 50% 灰 (#808080) 的 L≈0.216,感知与线性相差一整个 γ
0.05(闪烁余量)无单位常数规范固定防止 L=0 时除零:黑对白 = (1.05)/(0.05) = 21:1,公式理论最大值
Contrast无单位比例[1, 21];恒 ≥1同色 L1=L2 → 1:1;比较恒取较亮者为分子,公式无方向性
4.5 / 3 / 7 / 4.5无单位阈值WCAG 2.1 SC 1.4.3/1.4.6/1.4.11判定用原值:4.49:1 不过 4.5 线,四舍五入达标是违规写法
大字定义px/pt≥24px 常规 或 ≥18.66px bold;CJK 取等效字号「大字减半」只在这两个条件内成立;行高、字距不在定义内
极性偏差—深底浅字系统性高估可读性1.2–1.45 视觉低对比在浅灰字场景被全数放行——用 APCA Lc(正文 75)复核

经验口径:合规(法规/审计)用 WCAG 比值,产品内标向 7:1 靠;深色主题成对核算;半透明层按两端极端各自验。姊妹条目:wcag-contrast(同一公式的落地校验条目)、oklch-conversion(共享 γ 解码)、prefers-contrast(用户端的对比度偏好)、oklch-workflow(固定 L 让对比度可预测)。

适用场景 4
  • 设计 token 定稿:每个 文字/背景 对在浅深两主题下各算一次比值再入库
  • 灰阶阶梯生成:给一排灰找「最后一个过 4.5:1 的档」,即 AA 临界灰
  • 无障碍审计与合规:WCAG 2.x / EN 301 549 的法定口径就是这条公式
  • 组件库文档:给色彩 token 表附上实测比值,评审时不用争论「看着够不够」
何时不要用 4
  • 对深底浅字只报比值不验可读——比例制对亮色文字会系统性高估可读性(§适用边界)
  • 拿 AA 通过当终点——正文 AAA 7:1 才是 Apple/Ant 的企业内标,4.5:1 是法定下限不是目标
  • 对半透明叠加层只算最终合成色的比值——叠加随背景滚动变化,必须按最亮/最暗两端各自核对
  • 四舍五入达标:4.49:1 写成 4.5:1——比值必须原值过线
无障碍

这条公式本身就是无障碍工具:正文 AA 4.5:1、大字 3:1;AAA 正文 7:1、大字 4.5:1;非文本组件边界 3:1(SC 1.4.11)。大字定义 = ≥18pt(24px)常规或 ≥14pt(≈18.66px)bold,规范注明「CJK 字体取等效字号」。注意公式的已知偏差:对深底亮字的高估需要用 APCA(Lc 制)复核,Lc 75 是正文感知下限。

浏览器支持

纯数学定义,与浏览器无关;CSS 侧 contrast-color()(自动选黑/白前景)仍在提案阶段,社区口径——生产请自行按本公式预计算。WCAG 2.2 已发布但对比度定义未变,2.1 口径仍有效。

兼容回退

公式无运行时依赖,不存在回退;真正的『回退』是设计侧的:比值不达标时加深/提亮其一并重算,每深 10% 灰阶约抬升 0.4–0.6:1(实测线性域近似)——先算再交付,不要靠肉眼看「够不够深」。

来源 3

起源公式逐字取自 WCAG 2.1 规范原文(relative luminance 与 contrast ratio 两处定义,调研抓取全文核对);亮度系数 0.2126/0.7152/0.0722 与 ITU-R BT.709 原色同源;0.05 为场景闪烁余量;γ 解码阈值 2021-05 前为 0.03928(旧规范),官方注 2 背书更新为 0.04045,实际计算无差别(调研 14§2.3)。
