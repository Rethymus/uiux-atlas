目标梯度效应 Goal-Gradient Effect

目标梯度 · Goal-Gradient

越接近目标,奔向目标的行动力越强。给清晰的进度指示、在起点预置「人为进度」,把资源投在收尾冲刺段——离目标越近,每一步的动机越足。

社区流派 ★★★

几何▾
steps10章
章

JS 型参数:集章卡总章数(demo 教学参数,定律本身不规定数值)。默认 10 章是一张典型集章卡的规模;改小会让「收尾冲刺」来得更快,改大则中途动力低谷更明显。

headStart1章
章

JS 型参数:起点预盖的「人为进度」(artificial progress)章数。默认 1 取「步骤条/会员卡预盖一枚已完成章」的签名巧思(12 补研 §16-9);调 0 即无预盖对照——对比开局第一下的间隔,就能看到虚幻进度对开局的拉动。

代码拆解

结构与 DOM

演示是一张可玩的咖啡集章卡:集章格、进度条、打卡按钮,外加一块逐章间隔面板。

<div class="gg-card">
  <div class="gg-stamps">
    <span class="gg-stamp" data-pre="true">预</span>  <!-- 起点人为进度,如实标注 -->
    <span class="gg-stamp" data-hit="true">✓</span>   <!-- 用户打出的章 -->
    <span class="gg-stamp"></span>                     <!-- 空格 -->
  </div>
  <div class="gg-progress" role="progressbar"><i style="width: 40%"></i></div>
  <p class="gg-readout" aria-live="polite">已集 4/10 · 40% · 还差 6 章</p>
  <button class="gg-punch">打卡集章 Punch</button>
</div>
<div class="gg-panel">…逐章间隔柱状 + 最近/最短/最长文本…</div>

关键点:

  • 集章格三种状态靠字符 + 形状 + 颜色三通道区分:空格虚线圈、用户已集 ✓ 实线、预盖 预 字样并如实标注「人为进度」——不靠颜色单独传达(虚幻进度必须诚实,这是 Kivetz 等研究的伦理边界);
  • 结论不走读图:「已集 n/N · 百分比 · 还差 m 章」三组文本与 aria-live 播报同步,间隔面板逐柱带数值;
  • 打卡按钮在达标后原位变为「再来一轮」——终点之后立刻给出下一轮起点,梯度循环不断。

样式与参数

// steps / headStart 是 JS 型参数,订阅 store;间隔为真实毫秒测量
const prev = punches === 0 ? roundStart : roundStart + intervals.reduce((a, b) => a + b, 0);
setIntervals((arr) => [...arr, Math.round(now - prev)]);
  • steps 默认 10 章(典型集章卡规模)、headStart 默认 1 章——预盖一枚「已完成」章,取自「步骤条/会员卡预盖一枚已完成章」的签名巧思(12 补研 §16-9);
  • 两个参数都是 demo 教学参数:定律只说「越近越快」,不规定卡片多大、预盖几章,schema 如实标注;
  • 间隔 = 距上一章的真实毫秒数(第 1 章相对本轮起点)——demo 测的是用户自己的行为,不模拟数据;
  • 间隔柱高度按 interval / maxInterval 归一,柱序即章序,肉眼可比「开局 vs 收尾」;
  • 进度条 transition: width 0.3s ease,与站内 percent-done 惯例一致(NN/g:≥10s 必须给 percent-done,调研 07§20)。

动效与交互

  • 每次点击:新章 gg-pop 0.25s 一次性弹出、进度条 0.3s 滑动、间隔柱 0.3s 重排——全部只在 transform/opacity/width 上;
  • 达标瞬间:「达标!奖励到手 ✓」一次性庆祝文案 + 按钮变绿为「再来一轮」;庆祝只发生一次,不循环闪烁;
  • prefers-reduced-motion: reduce 下三处动画/过渡全部取消,数值即时更新——计时与文本不受动效开关影响;
  • 键盘可用:打卡是原生 button,Space/Enter 触发;集章格带逐格 aria-label。

真实产品案例

  • 咖啡集章卡「预盖一枚章」:12 补研 §14 记载的「人为进度」直接落地——起点送一枚已完成章,让用户开局就处于「非零进度」,开局间隔显著缩短(12 补研 §16-9 签名巧思);
  • Uber 类「起步进度」:12 补研 §14 原文点名的应用形态——流程起点先给一小段即时完成的进度,把用户送进「已接近」的心理状态;
  • NN/g 的 percent-done 进度条:≥10 秒的操作必须给百分比进度(调研 07§20)——加载进度线就是目标梯度在系统反馈层的载体,收尾反馈越清晰,等待越可容忍。

参数敏感度

参数调大会…调小会…
steps12 章:中途更长,动力低谷更明显——对照「没有里程碑的长目标」反面教材6 章:收尾冲刺来得更快,间隔收窄更早出现
headStart3 章:开局处于 30% 进度,第一下的间隔明显更短——人为进度对开局的拉动直接可测0 章:无预盖对照;与 headStart=1 轮流各打一轮,对比第 1 章间隔即是「虚幻进度」效应的自身复现

经验结论:进度要清晰(看得见)、诚实(预盖要标注)、可见收尾(还差 N 章常驻);资源投在收尾冲刺段回报最高——离目标越近,同样一步的动机越足(12 补研 §14)。

适用场景 3
  • 会员卡/集章/积分体系:起点预盖一枚章(人为进度),收尾阶段集中投放激励
  • 多步流程(注册/结账/引导):清晰的步骤条 + 百分比,让「还差两步」可见
  • 加载等待:≥10s 的操作给 percent-done 进度条(NN/g,调研 07§20),进度线本身就是目标梯度的载体
何时不要用 3
  • 虚报进度:预盖章必须如实标注为「人为进度」,把剩余量谎报为已完成是欺骗(虚幻进度研究的伦理边界)
  • 把进度藏在最后一屏才揭晓——梯度需要「越来越近」的持续感知
  • 目标过大且无中间里程碑(如 0→100% 只有一根空进度条):没有近目标,就没有加速
无障碍

进度信息必须双通道:集章格之外,「已集 n/N · 百分比 · 还差 m 章」与每次打卡间隔都以文本呈现并经 aria-live 播报;集章格不靠颜色单独区分(已集格带 ✓ 字符);间隔柱状图有逐柱数值文本;prefers-reduced-motion 下集章动画与进度条过渡全部取消,数值即时更新。

浏览器支持

演示全部使用原生 DOM/CSS/JS(div 集章格、button、transition),无新特性依赖,现代浏览器均可运行。

兼容回退

定律的工程出口:进度必须「清晰 + 真实 + 可见收尾」。可降级路径:无 CSS 特性依赖;若业务拿不到真实进度数据,可按 Kivetz 等的「人为进度」思路预置已完成步骤(必须如实验明,不得虚报剩余量);没有进度指示的界面,至少给出「还差几步」的文本。注意 NN/g 分层:>1s 才用指示器,≥10s 必须用 percent-done(调研 07§20)。
