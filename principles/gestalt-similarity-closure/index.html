格式塔·相似与闭合 Law of Similarity & Closure

相似原则 · 闭合原则 · Similarity · Closure

视觉相似(颜色/形状/大小/朝向)的元素被感知为同组;不完整的轮廓会被脑补成完整图形。相似的元素承担相似的功能,闭合让残缺的图形仍然可读。

相似演示的分组线索。color=同类行染强调色;shape=同类行图标换圆角方块。07§33 指导:同功能元素用颜色与形状标记;注意别让颜色成为唯一通道(呼应 07§30 的色觉告诫)。

marked2行

相似演示中被标记为「可点击同类」的行数(前 n 行)。被标记的行共享视觉特征→被感知为一组,并被预期承担同一功能(可点击)。

°

闭合演示中每个「吃豆人」圆盘的缺口张角。默认 24°:四个缺口朝内的圆盘足以让大脑补全出中间的正方形;拉到 60°+ 补全崩解——闭合是「脑补」,补全是自动的但需最小线索量。

代码拆解

结构与 DOM

演示是上下两个 pane:相似(6 行列表,前 n 行被标记为同类)与闭合(四个缺口朝内的圆盘围出一块「看不见的正方形」):

<!-- 相似:双通道标记 -->
<button class="gc-row" data-marked="true" data-cue="color">
  <span class="gc-ico"></span> 条目 1
</button>

<!-- 闭合:conic-gradient 挖缺口 -->
<span class="gc-pac" data-pos="tl" style="--gc-mouth: 24deg"></span>

关键点:

  • 相似线索强制双通道:color 模式下被标记行同时改文字色与图标色;shape 模式下图标从圆角方块变圆形——07§33「用颜色与形状标记同功能元素」的直接落地;
  • 闭合 pane 的关键数字是 --gc-mouth(缺口张角):24° 时四盘足够让大脑补全中间的正方形(Kanizsa 式错觉轮廓);60° 以上补全崩解;
  • 被标记行是真实 <button>(可 Tab 聚焦);未被标记的行 tabIndex=-1 + aria-disabled,语义上「不可点」与视觉上「不同类」对齐。

样式与参数

.demo-stage { --gc-mouth: 24deg; }
.gc-pac {
  background: conic-gradient(from var(--gc-rot), transparent var(--gc-mouth), oklch(0.45 0.05 260) var(--gc-mouth));
}
.gc-pac[data-pos="tl"] { --gc-rot: 135deg; } /* 四盘缺口一律朝向中心 */
  • mouth 默认 24°:最小可教学缺口;范围 0–90°,60° 是 demo 自定的「崩解阈值」;
  • cue(color/shape)与 marked(1–6 行)是 JS 型参数,订阅 store 驱动;
  • 缺口实现选 conic-gradient 而非 SVG:纯 CSS、无子元素、扇区角度即变量;不支持时退化为完整圆盘(闭合演示失去缺口但保持可读)。

动效与交互

  • 无循环动画;切换 cue / marked 时列表即时重排(无过渡,因为分组感知是「瞬时的知觉事件」,动画反而掩盖);
  • hover 被标记行显示浅色底——「可点击」的第三重确认(颜色+形状+悬停反馈);
  • 闭合 pane 静态呈现:错觉轮廓是知觉现象,不是动画效果;prefers-reduced-motion 无需处理。

真实产品案例

  • 链接的下划线惯例:Web 平台默认链接 = 蓝色 + 下划线,双通道区分于正文——07§33「确保链接与导航在视觉上与普通文本可区分」的最老牌实现;只染蓝不加下划线的极简主义反而与 SC 1.4.1 张力(编辑性泛例);
  • 加载 spinner:圆环缺口 + 旋转,靠闭合读作「一个转动的圆」——全局通用的加载语义(07§31 闭合的应用,调研 04§2.2 的加载反馈章节同源);
  • 图标族的形状语言:Material 系列图标同一栅格与描边粗细、antd 图标同一线条风格——同功能共享形状,新图标「入族」即自动获得功能暗示(07§33「同功能元素用相似视觉」的体系化落地,编辑性泛例)。

参数敏感度

参数调大会…调小会…
marked被标记行越多,「同类」组越大,但个体在组内的辨识度下降只有 1 行被标记时,相似性退化成「异类强调」(冯·雷斯托夫效应的地盘)
mouth≥60° 闭合崩解:四个缺角圆盘各归各,正方形消失0° 时圆盘变完整圆,「缺口线索」消失,同样没有闭合错觉(需要「残缺」才有「补全」)
cuecolor 是更快的知觉通道,但依赖色觉shape 不依赖色觉——色觉障碍用户的分组仍然成立(demo 的双通道保险)

经验结论:相似负责「谁是一伙的」,闭合负责「残缺也能读」;两条都有一条 a11y 红线——关键语义不能只活在视觉通道里:分组要语义化,错觉轮廓要配文本。

适用场景 3
  • 链接/按钮/正文用颜色+形状双通道区分,扫读时功能立辨(07§33)
  • 同功能图标族共享形状语言(全部圆角方块/全部描边风格)
  • 加载 spinner、环形进度:残缺圆环依赖闭合读作整体
何时不要用 2
  • 链接只靠颜色区分、不加下划线或形状差(与 SC 1.4.1 冲突)
  • 多个「异类」互相争夺注意——相似性被滥用成噪音(呼应 07§30「强调要有节制」)
无障碍

两条红线:①相似线索不能只有颜色(色觉障碍用户会丢失分组,呼应 07§30/SC 1.4.1)——demo 的 shape 线索就是双通道示范;②闭合「脑补」出的图形对读屏不存在——illusory square 没有语义,真实 UI 的关键信息不能只以闭合图形存在(配文本或 aria)。

浏览器支持

吃豆人圆盘用 conic-gradient 实现(缺角即透明扇区),现代浏览器全支持;不支持时退化为完整圆盘,闭合演示失去缺口,但仍可读。

兼容回退

闭合的工程出口:加载中的环形 spinner 就是「闭合」的应用——残缺圆环被读作旋转中的完整圆;骨架屏的灰色块同理。降级路径:conic-gradient 不支持时用 SVG path 画缺口,或退化为完整圆。相似原则的红线同接近性:语义分组(fieldset/列表)必须与视觉相似并行。

来源 2

起源格式塔分组原则的两支:相似原则——视觉相似的元素被感知为同组,指导「用颜色与形状标记同功能元素,确保链接与导航与普通文本可区分」(调研 07§33);闭合原则——共享明确轮廓的趋势,格式塔分组五类(Proximity/Similarity/Continuity/Closure/Connectedness)之一(07§31)。

  1. 条目 冯·雷斯托夫效应

    对比:被标记行从多到一只剩一行时,相似性分组就滑进异类强调——参数表原话「冯·雷斯托夫效应的地盘」;反向纪律是同时只许一个异类。

  2. 条目 WCAG 快速清单

    搭配:闭合的错觉轮廓对读屏不存在,相似的分组要语义化——1.3.1 与 1.4.1 两条 SC 正是这两页 a11y 红线在清单里的落点。

  3. 条目 格式塔·接近性

    反向自「格式塔·接近性」的精选:对比关系,原句「格式塔分组两条线索易混:接近性靠间距差(空间线索),相似性靠颜色/形状标记(特征线索)——两页的红线都是别让语义只活在视觉通道里。」
