导航菜单 Nav Menu

导航栏 · Navbar · Navigation Menu · Menubar · 顶部导航 · 侧边导航

将网站的信息架构分组归类并以导航的形式展示给用户,方便用户查找要获取的信息:顶部横向或侧栏纵向,二级导航聚合在下拉菜单中。

JS 型参数(demo 订阅后切换布局)。horizontal=顶部导航条,二级弹层向下展开;vertical=侧栏纵向菜单(menubar 声明 aria-orientation=vertical),二级弹层向右弹出。注意:Ant Design Menu 的 mode 官方默认是 vertical(vertical|horizontal|inline,06-antdesign.md §4.19),本条目默认取 horizontal——导航菜单最典型的形态是顶部导航条、与 demo 默认视图一致,属条目规格取值而非 antd 官方默认。

themelight

JS 型参数(demo 订阅后切换 data-theme)。light=白底菜单(antd Menu theme 官方默认 light,06-antdesign.md §4.19);dark=深底反白菜单,demo 深底取 antd dark 算法 colorBgElevated #1d1d1d、文字沿用中性文字 88% 透明度惯例 rgba(255,255,255,.88)(§2.3-⑤/§2.4)。

triggerhover

JS 型参数(二级下拉与头像用户菜单的展开方式)。hover 对应 antd Menu triggerSubMenuAction 的官方默认 hover(06-antdesign.md §4.19),关闭延时对齐其 subMenuCloseDelay 官方默认 0.1s;click 需按 APG menu-button 模式以 aria-haspopup/aria-expanded 声明状态(2026-11-21 实抓核验)。无论哪种触发,键盘与触屏都要有等价路径。

代码拆解

结构与 DOM

导航菜单把网站的信息架构分组归类并以导航的形式展示给用户,方便用户查找要获取的信息。DOM 上是三层:导航容器(nav + 列表)→ 一级项(直达链接,或「父项按钮 + 二级聚合弹层」)→ 二级聚合层(role="menu" 弹层)。二级导航聚合在下拉菜单里,不平铺到导航条上。

<nav aria-label="站点导航">
  <ul role="menubar" aria-label="站点导航">
    <li><a role="menuitem" href="/">首页</a></li>
    <li>
      <!-- 父项:disclosure 语义按钮 -->
      <button role="menuitem" aria-haspopup="menu"
              aria-expanded="false" aria-controls="menu-product">产品</button>
      <!-- 二级聚合层:父项的兄弟节点,绝对定位 -->
      <ul role="menu" id="menu-product" aria-label="产品">
        <li><button role="menuitem">产品矩阵</button></li>
        <li><button role="menuitem">定价</button></li>
      </ul>
    </li>
    <li class="nav-user">
      <!-- 个人中心:同一套 menu 语义挂在头像按钮上 -->
      <button aria-haspopup="menu" aria-expanded="false"
              aria-controls="menu-user" aria-label="个人中心"></button>
      <ul role="menu" id="menu-user" aria-label="个人中心">
        <li><button role="menuitem">个人中心</button></li>
        <li role="separator" aria-orientation="horizontal"></li>
        <li><button role="menuitem">退出登录</button></li>
      </ul>
    </li>
  </ul>
</nav>

关键点:

  • 一级项两种形态:直达 <a>,或「父项 <button> + 弹出 menu」;开合状态由 aria-haspopup / aria-expanded 声明(APG disclosure 与 menu-button 模式,2026-11-21 实抓核验);
  • menubar 默认 horizontal;垂直导航要显式声明 aria-orientation="vertical"(APG Menu and Menubar,2026-11-21 实抓核验);
  • 弹层绝对定位于父项之下,z-index 要盖过页面内容;隐藏时用 visibility: hidden 让菜单项同时退出 Tab 序列;
  • 无 JS 时整棵结构退化为链接列表,导航信息不丢失。

样式与参数

三个参数全部是 JS 型(demo 订阅 store):mode 切布局、theme 切 data-theme 配色、trigger 切二级展开方式。

.menu-item { padding: 0 14px; height: 36px; border-radius: 6px; font-size: 14px; }

/* 选中:antd 主色 #1677ff + 蓝板第 1 阶 #e6f4ff(controlItemBgActive = PrimaryBg) */
.menu-item[data-active="true"] { color: #1677ff; background: #e6f4ff; }
/* 悬停:4% 中性填充(antd controlItemBgHover = FillTertiary) */
.menu-item:hover { background: rgba(0, 0, 0, 0.04); }
/* 深色主题:antd dark 算法浮层底 #1d1d1d(colorBgElevated),文字 88% 反白 */
[data-theme="dark"] .menu-item[data-active="true"] { background: #1677ff; color: #fff; }

/* 二级聚合弹层 */
.menu {
  position: absolute; top: calc(100% + 6px); left: 0; min-width: 168px;
  padding: 4px; border-radius: 8px; background: #fff; border: 1px solid #f0f0f0;
  box-shadow: 0 6px 16px 0 rgba(0,0,0,.08), 0 3px 6px -4px rgba(0,0,0,.12), 0 9px 28px 8px rgba(0,0,0,.05);
  z-index: 1000;
  visibility: hidden; opacity: 0; transform: translateY(-4px);
}
.menu[data-open] { visibility: visible; opacity: 1; transform: none; }

数值出处(均经 out/design-study/06-antdesign.md 对 antd 6.7.1 核对):主色 #1677ff(seed colorPrimary)、选中底 #e6f4ff(蓝板第 1 阶)、hover 填充 4%(FillTertiary 分档)、中性文字 88% 透明度、深色浮层底 #1d1d1d(dark 算法 colorBgElevated)、圆角 6/8(borderRadius / borderRadiusLG)、弹层阴影 = boxShadow token 三段值、弹层层级基准 zIndexPopupBase = 1000。

动效与交互

  • hover 触发(antd triggerSubMenuAction 官方默认):进入父项立即展开,移出后延时 0.1s 再收起(antd subMenuCloseDelay 官方默认 0.1s)——这个延时是防止「鼠标斜向移动误关」的关键;click 触发则点击切换、点击外部收起;
  • 展开动画:淡入 + 4px 下移,0.2s(antd motionDurationMid)+ motionEaseOut 缓出 cubic-bezier(0.215, 0.61, 0.355, 1);prefers-reduced-motion: reduce 时取消过渡,只留显隐;
  • 键盘:Enter/Space 展开子菜单或激活项;Esc 关闭当前层并把焦点还给触发项(APG Menu and Menubar);方向键在打开的弹层内上下漫游;demo 实现 disclosure 基线,完整 menubar 一级项左右循环生产环境应补齐;
  • 右侧头像用户菜单与二级下拉共用同一套开合逻辑——「个人中心头像 hover 出现下拉菜单」由 trigger=hover 直接复现。

真实产品案例

  • CSDN 顶部导航:一条横向导航承载全站频道与产品入口,一般含个人中心;存在二级导航的频道把二级项聚合在下拉菜单里,鼠标悬停展开;右上角个人中心头像 hover 出现下拉菜单(资料、创作、退出等入口)——「一级在条上、二级聚合在下拉、头像挂用户菜单」的最典型结构。
  • GitHub 顶栏:左侧一级产品项(Products / Solutions / Open Source / Enterprise / Pricing)hover 展开大型下拉面板,把各产品线的二级入口聚合在一块面板中;右侧是搜索、通知与头像,头像菜单聚合个人资料、仓库列表、Sign out 等账户入口,与 CSDN 同构。
  • 飞书 / 钉钉工作台:桌面端导航聚合消息、文档、会议与「工作台」;工作台页内再把企业自建与第三方应用分组聚合成入口宫格——导航同时承担「流量分发入口」与「各功能聚合」两种角色。

参数敏感度

参数切到这一侧会…切到另一侧会…
modevertical:菜单变成侧栏,适合后台/控制台与更深的信息架构;一级项纵向堆叠,二级弹层向右弹出horizontal:顶部导航条,适合内容型网站;横向空间有限,二级必须聚合进下拉
themedark:深底反白,暗色站点/后台侧栏常用;深底上选中态改用实心主色块更易辨识light:白底菜单,内容型网站默认;浅底上文字对比度更容易核对
triggerclick:触屏友好、没有「路过即展开」的误触;代价是每次都多点一下hover:桌面端探索成本最低,但必须配 0.1s 关闭延时与 click/键盘等价路径,否则误触与不可达并存

经验区间:一级项 4–7 个(Hick 定律:决策时间随选项上升,调研 07§23);二级下拉宽 160–240px;关键入口放条的两端(序位效应,调研 07§29)。

适用场景 4
  • 提供流量分发入口:首页/频道/类目的一级入口,把用户送往各内容区
  • 网站各功能聚合:二级导航聚合在下拉菜单,功能入口集中、可发现
  • 后台/控制台的侧边导航(vertical),与内容区并排常驻
  • 与面包屑分工:导航负责跨区跳转,面包屑负责区内层级定位
何时不要用 4
  • 一级项过多——决策时间随选项数量上升(Hick 定律,调研 07§23),关键动作应放两端(序位效应,调研 07§29)
  • 导航层级超过三层——深层内容改用站内搜索/站点地图
  • 只用图标不用文字的一级项(语义不可猜)
  • 拿导航表达页面内层级——那是面包屑的职责
无障碍

APG 语义:横向持久导航用 menubar/menuitem(垂直 menubar 需显式 aria-orientation=vertical);二级下拉与头像菜单按 disclosure/menu-button 模式声明 aria-haspopup/aria-expanded,弹层用 role=menu + menuitem,分组处用 role=separator(2026-11-21 实抓核验);Escape 关闭当前层并把焦点还给触发项。demo 实现 disclosure 基线(按钮 + aria-expanded + menu 弹层、Enter/Space 切换、Esc 归还焦点、方向键在弹层内漫游);完整 menubar 一级项方向键循环生产环境应补齐。hover 不得是唯一触发路径(键盘/触屏需 click/focus 等价)。

浏览器支持

无 CSS 兼容性门槛:结构是普通 DOM + CSS,语义由 ARIA menubar/menu/menuitem 与 aria-expanded/aria-haspopup 提供(主流浏览器与读屏均支持);menubar 的方向键漫游焦点需作者自行实现(APG 键盘界面实践,调研 07§35)。

兼容回退

无 JS 时降级为普通链接列表(ul > li > a):一级项全部平铺可见、二级链接并列其下,导航信息不丢失;搜索引擎与读屏按文档结构阅读。

下一步学什么

按依据排序:本条目精选 > 路径下一站 > 反向推导 > 路径与配方归属

  1. 条目 标签页

    对比:导航与标签轴常被混用:导航跳页换区,标签轴在页面内换面板(浏览器「每个标签一个页面」是隐喻源头)——层级不同,别互相顶替。

  2. 条目 头像

    搭配:导航条右端的头像按钮挂着用户菜单:头像本身不做导航、只作为菜单锚点——导航条与头像菜单的组合范式。

  3. 条目 面包屑

    反向自「面包屑」的精选:对比关系,原句「同是定位件而方向相反:导航条分组归类全站信息、负责「换区」,面包屑只沿层级路径「上楼」——两者并用不互替,先分清再上页面。」
