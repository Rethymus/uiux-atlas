AI 流式响应 AI Streaming Response

AI 流式响应 · Streaming Markdown · 流式渲染 · 打字机流

AI 回答的渐进渲染:未闭合 markdown 自愈、末尾光标、锁底滚动与用户上滚打断、两级节流——token 流到哪,版面稳到哪。

代码拆解

结构与 DOM

流式响应容器是一台「文本到达状态机」:scroll 容器(锁底)→ role=“log” 的正文流(逐块追加)→ 末尾光标(伪元素)。三个层次各管一件事,不互相渗透。

<div class="chat-scroll">              <!-- 锁底滚动区 -->
  <div class="stream-body" role="log"> <!-- 正文:逐块追加 -->
    <p>已完成段落(不再重渲染)</p>
    <p>生长中的段落<span class="caret"></span></p>
  </div>
  <button class="jump">↓ 回到底部</button> <!-- 仅 !isAtBottom 时出现 -->
</div>

关键点:

  • 光标不是独立 DOM——Streamdown 用 CSS 变量 --streamdown-caret + 最后一个子元素的 ::after 实现,流结束移除属性即消失,零额外节点;
  • 未闭合语法是常态而非异常:token 流到达时 **This is bol、`code、[Click here 都可能停在半截,渲染层必须「按闭合态渲染」而不是报错或闪烁(Streamdown 官方问题定义);
  • 已完成段落要稳定:Streamdown 把内容解析为独立块,块级 memo——只有内容变化的块重渲染(vercel/chatbot 里 MessageResponse = memo(Streamdown),比较器只看 children 是否变化)。

与 骨架屏 的分工:骨架负责「一块内容还没到」的占位,流式渲染负责「内容正在生长」的表达;推理面板这类次级区域还要自己做面板内锁底(vercel/chatbot reasoning.tsx 在流式期间每次内容变化执行 scrollTop = scrollHeight),与外层会话锁底解耦。

样式与参数

六个参数对应三类声明:光标(data 属性选字符)、入场动画(时长走 CSS 变量)、行为开关(JS 型,由 demo 订阅):

/* 光标:仅流式期间挂在最后一个子元素上 */
.stream-body[data-live="true"] > :last-child::after {
  content: var(--srd-caret-char, "▋");       /* block=▋ / circle=● */
  color: var(--accent);
  animation: blink 0.9s steps(1) infinite;   /* 闪烁周期为本站建议值 800–1000ms */
}
/* 逐段入场:官方默认 150ms + ease + fill-mode both(先隐后显不闪烁) */
.stream-body[data-anim="fadeIn"] .tok { animation: fade var(--srd-anim-ms) ease both; }

@keyframes fade { from { opacity: 0; } }
@keyframes blink { 50% { opacity: 0; } }

数值出处(全部为官方记载,调研 15§1):

  • 光标形态:caret="block"(▋) | "circle"(●),仅 isAnimating 且 streaming 时显示,官方建议只对最后一条 assistant 消息显示;
  • 入场动画:三档 fadeIn / blurIn / slideUp,默认时长 150ms、easing ease、fill-mode both;快模型官方建议 blurIn + 200–300ms + ease-out;
  • 吐字节奏:AI SDK smoothStream delayInMs 默认 10ms(文档隐藏时自动跳过,防定时器节流拖停);chunking 默认 'word',CJK 明确建议 Intl.Segmenter(word 分块对中日韩失效);
  • 客户端节流:useChat 提供 throttle 选项,官方示例 50ms;
  • 锁底:use-stick-to-bottom——「聪明逻辑区分用户滚动与程序动画滚动,且不做可能漏事件的防抖」,scrollToBottom() 返回 Promise<boolean;
  • 「rAF 帧合并」为社区实现手段,官方未以 rAF 命名该机制(未证实),官方两级方案是 smoothStream(服务端)+ throttle(客户端)。

动效与交互

  • 吐字节奏:demo 以 smoothDelayMs(默认 10ms)为逐段 tick,模拟 smoothStream 服务端节奏;delayInMs: null 或 0 时不设节流。后台标签页里浏览器本来就会钳制定时器——官方对策是「文档隐藏时跳过延迟」,而不是对抗节流;
  • 打断锁底:用户 wheel 上滚或拖动滚动条离开底部,当帧解除粘底、无防抖(漏一次事件 = 用户永远追不上内容,NN/g:滚动过快要停得下来);回到底部按钮只在 !isAtBottom 出现,点击重新粘底;
  • 入场动画:只动 opacity / filter / translate;animation-fill-mode: both 保证「先隐后显」,批量 token 到达不闪烁;跳过 pre/svg/math(行内 code 参与动画是官方行为);
  • 光标生命周期:流开始挂 data-live="true",流结束摘除——光标即状态机(「是否在生成」压缩进一个伪元素);
  • 诚实模式:unclosedRepair: off 显示原始 token 语法,教学/调试用;生产默认 on;
  • prefers-reduced-motion:取消入场动画与光标闪烁(demo 实现),流式照常。

真实产品案例

  • Vercel Chat SDK(vercel/chatbot):components/ai-elements/message.tsx 中 MessageResponse = memo(Streamdown),比较器 prevProps.children === nextProps.children(文本不变即不重渲),插件集 {cjk, code, math, mermaid}——Streamdown 生产化的第一手样本(仓库源码核对,调研 15§1.1);
  • assistant-ui 双路径:StreamdownTextPrimitive 默认 mode="streaming"——已完成块稳定、仅最后一块生长;轻量路径 MarkdownTextPrimitive 的 smooth 默认 true(平滑吐字),大消息可开 defer 让 React 优先输入与滚动,但 defer 挂载期间必须恒定(官方 skill 文档);
  • use-stick-to-bottom(作者 Sam Denty,自述「Designed with AI chat bots in mind」):vercel/chatbot 的 Conversation 组件直接采用;ResizeObserver 检测内容尺寸变化,弹簧滚动动画优于定长 easing(流式内容尺寸不断变化时定长动画失调)——锁底与打断的参照实现(官方 README)。

参数敏感度

参数调大会…调小会…
caretTypeblock 终端感强、存在感高,长回答远距离也可见circle 更含蓄,适合密集排版;none 丢失「正在生成」信号,只能靠 shimmer 兜底
animStyleblurIn 质感最强、视觉噪音也最大,官方建议留给快模型;slideUp 行进感强fadeIn 最安静;off 零动画开销,读屏与低性能设备最稳
animDurationMs>200ms 快模型下动画追不上吐字,视觉滞后堆积(官方上限 300)<100ms 接近无动画,批量到达时闪烁风险回升(fill-mode both 也救不了单帧多次挂载)
smoothDelayMs>30ms 吐字明显变慢,总时长被拉长;后台标签页反而该跳过延迟(官方行为)0 即全速连吐,渲染压力全在客户端 throttle 一侧;官方默认 10ms 是折中
unclosedRepairon(默认):流中版面即成品版面,闭合符到达无缝替换off 显示原始语法,半截 ** 直接可见——调试利器,生产会显得「坏掉」
lockBottomon:新内容自动跟随,阅读流不被打断;代价是必须做好打断off:新内容在视口外无声增长,用户读到一半发现落后(经典失败态)

经验区间:吐字 10ms、入场 150ms(快模型 blurIn 200–300ms)、闪烁周期 800–1000ms;光标只属于最后一条消息,节流两级各管一段(服务端节奏 + 客户端渲染频率)。

适用场景 3
  • LLM 会话的 assistant 消息体——流式 markdown 的标准容器(Streamdown 官方定位)
  • 推理面板的次级锁底:面板内自动滚底与外层会话锁底解耦(vercel/chatbot reasoning.tsx)
  • 任何逐 token 到达的富文本:报告生成、代码补全流、长摘要
何时不要用 4
  • 对历史消息显示光标/入场动画——官方明确只对最后一条 assistant 消息显示光标
  • 高频逐字符重渲整棵 markdown 树——已完成块应 memo(Streamdown 块级记忆化)
  • 锁底用防抖判断用户滚动——use-stick-to-bottom 明确反对『可能漏事件的防抖』
  • 后台标签页仍按 10ms 定时吐字——smoothStream 在文档隐藏时跳过延迟,避免定时器节流拖停
无障碍

流式区域用 role="log" 让读屏可跟随追加内容,另设 aria-live="polite" 的状态行播报『生成中/已完成/已停止』;逐字/逐词动画对读屏无意义,别把关键信息只放在动画层;光标是纯装饰(::after,aria-hidden 语义);锁底必须可被用户打断(NN/g:动画按真实时钟计时,滚太快要停得下来);prefers-reduced-motion 下取消入场动画与光标闪烁,保留静态光标或直接移除。

浏览器支持

demo 用到的基础设施:CSS 动画与 ::after 光标全兼容;JS 分词优先 Intl.Segmenter(Chrome 87+/Firefox 125+/Safari 14.1+,Baseline 2024),不可用时回退正则逐词;溢出容器滚动为原生能力。生产级 Streamdown 另需 Shiki 高亮(现代浏览器全兼容)。

兼容回退

Intl.Segmenter 不可用时回退正则分词(CJK 退化为逐字,节奏仍平滑);动画与光标均为渐进增强,关闭后流式照常;锁底 JS 失效时容器仍是普通滚动区,仅缺自动跟随。
