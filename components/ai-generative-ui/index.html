代码拆解

结构与 DOM

生成式 UI 的结构是「模型请求 → 宿主渲染」的单向管道:工具卡(Collapsible)是容器,工具头(名称 + 状态徽章)是状态面,Parameters / Result 两个 mono/组件区是数据面。

<div class="tool">                                   <!-- Collapsible -->
  <button class="tool-head" aria-expanded="true" aria-controls="tool-body">
    <code>get_weather</code>                          <!-- 工具名 -->
    <span class="badge">◔ Running</span>              <!-- 七态文字徽章 -->
  </button>
  <div id="tool-body" role="region">
    <p class="label">Parameters</p>
    <pre>{ "city": "上海" }</pre>                     <!-- CodeBlock,随流填充 -->
    <p class="label">Result</p>
    <div class="weather-card">…</div>                 <!-- 映射组件或 JSON 降级卡 -->
  </div>
</div>

关键点:

  • 分派规则(AI SDK 官方):客户端按 message.parts 里 part.type === 'tool-${toolName}' 分派渲染;中间态三态 input-available(显示 Loading…)→ output-available(展开 part.output 渲染目标组件)→ output-error(显示 part.errorText);
  • 七态词表(Chat SDK tool.tsx,目前最完整的公开中间态词表):input-streaming=Pending ○、input-available=Running 🕐、output-available=Completed ✔、output-denied=Denied ✕、output-error=Error ✕、approval-requested=Awaiting Approval 🕐、approval-responded=Responded ✔;
  • 白名单是唯一边界:assistant-ui 官方语义——spec 引用任何不在白名单的组件名抛类型错误而非渲染;AI SDK 与 assistant-ui 两条路线一致结论:模型只能”请求”UI,渲染权永远在宿主;
  • 与 卡片 的关系:映射产物(天气卡等)就是一张普通卡片,生成式 UI 的增量只在「谁决定渲染它」——是宿主按白名单决定,不是模型。

样式与参数

六参数覆盖模式、徽章、折叠与降级四类决策:

/* 工具头折叠:grid-template-rows 0fr/1fr 高度过渡 */
.tool-body { display: grid; grid-template-rows: 0fr; transition: grid-template-rows 0.25s ease; }
.tool-body[data-open="true"] { grid-template-rows: 1fr; }
/* 七态徽章:文字必读,颜色冗余 */
.badge[data-tone="running"] { color: var(--accent); }
.badge[data-tone="error"]   { color: #ff4d4f; }
.badge[data-pulse="true"]   { animation: pulse 1.2s ease-in-out infinite; }

数值出处(调研 15§2):

  • 徽章词表 7 态逐字取自 Chat SDK components/ai-elements/tool.tsx(Pending/Running/Completed/Denied/Error/Awaiting Approval/Responded);结构 Tool(Collapsible)> ToolHeader(名称 + 徽章)> ToolContent > ToolInput(「Parameters」+ CodeBlock)> ToolOutput(「Result」,对象→CodeBlock、字符串→文本、错误优先显示 errorText);
  • 自动收起 1s 取自同仓库 reasoning.tsx 的 AUTO_CLOSE_DELAY = 1000ms(仅触发一次),流中自动展开、完成收起;
  • 多步工具循环官方示例上限 stopWhen: isStepCount(5);
  • CopilotKit「Components as Tools」官方语义:组件『reads only its props and can stream in as the agent fills the payload』;命名建议用动词(render_bar_chart)提高模型命中率;
  • 徽章文案覆写(Pending→Running)与 inputPreviewMs、approvalFlow 等为调研 2.3 的参数化建议,demo 取其策略、数值均官方记载。

动效与交互

  • 参数随流填充:Parameters 的 mono 块逐字生长(demo 节奏 28ms/字符为教学值,未证实),json-spec 模式下 spec 前缀用正则提取已闭合字段——值一闭合即上卡,复现 assistant-ui「partially-streamed spec renders progressively」语义;
  • 折叠时机:流中自动展开(状态可见性优先),output-available/output-error 后 1s 自动收起、可手动展开;收起只动 grid-template-rows(可过渡的布局属性)与高度,不动内容;
  • 状态徽章:Pending/Running 阶段 1.2s 脉冲(存在感 = 系统未崩溃,NN/g 进度三价值);完成/错误态静态,文字永远是第一载体;
  • 降级路径:未知组件名 → JSON 降级卡(白名单 on);白名单 off 档故意演示未注册组件被直接挂载的风险;
  • prefers-reduced-motion:脉冲与光标闪烁取消,折叠瞬时切换。

真实产品案例

  • AI SDK 官方示例:weather tool 的三态卡——input-available 显示「Loading weather…」、output-available 展开 output 渲染天气组件、output-error 显示 errorText;配合 stopWhen: isStepCount(5) 限多步循环(官方 generative-user-interfaces 文档);
  • Chat SDK(vercel/chatbot)Tool 组件:七态徽章 + ToolInput/ToolOutput 双区结构,错误态 errorText 优先、对象结果落 CodeBlock——生产级工具卡解剖样本(仓库 components/ai-elements/tool.tsx 源码核对);
  • CopilotKit「Components as Tools」:useComponent({ name, description, parameters: zodSchema, render }) 把 React 组件注册为前端工具,zod schema 即 props schema,props 随 agent 填参边填边渲;headless 场景用 CopilotChatToolCallsView 渲染工具调用(官方文档)。

参数敏感度

参数调大会…调小会…
genuiModejson-spec 给模型更大组装自由,但安全审计面变大(任意 JSON 树)tool-map 显式一对一映射,审计面最小;自由度也最小
pendingBadgeRunning 传达「已在执行」,长参数流下更少困惑Pending 是官方词表原文,语义最精确(尚未执行完入参)
collapsePolicyauto(完成 1s 收起)会话密度高,历史工具卡不占屏open 全程展开:中间态一目了然,长会话滚动成本高
allowliston:未知名降级 JSON 卡,渲染权在宿主(唯一安全形态)off:未注册组件直接挂载——演示用,生产等于把 XSS 面交给模型
streamPropson:边填边渲,首字段早几十毫秒可见;实现要容忍半截数据off:整块到达,实现简单;参数长的工具会有一段空白等待
resultRendercomponent-map 是 Generative UI 本体;raw-json 等于无映射的官方默认raw-json 永远可用(降级兜底),信息密度低、无视觉结构

经验区间:徽章 7 态够用(别自创第 8 态);自动收起 1s;多步循环 ≤5 步;白名单必须显式声明,「缺省全通过」不是默认而是漏洞。

适用场景 3
  • LLM 工具调用的中间态与结果卡:天气/股票/检索类结构化输出(AI SDK 官方范式)
  • 模型自组界面的宿主渲染器:JSON spec 树 + 组件白名单(assistant-ui GenerativeUISpec)
  • human-in-the-loop 审批流:approval-requested / approval-responded 两态(Chat SDK 词表)
何时不要用 4
  • 把模型输出的 JSON 直接 eval/innerHTML 进页面——注入直通车;渲染权必须在白名单内(AI 生成内容按不可信输入处理)
  • 白名单形同虚设:组件名照单全收后直接渲染——assistant-ui 官方语义是未注册名抛错而非渲染
  • 中间态只靠颜色区分——Pending/Running/Completed 必须有文字徽章(色觉障碍不可读)
  • 工具卡永远展开不收起——流式会话里每个工具卡都占一块,完成 1s 后应收起(Chat SDK AUTO_CLOSE_DELAY 策略)
无障碍

工具头是 button[aria-expanded][aria-controls] + 内容 region(Collapsible 官方语义);七态徽章必须文字可读,颜色只是冗余强化;状态切换经 aria-live="polite" 播报;Parameters/Result 的 mono 块语义上属于读给用户的文本,别塞纯截图;spec 流中的骨架是装饰(aria-hidden),已完成字段才是信息载体;错误卡的 errorText 用 role="alert"。

浏览器支持

纯 DOM + CSS 演示:Collapsible 用 button[aria-expanded] + grid-template-rows 0fr/1fr 高度过渡(现代浏览器全兼容);JSON 解析与正则字段提取为基础 JS 能力。生产级(React Server Components 流式传输、zod schema 校验)在现行全绿基线内。

兼容回退

任何解析失败/未知组件都必须落到降级渲染:未知组件名 → JSON 卡片(白名单 on 档官方语义);spec 半截 → 骨架占位 + 已完成字段渐进填充(demo 实现);JS 失败时工具卡退化为静态折叠块,徽章文案仍是唯一状态载体(不靠颜色)。

来源 5

起源AI SDK 官方范式「Generative UI is the process of connecting the results of a tool call to a React component」:客户端按 part.type === 'tool-${toolName}' 分派,中间态 input-available / output-available / output-error;Chat SDK tool.tsx 给出目前最完整的公开中间态词表(7 态徽章);assistant-ui GenerativeUISpec 允许模型自组 JSON 树但以组件白名单为安全边界;CopilotKit「Components as Tools」让 props 随流式参数边填边渲(调研 15§2)。
