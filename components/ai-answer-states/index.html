回答安全态 · Answer States · 拒答卡片 · 引用来源 · Refusal & Citations

结构与 DOM

回答安全态是「非常态的三张卡」:拒答卡(正常消息位的卡片,不是异常分支)→ 错误卡(通用文案 + 重试)→ 引用层(来源卡/角标/脚注)。三者共享同一条纪律:信息不泄漏、出口必存在。

<article class="msg" role="status">          <!-- 拒答卡:正常 200 消息位 -->
  <span class="badge">refusal · cyber</span> <!-- stop_details 类别徽章 -->
  <p>抱歉,我无法协助完成该请求。</p>          <!-- explanation 原文展示,不解析 -->
  <div class="partial" data-incomplete>已流出的部分输出(降权示灰,标注不完整)</div>
  <button class="retry">重新生成 Retry</button>
</article>

<details class="sources">                    <!-- 引用层:折叠来源卡 -->
  <summary>Used 2 sources</summary>
  <ul><li><a href="…">文档标题 — example.com</a></li></ul>
</details>

关键点:

  • 拒答是正常 200 响应而非错误——Anthropic 返回 stop_reason: “refusal” + stop_details 类别五种(cyber / bio / frontier_llm / reasoning_extraction / general_harms);OpenAI 把拒答放在 assistant message 的 refusal: string|null 字段——都指向「按普通消息位渲染卡片」;
  • explanation 展示而非解析——官方原文 display it rather than parse it:文案不稳定,任何解析分支都会碎;
  • 流中拒答丢弃部分输出——官方明确已有部分输出视为不完整应丢弃;demo 把已流出文字降权示灰并标注;
  • 引用走结构化数据——Anthropic citations 数组(cited_text 精确支撑段落,不计入输出 token)与 OpenAI url_citation annotations(url/title/start_index/end_index 区间)是官方推荐;markdown 内联引用是官方警示的未支持路线;
  • 与 AI 流式响应 的衔接:安全态打断流时,流式状态机从 streaming 直接落 refusal/error 终态;与 状态色系统 的关系:拒答/错误卡的语义色取状态层,不发明新红。

样式与参数

六个参数对应三类声明:引用形态(模式 + 轮播)、拒答出口(重试 + 流中策略)、安全闸(链接弹窗 + 免责位):

/* 拒答卡:正常消息位 + 类别徽章(语义色取状态系统,不发明新红) */
.refusal-card {
  border: 1px solid var(--border);
  border-left: 3px solid var(--status-warn, var(--accent));
  border-radius: 12px;
  background: var(--bg-elev);
  padding: 12px 16px;
}
.refusal-badge {
  font-family: var(--font-mono, ui-monospace, monospace);
  font-size: 11px;
  padding: 2px 8px;
  border-radius: 999px;
  background: color-mix(in srgb, var(--accent) 12%, transparent);
  color: var(--text-1);
}
/* 流中部分输出:降权示灰 + 不完整标注(官方:视为不完整应丢弃) */
.partial[data-incomplete="true"] {
  opacity: 0.45;
  text-decoration: line-through solid color-mix(in srgb, var(--text-1) 35%, transparent) 1px;
}
/* 来源卡:折叠触发器计数 = source-url 部件数(AI Elements Sources 同型) */
.sources summary { cursor: pointer; font-size: 12.5px; color: var(--text-dim, var(--text-1)); }
.sources summary:hover { color: var(--accent); }
.sources a { color: var(--accent); text-underline-offset: 2px; }

数值出处(全部为官方一手,调研 15§6):

  • 拒答类别:五种 cyber / bio / frontier_llm / reasoning_extraction / general_harms(Anthropic stop_details);
  • 部分输出:「视为不完整、应丢弃」(Anthropic 官方原文);
  • 通用错误文案:Something went wrong 类(AI SDK 官方建议)+ regenerate() 重试;
  • 引用分块:自动句级分块,cited_text 不计入输出 token;与 structured outputs 不兼容(JSON 模式会 400)——引用需与文本交错;
  • 链接安全四闸:allowedImagePrefixes / allowedLinkPrefixes / allowedProtocols / allowDataImages(rehype-harden),越界重写为 [blocked];
  • 免责声明位:官方无规定(未证实),常见实践消息尾注或来源卡下方。

动效与交互

  • 三态切换:demo 用场景选择器(正常 / 拒答 / 出错)切换卡片;拒答档先流式吐出半截文字,refusal 信号到达时按 midStreamRefusalPolicy 处理——discard-partial 降权示灰 + 标注不完整,keep-partial 原样保留(反面教材);
  • 重试出口:refusalRetry 三档——regenerate 回到重新生成(通用),fallback 走备用模型(Anthropic 官方机制),none 无出口死胡同(反面教材);
  • 引用形态:citationMode 三档——sources-card 折叠卡(计数 = 来源数)、inline-hover 角标悬停卡(支持 carouselEnabled 多来源轮播,prev/next + 「1/5」索引)、footnote 脚注列表;
  • 链接安全闸:AI 生成的出站链接按 linkSafetyModal: on 在跳转前展示完整 URL(rehype-harden 语义);off 档直跳(演示风险);
  • 免责位:disclaimerPosition 消息尾注 / 来源卡下方 / 不展示(未证实,实践建议)。

真实产品案例

  • Anthropic Refusals 官方文档:stop_reason: “refusal” + stop_details.category/explanation/recommended_model;「display it rather than parse it」;流中拒答丢弃部分输出;可配服务端/客户端 fallback 重试——拒答卡的完整官方蓝本(调研 15§6.1);
  • OpenAI API 参考:assistant message 的 refusal: string|null 字段——拒答作为消息字段而非异常传输;annotations[].type === “url_citation” 含 url/title/start_index/end_index(调研 15§6.1/§6.2);
  • Anthropic Citations API:cited_text 精确支撑段落、不计入输出 token、自动句级分块、char/page/content_block 三种定位;「显著更可能引用最相关段落」且「保证指向提供的文档」(调研 15§6.2);
  • AI SDK Error State:通用错误文案 + regenerate() 重试是官方建议——错误卡的第一手口径(调研 15§6.1);
  • AI Elements Sources / InlineCitation:「Used 3 sources」折叠触发器与悬停来源卡(轮播 prev/next + 「1/5」),并官方警示内联引用无支持、结构化驱动是推荐路线(调研 15§6.2);
  • Streamdown 安全层:rehype-sanitize(GitHub 消毒 schema)+ rehype-harden 四闸;官网确认跳转前弹窗展示完整 URL;针对 prompt injection 给出生产配置示例(AI 生成收紧、用户内容放宽)(调研 15§6.2)。

参数敏感度

参数调大会…调小会…
citationModeinline-hover 学术感强但悬浮层多,密集引用易打断阅读sources-card 最安静,正文零打扰;footnote 印刷感强、移动端跳转远
carouselEnabledon 多来源可翻,核实成本低off 只挂首条,多来源回答的佐证被藏起
refusalRetryfallback 恢复率高但需运维备用模型(Anthropic 官方机制)none 是死胡同:用户只能刷新页面,信任直接清零
midStreamRefusalPolicykeep-partial 留住上下文但可能保留被拒内容(反面教材)discard-partial 官方口径,信息最小化;配合「已丢弃」标注防困惑
linkSafetyModalon 每跳一停,核实成本换安全(官方语义)off 直跳快,但 AI 生成链接不可信前提被推翻
disclaimerPositionsources-below 与引用同区,「信任」集中一处none 免责缺位,AI 内容与人工内容无从分辨

经验区间:拒答卡 = 徽章 + 原文 + 出口三件套;错误态 = 通用文案 + regenerate;引用 = 结构化数据驱动、来源卡保底;链接 = 四闸 + 跳转前展示 URL。

适用场景 3
  • 分类器拒答(安全边界)——正常 200 响应 + refusal stop_reason 的卡片化呈现(Anthropic 官方形态)
  • 带引用来源的回答——citations 数组 / url_citation annotations 的结构化渲染(官方双家规范)
  • 生成失败/超时——通用错误文案 + 重试按钮(防服务端信息泄漏的官方最佳实践)
何时不要用 4
  • 解析拒答的 explanation 文案做分支逻辑——官方明确「展示而非解析」,文案不稳定
  • 流中拒答后继续保留已流出的部分输出——官方明确应丢弃,部分输出可能正是被拒内容
  • 把服务端异常文本直接透出给用户——通用文案 + 重试是官方口径,泄漏堆栈等于给攻击者发地图
  • 用 markdown 内联语法做引用——官方警示无好的语法、模型不自发输出;结构化 citations 数组驱动才是官方推荐
无障碍

拒答/错误卡用 role="status" 或 aria-live="polite" 播报(不打断读屏);重试按钮是真按钮(可聚焦、有按压态),焦点不落在已禁用的部分输出上;来源卡折叠用 details/summary 原生语义(键盘可达),角标悬停卡同时支持 focus 展开 modal 提示完整 URL;部分输出降权示灰时仍保留在 DOM 并标注「不完整」;引用角标不只靠颜色(带数字编号);prefers-reduced-motion 不涉及(无装饰动画)。

浏览器支持

demo 用到的基础设施:details/summary 原生折叠(来源卡);CSS color-mix 降权示灰(Baseline 2023);弹窗为 demo 内静态展开(不依赖 dialog 元素)。无新依赖。

兼容回退

details/summary 不可用时来源卡退化为常开列表;悬停卡不可用时角标退化为 title 提示;弹窗不可用时降级为链接下方内联展示完整 URL(信息不减);color-mix 不可用时部分输出用 opacity 降权。

来源 8

起源拒答的官方双家规范:Anthropic 分类器拒答返回正常 200 响应——stop_reason: "refusal" + stop_details 类别五种(cyber / bio / frontier_llm / reasoning_extraction / general_harms),官方明确 explanation 文案不稳定应「展示而非解析」(display it rather than parse it),流中拒答到达时已有部分输出视为不完整应丢弃;OpenAI 把拒答作为 assistant message 的 refusal: string|null 字段而非异常传输。引用来源的官方双家规范:Anthropic Citations API 的 citations 数组携带 cited_text 精确支撑段落(不计入输出 token,自动句级分块,与 structured outputs 不兼容);OpenAI annotations[].type === "url_citation" 含 url/title/start_index/end_index 区间。错误态官方最佳实践:AI SDK 建议展示通用文案(如 Something went wrong)防泄漏 + regenerate() 重试。Streamdown 官方警示:内联引用无官方支持(无好的 markdown 语法/模型不自发输出/AI SDK 无内建),结构化 citations 数组驱动渲染才是官方推荐(调研 15§6)。
