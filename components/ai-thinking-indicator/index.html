AI 思考中指示器 AI Thinking Indicator

思考中指示器 · Thinking Indicator · 三点脉冲 · Shimmer 思考标签 · 推理步骤卡

AI 推理等待的形态选型:NN/g 响应时间三限定形态、shimmer 思考标签、三点脉冲与步骤卡的自动收起——等待被承认,而不是被装饰。

代码拆解

结构与 DOM

思考中指示器是「等待的承认机制」:状态行(思考中/已完成)→ 思考主体(shimmer 标签或三点脉冲)→ 步骤卡(可选,推理过程)。三个层次按时长升降级,不是三选一的装饰竞赛。

<div class="msg" aria-busy="true">          <!-- 思考区:busy 语义挂容器 -->
  <button class="step-toggle" aria-expanded="true">
    Thinking… <span class="shimmer">推理步骤卡标题</span>
  </button>
  <div class="steps">                       <!-- 步骤卡:complete/active/pending -->
    <p data-state="done">已读取问题</p>
    <p data-state="active">正在比对方案…</p>
  </div>
  <button class="stop">停止 Stop</button>    <!-- >10s 必须可见 -->
</div>

关键点:

  • 形态由 NN/g 三限决定,不是由美感决定:0.1–1s 无需特殊反馈;超过 1s 必须表明「机器在干活」(shimmer/三点);超过 10s 必须 percent-done 进度 + 清晰可标记的中断方式(NN/g 一手原文,调研 15§3.1);
  • shimmer 不是发光滤镜——vercel/chatbot 的实现是 text-transparent + background-clip: text 的渐变扫光,参数 duration(默认 2s 线性)与 spread(高光带宽度系数,官方默认 2,且随文本长度自适应:dynamicSpread = children.length × spread);
  • 步骤卡是一台小状态机:AI Elements ChainOfThought 用 complete | active | pending,Task 用 pending | in_progress | completed 并内置「已完成/总数」计数;
  • 与 骨架屏 的分工:骨架说「一块内容还没到」,思考指示器说「整条回答还在路上」;与 Doherty 阈值 的关系:1s 恰是响应欲速上限,指示器就是为 1–10s 区间服务的。

样式与参数

六个参数对应三类声明:形态选型(enum)、扫光节奏(CSS 变量)、步骤卡行为(JS 型,demo 订阅):

/* shimmer 思考标签:渐变扫光 + background-clip:text(vercel/chatbot 同型) */
.sti-shimmer {
  background: linear-gradient(90deg, var(--text-faint) 40%, var(--text-1) 50%, var(--text-faint) 60%);
  background-size: calc(200% * var(--sti-spread, 2)) 100%;
  -webkit-background-clip: text;
  background-clip: text;
  color: transparent;
  animation: sti-sweep var(--sti-shimmer-ms, 2000ms) linear infinite;
}
@keyframes sti-sweep { from { background-position: 100% 0; } to { background-position: -100% 0; } }

/* 三点脉冲:submitted 空档(AI SDK 官方形态家族) */
.sti-dots i { animation: sti-pulse 1.2s ease-in-out infinite; }
.sti-dots i:nth-child(2) { animation-delay: 0.15s; }
.sti-dots i:nth-child(3) { animation-delay: 0.3s; }
@keyframes sti-pulse { 0%, 70%, 100% { opacity: 0.25; } 35% { opacity: 1; } }

数值出处(全部为一手源码/官方文档,调研 15§3.2):

  • 扫光时长:默认 2s、线性循环;AI Elements 官方档位 Fast 1s / Default 2s / Slow 4s / Very Slow 6s——参数滑杆即这四档;
  • 高光带:spread 默认 2,dynamicSpread = children.length × spread 随文本长度自适应;
  • 自动收起:AUTO_CLOSE_DELAY = 1000ms(reasoning.tsx 源码常量,仅自动收起一次);
  • submitted 空档:status === ‘submitted’ && 加载点/Spinner(AI SDK 官方示例);
  • 三家消费级产品的具体点阵形态官方均未发布 UI 规范(未证实),开源界一致复刻为「思考中文字 shimmer → 三点脉冲」。

动效与交互

  • 时长分档:demo 内部按时长推进——空档(三点)→ 思考段(shimmer + 步骤卡逐级点亮)→ 完成(收起 + 读数);每一段的形态切换就是 NN/g 三限的可视化;
  • 自动收起:流结束等 stepAutoCollapseMs(官方 1000ms)再收起,只自动收起一次;收起后标题行留下「Thought for N seconds」时长读数(未拿到时长时官方退化为 a few seconds),用户可手动再展开;
  • 展开策略:autoOpenOnStream: on 即 reasoning.tsx 的 defaultOpen ?? isStreaming——流开始自动展开,让用户跟着推理走;off 档步骤卡全程收起,只靠标题行扫光提示;
  • Stop 按钮:stopVisible: off 演示违反 NN/g 第三限的反面教材——>10s 的思考没有可标记的中断方式;AI SDK 官方配套是 useChat 的 stop();
  • 2–10s 禁伪进度条:NN/g display inertia——屏幕变化快到用户跟不上,这个区间用轮换文本/脉冲这类非精确反馈;
  • prefers-reduced-motion:停扫光与脉冲,保留静态「思考中…」文字标签(demo 实现)。

真实产品案例

  • vercel/chatbot shimmer.tsx:duration 默认 2s 线性循环、spread 默认 2、dynamicSpread 随文本长度自适应,模块级缓存 motion 组件 + memo 包裹——shimmer 思考标签的第一手生产样本(仓库源码核对,调研 15§3.2);
  • vercel/chatbot reasoning.tsx:流中触发「Thinking…」配 Shimmer;结束后 AUTO_CLOSE_DELAY = 1000ms 自动收起(仅一次);duration = Math.ceil((Date.now() - startTime) / 1000),收起后显示「Thought for N seconds」;流开始自动展开(defaultOpen ?? isStreaming);内容区流式期间自动滚底(调研 15§3.2);
  • AI SDK Chatbot 文档:status === ‘submitted’ 阶段官方配 Spinner/加载点——「已发出、等流开始」的空档有官方归属;
  • AI Elements ChainOfThought / Task:步骤状态机 complete|active|pending 与 pending|in_progress|completed,后者内置「已完成/总数」进度计数与可配时序的渐进 reveal——>10s 长思考的官方零件(调研 15§3.2)。

参数敏感度

参数调大会…调小会…
pendingIndicatorspinner 存在感最强但最「机器」;步骤卡适合 >3sshimmer 最含蓄,适合短思考;<1s 场景三者都多余
shimmerDurationMs>4s 扫光变「慢动作」,等待感被拉长(AI Elements 只有 Very Slow 6s 一档盖到这里)<1.5s 扫光变频闪,1–3s 思考段显得焦躁;官方默认 2s 恰落在区间中点
shimmerSpread>3 高光带过宽,长句整行在闪<1.5 高光带过窄,扫光存在感不足;官方默认 2 + 长度自适应已覆盖两端
stepAutoCollapseMs>2s 收起迟缓,用户多半已手动接管0 即永不自动收起,长回答会留下一整面打开的步骤墙;官方 1000ms 是「读完最后一步」的余量
autoOpenOnStreamon:推理过程透明,但长步骤流会推挤版面off:版面稳定,代价是推理过程被藏起——审计/教学场景不该用 off
stopVisibleon:>10s 红线达标,可中断性是进度三价值的兜底off:演示反面教材;长思考不可中断 = 用户只能干等或刷新

经验区间:扫光 2s(spread 2 + 长度自适应)、收起延迟 1000ms、三点脉冲周期 1.2s;形态跟着 NN/g 三限走,不用美感投票。

适用场景 3
  • status === 'submitted' 的空档——已发出请求、token 流还没开始(AI SDK 官方在此配 Spinner/加载点)
  • 推理模型的 1–10s 思考段——shimmer 思考标签 + 可展开的步骤卡(vercel/chatbot reasoning.tsx 范式)
  • >10s 的长任务——步骤/计数进度 + 可见 Stop 按钮(NN/g 第三限的硬要求)
何时不要用 4
  • 2–10s 的操作上放伪进度条——NN/g display inertia:屏幕变化快到用户跟不上,非精确反馈(轮换文本/脉冲)才是对的
  • 流结束后立即收起步骤卡且无时长读数——reasoning.tsx 收起前等 AUTO_CLOSE_DELAY 1000ms 并留下「Thought for N seconds」
  • 把「正在思考」只编码在动画上——读屏拿不到 shimmer/脉冲的语义,必须配 aria-busy 与状态行文字
  • 给 <1s 的快速响应也挂指示器——NN/g 0.1–1s 区间无需特殊反馈,加了反而制造颠簸
无障碍

思考区挂 aria-busy="true",状态行用 aria-live="polite" 播报「思考中/已完成/用时 N 秒」——时长读数是读屏唯一能拿到的等待量词;步骤卡用真实按钮 + aria-expanded 控制展开收起,收起后内容仍在 DOM 或可达;Stop 是真按钮(可聚焦、有按压态),>10s 场景不许隐藏;shimmer/三点/旋转全是装饰(aria-hidden),语义不依赖动画;prefers-reduced-motion 下停扫光与脉冲,保留静态文字标签。

浏览器支持

demo 用到的基础设施:background-clip: text 扫光需 -webkit- 前缀(Chromium/Firefox/Safari 全支持,CSS masking Baseline);三点脉冲与旋转均为 CSS 动画;步骤卡展开收起是普通 DOM 显隐。无新依赖。

兼容回退

background-clip: text 不可用时 shimmer 退化为静态「思考中…」文字标签(信息仍在);CSS 动画不可用时三点脉冲退化为静态三点;步骤卡收起是渐进增强,收起失败仅占空间不影响语义。

来源 7

起源形态依据是 NN/g 响应时间三限(0.1s 瞬时 / 1s 思流不中断,>1s 必须表明机器在工作 / 10s 注意力上限,>10s 必须 percent-done 进度 + 可标记的中断);一手参数来自 vercel/chatbot:shimmer.tsx 默认 2s 线性循环 + spread 高光带系数(dynamicSpread = 文本长度 × spread),reasoning.tsx 的 AUTO_CLOSE_DELAY = 1000ms 自动收起与「Thought for N seconds」时长读数,AI SDK 在 status === 'submitted' 阶段官方配 Spinner/加载点,AI Elements 再给 ChainOfThought(complete|active|pending)与 Task(pending|in_progress|completed)两个步骤化组件(调研 15§3)。
