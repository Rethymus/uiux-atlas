开关 Switch

切换开关 · Toggle · Toggle Switch

二态即时开关:拨杆在轨道左右滑动表达 on/off,状态即改即生效,不需要「提交」按钮。

组件库 ★★★
实例演示 官方默认
参数
动效▾
sizemd

JS 型参数(demo 订阅后切 data-size)。对齐 antd Switch 的 size:medium|small 默认 **medium**(v5 为 default|small 默认 default,设计调研 06§4.7/§5.1);demo 的轨道/滑块像素为自绘示意,不代表官方轨道尺寸(调研未记载)。

loadingoff

JS 型参数(demo 订阅后切 data-loading)。对齐 antd Switch 的 loading:默认 false(06§4.7);loading 时滑块内显示旋转指示、交互被抑制——语义是「变更已受理、正在生效」。

disabledoff

JS 型参数(demo 订阅后切 data-disabled)。对齐 antd Switch 的 disabled:默认 false(06§4.7);disabled 表示无权限或上级条件不满足,视觉减淡且不响应键盘。

checkedoff

JS 型参数(demo 订阅后切 aria-checked,点击开关也回写本参数,双向)。对齐 antd Switch 的 checked/defaultChecked:默认 **false**(06§4.7);这就是开关状态本身——面板与 demo 里的开关是同一个值。

代码拆解

结构与 DOM

开关是「恒定 label + 拨杆」结构,拨杆本体是原生 button 加 role="switch":

<label class="switch-row" id="mail-label">接收产品更新邮件</label>
<button type="button" role="switch" aria-checked="true" aria-labelledby="mail-label">
  <span class="thumb">
    <span class="glyph" aria-hidden="true">开</span>
  </span>
</button>

关键点:

  • 可访问名称恒定:外部 label 经 aria-labelledby 提供名称,拨杆里的「开/关」文字 aria-hidden——名称一旦随状态变化,读屏在焦点处播报的名称与状态就错位(APG 铁律,调研 07§6);
  • aria-checked 是唯一状态载体(“true”/“false”),不使用 pressed/checked 混用;
  • 滑块位移只写 transform,过渡在合成器上跑,不触发重排;
  • loading/disabled 时补 aria-disabled="true",读屏才知道为什么 Space 没反应。

样式与参数

四个参数都是 JS 型(经 store 订阅改 data-* 与 aria-checked),CSS 按 data-size / data-loading / data-disabled 分支:

.switch-btn {
  position: relative;
  display: inline-flex;
  align-items: center;
  border: 0;
  border-radius: 999px;
  background: rgba(0, 0, 0, 0.25);
  cursor: pointer;
  transition: background 0.2s cubic-bezier(0.645, 0.045, 0.355, 1);
}
.switch-btn[aria-checked="true"] { background: #1677ff; }   /* colorPrimary */
.switch-btn .thumb {
  position: absolute;
  left: 2px;
  border-radius: 50%;
  background: #fff;
  translate: 0 0;
  transition: translate 0.2s cubic-bezier(0.645, 0.045, 0.355, 1);
}
.switch-btn[aria-checked="true"] .thumb { translate: var(--thumb-travel) 0; }
.switch-btn[data-loading="on"] .thumb::after {              /* 旋转指示 */
  content: "";
  position: absolute;
  inset: 3px;
  border: 2px solid rgba(0, 0, 0, 0.25);
  border-top-color: transparent;
  border-radius: 50%;
  animation: sw-spin 0.6s linear infinite;
}
.switch-btn[data-disabled="on"] { opacity: 0.45; cursor: not-allowed; }
@keyframes sw-spin { to { rotate: 360deg; } }
@media (prefers-reduced-motion: reduce) {
  .switch-btn, .switch-btn .thumb { transition: none; }
  .switch-btn[data-loading="on"] .thumb::after { animation: none; }
}

数值出处:

  • size 对齐 antd v6 medium|small 默认 medium(v5 为 default|small,设计调研 06§4.7/§5.1);轨道像素为 demo 自绘示意,调研未记载官方轨道尺寸,不作官方断言;
  • checked/loading/disabled 默认值逐项对齐 antd 6.7.1 文档核对(06§4.7):false/false/false;
  • on 轨道色 #1677ff = antd colorPrimary(06§2.2);过渡 0.2s = motionDurationMid(06§3.1);缓动 = motionEaseInOut;
  • off 轨道灰 rgba(0,0,0,0.25) 为 demo 自绘示意值(语义对齐中性 25% 透明度档,06§2.3⑤,非官方轨道 token)。

动效与交互

  • 滑块位移:0.2s cubic-bezier(0.645, 0.045, 0.355, 1)(antd motionDurationMid + motionEaseInOut);只动 translate(transform);
  • 键盘:Space 切换(原生 button 行为,Enter 可选)——不加自定义键盘代码,把可预期性留给原生(APG,调研 07§6);
  • loading:滑块内 0.6s 线性旋转,交互被抑制但状态不回滚——表达「已受理、生效中」;prefers-reduced-motion 时旋转静止为圆环;
  • disabled:整键减淡、cursor not-allowed、不响应 Space;焦点按 Tab 顺序仍可到达(disabled button 不可聚焦,读屏语义由 aria-disabled 补充)。

真实产品案例

  • iOS 设置(UISwitch):系统设置里几乎每一行都是「文案 + 右侧拨杆」,开启为绿色、关闭为灰色,点击整行即切换——开关与行合并成一个命中区,是移动端最普及的开关形态;
  • 微信聊天设置:聊天详情页的「消息免打扰」「置顶聊天」等都是即改即生效的拨杆,改完无确认弹窗——即时生效心智的典型载体;
  • Android M3 Switch:选中态滑块带勾选图标、轨道随状态加宽,pressed 时滑块放大——Material 系对同一语义的更强调式表达。

参数敏感度

参数调大会…调小会…
sizemd 拨杆命中区更大、更适合触屏与行内主设置sm 适合紧凑列表/工具条,但滑块小、误触率上升
loadingon 期间交互被锁,快速连续点击被吸收,适合异步保存真实场景;但若后端不可靠,用户会被「永远生效中」卡住off 即回到即时切换;loading 只应为真实异步等待存在,不要拿它做视觉装饰
disabledon 明确「这里不可动」,减少无效点击;整组禁用时要说明原因(上级条件/无权限)off 回到可交互;长期 disabled 的设置项应该直接从界面移除而非永远灰着
checkedon 轨道变主色、滑块右移——即时反馈的强信号;大量开关同时 on 会形成大面积主色off 回到灰轨道;默认值全 on 会稀释「开启」的稀缺性与可发现性

经验区间:一屏开关不超过 6–8 个;默认值谨慎——多数设置默认 off,把「开启」留给用户显式决策;loading 态务必配超时兜底,不可无限旋转。

适用场景 3
  • 设置项的即时生效开关:通知、免打扰、深色模式等,改变即刻生效无需保存
  • 功能开关(feature flag)面板:一组开关用 fieldset/legend 或 role=group 命名(调研 07§6)
  • 二态且互斥的配置:只用开/关表达,不需要「部分选中」语义
何时不要用 4
  • 需要「提交才生效」的表单字段——改用 checkbox,并配保存按钮;开关的「即改即生效」心智会被破坏
  • 标签随状态变化的写法(如标签本身在「开/关」间切换)——APG 铁律:焦点处朗读的名称必须恒定(调研 07§6)
  • 三态需求(全选/半选)——switch 只有二态,半选语义归 checkbox 的 indeterminate(调研 07§6)
  • 同一屏出现大量开关——滑杆式控件扫视成本高于复选列表,批量设置优先 checkbox 组
无障碍

button(role="switch")+ aria-checked 表达状态;**可访问名称必须恒定**——demo 用外部 label 文案做名称、拨杆内的「开/关」文字 aria-hidden(否则状态变化时名称与播报错位,调研 07§6);键盘 Space 切换(Enter 可选);loading/disabled 时 aria-disabled 表达不可交互;成组用 fieldset/legend 或 role=group + aria-labelledby(调研 07§6)。

浏览器支持

button + role="switch" + aria-checked 在全部主流浏览器可用;滑块位移用 transform 实现(合成器友好)。读屏对 switch 角色的播报(「开/关」状态)各 AT 均已成熟;loading 指示为纯 CSS 旋转,无 JS 动画 API 依赖。

兼容回退

无 JS 或 AT 不支持 role="switch" 时,退化路径是原生 <input type="checkbox">(checkbox 模式);APG 的选型建议按语义选——「灯的开关」用 switch 友好,流程清单用 checkbox 更自然(调研 07§6)。

来源 2

起源APG 把 switch 定义为仅 on/off 二态的开关类型,键盘 Space 切换、aria-checked 表达状态,并立下「标签不得随状态改变」的铁律(调研 07§6);checkbox 与 toggle button 才允许第三态/半态。生产参照系是 Ant Design Switch(antd 6.7.1 核对:checked 默认 false、size 默认 medium(v6 由 v5 的 default 更名)、loading 默认 false、disabled 默认 false,见设计调研 06§4.7)。
