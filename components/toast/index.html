全局提示 Toast

轻提示 · Snackbar · Message · 全局轻提示

不打断操作的轻量反馈条:固定定位浮于页面之上、按时长自动消失、经 role=alert 播报,只承载非关键信息。

几何▾
duration3000ms
ms

单条 toast 的停留时长,超时整块移除(antd 出场不排队原则)。默认 3000ms 对齐 AntD message.duration 默认 3(秒,0=不自动关闭);MUI 提醒 autoHideDuration 必须给足阅读处理时间——消失过快违反 WCAG 2.2.3(WAI-APG Alert 告诫)。JS 型参数,demo 订阅后驱动计时器。

maxCount3

同时并存的最大条数,超出即移除最旧一条。AntD message.config.maxCount 默认不限制(-),本 demo 为演示堆栈收敛为 1–5;默认 3 为演示取值,非任何库的官方默认(调研未证实 3 为官方值)。

stiffness100

入场弹簧的刚度 k(半隐式欧拉积分,m=1):ω₀=√(k/m) 越大启动越猛、到位越快,过冲比例不受影响(ζ 不变时)。默认 100 = Motion 引擎 spring.ts 源码默认 stiffness=100(调研 10 §6.3 源码逐字核验;motion.dev 文档页标注默认 1 与源码不一致,以源码为准)。参考档位(调研 10 §2.3 本地实算):700/40 ≈ 快·稳(过冲 2.7%)、300/25 ≈ 中·微弹(3.8%)、200/15 ≈ 慢·弹(14.0%)。

damping10

入场弹簧的阻尼系数 c:ζ=c/(2√(km)) 决定过冲——默认 10 与 stiffness 100 组合得 ζ=0.5、首拍过冲约 16.3%(调研 10 §6.3 Motion 源码默认 + §4.3 实算);ζ≈1 为最快无过冲的临界阻尼(如 100/20),ζ>1 过阻尼粘滞(社区流传的 500/50 实为 ζ≈1.12 过阻尼反例,调研 10 §2.3)。c=0 永不停止(Motion 文档警告),故下限 1。

代码拆解

结构与 DOM

Toast 是「页面内容之上的浮层堆栈」:一个固定(或相对舞台)定位的容器按锚定位摆放,每条 toast 是容器内的一张小卡片,出现与消失都不影响页面文档流。

<div class="toast-stack" data-placement="top-center">
  <div class="toast" role="alert">
    <span class="toast-icon" aria-hidden="true"></span>
    已保存到草稿箱
  </div>
</div>

关键点:

  • 每条 toast 容器挂 role="alert",动态插入 DOM 时多数屏幕阅读器会自动播报(WAI-APG Alert);toast 不得夺取键盘焦点,需要打断用户就改用 alertdialog;
  • 容器层 pointer-events: none、卡片层恢复 auto,浮层不能挡住下方页面的操作;
  • MUI 把 Snackbar(即 toast)与 Alert(流内提醒)、Dialog(阻断)三者明确区分:toast 只放非关键信息。

样式与参数

五个参数全部是 JS 型(demo 订阅 store 驱动):duration 控制计时器、placement 切换容器六方位对齐、maxCount 截断最旧条目、stiffness/damping 驱动入场弹簧(见「动效与交互」)。视觉上对应这几条声明:

.toast-stack {
  position: fixed;            /* 或舞台内 absolute */
  inset: 0;
  padding: 14px;              /* AntD message.config.top 默认 8(视口) */
  display: flex;
  flex-direction: column;
  gap: 10px;
  pointer-events: none;
  z-index: 1010;              /* AntD message 层级位于 Modal(1000)之上 */
}
.toast-stack[data-placement="top-center"] { align-items: center; justify-content: flex-start; }
.toast {
  background: #fff;
  border: 1px solid #f0f0f0;  /* antd colorBorderSecondary */
  border-radius: 8px;         /* antd borderRadiusLG */
  box-shadow: 0 1px 2px 0 rgba(0,0,0,.05), 0 1px 6px -1px rgba(0,0,0,.03), 0 2px 4px 0 rgba(0,0,0,.03);
}

数值出处(均核对自 antd 6.7.1):功能色 success #52c41a / warning #faad14 / error #ff4d4f / info #1677ff(seed 功能色);默认 3s 自动消失、maxCount 默认不限制、pauseOnHover 默认 true(AntD message 文档)。六方位模型来自 MUI Snackbar 的 anchorOrigin(纵向 top/bottom × 横向 left/center/right)。弹簧默认 stiffness 100 / damping 10 = Motion 引擎 spring.ts 源码默认(调研 10 §6.3 源码逐字核验;文档页标注的 stiffness 默认 1 与源码不一致,以源码为准);入场叠层曲线 cubic-bezier(.21,1.02,.73,1) 与「从自身高度 200% 外滑入」取 react-hot-toast 源码(调研 10 §5.1)。

动效与交互

  • 入场(弹簧,面板可调):新 toast 从自身高度 −200%/+200% 外以物理弹簧滑入——半隐式欧拉积分(m=1,dt 单步上限 1/30,restDelta 0.002 对齐 Motion granular 口径),逐帧直写 el.style.transform;stiffness/damping 面板可调,默认 100/10(ζ=0.5,首拍过冲约 16.3%);调参中途触发时从当前位置+当前速度继续(速度接力,可打断不归零重启)。卡片层另叠 react-hot-toast 同款缩放/淡入:0.35s cubic-bezier(.21,1.02,.73,1),scale 0.6→1、opacity 0.5→1;
  • 出场不排队:计时到点整块直接消失,不做逐条退出动画——AntD 动效原则「出场比进场更快」;maxCount 超限时同样直接移除最旧一条。库对照:react-hot-toast 退场为 0.4s cubic-bezier(.06,.71,.55,1) 纯缓出收尾,sonner 用 400ms 过渡 + 4s 生命周期(调研 10 §5.1)——本 demo 沿用 AntD 整块消失口径;
  • Esc 关闭:MUI 无障碍要求 Snackbar 可用 Esc 关闭;demo 在有 toast 时监听 keydown,按 Esc 清空;
  • 悬停暂停(pauseOnHover,AntD 默认 true)与手动关闭是可选增强;
  • prefers-reduced-motion: reduce 时弹簧与缩放淡入全部停用,toast 直接出现(MDN:大幅位移动画对前庭障碍用户不友好);
  • 弹簧专题:stiffness/damping/mass 与 ζ 的完整手感拆解(ζ↔过冲换算、档位表、可中断速度接力)见动效条目 Toast 弹簧。

真实产品案例

  • Gmail:发送邮件后左下角弹出「邮件已发送」黑色 toast,并附「撤销」动作按钮——toast 携带动作的典型范式,撤销窗过了时限邮件才真正发出;
  • Google Docs:编辑时左下角持续显示「所有更改已保存在云端硬盘」状态条,把异步保存结果以不打断写作的方式呈现;
  • GitHub:在仓库设置页保存后,页面底部出现自动消失的确认 toast;GitHub(Primer)的 Toast 组件即固定在视口底部、数秒后自行消失。

参数敏感度

参数调大会…调小会…
duration信息停留更久、更易读到,但堆积的旧提示会掩盖新反馈;超过 5–6s 用户会误以为它需要手动关闭快节奏但读不完即消失——低于 2s 违反 WCAG 2.2.3 的风险陡增(MUI:给足处理时间);500ms 只适合「已复制」这类瞬间可确认的反馈
placement无「大小」可言,换的是注意力锚点:底部方位贴近拇指/视线收尾区,顶部方位更醒目但可能挡导航同上;关键是同站固定一个方位,频繁换位会让用户错过提示
maxCount并发上限高,信息全保留但堆栈占屏、时间线混乱(MUI 不鼓励堆叠)只留最新 1 条,页面干净但中间结果被吞——批量触发场景至少留 2–3 条
stiffness启动更猛、到位更快,波次更密(ω₀↑)而过冲比例不变;过高(>700,接近「瞬移」)失去弹簧感起步绵软、到位拖沓;与低 damping 组合会长时间荡摆不停
dampingζ↑ 过冲指数式下降:ζ≈1 临界最快无过冲复位,ζ>1 过阻尼粘滞(社区流传的 500/50 实为 ζ≈1.12 过阻尼反例,调研 10 §2.3)过冲放大:ζ=0.5 首拍过冲约 16.3%,ζ≈0.1 已是「弹跳球」(过冲 72.9%,调研 10 §4.3 实算);c=0 永不停止(Motion 文档警告,故下限 1)

经验区间:duration 2–5s(默认 3s 对齐 AntD)、maxCount 1–3、placement 全站统一(antd 系顶部居中、MUI 系底部);弹簧档位——微弹 300/25(过冲 3.8%)、Motion 默认 100/10(16.3%)、快·稳 700/40(2.7%),抄参数前先算 ζ=c/(2√(km))(调研 10 §2.3 实算表与巧思 3)。关键信息永远不走 toast,走持久 banner 或 alertdialog。

适用场景 3
  • 保存成功、复制成功等非关键过程反馈(不打断操作)
  • 带撤销动作的轻反馈(Gmail 式『已发送+撤销』)
  • 批量操作结果汇总(『已归档 12 项』)
何时不要用 4
  • 关键/必须处理的信息——走 Dialog(alertdialog)或持久 banner(APG:自动消失太快违反 WCAG 2.2.3)
  • 错误表单校验——错误要紧贴字段持久呈现(NN/g:勿用浮层报错)
  • 长时间进度(>10s)——改用进度条 + 可中断途径(NN/g 三限)
  • 大量堆叠刷屏——MUI 明确不鼓励堆叠多条 Snackbar
无障碍

每条 toast 容器用 role=alert,动态插入时多数屏幕阅读器自动播报(WAI-APG Alert);不得夺取键盘焦点,要打断用户就改用 alertdialog;必须提供 Esc 关闭(MUI Snackbar 无障碍要求);自动消失仅限非关键信息,消失过快违反 WCAG 2.2.3、频繁打断违反 2.2.4(APG Alert 告诫)。

浏览器支持

实现只依赖 CSS 固定定位 + transform/opacity 过渡与 JS 计时/事件,均为 Baseline 能力;prefers-reduced-motion 自 2020-01 起全浏览器可用(调研 07§37)。

兼容回退

不支持 transform 过渡的旧环境退化为直接出现/消失(无动效不影响信息传达);JS 禁用时 toast 无法触发,关键信息必须另有页面内持久承载,不能只靠 toast。

来源 6

起源融合自两条一手范式:Ant Design message(顶部居中、默认 3s 自动消失、不打断操作)与 MUI Snackbar(仅限非关键通知、role=alert 内容容器);「不得自动消失关键信息」的规范依据来自 WAI-APG Alert 模式对 WCAG 2.2.3 的告诫(调研 07§8/§9)。
