M3 色调表面 M3 Tone Surfaces

surface-container 五档 · tone-based surfaces · 色调表面

Material 3 用五档 tone 化表面角色(surface container lowest / low / (container) / high / highest)取代「surface + elevation 叠加不透明度」:层级由色调值表达,与海拔解耦。

Material 3 ★★★
实例演示 官方默认

动效▾

JS 型参数(demo 订阅后切换 data-mode)。亮色主题表面档位向高 tone(白)靠拢;深色主题层级靠「提亮」表达——更亮的档位读作更靠前(Android 文档 surface 角色随主题翻转色调,调研 06§7;暗色提亮惯例另见 Apple base/elevated,调研 06§14)。官方逐档 tone 值未在本调研中核实,demo 的 L 阶梯为演示值。

tiercontainer

JS 型参数:高亮五档中被选中的表面角色。五个值逐字取自 M3 官方博客的五档命名(调研 02§B7);container 为无后缀默认档,页脚/背景类用 lowest、浮动组件(卡片/底栏/对话框)向 high/highest 走。

结构与 DOM

五档表面是角色体系,不是五个 CSS 类:每档一个语义角色,组件按「层级地位」领角色,亮暗主题各配一张 tone 映射表。

<main class="page">                      <!-- surface-container-lowest -->
  <section class="section">…</section>   <!-- surface-container-low -->
  <article class="card">…</article>      <!-- surface-container -->
  <footer class="dock">…</footer>        <!-- surface-container-high -->
  <dialog class="sheet">…</dialog>       <!-- surface-container-highest -->
</main>
[data-theme="light"] .card { background-color: var(--ts-surface-container); }
[data-theme="dark"]  .card { background-color: var(--ts-surface-container); } /* 同一角色,换映射表 */

关键点:

  • M3 官方博客(2023-02)废弃「surface + elevation 1–5 叠加不透明度」,改为 surface container lowest / low / (container) / high / highest 五档 tone 化角色——层级与海拔解耦(调研 02§B7);
  • 角色成对设计:每档表面与它的 on-surface 文字/图标成对,官方声明保证最低 3:1 对比度(调研 02§B6);
  • 深色主题不是「换投影」,是换方向:层级靠提亮表达,更亮的档读作更靠前(与 Apple base/elevated 惯例同构,调研 06§14)。

样式与参数

底层机制是 HCT 色调调色板:Tone 0–100 即 CIE L*,固定色相与色度、只沿 tone 展开(Android 每个关键色 13 档,调研 06§5);表面家族取中性低色度列。demo 用 oklch L 作 tone 的工程近似(不同刻度),--ts-hue / --ts-chroma 为 CSS 变量型参数:

.ts-card { background-color: oklch(var(--ts-l) var(--ts-chroma) var(--ts-hue)); }
/* demo 阶梯(演示值):亮色 0.985→0.87 降 L;深色 0.06→0.22 升 L(提亮=前进) */

数值出处:

  • 五档命名与「与 elevation 解耦」:M3 官方博客 tone-based-surface-color-m3(调研 02§B7);
  • Tone 0–100 = CIE L*、13 档调色板、核心 5 板(Primary/Secondary/Tertiary/Neutral/Error):material-color-utilities 与 Android 文档(调研 06§5);
  • M3 基线参考值(demo 亮色 on-surface 即由此换算):surface #FFFBFE、on-surface #1C1B1F、亮 primary #6750A4、暗 primary #D0BCFF(≈tone 80)(调研 06§7);
  • 官方逐档 tone 值未在本调研中核实——社区常引用「亮色 lowest≈tone 100 / low 96 / container 90 / high 92 / highest 94,暗色 4/10/12/17/22」之类的表格,属社区常见值,未证实;demo 采用单调演示阶梯,不冒认该表。

动效与交互

五档表面是静态角色系统,动效只发生在「选中与切换」:

  • tier 参数:被选中的档位卡片右移 6px + 描边浮现,0.25s ease;prefers-reduced-motion 时取消位移与过渡;
  • mode 参数:亮暗两套 L 阶梯整体翻转(亮色降 L / 深色升 L),背景色 0.25s 过渡——同一份组件 DOM,换映射表即换主题;
  • 档位差本身就是「动效的替代品」:M3 用色调差取代 elevation 阴影动画,滚动/悬浮时不需要逐帧重算投影;
  • 无自主动画;色度调高得到的「彩色表面」上,文字对比度须按 WCAG AA 逐档核对(正文 4.5:1,调研 06§17)。

真实产品案例

  • Android 12+ 系统界面(Material You):动态取色后五档表面角色随壁纸重映射,系统设置、通知面板、底部面板的层级全部由 tone 档位承载——tone-based surfaces 更新的官方主场(调研 02§B7/06§6);
  • Material Theme Builder(Figma 插件/网页版,goo.gle/material-theme-builder-web):官方工具把种子色展开为整套 color role(含 surface 家族五档),导出亮暗两套 token(调研 06§7);
  • Radix Colors 步 1–3:12 步色阶把「app 背景(步 1)→ 次级背景(步 2)→ 组件表面(步 3)」写进步位语义——与五档表面同构的 web 端层级做法(调研 06§8;类比属编辑性整理)。

参数敏感度

参数调大会…调小会…
mode → dark档位方向翻转:越高层级越亮(提亮=前进);阴影消失,层级全靠色调差light:档位向白收敛,层级差靠微降 L 表达
chroma表面变「彩色」,品牌感上升;挤压 on-surface 文字对比度余量,正文 4.5:1 先告急回到中性灰阶——M3 表面家族的默认形态(演示值 0.02)
hue表面整体偏向该色相;跨色相时注意与 accent 角色的区分度0°/中性色相时表面读作纯灰,层级最安静
tierhigh/highest 档读作「浮起」——对话框、底栏、悬浮按钮的归属档lowest 读作「退后」——页面底、嵌入式背景的归属档

经验区间(演示值口径):中性表面 chroma ≤0.03;相邻档 L 差 ≥0.03 才可辨;深色档位跨度可略大于亮色(暗环境明度敏感度更低,Apple HIG 暗色对比底线 4.5:1、小字力争 7:1,调研 06§13)。

适用场景 4
  • 同一界面的层级表达:页面底 → lowest,列表分区 → low,卡片容器 → container,悬浮面板 → high/highest
  • 暗色模式的层级:靠提亮而非阴影/描边——「前台呈现更亮」的系统惯例(Apple base/elevated 同构,调研 06§14)
  • 动态取色系统:壁纸换色时五档一起重映射,层级关系不变(Android Material You 的角色化用法,调研 06§6/§7)
  • 替代 elevation 阴影的扁平化设计:层级用色调差而不是投影,减少视觉噪音
何时不要用 4
  • 档位间距离过近——相邻档位小于感知可辨差时,层级信息消失(仍需维持与 on-surface 文字的 3:1 成对对比,调研 02§B6)
  • 表面色度调高还叠大段正文——彩色表面吃掉文字对比度余量,正文 AA 4.5:1 优先(WCAG SC 1.4.3)
  • 深色主题沿用亮色方向的阶梯(档位越高层级越暗)——与系统提亮惯例相反,层级会读反
  • 把五档当装饰色带用——档位是层级语义,跨级跳用(如 lowest 直跳 highest)会破坏相邻档的层读
无障碍

M3 角色体系官方声明「角色成对设计保证最低 3:1 对比度」(调研 02§B6):每档表面须与其上的 on-surface 文字保持 WCAG 正文 4.5:1、组件边界 3:1(调研 06§17)。tone 即 CIE L*(调研 06§5),因此档位差是可感知明度差——demo 用 oklch L 近似该轴(不同刻度,演示值),并把每档的对比度读数留给文字色核对。深色档位提亮方向同时对低视力用户更友好:层级不依赖阴影感知。

浏览器支持

平台设计概念而非浏览器特性:五档角色由 Android/M3 主题以 token 形式提供(Android 开发者文档,调研 06§7);tone-based surfaces 更新发布于 2023-02(m3.material.io 官方博客,调研 02§B7)。Web 落地手段是 CSS 自定义属性(全平台支持)。

兼容回退

Web 近似的回退:每条表面变量写 var(--ts-surface-high, #f3f0f7) 带非空兜底值;不支持 color-mix/oklch 的环境退回预置 hex 主题表。深色环境若拿不到角色 token,用 @media (prefers-color-scheme: dark) 翻转同一组变量(调研 06§11 记载的传统策略)。

来源 3

起源M3 官方博客《Tone-based surface color in M3》(2023-02,调研 02§B7):废弃「surface + elevation 1–5 叠加不透明度」模型,改为 surface container lowest / low / (container) / high / highest 五档 tone 化角色;配套角色体系 26+ 官方 color role,角色成对设计保证最低 3:1 对比度(调研 02§B6)。底层机制:HCT 色调调色板,Tone 0–100 即 CIE L*,Android 为每个关键色生成 13 档(调研 06§5);表面家族取中性低色度调色板。
