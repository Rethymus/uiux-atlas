颜色函数族 Color Functions (color-mix & relative color)

color-mix · relative color syntax · 相对颜色语法

CSS 内建混色:color-mix() 在指定色彩空间插值(默认 oklab),相对颜色语法 rgb(from …) 把原色解构成通道变量做 calc 运算——派生色全部声明式,零硬编码 hex。

Web 标准 ★★★
实例演示 官方默认
参数
色彩▾
brandoklch(0.62 0.19 250)
L62.0C0.190H250.0α1.00

派生源品牌色。默认 oklch(0.62 0.19 250) 取自补研 12§11 片段;本会话实测该值越 sRGB 域、浏览器裁剪为 #0088F2(裁剪行为为调研 06§2 记载的现状)——所有派生色跟着这个底色走。

几何▾
hoverMix12%
%

hover 档向 black 混入的百分比。默认 12% 取自补研 12§11 片段(--brand-hover: color-mix(in oklab, var(--brand), black 12%));active 档取其 2 倍(24%,片段同款)。参数经 CSS 变量注入,demo 内 calc(var(--cf-hover-mix)) 直接进 color-mix()。

softBg12%
%

柔和底色:品牌色掺 transparent 的百分比。默认 12% 取自补研 12§11 片段(--brand-soft-bg: color-mix(in oklab, var(--brand) 12%, transparent));注意与 transparent 混合只能降不透明度,要提升/运算 alpha 得用相对颜色(补研 12§11)。

borderMix40%
%

品牌描边:品牌色掺 transparent 的百分比。默认 40% 取自补研 12§11 片段(--brand-border: color-mix(in oklab, var(--brand) 40%, transparent));阈值参照:传达语义的边框按 SC 1.4.11 对相邻色 ≥3:1 复核(调研 06§17)。

动效▾
spaceoklab

JS 型参数:空间实验室行的插值空间(demo 写 data-space,CSS 四档显式规则)。选型指引出自 MDN(补研 12§11):模拟色光→xyz/srgb-linear;感知均匀插值→oklab/lab;避免变灰→oklch/lch;匹配 sRGB 设备→srgb。不写 in 时默认在 sRGB 插值。

代码拆解

结构与 DOM

派生是单向引用:组件里零 hex,一切颜色从 --brand 变量经函数派生。DOM 上每个派生色是一个消费变量的元素,函数写在 CSS 里、不在 JS 里:

<div class="scene" data-space="oklab">
  <span class="chip base">base</span>
  <span class="chip hover">hover</span>
  <span class="chip soft">soft bg</span>
</div>
.chip.base  { background: var(--brand); }
.chip.hover { background: color-mix(in oklab, var(--brand), black 12%); }
.chip.soft  { background: color-mix(in oklab, var(--brand) 12%, transparent); }

关键点:

  • color-mix(<插值方法>?, <color> <p1>?, <color> <p2>?):默认在 oklab 插值;极坐标空间可加 shorter|longer|increasing|decreasing hue 色相策略(补研 12§11;调研 06§4);
  • 相对颜色语法 rgb(from <color> r g b / alpha):原色解构成通道变量,可 calc() 运算;输出空间可与输入不同(补研 12§11);
  • 回退纪律:每条派生声明先写静态兜底色,再在 @supports (color: color-mix(in oklab, red, blue)) 内覆写——不支持时声明按无效处理,没有兜底就是透明。

样式与参数

五个参数:brand/hoverMix/softBg/borderMix 为 CSS 变量型(demo 内 calc(var(--…)) 直接进函数),space 为 JS 型(data-space 四档显式规则):

:root {
  --brand: oklch(0.62 0.19 250); /* 补研 12§11 片段;实测越 sRGB 域,裁剪 ≈ #0088F2(调研 06§2) */
  --brand-hover:  color-mix(in oklab, var(--brand), black 12%);
  --brand-active: color-mix(in oklab, var(--brand), black 24%);
  --brand-soft-bg: color-mix(in oklab, var(--brand) 12%, transparent);
  --brand-border: color-mix(in oklab, var(--brand) 40%, transparent);
  --on-brand:     color-mix(in oklab, var(--brand), white 85%);
}
.btn:hover { background: rgb(from var(--brand) calc(r * .85) calc(g * .85) calc(b * .85)); }

数值出处(全部为补研 12§11 可复用片段原文):hover=black 12%、active=black 24%、soft-bg=12% 掺 transparent、border=40% 掺 transparent、on-brand=white 85%;空间选型指引(MDN):模拟色光→xyz/srgb-linear,感知均匀→oklab/lab,避免变灰→oklch/lch,匹配 sRGB 设备→srgb。

百分比归一化三规则(MDN,补研 12§11):双省 → 各 50%;单省 → 补足 100%;p1+p2 < 100% → alpha 乘数(等效向 transparent 混);两者 0% → 整条无效。

支持度:color-mix() Baseline 2023-05;相对颜色 Baseline「广泛可用」但「部分支持程度不一」,Safari 16.4 旧语法要求 calc 内通道带百分比,探测用 @supports (color: rgb(from red r g calc(b + 30%)))(MDN 原文示例,补研 12§8/§11)。

动效与交互

  • 函数是声明式的:滑杆改的是 CSS 变量,所有派生色由浏览器同步重算,无 JS 参与——这本身就是本条的交互模型;
  • hover 加深演示用真 :hover + 相对颜色 calc(r*.85)…,过渡 0.15s;prefers-reduced-motion 时取消过渡;
  • 空间实验室切换 data-space,三块色板即时换算(不给过渡——插值空间的差异要看得直接);
  • 相对颜色行整行包在 @supports 探测内:不支持的浏览器隐藏演示、显示说明行,而不是留一块死色。

真实产品案例

  • Tailwind CSS v4(2025-01):透明度工具链用 color-mix(in oklab, var(--color-blue-500) 50%, transparent),渐变默认 OKLAB 插值,整个调色板换成 oklch(官方公告,调研 06§4);
  • GitHub Primer Primitives:DTCG token 的 alpha 变换({ $value: '{base.color.blue.3}', alpha: 0.4 })是「编译期相对颜色」——同一思想在构建管线落地的形态(调研 06§10);
  • Evil Martians 生产工作流:hover 派生写 oklch(from var(--user-avatar-dominant) calc(l + 0.1) c h),固定 L 只调 C/H(调研 06§2)——相对颜色语法在真实站点的用法。

参数敏感度

参数调大会…调小会…
hoverMixhover/active 更深;>30% 后 active 与 hover 拉开但整体发暗hover 与 base 难区分;<5% 时按压态几乎不可辨
softBg淡底更浓,上面的深字对比下降(派生后仍要过 4.5:1)淡底趋近透明,状态感消失;0% 等于没写
borderMix描边更实:传达语义的边框过 3:1 更稳(SC 1.4.11)描边变虚;低过 3:1 时边框只剩装饰作用
spaceoklch 档饱和、srgb 档发灰——蓝→绿中点对比最直观(档位无大小;对照:默认 sRGB 长距离色相过渡出「脏灰带」,调研 06§4)
brand派生色全体随动;越域时浏览器裁剪,派生色跟着裁剪值走(实测现状)—

经验:派生配方给的是起点不是终点——on-brand 本会话实测对裁剪后品牌底仅 3.06:1(过 UI/大字档、不过正文 AA),任何派生组合按用途重跑 WCAG 闸(调研 06§17)。

适用场景 4
  • 从一个品牌变量派生全套交互态:hover/active/soft-bg/border/on-brand 全部 color-mix() 声明,换品牌只改一个变量(补研 12§11 配方)
  • 半透明状态色:color-mix(… , transparent) 造淡底/淡边;Tailwind v4 的透明度工具即此路线(调研 06§4)
  • hover 加深/提亮不用手挑色:相对颜色 rgb(from var(--c) calc(r*.85) …) 与 Evil Martians 的 oklch calc(l + 0.1) 同思路(调研 06§2/补研 12§11)
  • 渐变/混色发灰时换插值空间:sRGB 长距离色相过渡的「脏灰带」换 oklch/lab 解决(调研 06§4/补研 12§11)
何时不要用 4
  • 指望 color-mix(…, transparent) 提升不透明度——它只能降;要升要算用相对颜色 alpha 通道(补研 12§11)
  • 在相对颜色 calc 里给 rgb 通道加百分比——rgb 通道解析为 0–255 数字,calc(g + 25) 合法、calc(g + 25%) 无效(补研 12§11);Safari 16.4 旧语法恰相反,用 @supports 分支(补研 12§8)
  • 两份百分比合计 0% ——整个表达式无效(补研 12§11);p1+p2<100% 是 alpha 乘数,不是错误,但别误当实色用
  • 不写 in 就默认 sRGB 插值还抱怨混色发灰——长距离色相过渡这是默认行为,明示 in oklch/in oklab(调研 06§4)
无障碍

派生不是免检:color-mix 的产物照样按用途过 WCAG 闸——on-brand 文字对品牌底 ≥4.5:1(正文)/3:1(大字与 UI),状态边框对相邻色 ≥3:1(SC 1.4.11,调研 06§17)。本会话实测默认配方:on-brand(white 85%)对裁剪后品牌底 #0088F2 仅 **3.06:1**——过 UI/大字档、不过正文 AA;这正是「派生后必须复核」的实证,阈值判定不四舍五入。

浏览器支持

color-mix():Baseline 2023-05;相对颜色语法:Baseline 广泛可用但部分支持程度不一,Safari 16.4+ 走旧语法(calc 内通道需百分比),用 @supports (color: rgb(from red r g calc(b + 30%))) 分支探测(MDN 原文示例,补研 12§8/§11)。demo 对两族函数均有 @supports 回退。

兼容回退

不支持 color-mix() 时声明按无效处理回落:每条派生色都先写一条静态 hex 兜底声明,再在 @supports (color: color-mix(in oklab, red, blue)) 内覆写;相对颜色行整体包在 @supports 探测内,不支持的浏览器隐藏该行并显示说明。

来源 4

起源color-mix() 与相对颜色语法定义于 CSS Color 5;color-mix() 自 2023-05 起 Baseline 广泛可用,相对颜色语法 Baseline「广泛可用」但「部分支持程度不一」、Safari 16.4 起支持但旧语法要求 calc 内通道用百分比(MDN,补研 12§8/§11);百分比归一化规则与空间选型指引出自 MDN color-mix 参考页(补研 12§11);派生配方(hover=black 12%、soft-bg=12% 掺 transparent、border=40% 掺 transparent、on-brand=white 85%)取自补研 12§11 可复用片段。
