60-30-10 法则 60-30-10 Rule

60-30-10 法则 · 三分色占比 · 60/30/10 rule

三色配比口诀:60% 主导色铺画布、30% 辅助色撑表面、10% 强调色做焦点——源自室内设计的指导原则,不是硬性规定。

代码拆解

结构与 DOM

60-30-10 是角色分工法则:三个色不是随便三色,而是各占一个视觉职责,占比即「视觉面积预算」:

  • 60% 主导色——大面积基调,UI 中就是背景画布,通常用中性色(白/浅灰/深灰);
  • 30% 辅助色——次级表面:侧边栏、卡片、面板、搜索栏(LogRocket 原文例举);
  • 10% 强调色——CTA、链接、图标等少数焦点元素,是界面最鲜艳的部分(hype4:强调色是「焦点/行动号召」)。

demo 把三个占比做成一根构图条与一个线框示意,结构如下:

<div class="r-frame">
  <section class="r-band r-dominant">…画布骨架…</section>
  <section class="r-band r-secondary">…卡片骨架…</section>
  <section class="r-band r-accent">…CTA…</section>
</div>
  • 三段的 flex-grow 由归一化占比驱动——flex-grow 按比例分配剩余空间,天然完成归一化,与 JS 算出的百分比互为印证;
  • 三色是 demo 固定的示意配色(白画布/浅灰组件/亮蓝按钮,对应 LogRocket 记述的 Material 例证),参数只调占比、不调色。

样式与参数

三个 number 参数(0–100,JS 型,demo 内归一化):

// demo 内归一化:总和不必等于 100
const total = dominant + secondary + accent;
const pct = (v: number) => (total === 0 ? 0 : (v / total) * 100);
// 60/30/10 → 60% / 30% / 10%;70/40/20 → 53.8% / 30.8% / 15.4%
  • 默认 60 / 30 / 10 取法则定义值,LogRocket 与 hype4 两篇交叉一致(调研 06§9);
  • 经典例证(LogRocket):Material 白底 60 / 浅灰组件 30 / 亮蓝按钮 10;Spotify 黑 60 / 深灰 30 / 活力绿 10——同一法则在亮暗两种主题下都成立;
  • 法则源自室内设计,两篇来源均明示是指导原则而非硬性规定——占比是「预算线」,不是逐像素指标。

落到主题层,三个角色就是三条语义变量——组件只引用角色,占比与色值都在主题层集中管理:

:root {
  --role-dominant: var(--neutral-0);   /* 60%:画布,常为中性色 */
  --role-secondary: var(--neutral-50); /* 30%:卡片/侧栏/面板 */
  --role-accent: var(--brand-500);     /* 10%:CTA/链接/图标 */
}
.dark {
  /* 暗色翻转映射表;强调色在此提亮降饱和(M3 惯例,见上) */
  --role-dominant: var(--neutral-950);
  --role-secondary: var(--neutral-900);
  --role-accent: var(--brand-300);
}

暗色模式告诫(hype4 原文,调研 06§13):暗色下避免过度饱和——对比过高会造成视觉疲劳。官方注脚是 M3 的做法:暗色 accent 提亮降饱和(亮色 #6750A4 → 暗色 #D0BCFF,调研 06§7/§14)。调研同时明确:诸如「暗色整体降饱和 15–30%」的量化惯例未找到可靠量化标准——降饱和方向可信,具体幅度没有官方数字,按视觉复核为准。

动效与交互

  • 改任一占比参数,三段宽度即时重排,读数条同步显示归一化后的百分比(保留一位小数);
  • 宽度变化用 0.3s transition 过渡,只动 flex-grow(布局属性,动效克制、时长短);prefers-reduced-motion 时取消过渡直接跳变;
  • 归一化读数同时给出原始总和:当三者之和 ≠100 时,demo 明示「总和 X → 已归一化」,避免误读成占比失效;
  • 法则本身无动效语义;若给强调色元素加微动效(hover 提亮等),只动 transform/opacity,并且暗色下避免高饱和闪烁。

参数敏感度

参数调大会…调小会…
dominant画布更空更稳,页面呼吸感强;超过 ~70% 后辅助表面显得单薄画布被挤压,页面开始「吵」;主导色失去大面积定调作用
secondary次级表面扩张,信息密度感知上升;接近主导色占比时层次开始混淆卡片/面板萎缩,内容缺少落脚面;趋近 0 时只剩画布与 CTA 的两极
accent焦点元素更多更显眼;但强调色一旦不再稀少,「焦点」语义被稀释,页面变花(hype4:不要让所有颜色都鲜艳)CTA 存在感不足,行动号召难以被注意到;趋近 0 时界面只剩中性的两个层级

经验:把三参数拖到 70/20/10、40/40/20 等组合观察读数条,可以直观感受「预算转移」——主导色每让出一份,辅助与强调就获得一分存在感;真正稳定的界面几乎总是把强调压在最小的一份里。

适用场景 3
  • 内容型产品首屏:中性画布 60% + 卡片/侧栏 30% + 主 CTA 10%(LogRocket 例证:Material 白底/浅灰组件/亮蓝按钮)
  • 给新团队定『色彩预算』时当沟通语言:先分主导/辅助/强调三个角色,再填具体色值
  • 审计现有页面的色彩构成:截图估算三色占比,超过 10% 的强调色通常意味着焦点被稀释
何时不要用 4
  • 让所有颜色都鲜艳——hype4 原文告诫:大面积高饱和会让画面『吵』起来
  • 单色阶方案:只有一档灰时按钮会『消失』(hype4 提醒)——辅助/强调至少要拉开一档可感知差异
  • 暗色模式下过度饱和——对比过高造成视觉疲劳(hype4 原文,调研 06§13);M3 暗色 accent 提亮降饱和(#6750A4→#D0BCFF)是同一告诫的官方注脚
  • 把 60/30/10 当硬性指标逐像素抠——两篇来源都明示它只是指导原则
无障碍

占比本身不产生可访问性,三个角色之间的**对比**才产生:辅助/强调与画布的边界对比要过 SC 1.4.11 的 3:1(非文本),强调色上的文字按 wcag-contrast 条目四项阈值复核;LogRocket 例证 Spotify(黑 60/深灰 30/活力绿 10)说明暗色下同样成立,但强调色要控饱和(调研 06§9/§13)。

浏览器支持

设计法则,不依赖特定 CSS 特性;demo 仅用 flex 布局与普通颜色声明,所有现代浏览器可用。

兼容回退

无浏览器兼容问题。demo 用 JS 归一化(三值相加后折算百分比)驱动 flex 比例;flex-grow 本身也按比例自动分配,天然完成归一化,二者互为印证。
