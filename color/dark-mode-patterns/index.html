暗色设计模式 Dark Mode Patterns

暗色四模式 · dark mode 不是反转 · dark theme patterns

暗色不是浅色的反转:Apple 原文「not necessarily inversions」。四个模式——分层(base/elevated 靠提亮)、饱和度(accent 提亮降饱和)、阴影(层级让位给表面)、品牌色(accent 换对、图片压暗)。

代码拆解

结构与 DOM

一套 UI 骨架跑三种策略,骨架不变、只有 token 表在换——这正是「暗色不是反转」的结构性证明:反转是「同一张表逐值翻转」,语义暗色是「另一张按角色重挑的表」。

<div class="scene" data-strategy="dark-semantic">
  <div class="bar">窗口栏(base 层)</div>
  <div class="card">卡片(raised 层):标题、正文、按钮、徽标、图块</div>
</div>

关键点:

  • 分层:深色界面叠深色界面,层级靠「提亮表面」表达——Apple 用 base(更暗,背景后退)/ elevated(更亮,前台前进)两组背景,前台呈现(popover/modal sheet)自动切换(调研 06§13);
  • 层级归表面、不归阴影:黑底上纯黑阴影不可辨(demo 的 dark-inverted 档可直观看到),层级表达改由表面提亮承载,阴影保留但降权重(调研 06§13 的 Apple 机制;分层阴影工艺见调研 12§7);
  • 饱和度:高饱和强调色在暗色下提亮降饱和——M3 官方基线就是范例:亮 primary #6750A4 → 暗 primary #D0BCFF(≈tone 80,调研 06§7/§13);
  • 品牌色:accent 换成提亮降饱和的暗色对,白底图片内容压暗防「发光」(Apple HIG,调研 06§13);一切取色走语义变量,硬编码色是 Android 文档点名的翻车点(调研 06§12)。

样式与参数

四个参数:accentLight / accentDark 为 CSS 变量型(hex),strategy / elevation 为 JS 型:

/* 语义暗色 token 表(表面阶为演示值;官方锚点只有方向与基线色,调研 06§13) */
[data-strategy="dark-semantic"] {
  --dp-canvas: oklch(0.17 0.012 297);   /* base */
  --dp-surface: oklch(0.21 0.014 297);  /* raised:层级=逐档提亮 */
  --dp-fg: oklch(0.92 0.01 297);        /* ≈ #E5E3EB */
  --dp-accent: #D0BCFF;                 /* M3 暗色 primary 官方基线(调研 06§7) */
  --dp-on-accent: #381E72;              /* M3 暗色 on-primary 官方基线 */
  --dp-shadow: 0 6px 16px rgba(0, 0, 0, 0.32); /* 阴影降权重 */
}

/* 直接反转(反模式档):亮色值逐通道翻转,accent 原样保留 */
[data-strategy="dark-inverted"] {
  --dp-canvas: #000401;                 /* invert(#FFFBFE) */
  --dp-surface: #000000;                /* invert(#FFFFFF) —— 三档全黑,层级失效 */
  --dp-fg: #E3E4E0;                     /* invert(#1C1B1F) */
  --dp-accent: var(--dm-accent-light);  /* 亮色 accent 直接上暗底 */
}

数值出处:

  • #6750A4 / #D0BCFF / #381E72 / #B3261E / #FFFBFE / #1C1B1F 全部为 M3 官方基线值(Android 开发者文档,调研 06§7);本会话复测 #D0BCFF 配 #381E72 7.71:1、#D0BCFF 对暗表面 11.25:1;
  • 语义暗色表面阶 L 0.17/0.21/0.25 为演示阶梯——官方 elevation overlay 逐档透明度表在调研中未找到(调研 06§13 已如实记录「未找到」),文字对三档实测 15.09 / 13.97 / 12.64:1;
  • 纯反转白/黑 21:1:超过 AAA 上限的「过冲」,正是「对比过高造成视觉疲劳」(hype4,调研 06§13)的量化呈现。

动效与交互

  • 策略/层级切换改写 CSS 变量,表面、文字、阴影 0.25s ease 过渡;prefers-reduced-motion 时取消;
  • elevation 档位是证据链:semantic 档下切 base→raised→overlay,表面逐档提亮、卡片「浮」出来;dark-inverted 档下三档完全一致——层级表达失效,这就是反模式的可玩证明;
  • 徽标与按钮换色即时完成,不补过渡掩盖判定变化;图块的压暗层用 0.25s 淡入;
  • 入场动画只动 opacity/transform(合成器属性),prefers-reduced-motion 时取消。

真实产品案例

  • Apple iOS/iPadOS 系统暗色:base / elevated 两组背景实装,前台呈现(popover、modal sheet)自动从 base 切到 elevated;系统 semantic colors 随外观自动适配,自定义色要求 Xcode Color Set 提供亮/暗变体(Apple HIG,调研 06§13);
  • Android Force Dark:「分析每个 View 自动反色」的官方兜底方案,文档明示要充分测试、按 View 排除——官方亲自给「直接反转」路线标了警示牌(调研 06§12);
  • GitHub Primer:dark 与 dark-dimmed 两套暗色主题并存,同一套语义 token 的两张映射表,而非一套色加深(调研 06§10)——「暗色是独立映射表」的工程实证。

参数敏感度

参数换成…会…
strategy → dark-inverted表面全黑、白字 21:1 过冲、亮 accent 硬上暗底、黑阴影不可辨、白底图发光反模式全家桶:每一条都对得上文档警示(Apple「not necessarily inversions」、hype4 视觉疲劳、Android 翻车清单)
strategy → dark-semantic表面分层提亮、accent 换 #D0BCFF 对、徽标降饱和、图块压暗 25%四模式齐上;文字对比落在 12.6–15.1:1,比过冲舒适且全过 AAA
elevationbase→raised→overlay,semantic 档逐档提亮inverted 档三档无差异——层级是否成立一眼可辨
accentDark更亮更饱和的暗色 accent非 UI 文字(accent/表面 3:1 闸)余量变化;过饱和在暗底刺眼(hype4,调研 06§13)

经验:暗色主题是重新挑色不是翻转;每张暗色映射表逐组合重跑对比度(Apple 底线 4.5:1、小字力争 7:1,调研 06§13),层级交给表面提亮,阴影只做辅助。

适用场景 4
  • 为既有浅色产品补暗色主题:先决定「不反转」的四模式清单,再逐层换语义变量
  • 深色界面上叠深色界面(卡片/抽屉/模态):层级用表面提亮表达(Apple base/elevated,调研 06§13)
  • 品牌色直接上暗底发闷或刺眼时:按 M3 惯例准备提亮降饱和的暗色对(#6750A4→#D0BCFF,调研 06§7)
  • 暗色下白底截图/插图「发光」:给图片内容压暗处理(Apple HIG 建议,调研 06§13)
何时不要用 4
  • 把浅色调色板 L 值逐个翻转当暗色主题——Apple 原文否定(not necessarily inversions,调研 06§12);demo 的 dark-inverted 档即此反模式
  • 硬编码文字色/背景色/图标色不随主题翻转——Android 文档点名的暗色翻车点(调研 06§12)
  • 暗色下继续用亮色那套高饱和强调色——对比过高造成视觉疲劳(hype4,调研 06§13)
  • 做 app 级手动外观开关与系统设置打架——Apple HIG 不建议(调研 06§12);需要时改写 color-scheme 而非另写一套硬编码色
无障碍

暗色不是免检通道:文字对比仍按 WCAG 正文 AA≥4.5:1、AAA≥7:1、大字与 UI≥3:1 复核(调研 06§17);Apple 要求底线 4.5:1、小字力争 7:1(调研 06§13)。本会话实测:语义暗色表面阶(演示值)上正文 12.64–15.09:1(全过 AAA),纯反转白/黑 21:1——超过 AAA 上限的「过冲」正是 hype4 所说视觉疲劳的来源(调研 06§13);直接反转把 #6750A4 原样搬上暗底,#D0BCFF 对暗表面 11.25:1 而前者明显更低。

浏览器支持

模式本身是配色纪律,无新 API 依赖:demo 用 CSS 自定义属性 + prefers-color-scheme 语义(Baseline 2020-01,调研 06§11);对比度复核为 JS 内联 WCAG 公式,与浏览器支持无关。oklch() 色值需 Baseline 2023-05(调研 06§1),hex 参数值不受影响。

兼容回退

三档策略切换由 JS 完成,无浏览器兼容分叉;老浏览器若不支持 oklch() 兜底色,演示字色会回退为继承色——参数默认值全部为 hex,主路径不受影响。语义暗色的工程回退是 @media (prefers-color-scheme: dark) 翻转变量(调研 06§11 记载的传统策略)。

来源 4

起源Apple HIG Dark Mode 原文:暗色调色板「不一定是浅色的简单反转」、系统提供随外观自动适配的 semantic colors、前台呈现自动切 elevated 背景(调研 06§12/§13);Android 文档以 DayNight+主题属性为正路、Force Dark 自动反色为需充分测试的兜底反例(调研 06§12);暗色 accent 基线 #6750A4→#D0BCFF 出自 M3 官方值(调研 06§7)。
