动态取色 M3 Dynamic Color

Material You 动态取色 · Dynamic Color · 动态取色流程

从一个 source 色相出发,按变体配方展开 5 个调色板,再按角色 tone 映射成 primary/on-primary/container 等语义色——亮暗主题共用同一套 token。

Material 3 ★★★

参数
几何▾
sourceHue299deg
deg

source color 的 HCT 色相——整套方案的唯一输入。默认 299 = M3 官方基线种子紫 #6750A4 的 HCT 色相(demo 内嵌 CAM16 前向模型实测 298.98;调研 06§六7 载明 #6750A4 为官方亮色 primary)。注意 HCT 色相刻度与 hsl/oklch 不同:oklch 蓝≈220°,HCT 蓝≈300° 附近。

动效▾
varianttonal-spot

变体=关键色调色板的生成配方(色度档 + 色相旋转,常量取自 material-color-utilities scheme_*.js 发布源码):tonal-spot = primary(h,36)/secondary(h,16)/tertiary(h+60,24)/neutral(h,6)/NV(h,8),Android 12 起的默认;neutral = 12/8/16/2/2,近乎灰阶;vibrant = primary(h,200,按可达截断)+ secondary/tertiary 按色相断点表旋转,追求最大鲜艳;expressive = primary(h+240,40),中性色相偏 +15°,整体与种子色相刻意分离。变体名与出现时间(Android 12: Tonal Spot;Android 13: Neutral/Vibrant/Expressive)见调研 06§六6。

schemelight

亮/暗主题:同一套角色 token 换 tone 取值(库内 contrastLevel 0 约定)——accent 类 40↔80、container 类 90↔30、on-类 100↔20 或 30↔90、surface 类 98↔6。官方手调基线参照(调研 06§六7):亮 primary #6750A4 / on-primary #FFFFFF / primary-container #EADDFF / error #B3261E / surface #FFFBFE / on-surface #1C1B1F;暗 primary #D0BCFF(≈tone 80)/ on-primary #381E72 / primary-container #4F378B / surface-variant #49454F——体现『暗色 accent 更亮更低饱和』惯例。变体生成值与手调基线接近但不逐值相等(基线 primary 调色板 chroma≈48,变体管线为 36;基线 neutral≈4,变体为 6)。

代码拆解

结构与 DOM

动态取色是「一条流水线」,不是某个 CSS 属性:source color → 5 个关键色调色板 → 角色色 token。Web 端的落地形态是两组同名的 CSS 变量(亮/暗各一套),组件只引用角色名:

<body data-scheme="light">
  <button class="md-btn">Continue</button>
</body>
body { background: var(--md-surface); color: var(--md-on-surface); }
.md-btn { background: var(--md-primary); color: var(--md-on-primary); }
body[data-scheme="dark"] { --md-surface: #141218; /* …整组换映射 */ }
  • 角色命名分三类:accent 类(primary/secondary/tertiary/error)、surface 类(surface/surface-variant/…)、container 类 + on-X 反色(primary-container ↔ on-primary-container)(调研 06§六7);
  • 组件永远不写具体色值——这正是「语义 token 而非具体值」的 Android 官方表述(调研 06§二10 同构佐证);
  • on-X 类角色跟随其底色:换 scheme 或 variant 后必须整组重算,不允许只换 primary 不换 on-primary。

样式与参数

变体决定调色板、scheme 决定每档角色的 tone(库内 contrastLevel 0):

// 变体配方(常量取自 material-color-utilities 0.3.0 scheme_*.js)
tonalSpot:  primary(h,36) secondary(h,16) tertiary(h+60,24) neutral(h,6) nv(h,8)
neutral:    primary(h,12) secondary(h,8)  tertiary(h,16)    neutral(h,2) nv(h,2)
vibrant:    primary(h,200→可达截断) secondary(rot(h),24) tertiary(rot(h),32) neutral(h,10) nv(h,12)
expressive: primary(h+240,40) secondary(rot(h),24) tertiary(rot(h),32) neutral(h+15,8) nv(h+15,12)
// 角色 tone 映射(material_dynamic_colors.js,contrastLevel 0)
primary 40/80 · on-primary 100/20 · primary-container 90/30 · on-primary-container 30/90
surface 98/6 · on-surface 10/90 · surface-variant(NV) 90/30 · outline(NV) 50/60

数值出处:

  • 官方手调基线(调研 06§六7,Android 文档 colors.xml 原文):亮 primary #6750A4、on-primary #FFFFFF、primary-container #EADDFF、error #B3261E、surface #FFFBFE、on-surface #1C1B1F;暗 primary #D0BCFF(≈tone 80)、on-primary #381E72、primary-container #4F378B、surface-variant #49454F;
  • 变体管线的生成值与手调基线接近但不逐值相等:基线 primary 调色板 chroma≈48,tonal-spot 变体为 36;基线 neutral≈4,变体为 6(demo 用两套值并排呈现,不冒充);
  • error 调色板固定 (hue 25, chroma 84)(dynamic_scheme.js 构造器);
  • 壁纸→source 的取色链(quantize Celebi = Wu + WSMeans → score)见调研 06§六6,demo 从 source hue 起步;
  • 原流程中同一壁纸派生 5 套配色方案构成亮/暗主题基础(调研 06§六6);demo 简化为 source hue + variant + scheme 三个输入,便于观察生成规则本身;
  • 品牌色保留:HarmonizedColors 在 HCT 中把自定义色向系统色相调和,保持对比与视觉平衡(运行时 applyToContextIfAvailable(),调研 06§六6)。

动效与交互

  • 三个参数任一变化,整套角色色即时重算;亮暗切换是同角色换 tone,不是颜色反转(Apple HIG 暗色模式页立场:暗色主题「not necessarily inversions」,Android Force Dark 为兜底反例——调研 06 条目13);
  • 色块过渡只动 background-color/color(0.18s),prefers-reduced-motion 时取消;
  • 迷你界面卡用生成的 surface/on-surface/primary/secondary-container 拼装——角色语义对不对,一眼可验;
  • 本条目展示的角色 tone 表是库内 contrastLevel 0 的取值;contrastLevel ±1 会按 contrastCurve 与 toneDeltaPair 再调整(含把 tone 50–59 的「尴尬区」推开),本条目不暴露该参数(源码 dynamic_color.js);
  • 亮暗切换不应引起布局位移:角色色只影响 color/background,不牵动尺寸——把主题层与组件层解耦的又一理由;
  • 变体间最敏感的是 vibrant(primary chroma 200,按各 tone 可达值截断)与 expressive(primary 色相 +240°)——拖 sourceHue 看角色整体「跳档」。

参数敏感度

参数调大会…调小会…
sourceHue整套方案绕 HCT 色环转动;各角色相对关系(accent vs surface 的 tone 差)不变同上反向;299 是基线紫,±60° 就会进入 HCT 的蓝/品红区
variantvibrant:角色最鲜艳,近端 tone 可能被截断降饱和neutral:近乎灰阶,只剩明度差异
schemedark:accent 上浮到 tone 80(更亮更低饱和),surface 沉到 6——层级靠「提亮」表达light:accent 在 tone 40,surface 98,层级靠「加深」表达
适用场景 4
  • 按壁纸/品牌色整套换肤:一个 source hue 进来,primary/secondary/tertiary/neutral/error 五板 + 全套角色变量出去
  • 亮暗主题共用语义 token:组件只写 var(--md-primary),主题只换映射(与三层 token 架构同构)
  • 不同『性格』的产品主题:tonal-spot 跟随、neutral 克制、vibrant 张扬、expressive 出跳
  • 品牌色保留:自定义色经 HarmonizedColors 在 HCT 中向系统色相调和,保持对比与平衡
何时不要用 3
  • 把生成值当官方基线值:基线 #6750A4 系手调( chroma≈48),tonal-spot 管线 primary chroma=36,两者接近但不同
  • 只在暗色主题下检查对比度:两套 scheme 的 on-类角色是不同 tone,必须各自复核
  • 绕过角色直接用调色板任意 tone 上 UI:角色档位带对比度约束,随手取 tone 会破坏可读性
无障碍

角色档位自带对比度约束(库内 contrastLevel 0):on-色与色底 tone 差 ≥50 → 正文 ≥4.5:1(AA);tone 差 ≥40 → 非文本/大字 ≥3:1。primary 对 surface 的对比度由 contrastCurve(3,4.5,7,7) 保证最低 3:1。换 variant/scheme 后应重新核对关键组合(按钮字/底、文本/背景)而非假设恒成立;WCAG 阈值不得四舍五入。

浏览器支持

角色色以 hex/CSS 变量落地,任何浏览器可用;Android 平台由 DynamicColors 在运行时应用。demo 的调色板与角色计算是内嵌 TS 移植(material-color-utilities 官方提供 C++/Dart/Java/Swift/TypeScript/Kotlin 实现),无 CSS 特性依赖。

兼容回退

Web 端建议构建期生成两套角色变量(--md-primary/--md-on-primary/…)并按 prefers-color-scheme 或主题类切换;不支持变量切换的极端环境退回单主题固定 hex。角色值一律整值输出,不做运行时插值。

来源 2

起源Android 12 推出 Material You 动态取色:壁纸 → quantize(Celebi = Wu + WSMeans)→ score 选出 source color → 外推 5 个关键色 → 每关键色 13-tone 调色板 → 同一壁纸派生 5 套方案构成亮/暗主题;Android 13 增加 Neutral / Vibrant Tonal / Expressive 变体(各自以 vibrancy 与色相旋转配方变换种子色)(调研 06§六6)。demo 按官方库 material-color-utilities 0.3.0(Apache-2.0)的 scheme_*.js 与 material_dynamic_colors.js 实现。
