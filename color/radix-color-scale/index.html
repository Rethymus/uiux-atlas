Radix 色阶 Radix Color Scale

Radix 12 步色阶 · 语义色阶 · Radix Colors

每个 hue 一条 12 步色阶,步位即语义:1–2 背景、3–5 交互表面、6–8 边框、9–10 solid、11–12 文本——非 Material 路线的工业标杆。

代码拆解

结构与 DOM

Radix Colors 的核心抽象是「一条 hue = 一条 12 步色阶」,发布形态就是一组 CSS 自定义属性,直接可抄进项目:

<div class="card">
  <h3>标题 / Heading</h3>
  <p>正文 / Body</p>
  <button>操作 / Action</button>
</div>
.card {
  /* 步位即语义:背景 2 · 边框 6 · 标题 12 · 正文 11 · 按钮 9(配对文字见官方分档) */
  background: var(--blue-2);
  border: 1px solid var(--blue-6);
}
.card h3 { color: var(--blue-12); }
.card p { color: var(--blue-11); }
.card button { background: var(--blue-9); }
  • 12 步语义(Radix 官方,调研 06§二8):1 app 背景、2 次级/微妙背景、3 组件表面背景、4 hover 背景、5 pressed/selected 背景、6 非交互微妙边框、7 交互边框/焦点环、8 hover 边框/强边框、9 纯色 solid(全阶 chroma 最高、「混入白/黑最少」)、10 solid hover、11 低对比文本、12 高对比文本;
  • 官方目录:6 种中性色(Gray/Mauve/Slate/Sage/Olive/Sand)+ 26 个 accent + alpha 透明变体 + 独立调校的 -dark 暗色阶;
  • demo 的 8 组色值逐值取自官方发行包 @radix-ui/colors@3.0.0(亮色阶 sRGB hex)。

样式与参数

色阶是「编号即用法」的体系——不需要计算,只需要按步位取色:

/* 官方保证:步 11/12 在同类步 2 背景上达 APCA Lc 60 / Lc 90 */
:root {
  --scale-step-9-text: white;  /* 多数 hue 的 9 步配白字 */
}
:root[data-hue="sky"], :root[data-hue="mint"], :root[data-hue="lime"],
:root[data-hue="yellow"], :root[data-hue="amber"] {
  /* 官方例外:Sky/Mint/Lime/Yellow/Amber 5 阶的 9 步配深色字 */
  --scale-step-9-text: #2b2118;
}
  • 对比度保证是「步位对」而非单色:11/12 对 2 的 APCA Lc 60/90 由官方定标;自定义色阶要自己重建这套配对;
  • 工程落地:把 12 步映射进 CSS 变量(—blue-1…—blue-12)后,组件按语义槽位引用而非直接写步号——换 hue 时只改变量绑定,不动组件;
  • hover 反馈用相邻步位表达:背景 3→4、边框 7→8、solid 9→10——步位体系让「交互变色」不需要另设计新颜色;
  • 暗色主题不是亮色加深:官方 -dark 阶独立调校;亮色可用白色作 app 背景,暗色改用步 1/2 的灰或彩色,并为 AppBg 建 mutable alias 按模式重映射;
  • alpha 变体(-alpha 文件)解决彩色叠层的白边/灰边问题,阴影/遮罩用它而不是手调 rgba。

动效与交互

  • 切 hue,整条 12 步 + 语义示例卡同步重算;步 9 的文字色按官方分档自动切换(amber → 深字);
  • 高亮步位用 2px outline 标示,prefers-reduced-motion 时取消过渡直接跳变;
  • 不做颜色动画之外的动效:色阶演示里唯一该动的是「哪个步位在讲解」;
  • 与 Material tone 体系的分工:Radix 步位是语义槽位(每步一个用途),Material tone 是连续标尺(角色从标尺上取值)——两者常被混为一谈,demo 并排呈现就是为了让差别可见。

参数敏感度

参数调大会…调小会…
hue更暖/更冷取决于所选 accent;同一布局换 hue 时所有步位语义不变,视觉重量也大体不变(官方按 APCA 定标)gray 是唯一无彩阶:9 步是纯灰 CTA,适合克制型界面;换 hue 不改变对比度保证的成立性
step高于 9:进入文本档(11/12)——颜色变深变「墨」;hover 状态(10)属于交互反馈低于 9:进入表面/背景档(1–5)与边框档(6–8)——颜色变浅变「面」;选中步只是高亮位置,不影响色阶本身
适用场景 4
  • 设计系统底座:直接把步位当语义 token 用(1–2 页面底、3–5 交互面、6–8 描边、9–10 实色、11–12 文字)
  • 状态色体系:info/warning/danger 各取一条 hue,同一步位跨色互换保持视觉秩序
  • 暗色主题:官方 -dark 变体独立调校,不是亮色的简单加深
  • 高对比需求:步 11/12 已按 APCA Lc 60/90 定标,正文/标题文本直接取用
何时不要用 3
  • 跨步位乱配:比如拿步 3(表面)当文字色——步位语义与对比度保证是一体的,拆开用就失效
  • 给 Amber/Lime 等亮黄类 9 步强行配白字——官方明确这 5 阶配深色字
  • 把步 9 当『品牌主色』直接全屏铺:9 是 CTA/强调实色,大面积背景该用 1–3
无障碍

官方保证:步 11 与步 12 在同类步 2 背景上达到 APCA Lc 60 / Lc 90(调研 06§二8 原文);步 9 的文字配色按官方分档(多数白字,Sky/Mint/Lime/Yellow/Amber 深字)。换 hue 或自定义色阶时需重新核对这些配对;APCA 为非对称算法,深字浅底与浅字深底阈值不同,不能用 WCAG 比值直接套算。

浏览器支持

色阶以 hex/CSS 自定义属性发布,无 CSS 特性依赖;官方另发布 -dark(暗色)与 -alpha(透明)变体文件,并为 P3 广色域做了调校。demo 直接使用亮色阶 sRGB hex,任何浏览器可用。

兼容回退

无需回退。工程实践:亮色主题可直接用白色作 app 背景,暗色主题改用步 1/2 的灰或彩色,并为 AppBg 建 mutable alias 按模式重映射(官方用法);缺色时用 Gray 步阶兜底。

来源 2

起源Radix Colors 官方将每步语义写入文档(调研 06§二8):步 11/12 在步 2 背景上保证 APCA Lc 60 / Lc 90 对比度;官方以 APCA 定目标、支持 P3 广色域,并提供 6 种中性色 + 26 个 accent + alpha 透明变体。demo 的 8 组亮色阶 12 步 hex 逐值取自官方发行包 @radix-ui/colors@3.0.0(本次会话从 npm 包读取 gray/blue/green/amber/red/violet/cyan/pink.css)。
