渐变插值 Gradient Interpolation Space

渐变插值空间 · in oklab · hue 插值策略 · color interpolation

同一对端色,换个插值空间就是另一条渐变:in srgb/oklab/oklch/display-p3 与四种 hue 策略,治好 sRGB 插值长距离过渡的脏灰带。

Web 标准 ★★★
实例演示 官方默认
参数
动效▾
spaceoklab

JS 型参数:插值色彩空间。默认 oklab——Tailwind v4 渐变默认即 OKLAB 插值(调研 06§4);CSS Color 4 §13.1 亦规定宿主语法未定义兜底时用 Oklab。不写 in 时旧式 hex/命名色按兼容条款在 gamma sRGB 插值——长距离色相过渡易出脏灰带。oklch 保 chroma 最鲜艳;srgb 是兼容之选;display-p3 在 P3 基色上插值。

hueStrategyshorter

JS 型参数:色相插值策略,**仅对柱坐标空间有效**——本条目四个选项中只有 oklch 是柱坐标(srgb/oklab/display-p3 是直角空间,写 hue 关键词整条声明无效)。默认 shorter 取规范缺省:柱坐标空间未指定时按短弧插值(调研 06§4 仅列四策略清单未记载默认值,写作时已抓取 W3C CSS Color 4 §13.1 原文复核确认)。

色彩▾
from#FF0000

渐变起点色。默认 #FF0000 = CSS 命名色 red,取自调研/spec 例证 `linear-gradient(in oklab, red, blue)` 的起点(调研 06§4)——红蓝对撞正是展示 sRGB 插值脏灰带的经典用例。

to#0000FF

渐变终点色。默认 #0000FF = CSS 命名色 blue,同上例证。demo 同时以 color-mix(in 空间, from, to) 显示各空间 50% 中点色,脏灰带在 sRGB 的中点上最直观。

代码拆解

结构与 DOM

渐变是 <image>,in 空间子句随角度一起写在函数名后、色标表之前:

/* 角度在前,in 子句在后(MDN 惯用写法;正式语法中二者经 || 组合可互换位次) */
.hero {
  background: linear-gradient(90deg, red, blue);                 /* 兜底:旧式色默认 sRGB 插值 */
}
@supports (background: linear-gradient(90deg in oklab, red, blue)) {
  .hero {
    background: linear-gradient(90deg in oklab, red, blue);      /* 感知均匀插值 */
  }
}
  • 语法位次:正式语法 [ <angle> || <color-interpolation-method> ] 允许角度与 in 子句互换位次,惯用写法把角度放最前:linear-gradient(90deg in oklch longer hue, red, blue);
  • hue 策略只属于柱坐标空间:语法表 <polar-color-space> = hsl | hwb | lch | oklch(CSS Color 4 §13.1,写作时抓取规范原文复核);srgb/oklab/display-p3 是直角空间,携带 hue 关键词整条声明无效——demo 对非 oklch 空间显示「hue 不适用」;
  • 结构上每条对比条带 = 一个 div,背景由 JS 拼 linear-gradient(90deg in <space> [hue], var(--gi-from), var(--gi-to)) 内联注入;样式表里的无 in 普通渐变是兜底,内联声明无效(不支持)时被丢弃、自动落回兜底。

样式与参数

四个参数:两个 enum(JS 型)+ 两个 color(CSS 型,--gi-from/--gi-to):

.mid-srgb    { background: color-mix(in srgb,      var(--gi-from), var(--gi-to)); }
.mid-oklab   { background: color-mix(in oklab,     var(--gi-from), var(--gi-to)); }
.mid-oklch   { background: color-mix(in oklch shorter hue, var(--gi-from), var(--gi-to)); }
.mid-display { background: color-mix(in display-p3, var(--gi-from), var(--gi-to)); }

数值出处:

  • 端色默认 red #FF0000 → blue #0000FF,取 CSS Color 4 例证/调研原文 linear-gradient(in oklab, red, blue)(调研 06§4)——红蓝对撞在 sRGB 插值下中段穿过脏灰紫,是规范文档自己使用的演示用例;
  • space 默认 oklab:Tailwind v4(2025-01)渐变默认 OKLAB 插值(调研 06§4);CSS Color 4 §13.1 亦规定宿主语法未定义兜底空间时用 Oklab(写作时抓取规范复核);
  • hueStrategy 默认 shorter:调研 06§4 仅记载四策略清单(shorter/longer/increasing/decreasing)未记载默认值;写作时抓取 W3C CSS Color 4 §13.1 原文确认——「For a <polar-color-space> if the <hue-interpolation-method> is not specified, it defaults to shorter」;
  • 四种 hue 策略语义(规范 §13.4):shorter 走短弧、longer 走长弧、increasing 沿递增方向、decreasing 沿递减方向——后两者在动画中不会因差值越过 180° 而翻弧;
  • 缺失分量规则:白色等无色相的颜色在柱坐标空间插值时,hue 取对端色相参与插值(调研 06§4),所以 color-mix(in oklch, white, green) 得到的是真正「白→绿」的过渡而非偏红;

对白色这类无色相端点,规范的处理是让它继承对端色相(规范原文以 color-mix(in hsl, white 30%, green 70%) 为例):

/* white 在 oklch 中 hue 缺失 → 取 green 的 hue,得到纯白到绿的干净过渡 */
color-mix(in oklch, white, green);   /* 而非把 white 的 hue 当作 0°(偏红) */

Tailwind v4 的工程注脚:调色板整体 rgb→oklch、渐变默认 OKLAB 插值、bg-linear-to-r/srgb、/oklch 修饰符可切换空间、透明度用 color-mix(in oklab, var(--color-blue-500) 50%, transparent)(调研 06§4)。

动效与交互

  • 改任一参数,主条带、四条对比带与四个中点色块即时重绘——全部由浏览器插值,JS 只拼字符串;
  • 空间切换时条带宽度不变、颜色路线变:同一渐变在 oklch 下全程高饱和、srgb 下中段发灰——无需动画即可一眼对比;
  • hue 策略切换仅在空间 = oklch 时生效;其余空间 demo 明示「hue 不适用(直角空间)」,并把 hue 关键词从拼串中省略;
  • 条带无入场动画,避免动效掩盖色彩差异;prefers-reduced-motion 下亦无任何过渡(demo 无 transition);
  • 渐变上如需叠字,先按最亮/最暗两端核对对比度(wcag-contrast 条目),插值空间的选择会移动中段最差点。

参数敏感度

参数调大会…调小会…
spaceoklch:chroma 全程拉满最鲜艳(保 chroma 是它的设计目标);display-p3:在更广基色上插值,P3 屏上略鲜艳,但与 srgb 差异细微oklab:感知均匀、中段亮度平滑;切回 srgb 即回到兼容旧行为,红蓝类长距过渡立即出现脏灰带
hueStrategylonger:绕远弧,红→黄会途经蓝紫,适合刻意编排;increasing/decreasing:固定方向,动画中差值过 180° 不翻弧shorter(默认):走最短弧,过渡最经济;当两端色相近对跖时短弧与长弧差异最大
from / to两端色相夹角越大,空间间差异越明显——拉到红/蓝对跖是演示最优解两端越接近,各空间结果趋同,对比条带失去教学意义;同色相深浅渐变时各空间几乎无差

经验:默认组合(oklab + red→blue)是「安全又好看」的一档;要看最戏剧性的差异,把空间切到 srgb 看脏灰带、切到 oklch 再把 hue 策略拨到 longer 看绕行蓝紫的色相旅行——这两次切换就是本条目全部知识点的现场演示。

适用场景 4
  • 长距离色相过渡(红→蓝、橙→紫):显式 in oklab/in oklch,避免 sRGB 默认插值的中段脏灰(调研 06§4)
  • 极坐标空间保鲜艳:in oklch 让 chroma 全程不塌,Tailwind v4 默认渐变即 OKLAB 插值(调研 06§4)
  • 绕远路的色相旅行:in oklch longer hue 让红→黄走蓝紫一侧,适合 Aurora/mesh 光斑的色相编排(调研 06§14)
  • P3 屏渐变增强:in display-p3 配 @media (color-gamut: p3) 覆写更鲜艳版本(调研 06§3)
何时不要用 4
  • 对直角空间写 hue 策略——语法表只允许柱坐标空间(hsl/hwb/lch/oklch)携带 hue 关键词,写错整条声明无效
  • 默认(不写 in)直接上线的长距渐变——旧式颜色在 sRGB 插值,中段发灰发脏;这是规范的兼容条款,不是 bug(调研 06§4)
  • 同一渐变既无兜底声明又只有 in 语法——不支持的老浏览器会整条丢弃,必须有普通渐变在前
  • 渐变上叠小字不核对对比度:按最亮/最暗两端分别查(Aurora 配方建议光斑亮度保持 0.6–0.75,既发光又不炸文字对比度,调研 06§14)
无障碍

渐变本身不传达信息时无 a11y 义务;渐变上的文字要按『最亮端与最暗端』两种极端分别核对 4.5:1(正文)/3:1(大字),UI 组件边界 3:1(SC 1.4.11)——插值空间的选择会改变中段亮度,从而改变最差点位。Aurora/mesh 配方以光斑亮度 0.6–0.75 控制对比度风险(调研 06§14);渐变不得作为传达关键信息的唯一手段。

浏览器支持

in 空间渐变语法出自 CSS Color 4 §13(调研 06§六4,一手来源 W3C 规范);调研未逐浏览器记载该语法的支持年份,实施前请以 MDN/Can I Use 复核。底层颜色函数 oklch() 自 2023-05 起全主流支持(调研 06§1);color-mix() 为 CSS Color 5 函数。

兼容回退

不支持 in 语法的浏览器整条声明失效:先写不带 in 的普通渐变兜底,再覆写 in 版本;demo 即采用该结构——样式表里的普通渐变是兜底,内联 in 渐变仅在可解析时生效(无效内联声明被丢弃后自动落回样式表)。

来源 3

起源插值空间与 hue 策略由 CSS Color 4 §13 定义(调研 06§4);工业落地参照 Tailwind CSS v4(2025-01):调色板整体改用 oklch、渐变默认 OKLAB 插值、可用 /srgb 等修饰符切换(调研 06§4/§六5)。
