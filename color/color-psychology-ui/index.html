UI 色彩心理 UI Color Psychology

色彩情绪 · 暖冷色策略 · 色彩行为学

色彩对情绪与行为的影响属编辑性经验总结(本调研未系统证实):暖色相常关联紧迫与行动、冷色相常关联信任与冷静、高饱和=高唤起、高明度=轻。工程上可控的是 oklch 三轴——明度定对比度、色度定唤起强度、色相定情绪域。

代码拆解

结构与 DOM

色彩心理不是 DOM 结构,是内容策略层:同一张卡片 DOM,情绪由取色参数与注释文案表达。硬约束(对比度)与软叙事(情绪)在页面上分区呈现,互不冒充:

<div class="mood-card">        <!-- 卡面:oklch(L C H) 驱动 -->
  <h3>标题</h3>
  <p>正文</p>
  <button class="cta">行动号召</button>
</div>
<aside class="annotation">     <!-- 注释区:编辑性断言 + 可验证规则分列 -->
  …
</aside>

关键点:

  • 「情绪」最终只能落在三个工程量上:明度(定对比度与明暗基调)、色度(定饱和/唤起强度)、色相(定暖冷域);
  • 每条情绪断言必须带「编辑性总结,未证实」标注——本调研未取得色彩心理学的一手实证来源;
  • 可验证规则单独列出:强调色承担「焦点/行动号召」(hype4 60-30-10)、暗色避免过度饱和(hype4)、L≥0.87 配黑字对比度都好(Evil Martians)。

样式与参数

卡面由 --psy-light / --psy-chroma / --psy-hue 三个 CSS 变量驱动;文字色为 JS 型参数(黑/白切换后对比度重算):

.mood-card {
  background-color: oklch(var(--psy-light) var(--psy-chroma) var(--psy-hue));
  /* 默认 L=0.87 C=0.17 H=20:三个默认值都有出处(见下) */
  color: #000;
}

数值出处:

  • L=0.87:踩在 Evil Martians 可验证规则「L≥87% 的背景配黑字对比度都好」上(demo 内嵌 WCAG 公式实时验证);相邻规则:L=0.8 任何色相配黑字清晰、头像衍生色示例 L=0.8 C=0.17(调研 06§2);
  • C=0.17:同上 Evil Martians 示例值;oklch C 实用上限约 0.5、100%=0.4(MDN,调研 06§1);
  • H=20:Evil Martians 色相经验映射 红≈20/黄≈90/绿≈140/蓝≈220/紫≈320(demo 的暖冷判定即按此口径:≤90° 暖、>90° 冷)(调研 06§2);
  • 对比度公式:WCAG 2.1 相对亮度(L = 0.2126R+0.7152G+0.0722B,阈值 4.5:1/3:1,不得四舍五入)(调研 06§17);
  • 读数是 sRGB 近似:demo 把越域线性值钳制到 0–1(即浏览器实际会做的裁剪);P3 屏上高色度卡面的真实渲染由浏览器 gamut mapping 决定,比值可能与读数略有出入。

动效与交互

demo 的全部交互都是「证据链」,无自主动画:

  • 三滑杆:明度降 → 对比度读数实时跌破 4.5 并变红标「不达标」;色相跨 90° → 暖冷带自动切换注释文案;色度推高 → 「暗色避免过度饱和」的提示区依然在(可验证约束优先展示);
  • 黑/白字切换(JS 型参数):同明度下黑/白两枚比值同屏并列——文字色选择由对比度决定,不由情绪偏好决定;
  • 卡面背景/文字 0.25s ease 过渡,prefers-reduced-motion 时取消;
  • 注释区永远虚线描边+降透明度,视觉上与硬数据区分离——情绪叙事不冒充工程结论。

真实产品案例

  • Spotify:60-30-10 的经典例证——黑 60(大面积)/深灰 30(组件)/活力绿 10(播放键与 logo 强调);绿色强调承担「行动/焦点」职责而非情绪装饰(LogRocket 例证,调研 06§9);
  • Material 3 暗色主题:官方基线把 accent 从亮色 #6750A4 提亮降饱和为暗色 #D0BCFF(≈tone 80)——「暗色下高饱和/高对比致视觉疲劳」的可验证官方落地(调研 06§7/§9/§14);
  • Neo-Brutalism:高饱和「响亮」色块+粗描边作为吸睛策略的生产化案例;HubSpot 同时给出可访问性警示——浅色+微妙阴影对低视力用户是噩梦,抛弃常见导航模式增加认知负担(调研 11§6)。

参数敏感度

参数调大会…调小会…
lightness卡面更亮——可验证规则区内(L≥0.87)黑字恒过 4.5:1;情绪上「轻快」(编辑性)跌破 4.5:1 红灯;0.6–0.87 区间是「情绪压过对比度」的典型翻车区;0.8 是黑字仍清晰的实证下界
chroma饱和/唤起感增强(编辑性);暗色场景违背「避免过度饱和」的约束;对比度读数随色相浮动灰阶化——唤起叙事消失,但对比度最稳;0 是最安全档
hue跨 90° 换暖冷带,注释文案整段切换;不同色相下黑/白比值不同(同 L 不保证同对比)停在红 20°(默认)是「紧迫/行动」叙事位(编辑性)
textColor → white白字对照:同明度下比值显著更低,通常直接不达标——展示「白字更醒目」是错觉black 是默认与推荐:研究口径内最稳
适用场景 4
  • CTA 与关键操作的强调色:强调色承担「焦点/行动号召」职责是 60-30-10 的可验证分工(hype4,调研 06§9)
  • 品牌情绪板与营销页的色相域选择:按暖冷带组织候选色相(demo 的暖冷判定即此用法)
  • 长文阅读底色:APCA 专门讨论浅色底长时间阅读疲劳(调研 06§18)——阅读界面慎用高 L 差组合
  • 暗色主题的强调色:提亮降饱和的系统惯例(M3 #6750A4→#D0BCFF 官方基线,调研 06§7)
何时不要用 4
  • 把「红=紧迫」当因果定律写进需求——色彩心理叙事未获系统证实,只能当假设,A/B 验证后再放大
  • 用情绪色替代状态语义(错误红/成功绿)——色盲用户不可辨;状态须另有图标/文字承载(调研 06§19)
  • 情绪优先压过对比度红线——正文 AA 4.5:1 是硬约束(WCAG SC 1.4.3,对比度不得四舍五入,调研 06§17)
  • 暗色主题沿用亮色饱和度——「暗色避免过度饱和」有可验证出处(hype4,调研 06§9),M3 官方基线也演示了降饱和方向
无障碍

对比度是硬约束,情绪是软叙事:正文 ≥4.5:1、大字 ≥3:1、UI 组件边界 ≥3:1(WCAG 2.1 SC 1.4.3/1.4.11,阈值不得四舍五入,调研 06§17);demo 内嵌 WCAG 公式实时计算黑/白字的比值并通过/失败判定。可验证的明度规则:L=0.8 配黑字清晰、L≥0.87 背景配黑字对比度都好(Evil Martians,调研 06§2)。情绪色调不得作为唯一信息编码;APCA 若替代 WCAG 判定,注意其非对称性(浅底疲劳章节,调研 06§18)。

浏览器支持

方法论而非浏览器特性。参数化载体为 oklch()(Baseline 2023-05,调研 06§1)与 CSS 自定义属性(全平台);对比度计算用 WCAG 2.1 相对亮度公式(调研 06§17),与浏览器无关。

兼容回退

情绪注释与对比度读数都是增强层:JS 不可用时 oklch 三变量仍有静态 CSS 兜底值(与 schema 默认一致),文字色默认黑字保证 L=0.87 背景可读;不支持 oklch() 的旧浏览器会丢弃整条 background 声明——先写一层 sRGB 近似 hex 再用 @supports 覆写(渐进增强,调研 06§3 同款三件套)。

来源 3

起源无单一出处——色彩心理学的「红=紧迫/蓝=信任」叙事属设计业界通行说法,本次调研未取得一手实证来源,全部按编辑性内容标注(未证实)。调研中可证实的相邻事实:60-30-10 里强调色承担「焦点/行动号召」职责(hype4,调研 06§9);暗色模式避免过度饱和,对比过高造成视觉疲劳(hype4,调研 06§9);APCA 专门章节讨论浅色底长时间阅读疲劳(调研 06§18);M3 暗色 accent 提亮降饱和(#6750A4→#D0BCFF,调研 06§7/§14)。
