主题切换过渡 Theme Transition

圆形扩散主题切换 · startViewTransition 换肤 · clip-path circle reveal

用 document.startViewTransition + clip-path: circle() 把换肤做成从点击坐标扩散的圆形揭示:旧快照在下、新快照被圆形裁剪揭开,扩散半径到视口最远角;无 API 或 reduced-motion 时优雅降级为直接切换。

Web 标准 ★★★
实例演示 官方默认
参数
几何▾
duration500ms
ms

扩散动画时长。默认 500ms 取自 Chrome 官方文档主题切换示例的逐字值(调研 11§8);文档自带的交叉淡化对照写法为 0.3s。0ms 读作直切。注意换肤期间页面渲染冻结,时长越长冻结体感越重(见 motion/view-transitions 条目同款结论)。

动效▾
easingcubic-bezier(0.42, 0, 1, 1)

扩散缓动。默认 (0.42, 0, 1, 1) 即关键字 ease-in 的标准映射——Chrome 文档示例逐字使用 easing: 'ease-in'(调研 11§8);文档同页的交叉淡化自定义示例用 0.3s 时长。加速曲线让圆从点击点「启动」而非「漂移」,过冲曲线会让圆形揭示回缩,慎用。

revealcircle

JS 型参数。circle = 官方配方:旧快照置底、新快照按 clip-path circle 从点击坐标展开;crossfade = 不做自定义动画,只按 duration/easing 调默认交叉淡化(文档写法:animation-duration 覆写);direct = 模拟降级路径,apply 同步执行瞬间换态。三种模式在无 API/reduced-motion 时都自动落到 direct。

代码拆解

结构与 DOM

换肤的 DOM 是「一套结构、两张变量表」:组件不感知主题,data-theme 翻转的只是 CSS 变量;View Transitions 在这之上叠加一个快照层——旧状态截图置底、新状态截图被圆形 clip-path 逐步揭开。

<body data-theme="light">
  <button id="theme-toggle">切到深色</button>
  <!-- ::view-transition-old(root)  ← 旧快照(浏览器自动截图) -->
  <!-- ::view-transition-new(root)  ← 新快照,被圆形 clip-path 揭开 -->
</body>
// Chrome 官方文档示例(调研 11§8 逐字):
let lastClick;
addEventListener('click', event => (lastClick = event));

function themeToggle() {
  if (!document.startViewTransition) { swapTheme(); return; } // 优雅降级(官方写法)

  const x = lastClick?.clientX ?? innerWidth / 2;
  const y = lastClick?.clientY ?? innerHeight / 2;
  const endRadius = Math.hypot(Math.max(x, innerWidth - x), Math.max(y, innerHeight - y));

  const transition = document.startViewTransition(() => swapTheme());
  transition.ready.then(() => {
    document.documentElement.animate(
      { clipPath: [`circle(0 at ${x}px ${y}px)`, `circle(${endRadius}px at ${x}px ${y}px)`] },
      { duration: 500, easing: 'ease-in', pseudoElement: '::view-transition-new(root)' },
    );
  });
}

关键点:换肤本身(data-theme/color-scheme 翻转)与过渡解耦——不支持 API 时功能零损失;与 motion/view-transitions 条目不同,这里是 root 快照表演,不涉及元素级 view-transition-name。

样式与参数

主题表与过渡参数分离:--tt-bg/--tt-fg/--tt-accent 管配色,--tt-duration/--tt-easing 管动画(经 demo 镜像到 :root——::view-transition 伪元素树挂在 <html> 下,不继承 .demo-stage 的变量):

[data-theme="light"] { --tt-bg: oklch(0.992 0.006 334); --tt-accent: #6750A4; } /* M3 基线 */
[data-theme="dark"]  { --tt-bg: oklch(0.17 0.012 297);  --tt-accent: #D0BCFF; } /* accent=官方基线 */
::view-transition-old(root),
::view-transition-new(root) { animation-duration: var(--tt-duration); animation-timing-function: var(--tt-easing); }
/* circle 档阻断默认交叉淡化(文档写法):animation: none; mix-blend-mode: normal; */

数值出处:

  • duration 500ms + easing ease-in + hypot 最远角公式 + ::view-transition-new(root):Chrome 官方文档主题切换示例逐字(调研 11§8);
  • 0.3s:文档同页自定义默认交叉淡化的示例时长(::view-transition-old/new(root) { animation-duration: 0.3s; })(调研 11§8);
  • 亮侧 #FFFBFE/#1C1B1F/#6750A4、暗侧 #D0BCFF/#381E72:M3 官方基线角色值(调研 06§7);暗侧表面色为演示值(官方暗 surface 值未在本调研逐值列出);
  • API 支持:Chrome/Edge 111、Safari 18、Firefox 144(BCD,调研 11§8);换肤配色联动的 light-dark():Chrome/Edge 123、Firefox 120、Safari 17.5,Baseline 2024-05(调研 11§8)。

动效与交互

时间线是「截图 → 同步换肤 → 揭开」三拍,参数只动最后一拍:

  • circle(官方配方):点击坐标存入变量 → startViewTransition 截旧快照 → 回调内 flushSync 同步翻转 data-theme → 截新快照 → transition.ready 后对 ::view-transition-new(root) 跑 clip-path 圆形扩散(默认 500ms ease-in)——加速曲线让圆「从指尖发射」;
  • crossfade:不做自定义动画,默认交叉淡化被 animation-duration/timing-function 覆写为参数值;
  • direct(降级对照):跳过快照表演,apply() 同步执行瞬间换态——三档在「无 API」或「reduced-motion」时全部自动落到这一档;
  • 三路降级:①typeof document.startViewTransition !== 'function' 直切(官方写法);②prefers-reduced-motion 监听 matchMedia 变化、动态生效;③transition.ready reject 时 .catch 吞掉,界面停留在换肤后状态;
  • 同一时刻仅一个视图过渡:连点时新过渡把旧过渡跳到结尾(官方行为);换肤期间渲染冻结,500ms 是官方参考上限(再长冻结体感变重)。

真实产品案例

  • Chrome 官方开发者文档:圆形扩散配方的出处本身——文档内置的交互式演示即为「点击坐标→圆形揭开新主题」,并同步给出降级与 reduced-motion 写法(调研 11§8);
  • web.dev《light-dark》配套示例:换肤配色联动的官方教学——:root { color-scheme: light dark } + light-dark() 双值取色,与视图过渡叠用即「零 CSS 改动的换肤表演」(Chrome/Edge 123、Firefox 120、Safari 17.5 三引擎齐备,Baseline 2024-05,调研 11§8);
  • 开发者博客与个人作品集的主题开关:「圆形扩散换肤」在社区教程中广泛出现,多基于同一官方配方改写(编辑性总结——具体产品与采用率未逐一核实;配方本身逐字出自 Chrome 文档,见上)。

参数敏感度

参数调大会…调小会…
duration揭开更从容、扩散轨迹可辨;但渲染冻结期随之变长,>500ms 开始拖沓(官方参考即 500)趋近直切;0ms 等价 direct 档
easing加速曲线(默认 ease-in 映射)让圆有「发射感」;过冲曲线会让圆形揭示回缩露馅,禁用两控制点趋近对角线读作 linear——匀速扩散显机械;crossfade 档建议配 (0.4, 0, 0.2, 1) 类无过冲曲线
reveal → crossfade不做自定义动画只调时序——最保守,主题间无空间叙事circle:空间连续性最强、因果指向点击点;direct:零开销,但「换肤闪变」突兀
换肤频率高频切换时每次都冻结渲染并打断阅读——自动跟随系统主题时禁用过渡手动开关是唯一合适频率
适用场景 4
  • 用户触发的手动换肤开关(主题切换按钮)——圆形扩散从指尖发起,因果指向明确(官方示例场景)
  • 换肤与 light-dark()/data-theme 变量翻转联动:CSS 侧零改动,过渡只是「快照表演」
  • 给配色敏感的界面(仪表盘、编辑器)一个空间连续的换肤,替代生硬的全屏闪变
  • 同一配方可用于任何「全局状态翻转」:紧凑/宽松密度、色盲模式切换(语义色换表场景,见 semantic-token-layers)
何时不要用 4
  • 高频/自动触发的换肤——每次过渡都冻结渲染并打断阅读;自动跟随系统主题时不要加过渡
  • reduced-motion 用户身上强加扩散——系统要求减少动效时必须走直接切换(文档的媒体查询包裹建议)
  • 时长拉满 1000ms——冻结体感随时长线性增长,官方参考值 500ms、交叉淡化 0.3s,再长就开始拖沓
  • 把圆形扩散当页面路由过渡——它与 motion/view-transitions 的元素级 morph 是两回事;换肤是 root 快照表演,元素级衔接请看该条目
无障碍

三条底线:① reduced-motion 必须直达直切(demo 监听 matchMedia 变化,动态系统设置也即时生效);② 换肤本身不得丢失信息——过渡只是快照表演,底层状态同步完成(apply 在快照回调内同步执行);③ 新旧两套主题各自满足对比度红线(正文 4.5:1、边界 3:1,调研 06§17)——demo 亮侧用 M3 官方基线 #FFFBFE/#1C1B1F/#6750A4,暗侧 accent 用官方 #D0BCFF/#381E72;④ 前庭安全:扩散动画以点击点为圆心向外,不做缩放/视差,减少运动敏感风险。

浏览器支持

document.startViewTransition 同文档视图过渡:Chrome/Edge 111、Safari 18、Firefox 144(BCD view-transition-name.json,调研 11§8);::view-transition-new(root) 伪元素与 clip-path 动画随 API 同代支持。降级写法是官方示例自带的一部分——不支持时直接换肤,功能零损失。

兼容回退

官方降级链:① 不支持 startViewTransition → `if (!document.startViewTransition) { swapTheme(); return; }` 直接换肤(官方示例逐字,调研 11§8);② prefers-reduced-motion → 跳过快照动画,直接换肤(文档建议包一层媒体查询);③ 快照动画中途异常 → transition.ready promise 拒绝,界面仍停留在换肤后的新状态。demo 三路全实现。

来源 4

起源Chrome 官方文档的主题切换示例(调研 11§8 逐字收编):startViewTransition 包住换肤回调,transition.ready 后对 `::view-transition-new(root)` 做 clip-path 圆形扩散动画(duration 500、easing ease-in、半径 = hypot(点击点到最远水平/垂直角));文档同时给出降级写法 `if (!document.startViewTransition) { swapTheme(); return; }` 与自定义默认交叉淡化(animation-duration 0.3s)、以及 prefers-reduced-motion 包裹建议。API 支持:Chrome/Edge 111、Safari 18、Firefox 144(BCD,调研 11§8)。
