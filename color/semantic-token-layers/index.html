语义色三层架构 Semantic Token Layers

三层 token · primitive→semantic→component · Primer Primitives 分层

primitive(原始值)→ semantic(语义角色)→ component(组件)三层引用链:组件只认语义名,换一张映射表就得到 9 套主题——GitHub Primer 用它一口气生成高对比与色盲模式。

结构与 DOM

三层结构是引用方向的纪律,不是目录结构:第 1 层 primitive 存原始值(带序号层级),第 2 层 semantic 用角色词命名并只引用 primitive,第 3 层 component 的 CSS 只消费语义变量。

<article class="card">…</article>
/* 第 3 层:组件文件里零 hex */
.card {
  background-color: var(--st-bg, #ffffff);   /* 语义变量 + 兜底值 */
  color: var(--st-fg, #1c1b1f);
}
/* 第 2 层:语义映射表(light 主题的一行,Primer 实测分层) */
[data-theme="light"] {
  --st-bg: var(--st-primitive-neutral-0);
}

关键点:

  • 引用链单向:component → semantic → primitive,禁止反向跳层(组件直接摸 primitive 是 Android 文档点名的反模式——应「语义化分配 color role 而非具体值」);
  • 主题切换只改一张映射表:data-theme 属性重挂语义变量,9 套主题共用同一份组件 CSS;
  • 语义名必须是角色词(bgColor-default、fgColor-muted),不能是观感词(--light-blue-500)——观感词换主题即失效。

样式与参数

demo 的 9 套主题用 data-theme 重映射 6 条语义变量;三个参数全为 JS 型(theme / role / layer),映射面板按 DTCG 形状展示三层定义:

.st-scene[data-theme="dark"] {
  --st-bg: oklch(0.19 0.01 297);      /* 演示映射值 */
  --st-accent: #D0BCFF;                /* M3 暗色 primary 官方基线(调研 06§7) */
  --st-on-accent: #381E72;             /* M3 暗色 on-primary 官方基线 */
}

数值与命名出处(全部取自 Primer Primitives README,调研 06§10):

  • 官方主题清单 9 套,demo 逐字沿用:light / dark / dark-dimmed / light-high-contrast / dark-high-contrast / light-colorblind / dark-colorblind / light-tritanopia / dark-tritanopia;
  • 语义 token 官方示例名:bgColor-default、fgColor-muted、borderColor-accent.muted;primitive 官方示例键:base.color.blue.3(序号 = 明度层级);
  • token 文件格式遵循 W3C Design Tokens 社区组规范($value/$type/$extensions),支持 alpha 变换(官方原形 { $value: '{base.color.blue.3}', alpha: 0.4 })与 @-hack 定义默认+子值(bgColor.accent.@ → bgColor-accent);
  • 编译器:style-dictionary(Primer 实测采用)。

动效与交互

主题切换的动效克制且可选——架构本身是静态纪律:

  • theme 参数切换:data-theme 重挂变量,卡片底色/文字 0.25s ease 过渡;prefers-reduced-motion 时取消过渡;
  • role 参数:映射链中被选中的语义角色在卡片上以 2px 虚线 outline 定位宿主元素(bgColor-default → 卡片、fgColor-muted → 次级文字、borderColor-accent.muted → 徽标),面板同时放大该行;
  • layer 参数:面板在 primitive(原始值 + alpha 变换原形)/ semantic(DTCG $value 引用)/ component(组件消费侧)三层定义间切换;
  • 色盲/蓝黄色盲主题演示同一张组件 CSS 如何「整体变蓝」——accent 映射移向蓝区 220°(Evil Martians 色相映射),这正是「换映射表生成无障碍模式」的实证。

真实产品案例

  • GitHub.com:Primer 的生产主场——9 套主题全部实装,含 4 套无障碍主题(高对比×2、色盲×2、蓝黄色盲×2,调研 06§10/§19);用户在 github.com/settings/appearance 直接切换;
  • Android 系统 Dynamic Color:官方文档原文「用 design token 语义化分配 color role 而非具体值」,亮暗主题与壁纸动态取色共享同一套 token(调研 06§10 佐证)——三层架构的移动端同构;
  • style-dictionary 生态:Primer 的 primitive 经它编译为多平台产物(W3C DTCG 格式为通用交换格式,调研 06§10)——同一份 primitive 表喂给 Web/iOS/Android。

参数敏感度

参数换成…会…
theme → dark表面变暗、accent 提亮降饱和(#6750A4→#D0BCFF,M3 基线演示了该惯例)dark-dimmed 是折中档;dark 档对比更锐
theme → high-contrast文字推向纯黑/纯白、accent 加深、半透明描边收敛为高不透明是独立映射表,不是「同一套色加深」——逐套核对对比度
theme → colorblindaccent 移向蓝区(演示映射);红绿信息改由明度差承载蓝黄(tritanopia)同样换表解决——语义层一旦就位,无障碍主题是「填表」而非「改组件」
role高亮不同宿主元素,展示同一张表里不同角色的分工—
layerprimitive 层是唯一允许出现 hex 的地方;component 层零色值—
适用场景 4
  • 多主题体系:亮/暗/高对比/色盲模式共用一套组件,只换语义映射表(Primer 9 套主题的实证)
  • 组件库与产品解耦:组件 CSS 只引用语义变量,品牌换色不动组件
  • 跨平台 token 单一事实源:W3C DTCG 格式经 style-dictionary 编译到 Web/iOS/Android
  • 需要 alpha 变换的半透明体系:同一 primitive 派生多个透明度档位(官方 alpha: 0.4 写法)
何时不要用 3
  • 组件里直接写 hex/原始值——Android 文档点名的反模式(应「语义化分配 color role 而非具体值」)
  • 只有一层全局变量就把语义层省掉——主题数量增长后映射关系失控,色盲/高对比模式无从生成
  • 语义名带观感词(--light-blue-500)而非角色词——换主题即失效;Primer 的角色词(bgColor-default)才可跨主题存活
无障碍

三层架构是无障碍主题的生成机制本身:Primer 用语义层换映射表产出 light/dark-high-contrast 与 light/dark-colorblind、light/dark-tritanopia 四套无障碍主题(调研 06§10/§19)。每套主题仍需各自核对对比度(WCAG 正文 4.5:1、组件边界 3:1,调研 06§17);高对比主题不是「同一套色加深」而是独立映射表。demo 的演示映射值未做逐套对比度核验,官方值以 primer/primitives 为准。

浏览器支持

非浏览器特性——工程方法论。落地手段是 CSS 自定义属性(全平台支持)与构建期编译(style-dictionary,Primer 实测采用,调研 06§10);token 文件格式遵循 W3C Design Tokens 社区组规范。

兼容回退

三层架构的回退是「语义变量必须有非空兜底值」:每条 var() 都写成 var(--st-bg, #ffffff) 形式,token 未编译/未加载时组件仍有可用配色;主题切换用 data-* 属性 + CSS 变量重映射,JS 失效时系统主题仍由 @media (prefers-color-scheme) 兜底。
