WCAG 对比度 WCAG Contrast

WCAG 对比度 · 对比度比值 · Contrast ratio

WCAG 2.1 对比度四道阈值:正文 AA 4.5:1、AAA 7:1,大字减半,非文本组件 3:1——相对亮度公式实时判定,比值不得四舍五入达标。

实例演示 官方默认
参数
色彩▾
foreground#1C1B1F

前景色(文字/图形)。默认 #1C1B1F = M3 亮色主题 on-surface 官方基线值(Android 开发者文档,调研 06§7);对 M3 surface #FFFBFE 实测 16.7:1(本条目写作时按 WCAG 公式以 node 验算)。

动效▾
textScalenormal

JS 型参数:demo 订阅后切换示例文字档位与适用阈值。WCAG 定义大字为 ≥18pt(≈24px)或 ≥14pt(≈18.66px)粗体,阈值减半:AA 3:1 / AAA 4.5:1(W3C WCAG 2.1 Understanding,调研 06§17)。演示样字取 24px/18.66px bold 对照。

代码拆解

结构与 DOM

检查器是「一个样本 + 一组读数」的结构:左侧预览面板用参数色上底与文字(另放一个前景描边的图形样本供非文本 3:1 直观对照),右侧是比值与四项通过状态。

// WCAG 2.1 相对亮度:先把 gamma 编码的 sRGB 通道线性化,再加权求和
// (公式出处:W3C WCAG 2.1 Understanding / contrast-minimum)
const lin = (c: number) => {
  c /= 255;
  return c <= 0.03928 ? c / 12.92 : Math.pow((c + 0.055) / 1.055, 2.4);
};
const luminance = (hex: string) =>
  0.2126 * lin(r) + 0.7152 * lin(g) + 0.0722 * lin(b);
// 对比度:较亮者+0.05 作分子,较暗者+0.05 作分母(与前后景顺序无关)
const ratio = (L1: number, L2: number) =>
  (Math.max(L1, L2) + 0.05) / (Math.min(L1, L2) + 0.05);
  • 判定用未舍入原值:显示可以保留两位,但 4.499:1 必须显示 ✗——WCAG 原文明确阈值不得四舍五入(调研 06§17);
  • 前后景互换不影响比值(demo 把两个 hex 参数都画进预览,互换即验)。

样式与参数

两个 CSS 型 color 参数(经 --wc-* 变量注入)+ 一个 JS 型 enum 参数:

.wc-preview {
  background-color: var(--wc-bg); /* 默认 #FFFBFE(M3 surface 基线) */
  color: var(--wc-fg);            /* 默认 #1C1B1F(M3 on-surface 基线) */
}
.wc-preview[data-scale="large"] .wc-sample-normal { display: none; }
.wc-preview[data-scale="normal"] .wc-sample-large { display: none; }

数值出处:

  • 默认对取 M3 官方基线:on-surface #1C1B1F / surface #FFFBFE(Android 开发者文档原文,调研 06§7),实测 16.7:1(本条目写作时按 WCAG 公式以 node 验算);
  • 四道阈值(W3C WCAG 2.1 Understanding,调研 06§17):
    • AA / SC 1.4.3:正文 ≥ 4.5:1(依据约 20/40 视力对比敏感度损失 3×1.5);
    • AAA / SC 1.4.6:正文 ≥ 7:1(对应约 20/80 视力);
    • 大字:≥18pt(≈24px)或 ≥14pt(≈18.66px)粗体,阈值减半为 3:1 / 4.5:1;
    • 非文本 / SC 1.4.11:图标、焦点环、勾选标记、图表元素等 ≥ 3:1,仅默认状态,hover 不在范围;
  • 适用范围含占位符、tooltip、图片化文字;共同豁免:logotype、纯装饰、不可见元素、禁用组件、UA 默认样式、照片中的偶然文字。

动效与交互

  • 改任一 hex 或档位,比值与四项徽章即时重算——纯 JS 数学,无动画延迟;预览底色补 0.18s transition 只为视觉舒适,prefers-reduced-motion 时取消;
  • **textScale(大字)**切换的是「适用阈值」:normal 档按 4.5:1/7:1 判样字;large 档样字放大到 24px(或 18.66px bold),按 3:1/4.5:1 判——徽章本身始终显示四项,适用哪两项由档位明示;
  • 与 APCA 的分工(WCAG 3 候选,调研 06§18):APCA 输出 Lc 感知对比度而非比值,且非对称——深字浅底与浅字深底阈值不同,专为自发光屏幕建模;官方强制用 apca-w3 包,不得自行实现公式。Radix Colors 即以 APCA Lc60/Lc90 为文本色阶目标(调研 06§8)。本条目按 WCAG 2.1 计算,两者不可混用、不可互相冒充;
  • 工具对照:WebAIM Contrast Checker 的判定口径与之一致(AA 4.5/3、AAA 7/4.5、图形 3:1),可作为交叉验证器(调研 06§20)。

参数敏感度

参数调大会…调小会…
foreground前景更亮:若原本深于背景,比值先降后升(过中灰点后分子分母互换);对白底而言前景变亮通常降比值前景更暗:对浅底比值上升;深到与背景亮度接近时比值趋近 1:1,四项全崩
background背景更亮:对深前景比值上升、对浅前景下降背景更暗:对浅前景(如白字)有利、对深前景不利;调到与前景同亮度时比值 = 1:1,全不达标
textScalelarge:适用阈值降为 3:1/4.5:1,原本 4.2:1 的「边缘案例」从 ✗ 翻 ✅——前提是真的大字(≥18pt 或 ≥14pt bold)normal:回到 4.5:1/7:1 严格口径;8px 小字不能蹭大字豁免——豁免看 pt 尺寸,不看“感觉算大”

经验:别把比值当美感指标堆到 15:1——Apple HIG 的建议是 4.5:1 底线、小字力争 7:1(调研 06§12/§13);暗色下过高对比反而刺眼。真正要盯的是最差组合(浅底深字与深底浅字各查一遍)。

适用场景 4
  • 设计/开发阶段核对新配色:文字对底色过 4.5:1(AA)、力争 7:1(AAA),大字减半
  • 图标、勾选标记、焦点环、输入框边框等 UI 组件对相邻色过 3:1(SC 1.4.11,仅默认状态)
  • 给色板定档:像 Radix Colors 那样为文本色阶指定对比度目标(Radix 用 APCA Lc60/Lc90,调研 06§8)
  • 透明度/毛玻璃上的文字:按『透出的最亮与最暗背景』两种极端分别核对(glassmorphism 条目的 a11y 同款要求)
何时不要用 4
  • 四舍五入达标——WCAG 原文明确 4.499:1 就是不达标;demo 判定用未舍入原值,仅显示值保留两位
  • 把 4.5:1 当『越大越好』的唯一指标堆到 15:1——过高对比在暗色下反而刺眼,Apple HIG 建议 4.5:1 底线、小字力争 7:1(调研 06§12/§13)
  • 对禁用组件、纯装饰、logo/品牌字标强推 3:1——SC 1.4.11 明文豁免;UA 默认样式与照片中的偶然文字同样豁免
  • 用 WCAG 比值冒充 APCA——两套体系输出不同:APCA 给 Lc 感知值且非对称,官方要求用 apca-w3 包不得自行实现公式(调研 06§18)
无障碍

本条目本身就是可访问性工具:AA(SC 1.4.3)正文 4.5:1 / 大字 3:1;AAA(SC 1.4.6)正文 7:1 / 大字 4.5:1;非文本(SC 1.4.11)3:1。适用范围含占位符、tooltip 与图片化文字;共同豁免:logotype、纯装饰、不可见元素。WCAG 3 候选的 APCA 采用感知对比度 Lc 且非对称(深字浅底与浅字深底阈值不同),Radix Colors 已用 Lc60/90 定文本色阶(调研 06§17/§18/§8)。

浏览器支持

WCAG 2.1 为 W3C 正式推荐标准,对比度判定与浏览器特性无关;demo 的相对亮度公式按 WCAG 2.1 Understanding 文档定义用纯 JS 实现,无兼容性问题。

兼容回退

无浏览器兼容问题(纯 JS 数学)。若想复用同一套判定,服务端/Node 环境同样适用——公式只依赖 hex 解析与幂运算。

来源 4

起源阈值出自 W3C WCAG 2.1 Understanding 文档原文:SC 1.4.3(4.5:1,依据约 20/40 视力的对比敏感度损失 3×1.5)、SC 1.4.6(7:1,对应约 20/80 视力)、SC 1.4.11(非文本 3:1)(调研 06§17)。
